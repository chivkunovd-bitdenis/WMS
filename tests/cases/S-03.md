# Кейсы экрана S-03

База кейсов живёт между ночами. Номера постоянные и не переиспользуются: кейс, потерявший
смысл, помечается устаревшим, но не удаляется и номер не отдаёт.

Пройденным кейс считается только со скриншотом в `docs/evidence/<карточка>/`.
Проверка чтением кода, curl или пересказом разработчика не засчитывается.

Формат: `S-03-TC-001 · название` → начало, действия, точный ожидаемый результат.

## Кейсы

### S-03-TC-001 · Переключение физического склада в списке FBS

**Начало:** оператор ФФ вошёл в систему. У tenant есть операционные склады «Север» и «Юг» и служебный `FBS WB Москва`; для «Юг» есть FBS-заказ.

**Действия:** открыть список FBS, в строке под шапкой открыть `Склад`, выбрать «Юг».

**Ожидаемый результат:** строка показывает `Склад` и «Юг», список выбора закрывается, а таблица FBS показывает заказ склада «Юг». Существующий фильтр склада селлера/WB остаётся отдельным контролом. `FBS WB Москва` не показан ни в переключателе, ни как текущий склад.

### S-03-TC-002 · Скан ячейки выбирает её склад и подтверждает подбор

**Начало:** открыто рабочее место FBS-поставки со складом консолидации «Север». На «Юг» есть ячейка `A-01-02` с товаром заказа; сканер показывает текст `Сканер активен — пикните ШК склада или ячейки`.

**Действия:** сканировать штрихкод ячейки `A-01-02`, затем сканировать штрихкод товара из заказа.

**Ожидаемый результат:** после первого скана текущим складом становится «Юг», выбрана ячейка `A-01-02`, а подсказка сканера меняется на `Сканер активен — пикните ШК товара`. После скана товара показана единственная строка `Взято: Склад Юг / ячейка A-01-02`; не появляется отдельный чип «межскладский» и не видны технические идентификаторы.

### S-03-TC-003 · Создание поставки при наличии товара на другом складе

**Начало:** оператор выбрал FBS-заказы и открыл диалог создания поставки. Рекомендованный склад WMS — «Север»; для двух товаров на нём не хватает 24 штук, а на «Юг» эти 24 штуки доступны. Общего остатка по операционным складам достаточно.

**Действия:** дождаться завершения проверки остатков и нажать `Создать поставку`.

**Ожидаемый результат:** до создания показан один жёлтый `WarningNotice`: `На складе «Север» не хватает 24 шт. по 2 товарам. Нужно подобрать: «Юг» — 24 шт.`; ниже видна разбивка с колонками `Товар`, `Нужно`, `Здесь`, `Взять со склада`. Кнопка `Создать поставку` активна. После нажатия создаётся поставка со складом WMS «Север».

### S-03-TC-004 · Скан склада меняет место до выбора ячейки

**Начало:** открыто рабочее место FBS-поставки; текущий склад — «Север», ячейка ещё не выбрана. У операционного склада «Юг» есть напечатанный штрихкод склада.

**Действия:** сканировать штрихкод склада «Юг».

**Ожидаемый результат:** текущим складом становится «Юг», ранее невыбранная ячейка остаётся пустой, а сканер продолжает показывать `Сканер активен — пикните ШК склада или ячейки`. Технический код штрихкода не показывается оператору.

### S-03-TC-005 · Ошибочный скан не меняет уже выбранное место

**Начало:** открыто рабочее место FBS-поставки. Оператор уже выбрал ячейку `A-01-02` склада «Юг»; сканер ждёт штрихкод товара. Для текущего tenant существует пустая ячейка «Север», а штрихкод `WMS-WH-чужой` принадлежит складу другого tenant.

**Действия:** подряд сканировать пустую ячейку «Север», затем штрихкод `WMS-WH-чужой`, после каждого скана закрыть показанное уведомление.

**Ожидаемый результат:** после каждого скана показан понятный `ErrorNotice` без кода, UUID или текста исключения: для пустой ячейки — что в ней нет доступного товара поставки, для чужого склада — что этот склад недоступен. Контекст остаётся «Юг», ячейка `A-01-02` остаётся выбранной, подбор и остатки не меняются.

### S-03-TC-006 · Повтор быстрого скана создаёт один подбор и один перенос

**Начало:** поставка консолидируется на «Север». В ячейке `B-02-01` склада «Юг» есть одна свободная единица товара заказа; до операции в списке «Перемещения» нет записи для этого товара.

**Действия:** сканировать `B-02-01` и немедленно дважды подряд сканировать штрихкод товара, как это делает ТСД при повторной отправке после сетевой задержки.

**Ожидаемый результат:** экран один раз подтверждает `Взято: Склад Юг / ячейка B-02-01`; заказ подобран на одну единицу, а не на две. В «Перемещениях» видна ровно одна операция «из склада Юг» → «в склад Север» с двумя связанными сторонами в раскрытии. Не появляется второй перенос, отрицательный остаток или техническое сообщение о дубле.

### S-03-TC-007 · Закреплённую поставку нельзя переключить вторым окном

**Начало:** один оператор открыл одну FBS-поставку в двух вкладках. В первой вкладке он подтвердил хотя бы один подбор, и склад консолидации поставки «Север» уже закреплён; во второй вкладке до этого был открыт список выбора склада.

**Действия:** во второй вкладке выбрать «Юг» и попытаться продолжить работу с той же поставкой.

**Ожидаемый результат:** документ остаётся на складе «Север». Вместо изменения показано объяснение `Склад закреплён: подбор уже начат`; существующий подбор, движения и остатки не переписываются. Вторая вкладка может переключить только свой контекст списка после возврата из документа.

### S-03-TC-008 · Недостаток общего остатка блокирует повторное создание поставки

**Начало:** открыт диалог создания FBS-поставки: для выбранных заказов не хватает 11 шт. одного товара по всем операционным складам. Проверка остатков завершена и показывает разбиение `Нужно`, `Всего`, `Не хватает`.

**Действия:** быстро дважды нажать `Создать поставку`, затем обновить проверку остатков.

**Ожидаемый результат:** кнопка остаётся недоступной с понятной причиной, на экране виден один `ErrorNotice`: `Не хватает 11 шт. по 1 товару. Пополните остаток или уберите заказы из выборки`. Поставка не создаётся, заказы не резервируются, предупреждение не подменяется разрешающим из-за повторного нажатия.
