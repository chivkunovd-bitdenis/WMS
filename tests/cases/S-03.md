# Кейсы экрана S-03

База кейсов живёт между ночами. Номера постоянные и не переиспользуются: кейс, потерявший
смысл, помечается устаревшим, но не удаляется и номер не отдаёт.

Пройденным кейс считается только со скриншотом в `docs/evidence/<карточка>/`.
Проверка чтением кода, curl или пересказом разработчика не засчитывается.

Формат: `S-03-TC-001 · название` → начало, действия, точный ожидаемый результат.

## Кейсы

---

### S-03-TC-001 · Включить режим «Без распределения» до создания коробов

**Начало.** FF-оператор вошёл в систему. Открыл `/app/ff/fbs` → выбрал поставку WB
в стадии сборки → в боковой панели или воркспейсе перешёл на вкладку «Короба».
Список коробов пустой, ни один заказ не разложен.

**Действия:**
1. Найти чекбокс «Без распределения» в шапке вкладки «Короба».
2. Убедиться, что чекбокс визуально доступен (не затемнён, курсор не «запрещён»).
3. Щёлкнуть по чекбоксу, чтобы установить галочку.
4. Дождаться ответа сервера (спиннер или мгновенное обновление).
5. Обновить страницу (F5 или переоткрыть вкладку).

**Ожидаемый результат:**
- Шаг 3–4: чекбокс переключается в состояние «включено», ошибки не появляются.
- Шапка вкладки «Короба» меняется: текст вида «Распределено X из Y» **исчезает**;
  вместо него показан индикатор, отражающий включённый режим «Без распределения»
  (любое текстовое или визуальное обозначение режима).
- Шаг 5 (после обновления): галочка остаётся установленной, режим сохранён.

### S-03-TC-002 · Шапка не показывает «Распределено 0 из N» при включённом режиме

**Начало.** Режим «Без распределения» включён (выполнить TC-001 или взять поставку,
где галка уже стоит). Список коробов пустой — ни одного короба нет.

**Действия:**
1. Посмотреть на шапку вкладки «Короба».
2. Прочитать текст и найти числовые показатели прогресса.

**Ожидаемый результат:**
- В шапке **отсутствует** текст, содержащий слово «Распределено» рядом с дробью
  (вида «Распределено 0 из 155», «Распределено 0/155» или любой схожий паттерн).
- В шапке **отсутствуют** красные или предупреждающие числа, сигнализирующие о
  «нераспределённых» заказах.

*Этот кейс фиксирует дословную жалобу владельца: «шапка при включённом режиме
всё равно писала "Распределено ноль из ста пятидесяти пяти" и пугала оператора
красной цифрой».*

### S-03-TC-003 · Чекбокс доступен при наличии пустых коробов

**Начало.** FF-оператор на вкладке «Короба» поставки в стадии сборки. Режим
«Без распределения» **выключен**. В поставке есть хотя бы один короб, но ни один
заказ в короб **не разложен** (в коробе нет товарных позиций).

**Действия:**
1. Найти чекбокс «Без распределения» в шапке.
2. Проверить его визуальное состояние (активен или заблокирован).
3. Щёлкнуть по чекбоксу, чтобы установить галочку.

**Ожидаемый результат:**
- Шаг 2: чекбокс выглядит активным — не затемнён, атрибут `disabled` отсутствует.
- Шаг 3: галочка устанавливается, ошибки не появляются, сервер принимает запрос без 4xx.

*Это ключевое требование владельца: до фикса `disabled={workspace.boxes.length > 0}`
блокировало галку сразу при создании первого короба. Оператор оказывался в тупике.*

### S-03-TC-004 · Признак режима сохраняется после удаления всех коробов

**Начало.** Режим «Без распределения» **включён**. В поставке один или несколько
коробов — все пустые (заказов внутри нет).

**Действия:**
1. Удалить каждый короб по одному (кнопка удаления рядом с коробом → подтвердить).
2. Дождаться, пока список коробов станет полностью пустым.
3. Посмотреть на состояние чекбокса «Без распределения» и текст шапки.

**Ожидаемый результат:**
- Чекбокс остаётся в состоянии «включено».
- Шапка по-прежнему **не показывает** «Распределено X из Y».
- Признак режима не сброшен: удаление коробов не влияет на флаг поставки.

*Проверяет, что признак живёт на поставке (`boxes_without_distribution_at`), а не
в `creation_idempotency_key` первой партии коробов.*

### S-03-TC-005 · Признак режима переживает пересоздание коробов

**Начало.** Режим «Без распределения» **включён**. В поставке есть один пустой короб.

**Действия:**
1. Удалить существующий короб (кнопка удаления → подтвердить).
2. Дождаться, пока список коробов станет пустым.
3. Создать новый короб (кнопка «Добавить короб» или аналог → подтвердить).
4. Посмотреть на состояние чекбокса и текст шапки.

**Ожидаемый результат:**
- После шага 3: чекбокс остаётся включённым.
- Шапка не переключается в «Распределено X из Y».
- Новый короб создаётся, но признак «Без распределения» не сбрасывается.

*Главный регрессионный кейс инцидента 20.08: «режим переключали правкой в базе —
после первого раза короба пересоздались и признак слетел». До фикса приписка
`no-distribution:` терялась при любом новом `creation_idempotency_key`.*

### S-03-TC-006 · Выключить режим «Без распределения» через чекбокс

**Начало.** Режим «Без распределения» **включён**. Коробов нет или есть пустые короба.

**Действия:**
1. Снять галочку с чекбокса «Без распределения» (щелчок по чекбоксу).
2. Дождаться ответа сервера.
3. Обновить страницу (F5).

**Ожидаемый результат:**
- Шаг 1–2: чекбокс переключается в «выключено», ошибки нет.
- Шапка вкладки переходит в стандартный режим: отображает прогресс распределения
  (счётчик вида «Распределено X из Y шт» или аналогичный индикатор появляется).
- Шаг 3 (после обновления): галочка снята, режим остаётся выключенным.

### S-03-TC-007 · Чекбокс заблокирован, если заказы уже разложены в короба

**Начало.** Режим «Без распределения» **выключен**. В поставке есть короб, в который
разложен хотя бы один заказ (в коробе есть товарная позиция).

**Действия:**
1. Найти чекбокс «Без распределения» в шапке вкладки «Короба».
2. Попытаться щёлкнуть по чекбоксу.

**Ожидаемый результат:**
- Чекбокс **недоступен** (`disabled`, затемнён, либо щелчок не даёт эффекта)
  **или** сервер возвращает ошибку (HTTP 409), и фронт показывает понятное
  сообщение о том, что в короба уже разложены заказы.
- В любом случае режим **не** переключается в «включено».
- Пользователю виден явный индикатор причины блокировки (всплывающая подсказка,
  сообщение об ошибке или визуальная блокировка чекбокса).
