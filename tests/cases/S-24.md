# Кейсы экрана S-24

База кейсов живёт между ночами. Номера постоянные и не переиспользуются: кейс, потерявший
смысл, помечается устаревшим, но не удаляется и номер не отдаёт.

Пройденным кейс считается только со скриншотом в `docs/evidence/<карточка>/`.
Проверка чтением кода, curl или пересказом разработчика не засчитывается.

Формат: `S-24-TC-001 · название` → начало, действия, точный ожидаемый результат.

## Кейсы

---

### S-24-TC-001 · Один настоящий склад — на форме отгрузки нет селекта «Склад для заявки»

**Добавлен:** 04-warehouse-switch · 2026-08-22

**Начало:** Тенант с одним настоящим складом «Основной» и служебными `fbs-wb-*`.
Авторизован как `fulfillment_admin`.

**Действия:**

1. Перейти на `/app/ops/outbound` (экран `OutboundScreen`).
2. Нажать кнопку создания новой заявки на отгрузку.
3. Осмотреть форму создания.

**Ожидаемый результат:**

На форме нет поля «Склад для заявки» (ни в виде селекта, ни как скрытое поле с подписью).
Форма содержит поля, относящиеся к отгрузке. Заявка сохраняется с `warehouse_id`
единственного настоящего склада — это видно в строке созданной заявки в списке.

### S-24-TC-002 · Два настоящих склада — заявка отгрузки создаётся на складе из глобального контекста

**Добавлен:** 04-warehouse-switch · 2026-08-22

**Начало:** Тенант с двумя настоящими складами: «Основной» и «Дополнительный».
Авторизован как `fulfillment_admin`. Контекст шапки — «Дополнительный».

**Действия:**

1. Перейти на `/app/ops/outbound`.
2. Открыть форму создания заявки (без поля склада), заполнить минимальные поля, сохранить.
3. Найти созданную заявку в списке.

**Ожидаемый результат:**

Созданная заявка привязана к «Дополнительному» — это видно в строке заявки (колонка
«Склад» или подпись). На форме создания нет отдельного выбора склада — контекст берётся
из шапки. Переключение в шапке обратно на «Основной» убирает эту заявку из отображаемого
списка (фильтрация по складу работает).

### S-24-TC-003 · Нет настоящих складов — форма отгрузки заблокирована с Alert warning

**Добавлен:** 04-warehouse-switch · 2026-08-22 (ломающий)

**Начало:** Тенант, у которого в базе только служебные `fbs-wb-*` записи и нет ни одного
настоящего склада. Авторизован как `fulfillment_admin`.

**Действия:**

1. Перейти на `/app/ops/outbound`.
2. Попытаться открыть форму создания заявки на отгрузку.

**Ожидаемый результат:**

Кнопка создания заявки недоступна (disabled) или форма создания не открывается.
На экране виден Alert severity `warning` с той же формулировкой, что на приёмке:
«Нет доступного склада для создания заявки. Обратитесь к фулфилменту.» Текст не отличается
от S-22-TC-003 — единая формулировка на всех экранах (R-10). Никаких ошибок 500 нет.

### S-24-TC-004 · Обновить страницу отгрузки после переключения склада — список остаётся на выбранном складе

**Добавлен:** 04-warehouse-switch · 2026-08-22 (ломающий)

**Начало:** Тенант с двумя складами. Авторизован как `fulfillment_admin`. Контекст шапки —
«Дополнительный» (переключён вручную). Открыт `/app/ops/outbound`, виден список заявок
«Дополнительного».

**Действия:**

1. Нажать F5 (полный перезагрузка страницы).
2. Дождаться отрисовки.

**Ожидаемый результат:**

Одно из двух допустимых поведений: (а) контекст сохранился в localStorage/cookie и после
перезагрузки шапка по-прежнему показывает «Дополнительный», список фильтруется по нему —
OR — (б) контекст сбрасывается на «первый настоящий склад» (Основной), но это видно явно
в шапке, и список обновился под него. Недопустимо: в шапке «Дополнительный», а список
показывает заявки «Основного» — рассинхронизация контекста и данных.
