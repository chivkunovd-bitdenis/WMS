# Кейсы экрана S-14

База кейсов живёт между ночами. Номера постоянные и не переиспользуются: кейс, потерявший
смысл, помечается устаревшим, но не удаляется и номер не отдаёт.

Пройденным кейс считается только со скриншотом в `docs/evidence/<карточка>/`.
Проверка чтением кода, curl или пересказом разработчика не засчитывается.

Формат: `S-14-TC-001 · название` → начало, действия, точный ожидаемый результат.

## Кейсы

---

### S-14-TC-001 · Задание упаковки заблокировано, если код объявлен отсутствующим у WB

**Начало.** Задание упаковки связано с заказом, у которого прошла orphan-сверка: два тика WB-молчания подтверждены, `meta_status = 'missing'`, `marking_code_id = null`. `fbs_orders.metadata_delivery_allowed = false`.

**Действия.**
1. Открыть `/app/ff/packaging` (S-14, экран упаковки).
2. Найти задание, связанное с этим заказом.

**Ожидаемый результат.**
- Задание **не редактируемо**: кнопка начала упаковки (или аналогичное действие «взять в работу») серая или отсутствует.
- Задание не отображается среди готовых к упаковке.
- Видно, что маркировка заказа не подтверждена (существующий UI-блокировщик Б-11 по `taskEditable`).

---

### S-14-TC-002 · Задание упаковки редактируемо при подтверждённом коде WB

**Начало.** Задание упаковки связано с заказом, у которого все обязательные `kind` подтверждены WB: `meta_status = 'accepted'` для каждой строки `fbs_order_marking`. `fbs_orders.metadata_delivery_allowed = true`.

**Действия.**
1. Открыть `/app/ff/packaging` (S-14).
2. Найти задание, связанное с этим заказом.

**Ожидаемый результат.**
- Задание **редактируемо**: кнопка «Начать упаковку» (или аналогичная) активна, не серая.
- Нет блокирующего сообщения о маркировке.

---

### S-14-TC-003 · Orphan происходит пока оператор упаковывает — бэк блокирует подтверждение

**Начало.** Задание упаковки **редактируемо** (оператор успел войти в него до orphan). `meta_status = 'assigned'`, `metadata_delivery_allowed = true` на момент открытия задания. Пока оператор заполняет поля упаковки (коробы, вес), автополлер проводит второй тик orphan-сверки: `metadata_delivery_allowed` меняется на `false`, `meta_status = 'missing'`.

**Действия.**
1. Открыть `/app/ff/packaging` (S-14), найти задание, нажать «Начать упаковку».
2. Не завершая упаковку, дождаться двух тиков WB-молчания (orphan завершён в БД).
3. Нажать кнопку «Завершить упаковку» (или аналогичное финальное действие).

**Ожидаемый результат.**
- Бэкенд при подтверждении упаковки **перепроверяет** `metadata_delivery_allowed` — видит `false`.
- Ответ сервера — ошибка (HTTP 4xx) с текстом о том, что маркировка заказа более не подтверждена WB.
- Задание **не переходит** в завершённое состояние.
- UI показывает сообщение об ошибке. После обновления страницы (F5) задание отображается как нередактируемое (Б-11 по `taskEditable`).
- В `packaging_task` или `fbs_supply_orders` запись о завершении **не создаётся**.

---

### S-14-TC-004 · Задание с кодом `printed` после orphan-консервации — не редактируемо, задание в S-15

**Начало.** Заказ имел код `printed` (`FbsOrderMarking.marking_code_id` заполнен, `MarkingCode.status = 'printed'`). После двух тиков WB-молчания прошла orphan-сверка: `meta_status = 'missing'`, `marking_code_id = null`, физический статус кода `printed` **сохранён** (консервация — не возвращён в `available`).

**Действия.**
1. Открыть `/app/ff/packaging` (S-14).
2. Найти задание упаковки для этого заказа.

**Ожидаемый результат.**
- Задание **не редактируемо** (Б-11 срабатывает по `meta_status = 'missing'`).
- Задание не отображается среди активных/доступных для упаковки.
- В `marking_codes` запись: `status = 'printed'` (не изменился, не стал `available`).
- В `marking_code_events` запись `wb_orphaned` для этого кода.
- Заказ появляется в S-15 «Ожидает маркировки» (c пустым `marking_code_id`) — оператор должен сканировать новый КИЗ.
