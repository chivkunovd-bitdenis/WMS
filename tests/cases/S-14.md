# Кейсы экрана S-14

База кейсов живёт между ночами. Номера постоянные и не переиспользуются: кейс, потерявший
смысл, помечается устаревшим, но не удаляется и номер не отдаёт.

Пройденным кейс считается только со скриншотом в `docs/evidence/<карточка>/`.
Проверка чтением кода, curl или пересказом разработчика не засчитывается.

Формат: `S-14-TC-001 · название` → начало, действия, точный ожидаемый результат.

## Кейсы

### S-14-TC-001 · Упаковка не показывает ложную готовность при отсутствии кода у WB

**Начало.** Оператор FF вошёл в систему и открыл `/app/ff/packaging`. В задании упаковки
есть FBS-заказ `WB-1002` с локально привязанным кодом `010123456789012121MISSING`; после
проверки маркировки Wildberries не вернул этот код.

**Действия.** Оператор открывает задание упаковки и выполняет проверку готовности к передаче
в Wildberries.

**Ожидаемый результат.** Экран не показывает зелёное «всё в порядке» для заказа
`WB-1002`. В видимом результате проверки указано, что код отсутствует в ответе Wildberries;
оператор не может принять этот результат за подтверждённую WB маркировку.

### S-14-TC-002 · Подтверждённая Wildberries маркировка проходит проверку готовности

**Начало.** Оператор FF вошёл в систему и открыл `/app/ff/packaging`. В задании упаковки
есть FBS-заказ `WB-1001` с кодом `010123456789012121ABC`; последняя проверка маркировки
вернула от Wildberries решение `filled`.

**Действия.** Оператор открывает задание упаковки и выполняет проверку готовности к передаче
в Wildberries.

**Ожидаемый результат.** Для заказа `WB-1001` экран показывает успешный результат проверки
маркировки без предупреждения о расхождении. Этот заказ не помечен отсутствующим у WB и не
блокируется по причине маркировки.
