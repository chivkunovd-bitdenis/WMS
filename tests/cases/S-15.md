# Кейсы экрана S-15

База кейсов живёт между ночами. Номера постоянные и не переиспользуются: кейс, потерявший
смысл, помечается устаревшим, но не удаляется и номер не отдаёт.

Пройденным кейс считается только со скриншотом в `docs/evidence/<карточка>/`.
Проверка чтением кода, curl или пересказом разработчика не засчитывается.

Формат: `S-15-TC-001 · название` → начало, действия, точный ожидаемый результат.

## Кейсы

### S-15-TC-001 · Отклонённый FBS-код не попадает в очередь печати чужой упаковки

**Начало.** Оператор авторизован. В очереди `/app/ff/packaging/pending-marking`
есть строка обычного задания упаковки без напечатанного ЧЗ. Для отдельного
FBS-заказа WB вернул отказ привязанного кода.

**Действия.**

1. Открыть очередь незавершённой маркировки и отметить строку обычного задания.
2. Дождаться синхронизации отказа WB по FBS-заказу и обновить очередь.
3. Нажать печать выбранных кодов.

**Ожидаемый результат.** В очереди остаётся только исходная строка обычного
задания: отклонённый код FBS не добавляется в неё, не подменяет выбранную строку
и не печатается вместо неё. Выбранная строка продолжает печататься штатно либо
получает понятную ошибку своего задания; очередь не показывает технические
`decision`/`reason` и не меняет счётчик как будто работа выполнена.
