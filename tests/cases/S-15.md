# Кейсы экрана S-15

База кейсов живёт между ночами. Номера постоянные и не переиспользуются: кейс, потерявший
смысл, помечается устаревшим, но не удаляется и номер не отдаёт.

Пройденным кейс считается только со скриншотом в `docs/evidence/<карточка>/`.
Проверка чтением кода, curl или пересказом разработчика не засчитывается.

Формат: `S-15-TC-001 · название` → начало, действия, точный ожидаемый результат.

## Кейсы

### S-15-TC-001 · Заказ исчезает из списка ожидающих маркировки после подтверждения WB — без ручной перезагрузки

**Карточка:** 02-verdikt-screen · смежный (S-15 задет картой 01 через мета-данные)

**Начало.** Экран `PackagingPendingMarkingWorklist` (S-15). Список показывает несколько
заказов в статусе ожидания вердикта WB («Статус уточняется» / «WB проверяет»).

**Действия.**
1. Дождаться следующего тика автополлера (без ручных действий).
2. WB возвращает `decision = "accepted"` для одного из заказов.

**Ожидаемый результат.** Подтверждённый заказ **исчезает из ворклиста** автоматически —
без нажатия «Обновить» и без перезагрузки страницы. Счётчик ожидающих в шапке экрана
уменьшается на 1. Остальные заказы остаются на месте без перемигивания. Никаких
дублирующих строк не появляется.

---

### S-15-TC-002 · Все заказы подтверждены WB — ворклист показывает пустое состояние, не падает

**Карточка:** 02-verdikt-screen · смежный

**Начало.** Экран `PackagingPendingMarkingWorklist`. В списке был один заказ. WB
подтверждает его, и список опустел.

**Действия.**
1. Дождаться автополлера после последнего подтверждения WB.

**Ожидаемый результат.** Экран показывает **пустое состояние**: например, «Все коды
подтверждены Wildberries» или иллюстрация-заглушка из дизайн-системы. Нет зависшего
спиннера, нет JavaScript-ошибки в консоли, нет белого экрана. Кнопки или навигация,
доступные на пустом экране, работают корректно.

---

### S-15-TC-003 · Маркировочный код получает событие wb_orphaned — заказ возвращается в ворклист

**Карточка:** 02-verdikt-screen · смежный

**Начало.** Экран `PackagingPendingMarkingWorklist`. Заказ X ранее был подтверждён и
ушёл из списка. Карточка 01 вводит событие `wb_orphaned` (WB «потерял» метаданные по коду).
Код возвращается в состояние `available`, статус маркировки сбрасывается.

**Действия.**
1. Автополлер фиксирует сброс статуса и событие `wb_orphaned`.
2. Смотреть ворклист.

**Ожидаемый результат.** Заказ X **снова появляется** в ворклисте — он вернулся в состояние
«нужно заново привязать код и дождаться WB». Заказ не задвоился: если он уже был в списке
в момент сброса — присутствует ровно одной строкой. Чип в строке заказа показывает
«Нужен ЧЗ» (красный) — код снят, требуется повторное сканирование. Оператор видит
ситуацию без перезагрузки страницы.
