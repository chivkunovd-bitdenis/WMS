# Кейсы экрана S-15

База кейсов живёт между ночами. Номера постоянные и не переиспользуются: кейс, потерявший
смысл, помечается устаревшим, но не удаляется и номер не отдаёт.

Пройденным кейс считается только со скриншотом в `docs/evidence/<карточка>/`.
Проверка чтением кода, curl или пересказом разработчика не засчитывается.

Формат: `S-15-TC-001 · название` → начало, действия, точный ожидаемый результат.

## Кейсы

### S-15-TC-001 · Пустая фоновая сверка не заменяет список ожидающих маркировки

**Начало.** Сотрудник ФФ авторизован. На момент очередного фонового запуска нет
заданий, которые нужно сверять с Wildberries.

**Действия.**

1. Открыть `/app/ff/packaging/pending-marking`.
2. Дождаться очередного фонового запуска и обновить страницу браузера.
3. Просмотреть список и все элементы вокруг него.

**Ожидаемый результат.** Остаётся текущее состояние списка ожидающих маркировки: оно
не заменяется пустым состоянием фоновой сверки. На странице нет нового сообщения
«нечего проверять», баннера, уведомления, кнопки запуска сверки, фильтра, вкладки или
отдельного экрана.

### S-15-TC-002 · Повторная сверка не дублирует и не убирает ожидающее задание

**Начало.** Сотрудник ФФ авторизован. В `/app/ff/packaging/pending-marking` есть
задание с локально привязанным КИЗ. Два последовательных либо одновременно начатых
фоновых запуска получают одинаковый успешный ответ WB: требуемая маркировка указана
без значения.

**Действия.**

1. Открыть список ожидающих маркировки в двух вкладках браузера.
2. Дождаться завершения обоих запусков и обновить каждую вкладку.
3. Повторить обновление после ещё одного такого же ответа WB.

**Ожидаемый результат.** Список не содержит двух экземпляров одного задания и не
теряет его только из-за фоновой сверки. КИЗ остаётся связанным с исходным товаром и
недоступным как свободный для другого задания; повторный ответ не создаёт новый
экранный сценарий возврата. Структура списка, существующие действия и пустое состояние
не меняются, пока сотрудник не завершит работу по обычному процессу.
