# Кейсы экрана S-20

База кейсов живёт между ночами. Номера постоянные и не переиспользуются: кейс, потерявший
смысл, помечается устаревшим, но не удаляется и номер не отдаёт.

Пройденным кейс считается только со скриншотом в `docs/evidence/<карточка>/`.
Проверка чтением кода, curl или пересказом разработчика не засчитывается.

Формат: `S-20-TC-001 · название` → начало, действия, точный ожидаемый результат.

## Кейсы

### S-20-TC-001 · Повторная раскладка не списывает один остаток дважды

**Начало.** В незавершённой приёмке короб `INB-0003` содержит товар A с текущим
остатком `9`. Два оператора открыли одну и ту же строку для раскладки на
`/app/ff/sorting`; в отдельной вкладке доступен каталог.

**Действия.** Первый оператор подтверждает полную раскладку `9` штук. Сразу
после этого второй оператор пытается подтвердить ещё `9` штук из того же
короба, затем в каталоге сканируется `INB-0003`.

**Ожидаемый результат.** Первая подтверждённая раскладка уменьшает остаток до
нуля один раз. Вторая операция не создаёт отрицательный остаток и не проводит
дублирующее движение: оператор видит понятное сообщение, что доступного товара
в коробе уже нет, и остаётся на корректном состоянии сортировки. Повторный
скан в каталоге показывает «Товар из короба уже разложен», без исторических
строк как текущего состава.
