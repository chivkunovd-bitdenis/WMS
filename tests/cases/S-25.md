# Кейсы экрана S-25

База кейсов живёт между ночами. Номера постоянные и не переиспользуются: кейс, потерявший
смысл, помечается устаревшим, но не удаляется и номер не отдаёт.

Пройденным кейс считается только со скриншотом в `docs/evidence/<карточка>/`.
Проверка чтением кода, curl или пересказом разработчика не засчитывается.

Формат: `S-25-TC-001 · название` → начало, действия, точный ожидаемый результат.

## Кейсы

### S-25-TC-001 · Запись автопереноса при кросс-складском подборе появляется в журнале переносов

**Добавлен:** 04-warehouse-switch · 2026-08-22

**Начало:** Тенант с двумя настоящими складами: «Основной» и «Дополнительный».
Выполнен кросс-складской подбор: товар «A-003» (2 шт.) подобран из ячейки
«Дополнительного» склада в рамках поставки FBS «Основного» склада (сценарий S-03-TC-008).
Авторизован как `fulfillment_admin`.

**Действия:**

1. Перейти на `/app/ops/transfers` (экран `TransfersScreen`).
2. Найти в журнале запись, созданную в момент кросс-складского подбора.

**Ожидаемый результат:**

В журнале переносов видна новая строка. В ней отображаются:
- Дата и время, совпадающие с моментом подбора.
- Склад-источник: «Дополнительный».
- Склад-приёмник: «Основной».
- Товар: «A-003».
- Количество: 2.
- Оператор подбора (имя пользователя, выполнившего подбор).
- Кликабельная ссылка или идентификатор поставки-виновника.

### S-25-TC-002 · Тип «Автоперенос при подборе» отображается как StatusChip с синим тоном

**Добавлен:** 04-warehouse-switch · 2026-08-22

**Начало:** В журнале переносов есть хотя бы одна запись автопереноса при подборе
(создана через сценарий S-03-TC-008). Авторизован как `fulfillment_admin`.
Открыт `/app/ops/transfers`.

**Действия:**

1. Найти строку с автопереносом в журнале.
2. Посмотреть на колонку «Тип» (или аналогичную).

**Ожидаемый результат:**

В колонке «Тип» виден чип `StatusChip` с текстом «Автоперенос при подборе».
Цвет чипа — синий (severity `info`). Рядом могут быть записи «Ручной перенос»
с другим (нейтральным, серым) тоном — они не синие.

### S-25-TC-003 · Фильтр по типу «Автоперенос при подборе» в FilterBar

**Добавлен:** 04-warehouse-switch · 2026-08-22

**Начало:** В журнале переносов есть хотя бы два автопереноса при подборе и хотя бы
один ручной перенос. Авторизован как `fulfillment_admin`. Открыт `/app/ops/transfers`.

**Действия:**

1. В `FilterBar` найти фильтр по типу переноса.
2. Выбрать значение «Автоперенос при подборе».
3. Дождаться обновления списка.

**Ожидаемый результат:**

В журнале остались только записи с типом «Автоперенос при подборе» (синие чипы).
Строки «Ручной перенос» из списка пропали. Сбросить фильтр (выбрать «Все типы» или
снять галочку) — в списке снова появляются все типы переносов.

### S-25-TC-004 · Строка автопереноса содержит ссылку на поставку-источник

**Добавлен:** 04-warehouse-switch · 2026-08-22

**Начало:** В журнале переносов есть запись автопереноса, созданная при подборе в
поставку FBS № «П-0042». Авторизован как `fulfillment_admin`. Открыт `/app/ops/transfers`.

**Действия:**

1. Найти строку автопереноса, связанного с поставкой «П-0042».
2. Нажать на ссылку поставки в этой строке.

**Ожидаемый результат:**

Браузер переходит на экран воркспейса поставки «П-0042» (или открывает модалку с
деталями поставки). В URL или заголовке виден идентификатор поставки «П-0042».

### S-25-TC-005 · Ссылка на несуществующую/удалённую поставку из строки автопереноса — graceful 404

**Добавлен:** 04-warehouse-switch · 2026-08-22 (ломающий)

**Начало:** В журнале переносов есть строка автопереноса, связанная с поставкой,
которая была удалена или supply_id которой не существует в базе (например, данные
очищены вручную в рамках отладки). Авторизован как `fulfillment_admin`.
Открыт `/app/ops/transfers`.

**Действия:**

1. Найти строку автопереноса с несуществующей поставкой.
2. Нажать на ссылку поставки.

**Ожидаемый результат:**

Браузер не падает в JS-крэш. Открывается либо WMS-страница 404 («Поставка не найдена»),
либо Alert error в модалке/воркспейсе («Поставка с таким ID не существует»). Сам журнал
переносов при этом не ломается и остаётся интерактивным — остальные строки продолжают
работать нормально.

### S-25-TC-006 · Два оператора конкурентно делают кросс-складской подбор одного товара — нет двойного списания

**Добавлен:** 04-warehouse-switch · 2026-08-22 (ломающий)

**Начало:** Тенант с двумя складами. Ячейка «Д-02-01» «Дополнительного» склада содержит
ровно 2 шт. товара «A-010». Две поставки FBS «Основного» склада, каждой нужно по 2 шт.
«A-010». Оператор-A работает с поставкой № 11, Оператор-B — с поставкой № 12. Оба видят
`ScannerLine` активным.

**Действия:**

1. Оператор-A вводит баркод ячейки «Д-02-01» в `ScannerLine`.
2. Одновременно (параллельно) Оператор-B вводит тот же баркод в своей поставке.
3. Дождаться ответа обоих запросов.

**Ожидаемый результат:**

Один из операторов получает успешный тост «Товар перенесён со склада Дополнительный»
и подбор регистрируется. Второй оператор получает тост или Alert error «Недостаточно
остатка в ячейке» (не ошибку 500). Остаток ячейки «Д-02-01» после обоих запросов — 0,
но **не -2** (оптимистичная блокировка или транзакция на сервере не даёт уйти в минус).
В журнале переносов (S-25) — ровно одна запись автопереноса для этой ячейки.
