# Кейсы экрана S-25

База кейсов живёт между ночами. Номера постоянные и не переиспользуются: кейс, потерявший
смысл, помечается устаревшим, но не удаляется и номер не отдаёт.

Пройденным кейс считается только со скриншотом в `docs/evidence/<карточка>/`.
Проверка чтением кода, curl или пересказом разработчика не засчитывается.

Формат: `S-25-TC-001 · название` → начало, действия, точный ожидаемый результат.

## Кейсы

### S-25-TC-001 · Межскладской подбор показан одним понятным перемещением

**Начало:** оператор ФФ вошёл в систему. Для поставки со складом консолидации «Север» ранее подтверждён подбор товара из ячейки склада «Юг».

**Действия:** открыть «Перемещения», выбрать «Север» в строке `Склад`, раскрыть строку перемещения, связанную с этим подбором.

**Ожидаемый результат:** в списке показано одно раскрываемое перемещение с понятными именами «из склада Юг» и «в склад Север». В раскрытии видны связанные стороны операции, но не UUID группы перемещения.

### S-25-TC-002 · Отмена подбора возвращает обе стороны межскладского переноса

**Начало:** для FBS-поставки «Север» подтверждён подбор одной единицы из ячейки склада «Юг». В «Перемещениях» есть одна раскрываемая операция «из склада Юг» → «в склад Север».

**Действия:** в рабочем месте поставки отменить этот подбор, затем обновить список «Перемещения» для «Юг» и для «Север».

**Ожидаемый результат:** подбор снят, единица снова доступна в исходной ячейке «Юг», а сортировка «Север» не содержит её остатка. В журнале отражена одна понятная обратная операция; нет зависшей только входящей или только исходящей стороны, двойного возврата или отрицательного остатка.
