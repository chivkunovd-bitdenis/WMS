# Кейсы экрана S-28

База кейсов живёт между ночами. Номера постоянные и не переиспользуются: кейс, потерявший
смысл, помечается устаревшим, но не удаляется и номер не отдаёт.

Пройденным кейс считается только со скриншотом в `docs/evidence/<карточка>/`.
Проверка чтением кода, curl или пересказом разработчика не засчитывается.

Формат: `S-28-TC-001 · название` → начало, действия, точный ожидаемый результат.

## Кейсы

---

### S-28-TC-001 · На форме создания заявки приёмки в портале селлера нет поля «Склад»

**Добавлен:** 04-warehouse-switch · 2026-08-22

**Начало:** Тенант с двумя настоящими складами. Авторизован как `fulfillment_seller` (селлер).

**Действия:**

1. Открыть экран `SellerInboundDraftScreen` (S-28).
2. Нажать кнопку создания новой заявки на приёмку / открыть черновик.
3. Осмотреть форму.

**Ожидаемый результат:**

На форме нет поля выбора склада (ни селекта, ни автозаполненного поля с именем склада).
Форма содержит только товарные позиции и прочие поля заявки. Заявка при создании
получает склад автоматически (первый настоящий склад ФФ) без вмешательства селлера.

### S-28-TC-002 · Нет настоящих складов — форма создания заявки селлера заблокирована с Alert warning

**Добавлен:** 04-warehouse-switch · 2026-08-22

**Начало:** Тенант, у которого нет ни одного настоящего склада (только служебные
`fbs-wb-*`). Авторизован как `fulfillment_seller`.

**Действия:**

1. Открыть `SellerInboundDraftScreen` (S-28).
2. Попытаться создать новую заявку на приёмку.

**Ожидаемый результат:**

Кнопка создания недоступна или форма не открывается. Виден Alert severity `warning`
с текстом «Нет доступного склада для создания заявки. Обратитесь к фулфилменту.»
(дословно — та же формулировка, что используется на `InboundScreen` S-22-TC-003).
Технических ошибок на экране нет.

### S-28-TC-003 · Повторная отправка формы черновика двойным кликом «Сохранить» — заявка создаётся один раз

**Добавлен:** 04-warehouse-switch · 2026-08-22 (ломающий)

**Начало:** Тенант с одним настоящим складом. Авторизован как `fulfillment_seller`.
Открыт черновик заявки на приёмку (`SellerInboundDraftScreen`), заполнен минимально
(хотя бы один товар).

**Действия:**

1. Нажать «Сохранить» / «Отправить».
2. Немедленно (до появления индикатора загрузки или результата) нажать ещё раз.

**Ожидаемый результат:**

В системе создаётся ровно одна заявка на приёмку. Кнопка «Сохранить» уходит в disabled
после первого клика. Второй клик не порождает дублирующего запроса `POST /inbound`.
В списке заявок у оператора ФФ видна одна строка, а не две с одинаковыми данными.
