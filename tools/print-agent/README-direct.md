# WMS Print — прямая печать из Chrome

Распакуйте весь архив, запустите `wms-print` (Windows: `wms-print.exe`) и оставьте
консоль открытой. Программа использует **системный принтер по умолчанию**. Выбирать
модель, адрес, протокол или очередь в WMS Print не нужно. macOS-пакет содержит один
нативный исполняемый файл; Python на Mac не требуется.

WMS передаёт размер этикетки вместе с PNG. macOS получает `media=Custom.58x40mm`
для этикетки 58×40 мм; Windows получает размер в параметрах одного задания
(DEVMODE), не меняя сохранённые настройки принтера. Печатается один экземпляр,
пропорции QR сохраняются. Физический формат установленного рулона неизвестного
устройства программа определить не может.

Chrome при первом обращении сайта к локальной программе может запросить доступ
к локальному компьютеру. Программа не меняет настройки защиты браузера или ОС.
Сборка без Developer ID/notarization может потребовать системное разрешение запуска.

## История и восстановление

Откройте **http://127.0.0.1:17843/** на том же компьютере. Программа сама не открывает
вкладку. Эта локальная страница работает без выбранного принтера: она показывает
сохранённые задания, их ключи и переданные WMS сведения о заказе, исходные PNG,
размеры, выбранную при отправке очередь, квитанции и причины последних наблюдений.
Поиск работает по заказу, скану, штрихкоду и ключу. Файлы не удаляются после
успешного HTTP-ответа браузеру.

- **Сохранено** — PNG и описание уже на диске; передача ещё не началась. Такие
  задания продолжаются после перезапуска. **Отказ до отправки** можно повторить
  кнопкой «Отправить сохранённое задание»: используются прежние PNG и ключ.
- **Передаётся / исход неизвестен** — отправка могла состояться. Кнопка «Сверить
  с очередью» только читает системную очередь. Новые задания получают уникальное
  имя, по которому программа ищет ровно одну исходную запись после потери квитанции.
  Отсутствие записи, несколько совпадений или недоступность очереди не доказывают,
  что этикетка не вышла, и не запускают скрытую повторную печать.
- **Принято, ожидает, обрабатывается, приостановлено, остановлено, отменено,
  ошибка, завершено** — наблюдаемые состояния системной очереди. Доступные причины
  очереди и устройства находятся в полных сведениях. Даже `completed` может
  означать передачу дальше в устройство: **выход и читаемость бумаги не подтверждены**.
  Универсальные CUPS/Windows API не предоставляют надёжного подтверждения для всех
  принтеров; `physicalConfirmationSupported: false` отражает эту границу.
- После сверки принтера и очереди оператор может явно выбрать **«Создать повторную
  этикетку»**, подтвердив риск дубликата. Новая операция получает отдельный ключ,
  хранит связь с исходной и точную копию PNG/размеров/контекста. Старый исход не
  переписывается. Если HTTP-ответ потерян, повтор этого же действия использует
  сохранённый ключ дочерней операции. Исходную операцию с уже созданной дочерней
  копией нельзя незаметно отправить ещё раз через обычный retry.

Системная очередь проверяется в фоне; ручная сверка запрашивает актуальное
наблюдение. PNG сохраняется до обращения к очереди. Сбой диска до передачи
останавливает передачу; сбой после неё сохраняет неопределённость и запрещает
повтор наугад. При сообщении о недоступном диске освободите место и перезапустите
программу, сохранив каталог журнала. При повреждении записи исходник остаётся на
диске, ключ защищён от слепого повтора, остальные читаемые записи доступны.

## Постоянные данные и старый журнал

Mac: `~/Library/Application Support/WMS Print/direct/`:

- прежний `direct-jobs.json` остаётся на месте и не переписывается;
- `jobs-v2/` содержит JSON каждого задания и точную PNG с именем SHA256 от ключа;
- `runtime.lock` защищает журнал от одновременного использования двумя процессами.

Windows: каталог `direct` внутри постоянного каталога WMS Print (обычно
`%LOCALAPPDATA%\WMS Print\direct`); точное изображение и описание записываются
одной транзакцией в `direct-jobs.sqlite3`. Старые строки расширяются без удаления.

Старые записи содержали только хеш и квитанцию либо неизвестный исход. Изображение,
размер и отсутствующий контекст из них не восстанавливаются. Совместимы старые хеши
PNG и хеши PNG с размером из релизов `.4/.5`; их повтор не создаёт новое задание.
Нельзя по одной старой квитанции доказать, что бумага вышла. Старый номер CUPS без
уникального имени также нельзя надёжно связать с записью после повторного
использования номеров очередью.

Для разбора ночного инцидента сначала сохраните копию всего каталога `direct`,
получите список `/jobs` и исходные JSON/PNG. `lpstat -W all -o` и сведения системной
очереди — чтение, не повтор печати. Непрозрачный `scan_id` связывается с заказом
через записи WMS. Не удаляйте журнал и не отправляйте все неизвестные задания заново:
без журналов рабочего Mac и наблюдения оператора нельзя установить, какие именно
ночные этикетки не вышли.

## Локальный HTTP-контракт

Разрешены прежние WMS origins; сервер слушает только `127.0.0.1`. Все изменения
требуют `X-WMS-Print: 1`. Ключ в URL кодируется через `encodeURIComponent`.

- `GET /health`: версия протокола `2`; доступность истории не зависит от принтера.
- `POST /print`: `{idempotencyKey,imageDataUrl,widthMm,heightMm,context?,protocolVersion:2}`.
  После долговечного сохранения возвращает `202` и задание. Передача идёт независимо
  от жизни HTTP-соединения. Повтор того же ключа/PNG/размера возвращает прежний исход.
  Иной PNG или размер под тем же ключом — конфликт.
- Старый вызов без `protocolVersion:2` ждёт настоящую квитанцию до 18 секунд и
  возвращает `200 {receipt,...}` на обычном успешном пути. Локальный ключ не подменяет
  квитанцию ОС. Отказ, неизвестность, timeout или известное негативное состояние
  дают ошибку, при этом задание остаётся в истории.
- `GET /jobs`, `GET /jobs/{key}`, `GET /jobs/{key}/image`: история, детали, точная PNG.
  Детали включают `reprints` — сохранённые дочерние операции. `hash` связывает точные
  PNG и размеры; сравнение с родителем выполняется внутри одного runtime, поскольку
  старые Mac/Windows версии по-разному форматировали числа при хешировании.
- `POST /jobs/{key}/reconcile`: читает очередь, сохраняет время/причину наблюдения.
  `GET` возвращает последнее сохранённое наблюдение; оно не запускает печать.
- `POST /jobs/{key}/retry`: только доказанно неотправленное сохранённое задание.
- `POST /jobs/{key}/reprint`: `{idempotencyKey:newKey,acknowledgeDuplicateRisk:true}`;
  явная связанная копия. Повтор HTTP с тем же `newKey` не создаёт третью копию.

Контекст сохраняет только поля заказа/скана/поставки/клиента/оператора/маркетплейса;
токены авторизации в журнал не передаются. `paperStatus` всегда `unconfirmed`, пока
нет отдельного надёжного физического подтверждения. Получение квитанции не
эквивалентно физической приёмке этикетки.

## Проверки и пакет

```sh
python3 -m unittest discover -s tools/print-agent -p 'test_wms_print_direct.py'
python3 -m unittest discover -s tools/print-agent -p 'test_macos_native.py'
python3 tools/print-agent/build_console.py
```

Тесты используют отдельные временные каталоги и тестовые очереди. Они проверяют
350 параллельных операций, дубли одного ключа, реальные аварийные выходы процесса,
сбой записи до и после передачи, потерю HTTP-ответа, unique-title reconciliation,
статусы/причины CUPS, старые хеши, размеры Windows, локальный HTTP и связанные
повторы. `--self-test` у Mac-пакета также не обращается к рабочему принтеру.

Пакет собирается только из закоммиченных исходников. Проверенный SHA находится
в `build.json`. Windows x64, Mac arm64 и Intel собираются в
`.github/workflows/print-console-package.yml`. Сборка и тесты не доказывают ни
публикацию нового сайта, ни выкладку пакета, ни выход реальной этикетки.
