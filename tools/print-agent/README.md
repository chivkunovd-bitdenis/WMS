# WMS-442 — программа печати на ПК, продолжение WMS-402

ТСД отправляет намерение печати в WMS. Программа на компьютере сама получает
предназначенное ей задание по HTTPS и передаёт неизменяемый файл в выбранную
установленную очередь ОС. Входящих портов, расширения браузера и копирования
токена сотрудника нет. Драйвер устанавливается обычным способом через ОС.

## Пакет и первый запуск

Пакет содержит программу вместе с Python и компонентами печати: сотруднику не
нужно устанавливать Python, pip, WSL или программу просмотра PDF. Для macOS
arm64 это `WMS-Print-macOS.zip`: распакуйте его и запустите
`Подключить WMS.command`. Он копирует программу в `~/Applications/WMS Print` и
открывает настройку в терминале. Для Windows x64 это обычный
`WMS-Print-Setup-Windows-x64.exe`: запустите установщик из своей учётной записи,
а затем «Подключить WMS Print» из меню Пуск. Он устанавливается в
`%LocalAppData%\Programs\WMS Print` и появляется в штатном списке удаления
программ. Введите HTTPS-адрес API WMS, выберите номер из списка установленных
очередей. Если очередей нет, сначала добавьте принтер и его драйвер в
настройках ОС.

Программа покажет временный код подключения. Администратор WMS выбирает склад,
проверяет имя очереди в предварительном просмотре кода и подтверждает подключение.
Код действует 15 минут. Программа получает только доступ к собственной очереди
печати; обычные API товаров, складов и пользователей этот доступ отвергают.
После подключения программа сразу передаёт работу фоновому процессу. На macOS
это LaunchAgent, на Windows — задача Планировщика заданий текущего пользователя:
оба запускают программу при следующем входе и восстанавливают её после аварийного
завершения. Закрытие окна настройки и браузера не останавливает печать. Если ОС
не смогла зарегистрировать этот механизм, настройка завершается ошибкой и не
выдаёт себя за полностью подключённую.

Повторный запуск настройки восстанавливает уже сохранённое подключение, включая
потерю первого ответа WMS. Для новой очереди используйте `--reconnect`: старые
задания сохраняют прежнее назначение и не пересылаются на новый принтер.

Релизная матрица пакетов: **Windows 10 22H2 x64**, **Windows 11 x64** и
**macOS arm64**. `build.json` внутри каждого пакета содержит точный SHA исходников,
целевую архитектуру и отметку о непроверенной физической печати; рядом лежит
SHA256 установщика или ZIP. Linux-ветка CUPS не поставляется как релиз.
Автоматические проверки подтверждают сборку и синтетическую очередь, но не
заменяют установку на чистом Windows 10/11, модель/драйвер склада и бумагу.

Пакет не имеет Developer ID/notarization. Его запуск после интернет-загрузки
может потребовать штатного подтверждения macOS; настройки безопасности программа
не отключает. Проверка Gatekeeper на чистом профиле после скачивания ещё требуется.

## Что означает результат

- «Ожидает передачи»: сервер сохранил задание, программа ПК ещё не забрала его.
- «Передано в очередь принтера»: ОС вернула квитанцию приёма файла.
- «Не передано в очередь принтера»: ошибка проверок до начала передачи.
- «Результат печати неизвестен»: задание выдано, подтверждённой квитанции ещё нет.

**Принятие очередью не доказывает выход бумаги.** Принтер может быть выключен,
без бумаги или продолжать печатать предыдущие задания. После проверки оборудования
человек может намеренно заказать новую печать с новым UUID, учитывая возможный
дубликат. Таймер и перезапуск программы сами такую печать не создают.

Один файл `inflight.json` сохраняет только незавершённую передачу/квитанцию.
До вызова ОС записывается граница `submitting`; после приёма сохраняется квитанция.
Если ответ WMS потерян, программа повторяет только квитанцию. Если процесс упал
между приёмом ОС и сохранением квитанции, задание остаётся неизвестным без повторной
отправки в ОС. После этого другие задания продолжают обрабатываться. Это не журнал
печати, попыток или количеств. Один профиль защищён блокировкой ОС, а получение
заданий атомарно на сервере, в том числе между разными профилями/компьютерами.

Конфигурация и временная квитанция находятся в
`~/Library/Application Support/WMS Print` на macOS или `%LocalAppData%\WMS Print`
на Windows. Windows ограничивает ACL (список прав доступа) текущим пользователем
и SYSTEM; macOS использует каталог с правами только владельца. Автозапуск —
`~/Library/LaunchAgents/ru.wms.print-agent.plist` или задача Планировщика
`WMS Print`. Токен не выводится в консоль, не включается в аргументы автозапуска
и не попадает в пакет. В логах нет файлов этикеток или HTTP-тел.

При обновлении Windows-установщик сначала штатно останавливает один работающий
процесс, затем заменяет программу и запускает новую версию с тем же приватным
состоянием. Если установка не дошла до замены файлов, прежняя программа и её
состояние остаются на месте. Удаление через Windows прекращает процесс и убирает
автозапуск/файлы, но сохраняет `%LocalAppData%\WMS Print` для восстановления после
переустановки. Удалять это состояние разрешено только явной командой
`wms-print --reset-state --confirm-reset`: перед ней программа сообщает о
незавершённом задании и не делает этого молча во время обновления.

## Контракт для веба и ТСД

Все пути ниже относительно API WMS. Операции сортировки требуют существующее
право приёмки. Настройка склада требует администратора. Печать не требует FBS-поставки.

- `GET /operations/print/warehouses/{warehouse_id}/destination` возвращает
  `{destination: null | {connection_id, queue_name, platform, warehouse_id,
  paired, is_default, last_seen_at, online}}`. `online` отражает heartbeat за
  последние 60 секунд, а не готовность физического принтера.
- `POST /operations/print/warehouses/{warehouse_id}/pair/preview` с
  `{pairing_code}` показывает очередь/платформу до подтверждения.
- `POST /operations/print/warehouses/{warehouse_id}/pair` с `{pairing_code}`
  подтверждает назначение. Потерянный ответ допускает безопасный повтор того же
  кода до истечения 15 минут. Повтор не отменяет более позднее назначение.
- `GET /operations/print/sorting/{request_id}/label?kind=product|location&object_id=UUID&marketplace=wb|ozon`
  возвращает `{barcode,label_title,label_subtitle,warehouse_id,printable,error_message}`.
  Для ячейки marketplace не нужен. Ozon использует существующий активный
  `ProductMarketplaceLink.external_barcodes`, WB — `Product.wb_barcode`.
- `POST /operations/print/sorting/{request_id}/jobs` принимает:

  ```json
  {
    "job_id": "UUID намерения",
    "kind": "product",
    "object_id": "UUID товара из документа или ячейки его склада",
    "marketplace": "wb",
    "copies": 1,
    "connection_id": "UUID показанного назначения"
  }
  ```

  ТСД сохраняет UUID **и точное тело** до HTTP и восстанавливает их после ухода
  с экрана и перезапуска. Транспортный повтор использует тот же UUID. Изменение
  тела с тем же UUID даёт 409. Новое намеренное нажатие перепечатки — новый UUID.
- `GET /operations/print/jobs/{job_id}` восстанавливает состояние своего задания.
  При 404 после потери POST повторяется сохранённое тело с прежним UUID.
  Ответ включает стандартные поля WMS-402 (`id,status,status_text,checksum,
  content_type,width_mm,height_mm,queue_receipt,error_message,created_at,
  started_at,finished_at`) и `connection_id,queue_name,copies,barcode,label_title,
  label_subtitle,content_bytes,request_id`. Файл и claim_id оператору не выдаются.

ПК генерирует и сохраняет `connection_id` и случайный `device_token` до первого
`POST /operations/print/pairing` с `{connection_id,device_token,queue_name,platform}`.
Ответ содержит `pairing_code,expires_at` и описание соединения. Затем ПК вызывает
`POST /operations/print/agent/heartbeat`, `/agent/next`,
`GET /agent/jobs/{job_id}/content?claim_id=UUID`,
`POST /agent/jobs/{job_id}/result` с `{claim_id,handed_to_queue,queue_receipt,error_message}`.
Последние пути также имеют префикс `/operations/print`. Только выдавшийся claim
соответствующего соединения может получить файл или подтвердить результат.

Смена назначения меняет адресата **только новых** заданий. Старое соединение
может завершить свои старые задания. Старый токен не получает задания нового
соединения и наоборот. Склад и принтер не берутся из непроверенных полей агента.

## Совместимость WMS-402

Старые FBS API и существующая Android-печать сохраняются. Новые FBS-задания при
назначенном ПК получают его неизменяемое назначение и снимок исходного файла.
Готовые PNG/PDF площадки и PDF товарного ШК/ЧЗ не пересобираются. При отсутствии
назначения остаётся прежний FBS путь. Широкий employee JWT в новом пакете не
используется; старый `wms_print_agent.py --warehouse-id` оставлен для совместимости.

`BackgroundJob` остаётся единственной серверной очередью печати. Таблица
`print_connections` нужна для временного сопряжения, постоянной привязки очереди,
проверки узкого доступа и heartbeat: в `Warehouse` нет таких настроек, а задание
печати не является реестром действующего подключения. Таблиц попыток/остатков нет.

## Разработчику

```sh
python3 -m venv tools/print-agent/.build-venv
./tools/print-agent/.build-venv/bin/python -m pip install pyinstaller==6.20.0 certifi==2026.2.25
./tools/print-agent/.build-venv/bin/python tools/print-agent/build_package.py
python3 -m unittest discover -s tools/print-agent -v
```

`build.json` внутри пакета содержит Git SHA, ОС и архитектуру сборки; рядом с
артефактом лежит SHA256. `--self-test` проверяет пакет в отдельном временном профиле через
синтетическую очередь и перезапуск состояния, не обращаясь к WMS или принтеру.
`--list-printers` только читает имена установленных очередей. `--run --once`
с сохранённым подключением действительно может передать одно задание: это уже
операционная проверка, её нельзя запускать против реального склада без поручения.
