# WMS-387: изолированная учебная копия

Развёрнута 07.09.2026 на сервере друга в `/opt/wms-training`, Ubuntu 24.04
через WSL 2. Фронт и бэк взяты из активной версии стейджа
`6afa60e7f8ea72531fb6f541ff1eb159b732ace6`; эмулятор —
`520fac16f6fabaaa229883e03dd50c5a1a71ab87`. Версии закреплены в `snapshot.json`.
Рабочий стейдж не изменялся. PostgreSQL 18 закреплён по digest его образа.

После уточнения владельца передаваемый код очищается `clean_delivery.py`:
тесты, Markdown-документы, иллюстрации справки и примеры персональных имён
не входят в пакет. В копии убран встроенный список имён для доступа к
переключателю магазинов; штатный флаг пользователя продолжает работать.
Фронт пересобран из этих исходников, поэтому это версия стейджа с указанной
очисткой, а не байт-в-байт исходный веб-образ. Бизнес-логика остального
приложения не менялась. Удалённые материалы сохраняются в нашем Git.

## Данные и граница очистки

Первоначально перенесены 107 таблиц, 5179 записей, 50 файлов приложения и
согласованная SQLite-копия эмулятора. Перед передачей из дампа удалены все
найденные интеграционные секреты и старые хэши паролей. `sanitize_snapshot.py`
проверяет COPY-строки без изменения количества записей. `bootstrap_copy.py`
до старта API заменяет учётные данные, добавляет учебного администратора и
привязывает два продавца к новому токену локального эмулятора `seller_a`.
После создания администратора было 5180 записей. Браузерная проверка
синхронизации затем обновила статусы заказов только в копии.

Рабочий ключ Denmarcs не переносился. В копии остаются новые учебные токены,
пароль собственной БД, ключ подписи сессий и ключ шифрования. Значения
создаются только на сервере; `.env` имеет права 600, `private/` — 700.
Логин хранится в `private/training-login.json`, карта токенов — в
`private/emulator-tokens.json`. Секретов и дампов в этом Git-коммите нет.

Полная очистка содержимого базы от организаций, пользователей и документов
пока не выполнена: задан вопрос владельцу, сохранять ли учебное наполнение
или оставить пустую систему. До ответа нельзя считать копию обезличенной.
Архивы переноса, исходный скомпилированный фронт, установщик WSL и старый
кэш Docker удалены с сервера. Этот README также не передаётся другу.

## Сборка и проверка

`scripts/package_training_snapshot.py OUTPUT.tar.gz` читает закреплённые
Git-коммиты и применяет фильтр очистки при экспорте. Рабочий каталог исходного
проекта не редактируется. Пакет содержит исходники, Dockerfile, Compose и
версию; дампы и секреты передаются отдельно. Существующий архив не затирается.

`setup-linux.sh` устанавливает Docker из официального репозитория Ubuntu.
`stage-linux.sh` предназначен только для первого развёртывания: он откажется
работать при существующем `/opt/wms-training/.env`. Перед его запуском
подготовить перечисленные в нём архивы и карты соответствий в Windows
`wms-training-setup`. Он восстанавливает данные до первого запуска API.
`verify_copy.py` — проверка первоначального снимка **до очистки исходников и
браузерных действий**; требует отдельно подготовленных приватных манифестов.
Он не является проверкой поздней изменённой базы или очищенной сборки.

Сверка первоначального переноса подтвердила 426 файлов бэка, 34 файла
эмулятора, 177 файлов исходной веб-сборки, 50 пользовательских файлов и все
107 таблиц. Версии 62 зависимостей API и 33 зависимостей эмулятора совпали
с исходными контейнерами. Очищенная сборка проходит TypeScript и `npm run build`.
В браузере проверены вход, каталог и синхронизация заказов с локальным
эмулятором; после очистки также каталог и пустой раздел справки.

Синхронизация читает заказы из эмулятора, но исходный эмулятор не поддерживает
старый GET `/api/v3/supplies` (405). У пяти демо-продавцов исходной базы нет
ключей WB; интерфейс сообщает об этом. Это ограничения перенесённой версии,
полный цикл складской отгрузки в этой задаче не подтверждён.

## Изоляция, ресурсы и адрес

Четыре контейнера: `db`, `api`, `wb-emulator`, `web`. Первые три находятся
только во внутренней Docker-сети без выхода в интернет. Запрет проверен
TCP-соединением из API и эмулятора; локальный health эмулятора отвечает 200.
Все четыре адреса WB направлены на `http://wb-emulator:8000`, реальный Ozon
отключён. Рабочие настройки почты, платежей и DaData не передавались.
Тома базы, файлов и эмулятора принадлежат только `wms-training`.

WSL получает до 30 ГБ ОЗУ, все 12 логических процессоров и 4 ГБ swap.
Процессоры совместно используются Windows и Linux; эксклюзивного выделения
WSL здесь нет. Windows остаётся хостом WSL и SSH. Задача планировщика
`WMS-387 Training` запускает WSL/Docker после старта Windows, обновляет
перенаправление TCP 8088 на текущий IP Linux и удерживает WSL активным.
Скрипты `start-windows.ps1` и `register-startup.ps1` сохранены в Windows.
Полная перезагрузка проверена: загрузка Windows 13:40:36, задача запустилась
в 13:40:40 по времени сервера; без ручного запуска WSL сайт ответил health OK.
После перезагрузки повторно проверены изоляция и ресурсы. Все 792 файла
очищенных исходников на сервере совпали с экспортом закреплённых коммитов.

Проверенный адрес в LAN: `http://192.168.12.62:8088`. SSH идёт через внешний
40908, внешний 40158 отвечает RDP. Отдельного внешнего HTTP-порта пока нет:
для доступа из интернета владелец сети должен пробросить свободный внешний
TCP-порт на `192.168.12.62:8088`. Локальный SSH-туннель агента используется
только для проверки, не является постоянным адресом для друга.
