# WMS-387: самостоятельная копия стейджа

Это пакет развёртывания версии стейджа, проверенной 07.09.2026 через активные
deployment в Railway. Фронт и бэк: `6afa60e7f8ea72531fb6f541ff1eb159b732ace6`;
эмулятор: `520fac16f6fabaaa229883e03dd50c5a1a71ab87`. Образ PostgreSQL закреплён
по digest действующего сервиса. Исходники приложения не меняются.

Пакет пока **не является полным слепком данных и не проверен запуском**.
`snapshot.json` явно отмечает отсутствие снимка данных. Python-зависимости в
Dockerfile исходной версии устанавливаются без фиксации полного набора версий;
сборка из того же Git-коммита не означает совпадение всех библиотек с живым
контейнером. Перед приёмкой нужно сверить установленные зависимости со стейджем.

## Сборка переносимого пакета

Из постоянного checkout WMS:

```sh
python3 scripts/package_training_snapshot.py /absolute/path/wms-training.tar.gz
```

Скрипт берёт исходники из двух указанных Git-коммитов, а не из рабочего diff.
Он переносит только серверный код, миграции, фронт и код эмулятора. Файлы `.env`,
доступы, локальные базы, тестовые seed-файлы и посторонние проекты не копируются.
Дамп базы и пользовательские файлы должны передаваться отдельно.

## Изоляция

База, API и эмулятор находятся только во внутренней Docker-сети `private` с
`internal: true`. Выход наружу есть только у веб-сервера, который проксирует
фиксированный адрес `http://api:8000`. Публичных портов у базы, API и эмулятора
нет. Все четыре адреса WB направлены на локальный эмулятор; реальный Ozon
отключён. Не поддерживаемые эмулятором методы не станут обращаться в живой WB.
Почта, платежи и DaData не получают рабочих настроек.

Состояние хранится в собственных томах проекта `wms-training`. Каталоги и тома
рабочих стендов не подключаются. Не добавлять API во внешнюю сеть для исправления
ошибок интеграции: запрет внешних обращений является частью постановки владельца.

## Условия запуска

Нужны Linux с Docker Engine и Compose. На сервере друга проверены Windows 10 Pro
22H2, административный SSH-доступ, 12 логических процессоров, 31.9 ГБ общей
памяти и 226.2 ГБ свободного места. Linux запускается через WSL 2; Windows
переустанавливать не требуется. Перед завершением включения WSL нужна
перезагрузка по согласованию с владельцем сервера.

После распаковки рядом с `compose.yaml` должны находиться:

- приватный файл `.env` с отдельными `TRAINING_DB_PASSWORD` (URL-safe),
  `TRAINING_JWT_SECRET`, `TRAINING_FERNET_KEY`, `TRAINING_EMULATOR_ADMIN_TOKEN`,
  `TRAINING_PUBLIC_URL`, `TRAINING_BIND_ADDRESS`, `TRAINING_HTTP_PORT`;
- `private/emulator-tokens.json` с учебными токенами и ключами продавцов,
  согласованными с восстановленной базой WMS;
- проверенные снимки базы WMS, файлов `/app/var` и состояния эмулятора.

Новые секреты создаются только после отдельного прямого разрешения владельца
согласно глобальному AGENTS.md. Секреты и приватные снимки не включать в Git.
Рабочие ключи маркетплейсов не передавать другу. При замене ключа шифрования
сохранённые в базе интеграционные токены требуют отдельной обработки.

Сначала собрать образы (`docker compose build`), затем поднять только базу
(`docker compose up -d db`), восстановить снимки в новые тома и сверить их.
Только после этого запускать `docker compose up -d`: при старте API сам
накатывает миграции, как на стейдже. Не запускать на пустой базе и не выдавать
это за перенос текущего стейджа.

Порт `195.208.16.1:40908` ведёт на SSH. `195.208.16.1:40158` ответил протоколом
RDP (удалённый рабочий стол). Для сайта требуется отдельное перенаправление
внешнего порта на Windows-хост `192.168.12.62:8088`, а с него в WSL.
По умолчанию Compose слушает только loopback. Внешнюю публикацию включить после
проверки изоляции, входа и восстановления данных; отдельно настроить автозапуск
WSL и перенаправление порта после перезагрузки Windows.

## Приёмка

Проверить версии всех компонентов, количество восстановленных записей и файлов,
отсутствие внешнего доступа из API и эмулятора и доступность сайта извне.
В браузере проверить вход, каталог, остатки, документ склада и FBS-операцию с
эмулятором; отдельно проверить сохранение данных после перезапуска. До этого
пакет остаётся подготовкой к развёртыванию, а не переданным учебным стендом.
