# 04 — Тест-кейсы

> Заполняет: агент-тест-дизайнер ДО кода. Кейсы выводятся из критериев приёмки (`03-contract.md`).
> Код валидируется по ним. Для бага обязателен регресс-кейс, воспроизводящий баг.
> Эта таблица переносится в описание PR как блок `### Test coverage` (иначе CI красный).

## Где живут тесты
- backend: `cd backend && pytest <путь>` (Given/When/Then в описании кейса).
- frontend e2e: `cd frontend && npm run test:e2e` — user-centric через `data-testid`, проверяем **видимый результат**, не только HTTP 200. В тесте — комментарий со ссылкой на `TC-ID` (для трассируемости через рефакторы).
