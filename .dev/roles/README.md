# roles/ — кто что делает

Описание каждой роли конвейера: миссия, что читает на входе, что сдаёт на выходе, что ОБЯЗАН сделать,
когда стадия считается готовой (DoD) и что запрещено. Порядок и маршруты — в [`../PROCESS.md`](../PROCESS.md).

Одна роль = один активный агент на стадии. Один и тот же инструмент (Claude Code/Cursor/Codex) может
играть несколько ролей по очереди — **но роль «Ревьюер» (стадия 5) не играет тот, кто писал код.**

| 1 | Аналитик + арх-коуч | [analyst.md](analyst.md) |
| 2 | Бизнес-аналитик (BA) | [ba.md](ba.md) |
| 3 | Тест-дизайнер | [test-designer.md](test-designer.md) |

## Общие правила для ВСЕХ ролей (нарушать нельзя)
1. **Прочитай [`../PROCESS.md`](../PROCESS.md) и всю папку `tasks/<slug>/` до начала.** Продолжай с оборвавшейся стадии, не переделывай пройденное молча.
2. **Оставь след:** свой артефакт `tasks/<slug>/NN-*.md` (из шаблона [`../templates/`](../templates/)). Нет артефакта — стадия не пройдена.
3. **Не перепрыгивай гейты.** Пока `02-arch-decision.md` не ✅ человеком — стадии 2–4 не начинаются.
4. **Не расширяй scope.** Делаешь ровно свою стадию; замеченное «заодно» выносишь заметкой, не делаешь молча.
5. **Не трогаешь чужой артефакт задним числом** — дополняешь свой; расхождение поднимаешь человеку.
6. **Правила репо/окружения и CI** ([`../../AGENTS.md`](../../AGENTS.md): слои `api`/`services`/`models`/`db`/`tasks`, вертикальный срез, таблица `### Test coverage`, ветка→PR→зелёный CI) — обязательны.
