**Для уже сохранённой истории WMS-661 на `226b228843b321d93f5f6109adcc8e246a13c533` существующего подходящего пути не нашёл.** Общий механизм reviewed correction есть и сам по себе не требует неизменных assertions (проверяемых ожиданий теста), но конкретный `cc6b1b274` не проходит его ограничения. Одной записи реестра недостаточно.

Точный текущий путь: `check()` → `contract_change_errors()` → [`reviewed_contract_correction()`](/Users/deniscivkunov/Projects/WMS/.worktrees/support-task-14/scripts/ci/check_task_documents.py:189). Он читает **закоммиченный** `docs/reviews/contract-corrections/WMS-661.json` через `git show HEAD:…`. Минимальная запись содержит:

```json
{
  "task": "WMS-661",
  "contract_commit": "<полный SHA исходного контракта>",
  "correction_commit": "<полный SHA коррекции>",
  "files": ["<исправленные замороженные файлы>"],
  "review": {
    "model": "gpt-6-astra",
    "effort": "high",
    "verdict": "PASS"
  }
}
```

Однако проверка требует, чтобы коррекция шла после исходного контракта, меняла только часть его замороженных файлов и чтобы **весь набор файлов коммита коррекции точно совпадал с `files`**. После этого исправленные файлы сравниваются с коррекцией, остальные — с исходным контрактом. Проверки «только fixture» или «assertions unchanged» в этой общей функции нет.

У WMS-661 препятствия конкретные:

- `7d168b81393d0eefdaeebee010484c41cbe74443` заморозил оба тестовых файла **и handoff**; исключены только `docs/requirements/…`.
- `cc6b1b274bbfb7c31def404912f7f1533f70e81f` изменил тест, handoff **и документ требований**. Если перечислить все три файла, нарушается ограничение на замороженные файлы; если исключить требования, нарушается точное совпадение с составом коммита.
- Handoff затем изменён в `ca2a51018f5c2cdc319350ea9932dad557cd6e24` и `226b228…`. Поэтому даже назначение `cc6b1b274` новой базой handoff оставляет последующие изменения. Текущая функция поддерживает одну коррекцию на задачу.

Указанные примеры эту границу не закрывают. В [реестре WMS-517](/Users/deniscivkunov/Projects/WMS/.worktrees/wms517-sales-report-contract/docs/reviews/contract-corrections/WMS-517.json) бизнес-миграция `427fc2…` прямо находится в `excluded_changes`: она меняет ожидания и содержит дополнительные файлы, поэтому не считается допустимой коррекцией части замороженного контракта. Поддержанные записи относятся к точным fixture-коррекциям.
