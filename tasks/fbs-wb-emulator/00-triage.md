> Заполняет: первый агент, взявшийся за задачу. Первое действие по любой задаче.

- **Задача (одной строкой):** Отдельный HTTP-сервис — эмулятор WB Marketplace API v3 для тестового контура: полный цикл FBS (автопрос заказов → отгрузка → стикеры → КИЗ → deliver) без реального Wildberries и без правок кода WMS.
- **Тип:** `feature`
- **Размер:** `L`
- **GitHub Issue:** нет (в трекере не найдена; работа ведётся из `tasks/fbs-wb-emulator/TASK.md`)
- **Стоит ли делать сейчас / зачем:** Да. Без эмулятора каждый прогон FBS-цепочки зависит от живого WB, реальных заказов и токенов — это медленно, нестабильно и не даёт «упал новый заказ» по кнопке. Эмулятор даёт предсказуемый стенд для разработки, регресса и демо; WMS остаётся на том же коде, что на проде — меняется только адрес API через env.

## Что затрагивает (первая прикидка)

| Область | Затрагиваем? | Что именно |
|---------|--------------|------------|
| **Новый standalone-сервис** `wb_emulator/` | ✅ Да | FastAPI-приложение, SQLite-стор, админ-ручки `/__admin/`, генерация PNG-стикеров, зеркало эндпоинтов `/api/v3/...` |
| **Docker / env (только тест)** | ✅ Да | Сервис `wb-emulator` в compose; на `api`, `celery_worker`, `celery_beat` — `WILDBERRIES_MARKETPLACE_API_BASE=http://wb-emulator:<port>`. **Не** в `docker-compose.prod.yml` |
| **Фикстуры засева** | ✅ Да | `seed/<seller>.json` — баркоды/nmId из реального каталога селлера |
| **`backend/app` (WMS)** | ❌ Нет | Принцип задачи: код WMS не меняем; только env/compose. Клиент уже читает `settings.wildberries_marketplace_api_base` (env `WILDBERRIES_MARKETPLACE_API_BASE`) |
| **Frontend** | ❌ Нет | UI FBS уже есть; тестируем через существующие экраны |
| **Мобилка** | ❌ Нет | — |
| **БД WMS / миграции** | ❌ Нет | Состояние эмулятора — в своём SQLite на volume |

**Источник правды по контракту API:** `backend/app/services/wildberries_client.py` (пути, методы, поля ответа). Не документация WB снаружи.
