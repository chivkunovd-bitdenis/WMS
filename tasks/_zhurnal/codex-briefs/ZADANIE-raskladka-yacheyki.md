# Задача: раскладка не видит того, что уже разложено

## Что сломано (проверено по коду и базе стенда)

Экран раскладки в документе сортировки берёт данные из
`GET /warehouses/{warehouse_id}/sorting-objects`.

В `backend/app/services/warehouse_map_service.py`, функция `get_sorting_objects`
(около строки 1092) собирает список так:

```python
_sorting_tree_rows(data["unassigned"], holder=None, objects=objects, lines=lines)
```

То есть **только из зоны «Без ячеек»**. А ячейки в ответе отдаются голыми:

```python
"cells": [{"id": row["id"], "code": row["code"], "barcode": row["barcode"]} for row in data["cells"]]
```

**без содержимого**.

Из-за этого: оператор кладёт короб в ячейку, запись в базе появляется (проверено:
на стенде 16 коробов из 63 имеют `storage_location_id`), но при следующем чтении
короб исчезает с экрана — он уже не в «Без ячеек», а в ячейке содержимого нет.
Для оператора это выглядит как «закрепил за ячейкой, и оно сбросилось».

## Ещё два бага в той же ручке размещения

Файл `backend/app/api/warehouses.py`, роут
`POST /{warehouse_id}/sorting-objects/place` (около строки 367):

```python
cell_id = body.cell_id or body.to_id
if cell_id is None:
    raise HTTPException(422, detail="cell_id_required")
```

и дальше `warehouse_map_service.place_sorting_object`, который **всегда** зовёт
`move_object(..., to_kind="cell", to_id=cell_id, ...)`.

**Баг 1 — «снять с ячейки» не работает.** Фронт при снятии шлёт
`{cell_id: null, to_id: null}` и в коде рядом стоит комментарий, что сервер
понимает пустую цель как «Без ячеек». Сервер её не понимает — отвечает 422.
Нужно: пустая цель = переместить объект в зону «Без ячеек»
(ячейка с кодом `SORTING_LOCATION_CODE`), а не отказ.

**Баг 2 — вложить короб в палету нельзя.** Фронт шлёт id тары в `to_id`
(`{cell_id: null, to_id: "<uuid палеты/короба/грузоместа>"}`), а ручка кладёт
это значение в `cell_id` и передаёт как перемещение в ЯЧЕЙКУ. Нужно различать:
`cell_id` — цель-ячейка, `to_id` — цель-тара, и звать `move_object` с
правильным `to_kind`.

## Что сделать

1. `get_sorting_objects` должен возвращать **и** содержимое ячеек: для каждой
   ячейки — какая тара и какой товар в ней лежит, в том же формате, в каком
   сейчас отдаётся содержимое «Без ячеек» (`objects` с полем holder и `lines`).
   Смотри, как устроен `_sorting_tree_rows` и что кладёт `get_warehouse_map`
   в `data["cells"]` — переиспользуй, не пиши второй обход дерева.
   Формат ответа расширяй **добавлением**, ничего не убирая: фронт живой.
2. Роут `place`: пустая цель — снятие в «Без ячеек», без 422.
3. Роут `place`: цель-тара через `to_id` — вложение в тару, а не в ячейку.
4. Схема ответа `SortingObjectsOut` — обнови под новые поля.

## Тесты (обязательно, новые роуты/поведение без теста не принимаются)

Заведи `backend/tests/test_sorting_objects_cells.py`:
- объект положили в ячейку → он виден в ответе `GET sorting-objects` с этой ячейкой;
- «снять с ячейки» (пустая цель) → 200, объект вернулся в «Без ячеек»;
- вложить короб в палету через `to_id` → 200, короб внутри палеты, а не в ячейке;
- товар положили в ячейку → виден в содержимом ячейки с количеством.
