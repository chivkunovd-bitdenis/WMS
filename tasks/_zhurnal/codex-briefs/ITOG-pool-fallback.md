# Итог: новое правило остатка FBS полностью заменило старый пул

## Что изменено

Публикация остатков WB теперь получает количество только из
`fbs_stock_rule_service.publish_amounts_for_binding`. Чтение старого абсолютного
`fbs_binding_stock_pools.quantity` из sync-пути удалено полностью: это поле больше
не служит ни основой расчёта, ни аварийным запасным источником.

Товар попадает в расчёт и публикацию только при одновременно включённом
`fbs_stock_sync_enabled` и заданном `fbs_percent`. Поэтому выключенная публикация
или `fbs_percent IS NULL` означают «не трогать товар»: PUT с нулём или старым
числом в WB не отправляется. При заданном `fbs_percent = 0` товар, напротив,
остаётся в плане и в WB уходит осознанный ноль.

Привязка с `served = false` теперь отсекается до получения токена, расчёта и
сетевого вызова. Если расчёт правила выбрасывает исключение, публикация по этой
привязке прекращается, сама привязка получает статус `error` и код
`stock_rule_calculation_failed`; старое количество при этом не подставляется.

Комментарии у наследуемых полей моделей обновлены, чтобы они больше не обещали
аварийный откат к абсолютному числу.

## Регрессионные проверки

В адресных тестах закреплены все требуемые случаи:

1. При `fbs_percent IS NULL` сохранённое старое число 17/57 игнорируется, товар
   не попадает в публикацию.
2. При выключенном `fbs_stock_sync_enabled` старое число 57 не отправляется и
   ноль в WB не уходит.
3. При `fbs_percent = 0` выполняется PUT с количеством `0`, даже если в старом
   пуле лежало 64.
4. При `served = false` сетевых вызовов публикации нет.
5. При исключении в расчёте привязка помечается ошибкой, PUT не выполняется, а
   сохранённое старое число 57 не используется.

Старые sync-тесты, которые раньше подготавливали только абсолютный пул, переведены
на реальный расчёт доли от свободного остатка. Пачечная публикация, ошибки WB,
повтор после 429, readback и частично успешные пачки продолжают проверяться уже
через новый источник количества.

По согласованным данным задания у продавца **ИП Манкаев Т.Т.** на привязке
`wb_warehouse_id = 1870359` три товара имеют `fbs_percent IS NULL`, а в старом
пуле сохранены абсолютные количества `0 / 57 / 64`. После выкладки этого коммита
все три товара перестанут публиковаться до задания доли; старые числа больше не
будут подставляться. Это ожидаемое и согласованное изменение поведения.
