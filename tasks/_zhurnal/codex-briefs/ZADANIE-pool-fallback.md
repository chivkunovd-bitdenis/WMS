# Задача: новое правило остатка FBS должно ПОЛНОСТЬЮ заменить старый пул

## Решение владельца (дословно, 29.08.2026)

> «у нас механизм новый должен полностью замещать старую эту хуйню. если у меня
> выключен в новом окне этом, значит ничё не публикуется — система так должна работать»

## Что сейчас не так

`backend/app/services/fbs_stock_sync_service.py`, функция
`_resolve_publish_quantities`. Сейчас она делает так:

```python
stored = await _load_pool_quantities(session, binding.id)   # старые абсолютные числа
by_rule = await publish_amounts_for_binding(session, binding, products)  # новое правило
stored.update(by_rule)
return stored
```

То есть **старый сохранённый пул остаётся основой**, а новое правило только
дописывается сверху. Последствие: товар, у которого публикация в новом окне
выключена или доля не задана, всё равно публикуется старым числом из
`fbs_binding_stock_pools.quantity`. Выключенный тумблер ничего не выключает.

## Что должно быть

Единственный источник числа для публикации — новое правило
(`fbs_stock_rule_service.publish_amounts_for_binding`). Старые абсолютные
количества из `fbs_binding_stock_pools.quantity` источником быть перестают.

Правила поведения:
- Публикация у товара выключена (`fbs_stock_sync_enabled = false`) или доля не
  задана (`fbs_percent IS NULL`) → товар **не попадает в публикацию вообще**,
  система его не трогает. Ноль в WB при этом НЕ отправляем: осознанный ноль —
  это доля, равная нулю, а не отсутствие настройки. Это уже описано в докстринге
  `publish_amounts_for_binding`, сохрани это поведение.
- Привязка не отмечена как наша (`served = false`) → по ней не публикуем.
- Аварийный откат к старому пулу при исключении в расчёте правила — **убрать**.
  Если расчёт правила падает, это ошибка публикации: помечай привязку статусом
  ошибки и не публикуй, а не подставляй старое число молча.

## Важно: на бою есть живой продавец

`ИП Манкаев Т.Т.`, привязка `wb_warehouse_id = 1870359`, публикация ВКЛЮЧЕНА и
работает. У его трёх товаров сейчас `fbs_percent IS NULL`, а в пуле лежат
абсолютные 0 / 57 / 64. После твоей правки они перестанут публиковаться, пока
владелец не задаст долю — это ожидаемо и согласовано, но **обязательно напиши об
этом в итоге** отдельной строкой.

## Тесты (обязательно)

Расширь `backend/tests/test_fbs_stock_rule_service.py` или заведи рядом:
- у товара доля не задана, но в пуле лежит старое число → в публикацию не попадает;
- у товара публикация выключена → не попадает, ноль в WB не уходит;
- доля равна нулю → уходит осознанный ноль;
- привязка `served = false` → по ней не публикуем;
- расчёт правила упал → привязка помечена ошибкой, старое число НЕ подставляется.
