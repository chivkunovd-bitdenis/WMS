## 1. Ведомость хранения может начислить лишнюю копейку

`backend/app/services/storage_statement_service.py`, около строки 600.
Фиксация проверяет незаполненные габариты только на текущем складе, а округление
копеек распределяется между **всеми** складами селлера. Если зафиксировать склад A,
затем исправить данные склада B, распределение пересчитается, но неизменяемая
проводка A останется старой: складские проводки дадут 2 копейки, а отчёт — 1.

## 2. Грузоместо принимается коробочными процессами как обычный короб

Найди места, где процессы, рассчитанные на короб, принимают грузоместо без
различия, и разведи их. Иерархия тары: ячейка → палета → короб/грузоместо → товар.
Грузоместо — не короб, у него свой смысл в отгрузке.

## 3. Предел 200 товаров на остатках FBS с поиском на клиенте

Список товаров для распределения остатка FBS отдаёт не больше 200 позиций, а
поиск идёт на клиенте — то есть по 201-му товару искать нельзя. У Чжоу на бою
9292 карточки. Нужен серверный поиск и постраничность.

## 4. Квадратичные запросы в списке ведомостей

В списке ведомостей хранения запросы идут по строке на каждую ведомость.
Собери пакетно.
