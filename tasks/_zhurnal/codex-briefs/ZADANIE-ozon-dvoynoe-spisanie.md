# Задача: заказ Ozon списывается с остатка дважды

## Что сломано (проверено чтением кода на боевой ветке)

`backend/app/services/fbs_ozon_packaging_service.py`, около строки 192:
при упаковке заказа Ozon списывается остаток и создаётся расписка,
**но поле `shipment_movement_id` в ней не заполняется** — присвоения этого поля
в файле нет вообще (проверял grep'ом по всему файлу).

`backend/app/services/fbs_shipment_service.py`, функция
`_write_off_delivered_orders_once`: она выбирает доставленные заказы **без
разбора маркетплейса**, видит у заказа Ozon пустой `shipment_movement_id`,
считает что заказ ещё не списан, и списывает второй раз.

На цифрах это сейчас не проявляется только потому, что живых заказов Ozon нет:
кабинет отвергает ключ (403, code 7). Как только ключ починят — поедет минус.

## Что сделать

Заказ должен списываться ровно один раз. Выбери решение сам, но обоснуй в итоге:
либо упаковка Ozon проставляет `shipment_movement_id` в расписке (тогда списание
на доставке этот заказ пропустит), либо списание на доставке явно исключает
заказы, уже списанные на упаковке. Второй вариант надёжнее, если у Ozon упаковка
и доставка живут в разных таблицах — реши по коду, не по догадке.

Важно: **не ломай списание для WB**. Оно сейчас работает и на нём стоит склад.

## Тесты (обязательно)

Расширь или заведи рядом с `backend/tests/test_fbs_ozon_lane.py`:
- заказ Ozon упаковали, потом он доставлен → остаток уменьшился **один раз**;
- заказ WB проходит прежний путь и списывается один раз (регресс);
- заказ Ozon, отменённый после упаковки, не списывается повторно.
