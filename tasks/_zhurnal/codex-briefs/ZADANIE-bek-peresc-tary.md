# Задание: пересчёт по таре — палета, короб, грузоместо

## Дыра

Экран карты склада показывает дерево из строк пяти видов: ячейка, палета, короб,
грузоместо, товар. На каждой строке стоит кнопка «Пересчитать» — так согласовано
с владельцем.

Сервер это не вытягивает. `POST /operations/inventory-counts`
(`backend/app/api/inventory_counts.py`, схема `InventoryCountObjectIn`, строка 24)
принимает только:

    type: Literal["product", "storage_location", "location", "cell"]

**Палеты, короба и грузоместа нет.** Значит пересчитать короб нечем — фронт
некуда послать запрос. Это блокирует согласованную фичу целиком.

## Что сделать

Расширить пересчёт по объекту на тару. Виды тары во фронте называются
`pallet`, `box`, `cargo_place` — посмотри, как они называются в бэковых моделях
(ищи от `backend/app/api/warehouses.py`, ручка `GET /{warehouse_id}/map`, она уже
отдаёт это дерево — там же увидишь канонические имена и связи).

1. Добавить типы тары в `InventoryCountObjectIn.type`.
2. В `backend/app/services/inventory_count_service.py`, функция `create_count`,
   в ветке `if object_scope is not None` (около строки 181) добавить разбор тары:
   собрать состав так же, как это делает карта склада — **весь товар внутри этой
   тары, включая вложенную тару**. Короб внутри палеты — часть пересчёта палеты.
3. Не сломать существующие ветки `product` / `location` / `cell` и правило
   `object_not_available_without_address_storage`.

## Важно про смысл

Пересчёт по таре должен давать те же строки, что человек видит, раскрыв эту тару
на карте склада. Если карта показывает в коробе два товара по 18 и 7 штук — в
документе пересчёта должно быть ровно две строки с теми же числами в колонке
«Числится». Сверь это по коду ручки карты, чтобы состав не разъехался.

## Тесты

по пустой таре — понятная ошибка, а не пятисотка.
