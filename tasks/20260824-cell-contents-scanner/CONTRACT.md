# Узкий контракт экрана «Ячейки»

## Что должно измениться

1. Блок складов растёт только по фактическому числу строк и не имеет фиксированной высоты `33vh`.
2. Каждая строка ячейки раскрывается независимо.
3. Внутри раскрытой строки показываются:
   - физические короба, которые сейчас находятся в этой ячейке, и количество товаров в каждом;
   - текущие товарные остатки ячейки стандартными строками WMS.
4. Содержимое запрашивается лениво только для раскрытой или найденной сканером ячейки.
5. Скан ячейки выбирает её склад, раскрывает строку и прокручивает экран к ней.
6. Скан короба находит его текущую ячейку, раскрывает её, прокручивает экран и подсвечивает строку короба.

## Ошибки и пустые состояния

- Неизвестный штрихкод: понятная ошибка без изменения данных.
- Пустая ячейка: одна спокойная строка «Ячейка пуста».
- Короб без назначенной ячейки: понятный результат «Короб ещё не размещён».
- Короб, находящийся более чем в одной ячейке, не должен молча приводить к случайной ячейке.

## API и данные

API только read-only, с обязательными границами tenant и warehouse. Один запрос содержимого возвращает сразу товары и короба выбранной ячейки. Один запрос скана возвращает тип объекта и точную текущую ячейку.

## Тест-кейсы

- `TC-NEW-CELL-001`: ячейка раскрывается независимо, содержимое загружается один раз лениво.
- `TC-NEW-CELL-002`: скан ячейки выбирает склад, раскрывает и прокручивает к строке.
- `TC-NEW-CELL-003`: скан короба открывает его текущую ячейку и подсвечивает короб.
- `TC-NEW-CELL-004`: другой tenant и другой warehouse не видят содержимое или короб.
- `TC-NEW-CELL-005`: неизвестный/неразмещённый/неоднозначный короб не меняет данные и показывает точную ошибку.

## Блокер перед разработкой

Контракт требует именно текущую физическую связь входящего короба с ячейкой. Текущая схема её не хранит; использовать историю распределения как текущую связь запрещено. Поэтому код экрана и API не начинается до отдельного решения о модели хранения жизненного цикла входящего короба.
