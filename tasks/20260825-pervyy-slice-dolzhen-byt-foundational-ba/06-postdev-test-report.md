## Product findings requiring developer repair

* **F-01 — P0: production service embeds test-only state and helpers.** `MarketplaceAccountService` contains `_test_rows`, `from_test_client`, `save_candidate`, `count_primary_accounts` and `ciphertext_for_test`, with runtime branches in public lifecycle methods. This violates the required production/test boundary and makes the service evidence for encryption, isolation and concurrency an in-memory simulation rather than production behavior. **Required repair:** move all fake rows/helpers to `backend/tests` fixtures or a test-only fake adapter; production service must accept a real `AsyncSession` only and tests must use a local DB transaction.
* **F-02 — P0: WB E2E flag silently turns Ozon credential validation into success.** `validate_ozon_credentials` returns success when `E2E_MOCK_WB_CARDS=1`. This reuses an unrelated provider flag and creates a runtime bypass of the Ozon read-only validation/secrecy contract. **Required repair:** remove the runtime flag branch and inject the local Ozon validator/transport at test composition; at minimum use a dedicated Ozon-only test setting that cannot exist outside the local test server. Re-run all Ozon tests after repair.
* **F-03 — P1: real DB concurrency is not established.** The only service concurrency test invokes F-01's dictionary fake. The actual save path reads seller without `lock=True` and then locks an account row; when no primary row exists, that row cannot be locked. The two-request SQLite smoke passed, but is not proof against a first-create race/unique-constraint 500 in PostgreSQL. **Required repair:** lock the seller scope before the primary-row read (or use a robust scoped upsert/IntegrityError retry) and add a real local-DB barrier test for equal and differing concurrent PUTs.
* **F-04 — P1: accepted request-model/OpenAPI contract is not met.** The PUT parser manually consumes `Request`; there is no Pydantic request schema with `extra=forbid` in OpenAPI. Manual rejection currently works for tested payloads, but this loses the accepted typed API contract. **Required repair:** use an explicit strict Pydantic input model while preserving the exact error mapping and the scoped public-output secrecy test.
