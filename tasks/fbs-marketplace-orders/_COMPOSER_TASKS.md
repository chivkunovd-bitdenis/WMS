# FBS — задачи для Composer (индекс)

Эпик FBS прошёл всё «до разработки». Каждая под-задача — своя папка `tasks/<slug>/` с файлом `TASK.md`
(описание + scope + арх-подход + критерии приёмки + таблица `### Test coverage` с TC-ID и Given/When/Then).
Composer берёт `TASK.md`, кодит вертикальный срез, копирует таблицу Test coverage в описание PR (требование CI),
пишет тесты, гонит гейты. Независимое ревью (стадия 5) — отдельным проходом, не автором кода.

## Пред-разработческие артефакты эпика (готовы)
- `SPEC.md` — тех-дизайн + доменная модель + маппинг на WB API + разбивка.
- `api-feasibility.md` — что умеет WB Marketplace API (весь цикл реализуем).
- `DESIGN.md` — дизайн фронта (минимализм, UX, компоненты, data-testid).
- `00-triage.md` / `01-analysis.md` / `02-arch-decision.md` (✅ Гейт 1) — путь до утверждения.
- `wb-docs/` — 31 инструкция WB + `_CONSOLIDATED_FBS_SPEC.md` + `_IMAGE_INVENTORY.md`.

## Рекомендуемый ход
Сначала `fbs-orders-intake` (ядро, главный риск), параллельно можно `fbs-seller-warehouse-token`.
Затем `fbs-supply-assembly` → на нём разветвляются `fbs-marking`, оба потока отгрузки, отмены. Фронт и ТСД —
когда есть API. Часть, зависящую от точных путей WB API, начинать после дешёвой сверки эндпоинтов v3
(см. открытые вопросы в `SPEC.md` §9).
