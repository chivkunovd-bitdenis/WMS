# 02 — Арх-решение + стек  🔒 ГЕЙТ 1

## Принятое решение
- **Подход:** отдельный новый домен **`fbs_*`** (модели/сервисы/роуты/таск), переиспользующий остатки,
  резервы, упаковку, печать и модуль ЧЗ. Существующий `marketplace_unload` (ФБО) не трогаем.
- **Курс (подтверждён человеком):** **весь цикл FBS ведём из нашей WMS через WB Marketplace API v3.**
  Человека в кабинет WB не гоняем. Разбор реализуемости — [`api-feasibility.md`](api-feasibility.md).
- **Заказы:** **постоянный автоопрос** `GET /orders/new` по расписанию, per-seller, с идемпотентностью.
- **Стек:** SQLAlchemy + alembic; httpx-клиент Marketplace API в `wildberries_client.py`; фоновый опрос
  через существующий `background_job`/Celery; токен через `integration_fernet`; фронт — единый MUI;
  печать (стикеры заказов / QR поставки / QR грузомест) — конструктор печати + ТСД.
- **Осознанно НЕ делаем:** Ozon/Яндекс; посылки-группировку одного покупателя (у WB опция сейчас
  отключена — отложено); ценообразование и претензии покупателя (кроме отмены/возврата).

## Граница ответственности WMS ↔ WB — РЕШЕНО: всё по API из WMS
| Шаг | Кто делает |
|---|---|
| Заказы (сборочные задания) | наша WMS **читает** `GET /orders/new` (постоянный опрос) |
| Создание отгрузки (supply) | наша WMS по API `POST /supplies` |
| Наполнение отгрузки, стикеры заказов, КИЗ | наша WMS по API |
| Грузоместа + их QR (поток ПВЗ) | наша WMS по API `trbx` |
| Передача в доставку (deliver) + QR поставки | наша WMS по API |
| **Упаковка** (у WB нет как шага) | наш модуль `packaging_task` |
