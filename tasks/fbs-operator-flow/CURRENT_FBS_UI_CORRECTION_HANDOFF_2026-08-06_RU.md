## Что нужно сделать дальше

### 1. Сначала вернуть только UI упаковки

В `frontend/src/screens/v2/FfFbsSupplyWorkspace.tsx` вернуть визуальную и
интерактивную структуру архивного экрана:

- этап называется `Упаковка и маркировка`;
- внутри используется обычный `FfPackagingTaskPanel` без `compactLayout` и без
  `hidePrintActions`;
- в той же вкладке после таблицы остаётся блок `Идентификаторы заказа WB`;
- стандартные действия ЧЗ/ШК, preview и печать работают через прежний
  `FfPackagingTaskPanel` / `MarkingPrintDialog`, а не через новый самописный
  экран;
- `Стикеры WB` остаётся следующим штатным этапом.

Не переносить ручной подбор, короба и серверные ограничения назад: это новые
функции, они должны подключаться к сохранённому UI без визуального редизайна.

### 2. Короба — только после утверждения возвращённого экрана

Backend-контракт коробов уже есть и его не откатывать:

- `POST /operations/fbs-supplies/{supply_id}/boxes`;
- назначение/снятие заказа в короб;
- пустое удаление;
- QR короба только для ПВЗ;
- серверная блокировка передачи, если нет короба или упакованный заказ не
  назначен.

Но фронтовое размещение коробов требует отдельного согласования после показа
восстановленной вкладки упаковки. Не менять архивный экран ради коробов.

### 3. Ручной подбор сохранить

Сканер остаётся ускорителем. Ручной подбор из конкретной ячейки уже добавлен
на сервере и должен быть доступен без изменения привычного сканерного блока.
