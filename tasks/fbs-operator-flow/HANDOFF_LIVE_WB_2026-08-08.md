### Почему цепочку на живом заказе прогнать не удалось

В `inventory_balances` **нет остатков** ни по «Резинкам пружинкам глянцевым», ни по «Брюкам летним
льняным» — запрос вернул пустоту. Без остатка заказ нельзя подобрать, и цепочка честно упирается
в шаг подбора. Это не дефект: WMS не даёт собирать то, чего нет на складе.

**Чтобы прогнать живой заказ, сначала нужна приёмка** этих товаров на склад WMS (раздел «Приёмка»),
и только потом поставка → подбор → упаковка → короб → QR. Маршрут будет склад/СЦ: ПВЗ у этих
заказов недоступен по решению WB.

## Что блокирует живой прогон прямо сейчас

**Заказы из WB нечем притянуть.** Три независимых факта:

1. Во фронте **нет кнопки синхронизации заказов**. Вызова `/operations/fbs-orders/sync` в `frontend/src`
   нет вообще. Кнопка «Обновить данные» только перечитывает свою же базу.
2. Автоопрос живёт в Celery (`app/celery_app.py`, `app/tasks/background_jobs.py`), а на стенде
   **нет ни воркера, ни `CELERY_BROKER_URL`** — сервисов всего три. Опрашивать WB некому.
3. В форме ввода ключей (`WildberriesScreen.tsx`) **нет поля для маркетплейс-токена** — только
   «Токен контента WB» и «Токен поставок WB». Бэкенд третий токен принимает
   (`_parse_token_merge_patch` разбирает `marketplace_api_token`), фронт его не отдаёт.

Из-за этого сценарий «подключил ключ селлера — заказы приехали» не воспроизводится ни на одном контуре.
Это не про контракты, которые правил Кодекс: их просто некому вызвать.
