# 06 — Итог

- **Задача:** `20260822-hotfix-scan-fastpath` — ускорение операционного сканирования.
- **Тип:** аварийный bugfix.
- **Дата:** 2026-08-22.
- **Постоянная документация:** не требуется; бизнес-процесс не менялся.

## Суть

Задержку создавал не сканер и не WB. Каждый товар заставлял backend повторно загружать большой документ и каталог, а frontend ждал полные обновления нескольких экранов. Теперь уже загруженный экран передаёт серверу необязательную подсказку товара, сервер проверяет её в текущем документе и обновляет только нужную строку. Полная сверка остаётся фоновой или выполняется при закрытии окна.

## Для оператора

Скан подтверждается сразу изменением счётчика и подсветкой последней строки. Последовательные быстрые сканы не выполняются параллельно и не теряют единицы. Приёмка, короба, адресное хранение, план отгрузки и упаковка работают по прежним правилам.

## Технически

Убраны повторные загрузки полного ORM-графа (то есть всех связанных строк и событий), повторный разбор каталога WB и несколько полных GET после каждого POST. Для старых клиентов сохранён медленный fallback по одному штрихкоду, поэтому обновление фронта и backend можно разворачивать одним обычным deploy без миграции.
