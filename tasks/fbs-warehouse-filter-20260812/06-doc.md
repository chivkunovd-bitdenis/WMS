# 06 — Док

## Что сделали
На вкладке FBS «Новые» добавлен фильтр «Склад селлера». Оператор может выбрать склад, и таблица заказов сразу сужается до новых FBS-заказов этого склада.

## Почему так
Фильтр выполнен на сервере через параметр `wb_warehouse_id` в существующей ручке `/operations/fbs-orders/worklist`. Это важно: если бы фильтр работал только в браузере по первым 200 строкам, подходящие заказы могли бы находиться на следующей странице и не попасть в выдачу.

## Технически
- `backend/app/services/fbs_worklist_service.py` фильтрует worklist по `FbsOrder.wb_warehouse_id` и отдаёт `warehouse_options` для текущего seller/status scope.
- `backend/app/api/fbs_orders.py` принимает необязательный query-параметр `wb_warehouse_id`.
- `frontend/src/screens/v2/FfFbsOrdersScreen.tsx` показывает MUI Select только на вкладке «Новые», сбрасывает фильтр при смене селлера/вкладки и снимает выбранные заказы.
- `docs/IMPLEMENTED_PRODUCT_SCENARIOS_TEST_CASES_EN.md` получил постоянный сценарий `TC-S17-025`.

## Для бизнеса
Оператор меньше смешивает заказы разных складов в одной рабочей группе. Это снижает ручную сортировку перед формированием FBS-поставки и быстрее ведёт к совместимой выборке заказов.
