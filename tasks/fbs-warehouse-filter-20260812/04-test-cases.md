# 04 — Тест-кейсы

## Кейсы
| # | TC-ID | Что проверяем | Вход / предусловие | Ожидаемый результат (видимый) | Из критерия |
|---|-------|---------------|--------------------|-------------------------------|-------------|
| 1 | TC-S17-025 | Фильтр склада на вкладке «Новые» | Given: в worklist есть два новых FBS-заказа одного селлера на разных складах / When: оператор выбирает один склад | Then: таблица показывает только заказ выбранного склада, фильтр виден как «Склад селлера» | Срочный запрос пользователя |
| 2 | TC-S17-025 | Серверная фильтрация worklist | Given: API получает `seller_id`, `status_group=new`, `wb_warehouse_id` / When: backend строит страницу заказов | Then: в `items` попадают только заказы этого WB-склада, а `warehouse_options` остаётся списком складов текущего seller/status scope | Не терять заказы из-за пагинации |

## Крайние случаи / негатив
| # | Сценарий | Ожидаемое поведение |
|---|----------|--------------------|
| N1 | Смена селлера или уход с вкладки «Новые» | Фильтр склада сбрасывается на «Все склады», выделенные заказы снимаются. |
| N2 | Склад выбран, но заказов по нему больше нет | Таблица показывает штатное пустое состояние, без ошибки и без чужих складов. |

## Где живут тесты
- backend: `cd backend && pytest tests/test_fbs_worklist_query_count.py -k warehouse`
- frontend e2e: `cd frontend && npm run test:e2e -- ff-fbs-orders.spec.ts`
