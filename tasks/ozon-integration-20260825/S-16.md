# Вердикт S-16 / S-31 — каталог товаров

Файлы: `frontend/src/screens/v2/FfProductsCatalogScreen.tsx` (S-16, склад),
`frontend/src/screens/v2/ProductsScreen.tsx` и `frontend/src/sections/CatalogSection.tsx` (S-31, портал селлера).

Главное решение: **отдельного каталога Ozon нет.** Товар WMS остаётся одним, у него может быть
несколько внешних привязок сразу — WB и Ozon. Два товара из одной физической позиции не создавать.

| Элемент | Что делает сейчас | Вердикт |
|---|---|---|
| Кнопки «Добавить селлера», «Импорт», «Создать товар» | наши операции | `UNCHANGED` |
| Поиск «Артикул или название» | ищет по нашим полям | `UNCHANGED` на экране. Backend обязан находить и по артикулу/SKU Ozon. |
| Фильтр «Селлер» | выбор селлера | `UNCHANGED` |
| Фильтр маркетплейса | нет | `MINIMAL_DELTA`. Один `Select` рядом с «Селлер»: Все / Wildberries / Ozon. Ровно то, что просил владелец. |
| Колонки Фото / Размер / ШК / Артикул продавца / Селлер / ТЗ упаковки / Количество | — | `UNCHANGED`. **Новых колонок не добавлять.** Принадлежность к маркетплейсу — маленьким `Chip` в существующей ячейке, а не отдельным столбцом. |
| Сортировка по названию и количеству | наша | `UNCHANGED` |
| «ТЗ упаковки», «Нужен Честный знак при упаковке», печать ТЗ | наш процесс | `UNCHANGED`. Честный знак не трогать. |
| Сопоставление товара с Ozon | нет | `MINIMAL_DELTA`. Привязка живёт в существующей карточке товара рядом с привязкой WB, тем же видом поля. Отдельного экрана и отдельного мастера сопоставления не заводить. Несопоставленный товар Ozon виден в общем списке и помечен существующим способом. |

## Что обязано остаться неизменным для WB

Вид таблицы, набор колонок, поведение импорта и ТЗ упаковки. Селлер, у которого подключён только
WB, не должен увидеть на этом экране ни одного нового элемента, кроме фильтра маркетплейса.
