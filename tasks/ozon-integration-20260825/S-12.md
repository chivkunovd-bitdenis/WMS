# Вердикт S-12 — поставки и отгрузки на маркетплейс

Файл: `frontend/src/screens/ff/FfSuppliesShipmentsPage.tsx`.

Экран большой и общий для нескольких процессов. Трогать в нём можно только то, что перечислено ниже.
**Отдельного документа, вкладки или раздела FBO для Ozon не заводить** — владелец отклонил это прямо.

| Элемент | Что делает сейчас | Вердикт |
|---|---|---|
| Список документов: колонки Тип / Номер / Плановая дата / Создано / Статус / Селлер / Доп. / Строк | — | `UNCHANGED`. Новых колонок нет. Маркетплейс — `Chip` в существующей ячейке. |
| Фильтры «Селлер», «Сортировка» | — | `UNCHANGED`. Фильтр маркетплейса добавлять только если список документов реально смешанный. |
| Вкладки «Товары» и «Упаковка» | — | `UNCHANGED`. Третьей вкладки не появляется. |
| Поле «Склад WB (маркетплейс)» | выбор склада WB | `MINIMAL_DELTA` в подписи: «Склад маркетплейса», список подставляется по маркетплейсу документа. |
| Поле «Дата отгрузки на МП» | наша дата | `UNCHANGED` |
| Короба: создание, «Печать ШК короба», удаление пустого, пресеты, «Кол-во коробов», «Штрихкод готового короба (WHB-…)» | наш физический процесс | `UNCHANGED` для нашей части. Связь наших коробов с грузоместами Ozon — `BLOCKED`: по ресёрчу правила зависят от конкретной поставки и кабинета, кабинет заблокирован. Действие локально выключено с понятной строкой, физика упаковки не меняется. |
| Строки распределения, «Распределено», «Осталось», удаление строки | — | `UNCHANGED` |
| Передача документа на маркетплейс | вызов WB | `PROVIDER_DISPATCH` + подпись по маркетплейсу. |

## Что обязано остаться неизменным для WB

Весь текущий процесс отгрузки целиком: этапы, короба, распределение, печать. Этот экран — самое
опасное место всей задачи, здесь в прошлый заход и рисовали лишние панели. Любая правка тут —
строка или подпись, не блок.
