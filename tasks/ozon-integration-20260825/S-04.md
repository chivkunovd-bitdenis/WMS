# Вердикт S-04 — остатки FBS и их выгрузка

Файл: `frontend/src/screens/v2/FfFbsStockSyncScreen.tsx`.

Двухуровневый процесс (связка склад маркетплейса ↔ склад WMS, затем выгрузка) остаётся тем же.
Отдельного экрана остатков Ozon нет.

| Элемент | Что делает сейчас | Вердикт |
|---|---|---|
| Фильтр «Селлер» | выбор селлера | `UNCHANGED` |
| Кнопка «Обновить» | перечитывает связки | `UNCHANGED` |
| Кнопка «Добавить связь» | диалог создания связки | `PROVIDER_DISPATCH`. В том же диалоге появляется выбор маркетплейса; новой страницы, вкладки и второй кнопки нет. |
| Поле «Номер склада Wildberries» в диалоге | ввод id склада WB | `MINIMAL_DELTA` в подписи: «Номер склада маркетплейса», подсказка зависит от выбранного маркетплейса. |
| Колонка «Склад Wildberries» | заголовок таблицы | `MINIMAL_DELTA`: «Склад маркетплейса» плюс `Chip` какого именно. Новой колонки не добавлять. |
| Колонки «Склад WMS», «Выгружать остатки», «Последний статус», «Обновлено» | — | `UNCHANGED` |
| Переключатель «Автоматически выгружать остатки» | наш флаг | `UNCHANGED` |

| Кнопка «Статус» | последний результат выгрузки | `UNCHANGED`. Ошибку Ozon показывать в том же виде, включая `403 code 7` человеческой строкой. |
| Кнопка «Отключить связь» и диалог подтверждения | — | `UNCHANGED` |

## Обязательный тест-кейс

Физический остаток один. Конфликт WB и Ozon за последнюю единицу обязан быть покрыт тестом до
кода: два маркетплейса не должны опубликовать один и тот же остаток дважды.
