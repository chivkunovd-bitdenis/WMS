# S-19 — исполняемый screen contract для 2Б

Это контракт будущей реализации, не verdict и не доказательство реализованного UI.

## Граница экрана

- Screen registry: `S-19`, `/app/ff/settings`, owner `FfSettingsScreen`.
- Изменяемая зона: только новая panel «Тарифы» после existing staff panel.
- Не создаются route, shell navigation, screen tab, modal-first flow или
  соседняя правка Billing/Storage/Staff.
- `FfBillingScreen` не меняется: его существующий deep link
  `/app/ff/settings?tab=tariffs` остаётся единственным входом из начислений.
  Только `FfSettingsScreen` читает `tab=tariffs` и после render/fetch scrolls и
  переводит focus на stable tariff anchor (`id`/`data-testid`, `tabIndex=-1`).
  Другие query и открытие без query не меняют existing Settings content или
  normal scroll.
- Условие видимости: только `fulfillment_admin`; отсутствие права не заменяется
  пустой таблицей и не раскрывает money configuration.

## Компоновка при ширине 1600px

1. Existing `ScreenHeader` remains exact; warehouse and staff panels retain
   order/spacing/content.
2. Tariffs heading begins below staff panel with the same outlined Paper rhythm;
   no card-inside-card. Seller table precedes employee table. Storage is a
   short existing-style link, not a duplicated tariff form.
3. Table uses existing `DataTable`: `size=small`, sticky header, fixed widths,
   numeric rates right aligned. Required seller headers: «Услуга», «Считается»,
   «Единица», «Ставка, ₽», «Действует с», «Товарные цены», «Состояние».
   Employee headers: «Сотрудник», «Приёмка», «Подбор», «Отгрузка», «Возврат»,
   «Упаковка».
4. Horizontal overflow belongs only to existing table container; headings never
   overlap/crop, controls do not leave the Paper, and columns do not jump among
   loading/empty/error/disabled states. Judge records 1600px screenshot.

## Visible states and actions

- Loading: `TableSkeletonBody`; no misleading empty success.
- Empty: `EmptyState` says that rates are absent and tells admin to configure.
- Error: `ErrorNotice`, Russian action text, current rows remain visible.
- Disabled: product-price control disabled for document unit with tooltip/reason;
  save disabled while request pending or no actual draft change with a reason.
- Enabled/disabled service state is text/`StatusChip`, never a colored whole row.
- Actions use `PrimaryAction`/`SecondaryAction`/`ActionGroup`; no local Button
  analogue. No custom Select/filter/tab/dropdown: only existing permitted
  composition and MUI controls already used by S-19.

## Acceptance proof

Implementation must add stable `data-testid` only in S-19 and one targeted
Playwright flow, including `/app/ff/settings?tab=tariffs` anchor focus/scroll
and no-query scroll regression. It must run unit/type/build, targeted
Playwright, staff, ledger and invoice regressions, `ui_guard`,
invariants/screenshot evidence. A separate Terra ui-critic cites UX canon
sections 1–3; a different Terra judge completes the scenario in a live browser
at 1600px. Neither is the implementation author.
