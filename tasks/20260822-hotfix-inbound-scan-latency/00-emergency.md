# Срочный hotfix: задержка сканирования на приёмке

Статус: `EMERGENCY_BYPASS_USER_APPROVED`

Владелец 22.08.2026 прямо потребовал срочно исправить production: после скана товара
оператор ждёт несколько секунд, иногда видит ошибку. Скан должен подтверждаться практически
сразу, при этом нельзя менять смысл приёмки, штрихкоды, количества или работу сканера.

## Наблюдаемый production-контур

- основной живой трафик: `POST /operations/inbound-intake-requests/{request_id}/boxes/{box_id}/scan`;
- после каждого успешного POST интерфейс полностью перечитывает документ;
- backend на каждом скане повторно загружает полный граф документа и каталог селлера;
- внешних вызовов WB в горячем пути нет;
- один `404` между успешными сканами того же короба может означать `barcode_unknown`, потому что
  этот бизнес-ответ сейчас ошибочно отображается тем же HTTP-статусом, что и отсутствующий короб.

## Граница hotfix

1. Ускорить скан в свободную приёмку и в открытый короб без изменения допустимых штрихкодов.
2. Не загружать весь каталог селлера, если документ уже задаёт конечный набор товаров.
3. Не выполнять отдельную проверку по каждой строке документа после одного скана.
4. Интерфейс применяет ответ POST сразу: обновляет количество и выделяет последнюю успешно
   отсканированную строку спокойным зелёным цветом. Полная сверка может идти фоном и не блокирует
   следующий скан.
5. Не трогать FBS, адресное хранение, распределение по WB-коробам, печать, WB API и миграции.

Это аварийная стабилизация, а не продуктовая приёмка новой функции.
