# Регресс-кейсы hotfix сканирования

| TC-ID | Сценарий | Applies | Given / When / Then и ограничение |
|---|---|---|---|
| TC-NEW-SCAN-001 | Скан товара в свободную приёмку | Y | Given товар уже есть в документе, When оператор сканирует SKU или WB-штрихкод, Then количество увеличивается ровно на 1 и ответ не зависит от размера каталога селлера. Negative: товар другого документа не принимается. |
| TC-NEW-SCAN-002 | Скан товара в короб | Y | Given открыт короб приёмки, When оператор последовательно сканирует товары, Then каждый успешный скан увеличивает только нужную строку на 1. Restriction: количество в других коробах и свободной приёмке не меняется. |
| TC-NEW-SCAN-003 | Неизвестный штрихкод | Y | Given код не принадлежит товарам документа, When он отсканирован, Then оператор получает понятную ошибку, данные и предыдущий успешный результат не меняются. |
| TC-NEW-SCAN-004 | Мгновенная обратная связь | Y | Given открыт экран приёмки или наполнения короба, When POST скана успешен, Then счётчик и зелёное выделение последней строки меняются из ответа POST без ожидания полной перезагрузки документа; следующий успешный скан переносит выделение. |
| TC-NEW-SCAN-005 | Никаких внешних вызовов | Y | Given выполняется обычный scan POST, When сервер обрабатывает код, Then он использует только локальную БД и не обращается к WB. Negative: недоступность WB не должна задерживать или ронять скан. |

Production smoke после выкладки: health, вход в существующий документ без изменения данных,
один реальный операторский скан либо наблюдение первого штатного скана по access-log; никаких
искусственных POST в живой документ без оператора.
