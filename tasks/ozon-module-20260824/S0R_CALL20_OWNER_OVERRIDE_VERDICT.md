# S0R Call 20 — owner override verdict

**Дата:** 24 августа 2026 года

**Результат:** `PRODUCT_REJECTED`. Call 20 не допускается к gate/browser acceptance и не коммитится как продуктовый результат.

## Высший продуктовый принцип

Существующий процесс отгрузки не меняет экран и операторский путь. Для Ozon сборка, снятие из ячеек, подбор, упаковка и отгрузка проходят тем же существующим путём. То же правило действует для FBS. Отличие разрешено только после ссылки на официальный процесс Ozon и доказательства конкретной жёсткой несовместимости, которую нельзя выразить текущим действием, полем, этикеткой или условным состоянием в существующей зоне. Если такого доказательства нет, UI остаётся baseline.

Этот короткий принцип имеет приоритет над прежними длинными контрактами и прототипами.

## Находки Call 20

1. `FfSuppliesShipmentsPage.tsx` добавляет условный `ozon-fbo-pick-panel` вместо использования текущего `FfMpUnloadPickPanel`. Официальная несовместимость не приведена.
2. Тот же файл добавляет `ozon-fbo-packaging-context` с отдельными Ozon-действиями для коробов, грузомест и этикетки вместо доказанного расширения текущего PackagingTask/box flow. Официальная несовместимость каждого действия не приведена.
3. `FfFbsSupplyWorkspace.tsx` продолжает содержать отдельные Ozon-панели упаковки и коробов внутри текущих стадий. Сам факт размещения в существующей modal не доказывает переиспользование операторского процесса.
4. FBO fixture заменяет текущую товарную таблицу на условный набор колонок. Это изменение baseline UI без доказанной жёсткой необходимости.
5. Call 20 ссылается на внутренний контракт, но не даёт official-source matrix `текущий WMS шаг → официальный Ozon шаг → совместимо/несовместимо → неизбежная минимальная дельта`. Поэтому ни одна дополнительная панель или новый операторский action не допустимы.
6. Build и structural scope gate зелёные, но не проверяют новый высший принцип; они не отменяют продуктовый отказ.

## Обязательный следующий шаг

До любых новых application edits отдельный research-call должен по актуальным официальным материалам Ozon доказать только неизбежные различия FBS/FBO относительно уже наблюдённых WMS baseline-процессов. Результат — построчная delta matrix с официальной ссылкой, датой/версией, конкретной несовместимостью и минимальной существующей UI-зоной. Строка без доказательства получает решение `UI unchanged`.

После research архитектор удаляет из контракта и реализации все недоказанные условные панели/шаги. Незакоммиченный Call 19/20 diff остаётся отклонённым и не является основой для browser approval.
