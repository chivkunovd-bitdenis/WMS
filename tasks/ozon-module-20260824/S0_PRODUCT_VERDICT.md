## Находка S0-PROD-001 — параллельный Ozon UI вместо расширения текущих процессов

Прототип создал отдельные Ozon FBS и Ozon FBO разделы. Это нарушает исходное требование минимально затронуть фронт и органично уложить новые маркетплейсы в существующую WMS.

Необходимый результат rework:

1. Существующий полноценный FBS-flow становится marketplace-agnostic. Ozon подключается через adapter/capabilities; внутри текущих очереди и workspace добавляются только реально отличающиеся поля, статусы, этикетки и действия Ozon.
2. Ozon FBO не получает отдельный раздел. Он подключается к существующему документу и процессу отгрузки; Ozon-specific API steps, cargo/ТГМ, документы и состояния появляются внутри него только там, где без них нельзя выполнить физическую работу.
3. Существующие каталог и настройки селлера расширяются marketplace account, сопоставлениями и подключением Ozon. Параллельные Ozon-only каталог/connection экраны не создаются без доказанной необходимости.
4. Новый UI разрешён только для действия или данных, которые действительно отсутствуют в существующем процессе и не могут быть органично размещены в его текущей зоне.
5. Wildberries остаётся рабочим adapter того же операторского процесса; универсализация не должна менять его наблюдаемое поведение без отдельного требования.

## Жёсткий reuse-first контракт

Reuse-first является default и должен проверяться контрактом и машинными гейтами, а не оставаться общей рекомендацией.

Любой новый экран, вкладка, документ, отдельный workspace, маршрут или операторский шаг запрещён, пока архитектор не докажет конкретную несовместимость с существующим FBS, FBO/отгрузками, каталогом или настройками и почему её нельзя закрыть adapter/capability, дополнительным полем, фильтром или условным состоянием существующего UI.

Архитектурный rework обязан содержать полную reuse map в форме:

`текущий экран/процесс → минимальное изменение → доказанная Ozon-необходимость`.

Элемент без такой строки удаляется из архитектуры, прототипа и implementation scope.

Browser-call `08-prototype-browser-acceptance` был немедленно прерван после получения этого вердикта. Дальнейшая приёмка отвергнутого S0 запрещена; архитектура возвращается на reuse-first rework.
