# S05 PROCESS_MAP — BLG-D08

## Источник

Backlog item: `BLG-D08` — Удалить или реально подключить мёртвый экран FfFbsPickList

Business meaning:
В проекте лежит экран FfFbsPickList, который не подключён к приложению и используется только тестом. Разработчик может принять его за рабочий экран, внести туда исправление и потратить время на поиск причины, почему пользователь ничего не видит. Нужно проверить, есть ли у файла самостоятельная продуктовая роль, после чего либо подключить его через явный маршрут, либо удалить вместе с вводящими в заблуждение тестами и ссылками.

Dependencies: нет
Client item count: 0

## Process Map

### Actor and physical action
Основной актор — сотрудник фулфилмента или инженер WMS, который должен получить управляемый процесс вместо скрытой ручной диагностики. Физическое действие определяется карточкой: очистка/подключение экрана, безопасная ревизия worktree, решение по печати QR, либо разрезание клиентского списка на атомарные складские сценарии.

### Document and data
Входной документ — backlog item с полным `business_meaning`; для `BLG-KC01` дополнительно применимы `client_items`, каждый должен стать отдельной атомарной карточкой до Dev. Данные, которые нельзя выдумывать на этой стадии: live marketplace response, production database state, реальные секреты и release SHA.

### Success path
1. Зафиксировать текущую проблему и складскую ценность.
2. Назвать роли, документ/экран/API/данные, которых касается процесс.
3. Отделить автоматическое действие WMS от ручного действия человека.
4. Передать в S06 список зон WMS для reuse/extend/new/reject.

### Empty, error, repeat and cancel states
Пустое состояние должно объяснять отсутствие применимых объектов, а не выглядеть как потерянные данные. Ошибка должна быть привязана к безопасному следующему действию: повторить диагностику, открыть связанный документ, либо остановить stage с typed blocker. Повтор процесса должен быть идемпотентным: второй запуск не удаляет чужой diff, не печатает боевые QR и не создаёт release-действий.

### Observable trace
Минимальный след: этот `S05-PROCESS-MAP.md`, controller receipt, следующий packet/dispatch, а позднее S06 GAP with file/screen/API boundaries.
