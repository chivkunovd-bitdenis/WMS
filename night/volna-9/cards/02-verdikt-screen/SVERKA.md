# Сверка · 02-verdikt-screen

ВЕРДИКТ: ЧИСТО

ТИП: фича

## Тип

В разборе стоит «фича» — верно.

Раздел в системе уже есть и живёт: экран FBS-заказов (`FfFbsOrdersScreen.tsx`),
рабочий экран поставки (`FfFbsSupplyWorkspace.tsx`), сервис маркировки
(`fbs_marking_service.py`) со справочником `map_wb_decision_to_meta_status`,
гейт сдачи (`compute_delivery_allowed`, `fbs_shipment_service._build_delivery_checks`).
Владелец просит поправить существующее поведение («показывать раньше — до
передачи», «сдача только когда WB подтвердил»), а не спроектировать новую
предметную область. Домен и ресёрч тут не нужны — это фича на существующем
разделе.

## Расхождения

Расхождений нет. Каждый пункт «Что должно быть» тянется из первоисточника:

- «Справочник вердиктов знает все живые значения WB» ← «Справочник вердиктов
  не знает ни одного реального значения — всё приходящее превращается в
  „неизвестно“».
- «Гейт сдачи только по WB-подтверждению» (compute_delivery_allowed → только
  ACCEPTED/ALLOWED_WITHOUT_CHECK без непустого reason) ← «Сдача разрешена
  только тогда, когда Wildberries подтвердил» и «Признак „сдавать можно“
  система выставляет по собственному оптимистичному предположению».
- «Строка заказа показывает вердикт WB словами» + словарь `metaStatus.ts`
  + правка `FfFbsSupplyWorkspace.tsx` ← «настоящий вердикт маркетплейса виден
  словами прямо в строке заказа сразу после привязки кода, человек чинит
  по ходу работы».

Допущения 1–3 явно помечены как трактовки аналитика, а не как воля владельца,
и все выбраны в осторожную сторону («никогда не показать „можно“, пока WB
не сказал»), что прямо соответствует последнему предложению цитаты.

## Проверено

Просьбы владельца, которые нашёл в разборе:

- «блокировка на сдаче есть и работает, вопрос в том, чтобы показывать раньше —
  до передачи» → раздел «Гейт сдачи сейчас» подтверждает, что гейт есть;
  требование показывать раньше отражено в пункте 3 («сразу после привязки кода»).
- «Признак „сдавать можно“ система выставляет по собственному оптимистичному
  предположению» → раздел «Оптимистичный признак „сдавать можно“ именно здесь»
  и пункт 2 «Гейт сдачи только по WB-подтверждению».
- «На бою по всем двадцати шести заданиям стояло „можно“, пока Wildberries
  отказывал» → объяснено механикой `filled → ACCEPTED`.
- «Справочник вердиктов не знает ни одного реального значения» → пункт 1
  «Справочник вердиктов знает все живые значения WB» (required, optional,
  notRequired).
- «Оператор узнаёт о проблеме в конце дня, на сдаче, когда чинить поздно» →
  пункт 3, показ словами в строке заказа сразу после привязки.
- «настоящий вердикт маркетплейса виден словами прямо в строке заказа» →
  пункт 3 + словарь `metaStatus.ts`.
- «Сдача разрешена только тогда, когда Wildberries подтвердил» → пункт 2 и
  признак «получилось».
