# JUDGE · 03-no-distribution-mode

## Что судил

Карточка «Режим "без распределения" нельзя включить после создания коробов»
(экран `S-03`, `/app/ff/fbs`, вкладка «Короба» в `FfFbsSupplyWorkspace`).
Назначено 7 кейсов `S-03-TC-001..007` (см. `tests/cases/S-03.md`), проверяющих
три дефекта владельца из `ISTOCHNIK.md`:

1. Галка «Без распределения» блокируется при наличии любого короба.
2. Признак режима слетает при пересоздании коробов.
3. Шапка пишет «Распределено 0 из N» при включённом режиме.

Разработчик (`DEV.md`) применил ветку `fix/no-distribution-20260821`: миграция
`20260821_0094`, новые поля `boxes_without_distribution_at` /
`_by_user_id` на `FbsSupply`, роут
`POST /operations/fbs-supplies/{supply_id}/boxes-without-distribution`, охрана
`boxes_already_distributed`, чекбокс в Tooltip. Ревью (`REVIEW.md`) и
дизайн-ревью (`DESIGN-REVIEW.md`) — ЧИСТО.

## Находки

### Стоп-1 · Снимков ни по одному кейсу нет, живой стенд не открывался

**Источник:** `night/volna-9/cards/03-no-distribution-mode/CLICKS.md` (раздел
«Статус»), пустая директория
`docs/evidence/03-no-distribution-mode/` (0 файлов), `night/volna-9/JOURNAL.md`
(строки 46–71).

**Что сказано в CLICKS.md:** «РАБОТА НЕ НАЧАТА — БЛОКЕР: СТЕНД НЕ ДОСТУПЕН».
Кликер в первом запуске (10:16–10:19) записал, что в системном промпте
отсутствовали адрес стенда, логин и пароль, а инструкция запрещает поднимать
стенд самому. Все последующие вызовы кликера в журнале
(«05:18/10:16/10:37/10:53 clicker: уже сделано, пропускаю») отработали по
идемпотентности и снимков не сняли — даже после двух раундов правок
разработчика (10:22 круг 1, 10:40 круг 2, 10:53 круг 3 dev готово).

**Почему это Стоп:** правило судьи говорит буквально — «Кейс без снимка
пройденным не считается, что бы ни было написано. Нет картинки — нет
доказательства, и это находка сама по себе». Ни один из семи кейсов
`S-03-TC-001..007` физически не подтверждён живым UI: не подтверждена
разблокировка чекбокса при пустых коробах (TC-003), не подтверждено, что
шапка перестала выводить «Распределено 0 из 155» (TC-002), не подтверждено,
что признак переживает пересоздание коробов (TC-005) — то есть все три
дефекта владельца остаются формально не проверенными на живом экране, хотя
код правки лежит в дереве.

**Ведро:** Стоп по правилу судьи (нет доказательства прохождения ни одного
кейса), несмотря на то что для оператора в проде дефекты, по коду, устранены
разработчиком (что подтверждает `REVIEW.md`).

**Ссылка на снимок:** снимка нет — это и есть предмет находки.
`docs/evidence/03-no-distribution-mode/` создана, но пуста.

**Что нужно оркестратору по этой находке (запись, не блокер):** прогнать
кликера ещё раз с реальным адресом стенда/логином/паролем в промпте, иначе
до утра владелец получит закрытую карточку без единого доказательства работы
на живом UI.
