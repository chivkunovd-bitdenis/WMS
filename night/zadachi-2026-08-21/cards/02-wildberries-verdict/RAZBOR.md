## Что должно быть

Оператор, глядя на строку заказа сразу после привязки кода, видит одно из трёх состояний
человеческими словами:
- **«ждём WB»** — мы отправили код, ответа ещё нет (нейтральный маркер, без цвета);
- **«WB принял»** — WB вернул один из подтверждённо-позитивных `decision` из класса
  `CONFIRMED_ALLOW` (`filled`, `sgtinIntroduced`, `sgtinSoldB2B`, `imeiMaySell`,
  `imeiSoldB2B`, `uinMaySell`, `optional` при разрешении по продуктовому справочнику);
- **«WB отказал: <причина>»** — WB вернул любое значение из класса `BLOCK` (или
  `WB_ELIGIBLE_UNCONFIRMED` / `WAIT` / `UNKNOWN_BLOCK` / `INCOMPLETE_BLOCK`); причина —
  короткая русская фраза, за ней сохраняется `decision_raw` для поддержки.

Никаких «зелёная строка без ответа» и никаких «пусто» между привязкой и вердиктом больше
не бывает.

Правило готовности одно на бэк и фронт: заказ считается готовым к сдаче, только если по
всем требуемым видам маркировки последний вердикт WB — `CONFIRMED_ALLOW`. Все остальные
классы (включая `WAIT`, `WB_ELIGIBLE_UNCONFIRMED` типа `deadlineExceeded`, любые
`UNKNOWN_BLOCK`) — «ждём», а не «готово».

Словарь вердиктов расширен до реального актуального перечня WB по S03 BLG-I02 (полные
таблицы уже собраны, ссылки на официальные источники — там же). Любое непонятное
значение (потенциально новое или очень редкое) падает в `UNKNOWN_BLOCK`, оператор видит
явное «ответ WB не распознан — обратитесь в поддержку», код не считается принятым.

Признак сдачи на самой поставке (кнопка «Передать в WB» и совокупный прогресс) поднимается
только тогда, когда все заказы поставки — с подтверждённым `CONFIRMED_ALLOW`. Серверный
гейт `_build_delivery_checks` менять не надо — он и сейчас строгий; надо снять оптимизм с
фронта, поправить `compute_delivery_allowed` (убрать возврат `True` на пустом `required`,
пока это не выяснено у WB) и завести раздел «вердикт WB» в строке заказа.

Признак, по которому поймём, что получилось: возьми боевой день, где 26 заданий с
негативным вердиктом WB. Сегодня у всех у них строка на S-03 пустая или зелёная в
задании упаковки, а гейт срабатывает только в момент сдачи. После правки — строка каждого
из 26 заданий сразу после первой синхронизации с WB показывает «WB отказал: <текст>»,
оператор видит проблему в течение первого автопулла (≤ N минут), а не в конце дня.

жёлтый маркер, не смешивая с «готово».

**Зависимость, не вопрос.** Реальная реализация видимого вердикта имеет смысл только
после/вместе с задачей №1 `01-wildberries-marking`: без рабочего чтения WB словарь всё
равно нечего наполнять. Обе задачи атомарны, но пока №1 не сделана — сколько словарь ни
расширяй, живой ответ не пойдёт. Архитектору стоит планировать №1 и №2 как одну волну.
