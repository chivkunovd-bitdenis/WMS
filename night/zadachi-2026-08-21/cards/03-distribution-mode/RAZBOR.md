# RAZBOR · 03-distribution-mode

## Дословно

> Галка блокируется, как только создан хотя бы один короб. Оператор, который сначала создал
> короба, а потом понял, что раскладывать не нужно, оказывается в тупике: только удалять и
> создавать заново. Двадцатого августа режим переключали правкой в базе дважды — после первого
> раза короба пересоздались и признак слетел. Сам признак хранится не как признак, а припиской
> к служебному ключу короба. Вдобавок шапка при включённом режиме всё равно писала
> «Распределено ноль из ста пятидесяти пяти» и пугала оператора красной цифрой.
>
> Должно стать: режим переключается, пока в короба ничего не разложено; признак живёт в
> нормальном поле; шапка показывает то, что соответствует режиму.

Источник: `night/zadachi-2026-08-21.md`, строки 46-58, раздел «Из разбора дефектов»,
подзаголовок «Режим "без распределения" нельзя включить после создания коробов · ТЗ пишется».

### Что именно чинил тот наряд

Разбор коротко, из кода веток `etalon` и `fix/no-distribution-20260821`:

1. **Признак раньше хранился припиской к идемпотентному ключу коробa.**
   `backend/app/services/fbs_packing_box_service.py:41,314-326` — константа
   `WITHOUT_DISTRIBUTION_KEY_PREFIX = "no-distribution:"` и функция `_stored_creation_key`,
   которая при создании коробов с галкой пишет её в `FbsPackingBox.creation_idempotency_key`.
   Функция `_box_without_distribution(box)` определяет режим по `box.creation_idempotency_key.startswith(prefix)`.
   Служебный ключ идемпотентности — не хранилище состояния: если короба пересоздать другим
   ключом (что и случилось 20.08 после правки в базе), признак не переносится.

2. **Переключатель заблокирован после первого короба.**
   `frontend/src/screens/v2/FfFbsSupplyWorkspace.tsx:2030` — чекбокс имеет
   `disabled={!stageIsCurrent || !packagingEditable || workspace.boxes.length > 0}`.
   Как только на поставке появился один короб — галку не двинуть, вне зависимости от того,
   пустой он или уже с заказами.

3. **Шапка показывает «Распределено X из Y» даже в режиме «без распределения».**
   `FfFbsSupplyWorkspace.tsx:1278` — `hasNoDistributionBoxes` считается только сканом
   по массиву коробов (`workspace?.boxes.some((box) => box.without_distribution)`), поле на
   поставке не читается. Если режим был включён, но короба ещё не созданы (или их пересоздали
   без приставки) — шапка на строке 2011-2013 идёт в ветку `Распределено ${boxDistributedCount}
   из ${boxTotalCount} шт · осталось ${boxRemainingCount}` и красит нули красным.

4. **Backend-условие для шапки/этапа тоже гасило флаг при пустом списке коробов.**
   `backend/app/services/fbs_workspace_service.py:506-507` — `return bool(boxes) and any(...)`
   отдаёт `False`, если коробов ещё нет. Тот же паттерн в `fbs_packing_box_service.py:329-330`.

### Что предложено фикс-веткой (по коммитам)

- Миграция `backend/alembic/versions/20260821_0094_fbs_supplies_boxes_without_distribution.py`
  добавляет на `fbs_supplies` пару полей `boxes_without_distribution_at (timestamptz)` и
  `boxes_without_distribution_by_user_id (uuid → users.id, ON DELETE SET NULL)`. Паттерн один-в-один
  с `honest_sign_skipped_at/by_user_id`, что уже прижилось на этой таблице.
- Модель `backend/app/models/fbs_supply.py` — эти же два поля с комментарием, что до 21.08
  признак прятался в `creation_idempotency_key` (дефект I15).
- Новый роут `POST /operations/fbs-supplies/{supply_id}/boxes-without-distribution`
  (`backend/app/api/fbs_supplies.py:1280-1309`) с телом `{ "enabled": bool }` — идемпотентный
  переключатель. Возвращает актуальный `FbsWorkspaceOut`.
- `set_boxes_without_distribution` в сервисе — общая проверка: если хотя бы в одном коробе
  поставки есть назначенный заказ, переключение отклоняется кодом `boxes_already_distributed`
  (в API маппится в 409, `retryable=false`).
- Обратная совместимость: старое чтение `WITHOUT_DISTRIBUTION_KEY_PREFIX` сохранено как
  «фолбэк для коробов, созданных до переноса» — данные не мигрируют, но старые поставки
  режим не теряют.
- Фронт: новая функция `setFbsBoxesWithoutDistribution` в `fbsApi.ts`, поле
  `boxes_without_distribution?: boolean` в `FbsWorkspace.supply`, `hasNoDistributionBoxes`
  читает сначала поле на поставке (`workspace.supply.boxes_without_distribution`), потом
  фолбэк по коробам; чекбокс отключается только если в коробах уже есть заказы, а не по
  факту наличия коробов; при клике до создания коробов — локальный предвыбор, после — HTTP-переключатель.
- Тест `backend/tests/test_fbs_packing_box.py::test_boxes_without_distribution_flag_survives_empty_box_list`
  проверяет главный сценарий: включили переключателем при нулевых коробах →
  `/workspace` показывает `supply.boxes_without_distribution = true`.

## Что должно быть

Требование владельца из ISTOCHNIK разложено на три проверяемых признака. Всё нужное для
каждого уже есть в `fix/no-distribution-20260821`; ниже — как понять, что дошло до боевого
экрана после раскатки.

1. **Режим переключается, пока в короба ничего не разложено.**
   Признак: на вкладке «Короба» чекбокс «Без распределения» кликается и до создания первого
   короба, и после — до тех пор, пока сумма назначенных заказов по всем коробам равна нулю.
   Если хотя бы один заказ в коробе есть, чекбокс отключён, и рядом видно пояснение
   «В короба уже разложены заказы — сначала уберите их из коробов» (реализовано в
   `FfFbsSupplyWorkspace.tsx` из wip-коммита 9e2808e через Tooltip). Попытка переключить
   через API в этом состоянии возвращает 409 `boxes_already_distributed`.

2. **Признак живёт в нормальном поле.**
   Признак: в таблице `fbs_supplies` есть колонки `boxes_without_distribution_at` и
   `boxes_without_distribution_by_user_id`; операция переключения пишет туда `now()` и
   `user_id`, а `WITHOUT_DISTRIBUTION_KEY_PREFIX` больше не участвует в записи новых
   коробов (`create_boxes` пишет чистый `idempotency_key`). Пересоздание коробов
   (удалить все → создать заново) не сбрасывает режим.

3. **Шапка вкладки коробов соответствует режиму.**
   Признак: если `supply.boxes_without_distribution = true`, шапка пишет
   «Без распределения · коробов N» независимо от того, сколько коробов есть и сколько
   заказов «распределено». Красная фраза «Распределено 0 из 155 шт» в этом режиме не
   появляется никогда, включая момент между «включил галку» и «создал первый короб».

Заказы, вручную снятые в базе 20.08 через прямую правку `creation_idempotency_key`,
после раскатки продолжат работать за счёт фолбэка на приставку — миграция данных не
требуется.

## Вопросы и допущения

- **Допущение** (не блокирующее): формулировка «пока в короба ничего не разложено»
  трактуется как «пока ни в одном коробе поставки нет ни одного `FbsPackingBoxItem`».
  Именно так проверяет `_ensure_without_distribution_flag` в `fix/no-distribution-20260821`.
  Альтернативная трактовка «пока не создан ни один короб» — старое поведение, оно и есть
  причина дефекта; владелец её явно отверг («Двадцатого августа режим переключали правкой
  в базе дважды — после первого раза короба пересоздались»).
- **Вопрос владельцу** (не блокирующий раскатку): нужен ли рядом с чекбоксом видимый
  бейдж-объяснение «режим включён такой-то оператор такого-то числа», раз мы теперь храним
  `by_user_id` и `at`? В текущей реализации поля пишутся, но на экран не выводятся.
  Если ответ «нет» — просто оставляем как есть; если «да» — это отдельная мелкая доработка
  фронта, не мешает выкатке основной правки.
- **Вопрос владельцу** (по сопутствующему домену, вне ISTOCHNIK): нужно ли добавить в
  `docs/blockers/S-03.md` строчку про новую бизнес-охрану «нельзя выключить режим, если в
  коробах уже есть заказы» (код `boxes_already_distributed`, 409). Сама блокировка
  осмысленна и совпадает с симметричной для включения; в S-03 сейчас описан только старый
  вариант B-09.
