# Карточка 05 — контракт экрана S-03 при постраничной загрузке FBS

Экран: **S-03**, маршрут `/app/ff/fbs`, компонент `FfFbsOrdersScreen`.
Затрагиваемые зоны: фильтры, таблица и панель действий под таблицей. Новый экран не создаётся.
Backend-опрос Wildberries, очереди, память, метрики и административная диагностика не
проектируются как пользовательский интерфейс этой карточки.

## Контракт

### Что меняется

1. Рабочий список загружается страницами по 50 строк. При первом открытии вкладки экран получает
   только первую страницу. Если сервер вернул `next_cursor`, под таблицей показывается главное
   действие `Показать ещё`, собранное только из `PrimaryAction`. Нажатие добавляет следующую
   страницу в конец уже видимого списка, не повторяя строки с тем же ID. Уже показанные строки
   во время дозагрузки остаются на месте; ниже них появляются строки-скелеты из
   `TableSkeletonBody`. После последней страницы действие исчезает. Это **ДЫРА** в действующем
   каноне; предложено R-37.

2. Cursor (непрозрачная метка следующей страницы) сбрасывается при смене вкладки, селлера,
   склада или серверного поискового запроса. Экран заменяет список первой страницей нового
   набора, а последующие нажатия `Показать ещё` продолжают именно этот набор. Фильтры не
   сбрасываются при дозагрузке. Это **ДЫРА**; предложено R-37.

3. Автоматическое обновление и существующее действие `Обновить` запрашивают только первую
   страницу текущего набора. Они обновляют совпавшие строки, добавляют новые и не скачивают
   заново уже загруженные последующие страницы. Выбранные оператором заказы и их данные в
   `selectedCache` не теряются; при объединении страниц дубли по ID не появляются. Подпись
   `Обновить` сохраняется как уже существующая в UI-инвентаре. Это **ДЫРА**; предложено R-37.

4. Состав таблицы не меняется. На вкладке `Новые` остаются колонки `Товар`, `Селлер`,
   `Маршрут сдачи`, `Отгрузить до` и существующая колонка выбора без текстового заголовка.
   На остальных вкладках дополнительно остаётся `Статус`. Новых колонок, чипов, счётчиков
   страниц и технических полей (`cursor`, номер job, режим poll, время worker) нет. Таблица
   собирается из `DataTable`, ячейки — из `ProductCell` и `TextCell`, состояние — из
   `StatusChip`; названия существующих сущностей не переименовываются (R-04, R-07, R-09,
   R-10, R-14, R-35, R-36).

5. Поиск и действующие фильтры остаются над таблицей в `FilterBar`. Пагинация не добавляет
   отдельной панели фильтров и не переносит фильтры в таблицу (R-03).

6. Дозагрузка — единственное новое видимое действие. Оно находится под таблицей, не помещается
   в строку заказа и не выглядит как печать или опасная операция. Подпись состоит из двух слов,
   не переносится и не меняется между страницами (R-31, R-32, R-36).

### Состояния

- **Первая загрузка.** В таблице показываются пять строк-скелетов через `TableSkeletonBody`;
  спиннер поверх пустого экрана не используется (R-22).
- **Дозагрузка.** Уже загруженные строки остаются видимыми, а внизу таблицы появляются строки-
  скелеты. Повторное нажатие до ответа невозможно; новая параллельная дозагрузка не запускается
  (R-22; правило последовательной cursor-дозагрузки — ДЫРА, предложено R-37).
- **Успех.** Следующая страница дописывается без скачка колонок, потери фильтров или выбора.
  Отдельный toast об успехе не показывается: видимый результат — появившиеся строки, и экран
  не рапортует о действии, которого пользователь не совершал (R-09, R-24; сохранность выбора —
  ДЫРА, предложено R-37).
- **Последняя страница.** `Показать ещё` исчезает. Техническую подпись `next_cursor = null` и
  сообщение «все страницы загружены» экран не показывает (R-24, R-30).
- **Пустой набор.** `EmptyState` показывает `Заказов в этой группе нет` и подсказку
  `Измените фильтры или нажмите «Обновить».` На серверном поиске без совпадений заголовок —
  `По запросу ничего не найдено`, подсказка — `Измените или очистите поиск.` (R-21).
- **Ошибка первой страницы.** `ErrorNotice` в теле экрана показывает
  `Не удалось загрузить заказы. Повторите попытку.` без HTTP-кода и технических деталей;
  рядом доступно главное действие `Повторить` из `PrimaryAction` (R-23, R-30, R-31).
- **Ошибка дозагрузки.** Уже показанные строки и выбор сохраняются. Под таблицей `ErrorNotice`
  сообщает `Не удалось показать следующую страницу. Повторите попытку.`; действие `Повторить`
  повторяет тот же cursor, а не начинает список заново (R-23, R-30; сохранность страницы —
  ДЫРА, предложено R-37).
- **Ошибка фонового обновления.** Видимые строки не очищаются. `ErrorNotice` сообщает
  `Не удалось обновить список. Показаны ранее загруженные заказы.`; пользователь может нажать
  существующее `Обновить` (R-23, R-24, R-30).

### Чего на экране нет

- Нет нового экрана мониторинга, модального окна прогресса, колонок или чипов фоновой работы
  (R-10, R-14, R-35).
- Нет ручного выбора режимов `delta`, `status`, `reconcile`, очереди или cursor: это технические
  понятия и они не попадают в язык оператора (R-30).
- Нет номеров страниц и перехода на произвольную страницу: backend-контракт cursor не обещает
  стабильной нумерации; пользователь последовательно раскрывает рабочий список. Канон это не
  покрывает; предложено R-37.
- Нет изменений S-14, workspace поставки, печати, состава строк, статусов, палитры, плотности
  и соседних FBS-сценариев (R-07, R-10, R-13, R-14).

## Канон

| Пункт контракта | Правило канона |
|---|---|
| Единственная таблица в светлом контейнере, малая плотность | R-04, R-07 |
| Фиксированные названия и ширины колонок, без переноса заголовков | R-09, R-10, R-36 |
| Статус остаётся коротким чипом, не дублируется в строке | R-14, R-35 |
| Фильтры остаются над таблицей | R-03 |
| `Показать ещё` — короткое главное действие под таблицей | R-31, R-32, R-36 |
| Первая загрузка и дозагрузка показываются скелетами строк | R-22 |
| Пустота объясняет, что сделать дальше | R-21 |
| Ошибка написана на языке склада и не содержит технических деталей | R-23, R-30 |
| Экран не показывает ложный успех и внутренние статусы фоновой системы | R-24, R-30 |
| Новых колонок, технических чипов и дублей сущности нет | R-10, R-14, R-35 |
| Первая страница 50 строк, последовательная cursor-дозагрузка, сброс cursor при смене набора, дедупликация, сохранение строк и выбора при дозагрузке/обновлении | **ДЫРА → предложено R-37** |

### Предложение владельцу для канона

**R-37 · ДЫРА.** Длинный рабочий список открывается первой страницей не более 50 строк и
дозагружается явным действием `Показать ещё`. Смена вкладки, фильтра или серверного поиска
начинает новый набор с первой страницы. Дозагрузка и фоновое обновление не очищают уже видимые
строки и выбор оператора; повторные ID не показываются. Ошибка следующей страницы сохраняет
текущий список и позволяет повторить тот же cursor.

## Нехватка ui-kit

Пусто. Для контракта достаточно `DataTable`, `ProductCell`, `TextCell`, `StatusChip`,
`FilterBar`, `PrimaryAction`, `EmptyState`, `TableSkeletonBody` и `ErrorNotice`.

Дальше: после утверждения контракта владельцем передать карточку `screen-dev` для реализации
ровно постраничного поведения S-03 без изменений соседних экранов.
