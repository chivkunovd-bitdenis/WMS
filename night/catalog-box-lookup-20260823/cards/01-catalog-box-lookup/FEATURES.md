### 1. Зафиксировать результат адресного скана после успешного повтора списка

Тест должен дождаться второго `GET /operations/inbound-packages` и исчезновения скелетона перед этой проверкой, чтобы не пройти до прихода успешного ответа.

### 2. Защитить пользовательские сценарии гонки адресных сканов

Оператор может начать новый ввод, пока предыдущий адресный поиск ещё выполняется, либо повторить тот же скан. E2E-сценарии должны реально оборвать устаревший запрос на сетевом уровне, чтобы исполнился `catch`, и отдельно проверить два одинаковых скана до ответа: поздний ответ не показывает ложное «не найдено», не меняет фокус/выделение нового ввода и не создаёт две видимые строки одного короба.

Файлы:

- `/Users/deniscivkunov/Projects/WMS/.worktrees/.night-worktrees/catalog-box-lookup-20260823/lane-1-01-catalog-box-lookup/frontend/tests-e2e/catalog-box-lookup.spec.ts`

Зависит от: фичи 1 только из-за последовательной работы в одном файле; по поведению опирается на уже принятый механизм отсечения устаревших ответов.

Как проверить: запустить `S-16-TC-013`, `S-16-TC-014` и `S-16-TC-016` в браузере. Первый запрос задерживается и завершается сетевым сбоем после успешного второго поиска и начала третьего ввода; отдельный сценарий посылает два одинаковых Enter до ответа и подтверждает одну строку объекта и сохранённый фокус сканера.

### 3. Закрепить видимое состояние полной раскладки до завершения приёмки

Оператор после полной раскладки короба A, пока короб B той же приёмки ещё оставляет документ в статусе `sorting`, при адресном скане A видит «Товар из короба уже разложен», а не пустой короб. Сценарий должен создать оба короба в одной приёмке и проверять именно видимый текст в каталоге, а не только backend-ответ.

Файлы:

- `/Users/deniscivkunov/Projects/WMS/.worktrees/.night-worktrees/catalog-box-lookup-20260823/lane-1-01-catalog-box-lookup/frontend/tests-e2e/catalog-box-lookup.spec.ts`

Зависит от: фичи 2 только из-за последовательной работы в одном файле; по поведению опирается на уже принятую выдачу `fully_distributed`.

Как проверить: выполнить `S-16-TC-008` в варианте с двумя коробами одной приёмки: разложить A полностью, оставить B неразложенным, открыть каталог сканом A и увидеть состояние полной раскладки при незавершённой приёмке.

### 4. Закрепить заголовок приёмки с единственным знаком номера

Оператор в заголовке найденного объекта видит номер приёмки ровно с одним `№`, когда сервер уже прислал `request_display_number` с этим префиксом. E2E-проверка должна утверждать заголовок, а не только текст «Короб № 1».

Как проверить: запустить сценарий скана короба и явно проверить видимый заголовок приёмки на один префикс `№`; вариант `Приёмка № №…` должен сделать тест красным.
