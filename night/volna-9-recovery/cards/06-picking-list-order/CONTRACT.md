# Контракт экрана · 06-picking-list-order

МАКЕТ: MOCKUP.html
UI-KIT: НУЖНЫ ModalFrame, ChoiceFilter, CheckCell; расширение PrintAction

## Контракт

### Граница изменения

Меняется только модальный «Лист подбора» внутри экрана `S-03` и результат полной
печати стикеров заказов из этого листа. Новый экран, настройка сортировки, режим
выборочной печати и новые сущности не появляются. Состав существующих колонок и
локальные отметки `Собрал` / `Упаковал` сохраняются: задача добавляет к ним только
связь с лентой через колонку `№`.

### Обычное состояние листа

1. Заголовок остаётся `Лист подбора`, под ним одна строка
   `Собрано X/Y · Упаковано X/Y`.
2. Над таблицей остаются поиск `Артикул или название` и три существующих фильтра:
   `Все`, `Не собраны`, `Не упакованы`. Они меняют только видимые строки.
3. Таблица использует `DataTable`, имеет липкую шапку, малую плотность и фиксированные
   ширины. Колонки слева направо:
   - `№` — 76 px, по центру; одиночный заказ показывается как `12`, группа как
     `12–17`, без слова «наклейки» в каждой строке;
   - `Товар` — оставшееся место; название первой строкой, артикул продавца второй;
   - `Размер` — 92 px, по центру;
   - `Кол-во` — 90 px, вправо, через `QtyCell`;
   - `Собрал` — 90 px, по центру, через `CheckCell`;
   - `Упаковал` — 90 px, по центру, через `CheckCell`.
4. Строки приходят уже в каноническом серверном порядке
   `(article, sku_code, size, product_name)` по возрастанию. Внутри товарной группы
   заказы идут по `wb_order_id`, затем по невидимому `order.id`. Клиент не сортирует
   строки повторно. Диапазоны непрерывны, не пересекаются, начинаются с `1`, а
   `Кол-во` равно числу номеров диапазона.
5. Локальная отметка `Собрал` или `Упаковал`, поиск и фильтр не перенумеровывают
   строки. Например, после скрытия диапазона `4–7` следующая видимая строка остаётся
   `8–9`, а не становится `4–5`.
6. Внизу две кнопки одной высоты: второстепенная `Закрыть` и главное печатное
   действие `Печать стикеров`. Печать всегда охватывает все заказы поставки в
   полном каноническом порядке и с постоянными номерами полного листа. Поиск,
   фильтр и локальные отметки на состав печати не влияют.

### Лента и номер заказа

1. Каждый заказ образует последовательную пару: неизменённый стикер WB размером
   40×58 мм, затем одна собственная служебная этикетка WMS с заметным `№ K`.
2. Номер не накладывается на PNG Wildberries, не обрезает и не уменьшает его.
   Если выбранный макет обычно отключает собственную этикетку, для этой печати
   служебная этикетка с номером всё равно выводится один раз.
3. Первая пара ленты соответствует первому номеру листа, последняя — последнему.
   Повторная полная печать той же поставки при неизменном составе воспроизводит
   тот же порядок и номера.
4. В предпросмотре проблемный заказ показывается существующим `ErrorNotice`:
   `Заказ WB №…: стикер не получен`. Готовые пары не перенумеровываются, пропуск
   остаётся видимым; система не сдвигает следующие номера, скрывая ошибку.

### Состояния

- **Загрузка листа.** Каркас, фильтры и заголовки колонок уже видны, счётчики под
  заголовком и тело таблицы показаны скелетами (`TableSkeletonBody` для строк).
  Кнопка печати недоступна с пояснением `Лист подбора ещё загружается`, закрытие
  остаётся доступным.
- **Пустая поставка.** В таблице `EmptyState`: `В поставке нет позиций для подбора`
  и подсказка `Закройте лист и проверьте состав поставки`. Печать недоступна с
  пояснением `В поставке нет заказов для печати`.
- **Поиск или фильтр ничего не нашёл.** `EmptyState`: `Нет позиций по фильтру` и
  `Сбросьте поиск или выберите «Все»`. Кнопка `Печать стикеров` остаётся доступной,
  потому что печатает полную поставку; рядом с фильтром отдельное предупреждение
  не добавляется.
- **Ошибка загрузки.** Над таблицей `ErrorNotice`: `Не удалось загрузить лист
  подбора. Попробуйте ещё раз`. Старые строки не показываются, печать недоступна
  с той же причиной; отдельная кнопка повтора не добавляется — повтор выполняется
  повторным открытием существующего листа.
- **Подготовка печати.** В кнопке печати — короткий индикатор действия; повторное
  нажатие и закрытие заблокированы до ответа.
- **Стикеры ещё не готовы или получены не все.** Ошибка показывается в теле
  модального окна на языке склада. Нумерация полного листа сохраняется; готовые
  элементы не уплотняются вокруг пропуска.

### Чего на экране нет

- нет выбора порядка сортировки и ручного перетаскивания строк;
- нет отдельной нумерации для фильтра, поиска или отмеченных строк;
- нет кнопки «Печатать видимое» и выбора отдельных заказов;
- нет расхлопывания товарной группы до строки на каждый заказ;
- нет дополнительной колонки с техническим `order.id`;
- нет номера поверх стикера Wildberries;
- нет изменений соседних зон `S-03`, карточки заказа или состава документов.

Упрощение: убраны потенциальные настройка сортировки, выборочная печать и отдельный
экран сопоставления — один серверный порядок одновременно управляет листом и лентой.

## Нехватка ui-kit

### `ModalFrame`

Канонического каркаса модального документа в `frontend/src/ui-kit/index.ts` нет.
Нужен переиспользуемый элемент:

```ts
type ModalFrameProps = {
  open: boolean
  title: string
  purpose?: string
  maxWidth?: 'sm' | 'md' | 'lg'
  busy?: boolean
  onClose: () => void
  actions: ReactNode
  children: ReactNode
  testId?: string
}
```

Состояния: обычное, `busy` (закрытие заблокировано), длинное прокручиваемое тело.

### `ChoiceFilter`

`StatusChip` обозначает состояние и не подходит для кликабельного фильтра. Нужен
сегмент выбора внутри `FilterBar`:

```ts
type ChoiceFilterProps<Value extends string> = {
  value: Value
  options: Array<{ value: Value; label: string }>
  onChange: (value: Value) => void
  ariaLabel: string
  testId?: string
}
```

Состояния: выбран, не выбран, disabled, клавиатурный фокус.

### `CheckCell`

Для существующих колонок `Собрал` и `Упаковал` нет ячейки ui-kit:

```ts
type CheckCellProps = {
  checked: boolean
  onChange: (checked: boolean) => void
  ariaLabel: string
  disabledReason?: string
  testId?: string
}
```

Состояния: отмечено, не отмечено, disabled с пояснением, клавиатурный фокус.

### Расширение `PrintAction`

В закрытом типе `Printable` нет уже существующей печати FBS-стикеров. Добавить
значение `стикеры заказов`; сам компонент и его состояния переиспользуются без
нового визуального элемента.
