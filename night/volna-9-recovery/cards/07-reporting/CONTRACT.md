## Контракт

### Назначение и граница экрана

Один общий экран только для чтения (read-only) отвечает на три складских вопроса: сколько товара находится на фулфилменте сейчас, сколько пришло и ушло за выбранный период и как расход изменился относительно предыдущего периода такой же длины. Для ФФ сохраняется маршрут `/app/ff/reports`, для селлера добавляется `/app/seller/reports`; содержание и порядок блоков одинаковы, различается только доступная область данных. В реестре `/Users/deniscivkunov/Projects/WMS/.worktrees/.night-worktrees/volna-9-recovery/lane-1-07-reporting/frontend/screens.registry.json` экран пока отсутствует: при разработке его следует зарегистрировать как `S-33` с двумя маршрутами и одним контрактом зон. Это новый реестровый идентификатор, потому что `S-01…S-32` уже заняты. Шапка называется «Остатки и движения», пояснение — «Текущий остаток и складские движения за выбранный период». [R-02; канон не покрывает общий экран в двух ролевых маршрутах → предложено R-38]

Экран не становится каталогом отчётов и не получает вкладки. В нём нет продаж, выручки, прибыли, комиссий, счетов, задолженности, стоимости хранения, оборачиваемости, неликвида, прогнозов, данных о работе упаковщиков, первичных документов и ссылок на них. Нет PDF, Excel, рассылок, сохранённых шаблонов и конструктора. Это сохраняет один понятный экран и не выдаёт складские факты за финансовые или маркетплейсные. [раздел 8 канона; канон не покрывает предметную границу отчёта → предложено R-44]

При «Другой период» рядом раскрываются поля «С» и «По». Интервал не может быть длиннее 366 дней: поле показывает ошибку «Период не может быть длиннее 366 дней», запрос не отправляется, CSV недоступен с причиной. Служебные склады вида `FBS WB *` в обычный список не попадают. [R-03; канон не покрывает бесполезный выбор из одного значения → предложено R-37]

Фильтра и колонки маркетплейса нет, пока реально подключён только Wildberries. Техническое значение канала может оставаться в ответе API, но не выводится на экран и в CSV: файл повторяет видимую таблицу один к одному. Фильтры применяются сразу после выбора; отдельной кнопки «Применить» нет. Пока идёт обновление, старый результат не превращается в нули: числа и таблица заменяются скелетами. [R-22, R-24; канон не покрывает атомарное обновление связанных блоков → предложено R-42]

### Показатели и график

`ReportMetricStrip` показывает ровно четыре значения:

1. «Остаток сейчас» — физический остаток на момент формирования; период на него не влияет.
2. «Приход за период» — только внешний входящий поток.
3. «Расход за период» — только внешний исходящий поток.
4. «Расход к прошлому периоду» — процент и абсолютная разница; при отсутствии базы сравнения показано «—» и пояснение «В прошлом периоде расхода не было».

Внутренние перемещения между складами ФФ не увеличивают приход и расход верхней полосы. Числа выровнены вправо, используют табличные цифры и единицу «шт.». Текущий остаток никогда не сравнивается с прошлым периодом: для этого нет исторического снимка. [R-08, R-24, R-29; канон не покрывает показатели и их сравнимость → предложено R-39]

`MovementFlowChart` — один дневной линейный график без интерактивного конструктора: сплошные линии «Приход» и «Расход» за выбранный период; при включённом сравнении предыдущий расход показан одной пунктирной линией «Расход, прошлый период». У графика есть видимая легенда и доступное текстовое описание серий. Значения внутреннего перемещения в эти линии не входят. [R-13, R-16; канон не покрывает графики → предложено R-43]

Под графиком одна строка «Данные на 22 августа 2026, 02:41 МСК». Если импорт внешнего канала устарел, рядом появляется один `WarningNotice`: «Данные Wildberries могут быть неполными. Последнее обновление: …». Локальные остатки и движения при этом остаются доступны. Если при восстановлении измерений старой истории (backfill) осталась неоднозначность, администратор ФФ видит одно предупреждение на весь отчёт, а не чипы во всех строках; селлер этого технического предупреждения не видит. [R-14, R-16, R-24, R-30, R-35; канон не покрывает свежесть источника → предложено R-45]

### Группировка и таблица

Над таблицей поле «Группировка» имеет только два значения: «По товарам» и «По операциям». Это не вкладки и не два соседних экрана. Рядом находится единственное действие `PrimaryAction` «Скачать CSV». Файл строится сервером, повторяет текущие фильтры, группировку, порядок и видимые агрегированные колонки. При пустой таблице действие недоступно с объяснением «За выбранный период нечего выгружать». [R-18, R-20, R-24, R-31, R-32; канон не покрывает экспорт текущего среза → предложено R-46]

Таблица «По товарам» использует `DataTable` и следующие фиксированные колонки:

- «Товар» — `ProductCell`, фото и SKU, 150 px;
- «Название» — `TextCell`, 240 px;
- «Артикул продавца» — `TextCell`, 170 px;
- «ШК» — `TextCell`, 150 px;
- «Селлер» — `TextCell`, 150 px, только у ФФ;

Нулевое количество показывается числом `0`, отсутствие применимого значения — тире. «Нетто» — изменение количества, не деньги. Строки не получают заливку по знаку или размеру показателя. [R-05, R-07, R-08, R-09, R-10, R-11, R-29]

Таблица «По операциям» использует колонки «Операция» (`TextCell`, 260 px), «Приход» (`QtyCell`, 130 px), «Расход» (`QtyCell`, 130 px), «Нетто» (`QtyCell`, 130 px). Число документов и ссылки на документы отсутствуют. При выбранном складе внутренний поток показывается отдельными строками «Перемещение: пришло» и «Перемещение: ушло» и не примешивается к внешним итогам. [R-08, R-09, R-10, R-27; канон не покрывает отделение внутреннего потока → предложено R-47]

Пагинация серверная, по 50 строк. Строка «1–50 из 184» и переходы находятся под таблицей; смена страницы не меняет верхние агрегаты и CSV. Произвольного выбора размера страницы нет. [канон не покрывает пагинацию → предложено R-48]

### Роли и доступ

Администратор ФФ видит весь фулфилмент (tenant) и фильтр селлера. Сотрудник ФФ с правом `inventory` видит тот же экран в своей разрешённой области. Владелец селлера и сотрудник с `can_products` видят только своего селлера, без фильтра селлера и без служебной диагностики; `can_documents` для агрегированного отчёта не требуется. При отсутствии права пункт меню и маршрут недоступны, а не показывают пустой экран. [канон не покрывает права отчётности → предложено R-38]

### Состояния

- **Обычное.** Все блоки относятся к одному срезу; показатели, график, таблица и CSV синхронны. [R-24; предложено R-42]
- **Пустое.** `ReportMetricStrip` продолжает показывать «Остаток сейчас», потоковые показатели равны `0`; график сообщает «За выбранный период движений нет»; `DataTable` использует `EmptyState` с текстом «За выбранный период движений нет» и подсказкой «Измените период или снимите фильтры». CSV недоступен с причиной. [R-20, R-21, R-24]
- **Загрузка.** `ReportMetricStrip`, `MovementFlowChart` и `DataTable` показывают скелеты своей формы; предыдущие цифры не показываются как новые. [R-22, R-24; предложено R-42]
- **Ошибка показателей или графика.** На месте сбойного блока показан `ErrorNotice` «Не удалось загрузить сводку. Повторите попытку» и `PrimaryAction` «Повторить»; успешно загруженная таблица остаётся видимой. [R-23, R-24; канон не покрывает частичный отказ → предложено R-49]
- **Ошибка таблицы.** Показатели и график остаются, в зоне таблицы — `ErrorNotice` «Не удалось загрузить строки отчёта. Повторите попытку». Нули не подставляются. [R-23, R-24; предложено R-49]
- **Ошибка CSV.** Загрузка файла не очищает экран; над таблицей появляется `ErrorNotice` «Не удалось скачать CSV. Повторите попытку». [R-23, R-24]
- **Устаревшие внешние данные.** Один `WarningNotice` сообщает источник и время последнего обновления, не блокируя локальный отчёт. [R-16, R-24, R-30; предложено R-45]
- **Проблемная строка внутреннего перемещения.** При неполной transfer-паре над таблицей появляется `ErrorNotice` «В истории есть неполное перемещение. Значения показаны как записаны; отчёт ничего не достраивал». Строка «Перемещение» содержит существующий `StatusChip` «Ошибка», фактически записанную сторону движения и тире для отсутствующей; заливки строки нет. [R-11, R-14, R-23, R-24; предложено R-47]

Раскрытий и диалогов на экране нет: просмотр первичных документов и исправление данных не входят в эту карточку. [раздел 8 канона; предложено R-44]

### Что убрано как переусложнение

Убраны отдельные страницы по товару, складу, селлеру, маркетплейсу и операции: фильтры и две группировки отвечают на задачи на одном экране. Убраны отдельные карточки «с начала месяца» и «с начала года»: это уже пресеты периода. Скрыты выбор единственного склада и единственного маркетплейса. Убрана кнопка «Применить», потому что фильтры обновляют один read-only срез автоматически. Без этих элементов сценарий остаётся полным, а пользователю требуется меньше экранов и решений. [R-03, раздел 8 канона; предложено R-37, R-40, R-44]

- **R-45.** Свежесть данных показывается одной строкой; предупреждение на уровне источника не размножается по строкам таблицы и не скрывает достоверные локальные данные.

- **R-49.** На составном read-only экране ошибка одного независимого блока занимает его место, а успешно загруженные блоки остаются доступными; ошибка никогда не превращается в ноль.

### `ReportMetricStrip`

API: `items: { key: string; label: string; value: number | null; unit?: string; delta?: { value: number; direction: 'up' | 'down' | 'flat'; a11yLabel: string } }[]`, `loading?: boolean`, `testId?: string`. Состояния: обычное, нулевое значение, неприменимое значение `—`, загрузка скелетами. Компонент — одна outlined-полоса с четырьмя равными зонами, без вложенных карточек; числа выровнены вправо и используют табличные цифры.

### `MovementFlowChart`

API: `series: { date: string; inbound: number; outbound: number; previousOutbound?: number }[]`, `showPrevious: boolean`, `loading?: boolean`, `empty?: { title: string; hint: string }`, `ariaDescription: string`, `testId?: string`. Состояния: обычное, без линии сравнения, пустое, загрузка скелетом. Цвета берутся из палитры R-13; серии различаются также подписью и типом линии, а не только цветом.

### `WarningNotice`

API: `children: ReactNode`, `testId?: string`. Состояние одно: `Alert severity="warning"` в теле экрана, визуально и по отступам парное существующему `ErrorNotice`. Нужен для свежести импорта и единого предупреждения о legacy-истории; `StatusChip` для предупреждения уровня всего источника не подходит.

Остального ui-kit хватает: `ScreenHeader`, `FilterBar`, `PrimaryAction`, `DataTable`, `ProductCell`, `TextCell`, `QtyCell`, `EmptyState`, `TableSkeletonBody`, `ErrorNotice`, `StatusChip`.
