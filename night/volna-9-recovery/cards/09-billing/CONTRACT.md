## Контракт

### 1. Границы и навигация

1. В меню ФФ появляется один пункт **«Расчёты»**, ведущий на новый экран
   `/app/ff/billing`. Внутри две вкладки: **«Начисления»** и **«Счета»**. Отдельных пунктов
   «Начисления», «Счета», «Работа сотрудников» и «Реквизиты» нет (R-02, раздел 8 канона;
   вкладки — ДЫРА, предложено R-38).
2. Экран доступен только администратору ФФ. Селлер в этой волне не видит счета, а сотрудник
   склада не видит тарифы, реквизиты и суммы. Серверная изоляция tenant обязательна, но
   технические идентификаторы tenant в UI не выводятся (R-30; граница доступа — канон не
   покрывает, продуктово закреплена в `RESHENIYA.md`, решение 15).
3. Существующий экран `S-18 /app/ff/sellers` получает реквизиты конкретного селлера;
   существующий `S-19 /app/ff/settings` — реквизиты самого ФФ и тарифы. Соседние зоны этих
   экранов не переименовываются и не переделываются (раздел 8 канона).

### 2. S-18 «Селлеры»: реквизиты плательщика

1. Клик по строке селлера открывает диалог **«Селлер: {название}»**. В нём остаются уже
   существующие данные аккаунта и появляется раскрываемый блок **«Реквизиты для счетов»**.
   Новый маршрут и отдельный экран не создаются (R-01; диалог деталей — ДЫРА, предложено
   R-39).
2. Поля блока: **«Юридическое наименование»**, **«ИНН»**, **«КПП»**. Первые два обязательны;
   КПП необязателен и показывается без утверждения «не указан». Адрес, банк селлера,
   договор, несколько плательщиков и поиск организации по ИНН отсутствуют (R-06, R-10,
   R-30; раздел 8 канона).
3. Единственное действие блока — `PrimaryAction` **«Сохранить реквизиты»**. Во время запроса
   кнопка показывает короткую загрузку; после сохранения в блоке виден спокойный текст
   **«Реквизиты сохранены»**. Ошибка находится над полями как `ErrorNotice`, например
   **«Проверьте ИНН: контрольное число не совпадает»**, без серверного кода (R-22, R-23,
   R-24, R-32).
4. В таблицу селлеров не добавляется колонка «Реквизиты»: она не помогает основному
   сценарию списка и создаёт визуальный шум. Проблема отсутствующих реквизитов показывается
   там, где мешает сформировать счёт — на вкладке «Счета» (раздел 8 канона).

### 3. S-19 «Настройки»: реквизиты ФФ и тарифы

1. В `S-19` появляется верхнее переключение между сохранённым без изменений содержимым
   **«Склад и сотрудники»** и новой вкладкой **«Тарифы ФФ»**. Ставка упаковщика сотруднику
   остаётся в прежнем блоке и не смешивается с тарифами селлеру (раздел 8 канона; вкладки —
   ДЫРА, предложено R-38).
2. Вверху «Тарифов ФФ» расположен один раскрываемый блок **«Реквизиты ФФ»**. Поля:
   **«Юридическое наименование»**, **«ИНН»**, **«КПП»**, **«Название банка»**, **«БИК»**,
   **«Расчётный счёт»**, **«Корреспондентский счёт»**. КПП необязателен; остальные поля
   обязательны для выпуска счёта. Адрес, НДС, налоговый режим и логотип не собираются
   (R-06, R-10, R-30; раздел 8 канона).
3. Под реквизитами находится таблица действующих тарифов. Колонки фиксированы:

   | Колонка | Содержимое | Ширина и выравнивание |
   |---|---|---|
   | Услуга | «Приёмка», «Отгрузка», «Хранение» | 180 px, влево |
   | Для кого | «Все селлеры» либо существующее имя селлера | 240 px, влево |
   | Расчёт | «За документ», «За штуку», «За литр-день» | 170 px, влево |
   | Ставка | RUB с двумя знаками, например «45,00 ₽» | 150 px, вправо |
   | Действует с | дата по МСК | 150 px, влево |
   | Действие | `IconAction` «Открыть историю ставок» | 64 px, по центру |

   Таблица — `DataTable size="small"`, с липкой шапкой, без заливки строк. Текущая ставка
   показана один раз; завершённые версии находятся в редком раскрытии «История ставок», а
   не занимают основной список (R-04, R-05, R-07, R-08, R-09, R-11, R-17).
4. Над таблицей один `PrimaryAction` **«Новая ставка»**. Диалог содержит поля **«Услуга»**,
   **«Для кого»** (по умолчанию «Все селлеры»), **«Расчёт»**, **«Ставка, ₽»** и
   **«Действует с»**. Выбор расчёта закрыт тремя вариантами: «За документ», «За штуку» и
   «За литр-день»; для хранения доступен только литр-день. Одновременно фикс и поштучная
   цена невозможны. Нулевая ставка разрешена и подписана как явная бесплатная работа
   (R-10, R-20, R-31, R-32; ограничение формы следует `RESHENIYA.md`, решения 6–8).
5. `PrimaryAction` в диалоге — **«Сохранить ставку»**, рядом `SecondaryAction` —
   **«Отмена»**. Сохранение создаёт новую версию с выбранной даты и не редактирует прошлую.
   Если дата пересекает будущую версию, форма объясняет конфликт на языке пользователя и
   не сохраняется (R-20, R-23, R-31, R-32).
6. Пустая таблица: **«Тарифы ещё не заданы»** и подсказка **«Добавьте общие ставки, чтобы
   завершённые работы попадали в счета»**, затем `PrimaryAction` «Новая ставка» (R-21).
   Загрузка — скелет строк; ошибка загрузки — `ErrorNotice` над таблицей (R-22, R-23).

### 4. Новый экран «Расчёты»: общий каркас

1. `ScreenHeader`: заголовок **«Расчёты»**, назначение **«Начисления за работу склада и
   автоматически выставленные счета селлерам.»** Ни даты, ни действия в шапке нет (R-01,
   R-02).
2. Вкладки находятся сразу под шапкой. Переключение не меняет маршрут верхнего уровня и
   сохраняет выбранный месяц и селлера, чтобы сверка не начиналась заново (ДЫРА,
   предложено R-38).
3. Валюта везде только RUB. Деньги показываются с двумя знаками после запятой,
   неразрывным пробелом и «₽», выравниваются вправо; сторно имеет минус, но не получает
   красную окраску само по себе (R-08, R-11, R-13; формат денег — ДЫРА, предложено R-37).
4. Технические значения `unpriced`, `storage_period_not_closed`, `issued`, `cancelled`,
   `document`, `item`, `liter_day` не показываются. Пользователь видит соответственно
   «Нет тарифа», «Хранение не закрыто», «Выставлен», «Отменён», «За документ», «За штуку»
   и «За литр-день» (R-10, R-14, R-27, R-30).

### 5. Вкладка «Начисления»

1. `FilterBar` содержит поиск по номеру исходного документа, обязательный `PeriodPicker`
   **«Месяц»** (по умолчанию текущий месяц), выбор **«Селлер»**, выбор **«Услуга»** и режим
   **«По операциям / По исполнителям»**. Фильтра склада нет: тариф хранения уже получает
   готовый зафиксированный факт карточки 08, а оператор этой карточки сверяет деньги, не
   складскую аналитику (R-03; раздел 8 канона).
2. В режиме «По операциям» колонки:

   | Колонка | Содержимое | Ширина и выравнивание |
   |---|---|---|
   | Дата | дата оплачиваемого финального факта по МСК | 120 px, влево |
   | Селлер | существующее имя селлера | 190 px, влево |
   | Услуга | «Приёмка», «Отгрузка», «Хранение» | 150 px, влево |
   | Документ | номер исходного документа; клик открывает существующий документ | 190 px, влево |
   | Количество | число фактических единиц | 120 px, вправо |
   | Расчёт | «За документ», «За штуку», «За литр-день» | 150 px, влево |
   | Ставка | снимок ставки в RUB; «—» если тарифа нет | 130 px, вправо |
   | Сумма | сумма или «—» при отсутствии тарифа | 140 px, вправо |
   | Исполнитель | имя/email либо «Исполнитель не зафиксирован» | 220 px, влево |
   | Проблема | только требующая действия причина; иначе «—» | 180 px, влево |

   Числа и деньги используют `QtyCell`/`MoneyCell`, текст — `TextCell`, проблема —
   `StatusChip tone="stop"`. У нормальной строки нет чипа «Начислено»: он дублировал бы
   наличие суммы. Строки не окрашиваются (R-07–R-11, R-14–R-16, R-35).
3. Проблемная строка «Нет тарифа» сохраняет фактическое количество, дату и документ, но
   показывает «—» в ставке и сумме. Рядом с таблицей появляется единственное главное
   действие **«Открыть тарифы»**. Физическая работа склада не блокируется (R-18, R-23,
   R-31; продуктовое решение 7).
4. В режиме «По исполнителям» денежные колонки отсутствуют, чтобы сумму счёта селлеру не
   приняли за зарплату сотрудника. Колонки: **«Исполнитель»**, **«Услуга»**,
   **«Расчёт»**, **«Количество»**, **«Документов»**. Строка «Исполнитель не зафиксирован»
   остаётся отдельной и не угадывается по истории (R-08, R-10, R-29, R-30; раздел 8
   канона).
5. Пустое состояние по операциям: **«За выбранный месяц начислений нет»** и
   **«Начисления появятся после завершённой приёмки, отгрузки или фиксации хранения»**.
   При активных фильтрах текст меняется на **«По выбранным условиям начислений нет —
   измените фильтры»**. Пустое состояние по исполнителям: **«За месяц нет завершённых
   операций с исполнителем»** (R-21, R-24).
6. Загрузка таблицы — `TableSkeletonBody`; ошибка запроса — `ErrorNotice` **«Не удалось
   загрузить начисления. Повторите попытку»**. Предыдущие данные при ошибке не выдаются за
   актуальные (R-22, R-23, R-24).

### 6. Вкладка «Счета»

1. `FilterBar` содержит поиск по номеру счёта, `PeriodPicker` **«Месяц»** (по умолчанию
   последний закрытый месяц), выбор **«Селлер»** и **«Статус»**. Отдельных фильтров оплаты,
   задолженности, НДС и срока нет, потому что система их не ведёт (R-03; раздел 8 канона).
2. Над таблицей показывается компактный список только блокирующих выпуск проблем. Каждая
   проблема — строка с селлером, месяцем и одним `StatusChip tone="stop"`:
   **«Нет тарифа»**, **«Нет реквизитов»** или **«Хранение не закрыто»**. У строки одно
   исправляющее действие: **«Открыть тарифы»**, **«Открыть селлера»** или
   **«Открыть хранение»**. Технический код причины не виден (R-14, R-16, R-18, R-30,
   R-31, R-32).
3. После устранения причин блок меняется на текст **«Причины устранены — повторите
   формирование»** и `PrimaryAction` **«Повторить формирование»**. Пока причина остаётся,
   эта кнопка недоступна и через `disabledReason` объясняет, что сначала исправить. Второго
   ручного алгоритма и редактируемого черновика нет (R-20, R-24, R-31, R-32).
4. Таблица счетов:

   | Колонка | Содержимое | Ширина и выравнивание |
   |---|---|---|
   | Номер | неизменяемый номер счёта | 170 px, влево |
   | Период | календарный месяц | 150 px, влево |
   | Селлер | имя селлера | 220 px, влево |
   | Выставлен | дата формирования по МСК | 150 px, влево |
   | Сумма | итог в RUB | 160 px, вправо |
   | Статус | `StatusChip`: «Выставлен» / «Отменён» | 140 px, влево |
   | Действие | `IconAction` «Открыть счёт» | 64 px, по центру |

   «Выставлен» — `tone="ok"`, «Отменён» — `tone="neutral"`: отмена окончательна, но не
   является текущей ошибкой, мешающей работать. Заливки строк нет (R-07–R-11, R-14,
   R-16, R-17).
5. Пустой закрытый месяц: **«За этот месяц счета не выставлены»**. Если начислений нет,
   подсказка: **«Нет начислений для формирования»**. Если есть блокирующие причины,
   подсказка не дублируется: причины уже перечислены над таблицей (R-21, R-24, R-35).
6. Загрузка — скелет строк; ошибка запроса — `ErrorNotice` **«Не удалось загрузить счета.
   Повторите попытку»** (R-22, R-23).

### 7. Просмотр счёта и детализация

1. `IconAction` «Открыть счёт» открывает широкий диалог, не новый маршрут. Заголовок:
   **«Счёт {номер}»**, рядом один статус-чип. Далее видны период, дата выставления,
   неизменяемые снимки реквизитов ФФ и плательщика, итог и таблица строк счёта. НДС,
   «Без НДС», срок оплаты, статус оплаты, акт, УПД и счёт-фактура отсутствуют (R-06,
   R-14, R-30; диалог — ДЫРА, предложено R-39).
2. Строки счёта имеют колонки **«Услуга»**, **«Расчёт»**, **«Количество»**, **«Ставка»**,
   **«Сумма»**, **«Детализация»**. `IconAction` «Показать документы» раскрывает под строкой
   исходные документы с датой, номером, количеством и суммой. Для хранения источником
   называется **«Расчёт хранения за {месяц}»**, без технического `storage_measurement`
   (R-08–R-10, R-17, R-30).
3. В панели диалога `PrintAction placement="panel" what="счёт"` с подписью
   **«Печать счёта»** открывает печатное HTML-представление браузера. PDF-файл, экспорт,
   отправка селлеру и выбор шаблона отсутствуют (R-18, R-19, R-31, R-33).
4. Для выставленного счёта рядом с печатью доступен `DangerAction` **«Отменить счёт»**.
   Подтверждение прямо сообщает: **«Счёт останется в истории со статусом “Отменён”. Это
   действие нельзя отменить»**. Причина отмены не запрашивается: такого учёта продуктовые
   решения не вводили. У отменённого счёта действия отмены нет, печать остаётся доступной
   (R-18, R-31, R-32; необратимое подтверждение — канон не покрывает, предложено R-39).
5. Печатный вид содержит только снимки реквизитов, номер, период, дату, строки и итог.
   Управляющие кнопки, фильтры, навигация и технические идентификаторы в печать не входят
   (R-24, R-30, R-33).

### 8. Что убрано ради простоты

- Убраны четыре потенциальных отдельных экрана: реквизиты, начисления, счета и работа
  сотрудников. Они заменены существующими `S-18`, `S-19` и одним разделом «Расчёты».
- Убраны графики, KPI-карточки, баланс, оплаты, задолженность, НДС, договоры, ручной
  калькулятор, редактируемый черновик, PDF-движок и экспорт. Без них можно выставить,
  проверить и распечатать внутренний коммерческий счёт.
- Убраны успешные чипы из каждой строки начислений: наличие ставки и суммы уже сообщает об
  успехе, второй сигнал только перегружал бы таблицу.
- Убрана колонка реквизитов из списка селлеров: проблема появляется только в контексте
  формирования счёта, а исправляется в карточке селлера.
- Убрана одновременная демонстрация истории тарифов: она доступна по раскрытию, но не
  конкурирует с действующими ставками.

Сложность диалога счёта оправдана: без снимков обеих сторон и раскрытия до исходных
документов администратор не сможет доказать неизменяемую сумму и найти ошибочный факт.

## Нехватка ui-kit

### `MoneyCell`

Нужна общая денежная ячейка, потому что `QtyCell` теряет копейки и валюту, а `TextCell` не
гарантирует правое выравнивание и табличные цифры.

```ts
type MoneyCellProps = {
  minor: number | null | undefined
  currency?: 'RUB' // default RUB; других валют в MVP нет
  muted?: boolean
}
```

Состояния: положительная сумма, ноль, отрицательное сторно, `null/undefined` → «—».
Формат: `ru-RU`, ровно два знака, неразрывный пробел перед `₽`, знак минус текстом, без
сигнального цвета.

### `PeriodPicker`

Нужен единый выбор календарного месяца: в коде уже есть разрозненные `TextField
type="month"`, но в экспортируемом ui-kit компонента нет.

```ts
type PeriodPickerProps = {
  label?: string // default «Месяц»
  value: string // YYYY-MM
  onChange: (value: string) => void
  min?: string
  max?: string
  disabled?: boolean
  error?: string
  testId?: string
}
```

Состояния: обычное, focus, disabled с причиной, ошибка формата/границы, загрузка родительского
фильтра без очистки выбранного значения.

### Расширение `PrintAction`

Существующий закрытый тип `Printable` не содержит счёт. Требуется добавить ровно значение
`'счёт'`; новый вид кнопки не нужен. Для `placement="panel"` подпись автоматически становится
«Печать счёта». Состояния уже покрыты `PrintAction`: обычное и disabled с причиной.

Других новых элементов ui-kit не требуется. Вкладки, диалоги, раскрытие и поля используют
уже применяемые в продукте композиции MUI, но все действия, чипы и ячейки в них берутся
только из
`/Users/deniscivkunov/Projects/WMS/.worktrees/.night-worktrees/volna-9-recovery/lane-3-09-billing/frontend/src/ui-kit/index.ts`
после добавления перечисленных атомов.
