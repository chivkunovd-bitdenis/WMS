# Возврат нарезки · раунд 1

Первый проход `splitter` остановлен до разработки: allowlist содержал лишний продуктовый файл и не называл уборку уже внесённого лишнего UX.

## Исправить

1. Удалить `backend/app/services/fbs_shipment_service.py` из атома: существующий shipment-путь уже получает `without_distribution` через `fbs_packing_box_service.get_delivery_box_readiness`; контракт не требует его изменения.
2. Backend/API-атом должен включить только те файлы, которые действительно нужны для сохранения режима, проверки назначений, API-переключения и свежего workspace. Не добавлять новый текст ошибки.
3. Frontend-атом обязан не только связать галку с серверным состоянием, но и убрать из текущего кандидата незапрошенный тултип и соответствующие ожидания теста. Шапку, QR, печать, меню и соседние действия не менять относительно исходного экрана.
4. В тестах не ожидать новый тултип, новую строку ошибки или новый текст шапки. Проверять состояние галки, сохранность коробов/назначений и прежний gate передачи.
5. Не создавать отдельный атом ui-kit и не разрешать ни одного файла другого FBS-экрана.

## Критерий

Каждый путь в `FEATURES.md` должен быть необходим для одного пункта `OWNER-SCOPE.md`. Файл, который только «может пригодиться» или уже умеет потреблять результат без изменения, в allowlist не входит.
