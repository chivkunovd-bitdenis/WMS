# Механика охраны WMS-652

Состояние локального набора `active`: по прямому заданию B владельца от
03.10.2026 добавлены G-STOCK-1…8, восемь backend-файлов тестов остатков.
Манифест включает их общий helper и README. Матрица сканирования/печати
фронта этим разрешением не активирована. Доказательства мутаций находятся в
`docs/evidence/wms652/stock-guards-proof.md`.

`python scripts/ci/check_regression_guards.py --base <trusted-sha>` сверяет
содержимое с манифестом доверенного коммита и отвергает изменение самого
манифеста. Одновременная замена теста и его хэша не проходит. Обнаруживаются
добавления, удаления и изменения всех файлов в двух защищённых каталогах.
Тесты исполняются отдельными шагами CI после проверки целостности.

При первом введении инфраструктуры, когда в BASE ещё нет манифеста и файлов,
допустим только явный `--allow-bootstrap` с `state=bootstrap` и без бизнес-тестов.
CI явно сообщает этот режим. В последующих PR проверяющий скрипт берётся из
BASE, поэтому правка его копии в кандидате не ослабляет проверку.

BASE для PR — SHA базовой ветки события; для push — `github.event.before`.
Ручной запуск требует точный предыдущий `base_sha`. Первый push с нулевым
`before` отказывает с инструкцией ручного запуска: предположение `HEAD^`
скрыло бы более ранние коммиты первого push. Пустой диапазон запрещён.

До отдельного утверждения процедуры пополнения набора **любая** правка
манифеста относительно существующей базы красная. Добавление бизнес-тестов и
обновление доверенной базы требует следующего согласованного этапа; флажка
самоодобрения по тексту PR или переменной окружения нет.

Поэтому добавление утверждённого набора B ожидаемо красное относительно
прежней bootstrap-базы `6061f431ec5963b0eb9d5ea56fa0811959135a86`.
Проверка с `--base <локальный-коммит-набора-B>` подтверждает только целостность
сохранённого набора, не внешнее одобрение смены доверенной базы. Флага пополнения
в текущем скрипте нет; новые хэши рассчитаны SHA256, барьер не ослаблен.

Это диагностический барьер, а не защита от администратора: workflow кандидата
пока может быть изменён. CODEOWNERS, ruleset, отдельная учётная запись агентов
и deploy-gate подготовлены отдельно и не включены. Зелёная «охрана» в bootstrap
не доказывает защиту бизнес-процессов и не разрешает деплой.
