# WMS-533: движения клиента в JSON и Excel

Вызовы синхронные, доступны на базовом URL действующего WMS API. Пути приложения: `GET /reports/client-movements` и `GET /reports/client-movements/export.xlsx`. Домен и возможный префикс обратного прокси зависят от развёртывания. Вход выполняется существующим `POST /auth/login`; токен передают заголовком `Authorization: Bearer <token>`. Новые интеграционные ключи не нужны. Право доступа совпадает с чтением складского отчёта. Кабинет селлера ограничен активным магазином из токена.

Отдельная интерактивная Swagger-страница интеграции находится по `/docs/client` на прямом API или `/api/docs/client` за публичным прокси. Она показывает только вход и два метода этого отчёта; схема доступна по `/openapi-client.json` или `/api/openapi-client.json`. Общая документация WMS по `/docs` остаётся доступной. Для входа селлера укажите в теле `POST /auth/login` поле `portal: "seller"`, для сотрудника фулфилмента — `portal: "fulfillment"`; полученный `access_token` вставьте в кнопку **Authorize** как Bearer-токен.

Оба метода требуют `date_from` и `date_to` в ISO 8601 с часовым смещением, например `2026-09-01T00:00:00Z` и `2026-10-01T00:00:00Z`. Начало периода включено, конец исключён. Значения сравниваются в UTC. Даты без смещения и период с концом не позже начала дают HTTP 422.

Общие необязательные фильтры: `sku` — точный `Product.sku_code`, `shk` — точный основной `Product.wb_barcode` или дополнительный ШК товара `ProductBarcode` в границах того же клиента и селлера, `warehouse_id` — UUID склада самого движения, `marketplace` — `wb` либо `ozon`. `sku` и `shk` нельзя указывать вместе: оба метода вернут HTTP 422. Если не указан ни один, отчёт содержит все доступные товары за период. Остальные фильтры совмещаются. Селлер определяется по Bearer-токену кабинета; параметра `seller_id` нет. Параметра `operation` тоже нет: это поле ответа означает тип движения (например, `fbs_shipment`, `inbound_intake` или `return`).

Только JSON принимает `limit` от 1 до 1000 (по умолчанию 200) и `cursor`. Ответ содержит `rows`, `next_cursor`, `limit`. Пока `next_cursor` не равен `null`, передавайте его в следующем запросе с теми же фильтрами. Порядок: время движения, UUID движения, индекс штуки. Файл Excel обходит всю выборку без ограничения лимитом JSON.

```http
GET /reports/client-movements?date_from=2026-09-01T00%3A00%3A00Z&date_to=2026-10-01T00%3A00%3A00Z&sku=0007&limit=200
Authorization: Bearer <token>
```

```json
{
  "rows": [{
    "id": "4cd4e360-4130-4141-b5e3-a3f50dbc1464:0",
    "movement_id": "4cd4e360-4130-4141-b5e3-a3f50dbc1464",
    "occurred_at": "2026-09-12T12:00:00+00:00",
    "operation": "fbs_shipment",
    "warehouse_id": "00000000-0000-0000-0000-000000000001",
    "product_id": "00000000-0000-0000-0000-000000000002",
    "sku": "0007", "product_name": "Товар", "shk": "0000123456789", "size": "42",
    "marketplace": "ozon",
    "document": {"id": "00000000-0000-0000-0000-000000000003", "type": "fbs_order", "number": "OZ-702"},
    "quantity_delta": -1, "kiz": "0101234567890121\u001dSERIAL"
  }],
  "next_cursor": null, "limit": 200
}
```

`id` — стабильный ID строки: UUID движения либо `UUID:индекс` для FBS-штуки. `movement_id` — исходная запись журнала. `size` — размер именно того товара, чей `shk` указан в строке. Минус в `quantity_delta` означает списание, плюс — оприходование. Связанный с заказом FBS раскрывается до штуки (`-1` или `+1`); положительное сторно отгрузки не наследует КИЗ списанной штуки.

Отчёт содержит только движения, которые представляют приход или расход товара селлера: приёмку, подтверждённый возврат, загрузку ТЗ, отгрузки FBS и FBO, обычную отгрузку, инвентаризацию, акт расхождений и историческую корректировку остатка. Внутренние перекладывания, переносы между складами и контейнерами, подбор/отмена подбора FBS, передача товара между продавцами в клиентский отчёт не входят. Неизвестные технические типы движений также не выводятся автоматически.

FBO (`operation: "marketplace_unload"`) попадает в отчёт только для связанной заявки со статусом `shipped` или `done` и заполненным `shipped_at`. `occurred_at` для такой строки — время фактического завершения отгрузки `shipped_at`; оно определяет выбор периода, порядок и курсор. Подбор собираемой, отменённой либо несвязанной заявки не показывается. Отдельной записи списания при завершении FBO система не создаёт, поэтому отчёт использует подтверждённое движение подбора только после отгрузки.

Площадка берётся из связанного FBS-заказа или FBO-документа `marketplace_unload_requests`. Операции без площадки получают `marketplace: null`. В Excel три листа: «WB», «Ozon», «Общие». КИЗ FBO всегда `null`. Для FBS код выбирается только по связи заказа с SGTIN-маркировкой нужного товара; отвергнутые коды не берутся. Если историческая связь движения или позиция Ozon с несколькими одинаковыми товарами неоднозначна, КИЗ остаётся `null`, строка сохраняется. Рецепт списания Ozon не содержит `order_product_id`, поэтому распределение КИЗ между несколькими позициями одного товара не угадывается.

Возврат определяется только для движения `inbound_intake`, явно связанного со строкой заявки `InboundIntakeRequest` с `operation_type=return`. Такая строка получает `operation: "return"` и `document.type: "return"`; площадка `wb` или `ozon` берётся из той же заявки, поэтому фильтр площадки и лист Excel работают одинаково. В исторических возвратных заявках площадка может быть не заполнена: тогда поле остаётся `null` и строка попадает в «Общие». Обычная или несвязанная приёмка остаётся `inbound_intake`. Положительное сторно FBS сохраняет документ заказа и знак прихода, но не наследует КИЗ отгруженной единицы; КИЗ выдаётся только для связанного отрицательного движения отгрузки. Отгрузки FBS без сохранённой связи ledger и FBO без связанного документа не получают выдуманных КИЗ, документа или площадки.

Excel содержит листы «WB», «Ozon», «Общие» и колонки «Дата и время (UTC)», «Движение», «Причина», «Документ / заказ», «Код товара», «Товар», «Размер», «Штрихкод», «Приход, шт.», «Расход, шт.», «Склад», «КИЗ». В «Движении» только «Оприходование» или «Списание»; количество находится в соответствующей колонке. В файле нет UUID и технических кодов операций. Все строки белые с чёрным текстом, шапка серая.

JSON передаёт полный сохранённый КИЗ: после разбора JSON `\u001d` снова становится управляющим символом GS. Excel хранит коды и остальные строковые поля текстом, сохраняя ведущие нули и исключая интерпретацию начальных `=`/`+`/`-`/`@` как формулы. Для Excel управляющие символы и обратные слеши представлены обратимым экранированием JSON без внешних кавычек.

Неверные параметры дают HTTP 422, отсутствие токена — 401, отсутствие права — 403. Выдача доступа конкретному клиенту выполняется существующим процессом учётных записей и в этот выпуск не входит.
