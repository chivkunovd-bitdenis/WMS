## Блокировки

### 1. Импорт маркировок требует выбранного продавца

**Что блокируется:**
Кнопка "Загрузить КМ" (загрузить коды маркировки) на экране управления кодами маркировки «Честный знак» в портале фулфилмент-центра отключена, пока не выбран продавец.

**Каким условием:**
```
frontend/src/screens/shared/HonestSignScreen.tsx:208
const importDisabled = sellerIdRequiredForImport && !effectiveSellerId
```

Кнопка отключена, когда `sellerIdRequiredForImport=true` (установлено на FF экране в `FfHonestSignPage.tsx:28`) и нет выбранного `effectiveSellerId`.

**Где живёт проверка:**
- Экран: есть, на фронтенде отключает кнопку
- Сервер: есть, но на уровне авторизации (строки 675–687 в `backend/app/api/marking_codes.py:import_marking_codes`):
  - Для `FULFILLMENT_SELLER`: требует, чтобы `effective_seller_id != None`, иначе ошибка `"seller_not_linked"`
  - Для `FULFILLMENT_ADMIN`: требует явного `seller_id` в форме, иначе ошибка `"seller_id_required"`

**Совпадение слоёв:** ✓ совпадают — оба слоя отвергают запрос без продавца.

**Что видит оператор:**
Tooltip с текстом "Выберите селлера" (строки 523–528 в `HonestSignScreen.tsx`). Tooltip отображается только когда кнопка отключена.

**Как разблокировать:**
Выбрать продавца из выпадающего списка в компоненте `MarkingSellerPicker` (строки 554–560).

**Зачем бизнесово:**
В портале фулфилмент-центра импорт маркировок — это действие, связанное с конкретным продавцом (в системе может быть несколько продавцов, каждый с собственными кодами маркировки). На сервере проверка повторяется на уровне авторизации: система гарантирует, что `FULFILLMENT_ADMIN` всегда передаст `seller_id`, а `FULFILLMENT_SELLER` всегда будет привязан к одному продавцу. Блокировка логична и согласована между слоями.

## Находки

### 1. Обоснование не сочинено, но источник не процитирован

BLOCKERS.md в секции «Зачем бизнесово» объясняет блокировку через рассуждение («импорт привязан к конкретному продавцу, у каждого свои коды»), не называя документ. Я проверил по канону:

- `docs/CHESTNY_ZNAK_TASKS_RU.md` строка 28-29 — **И5**: «Всё мультитенантно: каждый запрос/выборка фильтруется по `tenant_id`; для селлера — ещё по его `seller_id`.»
- `docs/CHESTNY_ZNAK_TASKS_RU.md` строка 37: «Селлер видит только свой `seller_id` (через `get_effective_seller_id`).»
- `docs/CHESTNY_ZNAK_TASKS_RU.md` строка 109: сигнатура сервисной функции `import_marking_codes(session, tenant_id, seller_id, ...)` — `seller_id` обязателен на уровне сервиса.
- `docs/CHESTNY_ZNAK_DESIGN_RU.md` строка 235-237: «Кто видит: селлер (свои), ФФ (с предвыбором селлера). (ФФ) селектор селлера, если не выбран на Экране 1.»

**Вывод:** обоснование сочинением не является — принцип «импорт строго по `seller_id`» закреплён в спецификации И5 и дизайне. Переносить в «Без обоснования» не нужно. Но BLOCKERS.md не содержит ссылок на источники, что снижает проверяемость. Ничего не правлю: это ради красоты.

### 2. Дизайн-спецификация и реализация: расхождение UX, но не слоёв

`docs/CHESTNY_ZNAK_DESIGN_RU.md` строка 237 говорит: «(ФФ) селектор селлера, если не выбран на Экране 1» — то есть дизайн допускал открытие диалога «Загрузить коды» без предварительного выбора продавца, с выбором внутри диалога.

Реализация блокирует кнопку до открытия диалога:
- `HonestSignScreen.tsx:208` — вычисляет `importDisabled = sellerIdRequiredForImport && !effectiveSellerId`
- `HonestSignScreen.tsx:533` — `disabled={importDisabled}`
- `HonestSignScreen.tsx:372-374` — `openImport()` сам делает ранний выход без диалога

При этом `FfHonestSignPage.tsx:17-22` автоматически выбирает первого продавца из списка, если список непустой. Практически кнопка блокируется только при пустом списке продавцов. **Это расхождение UX-дизайна с реализацией, а не расхождение фронта с бэком**: оба слоя корректно требуют `seller_id`. Находкой уровня «разошлись слои» не считается, но вопрос для владельца:

> Требование «блокировать кнопку до выбора продавца» было сознательным отходом от CHESTNY_ZNAK_DESIGN_RU.md (п. Экран 2), или документ устарел? Нынешнее поведение безопаснее, но расходится с первоначальным дизайном.
