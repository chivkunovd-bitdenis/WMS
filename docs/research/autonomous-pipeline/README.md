# Исследование автономного конвейера разработки WMS

Дата начала: 2026-08-24.

## Цель

Спроектировать минимальный, но надёжный конвейер, который принимает обычное описание нового
модуля или набора изменений и без постоянного ручного сопровождения доводит работу до проверяемого
результата: продуктовый контракт, код, тесты, живая браузерная приёмка, доказательства и сохранённый
Git commit. Если завершение невозможно, конвейер обязан оставить точный классифицированный блокер и
восстановимый checkpoint, а не просто остановиться.

Исследование намеренно сосредоточено не на названиях агентных ролей, а на исполняемой механике:
состояниях, переходах, машинных гейтах, модельных решениях, форматах артефактов, ограничении scope,
повторных попытках, восстановлении и Git-долговечности.

## Состав досье

- `EXECUTIVE-SUMMARY.md` — короткий итог исследования и рекомендуемая архитектура.
- `WMS-PROBLEM-BRIEF.md` — уточнённые проблемы и критерии успеха.
- `RESEARCH-METHOD.md` — правила поиска, отбора и доказательного разбора источников.
- `sources/` — 279 каталожных записей в трёх полосах; между полосами есть намеренные пересечения.
- `source-analyses/` — 34 подробных поштучных разбора отобранных источников.
- `CURRENT-PIPELINE-AS-EXECUTED.md` — фактический WMS pipeline по коду, промптам и журналам.
- `PATTERNS-AND-FAILURES.md` — общие рабочие паттерны и антипаттерны.
- `WMS-TRACEABILITY-MATRIX.md` — связь каждой боли WMS с внешними доказательствами и решением.
- `TARGET-PIPELINE-DESIGN.md` — итоговая схема состояний, переходов, гейтов и восстановления.
- `IMPLEMENTATION-ROADMAP.md` — минимальная последовательность внедрения.

Все перечисленные итоговые файлы созданы. Каталоги остаются картой кандидатов, а не рекомендацией:
архитектурные выводы опираются на отдельные карточки глубокого чтения.
