# WMS-705: Изолированные тестовые тенанты на Railway staging

## Исходный запрос

Подготовить Railway staging как рабочий тестовый контур для ArtMaks, «Империи Львова» и AV Pack. Для каждого клиента создать новый отдельный тестовый тенант и учётки. Перенести рабочие данные, необходимые для реалистичной проверки склада: товары, селлеров, склады, ячейки, короба, настройки размещения и остатки. Существующие FBS-заказы заменить тестовыми. Реальные ключи и учётные данные селлеров не переносить. Показывать сверху заметную жёлтую плашку о тестовом контуре на всех порталах. Дважды в день автоматически создавать по 10 новых тестовых FBS-заказов в каждом подготовленном тенанте. Использовать тестовые КИЗы, доступные только на стейдже.

Работа выполняется по прямому поручению владельца без автоматических тестов и без изменения production. Известные источники: ArtMaks (`82b36645-8662-497f-9631-a0743994632c`), AVpack (`d6e1ad21-8afa-4acf-8d0b-907b9f2adcfe`), предполагаемый источник «ИП Львова В.В.» (`5fbf633c-3ea9-4c29-b5f5-f549b122bcae`). Последнее соответствие — рабочее предположение по названию и должно быть отражено в отчёте.

## Требования

| ID | Требование |
|---|---|
| R1 | Создать в Railway staging отдельный новый тенант на каждого из трёх источников, не переиспользуя существующие тенанты. |
| R2 | Перенести тенантные складские данные и связи, необходимые для работы каталога, склада, размещения, коробов, остатков и FBO-документов. Не переносить записи в production и не менять production-состояние. Универсальный исторический журнал `document_event` не копировать: его произвольный payload может содержать реальные КИЗы. |
| R3 | Не переносить секреты и живые интеграционные учётные данные, включая ключи WB/Ozon и токены маркировки, хеши паролей production-пользователей, реальные КИЗы и привязки к реальным принтерам. |
| R4 | Не переносить реальные FBS-заказы и связанные с ними незавершённые операции; создать в staging новые тестовые FBS-заказы, пригодные для операторского сценария. |
| R5 | В каждом подготовленном тенанте автоматически создавать по 10 новых FBS-заказов два раза в день. Генератор действует только на тестовых тенантах в режиме `staging` и не обращается к внешнему продавцу для создания заказа. |
| R6 | Использовать тестовую маркировку: создать по 100 явно синтетических КИЗов на каждого нового продавца, не копируя реальные производственные КИЗы и печатные коды. |
| R7 | На fulfillment- и seller-порталах, а также в мобильном ТСД показывать заметную жёлтую плашку «ТЕСТОВЫЙ КОНТУР» сверху; она не закрывает рабочие элементы и зависит от окружения сервера. |
| R8 | Проверить безопасные параметры Railway staging без чтения значений секретов. Тестовые складские действия не должны менять production-остатки или создавать внешние операции от лица скопированных production-селлеров. |

## Проверки и вердикт

| ID | Проверка | Класс | Вердикт |
|---|---|---|---|
| C1 | Три новых тестовых тенанта созданы отдельно; число строк по выбранным таблицам сходится с источником после оговорённых исключений. | Разово | Ожидает выполнения |
| C2 | В staging-данных отсутствуют секреты, хеши production-паролей и рабочие FBS-заказы; production не изменён. | Разово | Ожидает выполнения |
| C3 | Два расписания запускают генерацию по 10 заказов на тенант; создаются только локальные заказы в тестовых тенантах. | Разово | Ожидает выполнения |
| C4 | Баннер виден сверху на fulfillment- и seller-порталах и в мобильном ТСД; рабочие элементы остаются доступны. | Руками | Ожидает выполнения |
| C5 | Код или конфигурация, помечающие окружение, не показывают баннер на production. | Разово | Ожидает выполнения |

## Заключение

Не принято. Предварительно установлено, что production и staging имеют одинаковую ревизию схемы `20261007_2303`, а FBS Wildberries направляется в staging-эмулятор. Доступные на стейдже коды маркировки не подтверждены как тестовые, поэтому перенос реальных кодов запрещён; копировщик создаёт отдельные синтетические коды. Ozon live включён на уровне приложения, поэтому тестовые тенанты не получают production-учётные данные. Выполнение переноса, автоматического генератора и баннера ожидает.
