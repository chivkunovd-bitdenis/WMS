# WMS-513. Рабочая сессия без автоматического обрыва

## Исходный запрос

> «бляь заебали они протухать
> нахуй вооьше это слелано? вечно у людей посреди работы просто всё отваливается нахуй
> давай уберём эта залупу?»

Уточнение владельца: отдельная аналитика для этой правки не нужна; требуется убрать
автоматическое протухание пользовательской сессии.

## Существующий процесс и цель

Сейчас каждый вход выдаёт JWT с `exp` на 24 часа. После истечения любой рабочий запрос
получает `401 Unauthorized`; открытый экран остаётся на месте и показывает общую ошибку,
а рабочий сценарий оператора прерывается. Цель — один раз войти и продолжать работу без
календарного обрыва сессии. Явный выход, удаление пользователя и проверка его текущих
прав в базе сохраняются.

## Требования

- **R1.** Новый токен после входа, регистрации, задания пароля или переключения магазина
  не содержит календарного срока окончания и не становится недействительным из-за
  прошедшего времени.
- **R2.** Токен продолжает подписываться серверным ключом и несёт прежние границы:
  пользователя, клиента, роль и выбранного селлера. Токен с чужой подписью отклоняется.
- **R3.** Явный выход по-прежнему удаляет токен на устройстве. Удалённый пользователь и
  пользователь с изменёнными серверными правами по-прежнему проверяются по базе на каждом
  запросе существующей зависимостью авторизации.
- **R4.** Токены, выданные до выкладки, сохраняют старый срок. После выкладки нужен один
  последний вход; все последующие токены работают без автоматического окончания.

## Проверки

| Проверка | Требования | Вердикт |
|---|---|---|
| C1. Выпустить токен со всеми полями области доступа и декодировать его; `exp` отсутствует, `iat` и область доступа сохранены. | R1, R2 | подтверждено: `test_access_token_has_no_wall_clock_expiration` |
| C2. Подписать токен другим ключом и передать штатному декодеру. | R2 | подтверждено: `test_access_token_still_rejects_a_foreign_signature` |
| C3. Запустить целевые тесты токенов и авторизации. | R1–R4 | подтверждено: результаты указаны в заключении |
| C4. Проверить документ задачи относительно базовой ветки. | R1–R4 | подтверждено: результаты указаны в заключении |

## Заключение

Новые пользовательские токены больше не содержат автоматического срока окончания.
Подпись, клиент, роль и выбранный селлер сохранены. Существующие старые токены потребуют
одного повторного входа после выкладки. `ruff check .` и `mypy .` прошли; адресный набор
`tests/test_tokens.py tests/test_auth.py tests/test_seller_shop_scope.py` — 7 тестов
пройдено. Локальный скрипт проверки документов отсутствует в базовой ветке `origin/etalon`,
поэтому отдельно не запускался. Реализация сохранена в ветке
`codex/wms513-persistent-session`, commit `b7a96f80`.
