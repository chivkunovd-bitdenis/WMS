# WMS-584 · ТСД FBS: компактные заказы, массовое создание поставок как в вебе, компактный подбор с ячейками и отменой

Запись задачи: [канонический бэклог, WMS-584](../KANONICHESKIY_BACKLOG.md#wms-584). Продолжение [WMS-445](WMS-445.md) и [WMS-401](../KANONICHESKIY_BACKLOG.md#wms-401).
Без аналитика по указанию владельца («давай без аналитиков, без скиллов»). Реализация — Claude Sonnet (фронт мобилки), перекрёстное ревью — Sol 5.6, по поручению владельца 29.09.2026.

Код: отдельный репозиторий `mobile/` (без remote), база — коммит `cef944b` (APK18 `3206669` + проверенная правка WMS-445 о начале draft-поставки).

## 2. Что проверено ведущим 29.09.2026 (эмулятор, APK18, локальный стенд с кодом прода 9f92acee)

- Карточка заказа — 9 строк, на экране 1080×2280 помещаются 2 карточки; строка «Маршрут: … · Статус: …» есть. Выбора всех / снятия / фильтра по селлеру нет.
- **Застревание неудачной попытки создания/добавления.** `FbsViewModel.create/addTo` сохраняют запрос до сети и стирают только при успехе. Сервер на смешанный набор отвечает `409 {"code":"order_incompatible","context":{"reasons":["different_seller"]},"retryable":false}`; приложение сохранённую попытку не стирает, при каждом входе в FBS `resumePendingSupplyMutation` повторяет POST, снова открывает окно и подменяет выбор заказами из неё. «Отмена» не помогает (воспроизведено: отмена → выход → вход → окно снова). Это и есть «нажимаю назад, он применяет предыдущие шаги».
- **Сам пищит и мигает зелёным.** `FbsViewModel.perform` на любом успехе ставит `ScanFlash.Success` (звук, вибрация, зелёная вспышка), в том числе на `loadOrders` и `loadSupply`.
- Зелёные «Подобран» в общем списке — заказы, подобранные внутри поставки; общий список показывает и заказы в поставках.
- Экран поставки: селлер, маршрут, склад и полный состав выше кнопок шагов; третья кнопка «Короба» за краем экрана.
- Подбор: скан ячейки → источник, скан товара → подбор (сервер принял), скан другой ячейки → источник переключён — **работает**. Список подбора — полные карточки заказов; ячейки видны только после подбора; отмены последнего подбора нет. «Сменить» сбрасывает отсканированную ячейку и без неё ничего не делает.
- Ввод названия не работал из-за настройки эмулятора (hw.keyboard=no), не из-за приложения; исправлено в эмуляторе.
- Сервер уже умеет всё нужное, **правок бэка нет**: `preflight` и `from-orders` по группам (как веб WMS-574, `groupFbsOrdersForSupplies`/`fbsSupplyGroupKey` в `frontend/src/screens/v2/fbsSupplyAssembly.ts`), `pick-options` (ячейки с доступным количеством по товару), `pick/set` (задать количество подобранного — используется вебом, пригодно для отмены), `image_url` товара в заказах.

## 3. Требования

- **R1. Компактная карточка заказа.** Фото слева, справа: номер заказа, название товара (до 2 строк), ШК/артикул, селлер, «Отгрузить до». Строку маршрута и строку «Поступил» убрать; статус не выводить отдельной строкой. На экране 1080×2280 видно не меньше 4 карточек. Близкий срок по-прежнему выделен (WMS-401).
- **R2. «Выбрать все» и «Снять выделение»** для заказов, доступных к выбору в текущем списке (с учётом фильтра R3).
- **R3. Фильтр по селлеру** над списком: «Все селлеры» + селлеры из загруженных заказов текущей площадки.
- **R4. Общий список — только новые заказы для выбора.** Заказы, уже находящиеся в поставке, в общем списке не показываются (к ним ведёт «В работе»); зелёной подсветки подбора в общем списке нет. *(Решение ведущего по словам «как будто я их не взял в работу»; владельцу сообщено.)*
- **R5. Массовое создание поставок как в вебе.** Кнопка «Создать поставки (N)» делит выбранные заказы на группы тем же ключом, что веб (`fbsSupplyGroupKey`: селлер, склад WB, тип груза, склад WMS, тип покупателя), показывает группы (селлер · кол-во заказов), для WB — выбор «Склад / СЦ» или «ПВЗ». Название вводить не обязательно: имя как в вебе — `FBS <дата dd.MM.yyyy>`. По каждой группе — `preflight`, несовместимая группа показывается с причиной и не создаётся; совместимые создаются `from-orders` по одной с ключом повтора на группу (частичный успех виден по группам). Разные селлеры больше не дают общий отказ.
- **R6. Общий подбор созданных поставок.** После создания открывается один экран подбора по всем созданным поставкам (как «едины на подборе» в вебе): общий список товаров по R8, скан товара подбирает для самого старого неподобранного подходящего заказа среди всех поставок группы (в ту поставку, где этот заказ). Для одной поставки — тот же экран.
- **R7. Отказ сервера не застревает.** Если сервер окончательно отказал (HTTP 4xx или `retryable:false`), сохранённая попытка создания/добавления стирается, повторно не отправляется и окно само не открывается; оператор видит причину по-русски применительно к заказам (`different_seller` → «разные селлеры» и т. п., номера заказов). Сохранённая попытка остаётся и восстанавливается только при потере связи / 5xx / неизвестном результате (защита WMS-445 от дубля сохраняется).
- **R8. Экран поставки — как был, без селлера/маршрута/склада.** Исходный вид (cef944b) сохраняется: название, «площадка · статус», строка счётчиков, «Состав», три вертикальные кнопки во всю ширину «Подбор», «Упаковка и этикетки», «Короба», ниже передача. Убираются только строки «Селлер», «Маршрут», «Склад». Состав — карточками товаров с фото (решение владельца 29.09). Карточка поставки в «В работе» — исходная. *(Исправление ведущего: прежняя редакция R8 с «кнопками наверху» была дописана ведущим от себя, владелец её отклонил: «зачем остальные экраны поменяли… он же был нормальный».)*
- **R9. Компактный подбор по товарам.** Список товаров поставки (или группы), одна строка на товар: фото, название, ШК, «подобрано X из Y»; под строкой — ячейки, где товар есть, с доступным количеством (из `pick-options`), подобранные — зелёным. Карточки заказов, селлер, маршрут, «Поступил», «Отгрузить» на подборе не выводятся. Сканирование ячейки/товара — как сейчас (работает).
- **R9a. Карточки подбора по образцу владельца.** Сверху полоса текущей ячейки (зелёная — ячейка отсканирована, серая — нет), заголовок «Товары»; карточка товара: крупное фото ~1/3 ширины, название, артикул, ШК, крупно красным «N шт.» к подбору, «Подобрано» зелёным; ячейки с остатком под карточкой. Состав поставки — те же карточки без красного.
- **R10. Отменить последний подбор.** Кнопка «Отменить последний» возвращает последнюю успешно подобранную единицу (через `pick/set` товара в той же ячейке/контейнере на количество −1 от текущего, с защитой от повторного нажатия), после чего данные перечитываются с сервера. Если отменять нечего — кнопка неактивна.
- **R11. «Сменить ячейку».** Кнопка видна только когда ячейка отсканирована и называется «Сменить ячейку».
- **R12. Без ложных сигналов.** Звук/вибрация/зелёная вспышка успеха — только на результат скана или действия оператора (подбор, упаковка, короб, ЧЗ, создание), не на загрузку и обновление экранов.
- **R13. Остальное не меняется:** упаковка и этикетки, ЧЗ, короба («открыть/закрыть короб»), передача, Ozon-позиции, восстановление после потери ответа там, где сервер не ответил. Серверный код не меняется.
