# WMS-617 · Стенд для записи видео по клиентскому списку

## Исходный запрос

Дословное поручение владельца 01.10.2026, переданное ведущим аналитику:

> проверь, есть ли засеяные данные для всего: для FBS, для массовой сборки, для вот этой засеи по всем артикулам 2ШК, чтобы можно было выбрать ШК по умолчанию, проверить, что это отображается в карточке, подними, ну, засей тоже, по сути, мобилку, чтобы в мобилке всё это отображалось, инвентаризации и прочее. кода или APK само по себе не подтверждает пригодность сценария для записи.

## Решения аналитика о демонстрационных данных

Новые экраны и режимы для ролика не требуются. Используется существующий staging,
его WB-эмулятор и существующее staging-приложение ТСД. В мобильном приложении
показываются серверные данные того же склада/селлера, отдельная несвязанная
«мобильная база» не создаётся.

Под «по всем артикулам 2ШК» понимаются **все артикулы согласованного набора
для записи**, а не произвольные рабочие записи всего стенда. Исполнитель
сначала инвентаризирует прежние демонстрационные записи и составляет в этом
документе точный перечень ID/SKU. Пригодные записи сохраняются; недостающие
добавляются с префиксом `WMS617-DEMO`. Чужие данные не переписываются.
Если владелец затем уточнит «весь каталог», это уточнение сохраняется отдельно.

Минимальный набор ниже задаёт покрытие сценариев; допустимо использовать
эквивалентные прежние demo-записи с зафиксированным соответствием:

| Данные | Требуемый состав |
|---|---|
| Селлеры/склады | Два синтетических селлера; WB у обоих, Ozon хотя бы у одного; два маршрута WB, существующий склад ФФ с ячейками и тарой. Без новых реальных ключей и изменения чужих прав. |
| Товары | Не менее 6 SKU: WB обычный, WB с обязательным ЧЗ, WB второго селлера, Ozon обычный, Ozon со вторым ШК, связанный WB/Ozon пример. У каждого SKU набора минимум 2 различных действующих алиаса и ровно один выбранный основной; исходные алиасы не удаляются. |
| Остатки/размещение | Каждый SKU имеет не менее 20 доступных единиц до резервов демонстрации; один товар лежит в двух ячейках/тарах. Остаток, резерв и расположение согласованы с существующими источниками. Приход/движения оформлены связанными документами, а не вымышленными строками журнала. |
| FBS | Минимум 12 пригодных заказов: 8 WB разных селлеров/маршрутов и 4 Ozon, включая многоштучный заказ; отдельные примеры «Новые», обычная сборка, общая сборка, доставка. После репетиции остаётся незавершённый набор для записи. Сроки относительные к дню записи, один ближайший и один просроченный. |
| ЧЗ/печать | Достаточный синтетический пул для двух проходов, отдельный товар без обязательного ЧЗ. Ошибочный скан не расходует последнюю пригодную запись. Заказы, этикетки и поставки согласованы с WB-эмулятором; повторная печать не создаёт новое движение. |
| Инвентаризация | Один черновик со всеми SKU набора, остатком и резервом; один документ с частично введённым фактом для продолжения на ТСД; завершённый пример только при корректных документах движения. Фактическое проведение не требуется ради заполненного экрана. |
| Селлер/расчёты | Синтетические реквизиты, хотя бы 2 начисления, один выставленный счёт и ставка у первого селлера; отдельная строка второго для проверки изоляции. Никаких настоящих оплат/рассылок. |
| Выборочный каталог | Несколько синтетических позиций доступны в каталоге площадки, часть уже выбрана, хотя бы одна не выбрана и пригодна для добавления в ролике. |

## Требования

- **R1.** Сохранить полную матрицу 11 исходных клиентских пунктов и дополнений
  547/549; каждому сопоставить существующую задачу, функцию и конкретный вердикт
  на итоговом staging. Источник: просьба «ещё раз сопоставь всё со списком».

  Повторный запуск не размножает товары/заказы/начисления и не сбрасывает работу

## Заключение

**Постановка подготовлена; WMS-617 не принята как готовность стенда к записи.**
Часть демонстрационных данных существует, что подтверждено каталогом в браузере.
Полнота двух ШК, связанные FBS/эмуляторные состояния и мобильный проход ещё
не проверены. Заполнение стенда не устраняет функциональные пробелы исходного
PSP: их нельзя показывать как готовые. Исполнителю передаются R2–R12 и C2–C16;
после подготовки аналитик проверяет фактические ID и обновляет это заключение.

Проверка трассировки постановки: FBS → R5/C5/C7/C14; массовая сборка → R6/C6;
два ШК и карточка → R3–R4/C3–C4; мобильный ТСД/эмулятор → R8/C9;
инвентаризация → R7/C8; полный клиентский список → R1/R9–R11/C1/C10–C15;
пригодность записи и сохранность → R2/R11–R12/C2/C15–C16.
