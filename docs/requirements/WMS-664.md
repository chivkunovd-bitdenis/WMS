# WMS-664 · Telegram-бот не должен зацикливаться на допустимом разбиении сообщения на темы

Источник: прямое поручение владельца 05.10.2026 после проверки локального
`pro.sellerfocus.wms-support-agent`.

## Фактический сбой

В сообщении владельца было пять связанных вопросов по КИЗ. Маршрутизатор вернул
продолжения двух существующих тем и две новые подтемы. Новая `topic-190-1`
оказалась второй по позиции в массиве, а код разрешал на этой позиции только
`topic-190-2`. Весь ответ откатывался с `invalid new topic id`, очередь
сохранялась, после чего бот повторял тот же платный модельный запрос каждые
20–40 секунд. За 30 минут выполнено 60 одинаковых повторов. Следующие сообщения
также остались за заблокированным пакетом.

## Требования

R1. Для входного сообщения безопасным новым идентификатором считается только
`topic-<source_id>` либо `topic-<source_id>-N`, где `N` от 1 до 8. Номер новой
подтемы не зависит от её позиции среди продолжений уже существующих тем.

R2. Существующие ограничения сохраняются: нельзя открыть тему другого сообщения
или чата, нельзя менять тему внутреннего события, нельзя создать больше восьми
частей из одного сообщения.

R3. При ошибке маршрутизации очередь и исходные сообщения сохраняются. Повтор
не должен запускаться на каждом коротком цикле сервиса: задержка между повторами
увеличивается, а после третьей одинаковой ошибки составляет не меньше пяти минут.

R4. После успешной маршрутизации счётчик ошибки сбрасывается. Новая версия кода
должна обработать уже сохранённые сообщения без ручного удаления из SQLite.

R5. Исправление сохраняется отдельным коммитом и устанавливается в локальный
LaunchAgent только из проверенного SHA. Оно не выполняет продуктовый деплой WMS,
не выводит КИЗ из оборота и не меняет складские данные.

R6. Если одно сообщение владельца разложено на несколько независимых подтем,
подтемы могут выполняться параллельно, но бот отправляет владельцу не несколько
частичных финальных ответов, а одно сводное завершение после обработки всех
частей. Промежуточные результаты частей не должны превращаться в отдельную
лавину уведомлений.

R7. Новый проектный запуск с WMS-номером, который уже входит в незавершённую
работу (`scheduled`, `queued`, `running` или `recovering`), не создаётся.
Координатор возвращает существующую работу, чтобы две сессии не меняли одну
задачу параллельно.

R8. Явная отмена владельцем завершает ещё не выпущенную ночную работу без
автоматического отчёта по каждой отменённой задаче. Состояние и рабочие файлы
сохраняются для проверки, но отмена не создаёт новую серию Telegram-сообщений.
Если внешнее действие уже могло начаться, действующее правило сверки
неизвестного результата сохраняется.

R9. Несколько последовательных сообщений одного чата, попавших в одну пачку
маршрутизации, можно объединить в одну новую тему, названную по любому сообщению
этой пачки из того же чата. Идентификатор сообщения из другого чата по-прежнему
не может открыть или переименовать тему.

## Заключение

Первый выпуск исправления был принят по C1–C8. Повторная живая проверка в 22:13
выявила новый случай C9: два соседних сообщения владельца маршрутизатор объединял
в тему второго сообщения, а проверка откатывала всю пачку. До исправления C9
итоговый статус задачи снова «в работе». Полный набор первого выпуска `tools/support_agent`:
`671 passed`; `ruff check support_agent tests` и адресный `mypy` для изменённых
модулей прошли. Локальный LaunchAgent работает, установленный код побайтно
совпадает с коммитом реализации `62955303d623f9c995ad05271ebd746fc995ab6b`.

Сохранённая очередь разобрана, счётчик LLM остановился на вызове 1048 в 17:17:33,
после финального запуска новых модельных вызовов и новых сообщений не появилось.
По прямому распоряжению владельца работы `5beb52dad9529727` и
`a042ac1424ab89ab`, оставшиеся темы сообщений 190–194 и неотправленный вопрос
Виталию остановлены; их Git-worktree и состояние не удалялись.

Во время первой проверки обнаружился дополнительный дефект: старый код успел
отправить два отчёта об уже отменённых ночных работах (outbox 269–270). После
этого добавлена R8 и установлена тихая отмена; повторная проверка новых сообщений
не создала. Это установка локального Telegram-бота, а не deploy WMS в production.
