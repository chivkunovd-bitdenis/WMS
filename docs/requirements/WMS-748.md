# WMS-748 · После сортировки место короба должно совпадать с ячейкой его остатка

## Исходное поручение

При размещении полного короба из сортировки остаток переносится в выбранную ячейку, но запись короба остаётся привязана к `__SORTING__`. Подбор FBS (сборка товара для отправки со склада) затем отклоняет этот источник, потому что место тары расходится с выбранной оператором ячейкой. Исправить расположение записи короба тем же механизмом, которым складские операции перемещения обновляют расположение тары. Количество остатка при этом не меняется.

Для существующих данных проверить только читающими запросами число коробов и тары в системной сортировке, выделить случаи с остатком ровно в одной ячейке и добавить идемпотентную миграцию только для таких случаев. Неоднозначные случаи не менять, а посчитать в логе миграции. Откат миграции данных — no-op, так как восстановление старого расположения сделало бы правильные данные неверными.

## Установленные факты

В отчёте живого прохода ТСД `/Users/deniscivkunov/Projects/WMS/.worktrees/_night-20261010/lanes/live-fbs.md`, раздел P1-1, описан отказ 409 при подборе из коробов после сортировки: запись короба указывает на `__SORTING__`, а остаток находится в ячейках. Проверка выполнялась на стенде с имитатором WB; отчёт говорит, что прямой запрос подбора дал тот же отказ.

10.10.2026 на production-базе выполнены только SELECT-запросы через `ssh root@sellerfocus.pro` и `docker exec wms_prod-db-1 psql -U postgres -d wms`. Для записей в системной локации `__SORTING__` однозначных коробов или тары с остатком в одной ячейке не найдено. У ArtMaks (`artmaks-3j511`) найдены 4 короба без ненулевого баланса, 1 короб на палете и 1 грузоместо без ненулевого баланса. У «Империи ФФ» найдены 759 коробов: у 597 остаток всё ещё в сортировке, у 162 нет ненулевого баланса. Эти строки не являются безопасными кандидатами на перенос места.

Системное место сортировки задаётся кодом `__SORTING__` в `sorting_location_service.py`. При обычном перемещении контейнера запись места обновляется в `warehouse_map_service._place_container`.

## Требования

R1. При размещении полного короба из сортировки в ячейку поле места записи короба указывает на эту ячейку тем же механизмом обновления записи тары, который используется при перемещении контейнера. При частичном размещении остаток в коробе и его место не меняются. | навсегда

R2. Исправление расположения не меняет остаток: суммарное количество товара остаётся прежним, а баланс полного короба после размещения привязан к выбранной ячейке. | навсегда

R3. Миграция переносит место только у записи тары в `__SORTING__`, для которой весь ненулевой остаток находится ровно в одной действующей обычной ячейке того же склада и арендатора, а сама тара не привязана к палете. Системные места `__SORTING__` и `__DEFECT__`, удалённые локации и любая другая ситуация остаются без изменений и учитываются в логе миграции. Повторный запуск не меняет результат. | разово

R4. `downgrade` миграции не меняет данные. | разово
