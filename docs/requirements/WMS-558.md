# WMS-558 · FBS: сохранять открытый этап после обновления страницы

## Запрос и требования

После refresh страницы FBS оставаться на выбранном этапе текущей поставки.
«Короба» остаются коробами, другой этап тоже восстанавливается. Переключение
поставки не переносит в неё чужую вкладку. Бизнес-статусы и ограничения этапов
не меняются; правило `assembling → picking` не восстанавливается.
По прямому указанию владельца работа выполняется без навыков и отдельной ролевой цепочки.

Поставка уже хранится в URL `supply_id`. Её выбранная вкладка сохраняется в существующем
sessionStorage по глобально уникальному UUID поставки. Начальная загрузка только читает
значение; запись происходит при выборе этапа. Недоступное хранилище и неизвестное
значение возвращают прежнее поведение без ошибки экрана. Данные операций не затрагиваются.

## Проверки

| ID | Проверка | Вердикт |
|---|---|---|
| C1 | Повторное открытие коробов, упаковки, подбора и состава восстанавливает выбор. | PASS: тесты хранения всех этапов и исполнения загрузки workspace. |
| C2 | Две поставки сохраняют независимые этапы, новая поставка не наследует чужой. | PASS: адресные тесты. |
| C3 | Некорректное значение, недоступное sessionStorage, начальная загрузка. | PASS: адресные тесты, запись только при выборе. |
| C4 | Целевые тесты, TypeScript, build и браузерный refresh. | 112 тестов PASS совместно с WMS-557, TypeScript PASS. Build выполняется; браузерный refresh после выкладки ещё не проверен. |

## Заключение

Реализация сохраняет выбранный этап без изменения бизнес-статусов и блокировок.
112 целевых тестов и TypeScript проходят. Общая сборка выполняется; деплой и
браузерный refresh нового кода ещё не выполнялись.
