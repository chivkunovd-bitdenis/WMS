# WMS-726 · FBS упаковка: кнопка «Выбрать без ЧЗ»

Статус: постановка подготовлена 09.10.2026, реализация не начата. Делается по полному процессу (аналитик → тесты до кода →
разработка → ревью → приёмка → CI). Пакет поручений владельца от 09.10.2026: WMS-716…WMS-734.

## Исходное поручение

09.10.2026, сообщение владельца в чате (дословно, с опечатками оригинала):
«кнпока выбрать без ЧЗ в упаковке - чтобы только они выделялись».

## Что проверено при заведении

- Код прода 694de0413 и etalon 61012808c, вкладка «Упаковка и маркировка» карточки поставки FBS:
  кнопки выбора только заказов без Честного знака нет (поиск по «Выбрать без», «без ЧЗ» в экранах
  FBS ничего такого не нашёл); у строк есть галки выбора заказа.
- Экран в браузере при заведении не открывался: во встроенном браузере нет входа на прод.

## Разбор кода 09.10.2026

У заказа в данных поставки есть список требуемой маркировки (order.metadata.required, на экране
«Состав» выводится как «Не требуется», если пусто); на упаковке у строк есть галки выбора
(packingSelectedIds). Признак «без ЧЗ» берётся из этих данных.

## Существующий процесс и цель изменения

Код сверён в текущем worktree на `159f6a9a9ab4a1a1254c31f8b48f59ba641863e2`.
Исторические сведения ведущего выше сохранены; production повторно не проверялся.
Упаковка и образцы дизайна **на экране не проверены**: браузера и боевой базы у аналитика нет.

Оператор отмечает галки заказов в «Упаковке и маркировке» карточки FBS; выбор хранится в
`packingSelectedIds`, выбранные заказы передаются прежним действиям в порядке `fullTapeOrders`.
Специальной кнопки выбора без ЧЗ в `FfFbsSupplyWorkspace.tsx` нет. Карточка может также служить
общей сборке через `assemblyFrame`/`registerPackingActions`; изменение общей логики не должно
переносить выбор на другую поставку или менять маршрут скана/печати.

Предварительный разбор выше уточнён: **одного пустого `metadata.required` недостаточно**.
`requiresOrderHonestSign` учитывает `product.requires_honest_sign`, признак строки задания
упаковки и наличие `sgtin` (тип кода ЧЗ) в обязательных метаданных. В режиме пропуска ЧЗ эта
функция меняет смысл на необходимость работы с уже сохранённым кодом; её результат нельзя
безусловно использовать как признак немаркируемого товара.

Для Ozon `_requirements_by_sku` в `ozon_fbs_sync_service.py` учитывает товары всех позиций:
маркируемая вторая позиция добавляет `sgtin` в требование всего отправления. Там же и в
`ozon_fbs_marking_gate_service.ozon_requirements_known` различаются разобранные пустые
требования и неизвестные. `build_order_metadata` возвращает required/optional/states, но не
отдельный признак известности требований. Это найденная граница данных для исполнителя,
а не разрешение считать неизвестное отправление немаркируемым или добавить новый запрет.
Цель — одним нажатием заменить ручные галки выбором заказов, которым ЧЗ не требуется.

## Требования

**R1. Кнопка выбора в упаковке.** Условие: открыта «Упаковка и маркировка» карточки поставки
WB/Ozon и загружены её заказы. Действие: нажать «Выбрать без ЧЗ» рядом с существующими действиями
выбранных заказов над списком упаковки. Результат: галки текущей поставки заменены множеством
заказов без необходимости ЧЗ; ранее выбранные маркируемые заказы сняты. Список не скрывается
и не фильтруется этим действием. Основание: исходное «чтобы только они выделялись», D1–D2.

**R2. Критерий — необходимость ЧЗ, не наличие кода.** Условие: классифицируется заказ для R1.
Действие: определить необходимость по существующим данным заказа, товара и задания.
Результат: WB заказ выбирается, если нет `sgtin` в обязательных метаданных и ни товар, ни
строка задания не требуют ЧЗ. Обязательные IMEI/UIN сами по себе не являются ЧЗ и не исключают
заказ. Маркируемые заказы без кода, с принятым/отклонённым кодом или после пропуска/очистки
ЧЗ не становятся «без ЧЗ» из-за состояния привязки. Для Ozon выбирается целое отправление
только с известными требованиями без `sgtin` и без маркируемых товаров во всех позициях;
неизвестность требований не считается подтверждением «без ЧЗ». Основание: D1, реальные
признаки кода и различие неизвестного/пустого в существующем Ozon-процессе.

**R3. Только изменение галок.** Условие: оператор нажал кнопку один или несколько раз.
Действие: применить выбор. Результат: не создаются запросы упаковки/печати/привязки или
очистки кодов; не меняются заказы, резерв, остаток, отметки упаковки, короб, настройки печати
и активный адресат скана. Повтор с теми же данными даёт те же галки; если подходящих заказов
нет, выбор пуст. После этого галки можно менять вручную обычным способом.
Основание: поручение про выделение, AGENTS.md и D2.

**R4. Прежние действия для выбранных.** Условие: выбор сделан новой кнопкой либо теми же
галками вручную. Действие: выполнить существующее действие выбранных заказов.
Результат: целевые идентификаторы и их порядок одинаковы; печать использует прежний общий
маршрут и действующие настройки, без самовольного пропуска ЧЗ, выдачи кодов или отметки
упаковки. Действия, работающие со всей поставкой, сохраняют свой прежний охват.
После отказа печати/скана остаётся прежнее восстановление и возможность работать с другим
заказом. Основание: предварительное R3, B18–B19 и границы этой задачи.

**R5. Актуальность и границы выбора.** Условие: состав перечитан или открыта другая поставка.
Действие: нажать кнопку вновь. Результат: выбор строится по актуальным заказам текущей
поставки, не содержит удалённые/чужие идентификаторы и не меняет выбор соседней поставки
в общей сборке; тихое обновление не добавляет новые галки автоматически. Существующая защита
действий на время запроса сохраняется; новых запретов переходить по вкладкам WB нет.
Основание: действующий выбор по идентификаторам, правило WB и сценарии восстановления навыка.

## Решения аналитика и оставшиеся вопросы

- **D1. «Без ЧЗ» = ЧЗ не требуется**, а не «код ещё не привязан». Второе включало бы
  маркируемые товары, которым как раз предстоит назначение кода; слова «только они» и
  существующие признаки необходимости позволяют закрыть вопрос без изменения бизнес-процесса.
  Пустой required, optional `sgtin`, наличие хвоста кода и готовность к сдаче — разные факты.
  Optional `sgtin` сам по себе не делает WB товар маркируемым; положительный признак товара
  или задания это делает. Пропуск ЧЗ не переименовывает маркируемый товар в немаркируемый.
- **D2. Выбор заменяется целиком**, иначе старые галки ЧЗ нарушали бы «только они выделялись».
  Охват — все заказы открытой поставки, включая уже напечатанные/упакованные, поскольку
  ручные галки доступны и для них. Существующий фильтр непринятых кодов не меняет состав
  множества и не выключается новым действием; скрытие строки не означает её отсутствие в
  поставке. Нового фильтра или окна нет.
- **D3. Для Ozon используется существующее знание требований всех позиций.** Если для UI
  необходима проекция уже сохранённого признака известности, она передаёт этот факт из
  существующих данных, не заводит новый статус/журнал. `delivery_allowed` не заменяет
  необходимость ЧЗ: запрет сдачи может относиться к IMEI/UIN или иной причине. Автовыбор
  неизвестного отправления не выполняется, но ручной выбор, скан, вкладки и действующие
  операции этой задачей не блокируются.
- **D4. Общие компоненты проверяются вторым путём сборки**, чтобы новая кнопка карточки
  не сломала регистрацию действий/сканер. Новая панель или отдельный режим сборки не нужны.
- Вопросов владельцу нет. Вопросы черновика закрыты D1–D3 с указанными основаниями.

## Сверка запроса с требованиями

Прямо: «кнпока выбрать без ЧЗ в упаковке» → R1–R2; «чтобы только они выделялись» → R1, R3.
Обратно: R1 — исходный запрос; R2 — D1/D3 и действующие данные необходимости; R3 — выделение
галками без нового действия; R4 — сохранение обычных действий и библиотека B18–B19;
R5 — границы объекта и WB-навигация AGENTS.md. Новых блокировок, автоматической упаковки,
пропуска маркировки или фильтра нет.
