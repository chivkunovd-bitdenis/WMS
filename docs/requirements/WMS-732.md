## Исходное поручение

09.10.2026, сообщение владельца в чате (дословно): «автоматом тянуть список складов по расписанию».
Строка стоит в одном блоке с поручениями по FBO (WMS-731).

## Что проверено при заведении

- Код etalon 61012808c: расписание фоновых задач (backend/app/celery_app.py) уже содержит
  ежедневную загрузку складов WB «wb-mp-warehouses-daily» в 03:00 (по времени Celery). Она
  перезаписывает кэш складов WB фулфилмента (таблица tenant_wb_mp_warehouses) по ключам первого
  зарегистрированного селлера (wb_mp_warehouse_service.py). Этот список — «Склад маркетплейса»
  в отгрузке FBO.
- Боевая база, запрос только на чтение 09.10.2026: в кэше 173 склада у 6 фулфилментов, последняя
  загрузка — 14.08.2026 03:00 UTC. То есть с 14.08 расписание ни разу успешно не обновило список.
  Контейнеры celery_beat и celery_worker на проде запущены. Причина по логам не установлена.
- Экран в браузере при заведении не открывался: во встроенном браузере нет входа на прод.

## Требования (предварительно, аналитик уточняет по экрану)

R1. Список складов маркетплейса обновляется автоматически по расписанию, без действий оператора.
R2. Сбой площадки или ключа одного селлера не оставляет список навсегда устаревшим: следующий
запуск повторяет загрузку.

## Открытые вопросы аналитику

1. Какой список имеется в виду: склады WB для отгрузки FBO (тот, что не обновлялся с 14.08),
   склады продавца FBS, склады Ozon — уточнить у владельца.
2. Почему ежедневная загрузка не срабатывает с 14.08 — установить до реализации (ключ первого
   селлера, ошибка WB, расписание).
