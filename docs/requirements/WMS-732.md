# WMS-732 · Склады WB: ежедневно загружать новые склады

Статус: заведена 09.10.2026, не начата. Делается по полному процессу (аналитик → тесты до кода →
разработка → ревью → приёмка → CI). Пакет поручений владельца от 09.10.2026: WMS-716…WMS-734.

## 1. Исходный запрос и уточнения

09.10.2026, первое сообщение владельца (дословно): «автоматом тянуть список складов по расписанию».

09.10.2026, второе сообщение владельца (голосом, дословно по расшифровке): «По складам ежедневная
загрузка должна быть и загружать эти склады, актуализировать. Не актуализировать, а просто новые
загружать.»

## 2. Существующий процесс (проверено 09.10.2026)

- Список складов WB фулфилмента — таблица tenant_wb_mp_warehouses; из неё берётся выбор «Склад
  маркетплейса» в отгрузке FBO (GET /operations/wb-mp-warehouses, FfSuppliesShipmentsPage.tsx,
  SellerMarketplaceUnloadDialog.tsx).
- В расписании (backend/app/celery_app.py) есть ежедневная задача «wb-mp-warehouses-daily»
  в 03:00. Она берёт ключи только первого зарегистрированного селлера фулфилмента и заменяет
  список целиком: удаляет все строки и вставляет полученные (wb_mp_warehouse_service.py,
  replace_tenant_mp_warehouses). При пустом списке есть ленивая загрузка при открытии.
- Боевая база, только чтение 09.10.2026: последняя загрузка у AVpack, FFAdam, «Империи ФФ»,
  «ИП Тестовый», «ПакХаб» — 14.08.2026, у «ИП Львова» — 12.08.2026; у ArtMaks, «Бамбука» и
  «Руспро» складов нет вообще, хотя ключи WB у селлеров есть.
- Диагностика на проде 09.10.2026 тем же запросом, что делает задача, без записи в базу:
  GET https://supplies-api.wildberries.ru/api/v1/warehouses отвечает 404 у всех фулфилментов
  (по ключу первого селлера), вторым ключом — 401. Поэтому список не обновляется с середины
  августа. Официальная документация WB (раздел «Поставки FBW») по-прежнему описывает этот путь —
  фактическую рабочую версию метода должен установить разработчик.
- Контейнеры celery_beat и celery_worker на проде запущены.

## 3. Требования (предварительно, аналитик уточняет)

R1. Раз в сутки WMS загружает склады WB для каждого фулфилмента с действующим ключом WB.
R2. Загрузка добавляет новые склады; уже загруженные склады не удаляются и не перезаписываются
(слова владельца: «не актуализировать, а просто новые загружать»).
R3. Склад, выбранный в существующих отгрузках FBO, остаётся доступным и показывается как раньше.
R4. Если WB не ответил или ключ одного селлера не подходит, это не останавливает загрузку
других фулфилментов, и следующий запуск снова пробует загрузить.

## 4. Решения и вопросы аналитику

1. Каким ключом загружать, если у первого селлера ключ не подходит (перебор селлеров
   фулфилмента) — решение аналитика.
2. Как вести себя при 404 — установить действующий метод WB до реализации.
