# WMS-556 · WMS-517: ограничить вывод КИЗ из оборота одним селлером AVpack

Запись задачи: [канонический бэклог, WMS-556](../KANONICHESKIY_BACKLOG.md#wms-556).
Связанная функциональность: [WMS-517](../KANONICHESKIY_BACKLOG.md#wms-517) — селлерский
реестр и локально подписанный вывод переданных WB FBS-КИЗ из оборота.

## 1. Исходный запрос и уточнения

Первоначальный запрос владельца:

> «Можем выкатить только для AV-пак каким-нибудь фичитогом, чтобы это только по нему
> заработало, исключительно на его фулфиллменте и стал, ну, активен этот процесс.»

Уточнение владельца, сузившее доступ с фулфилмента до одного селлера:

> «А, ну там у него привязан селлер, что-то горячкино что ли, типа. Там у этого селлера
> очки, палантины. Да вот мы сегодня вот в этом чате всё по нему делали, по товарам этого
> селлера. Вот, соответственно, там нужно ему только открыть. Можем этому селлеру только
> открыть.»

Последующее исправление владельца:

> «не шерин. Нет, не Шерин. У Vpak есть именно то ли горячкина, то ли горячего. Вот у него
> леггинсы, по-моему. Вот этот целер тоже.»

По production-данным идентифицирован точный адресат: **ИП Горячкина Т.И.**,
`seller_id=0b8da5d8-f43a-42f5-a2ec-43173ea844bd`, tenant AVpack
`d6e1ad21-8afa-4acf-8d0b-907b9f2adcfe`. Идентификация подтверждена по товарам
«Леггинсы со штрипками утягивающие спортивные». ИП Шерин И.М. и другие селлеры AVpack
не являются адресатами этой задачи.

Операционная граница постановки: задача готовит ограниченный rollout WMS-517, но не
разрешает и не выполняет реальный production-вывод КИЗ. До него отдельно требуются
проверка сертификата и сквозной прогон в sandbox True API, явное разрешение владельца
и включение существующего общего production-submit gate WMS-517.

## 2. Существующий процесс и цель изменения

В ветке `origin/codex/wms517-kiz-withdrawal-mockup` WMS-517 добавляет в seller-портал
маршрут `/seller/honest-sign/withdrawals`, вкладку «Вывод из оборота», same-origin API
`/operations/marking-codes/self/withdrawals` и фоновый Celery-процесс отправки и
восстановления. Проверка API сейчас ограничивает tenant, активного селлера, роль и право
`honest_sign`, но не содержит rollout-допуска конкретного селлера. Фоновый процесс
выбирает сохраняемые withdrawal-документы без такого допуска. Поэтому одно скрытие
вкладки оставило бы прямой API и воркер доступными вне требуемой границы.

Принятый экран и бизнес-процесс WMS-517 не перерабатываются. Цель WMS-556 — добавить
один доверенный серверный допуск, который одинаково закрывает интерфейс, все withdrawal
API и фоновую обработку для любого селлера, кроме явно разрешённого. По умолчанию список
пуст, поэтому сам факт выкладки кода не открывает функцию никому.

## 3. Требования

| № | Требование | Основание |
|---|---|---|
| R1 | Rollout-допуск WMS-517 задаётся доверенной серверной конфигурацией как список точных UUID селлеров. Значение по умолчанию — пустой список: при отсутствующей, пустой или невалидной конфигурации функция закрыта для всех. Имя «Горячкина», UUID целевого селлера и список разрешённых селлеров не хардкодятся в React-коде, клиентском bundle или пользовательском запросе. | Просьба владельца о feature toggle только для одного селлера; правило fail-closed. |
| R2 | При конфигурации production-кандидата единственная разрешённая запись — `seller_id=0b8da5d8-f43a-42f5-a2ec-43173ea844bd`. Доступ проверяется для effective seller текущей сессии внутри существующей tenant-границы; принадлежность целевого селлера tenant AVpack `d6e1ad21-8afa-4acf-8d0b-907b9f2adcfe` не позволяет открыть функцию другим селлерам этого tenant. ИП Шерин И.М. явно не допускается. | Последнее уточнение владельца и подтверждённая production-идентификация. |
| R3 | Для разрешённого effective seller существующий переход «Честный знак → Вывод из оборота», маршрут и экран WMS-517 доступны при сохранении действующих проверок роли и права `honest_sign`. Видимость перехода определяется ответом сервера о доступности текущего effective seller, а не локальным сравнением имени или UUID. Переключение активного селлера обновляет доступ без повторного входа. | Нужно открыть функцию только целевому привязанному селлеру; существующий active-seller процесс WMS. |
| R4 | Для любого неразрешённого effective seller переход не показывается. Прямое открытие URL не раскрывает реестр и возвращает штатный отказ в доступе. После отказа остальные страницы раздела «Честный знак» продолжают работать в прежнем объёме. | Скрытия UI недостаточно; требование открыть только одному селлеру. |
| R5 | Единая backend-проверка допуска выполняется до чтения или изменения withdrawal-данных на каждом endpoint WMS-517: реестр, товары, создание и чтение операции, retry, повторная авторизация, приём auth-подписи и подписей документов. Неразрешённый seller получает отказ до запросов True API и до создания/изменения withdrawal ledger; переданный клиентом seller ID, операция или подпись не могут расширить доступ. | Backend-enforced seller allowlist и существующая tenant/seller isolation WMS-517. |
| R6 | API, worker, beat и recovery используют одну и ту же server-trusted конфигурацию допуска. Фоновый процесс не claim-ит, не отправляет и не восстанавливает withdrawal-операции неразрешённых селлеров и не вызывает для них True API. Такие записи, если они появились в тесте или остались после изменения конфигурации, сохраняются без мутации для диагностики; они не переадресуются разрешённому селлеру. | Уточнение постановки: worker/recovery и реальная отправка недоступны другим seller; безопасная изоляция сохранённого состояния. |
| R7 | Seller allowlist — дополнительный gate и не заменяет общий gate среды WMS-517. При `withdrawal_environment=production` и выключенном `withdrawal_production_submit_enabled` ни разрешённый селлер, ни фоновые процессы не выполняют production auth/create submit. WMS-556 не меняет этот флаг, не включает production submit и не совершает реальный вывод КИЗ. | Явная граница текущей задачи и release gate WMS-517. |
| R8 | При включении целевого селлера сохраняется существующее поведение WMS-517: состав реестра только из переданных WB FBS-КИЗ, выбор, подпись, идемпотентность, ledger, polling/reconciliation и отображение результата. Новый gate не добавляет экранов, пояснений, статусов, таблиц или пользовательских шагов. | Владелец просит ограниченный rollout принятого процесса, а не его переработку. |
| R9 | Обычный раздел «Честный знак» — пулы, импорт, печать/перепечать и другие не-withdrawal действия — не зависит от нового allowlist и остаётся доступен по прежним ролям и правам всем соответствующим селлерам. Не изменяются WB/Ozon FBS, данные товаров, КИЗ и отгрузок. | Узкая граница задачи поверх WMS-517; отсутствие побочных блокировок. |
| R10 | Значение allowlist передаётся согласованно во все процессы, способные исполнять WMS-517 (API, Celery worker и beat/recovery). Различающаяся или невалидная конфигурация не должна приводить к открытию функции: соответствующий процесс остаётся fail-closed и не вызывает True API. | WMS-517 имеет отдельные API/worker/beat контуры; feature gate должен действовать одинаково. |

## 4. Решения и оставшиеся вопросы

Используется allowlist селлеров, а не tenant-флаг: владелец сначала назвал AVpack, затем
явно сузил адресата до одного привязанного селлера и отдельно исключил Шерина. Проверка
строится по UUID effective seller; отображаемое имя не является устойчивым идентификатором.

Конфигурация хранится только на сервере и по умолчанию пуста. Frontend получает лишь
результат допуска для текущего active seller и поэтому не содержит список клиентов.
Это позволяет тем же механизмом закрыть прямой URL и обновить навигацию при переключении
селлера, не создавая второго независимого источника правил.

Оставшихся продуктовых вопросов для реализации gate нет. Отдельно за границей WMS-556
остаются назначение sandbox participant, физическая проверка КриптоПро/ГОСТ/токена,
production-конфигурация True API и разрешение на первую реальную операцию.

## 6. Сверка перед передачей разработчику

- «Только для AVpack» покрыто существующей tenant-границей и R2, но более позднее
  уточнение «этому селлеру только» имеет приоритет и задаёт seller allowlist в R1–R6.
- «Не Шерин», «Горячкина», «леггинсы» покрыты точной подтверждённой идентификацией
  ИП Горячкина Т.И. и явным отрицательным сценарием C3.
- Feature toggle покрыт server-trusted, default-closed конфигурацией R1 и согласованным
  применением в UI/API/worker/beat R3–R6, R10.
- Требование не ограничиваться скрытием интерфейса покрыто общим backend gate R5,
  фоновым gate R6 и прямыми отрицательными проверками C1/C3/C6.
- Запрет на самовольный production withdrawal покрыт R7/C7. В документ не добавлено
  разрешение менять сертификаты, секреты, sandbox participant или production-флаг.
- Обратная сверка требований показывает, что R8–R9 только сохраняют принятую WMS-517
  и соседние процессы; новых бизнес-функций или пользовательских запретов не добавлено.

## 7. Заключение

Постановка подготовлена, реализация и приёмка ещё не проводились. До приёмки столбец
«Вердикт» намеренно оставлен пустым. WMS-556 не является разрешением на deployment или
production True API submit и не подтверждает физическую работу сертификата/КриптоПро.
