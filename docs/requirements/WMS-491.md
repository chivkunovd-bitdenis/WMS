# WMS-491 · Карточка селлера: реквизиты, выставленные счета, переходы к товарам и в «Расчёты»

Пакет PSP-2. Связанная задача: [WMS-547](WMS-547.md) — реквизиты селлера подтягиваются по API
площадки (владелец: «Это ну как бы отдельная да, часть задач»; документ WMS-547 лежит в ветке
`feat/wms547-seller-requisites-api`).

## 1. Исходный запрос и уточнения

### 1.1. Встреча 21.09.2026 (прежняя постановка)

Пункт 5 расшифровки встречи «PSP»: «быстрый переход из карточки клиента к его товарам».
Прежний документ (ветка `origin/codex/wms-psp-backlog-20260921`, `docs/requirements/WMS-491.md`):
R1 — в строке или карточке селлера есть явное действие перехода к его товарам; R2 — переход
открывает существующий каталог с применённым фильтром этого селлера; R3 — копия каталога или
отдельный экран под этот переход не создаётся. Эти требования сохраняются (ниже — R7, R9).

## 2. Существующий процесс и цель изменения

### 2.1. Кто и где

Администратор фулфилмента (роль `fulfillment_admin`) в разделе меню «Селлеры»
(`/app/ff/sellers`, `frontend/src/screens/v2/SellersScreen.tsx`). Раздел виден и открывается
только админу ФФ (`AuthedAppLayout.tsx`, маршрут в `App.tsx` под `isFulfillmentAdmin`).

### 2.2. Как сейчас (проверено по коду ветки от `origin/etalon` 141c9fb9; экран — см. 2.4)

- **Список селлеров.** Таблица: «Название», «Реквизиты для счетов» (краткая сводка: наименование,
  ИНН/КПП, банк/БИК/счёт или «Не заполнены»), «WB Marketplace» (статус ключа WB и время проверки),
  справа — кнопка «Реквизиты». Клик по строке ничего не открывает. Справа от таблицы — форма
  «Добавить селлера». Сводка реквизитов загружается запросом `GET /api/billing/profiles/sellers/{id}`
  по каждой строке.
- **Окно «Реквизиты»** (`frontend/src/screens/ff/FfBillingProfilesDialog.tsx`). Открывается кнопкой
  «Реквизиты». Поля: ИНН + кнопка «Заполнить по ИНН» (DaData), Наименование, КПП, Банк, БИК,
  Расчётный счёт, Корреспондентский счёт; «Сохранить» → `PUT /api/billing/profiles/sellers/{id}`
  (одна запись на селлера, таблица `billing_profiles`, изменения пишутся в журнал документа).
  Когда окну передан селлер, выбора «Чьи реквизиты» нет.
- **То же окно в «Расчётах».** На вкладке «Селлеры» раздела «Расчёты» есть своя кнопка
  «Реквизиты» с выбором «Чьи реквизиты»: «Наши — фулфилмент» или любой селлер. Реквизиты ФФ
  заполняются только там.
- **Выставленные счета.** «Расчёты» → вкладка «Выставленные счета»
  (`frontend/src/screens/ff/FfBillingInvoicesPanel.tsx`): таблица «Номер», «Селлер», «Период»,
  «Выставлен», «Сумма», «Статус», действие открытия; фильтры «Селлер», «Статус», поиск по номеру;
  данные — `GET /api/billing/invoices-v2?seller_id=…&status=…` (старые и новые счета вместе).
  Открытый счёт — окно с реквизитами получателя/плательщика, строками, печатью и отменой.
- **Каталог ФФ** (`/app/ff/products`, `frontend/src/screens/v2/FfProductsCatalogScreen.tsx`, пункт меню
  «Каталог»). Фильтр «Селлер» — выпадающий список «Все селлеры» / селлеры; состояние живёт только
  внутри экрана и при открытии всегда «Все селлеры». Адрес страницы фильтр не задаёт. Прецедент
  чтения параметра адреса на этом экране уже есть: `?fbs_limit=<id>` открывает окно остатка.
- **«Расчёты»** (`/app/ff/billing`, `frontend/src/screens/ff/FfBillingScreen.tsx`). Вкладка «Селлеры»:
  период (по умолчанию «сегодня» по Москве) + быстрые периоды, фильтр «Селлер» (по умолчанию
  «Все селлеры»), метрики, кнопки «Реквизиты» и «Выставить счёт», таблица селлеров с раскрытием
  документов. Фильтр из адреса не читается. Счёт выставляется существующим путём: раскрыть
  селлера, отметить документы → «Выставить счёт»; без отметок — ручной счёт.
- **Детальные страницы по адресу уже есть**, например карточка товара ЧЗ
  `/app/ff/honest-sign/product/:productId` (`HonestSignProductPage.tsx`): стрелка «Назад к списку»
  и заголовок. Отдельной карточки селлера нет.
- **Данные о селлере**, которые уже приходят с `GET /api/sellers`: `name`, `wb_has_key`,
  `wb_marketplace_scope_ok`, `wb_marketplace_scope_checked_at`, `ozon_connected`.

### 2.3. Что должен получить пользователь

Админ ФФ кликает по селлеру и попадает в его карточку: видит, что это за селлер, его реквизиты
и выставленные ему счета; из карточки одной кнопкой правит реквизиты, одной кнопкой попадает
в каталог, уже отфильтрованный по этому селлеру, и одной кнопкой — в «Расчёты», уже отфильтрованные
по нему, чтобы выставить счёт. Кнопки «Реквизиты» в списке селлеров больше нет.

### 2.4. Что посмотрено глазами

Экраны «Селлеры», окно «Реквизиты», «Каталог» и «Расчёты» открыты на стенде — раздел 9.
Код и экран совпадают: фильтр селлера в «Каталоге» и «Расчётах» адресом не задаётся.

## 3. Решения аналитика (навык принятия решения)

Прочитаны [owner-cases.md](../reviews/2026-09-11-analyst-draft/owner-cases.md) (главное для этой задачи —
«Плохой случай 1»: действие должно жить в контексте своего документа) и
[failure-cases.md](../reviews/2026-09-11-analyst-draft/failure-cases.md) (B05 — ошибка сохранения видна
в самом окне, введённое не теряется). Эталоны интерфейса — «Расчёты» (отчёты, таблицы) и «Ячейки»
(структуры); компоненты — существующий `ui-kit`.

**РА1. Карточка — отдельная страница по адресу `/app/ff/sellers/<id>`, а не всплывающее окно.**
Из карточки два перехода в другие разделы («Товары», «Выставить счёт»); со страницы кнопка браузера
«Назад» возвращает в карточку, а окно при переходе просто закрылось бы. Счёт и реквизиты внутри
открываются существующими окнами — со страницы они не ложатся «окно на окно». Образец детальной
страницы в приложении уже есть (карточка товара ЧЗ: стрелка назад + заголовок). Слова владельца
«карточка кликабельна, она открывается» этому не противоречат. Если ведущий по WMS-490 выберет для
карточки товара другую форму, формы двух карточек нужно выровнять — ведущему свести.

**РА2. «Товары» открывает каталог в той же вкладке браузера, обычной ссылкой.** Владелец сначала
сказал «открывается новая вкладка», сразу отменил весь этот вариант («Сейчас, нет, даже не так»),
а в итоговой версии говорит «мы переходим в каталог» и «у нас открывается наш каталог». Вторая кнопка
карточки по его же словам «перекидывает» в «Расчёты» — две кнопки ведут себя одинаково. Ссылка
обычная: открыть в новой вкладке браузера можно штатно (Cmd/Ctrl-клик, средняя кнопка), а «Назад»
возвращает в карточку. Бизнес-результат (открыт каталог с фильтром селлера) одинаков, поэтому
вопрос владельцу не задаётся.

**РА3. Фильтр передаётся адресом.** Каталог открывается как `/app/ff/products?seller_id=<id>`,
«Расчёты» — как `/app/ff/billing?seller_id=<id>`. Экраны при открытии по такой ссылке выставляют
**свой существующий** выпадающий список «Селлер» на этого селлера. Копии каталога или «Расчётов»
не создаётся (прежний R3 от 21.09). Обычное открытие из меню — как раньше, «Все селлеры».

**РА4. «Выставить счёт» только применяет фильтр селлера на вкладке «Селлеры» «Расчётов».**
Период, раскрытие строк и сам путь выставления счёта не меняются — владелец сказал ровно
«где уже применён фильтр по этому селлеру». Кнопку не превращаем в отдельное выставление счёта
из карточки: счёт собирается из документов, а документы живут в «Расчётах».

**РА5. Реквизиты в карточке: значения видны сразу, правка — той же кнопкой «Реквизиты».**
Владелец: «там написаны его реквизиты» и «кнопка реквизиты пропадает, она переезжает туда».
Значит, в карточке показываем сохранённые реквизиты, а кнопка «Реквизиты» (та же, что была в строке)
открывает то же окно этого селлера. Форму не перерисовываем и не дублируем. В «Расчётах» кнопка
«Реквизиты» остаётся: там же заполняются реквизиты самого фулфилмента, владелец её не трогал.

**РА6. «Что за селлер» — только уже существующие данные.** Название (заголовок карточки), статус
WB (тот же текст, что в колонке «WB Marketplace» списка) и подключён ли Ozon. Новых сведений о селлере
не заводим. Что ещё владелец имел в виду под «какая-то там по нему информация» — вопрос В1 ниже;
по умолчанию больше ничего.

**РА7. Выставленные счета — тот же список счетов из «Расчётов», закреплённый за этим селлером.**
Переиспользуется `FfBillingInvoicesPanel`: без выбора селлера и без колонки «Селлер» (селлер один),
остальное как в «Расчётах» — статус, поиск по номеру, открытие счёта в том же окне с печатью и
отменой. В пустом списке — только «Счета ещё не выставлены», без подсказки про вкладку «Селлеры»
(в карточке она сбивает с толку, а подсказки владелец запретил).

**РА8. В списке «Селлеры» меняется только то, что сказал владелец:** исчезает кнопка «Реквизиты»,
строка становится кликабельной. Колонки, сводка реквизитов в строке и форма «Добавить селлера»
остаются как есть.
