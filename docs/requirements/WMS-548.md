## 1. Исходный запрос и уточнения

### 1.1. Встреча 21.09.2026, пункт 3

Из прежней постановки (расшифровка встречи в репозиторий не добавлялась):
«выбор актуальных товаров при первоначальной загрузке». Тогда осталось открытым, что считать
«актуальным» и как потом включить отложенный товар. Диктовка 27.09 отвечает на оба вопроса:
актуальные — те, что селлер сам отметил; включить потом — кнопкой «Добавить к фулфилменту» в каталоге.

То есть если у него 15 тысяч карточек, а он торгует 500 только и будет грузить из них там 100 условно, да, то он эти 100 просто выберет. нажмет типа и все и после этого мы синхронизацию запустим только по этим товарам на фулфилменте отображаются только эти товары больше там соответственно ничего нету и остальные товары просто не отображаются. То есть у фулфилмента отображается не все его товары, только те, которые выбраны, в принципе, с ними во всех процессах участвуют только выбранные товары, да? Приезжают на фулфилмент. ## 2. Как это работает сейчас и что должно получиться

Всё ниже проверено чтением кода `origin/etalon` 141c9fb9 (ветка задачи создана от него), если не
сказано иное. Что из этого видел на экране — отдельный абзац «Что видел глазами» ниже.

**Кто и где вводит ключи.** Самостоятельной регистрации селлера в системе нет: учётку селлера
заводит фулфилмент (POST /auth/seller-accounts), селлер получает приглашение и задаёт пароль.
Поэтому «при регистрации» на деле означает первый ввод ключа. Селлер вводит его в портале:
«Настройки» → блок «Wildberries» → «Добавить ключ» → окно «WB API ключ» → «Сохранить»; рядом блок
«Ozon» с полями Client-Id и Api-Key. У фулфилмента WB-ключи селлера можно сохранить на старом
техническом экране /app/integrations/wb, которого нет в меню (проверено по коду меню
AuthedAppLayout); Ozon-ключи за селлера фулфилмент в интерфейсе не вводит.

**Что происходит с каталогом WB сейчас.** Сохранение ключа (POST /integrations/wildberries/self/content-token)
в одном запросе скачивает все карточки кабинета, пишет их снимок в таблицу seller_wildberries_imported_cards
(по строке на карточку, с полным JSON: фото, размеры, ШК, категория) и тут же заводит товар WMS на каждый
размер каждой карточки (upsert_products_from_wb_cards). Если проверка ключа не прошла (например, нет
прав «Маркетплейс»), ни снимок, ни товары не пишутся. То же самое делают кнопки «Синхронизировать по API»
в каталоге селлера и «Синхронизировать товары» в настройках (POST /self/sync-products) и ежечасный проход
(Celery «wb-catalog-hourly», минута 17, run_wb_products_sync_all_sellers — по всем селлерам с ключом).
Новая карточка, которую селлер завёл на WB, сама появляется у фулфилмента в течение часа. Фоновая задача
«wildberries_cards_sync» (кнопка «Обновить карточки» на техническом экране ФФ) пишет только снимок, товары
не заводит.

**Что происходит с каталогом Ozon сейчас.** Сохранение ключей (PUT /integrations/ozon/self/account)
сразу импортирует все карточки кабинета (import_ozon_product_cards): карточка привязывается к уже
существующему товару (по ШК, по артикулу, по формуле «OZ + nmID + артикул»), а не найденная — заводится
новым товаром; неоднозначные не трогаются. Снимка карточек Ozon в системе нет, периодического импорта
Ozon нет, кнопки ручной синхронизации Ozon в интерфейсе селлера нет (сам API /integrations/ozon/self/sync-products есть).

**Каталоги.** Каталог ФФ (GET /products/ff-catalog-page) и каталог селлера (GET /products/wb-catalog)
показывают товары WMS — строки таблицы products; фото, категорию и ШК подтягивают из снимка. Каталог ФФ
листается постранично на сервере, каталог селлера грузится целиком и фильтруется в браузере.

**Процессы.** Приёмка, FBS, остатки и их передача на площадки, инвентаризация, отгрузки, Честный знак
работают только с товарами WMS. Товары WMS создаются ровно в четырёх местах: импорт WB, импорт Ozon,
ручное создание фулфилментом и загрузка ТЗ из Excel (поиск по коду всех мест создания Product).
Снимок карточек WB читается только для фото и категории уже заведённых товаров и заказов.

**FBS-заказ на товар, которого нет в WMS.** Такой заказ WB с обслуживаемого склада всё равно попадает
в список FBS: mapping_status = missing, резерв не ставится, в рабочем списке — причина «Товар не
сопоставлен с карточкой», в поставку его не добавить. Когда товар появляется, заказ сопоставляется при
следующем обмене (повторная обработка строки заказа, _apply_wb_row_to_existing; лента новых заказов
и обход за 30 дней). Для Ozon — то же по позициям отправления.

**Масштаб.** По документу WMS-538 у ArtMaks 55 313 товаров после импорта 55 тысяч карточек одного селлера
(ООО «Фабрика»); полный каталог ФФ без фильтра теперь отвечает отказом 413 при числе товаров больше 20 000,
из-за чего в инвентаризации пустое «Добавить товар» (WMS-545). Сам я боевую базу не читал: прод по вводной
пакета не трогаем.

**Что видел глазами 27.09** (общий стенд пакета на etalon 141c9fb9, Playwright headless, только просмотр,
ключи на общем стенде не сохранял). Портал селлера, «Товары»: полоса действий «Синхронизировать по API»
и «Включить ЧЗ», ряд фильтров (поиск, «Категория», «Найдено: 9 из 9»), таблица «Фото, Название, Артикул
продавца, SKU, ШК, Размер, Остаток, ТЗ, ЧЗ, Резервы» с чекбоксами и пагинацией «На странице 10»; значков
площадки в строках нет. «Настройки»: блок «Wildberries» с «Ключ: не добавлен», «WB товары: —», кнопками
«Добавить ключ» и «Синхронизировать товары»; окно «WB API ключ» с одним полем и «Сохранить»; блок «Ozon»
с полями Client-Id, Api-Key и «Подключить». Каталог ФФ: ряд фильтров «Селлер», «Маркетплейс», «Передача
остатков», «Категория», «Найдено: 13 из 13», в колонке артикула — значки «Wildberries»/«Ozon». Меню ФФ
пункта интеграций не содержит; по прямому адресу /app/integrations/wb открывается технический экран
«Wildberries» с сохранением токенов селлера и списком «Импортированные карточки». Путь «сохранить ключ →
товары появились» глазами не проходил: для этого нужна заглушка WB, на общем стенде её нет.

**Что должно получиться.** Селлер при первом подключении отмечает, какие товары поедут на фулфилмент.
У фулфилмента появляются и участвуют во всех процессах только они. Селлер у себя видит весь свой каталог
и в любой момент может отметить ещё товары и нажать «Добавить к фулфилменту».

## 3. Решения аналитика

Каждое решение принято по навыку продуктового решения: в рамках запроса, привычным для пользователя
способом, без новых сущностей там, где хватает существующих.

**А1. «Не загружаем» и «у селлера виден весь каталог».** Противоречие снимается тем, что в системе уже
есть два разных слоя: снимок карточек WB (список всего кабинета селлера, который и сейчас хранится целиком)
и товары WMS (то, с чем работает склад). «Не загружаем, не работаем» относится ко второму слою: невыбранная
карточка не становится товаром WMS, поэтому её нет ни в одном экране и процессе фулфилмента. Первый слой
остаётся и служит только для того, чтобы селлер видел свой каталог и мог выбрать. Новой таблицы для WB
не нужно.

**А2. Что именно выбирает селлер.** Владелец говорит о карточках: «если у него 15 тысяч карточек …
эти 100 просто выберет». Единица выбора WB — карточка (nmID) целиком, со всеми её размерами; у фулфилмента
она превращается в товары по размерам, как сейчас. Новый размер у выбранной карточки заводится при
синхронизации сам. Для Ozon единица выбора — карточка товара Ozon.

**А3. Где хранится выбор.** Отдельного флага, статуса или журнала нет. Карточка WB «на фулфилменте», если
у этого селлера есть хотя бы один товар WMS с её nmID; карточка Ozon — если у неё есть действующая привязка
к товару WMS. Так выбор не расходится с фактом: второго независимого источника нет (правило AGENTS.md
о вычисляемых величинах), и данные уже подключённых селлеров не требуют миграции.

**А4. Уже подключённые селлеры, в том числе крупные.** Ничего не удаляется и не скрывается: снятие товаров
владелец отменил. Всё уже загруженное считается выбранным и работает как раньше. Меняется одно: новые
карточки, которые такой селлер заведёт на WB, больше не приезжают на фулфилмент сами — только через
«Добавить к фулфилменту». Это прямо следует из «синхронизацию запустим только по этим товарам», но меняет
привычное поведение, поэтому вынесено вопросом В1 с этим решением по умолчанию. У ArtMaks каталог
не уменьшится; задача останавливает рост, а не чистит уже загруженное.

**А5. FBS-заказ на невыбранный товар.** Оставляем существующее поведение: заказ виден в FBS с причиной
«Товар не сопоставлен с карточкой», после «Добавить к фулфилменту» сопоставляется при следующем обмене.
Прятать такой заказ нельзя: это реальный заказ покупателя, и молча его потерять дороже, чем показать.
Новой блокировки не вводим.

**А6. Ozon.** Правило то же: «когда вводит API-ключ» относится к любому ключу площадки, а при старом импорте
Ozon все карточки кабинета стали бы товарами фулфилмента — это нарушило бы главное требование. Импорт Ozon
продолжает привязывать карточку к товару, который уже на фулфилменте (это та же физическая вещь, одна
объединённая карточка), но новые товары заводит только для выбранных карточек. Чтобы селлер видел карточки
Ozon, которых нет на фулфилменте, и мог добавить их без повторного обхода всего кабинета, нужен снимок
карточек Ozon — **новая таблица**, по образцу снимка WB. Существующие таблицы для этого не подходят:
привязка Ozon (product_marketplace_links) не бывает без товара WMS, а снимок WB устроен вокруг nmID.
Категорий Ozon у нас нет (импорт их не получает), поэтому фильтр по категории работает только по карточкам WB.

**А7. Ключ вводит фулфилмент за селлера.** Фулфилмент может сохранить WB-ключ на техническом экране
не из меню; товары при этом и сейчас не заводятся. После изменения ежечасный проход тоже ничего не заведёт,
пока селлер не выберет товары в своём портале: выбирает селлер, как сказано в диктовке. Экран ФФ не меняем,
кнопку «выбрать за селлера» не добавляем. Вопрос В2 — на случай, если есть селлеры, которые в портал
не заходят. Технический экран ФФ продолжает показывать список карточек WB селлера (nmID и артикул) —
это служебная страница для привязки, в меню её нет, в этой задаче не меняется.

**А8. Большие каталоги и отказ 413.** Окно выбора и каталог селлера листаются постранично на сервере,
поиск и фильтр тоже на сервере — полного списка в браузер не грузим (урок WMS-538). Сохранение ключа
больше не заводит десятки тысяч товаров в одном запросе, а добавление большой выборки идёт порциями,
каждая порция сохраняется сама, поэтому обрыв на середине не теряет уже добавленное и не создаёт дублей
при повторе. WMS-545 (пустое «Добавить товар» у ArtMaks) этой задачей не закрывается.

**А9. Когда открывается окно выбора.** Сразу после успешного сохранения ключа площадки, если до этого ключа
этой площадки у селлера не было и карточки получены. При замене ключа окно не открывается — добавлять
дальше селлер будет в каталоге. Закрыл окно, ничего не выбрав, — у фулфилмента пусто, всё можно добавить
из каталога.

**А10. Где кнопка «Добавить к фулфилменту».** В окне выбора — это его единственное действие. В каталоге
селлера — в существующей полосе «Выбрано N» над таблицей, рядом с «Задать остаток»: действие относится
к отмеченным строкам, там же, где и остальные действия над выбором. Чтобы среди тысяч карточек найти ещё
не добавленные, в существующий ряд фильтров добавляется один выпадающий фильтр «Фулфилмент»
(«Все товары» / «На фулфилменте» / «Не на фулфилменте») в том же виде, что фильтр «Передача остатков»
у фулфилмента. По умолчанию — «Все товары»: «у селлера отображается весь его каталог».

**А11. Права.** Выбор и добавление — у пользователя селлера с правом «Товары» (то же право, что открывает
каталог), в границах текущего магазина по существующим правилам переключения магазинов. Фулфилмент этим
действием не пользуется.

## 4. Требования

**R1. Окно выбора после первого ключа.** Условие: селлер в портале «Настройки» сохраняет ключ WB
(или ключи Ozon), ключа этой площадки у селлера до этого не было, проверка прошла и карточки получены.
Результат: сразу открывается большое окно со списком карточек этой площадки. При замене ключа, при
неуспешной проверке и при нуле полученных карточек окно не открывается, сообщения настроек — как сейчас.
Основание: «когда вводит API-ключ, первым делом … должна вылезти большая модалка»; решение А9.

**R2. Вид и поиск в окне.** Окно выглядит как наш стандартный каталог: фото, название, артикул продавца,
ШК, размеры, отметка площадки существующим значком. У каждой строки — чекбокс. Есть поисковая строка,
которая находит карточку по артикулу продавца, по любому ШК любого её размера и по части названия,
и фильтр по категориям. Список листается постранично; найденное количество видно. Можно отметить все
карточки на странице и все найденные текущим фильтром — включая «все вообще». Карточки, которые уже на
фулфилменте (для Ozon — привязанные к товарам на ФФ), показаны отмеченными и недоступными для снятия.
Основание: «модалка с нашим каталогом стандартным … чекбокс … может все, может не все … фильтр по
категориям, поиск по артикулу, по ШК, по названию».

**R3. «Добавить к фулфилменту» в окне.** Селлер отмечает карточки и нажимает «Добавить к фулфилменту».
Каждая отмеченная карточка WB становится товарами WMS по всем её размерам — с теми же названиями,
артикулами, ШК, габаритами, что заводит сегодняшний импорт; карточка Ozon — товаром с привязкой Ozon
(или только привязкой, если такой товар на ФФ уже есть). Неотмеченные товарами не становятся. Окно
закрывается; при повторном открытии каталога селлера добавленные видны как товары на фулфилменте.
Основание: «он эти 100 просто выберет. нажмет … и все»; решения А2, А3.

**R4. Ключ сам не заводит товары.** Сохранение ключа WB и ключей Ozon обновляет список карточек селлера,
но не создаёт ни одного товара WMS для карточек, которых нет на фулфилменте. Основание: «мы их не
загружаем, мы с ними не работаем».

**R5. Синхронизация — только по выбранным.** Ежечасная синхронизация WB и ручная («Синхронизировать по API»,
«Синхронизировать товары») обновляют список всех карточек селлера, обновляют товары WMS только тех карточек,
которые уже на фулфилменте, заводят новые размеры у этих карточек и не заводят товары для остальных карточек,
включая новые, появившиеся на WB. Основание: «после этого мы синхронизацию запустим только по этим товарам»;
решения А1, А2.

**R6. У фулфилмента — только выбранные.** Карточки не на фулфилменте не видны ни в одном экране фулфилмента
(каталог, приёмка, сортировка, FBS-остатки и «Задать остаток», инвентаризация и её «Добавить товар»,
отгрузки на МП, Честный знак, отчёты) и не участвуют ни в одном процессе: их ШК при сканировании не находятся,
остаток по ним не передаётся. Основание: «на фулфилменте отображаются только эти товары больше там
соответственно ничего нету … с ними во всех процессах участвуют только выбранные товары».

**R7. У селлера — весь каталог.** В разделе «Товары» портала селлера видны все карточки селлера по обеим
подключённым площадкам: товары на фулфилменте — как сейчас, со всеми колонками и действиями; карточки не на
фулфилменте — строками с фото, названием, артикулом, ШК, размерами и значком площадки, без остатка, ТЗ, ЧЗ,
резервов и действий над ними. Поиск, фильтр по категориям и новый фильтр «Фулфилмент» работают по всему
каталогу; каталог листается постранично. Основание: «у селлера отображается весь его каталог»; решения А8, А10.

**R8. «Добавить к фулфилменту» в каталоге селлера.** Селлер отмечает строки карточек не на фулфилменте
и в полосе «Выбрано N» нажимает «Добавить к фулфилменту». Результат тот же, что в R3: карточки становятся
товарами WMS, появляются в каталоге фулфилмента и с ними можно работать во всех процессах; у селлера эти
строки после обновления — товары на фулфилменте. Отмеченные строки, которые уже на фулфилменте, этим действием
не меняются; «Задать остаток» и «Включить ЧЗ» по-прежнему действуют только на товары на фулфилменте.
Основание: «в каталоге выбрать еще некоторые товары и нажать кнопкой … к фулфилменту … появляются в каталоге
у фула. И с ними там уже … можно работать».

**R9. Повтор, одновременность и сбой при добавлении.** Повторное нажатие или повтор того же запроса не создаёт
второй комплект товаров; два одновременных добавления одной карточки (две вкладки) дают один комплект.
Большая выборка добавляется порциями: если порция не прошла, уже добавленное остаётся на фулфилменте,
отметка у недобавленных сохраняется, повтор добавляет оставшееся. Карточку, которую завести нельзя
(нет размеров и ШК, конфликт артикула), система пропускает, добавляет остальные и показывает селлеру
артикулы недобавленных. Основание: правила AGENTS.md о повторах и частичном сохранении; решение А8.

**R10. Уже подключённые селлеры.** После выкладки у каждого селлера все уже заведённые товары остаются у
фулфилмента с прежними остатками, резервами, ячейками, ЧЗ и правилами передачи остатков; у селлера они
видны как товары на фулфилменте; синхронизация обновляет их как раньше. Никакие данные не удаляются
и не скрываются. Основание: отмена «Не отображать»; решение А4, вопрос В1.

**R11. FBS-заказ на карточку не на фулфилменте.** Поведение не меняется: заказ виден у фулфилмента в FBS
с причиной «Товар не сопоставлен с карточкой» и в поставку не добавляется, как сегодня; после того как
селлер добавил карточку к фулфилменту, заказ сопоставляется с товаром при следующем обмене с площадкой.
Основание: решение А5.

**R12. Ozon по тому же правилу.** Сохранение ключей Ozon и синхронизация Ozon привязывают карточки Ozon
к товарам, которые уже на фулфилменте, и не заводят новых товаров для остальных карточек; все карточки Ozon
селлера доступны ему в окне выбора и в каталоге и добавляются так же, как карточки WB. Кнопка
«Синхронизировать по API» в каталоге селлера обновляет список карточек каждой подключённой площадки —
и WB, и Ozon. Основание: решение А6.

**R13. Объединённая карточка при добавлении.** Если у добавляемой карточки WB есть двойник Ozon в списке
карточек Ozon селлера (совпадение по существующим правилам привязки импорта Ozon), после добавления товар
на фулфилменте сразу привязан к этой карточке Ozon, и в каталоге селлера двойник больше не висит отдельной
строкой «не на фулфилменте». Основание: решение А6; одобренный владельцем принцип «один физический товар —
одна карточка и общий остаток» (библиотека случаев, хороший случай 1).

**R14. Изоляция.** Селлер видит в окне и каталоге и добавляет к фулфилменту только карточки своего текущего
магазина. Идентификатор чужой карточки (другой селлер того же фулфилмента, другой фулфилмент) в запросе
ничего не создаёт и ничего не раскрывает. Пользователь селлера без права «Товары» не видит список и не может
добавлять; фулфилмент получает отказ на действие добавления. Основание: AGENTS.md «соблюдай права доступа
и границы клиентов»; решение А11.

**R15. Большие каталоги.** У селлера с 15 000 карточек сохранение ключа завершается, окно выбора открывается,
поиск по ШК находит карточку, «выбрать все найденные» и «Добавить к фулфилменту» добавляют всё выбранное;
ни один из этих шагов не отвечает отказом 413 и не останавливает сервер для других пользователей.
Основание: пример владельца «15 тысяч карточек»; авария WMS-538; решение А8.

**R16. Без лишнего в интерфейсе.** Окно и изменения каталога селлера собраны из существующих компонентов
и темы (таблица, фильтры, полоса «Выбрано N», пагинация, значок площадки, фото товара). Нет пояснительных
текстов, подсказок, новых чипов и надписей; нет кнопок снятия или скрытия товаров; экраны фулфилмента
не меняются. Основание: «строго не пиши ничего лишнего …»; отмена «Не отображать».

## 5. Вопросы владельцу (работа идёт с решением по умолчанию)

**В1. Уже подключённые селлеры.** Всё, что у них уже загружено (у ArtMaks — все 55 тысяч товаров
«Фабрики»), остаётся у фулфилмента как выбранное. Но новые карточки, которые такой селлер заведёт на WB,
больше не будут сами приезжать на фулфилмент — только если селлер нажмёт «Добавить к фулфилменту».
Так и оставляем?
*По умолчанию: да, так (R5, R10).*

**В2. Селлер, который в портал не заходит.** Если ключ WB за селлера вносит сам фулфилмент, товары у фулфилмента
появятся только после того, как селлер отметит их в своём портале. Нужно ли фулфилменту уметь отметить
товары за такого селлера?
*По умолчанию: нет, выбирает только селлер (А7).*

## 7. План реализации (разработчики — Sonnet)

Каждый кусок — своя ветка от `feat/wms548-catalog-selection` (например feat/wms548-d1-wb-sync) в своём worktree

Контракт API для параллельной работы фронта (D4, D5) с бэком (D2, D3):

- GET /seller-catalog/page — параметры search, category, on_fulfillment (all | yes | no),
  marketplace (wildberries | ozon, необязательно), limit (1…200), offset. Ответ: items, total, scope_total,
  categories. Строка: key (product:<uuid> / wb:<nmID> / ozon:<id товара Ozon>), on_fulfillment, marketplace;
  для товара на ФФ — поля сегодняшней строки /products/wb-catalog; для карточки не на ФФ — nm_id или
  ozon_product_id, vendor_code (артикул продавца / offer_id), name, photo_url, barcodes (все ШК всех размеров),
  sizes, category.
- GET /seller-catalog/keys — те же фильтры, ответ — список key всех найденных (для «выбрать все найденные»).
- POST /seller-catalog/add-to-fulfillment — тело { wb_nm_ids: [...], ozon_product_ids: [...] },
  не больше 500 идентификаторов за запрос. Ответ: added (площадка, идентификатор, артикул, сколько товаров
  заведено) и skipped (площадка, идентификатор, артикул, причина).
- Доступ: как у GET /products/wb-catalog — роль селлера, право «Товары», текущий магазин по
  get_effective_seller_id и user_can_manage_seller_shops; фулфилмент — 403.
