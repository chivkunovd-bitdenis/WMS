# WMS-565 · Короба приёмки: INB-код вместо «КР-00000N» у всех, кроме «Империи ФФ»; окно наполнения короба шире

## Исходный запрос

28.09.2026, владелец, после проверки сортировки на стенде («Короб КР-000001»): «он должен быть как inb». И про окно наполнения короба, где правые колонки обрезаны: «вот это надо точечно тоже поправить быстро прям на проде - без скиллов - чтобы было нормально видно».

## Контекст

WMS-564 (выкачен 28.09, 3ca5dd9a) по просьбе «именно для империи львов вернуть» сделал правило по виду кода: любой системный INB-код подписывается «КР-00000N» / «Короб № N». С сегодняшнего дня ArtMaks создаёт короба в WMS сам (приёмка №000007 очищена от импортных коробов), у них системные INB-коды и этикетка с этим кодом — правило WMS-564 подменяло им код на «КР-». Окно «Наполнить короб» было ограничено 960 px, а колонки таблицы шире — «Всего принято»/«Заявлено» и «В коробе» уезжали за край.

## Требования

- R1. Подпись «КР-00000N» (карта, сортировка, путь тары, подпись при скане тары) и «Короб № N» (экран приёмки: строка короба, чекбокс, окно наполнения, этикетка, сборка палеты) для системного INB-кода — только у «Империи ФФ». У остальных арендаторов — сам код короба. Внешние коды (WB_…) — как есть у всех.
- R2. Окно «Наполнить короб» приёмки на экранах от 1200 px показывает все колонки без прокрутки вбок. Окно короба отгрузки не меняется.
- R3. Сканирование, штрихкоды, остатки и другие данные не меняются.

## Заключение

Сделано ведущим без аналитика и ревью по указанию владельца. «Империя ФФ» определяется по идентификатору арендатора в box_barcode_service.NUMBERED_INBOUND_BOX_LABEL_TENANTS; фронт получает признак numbered_inbound_box_labels в профиле. На экранах уже 1024–1199 px таблица окна по-прежнему прокручивается вбок.
