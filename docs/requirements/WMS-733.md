# WMS-733: «ШК + ЧЗ» в упаковке FBO считает по подобранному

## Исходный запрос

09.10.2026 при проверке WMS-686 для инструкции АртМакса найдено расхождение с WMS-686 R51:
кнопка «ШК + ЧЗ» на вкладке «Упаковка» отгрузки FBO печатает N этикеток ШК, где N должно быть
подобранным количеством S (сумма подборов), а при S = 0 — планом P; ЧЗ выдаются только
недостающие N − K. Фактически N бралось из lines[].picked_qty детального ответа, а сервер
кладёт туда количество, уже уложенное в короба. Пример на локальном стенде той же версии:
план 4, подобрано 4, в коробе 1, привязан 1 КИЗ — напечатан 1 ШК, ЧЗ не выданы
(ожидалось 4 ШК и 3 ЧЗ). Владелец: «это надо поправить».

## Требования

| ID | Требование |
|---|---|
| R1 | Для строк общей таблицы упаковки FBO «подобрано» (S) считается суммой pick_allocations товара из детального ответа отгрузки; lines[].picked_qty используется только если pick_allocations в ответе нет. |
| R2 | Правило «ШК + ЧЗ» WMS-686 R51 не меняется: N = S при S > 0, иначе P; выдача ЧЗ — N − K. Смысл поля picked_qty в API и поведение других экранов и ТСД не меняются. |
