# WMS-668 · Telegram-диспетчер должен объединять соседние сообщения одного чата

Источник: живая очередь локального Telegram-бота 05.10.2026 после первого выпуска
WMS-664 и прямое поручение владельца дочинить бота.

## Фактический сбой

Два последовательных сообщения владельца попали в одну пачку маршрутизации. Модель
объединила их в одну новую тему и назвала её по идентификатору второго сообщения.
Проверка первого события сочла такой идентификатор чужим, откатила всю пачку и
оставила 59 событий в очереди. После защитной задержки бот продолжал один платный
повтор каждые десять минут.

## Требования

R1. Несколько входных событий одной текущей пачки и одного чата могут быть направлены
в одну новую тему, названную по любому входному событию этой пачки из того же чата.

R2. Идентификатор сообщения из другого чата, старого события вне текущей пачки или
несуществующего сообщения не может открыть новую тему.

R3. Формат нового идентификатора остаётся ограниченным: `topic-<source_id>` либо
`topic-<source_id>-N`, где `N` от 1 до 8.

R4. Сохранённая очередь должна пройти после установки без ручного удаления событий.
Успешная маршрутизация удаляет retry-state. После опустошения очереди не должно быть
новых модельных повторов или неотправленных сообщений.

R5. Исправление устанавливается в локальный LaunchAgent только из проверенного SHA.
Это не продуктовый deploy WMS и не меняет складские данные.

## Заключение

Сбой воспроизведён на сохранённой очереди. Автоматический контракт будет зафиксирован
отдельным коммитом до реализации; итоговый вердикт заполняется после установки и
повторной проверки живого состояния.
