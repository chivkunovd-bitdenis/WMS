# WMS-598 — фактический штрихкод в таблице инвентаризации

## Исходный запрос и границы

30.09.2026 владелец сообщил о срочном производственном дефекте: в таблице
инвентаризации пустая колонка штрихкода, хотя у товара есть реальный код. Поручено
сделать минимальный самостоятельный hotfix без зависимости от незавершённого WMS-593,
без косметических изменений. Владелец поручил срочно выпустить исправление на production.
Исполнитель подготовил код; координатор отвечает за независимое ревью и выпуск.
Навыки и отдельная формальная аналитическая цепочка отменены прямым указанием владельца.

Диагностика показала два звена дефекта. Backend заполнял универсальное поле `barcode`
только из `Product.wb_barcode`, поэтому не видел дополнительные коды WB и коды Ozon.
Frontend при этом выводил в колонке «ШК» только WB-специфичное поле `wb_barcode`,
игнорируя универсальное поле.

## Требования

| ID | Требование |
|---|---|
| R1 | В дереве документа и в его плоском списке строк показывать фактический код с приоритетом: непустой основной WB-код, затем известный WB-алиас, затем первый непустой код активной Ozon-привязки. |
| R2 | Если фактического кода нет, колонка остаётся пустой. SKU, offer ID и другие артикулы не выдаются за штрихкод. |
| R3 | Колонка «ШК» использует универсальный `barcode`, сохраняя старое `wb_barcode` отдельным WB-специфичным значением и совместимым запасным источником для прежних ответов API. |
| R4 | Поиск кодов выполняется пакетно и только внутри tenant документа; запрос на каждую строку не допускается. |
| R5 | Товар, добавленный в открытый документ как находка, сразу получает тот же фактический код. Существующее сканирование, количества и движения не меняются. |
| R6 | Не вводить новое primary-barcode поле, миграцию или зависимость от WMS-593; не менять визуальную структуру таблицы. |

## Заключение

Минимальная правка реализована локально в отдельной ветке. Она использует текущую
production-схему: существующие `products.wb_barcode`, `product_barcodes` и
`product_marketplace_links.external_barcodes`. Новых сущностей и миграций нет.
Обязательные статические проверки, 81 backend-тест, DOM-регрессия и frontend-сборка прошли.
Независимое техническое ревью — PASS. Браузерная проверка на локальной PostgreSQL-копии пройдена.
Изменение принято для срочного выпуска; фактический production-результат проверяется после деплоя.
