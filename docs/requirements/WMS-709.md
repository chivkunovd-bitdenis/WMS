# WMS-709 · Подбор FBS по ячейкам: «План», «Осталось» и раздел «Уже подобрано»

## Исходное поручение

Ночь 08→09.10.2026, АртМакс, поставка WB-GI-290217055 (52 заказа). На вкладке
«Подбор» одна строка висела неподобранной — платье-пиджак 56800-001/46 в Ж-1-14,
хотя его уже сняли из Ж-1-7; на «Упаковке» серой была другая строка — лонгслив
ФА_МОД202а/052/46. По базе и по WB не подобран только лонгслив: его единственная
штука лежит на сортировке, а внизу списка, в блоке «Без ячеек», он терялся среди
35 строк уже подобранных штук с «Собрано 0».

Владелец задал поведение прямо: в строке ячейки нужны «план всего, сколько
осталось подобрать, сколько лежит на текущей ячейке, и сколько ты снимаешь»;
«сколько осталось подобрать» — «цифра динамическая, которая меняется сразу».
Внизу — отдельный раздел «Уже подобрано», раскрывашка, куда попадают уже собранные
штуки, «и отдельно там будет зона сортировки, чтобы это не путалось». Не ломать
другой фронт и логику, не перерисовывать ничего сверх этого; накатить на прод
быстро в обход скиллов и тестов, затем закрепить через CI.

## Требования и границы

R1. В строке места вида «по ячейкам» колонка «Собрать» (весь план товара в каждой
строке) заменяется на «План» (весь план товара) и «Осталось» (план минус снятое
со всех мест этого товара). «Осталось» пересчитывается сразу при изменении
«Собрано» в любой строке товара. «Остаток в коробе» и «Собрано» сохраняются.
R2. Штуки на сортировке, с которых в этом подборе ничего не снято и снять нечего
(товар уже собран или место не даёт свободного количества), выводятся в отдельном
свёрнутом разделе «Уже подобрано» в конце списка, без поля «Собрано». В блоке
«Без ячеек» остаётся только то, что ещё можно снять с сортировки.
R3. Логика подбора и сканирования, данные, API и другие экраны не меняются.
R4. Выкладка на прод без перезапуска API и фоновых задач; затем та же правка в etalon
через CI, чтобы следующая выкатка её не потеряла.

## Заключение

Правка выкачена на прод хотфиксом по прямому поручению владельца, без аналитика,
независимого ревью и приёмки агентом. Изменены только три файла экрана подбора по
ячейкам (`pickRows.ts`, `FbsCellPickTable.tsx` и его тест); подбор, сканирование,
API и данные не затронуты. В etalon дополнительно обновлены ожидания шапки в тесте
WMS-673 и в браузерном наборе `fbs-picking`, которые проверяли прежнюю колонку
«Собрать». Экран глазами в браузере не проверен (C8), результат браузерного набора
ожидается (C9).

Попутно выяснено и задачей не исправляется: лонгслив WB 5983814390 не подобран
и не упакован — успешных записей подбора, упаковки и кода ЧЗ нет; на 46 размер нет
свободных кодов ЧЗ. Неудачные сканы сервер не сохраняет (какой штрихкод
сканировали — неизвестно).
