# WMS-588 · Сборочное задание — агрегат поставок массовой сборки (веб и ТСД)

Запись задачи: [канонический бэклог, WMS-588](../KANONICHESKIY_BACKLOG.md#wms-588). Связь: [WMS-574](WMS-574.md) (массовая сборка в вебе), [WMS-584](WMS-584.md) (массовая сборка на ТСД).
Без аналитика по указанию владельца. Бэк — Codex Sol 5.6, вёрстка — Claude Sonnet, проверка — ведущий.

## 1. Исходные слова владельца (29.09.2026, дословно)

> И еще момент. Я знаешь, о чем думаю? Нам, наверное, нужна агрегирующая сущность, типа а, сборочное задание. Но это просто агрегат, сука. Без, блядь, там каких-то статусов и прочего говна. Зачем это надо? Смотри, вот я, например, собрал... Вот сейчас на ТСД как это работает? Ты создал разом э, поставки, а потом, например, ты вышел из этой сборки. И ты оказываешься где? Ты оказываешься на экране, где отдельные поставки. То есть сборщик уже не может пойти и собирать их просто все вместе, понял? Поэтому нужна какая-то на самом деле агрегация. Ну и, кстати говоря... Как у нас это реализовано сейчас в поставке-то с массовым этим, когда мы много собираем на вебе? У нас же один экран. Мы туда просто заходим в подбор, и там уже все товары. То есть у нас там уже какая-то агрегация типа есть, видимо. Или это не сущность сделана?

Ответ ведущего (проверено кодом): в вебе группа — только список поставок в адресе страницы (`FfFbsOrdersScreen.openAssembly` → параметр URL), на ТСД — только маршрут навигации; после выхода группа теряется. Предложен вариант А (серверный агрегат без статусов) с умолчаниями ниже.

> да не останавливай ты блядь параллеьно делай

## 2. Требования

- **R1. Сущность.** «Сборочное задание»: номер, дата создания, кто создал, список поставок FBS. Никаких статусов, этапов и блокировок. Поставка может входить не более чем в одно сборочное задание. Остальные свойства (прогресс, «активно ли») вычисляются из поставок, не хранятся.
- **R2. Создание.** Создаётся автоматически при массовом создании поставок (веб WMS-574 и ТСД WMS-584) из всех созданных в этой операции поставок; повтор операции не создаёт второе задание (ключ повтора).
- **R3. Список «Сборки».** В вебе (FBS, рядом с «В работе») и на ТСД (FBS, рядом с «В работе») — список сборочных заданий, в которых есть хотя бы одна непереданная поставка: номер, дата, число поставок, селлеры, прогресс подбора/упаковки. Тап/клик → открывается общий экран сборки этих поставок (веб — существующая групповая сборка WMS-574; ТСД — общий подбор и «К упаковке» WMS-584).
- **R4. Совместимость.** Поставки и все их действия не меняются; поставку по-прежнему можно открыть отдельно из «В работе». Серверные права и границы клиента — как у поставок.
- **R5. Без лишнего.** Нет статусов, закрытия, отмены, удаления, редактирования состава (кроме автоматического создания). Когда все поставки задания переданы — оно просто пропадает из списка «Сборки» (вычисляемо).

## 3. Проверки

| № | Требования | Проверка | Вердикт |
|---|---|---|---|
| C1 | R1, R2 | Массовое создание 4 поставок в вебе → в базе одно задание с 4 поставками; повтор запроса с тем же ключом — задание одно. | **Частично, сервер:** POST создаёт одно задание со всеми переданными поставками, повтор ключа возвращает тот же ID; уникальности проверены на PostgreSQL. Вызов POST из массового веб-сценария относится к отдельной реализации фронта и здесь не проверен. |
| C2 | R2, R3 | Массовое создание на ТСД → выйти в главное меню → FBS → «Сборки» → задание → общий подбор тех же поставок. | **Не проверено:** мобильный клиент вне серверной задачи. |
| C3 | R3 | Задание, созданное на ТСД, видно в вебе в «Сборки» и открывает групповую сборку тех же поставок (и наоборот). | **Частично, сервер:** созданное через общий API задание читается через list/detail с тем же составом. Веб и ТСД вне серверной задачи. |
| C4 | R5 | Передать все поставки задания → задание пропало из «Сборки»; одну из нескольких — осталось. | **Пройдено на сервере:** задание с одной активной поставкой остаётся; после перевода всех поставок в конечный статус исчезает из списка. |
| C5 | R4 | Поставка задания открывается отдельно из «В работе», её действия работают как раньше; тесты бэка/фронта зелёные. | **Частично, сервер:** существующая модель и API поставки не изменены; новый и регрессионный seller-scope тесты бэка зелёные. Фронт и операторский путь не проверялись. |
