# WMS-639 · Скан упаковки не ждёт проверку WB после записи КИЗ

## Исходный запрос

> «Мы же это чётко, жёстко обсуждали… что мы не ждём ВБ вообще… Какие 60 секунд?» —
> «Значит, исправлять точечно. Кати сейчас. Им сейчас принимать надо.» (владелец, 02.10.2026)

Срочный точечный хотфикс по прямому указанию владельца, без аналитика и ревью.

## Причина (проверено 02.10.2026 на стенде с кодом прода 549f7ba9)

WMS-635 Q1 ограничил ожидание WB при скане 4 секундами только для **записи** КИЗ
(`put_marketplace_order_meta`). Сразу после принятой записи в том же запросе скана
`fbs_marking_service` читал у WB вердикт (`_sync_order_meta_from_wb`) с обычным
пределом 60 с. «Поддельный WB»: запись 200, чтение висит 70 с → скан ЧЗ в 20:23:15,
стикер в 20:24:15, сканы в эту минуту терялись. То же для «Печатать ЧЗ» из пула.

## Требования

### R1. Скан упаковки не читает вердикт WB после записи КИЗ

В режиме скана (тот же признак, что ставит короткий предел записи WMS-635 Q1:
`scan_no_wb_wait` у коммита КИЗ и `print_chz` у ленты скана) после принятой записи
сервер не обращается к WB, а сразу отвечает «код привязан, ждёт подтверждения WB»
(`wb_pending_confirmation`). Дальше — существующий путь WMS-635: стикер/ЧЗ/копия
печатаются, заказ упаковывается, вердикт WB досверяет фоновая сверка.

### R2. Вне скана ничего не меняется

Коммит КИЗ без признака скана по-прежнему читает вердикт WB сразу.

### R3. Ничего лишнего

Фронт, запись КИЗ, фоновая сверка, удаление КИЗ при замене не меняются.

## Заключение

Принято локально и на стенде без аналитика и ревью по указанию владельца. Отказ WB по
коду, который раньше при скане виден сразу, теперь становится красным после фоновой
сверки — это прямое следствие «скан не ждёт WB». Не входит в задачу и остаётся:
при замене КИЗ (поле строки, «Назад») удаление старого кода в WB ждёт ответа до 60 с;
запись КИЗ при скане ждёт до 4 с (WMS-635 Q1).
