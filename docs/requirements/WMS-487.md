# WMS-487 · Печать ленты FBS: заказ с маркируемым товаром без кода не считается напечатанным; «Печать всего» выдаёт новые коды тем, у кого их нет

Срочная постановка ведущего по поручению владельца 20.09.2026 (аналитик не вызывался — владелец
велел экономить ресурсы и отдавать задачи Codex по описанию). Исполнитель — Codex (Astra).
Ветка `fix/wms487-tape-print-missing-codes` от `origin/etalon` 74665f91 (= бой d5903838 + WMS-484).

## 1. Исходный запрос владельца (дословно)

20.09.2026, скриншот окна «Повторная печать» на поставке FBS 20.09.2026 AVpack (ИП Горячкина):
«Напечатано 12 из 12», ошибка «Напечатано заказов: 1 из 12. Не попали в ленту: 5819413310,
5820714258, 5816032987, 5816793125, 5817203198, 5817230067, 5819064782, 5821451856, 5823657167,
5815685433, 5819379475. Причина по первому: nothing_to_reprint. Повторите печать по этим заказам.»

- «Че за хуйня»
- «сделай все нормально, чтобы он спокойно напечатал всю ленту нормально. Он не будет печатать по одному»

## 2. Что происходит (проверено по коду и по бою)

- Поставка: 12 заказов — 9 леггинсов LEG_BL_AV (S/M/L), 2 палантина PAL_BROWN_AV (у всех
  `product.requires_honest_sign = true`, у WB `required_meta = []`, `optional_meta = ["sgtin"]`)
  и 1 сумка Sum1AVbrown (ЧЗ не требует). QR-стикеры у всех 12 напечатаны. Коды ЧЗ у 11
  маркируемых заказов были отвязаны крестиком (WMS-486) и затем возвращены в пул ведущим.
- Экран `frontend/src/screens/v2/FfFbsSupplyWorkspace.tsx`: `orderPrintDone` (строки ~1510–1515)
  считает заказ напечатанным, если стикер напечатан/применён **и** `fbsOrderMarkingAccepted(order.metadata)`
  (`frontend/src/screens/v2/fbsUx.ts:398`). При `metadata.required = []` и без кодов
  `fbsOrderMarkingAccepted` возвращает `true` (`[].every(...)`), хотя товар маркируемый —
  признак товара (`requiresOrderHonestSign(order)`, строки ~1140–1147) здесь не учитывается.
  Поэтому «Напечатано 12 из 12», и `openBulkOrderMarkingPrint(printPackingOrders,
  printPackingOrders.every(orderPrintDone))` (строка ~2056) открывает окно в режиме **повторной**
  печати (`reprint = true`).
- Сервер `backend/app/services/fbs_order_tape_print_service.py`, `_print_or_reprint_order_code`
  (строки ~652–716): при `reprint=True` и отсутствии привязанного кода бросает
  `nothing_to_reprint`; при `reprint=False` печатает существующий код повторно (без события
  reprinted) и выдаёт новый код заказу без кода. То есть смешанная лента при `reprint=False`
  работает, ломает её только флаг.
- Кнопка принтера в строке заказа (`openOrderMarkingPrint(order, line)`, `reprint=false`) работает,
  но владелец прямо сказал: печатать по одному оператор не будет.

## 3. Требования

**R1. Заказ с маркируемым товаром без кода не считается напечатанным.** `orderPrintDone` должен
возвращать `false`, если `requiresOrderHonestSign(order)` истинно и у заказа нет внесённого кода
sgtin (по `value_tail`, как в `fbsMarkingVerdictsSummary`/«Очистить ЧЗ»), независимо от того,
что WB не требует sgtin. Счётчик «Напечатано X из N» и заголовок/режим окна печати следуют из
этого же признака. Заказы без требования ЧЗ (сумка) считаются напечатанными по стикеру, как сейчас.

**R2. Групповая печать не уходит в «повторную», пока хоть у одного заказа нет нужного кода.**
Режим повторной печати (`reprint=true`) включается только когда у всех печатаемых заказов
`orderPrintDone` истинно по R1. Если хотя бы одному заказу нужен код — обычная печать
(`reprint=false`): существующие коды печатаются повторно, недостающие выдаются из пула.

**R3. Сервер не отвечает «нечего перепечатывать» заказу, которому нужен код.** В
`_print_or_reprint_order_code` при `reprint=True`, отсутствии привязанного кода и
`_order_requires_sgtin(order)` — выдавать новый код так же, как при `reprint=False` (та же ветка
`print_codes_for_packaging_line` + `_assign_printed_code_to_order`), а не бросать
`nothing_to_reprint`. `nothing_to_reprint` остаётся только для заказа, которому код не требуется.
Защита от новых кодов при «Сдать без Честного знака» (`honest_sign_skipped`) и запрет печати
операторского кода (`operator_kiz_print_forbidden`) не меняются.

**R4. Ничего лишнего.** Не менять состав ленты, шаблоны, порядок этикеток, поведение кнопки в
строке, режим Ozon. Никаких новых статусов, сущностей, настроек.

**R5. Тесты.** vitest на `orderPrintDone`/новый чистый хелпер (маркируемый без кода → false;
маркируемый с кодом accepted → true; немаркируемый со стикером → true; `honest_sign_skipped`
не ломает существующую логику) и на выбор режима reprint; pytest на `_print_or_reprint_order_code`
/ `print_fbs_order_tape` с `reprint=True`: заказ с кодом → повторная печать существующего,
заказ без кода и требованием ЧЗ → новый код, заказ без требования → `nothing_to_reprint` как раньше.

## 5. Заключение

**Принято ведущим к выкатке 20.09.2026** (аналитик и перекрёстное ревью не вызывались по поручению владельца экономить ресурсы; исправление срочное). R1–R3 подтверждены: браузером на стенде (C1) и тестами (C3–C6); R4 — по диффу (три точечных правки: серверное условие `reprint and not _order_requires_sgtin`, чистая функция `fbsOrderPrintDone`, режим групповой печати). Не проверено в браузере: сама печать ленты с выдачей кодов (C2) — пул стенда пуст; на бою до выкатки та же поставка разблокирована ручной правкой отметки стикера (см. WMS-487 в бэклоге).
