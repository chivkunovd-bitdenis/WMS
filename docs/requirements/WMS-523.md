# WMS-523 — Автозагрузка КИЗ: отдельный пул на каждую новую группу товар+GTIN

Запись задачи: [канонический бэклог, WMS-523](../KANONICHESKIY_BACKLOG.md#wms-523).

## 1. Исходный запрос и уточнения

> господи долбоёбы сосоздай новый пул прямо снйчас быстро для авпак по всем загруженным без пулов и бери задачу на исправление - по каждорму товару при автозагрузке, каждый пул кодов, это пул

Предыдущее уточнение владельца:

> пул — агрегация загрузки, не должен отсекать общие остатки товара

Срочное исправление уже загруженных AVpack-кодов выполняется отдельно. WMS-523
описывает постоянное исправление новых загрузок и не ждёт production repair.

## 2. Проверенный текущий процесс и цель

WMS-476 `auto_import_marking_codes` и `assign_import_rows_to_product` сейчас создают
новые `MarkingCode` с `pool_id=None`, прямым `product_id` и `import_batch_id`.
Если у товара есть хотя бы одна `MarkingPoolProduct`, `_code_filter_for_product` и
batch count переходят на связанные пулы и перестают учитывать прямые коды этого
товара. Поэтому успешная автозагрузка может быть видна в результате импорта, но не
попасть в общий доступный остаток и реальную выдачу печати.

Цель: каждая фактическая новая загрузка WMS-476 создаёт собственные обычные пулы по
группам `товар + GTIN`; те же правила действуют при ручном назначении остатка этого
auto-процесса. Старые пулы не переиспользуются и не объединяются.

## 3. Требования

| ID | Проверяемое правило | Основание |
|---|---|---|
| R1 | В одном новом auto-import после дедупликации каждая непустая группа `product_id + GTIN` получает один новый `MarkingPool` и одну связь `MarkingPoolProduct` с этим товаром. Все новые коды группы получают этот `pool_id` и сохраняют прямой `product_id`. | Прямой запрос владельца; существующая модель обычного пула. |
| R2 | Следующий фактический auto-import того же товара и GTIN создаёт новый пул своей загрузки. Реализация не ищет, не переиспользует и не расширяет прежний пул только из-за совпадения GTIN. | Уточнение: пул — агрегация загрузки; контракт WMS-520 о свежем пуле загрузки. |
| R3 | Ручное назначение оставшихся строк auto-процесса применяет то же правило: один новый пул на каждую непустую группу `выбранный товар + GTIN` текущего assign-запроса. Несколько GTIN не смешиваются в один пул. | Запрос охватывает ручное продолжение автозагрузки. |
| R4 | Исправление не теряет существующие данные: у кода сохраняются `product_id`, `import_batch_id`, исходный PDF/label artifact, статус и импортное событие. Формат ответа WMS-476 и его idempotent result остаются прежними. | Граница текущего рабочего процесса. |
| R5 | All-duplicate группа, невалидные/неназначенные строки и отказ до сохранения не оставляют пустой пул или связь. Повтор того же `request_id` возвращает прежний результат и не создаёт новые batch/pool/link/code/event; конфликтующий повтор остаётся конфликтом. | Защита от дублей, частичной записи и повторной доставки. |
| R6 | Доступный остаток товара агрегирует все его связанные пулы без дублей. Сценарий «старый пул + две новые загрузки» даёт сумму кодов всех трёх пулов и в каталоге, и в упаковке; фактическая тестовая выдача печати последовательно берёт каждый код ровно один раз. | Исходный дефект: наличие pool link отсекало прямые коды; явная обязательная проверка владельца. |
| R7 | Все созданные batch/pool/link/code остаются в исходных tenant и seller. Товар другого seller не получает связь, его counts и доступные для печати коды не меняются. | Действующая граница доступа WMS. |
| R8 | Изменение ограничено backend-логикой WMS-476 и адресными тестами. UI, API-форматы, общая архитектура пулов, старые данные и production-печать не меняются; production repair AVpack остаётся отдельной операцией. | Явная граница поручения. |

## 4. Решение аналитика

Новая сущность не нужна: используются действующие `MarkingPool` и
`MarkingPoolProduct`. Граница пула — текущий import batch, товар и GTIN. Создавать пул
следует только после того, как для группы установлено наличие хотя бы одного реально
нового кода; пул и коды сохраняются одной транзакцией. Это выполняет запрос и не
возвращает ошибочное переиспользование пулов по одному GTIN.

## 6. Сверка с запросом

Новый пул на каждую новую загрузку покрыт R1–R3; запрет склеивания по GTIN — R2;
сохранность существующих данных — R4; отсутствие пустых/повторных пулов — R5;
обязательная сумма и реальная тестовая выдача «старый + две новые» — R6/C5;
изоляция seller — R7/C6; отсутствие UI, общей переделки и production-печати — R8.
Срочный AVpack repair явно оставлен за границей продуктовой реализации.

## Заключение

Постановка подготовлена; реализация и приёмка ещё не выполнялись. Вердикты C1–C7
оставлены пустыми до предъявления продуктового SHA. Незакрытых продуктовых вопросов
нет: требуемая гранулярность пула задана как `import batch + product + GTIN`.
