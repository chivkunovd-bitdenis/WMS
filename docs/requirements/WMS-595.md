# WMS-595 · Инвентаризация в приложении ТСД по процессу веба

## Исходный запрос и уточнения

30.09.2026: Инвентаризацию нужно вывести в ТСД строго. Она должна быть такая же, как в вебе, включая создание.

Владелец поручил срочную параллельную реализацию Sol/Terra без навыков и отдельной аналитической цепочки, затем изолированное ревью. Деплой и внешние операции этим пакетом не выполняются.

## Требования

**R1.** В приложении ТСД доступны список, создание и открытие документов инвентаризации с существующими фильтрами и данными веба.

**R2.** Пересчёт товара по ячейке/палете/коробу и товару: сканы, ручное количество и корректировка, расхождения, повторное открытие с сохранённым результатом.

**R3.** Черновик и окончательное проведение различаются; используются существующие серверные операции и единый остаток, без второго учёта.

**R4.** Права на инвентаризацию соблюдаются; повтор/потеря ответа не приводит к двойному пересчёту или проведению.

## Проверки

| Проверка | Вердикт |
|---|---|
| C1: проверить R1 на собранной реализации | Выполнено локально: в APK открыты список, компактные фильтры склада/селлера/дат и создание через `/products/ff-catalog-page`; каталог не выгружается целиком. Чистый ввод даты на медленном эмуляторе не доведён, границы и server-side параметры покрыты адресным тестом. |
| C2: проверить R2 на собранной реализации | Выполнено на synthetic API/DB: документ `38dddd6d-90f2-4dac-8593-221bfd47b5e8`, ячейка B-02, скан `OZN445101` дал факт 1, соседний `OZN445102` получил `line_barcode_mismatch`, ручная коррекция сохранила факт 30; после выхода и повторного открытия результат сохранился. |
| C3: проверить R3 на собранной реализации | Выполнено: документ был черновиком до подтверждения, затем проведён существующим API (`status=posted`, `posted_at=2026-09-30 14:53:02.603712+03`). Остаток остался 30, поскольку факт совпал с текущим остатком; отдельный ledger клиент не создаёт. |
| C4: проверить R4 на собранной реализации | Выполнено кодом и адресными тестами: explicit false права скрывают/запрещают раздел, отсутствие нового ключа совместимо со старым сервером. Fake-server создал документ, вернул 504; pending сохранился, второй POST не ушёл, reconciliation нашёл документ и только после этого снял pending. |

## Заключение

Локальная реализация и адресная эмуляторная проверка требований завершены. Два P2
финального read-only Sol-review (неопределённый 504 при создании и название товара
для КИЗ многопозиционного Ozon-заказа) исправлены и покрыты тестами; повторное независимое ревью прошло. Ведущий сверил все пять хешей из заключения
ревьюера с файлами коммита `825e7d9091231d6d361ed57d0907bd5565c468e2`: совпадение полное. Физический ТСД
не проверялся. Ветка, APK и сервер не опубликованы из-за прямой команды владельца
«пока ничего не кати»; merge/deploy/release не выполнялись.
