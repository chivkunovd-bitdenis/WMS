# WMS-519 — Сохранять геометрию Data Matrix при печати и перепечати ЧЗ

Задача зарегистрирована 24.09.2026 по дефекту печати ЧЗ на production. Постановка
подготовлена в ветке `codex/wms519-kiz-label-aspect-ratio` от `origin/etalon`
`f9ac3bc97b9c7c620f30a6992391153ad57a7618`.

Запись задачи: [канонический бэклог, WMS-519](../KANONICHESKIY_BACKLOG.md#wms-519).

## 1. Исходный запрос владельца

Переданная ведущим формулировка владельца:

> При перепечати ЧЗ из каталога, раздела «Честный знак», Chrome preview показывает
> сжатую по высоте/растянутую по ширине этикетку; на screenshot Data Matrix
> прямоугольный, а должен сохранять квадратные модули и нормально помещаться на
> физической этикетке. Нужно срочно исправить на production и убедиться, что во
> всех остальных местах перепечати ЧЗ этикетки не искажаются.

Уточнённая граница поручения:

> Исправить геометрию/масштаб печатной этикетки и унифицировать существующие
> reprint-входы через корректный общий путь, без изменения данных КИЗ,
> allocation/pool state, пользовательских процессов, экранов и бизнес-логики.

## 2. Исходное evidence и подтверждённый симптом

Скриншот владельца от 24.09.2026 сохранён в исходной переписке. Полученный файл
имел размер 1334×764 px и SHA-256
`e5b156ff383e08976712d96aa5395c9fe9243bd6c9e228fe7a6aef52fc3f425c`.
На нём видны Chrome print preview, одна страница, выбранный принтер
`Xprinter XP-370B` и ЧЗ-этикетка с явно неравномерно растянутым Data Matrix:
горизонтальный шаг модулей больше вертикального. Это screenshot evidence дефекта,
но не доказательство его причины и не физическая проверка напечатанной наклейки.

В текущем коде подтверждены следующие факты:

- штатный базовый размер термоэтикетки — 58×40 мм; также уже поддерживаются
  60×80, 60×40 и 70×120 мм, а в конструкторе ЧЗ есть существующая ориентация;
- HTML-печать задаёт выбранный размер через `@page` и строит ЧЗ в
  `frontend/src/utils/printMarkingCodeLabel.ts`;
- Data Matrix генерируется `bwip-js` с общим `scale: 4` и отдельным
  `height: 12`, после чего растровое изображение помещается в квадратный CSS-блок;
  тесты проверяют наличие квадратного внешнего блока, но не квадратность самих
  модулей растра. Сочетание является подтверждённой зоной риска и должно быть
  проверено исправлением, однако окончательная причина устанавливается тестом
  фактического raster output, а не предположением по одной опции;
- `printMarkingCodeLabels` → `printMarkingCodeTape` →
  `buildMarkingTapeSections` → `buildMarkingTapeDocument` →
  `printHtmlInIframe` — общий browser-print путь для точного отсканированного КИЗ;
- если у кода сохранён исходный PDF селлера, чистая ЧЗ-лента может печататься
  нативным PDF; сервер вписывает страницу равномерным коэффициентом. В смешанной
  ленте PDF превращается в PNG и помещается через `object-fit: contain`;
- локальный print-agent в текущем `origin/etalon` обслуживает другие готовые
  FBS/sorting assets. Отдельного agent endpoint для КИЗ-перепечати не найдено;
  текущая перепечать ЧЗ вызывает browser `window.print()`;
- в проверенном кандидате WMS-514 `8069a12515d6512551c1c123d0f5b8581684fb57`
  мгновенная печать/перепечать после скана также вызывает тот же
  `printMarkingCodeLabels`. Поэтому исправленный общий renderer обязан покрыть и
  этот путь при совместном включении задач; новый второй шаблон для WMS-514 не нужен.

Экран «Осталось промаркировать», обычная выдача ЧЗ из пула, первичная печать из

отдельным пользовательским входом.

## 4. Продуктовое решение

Исправляется один общий печатный контур, а не каждый экран отдельно. Для
сгенерированного по полному КИЗ Data Matrix renderer обязан выдавать растр или
вектор с одинаковым масштабом по X и Y; CSS может только равномерно вписать его в
существующую область. Для сохранённого PDF селлера остаётся нативный PDF как более
точный источник, но его вписывание в выбранную страницу также обязано быть
равномерным. Смешанная лента использует тот же aspect-safe принцип.

Существующий набор размеров, ориентация, кнопки, модалки, порядок действий,
автоматический запуск `window.print()` и выбор системного принтера не меняются.
Новый preview, настройка размера, подтверждение, состояние КИЗ или серверная
сущность для этого дефекта не нужны. Если WMS-514 включается в тот же релиз,
мгновенный путь наследует исправленный renderer и не вводит собственную разметку.

## 5. Требования

| ID | Условие, действие и наблюдаемый результат | Основание |
|---|---|---|
| R1 | При генерации Data Matrix из полного КИЗ каждый модуль остаётся квадратным: применяется один коэффициент масштаба по X и Y. Запрещено растягивать или сжимать символ по одной оси, даже если внешний `img` или контейнер имеет квадратный размер. | Прямой дефект на screenshot владельца. |
| R2 | Data Matrix сохраняет неповреждённую светлую quiet zone (свободное поле вокруг символа), не обрезается контейнером/страницей и остаётся считываемым штатным сканером после физической печати. | Прямое требование о читаемости и безопасная геометрия 2D-кода. |
| R3 | ЧЗ-этикетка равномерно вписывается в уже выбранные размер и ориентацию. ## 7. Граница программной и физической приёмки

Кодовые тесты могут доказать одинаковый коэффициент масштаба, сохранность байтов
КИЗ, количество страниц, размер `@page`, общий маршрут вызовов и отсутствие
бизнес-побочных эффектов. Они не доказывают настройки драйвера, фактический
размер рулона, качество термоголовки и считывание бумажной наклейки. Поэтому C9 и
C10 закрываются только на рабочем Xprinter XP-370B; screenshot Chrome без
физической печати не закрывает C9.

Если production-рабочее место использует не 58×40 мм, перед физической приёмкой
фиксируется фактический выбранный штатный размер из уже поддерживаемого списка.
Это не требует нового продуктового решения: алгоритм обязан сохранять пропорции
на каждом существующем размере.

## 8. Сверка постановки

Исходный прямоугольный Data Matrix покрыт R1–R4 и C1–C3. Раздел «Честный знак»
и все найденные reprint-входы покрыты R5 и C4–C8. Quiet zone и реальная
считываемость покрыты R2, R8 и C1/C9. Длинный полный КИЗ и сохранность его байтов
покрыты R7–R8. Chrome preview, отсутствие обрезки и второй страницы покрыты
R4, R9 и C2/C10. Мгновенный WMS-514-путь и возможный local-agent artifact
покрыты R10/C8 без добавления нового механизма. Запрет менять pool/allocation,
процессы и UI покрыт R11–R13 и C4–C12.

В постановку не добавлены новый размер бумаги, новый экран, настройка, модалка,
подтверждение или бизнес-ограничение. Единственное продуктовое изменение —
корректная геометрия существующей печатной этикетки через общий путь.
