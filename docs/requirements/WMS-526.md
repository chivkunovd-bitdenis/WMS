## 2. Существующий процесс (проверено)

**Кто и где.** Оператор фулфилмента в окне FBS-поставки Ozon, вкладка «Короба»
(`frontend/src/screens/v2/FfFbsSupplyWorkspace.tsx`, блок `stage === 'boxes'`).

**Что видно на экране.** Экран открыт 24.09.2026 во встроенном браузере на локальном
стенде этого worktree (etalon `4c59dc7f`, PostgreSQL, тестовая поставка Ozon из пяти
заказов: три заказа по одному товару, один заказ из двух разных товаров, один заказ
из одного товара в количестве 2). В шапке блока — «Короба · Ozon», строка
«Распределено 0 из 7 шт · осталось 7», текстовая кнопка «Печать всех этикеток Ozon (N)»,
поле «Коробов» и основная кнопка «Добавить короба». Для WB в той же шапке —
«Короба · Склад / СЦ», «Печать всех QR (N)», галка «Без распределения», «Коробов»,
«Добавить короба».

**Как оператор сейчас получает этикетку на один заказ Ozon** (шаги 1–3 пройдены руками
на стенде, шаги 4–6 — по коду, успешная сборка на стенде невозможна):

1. «Добавить короба» с числом N создаёт N пустых коробов (Ozon — только локально, без
   обращения к Ozon; `POST /operations/fbs-supplies/{id}/boxes`, не больше 100 за запрос,
   `fbs_packing_box_service.create_boxes`).
2. В каждом коробе «Добавить товары» открывает окно: позиции сгруппированы по заказам
   «Ozon №…», у каждой позиции чекбокс и количество. Позиция выбирается целиком, в один
   короб можно положить позиции только одного заказа
   (`POST …/boxes/{box_id}/orders` с `order_product_ids`, `_assign_ozon_positions`).
3. Кнопка короба «Собрать и получить этикетку» неактивна, пока все позиции заказа не
   разложены по коробам (на стенде: после раскладки первой из двух позиций заказа
   короб показал «осталось разложить 1 шт» и неактивную кнопку; после раскладки второй
   позиции во второй короб кнопка стала активной в обоих коробах).
4. Нажатие вызывает `POST …/boxes/{box_id}/retry-qr`. Для Ozon это
   `ozon_box_assembly_service.assemble_box_order` — сборка **всего заказа**:
   проверка ограничений, затем `/v4/posting/fbs/ship`, где каждый короб заказа — отдельная
   упаковка `packages[]` со списком `{SKU, количество позиции}`; затем запрос этикетки
   `order_sticker`. Одного вызова на любой короб заказа достаточно для всех его коробов.
   Перед необратимым запросом сохраняется метка `ozon_assembly`; при потере ответа
   повтор только перечитывает отправление и не отправляет сборку второй раз.
   После сборки состав короба фиксируется, кнопка короба называется «Этикетка Ozon».
5. «Печать всех этикеток Ozon» собирает готовые этикетки всех коробов в одну ленту
   (без повторов одного документа).
6. «Передать в Ozon» требует, чтобы каждый заказ был собран через этикетку короба.

Итого на поставку из 100 однотоварных заказов оператор делает одно создание коробов,
100 окон «Добавить товары» и 100 нажатий «Собрать и получить этикетку».

**Проверенные ограничения модели.** Неделимая единица раскладки Ozon — позиция заказа
(`FbsOrderProduct`: товар + заказ + количество). Уникальный индекс не даёт одной
позиции лежать в двух коробах; количество в коробе берётся из позиции (WMS-355).
Если позиции одного заказа лежат в разных коробах, Ozon при сборке разрезает
отправление на столько отправлений, сколько коробов, и возвращает на каждое свою
этикетку (описание API в `backend/app/schemas/ozon_fbs_api.py`: «Каждая упаковка
содержит список отправлений, на которые делится заказ»).

**Не проверено.** Как часто в реальных поставках Ozon встречаются многотоварные заказы и
позиции с количеством больше 1 — боевые данные в этой постановке не смотрелись.
Успешная сборка Ozon на стенде не проверялась: обмен с Ozon локально выключен, нажатие
«Собрать и получить этикетку» показало «Обмен с Ozon выключен настройкой.».

**Цель.** Одним нажатием разложить все ещё не разложенные товары поставки Ozon каждый
в свой короб и запросить по ним этикетки тем же механизмом, после чего оператор жмёт
«Печать всех этикеток Ozon» и клеит ленту.

## 4. Решения аналитика и вопрос владельцу

**Р-1. «Товар» = позиция заказа.** Владелец поправился: «не на каждый заказ, на каждый
товар». В его же решении WMS-355 неделимая единица — связка товар-заказ, а позиция по
коробам не дробится. Поэтому короб создаётся на позицию, количество позиции в коробе
целиком (R2). Для типичного случая «один товар — один заказ» это ровно один короб на
заказ. Дробить позицию «2 шт» на два короба нельзя без отмены решения WMS-355 и
изменения модели — это не делается.

R2 подтверждён владельцем 24.09.2026 (см. уточнение в разделе 1): короб на каждый
разный товар заказа, Ozon делит такой заказ на несколько отправлений с отдельными
этикетками; позиция «2 шт» — один короб.

**Р-2. Этикетки запрашиваются по заказам, которые после раскладки полностью разложены
и ещё без готовой этикетки, — включая разложенные вручную ранее (R5).** Так повторное
нажатие становится обычным способом «доделать» после сбоев (R7) без отдельной памяти о
том, какие короба создала кнопка, а конечное состояние совпадает с целью владельца —
всё разложено и всё можно напечатать одной лентой. Полностью разложенный вручную
заказ оператор всё равно отправил бы той же кнопкой короба.

**Р-3. Где и как выглядит кнопка.** В шапке блока коробов — в контексте поставки, рядом
с существующими действиями над коробами; вариант — как «Печать всех этикеток Ozon»
(текстовая кнопка), чтобы основной кнопкой оставалась «Добавить короба». Название
«Создать автоматически»: коротко, а слово «короба» уже есть в заголовке блока.
Модальное окно не делается («Давай забудем про модалку пока»).

**Р-4. Нужен ли бэк.** По коду все шаги уже доступны через API: создание коробов
(до 100 за запрос), раскладка позиций в конкретный короб, `retry-qr` на короб.
Но раскладка фронтом — это 1 + N запросов, каждый возвращает весь снимок поставки, и
обрыв посередине оставляет пустые короба и полураскладку; одновременное нажатие двумя
операторами тоже оставит лишние пустые короба. Требование R4/R8 при таком подходе
выполняется только сложной компенсацией на фронте. Рекомендация исполнителю:
одна небольшая серверная операция «разложить все неразложенные позиции Ozon по новым
коробам» в одной транзакции под уже существующей блокировкой поставки (переиспользуя
`create_boxes`/`_assign_ozon_positions`, без новых таблиц, статусов и миграций), а
этикетки — существующим `POST …/boxes/{box_id}/retry-qr` по одному коробу каждого
заказа последовательным циклом на фронте (одна сборка может идти секунды, сотня в одном
HTTP-запросе упрётся в тайм-ауты). Выбор реализации остаётся за исполнителем при
условии выполнения R1–R11.

## 5. Проверки

Стенд для UI: локальный стенд этого worktree (конфигурации `wms525-api`/`wms525-web` в
`.claude/launch.json` основного checkout, база `wms525_ui`), тестовая поставка Ozon
`11111111-0000-0000-0000-000000000525` и WB `22222222-0000-0000-0000-000000000525`.
На стенде обмен с Ozon выключен, поэтому успешный путь сборки проверяется серверными
тестами с подменой провайдера Ozon (как в существующих тестах `ozon_box_assembly`),
а экранный путь сбоя — на стенде как есть. Боевой прод не используется.
