# WMS-607 — запуск и прямая печать QR без настройки подключения

## Исходный запрос
30.09.2026: срочно исправить WMS Print. Windows и Mac: запустить программу,
сканировать из Chrome, сразу печатать QR системным принтером по умолчанию.
Без адресов, кодов сопряжения, выбора очереди, навыков, агентов и большого набора тестов.
Последнее указание владельца отменяет агентную цепочку для этой задачи.

## Требования
R1. Запуск отдельной программы без вопросов о сервере/складе/коде/принтере.
R2. Прямой приём подготовленной QR-этикетки из Chrome без window.print.
R3. Использовать текущий принтер ОС по умолчанию для каждого нового задания.
R4. Сохранить последовательность и не дублировать задание после потери ответа/перезапуска.
R5. Самостоятельные пакеты Windows x64 и macOS; исходники и SHA сохранены в Git.
R6. Программа открывает готовую локальную страницу проверки в Chrome.
R8. Уточнение владельца: «важно работать должно мгновенно прям за секунду».
Цель — скан → квитанция ОС менее 1000 мс; механика физического принтера измеряется отдельно.
R7. Не менять настройки безопасности ОС/Chrome. Первое системное разрешение
для загруженного приложения или обращения сайта к localhost нельзя обещать устранить.

## Ошибка загрузки Python на Mac оператора

Получен фактический сбой `library load disallowed by system policy` для
_internal/Python. Дополнительно локальный codesign --verify выявил
`code has no resources but signature indicates they must be present`.
Исправление упаковки: собранный Python.framework подписывается заново
локальной ad-hoc подписью, ZIP создаётся ditto с сохранением ссылок; после
распаковки сборщик проверяет подпись framework и выполняет self-test.
Это исправляет целостность пакета, но не заменяет Developer ID/notarization.
Для архива без Apple Developer ID пользователю предоставлена ограниченная
команда снятия quarantine только с папки данной программы.

## Контракт команды автообновления Mac ArtMaks — до кода установщика

Последнее поручение владельца передано ведущим этой сессии: довести исправленную
ПО-версию ArtMaks, проверить и подготовить команду автообновления с сохранением
предыдущей версии и штатными разрешениями; отправка владельцу в Telegram позже.
Дословная формулировка владельца в этой сессии не предъявлена: это сохранённый
контекст ведущего, не выдуманная прямая цитата.

Оператор сейчас вручную скачивает консольную папку wms-print, запускает один
native executable и сканирует в Chrome. Состояние Direct хранится отдельно в
`~/Library/Application Support/WMS Print/direct`: jobs-v2, изображения,
direct-jobs.json, квитанции и unknown. Старые сборки с Python не являются
требуемым Mac Direct-пакетом. Цель — одна команда обновляет именно эту программу,
сохраняет восстанавливаемую прошлую версию и существующую историю печати.

### Требования обновления

R-U1. На Mac команда сама определяет аппаратную ARM/Intel архитектуру, включая
ARM Mac с Terminal под Rosetta, и выбирает соответствующий native Direct artifact.
Неподдерживаемая ОС/архитектура дают понятный отказ до остановки программы и
изменения файлов. Основание: автоматическое обновление Mac и существующие два
самостоятельных Mac-пакета; техническое решение аналитика.

R-U2. До любых изменений команда скачивает immutable artifact по закреплённому
URL и проверяет закреплённые SHA256 архива и точный source_commit из build.json,
runtime=direct, console=true, архитектуру бинарника и отсутствие вложенного Python.
SHA пакета должен соответствовать конкретному принятому и проверенному в
Direct console CI исходнику; отдельно доказывается совпадение product blobs с
исправлением. Сейчас пакет и его SHA256 отсутствуют, подставлять guessed/latest
URL или source hash вместо checksum архива нельзя. Ошибка скачивания, checksum,
метаданных, распаковки или unpacked self-test оставляет старую программу рабочей.
Основание: R5,R13,R14,R18 и исправление ошибки выпуска paired/устаревшего source.

R-U3. После проверки staging-пакета и перед заменой команда сохраняет в уникальном
месте целую прошлую application directory: executable, соседние файлы, build.json,
права и ссылки. Отдельно сохраняет согласованный снимок существующего Direct
состояния и имеющейся конфигурации; содержимое конфигурации не выводит. Проверяет
полноту и возможность прочитать архив. Недостаток места/ошибка архива не допускают
замену. Предыдущий архив повторной командой не затирается. Основание: прямое
поручение сохранить предыдущую версию, R4 и необходимость восстановимого состояния.

R-U4. Команда сверяет, что процесс/порт17843 принадлежат именно выбранному
старому executable. Если порт занят другим процессом, сообщает причину и не
завершает его. Завершает только свой процесс штатно, получает стабильный снимок
состояния и заменяет программу полностью подготовленным деревом на том же
файловом разделе без смешения старых и новых файлов. После запуска сверяет
фактически запущенный executable, его build metadata и HTTP health. Одного health200
недостаточно: реализация de9 возвращает health200 без проверки принтера.
Основание: безопасное обновление, существующий общий local port и R4/R14.

R-U5. При отказе замены/запуска/проверки новой программы восстанавливается
прошлая application directory из сохранённых bytes; успешное обновление не
сообщается. Текущее состояние печати не откатывается к старому снимку:
появившиеся квитанции и unknown не исчезают. Для совместимой прошлой Direct
версии запуск с текущим журналом сохраняет прежнюю квитанцию/неопределённый
исход; если старый пакет несовместим, bytes восстановлены, но нельзя заявлять
рабочий запуск или удалять журнал ради него. Основание: R4 и прямое сохранение
прошлой версии; B11/B20 библиотеки сбоев.

R-U6. Повтор команды после успешного обновления сверяет установленный target и
работающий target process; не создаёт новую «предыдущую» копию поверх настоящей
старой, не теряет архив и историю. После прерывания команды позволяет завершить
обновление/rollback из сохранённых файлов. Два одновременных обновления не
подменяют каталоги/архивы друг друга. Ни одно обновление само не отправляет
этикетки, не повторяет unknown и не создаёт новый idempotency key ради восстановления.
Основание: R4, сохранение предыдущей версии и техническая защита внешнего результата.

R-U7. Команда сохраняет Gatekeeper и настройки Chrome. Если macOS просит запуск,
даёт штатный путь разрешения именно проверенного executable в настройках
«Конфиденциальность и безопасность»; Chrome может запросить разрешение локального
доступа именно для сайта WMS. Команда сообщает этот требуемый шаг и корректно
продолжается после разрешения, не обещая нулевых предупреждений. Не отключает
Gatekeeper, не применяет массовое снятие quarantine, не требует Full Disk Access,
не меняет default printer и не устанавливает Python/Homebrew/toolchain. Основание:
R7,R18 и прямое «штатные разрешения».

R-U8. Успех обновления означает точный проверенный target executable и
сохранённый предыдущий архив/состояние. Печать подтверждается отдельно одним
контролируемым QR и повтором его ключа после перезапуска; unknown остаётся
неизвестным без второй отправки. Физический размер, число копий и чтение QR
подтверждает оператор на принтере ArtMaks. Telegram получает только проверенную
команду с точными артефактами и границами после следующих этапов. Основание:
R4,R5,R7 и явное поручение подготовить/проверить/позднее отправить.
