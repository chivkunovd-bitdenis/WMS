# WMS-488 · AVpack: товары каждого селлера видны только ему и фулфилменту

## Исходный запрос

Формулировка владельца, переданная ведущим 21.09.2026: подключённые к AVpack селлеры видят в своём каталоге чужие товары друг друга. Нужен глубокий разбор и закрытие всех путей утечки. AVpack как фулфилмент должен видеть товары подключённых селлеров; каждый селлер — только свои. Требование не ограничено скрытием строк на экране.

Это **новая WMS-488**. Историческая WMS-481 от 19.09 касалась удаления копии селлера AVpack из другого, тестового арендатора. Тогдашний вывод о доступе не доказывает состояние текущего AVpack и не закрывает этот запрос.

## Проверенный процесс и границы расследования

В текущем коде селлерский экран `/seller/products` загружает `GET /products/wb-catalog`. Сервер берёт `effective_seller_id` из активного магазина в токене; для пользователя с правом управления магазинами это может быть не домашний селлер. `seller_shop_service.py` даёт это право по признаку пользователя, списку email и встроенным фрагментам email; затем включённая делегация разрешает другой магазин того же арендатора. Поэтому один только фильтр списка по `effective_seller_id` не обеспечивает правило владельца «каждый селлер — только свои». Также существуют `GET /products`, `/products/categories`, прямые маршруты по ID, массовые изменения, связанные списки и выгрузки; каждый путь требуется проверить по фактическим правам и данным.

Ведущий исследователь сообщил о свежей проверке production на чтение: в AVpack есть пользователь селлера с включённым управлением магазинами и делегациями на других селлеров. Это подтверждает существование конкретного **разрешённого текущим кодом** пути к чужому каталогу; не доказывает, что любой селлер AVpack видит всё, и не доказывает отсутствия иных путей. Конкретные результаты API/данных и корневая причина должны быть приложены к приёмке. Боевые данные менять ради воспроизведения нельзя.

Позднее исследование на опубликованном frontend bundle подтвердило отдельный клиентский дефект: первая вкладка показывала 38 товаров одного селлера; во второй вкладке вошли другим селлером с 19 товарами и затем вышли. Первая вкладка получила события `storage`, но продолжила показывать старый каталог и пользоваться старой сессией. `useAuth` не синхронизировал состояние React с изменением общего хранилища. Источник и границы воспроизведения — [AUDIT.md](../evidence/WMS-488/AUDIT.md). Связь этого механизма с конкретным наблюдением владельца не доказана, но раскрытие прежних карточек после смены общего пользователя подтверждено.

Первичная постановка готовилась до браузерной проверки. После реализации ведущий исследователь прошёл селлерский и FF-каталог в настоящем Chrome на локальном production build с обезличенными API fixtures; реальные серверные границы проверены отдельно на тестовой БД. Полное доказательство и ограничения — [ACCEPTANCE.md](../evidence/WMS-488/ACCEPTANCE.md). Финальная приёмка исходного аналитика следует после общего перекрёстного ревью.

## Требования

| ID | Проверяемое поведение | Основание |
|---|---|---|
| R1 | Обычный пользователь портала селлера AVpack видит в каталоге только товары, принадлежащие **его** селлеру. Список, карточка, поиск, фильтры, категории, счётчики, подсказки и пагинация считают данные в той же границе; наличие чужого артикула, ШК, SKU или названия не выдаёт чужой товар. Особый доступ существующего multi-shop пользователя остаётся отдельным вопросом владельцу ниже. | Прямое правило владельца «каждый селлер — только свои»; обнаруженная развилка по уже выданной делегации. |
| R2 | AVpack под ролью фулфилмента с существующим правом чтения каталога продолжает видеть товары всех подключённых к **этому** фулфилменту селлеров, в том числе через выбор нужного селлера. Селлерский вход и вход ФФ различаются по серверному праву, а не по видимости кнопки. | Прямое правило владельца «AVpack как ФФ должен видеть товары подключённых селлеров». |
| R3 | Прямой запрос селлера к чужому товару по ID или через скан кода и связанные с ним чтения (карточка, остатки, направления, правила публикации, упаковочные инструкции, история размеров, маркировка, изображения/печатные данные, если доступны из кабинета) не возвращают сведения о чужом товаре. Даже ответ о нескольких совпадениях кода не раскрывает чужие товары или заказы. Обращение к собственному товару продолжает работать. | Требование закрыть все пути утечки, не только таблицу; в текущем коде `GET /operations/scan/resolve` ищет по `tenant_id` без seller scope. |
| R4 | Селлер не может создать, изменить, импортировать, объединить, привязать, напечатать или массово изменить чужой товар через прямой ID, подменённый `seller_id`, активный магазин в токене, смешанный список ID либо экспорт/импорт. Отказ происходит до изменения чужих данных; собственные операции сохраняются. | Та же граница владения должна действовать на записи и действия, иначе обход экрана остаётся. |
| R5 | Любая выгрузка, отчёт, файл, печать или вспомогательный список товаров, доступные селлеру AVpack, включают только его товары и производные данные. Пустой результат поиска и метаданные страницы не раскрывают наличие чужих товаров. | Запрос о всех путях утечки; экспорты и агрегаты обходят экранный фильтр. |
| R6 | Смена активного магазина, старый токен с чужим `seller_id`, обновление страницы, повторный вход и клиентский кэш не открывают чужой каталог обычному селлеру AVpack. Когда в другой вкладке браузера происходит вход под другим пользователем или выход, открытая вкладка сразу прекращает использовать прежнюю сессию и убирает старые карточки, счётчики и детали со своего экрана; при новом входе показывает данные только после проверки нового пользователя и его области. Запоздалый ответ чтения каталога или `/auth/me`, начатого до смены/выхода, не может снова показать прежнего пользователя и его товары. Сервер независимо проверяет принадлежность товара на каждом пути. Существующие легитимные делегирования не изменяются без решения владельца об особом пользователе и конкретном объёме доступа. | Нынешняя модель активного магазина и делегаций; подтверждённый межвкладочный дефект и незакрытая старая сессия в [AUDIT.md](../evidence/WMS-488/AUDIT.md); вопрос о намеренном multi-shop доступе остаётся открытым. |
| R7 | Товары другого арендатора не видны и не изменяемы ни AVpack-ФФ, ни его селлерами; товар селлера AVpack сохраняет правильного владельца после синхронизации WB/Ozon, импорта, создания и объединения. Ошибочно принадлежащие другому селлеру данные не маскируются одной только правкой интерфейса: первопричина и затронутые записи устанавливаются отдельно перед исправлением данных. | Изоляция клиентов проекта и глубокий анализ причины, а не косметический фильтр. |

## Продуктовое решение и неизвестное

Базовое право AVpack видеть товары всех подключённых селлеров реализует **роль фулфилмента**. Но у одного пользователя с ролью селлера AVpack в production включены флаг менеджера и делегации на другие магазины. Ведущий уже спросил владельца, является ли он намеренно уполномоченным multi-shop оператором. **Ответ ожидается.** До него нельзя ни объявлять этот доступ утечкой, ни молча отменять делегации: оба варианта меняют бизнес-результат. Независимые обходы изоляции для обычного селлера, прежде всего сканирование по коду, можно исправлять без ожидания этого ответа. Общая функция делегирования для других арендаторов не меняется без отдельного основания.

Исследование установило scan-обход, сохранение прежней сессии между вкладками, runtime-право менеджера по email и пропуск Products permission в массовом признаке ЧЗ. Карта маршрутов и production read-only результаты сохранены в [AUDIT.md](../evidence/WMS-488/AUDIT.md); ошибочных владельцев товаров не найдено. Точная причина каждого сообщения владельца о массовом показе всех чужих товаров и назначение особого менеджера остаются неустановленными.

## Заключение

**Предварительная техническая проверка ведущего: подтверждённые дефекты исправлены; финальная продуктовая приёмка и проверка новой production-версии впереди.** Backend — `65b15418c53a143f783cb4d2a8138c041a1d2c78`; frontend — `90dd00448082c3a078c667beffe6c994b127e6f1`; дополнительная API-матрица — `0a111c13c6086db156c8099d88f562034d10c0c8`. Ветка опубликована. Пройдены 16 frontend unit tests, tsc/build, 8 Chrome сценариев и 153 backend tests, подробно перечисленные в [ACCEPTANCE.md](../evidence/WMS-488/ACCEPTANCE.md).

Исправление ограничивает сканирование владельцем и существующими правами, добавляет пропущенное право Products для массового ЧЗ, заменяет runtime email-право явным флагом без расширения действующих делегаций и синхронизирует вкладки при смене/выходе с отбрасыванием старых ответов. FF-каталог всех своих селлеров сохранён. Product code сверх этих подтверждённых дефектов не менялся; боевые данные и права вручную не изменялись.

Свежий обычный каталог с массовым показом чужих товаров повтором не воспроизведён; это не опровергает наблюдение владельца и не объявляется установленной причиной каждого случая. Доступ существующего multi-shop менеджера остаётся отдельным вопросом назначения роли. Перед закрытием нужны общее Opus/Astra CLI review, заключение исходного аналитика и C9 после выкладки. Локальные fixtures и API tests не являются доказательством production-деплоя.
