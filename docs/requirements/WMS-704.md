# WMS-704 · Параллельная диагностика и короткий цикл исправлений

## Исходный запрос

После девятичасового прохода переписать правила и действующий CI так, чтобы
независимые проверки запускались одновременно, первичный проход собирал все
независимые ошибки, связанные исправления проверялись короткими целевыми
сценариями, а полный набор запускался после пакета исправлений. Сохранить
блокировку выпуска при реальных ошибках, обязательный продуктовый охват,
независимое Astra-ревью и реальные проверки. Не ускорять процесс пропусками,
увеличением тайм-аутов или ослаблением проверок. Документы и журналы без
исполняемого кода не должны автоматически запускать тяжёлые браузерные наборы.

Пользователь отдельно разрешил заменить замораживание целых тестовых файлов,
их имён и внешнюю main-only pin-церемонию (специальную привязку к контрольному
коммиту `main`) на обычное независимое ревью изменения поведения. Добавление
теста, исправление фикстуры (управляемых тестовых данных) или переименование
не должны требовать восстановления старых байтов/истории или специального pin.
Защита от исчезновения обязательного покрытия, отключения теста, пропуска и
неполного отчёта должна сохраниться. Новые реестры и слои подписей не вводить.

## Требования

| ID | Требование |
|---|---|
| R1 | До работы один раз проверить исходную ветку/ревизию, готовность среды и известные красные проверки; не превращать эти факты в повторный полный прогон после каждого изменения. |
| R2 | Первичный проход запускает независимые проверки параллельно с `fail-fast=false` (не прекращать соседние проверки при первом падении) и с изолированными данными; зависимая проверка без предусловия получает статус blocked, предусловие не имитируется. |
| R3 | Первичный проход собирает результаты всех независимых проверок. Сбои классифицируются как дефект продукта, теста или среды; несколько ошибок в одном сценарии требуют сверить весь оставшийся маршрут с реальными DOM/API и исправить подтверждённые ошибки вместе. |
| R4 | Для подтверждённого дефекта фиксируются короткий воспроизводящий сценарий, исправление и затронутые проверки. После каждого пакета выполняются только затронутые проверки; полный финальный набор выполняется после пакета исправлений. Каждый повтор имеет конкретное изменение или диагностическое основание; уже принятые неизменённые проверки без нового основания не гоняются повторно. Не создаётся отдельный агент на каждый красный тест. |
| R5 | Полный набор остаётся блокирующим для выпуска, покрывает согласованный продуктовый объём, проверяет реальные результаты сценариев и завершается независимым Astra-ревью в разрешённом effort. Нельзя снижать assertions (проверяемые условия), добавлять skips (пропуски) или раздувать тайм-ауты ради зелёного результата. |
| R6 | Изменение только документов/журналов без исполняемого кода не запускает тяжёлые FBS browser suites. Прямой `workflow_dispatch` (ручной запуск workflow) по-прежнему выполняет выбранную проверку. |
| R7 | CI больше не требует неизменных байтов/имён тестовых файлов либо external main-only pin для добавления, переименования или обоснованной правки fixture. Сохраняются обязательные suites, минимальный размер их набора, фактическое выполнение без missing/skip/duplicate/collection errors; содержательная правка тестовых ожиданий проходит обычное независимое ревью. |

| C2: независимые job/shard идут с fail-fast=false и отдельными данными; зависимый шаг не маскирует отсутствующее предусловие | R2–R3, R5 | навсегда | focused CI infrastructure tests и workflow review | пройдено локально: 82 process/scope/deploy tests и 96 subtests; run_release_postgres.sh синтаксически проверен |

## Заключение

Реализация и указанные локальные focused checks выполнены. Задача ещё не принята:
независимое Astra-ревью итогового SHA и один полный финальный CI после интеграции
исправлений остаются открытыми. Release readiness, merge и deploy этим документом
не подтверждаются.
