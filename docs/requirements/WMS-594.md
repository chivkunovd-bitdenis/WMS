# WMS-594 · Отдельные права сотрудников на разделы

## Исходный запрос и уточнения

30.09.2026: Отдельные права: Расчёты, Хранение, Инвентаризация (создание и просмотр/работа), FBS, Честный знак, Настройки. Без права раздел не виден и операции недоступны.

Владелец поручил срочную параллельную реализацию Sol/Terra без навыков и отдельной аналитической цепочки, затем изолированное ревью. Деплой и внешние операции этим пакетом не выполняются.

## Требования

**R1.** Независимые разрешения на Расчёты, Хранение, Инвентаризацию, FBS, Честный знак и Настройки в существующей модели сотрудников.

**R2.** Меню и прямые маршруты учитывают право; API запрещает чтение и изменения запрещённого раздела.

**R3.** Администратор сохраняет доступ. Переход существующих сотрудников не расширяет их прежние эффективные права и не лишает разрешённой работы без изменения настройки.

**R4.** Разрешения действуют на веб и ТСД; сохраняются границы клиентов. Инвентаризация включает просмотр, создание и работу с документом; отдельное разделение просмотра/создания владелец не потребовал.

**Граница существующих прав.** Право FBS открывает штатную работу с заказами, подбором, упаковкой и правилами остатка. Административная настройка привязки складов маркетплейса остаётся за администратором: разделное право FBS не расширяет эту уже существующую границу.

## Проверки

| Проверка | Вердикт |
|---|---|
| C1: проверить R1 на собранной реализации | Локально выполнено: четыре новых поля БД и API вместе с прежними `settings` и `inventory`; интерфейс настроек меняет каждое право отдельно. `tsc` и production build прошли. |
| C2: проверить R2 на собранной реализации | Локально выполнено: API-тест с прежним токеном проверяет выдачу и отзыв всех шести прав, а также чтение привязок для FBS без доступа к их настройке. Товарные маршруты ЧЗ (обзор, список и печать кодов) закрыты для сотрудника только с FBS. Адресный тест кодов подтверждает, что история ЧЗ закрыта без права ЧЗ, а артефакт этикетки и лента PDF недоступны для свободного кода без документа упаковки; с правом ЧЗ эти действия разрешены. В браузере локального стенда проверены отдельные флажки настройки и вход синтетического сотрудника только с FBS: FBS виден и открывается, «Расчёты» и «Настройки» скрыты, прямые маршруты `/app/ff/billing` и `/app/ff/settings` показывают «Нет доступа». |
| C3: проверить R3 на собранной реализации | Частично проверено: администратору возвращаются все права; миграция переносит старое `inventory` в `storage`, `packaging` в `fbs`, сохраняя прежний эффективный доступ. Ведущий агент применил миграции 0566/0567 к отдельной локальной PostgreSQL-базе; действующие аккаунты в production не затрагивались. |
| C4: проверить R4 на собранной реализации | Частично проверено: тест API подтверждает изоляцию разделов FBS и ЧЗ, хранения и инвентаризации, а API инвентаризации использует одно право на просмотр, создание и работу. После штатной печати кода в документе упаковки сотруднику только с FBS доступны артефакт этикетки и лента PDF этого кода. Нативный клиент разбирает права `/auth/me`, скрывает и запрещает разделы FBS/инвентаризации при explicit false; совместимость со старым сервером проверена адресными тестами. Мобильный код сохранён в `8f9f4b35a9eab3d52d9422ae15b1f58e1d7859c0`, независимое ревью пройдено. На физическом ТСД вход сотрудником не проверялся. |

## Заключение

Локальная реализация, автоматические проверки и короткая браузерная проверка на синтетическом сотруднике выполнены. Независимое ревью Sol и повторная проверка исправлений пройдены на SHA `b3284895fc6a2522659b36276c6db1896db72d15`. Мобильный клиент проверен кодом и адресными тестами; его независимое ревью пройдено, финальные хеши совпали с сохранённым коммитом. Производственная проверка ролей на физическом ТСД не выполнялась. Выкладка и работа с настоящими заказами в эту проверку не входят. По команде владельца от 30.09.2026 публикация новых изменений и деплой остановлены.
