# WMS-654 · Настраиваемые стороны и ярусы при создании ячеек

**Версия постановки:** 2 от 05.10.2026.

**Источник:** чат 689889703, сообщения #56, #57, #58, #61, #62, #63.

**Версия исходного описания:** `444ea612f668db597e25`. Подтверждение автора: сообщение #62.

## Исходный запрос и уточнение владельца

Клиент использует буквенные ряды А, Б, В, Г, Д. Каждый ряд для него отдельный:
деление на левую и правую стороны не требуется, но нужны ярусы. В существующем
окне создания ячейки нужны два независимых флажка — для сторон и для ярусов —
и составное имя ячейки из выбранных частей адреса.

Уточнение владельца от 05.10.2026: сначала показать кликабельный React-макет,
который наследует текущий экран «Ячейки» без иных изменений. После просмотра
макета владелец отдельно решит, продолжать ли продуктовую реализацию. Это
уточнение не разрешает менять рабочий экран, сервер или данные на текущем этапе.

## Проверенный существующий процесс

В действующем разделе «Ячейки» (`/app/ff/warehouse-map`, заголовок «Карта
склада») окно «Создать ячейку» содержит поле «Стеллаж», обязательный выбор
стороны 1 или 2, поле «Позиция», подсказку о следующей свободной позиции и
предпросмотр кода ячейки. Отдельного поля яруса нет. В таблице уже существуют
адреса вида «А 1.1»; для них хранятся собственные уникальные коды и штрихкоды.

На первом этапе предмет задачи — только кликабельный макет этого окна в контексте
текущего React-экрана. Макет нужен для проверки поведения и расположения полей,
а не для записи данных.

## Требования

### R1. Сначала — кликабельный React-макет

До продуктовой реализации подготовить кликабельный React-макет на основе
текущего экрана «Карта склада». Внешний вид и поведение остального экрана не
менять. Макет не вызывает рабочие API и не создаёт, не изменяет и не удаляет
ячейки.

### R2. Два независимых флажка

В существующем окне «Создать ячейку» макет показывает два независимых флажка:

1. «Учитывать стороны».
2. «Учитывать ярусы».

Каждый флажок переключается независимо от другого. Макет должен позволить
просмотреть все четыре сочетания: без сторон и ярусов, только стороны, только
ярусы, стороны вместе с ярусами.

### R3. Поля зависят от выбранных измерений

Если включён флажок «Учитывать стороны», оператор выбирает сторону 1 или 2. Если
он выключен, сторона не запрашивается и не входит в имя новой ячейки.

Если включён флажок «Учитывать ярусы», оператор указывает ярус. Если он выключен,
ярус не запрашивается и не входит в имя новой ячейки.

Существующие поля ряда (сейчас оно называется «Стеллаж») и позиции остаются
частями адреса при любом сочетании флажков.

### R4. Составное имя и предпросмотр

Имя новой ячейки составляется в порядке: ряд, сторона при её использовании,
ярус при его использовании, позиция. До создания оператор видит итоговое имя,
и оно сразу меняется при переключении флажков или вводе значений.

Точные разделители между частями адреса должны продолжать визуальный стиль
действующих адресов WMS. Утверждать отдельный новый формат по одному примеру
в постановке не требуется: кликабельный макет должен сделать выбранное
представление видимым владельцу до решения о продолжении.

### R5. Подсказка следующей свободной позиции

Существующую подсказку следующей свободной позиции сохранить. В будущем рабочем
поведении она должна рассчитываться в пределах выбранного ряда и только тех
измерений, которые включены флажками. На этапе макета достаточно показать
понятное изменение подсказки при смене выбранных измерений без обращения к
рабочим данным.

### R6. Остальное остаётся неизменным

Новый отдельный экран не создаётся. Таблица ячеек, поиск и фильтры, печать
этикетки, действующие права доступа и остальные действия раздела остаются без
изменений. Уже созданные ячейки, их имена, уникальные коды и штрихкоды не
переименовываются и не пересобираются.

### R7. Решение о продолжении принимает владелец

После демонстрации кликабельного макета зафиксировать решение владельца.
Изменение продуктового кода и данных допускается только после его отдельной
команды продолжить работу.

## Продуктовое решение

Флажки размещаются внутри уже существующего окна «Создать ячейку», потому что
они меняют способ задания адреса, а не вводят новый процесс. Макет наследует
текущий экран и существующие компоненты: это позволяет сравнить только требуемую
развилку и не маскирует её попутным редизайном.

Точные значения флажков по умолчанию и окончательное визуальное представление
составного имени не закрепляются до просмотра макета владельцем: эти решения
влияют на привычный сценарий создания ячейки, поэтому должны быть видны в
кликабельном варианте до разрешения продуктовой реализации.
