## 2. Что проверено ведущим 29.09.2026 (эмулятор, APK18, локальный стенд с кодом прода 9f92acee)

- Приёмка «Передано на склад» открывается экраном коробов (`inbound/{id}/boxes`: «План N коробов · Создано 0 · Нет созданных коробов»). «К приёмке товара» уходит на экран приёмки с `popUpTo(boxes, inclusive)`, поэтому «назад» с приёмки ведёт в общий список.
- «Создать короб» на экране приёмки **ничего не создаёт**: только открывает экран коробов с «Нет созданных коробов»; дальше «+ Добавить короб», затем «Короб №N · наполнять →» — три действия.
- После «Закрыть короб» экран приёмки просит «Отсканируйте штрихкод короба»; нового короба на месте нет, только через «Короба (N)».
- Во втором коробе строка показывает итог по всем коробам («3 / 10») — суммирование есть. Окно количества показывает только «План» и «Количество в короб №N»; нет «в других коробах» и «осталось», в строке не видно количество в текущем коробе.
- «5 из 5», план меняется вслед за вводом, строка всегда зелёная — **правило сервера для приёмок, созданных самим ФФ** (WMS-440/473/534: одно число — план и факт); демо-приёмки были засеяны от имени ФФ. На приёмке, созданной селлером, проверено: 5/10 → 3/10, план в базе 10. Поведение приёмок ФФ не меняется.
- «Завершить пересчёт» доступен на нетронутой приёмке `submitted`; сервер `409 not_verifying`, приложение показывает сырой код.
- «24 не пишется» — настройка эмулятора (hw.keyboard=no), исправлено в эмуляторе.
- Сервер отдаёт в `GET /operations/inbound-intake-requests/{id}` короба с составом по товарам (`boxes[].lines[].quantity`, `is_open`) — **правок бэка нет**.

## 3. Требования

- **R1. Сразу к товарам.** Открытие приёмки «Передано на склад» или «В приёмке» из списка ведёт прямо на экран приёмки товара (список товаров). Промежуточного экрана коробов нет; «назад» с приёмки — в список приёмок.
- **R2. Короб в одно касание.** На экране приёмки кнопка «Создать короб» создаёт короб на сервере и сразу делает его активным: вверху «Короб №N», сканы и ручной ввод идут в него. Никаких «Добавить короб» и «наполнять» после этого. Кнопка доступна, пока сервер разрешает создание коробов (как сейчас: `submitted`/`receiving`).
- **R3. Закрыл — следующий.** «Закрыть короб» (с подтверждением как сейчас) возвращает на тот же экран приёмки без активного короба, где сразу доступны «Создать короб» и «Приёмка без короба»; скан штрихкода существующего короба по-прежнему открывает его.
- **R4. Счётчики по коробам.** При активном коробе строка товара показывает общий план, сколько уже принято в других коробах и без короба, и сколько лежит в текущем коробе; окно количества показывает «План всего», «Уже в других коробах», «Осталось» и поле «В этом коробе». Сохранение меняет количество только в текущем коробе; итог строки = сумма коробов + без короба (серверное effective). Позиции, где итог достиг плана, зелёные.
- **R5. Короба на экране приёмки.** На экране приёмки виден список коробов (номер, открыт/закрыт, сколько штук) и общий итог; тап по коробу делает его активным (закрытый — переоткрывает, если сервер позволяет). Отдельный экран коробов может остаться для печати/удаления, но не как обязательный шаг.
- **R6. Завершение.** «Завершить пересчёт» не показывается, пока на приёмке ничего не принято (сервер ответит `not_verifying`); коды сервера `not_verifying` и другие коды завершения показываются по-русски («Сначала примите хотя бы один товар» и т. п.).
- **R7. Остальное не меняется:** правило «одного числа» для приёмок ФФ, приёмка без короба, сканирование, сводка завершения B4, сортировка, серверный код.
