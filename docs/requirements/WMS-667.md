# WMS-667 · Фильтр товаров с фактическим остатком в каталоге

Источник: чат -1004441620578, сообщения #205, #206, #211, #224, #230.
Версия описания: `169df20e4ada819c9aa2`. Подтверждение автора: #230.

Исходное подтверждённое описание ниже сохранено без изменения смысла. Текущее
поручение владельца от 06.10.2026: независимая постановка по существующей задаче,
конкретные проверки для отдельного тестировщика; без реализации, изменения

## Ожидаемое поведение

В существующем разделе «Каталог» добавить к текущим фильтрам возможность показать только товары, у которых фактический остаток на фулфилменте больше нуля. Фильтр должен работать по всему каталогу до разбиения на страницы и сочетаться с уже существующими фильтрами по селлеру, маркетплейсу, категории и поиском. Так оператор сможет выбрать клиента в фильтре «Селлер» и увидеть, какие его товары реально есть на остатке. Использовать нужно тот же показатель фактического остатка, который уже отображается в колонке «Остаток»; настройку публикации и передачи остатков FBS этот фильтр не меняет.

## Проверки

### Требования

- **R1.** В текущем блоке фильтров каталога оператор может включить отбор
  «С остатком». Включённый отбор оставляет только товары с фактическим
  отображаемым остатком строго больше нуля; выключенный возвращает прежнюю
  выборку с сохранением остальных выбранных фильтров. Новый экран не нужен.
- **R2.** Критерий равен `quantity > 0` из
  `/operations/inventory-balances/summary`, которое экран показывает как
  `stock_on_hand` в колонке «Остаток». Это существующий расчёт остатка организации
  `organization_stock_totals_by_product(...).on_hand`, а не доступное количество,
  резерв, остаток в конкретной ячейке или публикуемый остаток FBS. Товар с
  положительным остатком и нулевым либо отрицательным доступным количеством
  остаётся в выборке. Отсутствие остатка означает ноль.
- **R3.** Сервер применяет критерий ко всей подходящей выборке до `limit/offset`
  (разбиения на страницы). `items` и `total` описывают один и тот же отбор;
  положительный товар за пределами первоначальной страницы не теряется.
  Существующие значения `scope_total` и списка категорий сохраняют свой смысл.
- **R4.** Отбор сочетается по условию «и» с селлером, маркетплейсом, категорией
  и поиском. Существующий фильтр «Передача остатков» сохраняется и может
  использоваться одновременно. Границы организации и существующие права доступа
  сохраняются. Переключение отбора на поздней странице начинает показ с первой
  страницы новой выборки, как изменение остальных фильтров.
- **R5.** Фильтр только читает данные: не меняет настройки передачи остатков FBS,
  лимиты оператора, резерв, учёт остатка и расположение товара. Товар на сортировке,
  в ячейке или таре оценивается по тому же общему остатку, который уже показан
  оператору. Внешних операций маркетплейса при фильтрации нет.

### Подтверждённый текущий код и экран

Проверено на свежем `origin/etalon`
`0f1460b023700a99f17b504d6af3934a02bc68cc` и сохранённых требованиях задачи.
`frontend/src/screens/v2/FfProductsCatalogScreen.tsx` получает страницу через
`GET /products/ff-catalog-page`, затем сводку только для товаров этой страницы;
значение `quantity` превращается в `stock_on_hand`. Блок фильтров уже содержит
поиск, селлера, маркетплейс, передачу остатков и категорию.

`backend/app/api/products.py::get_ff_catalog_page` передаёт отбор в
`backend/app/services/seller_wb_catalog_service.py::list_linked_wb_catalog_page_rows`.
Сервис считает `total` до пагинации и сортирует по `sku_code, id`; критерия
фактического остатка пока нет. Источник показателя —
`backend/app/api/inventory_balances.py::get_inventory_balances_summary` и
`backend/app/services/fbs_stock_availability_service.py::organization_stock_totals_by_product`.
При реализации требуется переиспользовать существующую семантику расчёта,
не заводя второй независимый источник остатка.

Браузерная проверка пока не выполнена: существующая вкладка группы «WMS staging»
занята другой сессией автоматизации. Авторизацию и секреты не использовали,
новый стенд не запускали. Выбор места фильтра основан на прочитанном коде;
визуальную проверку нужно выполнить при последующей приёмке.
