## 3. Требования

**R1. Ни при какой ошибке фронта пользователь не видит служебного текста.** Страница
react-router по умолчанию, стек, английские сообщения, коды и имена функций — никогда, ни в
портале фулфилмента, ни в портале селлера. Проверяется и на ошибке при отрисовке, и на ошибке
в эффекте, и на ошибке в ленивой подгрузке кода маршрута (`Failed to fetch dynamically
imported module` после выкатки).

**R2. Ошибка одного блока не убивает приложение.** Перехватчики (React ErrorBoundary,
классовый компонент — иначе в React их не сделать) стоят: (а) на корневом маршруте каждого
портала как `errorElement`/обёртка — последний рубеж; (б) вокруг содержимого каждого
раздела (элемент каждого `Route` в `App.tsx` и `SellerApp.tsx`); (в) вокруг содержимого
рабочего места поставки FBS `FfFbsSupplyWorkspace` (место падения) и вокруг тела остальных
крупных окон-диалогов, где это делается одной обёрткой без переписывания окна. Меню, шапка и
соседние разделы при ошибке одного блока продолжают работать.

**R3. Самовосстановление до показа чего-либо.** Поймав ошибку, перехватчик молча
перемонтирует упавшее поддерево (сброс ключа) — один раз сразу и ещё раз через короткую
паузу (порядка 1–2 с), потому что для рассинхрона DOM (translate/расширения) перемонтирование
лечит. Только если тот же перехватчик упал третий раз за короткое окно (порядка 30 с) —
показывается запасной вид.

**R4. Запасной вид — одна человеческая фраза в стиле приложения.** MUI `Alert` (или
существующий компонент состояния ошибки, если такой есть в `docs/UI_DESIGN_SYSTEM_RU.md`)
с текстом вида «Не удалось показать этот раздел. Обновите страницу.» и кнопкой «Обновить»
(перезагрузка страницы). Для корневого рубежа — та же фраза на пустой странице с логотипом,
как у существующих экранов входа/загрузки (`ProfileLoadingScreen`, `SubscriptionBlockedScreen`
— взять за образец оформления). Никаких стеков, кодов, ссылок на документацию, английских слов.
Для ошибки подгрузки чанка после выкатки — сразу автоматическая перезагрузка страницы один
раз (с защитой от бесконечного цикла через `sessionStorage`), без показа чего-либо.

**R5. Журнал ошибок фронта на сервере.** Новая ручка `POST /client-errors`
(`backend/app/api/client_errors.py`, логика в `backend/app/services/client_error_service.py`):
принимает JSON `{message, stack, url, screen, component, action, user_agent, app_build}`
(строки, лимит на размер каждого поля и всего тела ~16 КБ, лишнее обрезать, не отвергать),
требует обычную авторизацию, пишет одну запись в серверный журнал уровня ERROR с
префиксом `client error` и полями `tenant_id`, `user_id`, `role`, `url`, `screen`,
`component`, `action`, `message`, первые ~40 строк `stack`. **Без новой таблицы** — журнал
контейнера уже собирается (`docker logs`), этого достаточно, чтобы увидеть причину;
таблицу заводить запрещено. Ограничение частоты: не более ~20 записей в минуту на пользователя
(простой счётчик в памяти процесса), сверх — 204 без записи. Ответ 204. Ошибки самой ручки
никогда не 500 наружу.

**R6. Фронт отправляет всё пойманное.** Один модуль `frontend/src/utils/clientErrorReport.ts`:
`reportClientError(error, {screen, component, action})` — fire-and-forget `fetch` с текущим
токеном (`apiUrl`, `authHeaders` как у соседей), с дедупликацией одинаковых сообщений в
пределах минуты и без исключений наружу (сбой отправки глотается). Вызывается: из каждого
перехватчика (при каждой поимке, включая успешно восстановленные — иначе причина падения
17-го числа так и останется неизвестной), из `window.addEventListener('error')` и
`window.addEventListener('unhandledrejection')` (регистрация в `main.tsx` обоих порталов).
Никакого UI у этих обработчиков нет.

**R7. Запрет автоперевода.** `frontend/index.html`: `lang="ru"` (как у селлера),
`translate="no"` на `<html>` и `<meta name="google" content="notranslate">` — в обоих
`index.html`. Это гигиена, не «причина» — владелец прямо сказал, что причина — само
появление ошибки; поэтому R1–R6 обязательны независимо от R7.

**R8. Ничего лишнего.** Не менять поведение экранов, не трогать WMS-477 (в ветке он
отреверчен и возвращается отдельно), не заводить новые таблицы, статусы, настройки в UI. Не
переписывать существующие компоненты ради обёртки — обёртка снаружи. Тексты — по-русски,
человеческие, без техножаргона.

## 5. Заключение

**Принято ведущим к выкатке 20.09.2026** (аналитик не вызывался по поручению владельца «сам экономь ресурсы»; перекрёстное ревью не проводилось — по тому же поручению; владелец может запросить его отдельно). Проверено руками в браузере: одиночная ошибка раздела гасится молча (C1), устойчивая — заменяется одной человеческой фразой с кнопкой при живом меню (C2), каждая поимка и ошибки окна уходят в журнал API с текстом, стеком, экраном и пользователем (C5, C6). Гейты ruff/mypy/pytest/tsc/build/vitest пройдены (C10); два падения `FfInboundRequestView.test.ts` существуют в etalon до этой ветки и к задаче не относятся. Не проверено в браузере: корневой рубеж (C3), перезагрузка при ошибке чанка (C4), портал селлера (C8), рабочее место FBS (часть C11) — по коду и тестам. В ветке отреверчен WMS-477; его возврат — отдельно, после того как журнал ошибок покажет причину падения 20.09.
