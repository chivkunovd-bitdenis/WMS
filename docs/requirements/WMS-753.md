# WMS-753 · Вход на сайт по ФИО и паролю — те же учётки, что на ТСД

**Статус:** ХОТФИКС, ДОГОН НЕ ЗАВЕРШЁН. Ветка hotfix/wms-753 от прода aa3267904 (hotfix/wms-752).

## Запрос владельца (10.10.2026)

АртМакс (Максимус) не смог войти с ноутбука под учётками сотрудников, заведёнными для ТСД. Владелец: «Надо чтобы работали учетки везде».

## Баг

Сотрудников ФФ заводят по ФИО и паролю без почты (форма «Добавить пользователя» почту не спрашивает), ТСД входит по ФИО через /auth/login-by-name. Страница входа на сайте с 14.09.2026 (a5520fb4b «restore email login for all portals») принимает только почту: поле type=email и только /auth/login. Сотрудник без почты в браузер не входит вообще. Сервер вход по ФИО поддерживает.

## Требования

- R1. На странице входа одно поле «Email или ФИО». Есть «@» — вход по почте как раньше (/auth/login с portal). Нет «@» — вход по ФИО и паролю (/auth/login-by-name), как на ТСД.
- R2. Учётка и пароль сотрудника одни и те же на ТСД и на сайте. Остальное на странице входа не меняется.

## Проверки

| Проверка | Класс | Вердикт |
|---|---|---|
| C1. Локальный стенд: сотрудник без почты, созданный формой ФФ, входит на сайт по ФИО (в нижнем регистре) и паролю | разово | выполнено 10.10: вошёл, в шапке его ФИО и должность |
| C2. Локальный стенд: администратор входит по почте и паролю | разово | выполнено 10.10: вошёл, полное меню |
| C3. Тест на вход по ФИО со страницы входа | навсегда | не написан — догон |
| C4. Прод после выкладки: страница входа показывает «Email или ФИО», бандл содержит login-by-name | разово | см. заключение |

## Заключение

Хотфикс по прямому слову владельца, без аналитика и ревью. Догон: возврат в etalon, тест C3, ревью и приёмка.
