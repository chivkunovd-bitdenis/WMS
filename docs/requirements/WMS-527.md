# WMS-527 · Выпустить остатки и печать КИЗ без вывода из оборота

Запись задачи: [канонический бэклог, WMS-527](../KANONICHESKIY_BACKLOG.md#wms-527).

## 1. Исходный запрос

> Нужно напротив влить всё кроме вывода кизов из оборота.

В контексте предыдущего перечня «всё» означает WMS-469, WMS-514 и ещё не влитый
legacy guard WMS-476. WMS-517 — вывод КИЗ из оборота — исключена целиком.

  В нём уже находятся WMS-469 и WMS-514, слитые через PR #251, и совместимые
  WMS-519/520/523.
- Проверенный production baseline —
  `3c90970b132144f9b375b5967b40f857c9af38a3`; он является предком
  `origin/etalon`. Перед deploy production SHA перечитывается заново.
- Legacy guard WMS-476 находится в `origin/codex/wms476-auto-legacy-guard`;

## 3. Требования

### R1. Состав кандидата

Кандидат строится от актуального `origin/etalon`. В него входят:

1. WMS-469 — принятое распределение остатков по связкам складов, независимые
   WB/Ozon, число/процент и `min(лимит оператора, свободный остаток)`;
2. WMS-514 — три галки в существующей строке WB FBS, шесть режимов, инертный `000`,
   точный КИЗ и прежний QR→КИЗ;
3. legacy guard WMS-476 — неполный старый `/import` атомарно отвечает
   `422 manual_import_product_required` до любых записей; полностью назначенный
   ручной импорт и `/import/auto` продолжают работать.

### R2. Сохранить уже выпущенное

WMS-519/520/523 не реализуются заново. Сохраняются исправление геометрии
сохранённого PDF/PNG, preview/manual import при нескольких пулах одного GTIN,
отдельные auto/assign-пулы и общие catalog/package counts без дублей.

### R3. WMS-517 полностью отсутствует

PR #247/#248 не сливаются и не используются как база. В diff, staging и production
не попадают WMS-517 API/UI, withdrawal ledger/models/migrations, True API,
CryptoPro/`cadesplugin_api.js`, worker/beat, Redis-limiter, Railway-конфигурация и
production-submit flags. Действия вывода из оборота и внешних withdrawal-вызовов нет.

### R4. CI исправляется по существу

Все пять известных падений закрываются без формального повышения query limit,
удаления проверок или ослабления независимого сохранения WB/Ozon. После последнего
изменения выполняются адресные тесты WMS-469/476/514/519/520/523 и один полный PR CI.
Неизменившиеся зелёные проверки и review без нового diff повторно не гоняются.

### R5. Staging

На staging разворачивается exact SHA с миграциями. В браузере проверяются:

- WMS-469 в FF и seller: блоки WB/Ozon, число/процент, сохранение и повторное открытие;
- WMS-514 в WB FBS: ровно три галки, `000`, выбор единицы, отсутствие новых окон,
  сохранность QR→КИЗ;
- WMS-476 на тестовых данных: старый неполный запрос не пишет ничего, полностью
  назначенный импорт проходит.

Если реально доступны настроенные принтер и сканер, дополнительно проверяются тихая
печать QR/нового ЧЗ/точной копии и считывание полного КИЗ. Если недоступны, это
остаётся явно непроверенной физической границей, а не объявляется PASS по тестам.

### R6. Merge и production

После зелёного CI, перекрёстного review и аналитической приёмки PR вливается в
`etalon`. Production разворачивается из exact merge SHA. После deploy проверяются
checkout/version, ancestry от `3c90970b` и merge SHA, миграции, `/api/health`, корень,
seller-портал и безопасный browser smoke WMS-469/WMS-514.

## Заключение

Разработчик собрал локально проверенный кандидат от `75c1bff5`: перенёс только
legacy guard WMS-476, сохранив создание отдельных пулов WMS-523. Пять прежних
CI-падений воспроизведены и закрыты в тестовой инфраструктуре: измеритель SQL
считал фоновую публикацию fixture, а HTTP harness вызывал удалённый старый
frontend saveRule. Продуктовые stock/print/WB/Ozon потоки не менялись.

После последнего изменения кода прошли `ruff check .`, `mypy .` (473 файла),
`pytest -q -n auto tests/test_wms469_stock_dialog_backend.py
tests/test_wms476_auto_marking_import.py tests/test_wms514_scan_auto_print.py
tests/test_wms417_stock_http_contract.py tests/test_fbs_worklist_query_count.py
tests/test_fbs_worklist_search.py tests/test_marking*.py` (218 passed, 7 skipped —
PostgreSQL row/advisory locks и сериализация конфликтов не проверяются SQLite).
Frontend: `npx tsc --noEmit -p tsconfig.app.json`, `npm run build` и семь
адресных unit suites (fbsStockBlocks, fbsStockDialogLoader, fbsStockDialogSession,
FfFbsSupplyWorkspace.wms514, markingImportMerge, markingAvailability,
markingPrintPresets) — 92 passed.

Это технические результаты разработчика, не заключение аналитической приёмки.
Полный PR CI, перекрёстное review, staging/browser, физическая печать и production
пока не проверены. Частичное добавление инфраструктуры WMS-517 также считается
нарушением задачи.
