# WMS-731 · FBO: печать листа подбора на вкладке «Подбор» — полный или только выбранные ячейки и короба

Статус: приёмка аналитика проведена 09.10.2026 после реализации и независимого ревью;
полностью не принято — C17 нарушено, C18–C19 не проверены полностью (подробности в заключении). Пакет поручений владельца от 09.10.2026: WMS-716…WMS-734.
Главная задача FBO по второму сообщению владельца. Коммиты и публикацию выполняет ведущий.

## 2. Существующий процесс и цель изменения

Сотрудник фулфилмента (ФФ) открывает документ FBO — отгрузку на маркетплейс — в разделе
«Отгрузки на МП» и работает на вкладке «Подбор». Он должен получить бумажную таблицу мест,
где лежат товары этой отгрузки, в выбранной группировке; при необходимости ограничить её
галками ячеек и тары. Печать — чтение данных, а не подтверждение подбора.

### 2.1. Основа задачи и проверенные факты кода

Проверено чтением файлов **текущего worktree**, ветка `feat/wms731-fbo-pick-list`, исходный
HEAD `4c7ddf0b5dd96766130196f1a3cc5161daaf4a66`. Это продолжение реализации WMS-686 с
исправлением WMS-733 (`ab3eeb2df`), а не старый подбор из etalon. По поручению ведущего
задача строится поверх этих изменений; переходить на etalon без них нельзя. Источники
решений по старшинству: [WMS-686-decisions-2026-10-09.md](WMS-686-decisions-2026-10-09.md),
[WMS-686-owner-review-2026-10-08.md](WMS-686-owner-review-2026-10-08.md), актуальная редакция
[WMS-686.md](WMS-686.md). Их решения о подборе, упаковке и КИЗ эта задача не пересматривает.

- `frontend/src/screens/ff/FfSuppliesShipmentsPage.tsx`: вкладки «Товары», «Подбор»,
  «Упаковка» остаются раздельными. В «Подбор» встроен `FfUnloadPickPage` с идентификатором
  текущей отгрузки. Интерфейс допускает вкладку при submitted, confirmed, collecting;
  серверный `pick-options` допускает только confirmed и collecting. Это существующее
  расхождение границ доступности, не основание расширять статусы в WMS-731.
- `frontend/src/screens/ff/unload-pick/FfUnloadPickPage.tsx`: документ и места загружаются
  отдельно; состав FBO берётся из строк отгрузки. Для FBO передаются `fboMode` и ключ
  состояния документа; для FBS используется тот же компонент без нового поведения FBO.
- `UnloadPickScreen.tsx`: для FBO уже есть переключатель «По ячейкам / По товарам».
  При отсутствии сохранённого вида установлен «По ячейкам». `fboPickState.ts` сохраняет
  вид, раскрытия и источник сканирования в памяти браузерной вкладки по документу.
- `FbsCellPickTable.tsx`: ячейки и тара раскрываются, есть «План», «Осталось», «КИЗ»,
  «Остаток в коробе», «Собрано» и отдельный раздел «Уже подобрано». `PickPlacesTree.tsx`
  раскрывает места под товаром; показывает ячейку, цепочку тары и товар. Раскрытие — только
  видимость строк, источник сканирования — отдельное состояние. Галок для печати нет.
- `pickRows.ts`: реальное место — россыпь на ячейке либо самый внутренний объект тары;
  палета и короб на ней образуют путь, а не два независимых остатка. Есть существующие
  обозначения «Россыпью», «Без ячейки», «Без ячеек» и товар без мест («Нет на складе»).
  `cellPickRowsOf` размещает уже подобранное отдельно; свёрнутые строки остаются в данных.
- `backend/app/api/marketplace_unload_requests.py`, `get_marketplace_unload_pick_options`:
  GET `/operations/marketplace-unload-requests/{id}/pick-options` возвращает план и подбор
  товара, ячейки и источники. `container_path` содержит виды, идентификаторы и номера тары;
  `quantity` — физическое количество источника, `available` — доступное, `picked` — снятое
  отсюда. При выключенном адресном хранении `locations` пусты. Права и границы клиента
  проверяет существующий серверный путь; печать их не расширяет.
- `backend/app/services/marketplace_unload_pick_service.py`, `get_pick_options`: получает
  только товары плана данной отгрузки и места её склада. Подбор по товару считается
  отдельно от количества в коробах отгрузки (`boxed_qty`).
  `pick_option_location_service.py` сохраняет также источники с `quantity=0`, если из них
  уже подбирали. В листе нельзя повторно вычитать `picked` из физического `quantity`.
- `FfUnloadPickPage.tsx` преобразует физический остаток в `place.qty`; `pickRows.ts`
  вычисляет план и оставшуюся потребность, `FbsCellPickTable.tsx` показывает их отдельно.
  Это основание для смысла чисел в листе, а не для автоматического выбора, сколько брать
  из каждого короба. Исправление WMS-733 различает подобранное и уложенное в короба;
  использовать количество в коробах вместо подбора для листа нельзя.
- В перечисленных компонентах FBO нет кнопки или шаблона листа подбора. У FBS есть отдельный
  шаблон `frontend/src/screens/v2/fbsUx.ts`, `buildFbsPickingListPrintHtml`; его колонки
  связаны с заказами FBS и не задают структуру листа FBO.

### 2.2. Границы подтверждённого

**На экране не проверено:** действительный вид вкладки, доступность кнопок, раскрытия,
эталон «Ячейки»/«Расчёты»/«Инвентаризация», печатное представление и бумага. У аналитика
нет браузера и доступа к боевой базе. Факты выше подтверждены кодом, не действием оператора.

В черновике ведущим зафиксированы исторические сведения: WMS-686 находилась в ветке
`claude/wms686-fbo-impl`, была выложена на стенд, в etalon `61012808c` не была влита;
на проде `694de0413` был подбор от товара без переключателя, печати листа FBO не было
ни на проде, ни на стенде. Здесь это сохранённые сведения ведущего, **повторно не проверенные**,
а не утверждение о текущей версии среды. Обновление remote, проверка выкладки и выпуск —
задачи ведущего, не действия аналитика этой постановки.

## 3. Требования

В каждом пункте отдельно заданы условие, действие, результат и основание. D1…D8 — решения
аналитика из раздела 4; они не являются дословными словами владельца.

**R1. Кнопка в контексте подбора FBO.** Условие: сотрудник ФФ открыл работающую вкладку
«Подбор» отгрузки FBO с загруженными данными. Действие: нажать «Печать листа подбора»
над таблицей, рядом с существующим переключателем вида. Результат: открывается печатное
представление этой отгрузки. Объект действия — открытая отгрузка; в шапке листа остаётся её
номер/название и селлер из текущего документа. Печатный лист обозначает принадлежность
к WB или Ozon по данным документа. Основание: «кнопка печати листа подбора» на этапе
подбора; AGENTS.md §3 (контекст действия и обозначение площадки); D1, D7.

**R2. Без галок — полный лист.** Условие: в текущем документе нет выбранных для печати
строк. Действие: печать. Результат: включены все товары плана и все их места подбора,
включая содержимое свёрнутых ячеек/коробов и нераскрытых товаров. Выбранный сканом источник
не ограничивает лист. После снятия всех галок следующее нажатие снова печатает полный
лист. «Полный» относится к этой отгрузке, а не ко всему ассортименту склада.
Основание: «если ничего не выбрано… лист подбора полный»; D2, D5.

**R3. Лист по товарам.** Условие: переключатель в положении «По товарам».
Действие: печать полного либо выбранного набора. Результат: разлинованная таблица
«Товар (название) → Ячейка → Короб/тара (номер) → Количество, шт». Один товар объединяет
свои места; полный путь вложенной тары сохранён. Идентификаторы товара, уже доступные
в подборе (артикул/SKU, размер при наличии), позволяют отличить одноимённые позиции.
Основание: дословное описание таблицы владельцем; D3, D4.

**R4. Лист по ячейкам.** Условие: переключатель в положении «По ячейкам».
Действие: печать. Результат: та же информация, сгруппированная «Ячейка → Короб/тара →
Товар → Количество, шт», в порядке ячеек и вложенных источников существующего подбора.
Меняется группировка, а не состав или числа выбранного набора. Без сохранённого выбора
вида остаётся установленное WMS-686 положение «По ячейкам».
Основание: «такая же таблица, только наоборот»; WMS-686 D1.1; D3, D5.

**R5. Галки на ячейках и таре.** Условие: любой из двух видов подбора FBO.
Действие: поставить/снять галку ячейки или короба/тары в существующей структуре.
Результат: меняется набор строк для печати; раскрытие и выбор источника сканирования
не меняются. В виде «По товарам» галка действует на места под данным товаром; в виде
«По ячейкам» — на товары плана в выбранном месте. Перенос набора между видами сохраняет
те же пары «товар + источник», не добавляет другие товары из того же короба. Частичный
выбор родителя обозначается обычным неполным состоянием галки.
Основание: «чекбоксами, именно ячеек и коробов», пример «под товаром только две ячейки»;
D2, D5; WMS-686 D1.1–D1.2.

**R6. Ячейка выбирается вместе с содержимым.** Условие: у ячейки есть строки товаров
в таре или россыпью. Действие: поставить галку ячейки, не ограничивая дочерние строки.
Результат: выбраны все её строки в указанном R5 контексте; пустая строка ячейки без
содержимого не является самостоятельной строкой подбора. Действие: выбрать только
конкретный короб или, после выбора всей ячейки, снять галки ненужных коробов.
Результат: печатается только оставшееся выбранное содержимое с названием родительской
ячейки; соседние невыбранные короба не попадают в лист. Галка короба не требует отдельного
повторного выбора родительской ячейки. Снятие галки родителя снимает его дочерний набор.
Основание: «ее одну я выбрать не могу», «тара печатается вся, если я явно не выбрал…
конкретную»; D2, D4.

**R7. Выбранное печатается без посторонних строк и дублей.** Условие: набор галок
непустой. Действие: печать. Результат: только выбранные строки товаров и источников плюс
их необходимые заголовки товара/ячейки/пути тары. Выбор палеты вместе с вложенным коробом
не дублирует товар этого короба; структурный родитель не добавляет своё второе количество.
Пример владельца — под одним товаром две ячейки с двумя выбранными коробами — не включает
третий короб, третью ячейку и другие товары, которые не выбирали.
Основание: «только выбранные мной строки», «структура остается та же»; D2, D4, D5.

**R8. Количества сохраняют смысл существующего подбора.** Условие: лист сформирован
из загруженных данных текущего подбора. Действие: читать товар и его источники.
Результат: «Количество, шт» у источника равно физическому остатку `quantity` (`place.qty`),
а не `available`, уже снятому или автоматически назначенному «взять». Для товара отдельно
сохраняются существующие «План» и «Осталось» (план минус фактически подобранное в этой
отгрузке, не минус уложенное в короба). Повторение этих чисел у разных источников не
превращает их в суммируемый итог. Отбор галками не пересчитывает план отгрузки.
Числа источников не уменьшаются второй раз на уже снятое; печать не распределяет оставшуюся
потребность автоматически. Основание: «где он лежит… количество штук», «эту таблицу… взять»;
существующая таблица WMS-686, различение подбора и упаковки WMS-733; D3.

**R9. Россыпь, отсутствующая ячейка и уже подобранное не теряются.** Условие:
в данных есть товар без короба, источник без адреса либо товар плана без мест.
Действие: полный лист или выбор соответствующего реального источника.
Результат: используются существующие обозначения: «Россыпью» вместо выдуманного короба,
«Без ячейки»/«Без ячеек» вместо выдуманного адреса, «Нет на складе» у товара без мест
(количество источника отсутствует, это не нулевой план). Ячейка только с россыпью
выбирает её строки; при выборе конкретного короба россыпь не добавляется автоматически.
Тара без адреса выбирается по самой таре. Уже подобранные позиции сохраняются в полном
листе отдельно от мест, из которых ещё подбирают, по существующему разделу «Уже подобрано»;
источник с нулевым физическим количеством и фактом подбора не объявляется положительным
остатком. Основание: полный лист R2, существующие состояния `pickRows.ts`; D4.

**R10. Выбор и повторная печать относятся к одному документу.** Условие: сотрудник
выбрал строки для печати. Действие: переключить вид, свернуть/раскрыть ветви, перейти
на соседнюю вкладку документа и вернуться либо повторно напечатать. Результат: выбранный
набор сохраняется, раскрытие не влияет на него. В пределах той же браузерной вкладки
обновление страницы восстанавливает набор этого документа по образцу состояния WMS-686;
у новой отгрузки набор не наследуется. После перечитывания печатаются текущие числа и
только существующие выбранные источники. Исчезнувшая выбранная строка не подменяется
другой по совпавшему названию; если выбранных строк больше нет, действует R2.
Основание: WMS-686 D1.2, AGENTS.md (продолжение после сбоя, границы документов); D5.

**R11. Печать не совершает складских операций.** Условие: выбор, печать, отмена
печатного диалога или повтор печати. Результат: неизменны остаток, резерв, расположение,
подбор, короба отгрузки, КИЗ (коды маркировки товара) и статус документа. Галка не сканирует
товар, не забирает короб целиком и не назначает коды. Следующий обычный скан работает
с прежним выбранным источником. Основание: AGENTS.md §3; D2, D6.

**R12. Ошибка печати оставляет путь продолжения.** Условие: не удалось открыть
печатное представление/подготовить лист либо актуальные данные подбора не загрузились.
Действие: попытка печати, затем исправление причины и явный повтор.
Результат: нет пустого листа, выдаваемого за успешно сформированный из незагруженных данных;
ошибка видна существующим способом в контексте подбора. Вид, галки и источник не стираются;
повтор использует актуальные галки (включая снятые после отказа), а не старый снимок выбора.
Отмена браузерной печати не блокирует подбор. Самостоятельной повторной отправки на
принтер нет; пользователь может повторить действие. Загруженный действительно пустой
план не равен ошибке загрузки: лист сохраняет шапку и пустую таблицу без выдуманных строк.
Основание: навык аналитика (сбой и восстановление), AGENTS.md §3; D6; случаи B05, B19, B20.

**R13. Читаемая печатная таблица.** Условие: короткий либо многостраничный лист,
длинные названия товаров/ячеек/тары, вложенная палета с коробами. Действие: открыть
печатное представление и распечатать. Результат: сетка различима, числа соответствуют
своим товарам и источникам; длинный текст переносится, не перекрывает соседние столбцы
и не обрезает номера коробов. Продолжение таблицы имеет понятные заголовки; нет хвостовой
пустой страницы из-за принудительного разрыва. Интерфейсные кнопки, поля ввода и списки
КИЗ не печатаются вместо таблицы. Основание: «прям разлинованную… таблицу», AGENTS.md §3;
D7; применимые риски B12, B16. PDF и физическая бумага проверяются отдельно.

**R14. Объём изменения ограничен FBO.** Условие: отгрузки FBO WB и Ozon, общий компонент
подбора используется также FBS. Действие: открыть подбор и воспользоваться листом.
Результат: одинаковые правила печати для FBO обеих площадок; новые галки и кнопка
включены только в контексте FBO. Существующие пути FBS, сканирования, упаковки, «ШК + ЧЗ»
и выгрузок сохраняются. Вкладки «Товары» и «Подбор» не объединяются, не появляется
зависимость от задания упаковки, ЧЗ, пропуска или завершённости подбора для печати.
Новых таблиц, журналов, статусов, экранов, настроечных окон и поясняющих подсказок нет.
Основание: отложенная владельцем WMS-734, WMS-686 D0.1, D0.3, D0.6, AGENTS.md §3; D1, D8.

## 4. Решения аналитика и вопросы владельцу

Это решения внутри заданного поведения, принятые по коду и действующей постановке;
экран при постановке недоступен. Они не расширяют процесс подбора или упаковки.

- **D1. Основа и место действия.** Закрыт вопрос черновика о базе: текущий worktree уже
  содержит WMS-686 и WMS-733. Кнопка — в существующей панели подбора рядом с видом;
  объединение вкладок отложено. Причина: действие над открытым документом и прямое
  поручение ведущего строить поверх WMS-686. Следствия: R1, R14.
- **D2. Выбор — дочерние строки источников.** Галка родителя выбирает содержимое; короб
  выбирает свои строки и необходимый адрес. Используется обычная иерархическая галка
  с неполным состоянием; выбирать пустой заголовок не требуется. Выбор для печати
  независим от выбранного сканером места. Причина: оба прямых условия владельца —
  ячейка не одна, без уточнения тары печатается вся. Следствия: R2, R5–R7, R11.
- **D3. Число у короба — сколько физически лежит; план отдельно.** Закрыт вопрос
  черновика «остаток, взять или оба»: печатается физическое количество у места и
  существующие «План»/«Осталось» товара. Автоматически назначать «взять» по источникам
  нельзя: текущий процесс оставляет выбор места оператору, владелец говорит «где он
  лежит» и предлагает взять таблицу. Доступность и остаток не смешиваются. Подбор для
  остатка плана берётся из фактов подбора, не из заполнения коробов (WMS-733).
  Следствия: R3, R4, R8. Это решение аналитика, не утверждение о просмотренном экране.
- **D4. Реальные источники без выдуманного адреса.** Закрыт вопрос черновика о россыпи
  и товаре без ячейки. Используются существующие обозначения и путь тары. Выбор вложенной
  палеты охватывает вложенные источники один раз; сам заголовок палеты не является
  вторым товарным остатком. Полный лист сохраняет также товары без мест и существующее
  отделение уже подобранного. Причина: код допускает эти состояния, «полный лист» не
  разрешает терять товар из плана и не разрешает выдавать уже снятое за новое место.
  Следствия: R3, R6, R7, R9.
- **D5. Контекст выбора сохраняется при смене вида.** Внутренний смысл выбора — строки
  «товар + источник» текущего документа. Галка под товаром ограничена этим товаром;
  галка общей ячейки выбирает товары плана в ней. Переключение только перегруппировывает
  тот же набор. Память выбора — по образцу WMS-686, в пределах браузерной вкладки и
  документа; серверный журнал выбора не нужен. Причина: пример владельца «под товаром»
  и WMS-686 D1.1–D1.2. Следствия: R2, R4, R5, R7, R10.
- **D6. Лист — самостоятельная операция чтения.** Повторная печать допустима; отмена
  диалога не является ошибкой подбора. Не нужна проверка конкурентного списания для
  самой печати, которая ничего не списывает; проверяется отсутствие вызовов изменения
  склада. Для подготовки данных допустим существующий путь чтения, без внешних API
  WB/Ozon/ЧЗ. При сбое сохраняется выбор, сообщение используется существующее.
  Следствия: R11, R12, R14.
- **D7. Формат — обычный лист таблицы.** Подготовка печатного представления и штатный
  диалог печати браузера не вводят отдельный продуктовый экран или окно настройки.
  Как рабочий формат используется A4 (как у существующего листа FBS); ориентация и ширины
  выбираются по читаемости обеих группировок. Шаблон FBS не переписывается. Фотографии,
  штрихкодовые этикетки и списки КИЗ в лист не добавляются: такого поручения нет.
  Шапка использует уже имеющиеся данные документа, без нового ввода. Следствия: R1, R13.
- **D8. Границы.** Сохранены текущие права и серверные статусы подбора; WMS-731 не
  исправляет их расхождения и не вводит новых проверок полноты/маркировки. WB и Ozon FBO
  используют один процесс по WMS-686, FBS нового поведения не получает. WMS-734 отложена,
  её документ не меняется. Следствия: R14.

Вопросов владельцу, меняющих бизнес-результат и не разрешённых источниками, не осталось.
Запись созвона по-прежнему недоступна; дополнительное поведение из неё не предполагается.
Визуальный вид и бумага — непроверенные результаты будущих проверок, не вопросы о намерении.
