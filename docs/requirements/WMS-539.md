# WMS-539 · ArtMaks: загрузить 876 ячеек склада из файла фулфилмента

Разовая загрузка данных, без изменения кода продукта. По прямому указанию владельца
(«Зачем аналитик, чтобы нахуй сделать импорт, блять, из файла?») выполнена ведущим
без отдельных аналитика, исполнителя и перекрёстного ревью.

## 1. Исходный запрос и уточнения

Исходный запрос, 26.09.2026:

> Смотри, это э, раскладка с кладов, у фулфилмента арт. Соответственно, нам нужно в точности
> вот так все создать. То есть создать с такими же названиями, типа ячейки, э, ну, ячейки. Вот,
> склады, наверное, разные создавать не нужно. Соответственно, у них, ну, они должны
> отображаться в системе, у них должны быть штрих-коды, все должно нормально на них
> сканироваться и спокойно раскладываться. Напиши, как посмотришь файл, все ли там понятно.

Уточнения владельца:

- «их в базе надо создать лядбь импортом»
- на вопросы о колонках файла, содержимом штрихкода, QR/ШК и старых ячейках:
  «1. ТОлько названия 2. У нас же есть генерация стандартрная штрихкодов блядь в системе, нет?
  надо сделоать сука чтобы в сортировке в подборе в отгрузке, в иинвентарке и где угодн, этот
  шк сканировался на 120% 3. Делаем ШК 4. Оставь как есть»
- о таре: «если в файле, блядь, есть тара, загрузи тару. Если нет, загрузи, блядь, без тары.»
- «Давай, делай быстрее импорт»

Часть «сканировался на 120 % везде» вынесена в [WMS-540](../KANONICHESKIY_BACKLOG.md#wms-540).

Источник: [artmaks-cell-addresses.xlsx](WMS-539/artmaks-cell-addresses.xlsx) — листы «Адреса»
(876 строк) и «Сводка». Тары в файле нет: ни номеров паллет или коробов, ни содержимого;
«Коробок на место» — вместимость (раздел «Вместимость коробок» на листе «Сводка»).

## 2. Требования

| № | Требование |
|---|---|
| R1 | На единственном складе ArtMaks «Основной» есть ячейка с каждым из 876 названий колонки «Адрес», символ в символ. Других складов не создаётся. |
| R2 | Каждая новая ячейка получает стандартный штрихкод системы (`LOC-` + 12 hex), созданный штатной `catalog_service.create_location`. |
| R3 | Из файла грузятся только названия; тара не создаётся. |
| R4 | Существующие ячейки `A 1.1`, `A 1.2`, `__SORTING__`, их остатки и паллеты не меняются. |
| R5 | Повторный запуск не создаёт дублей и не меняет штрихкоды. |
| R6 | Выдан PDF этикеток ШК (CODE128) 58×40 мм — системный размер по умолчанию: название ячейки, штрихкод, значение штрихкода. |
| R7 | Скан штрихкода новой ячейки находит именно её. |

Решение ведущего: размер этикетки — `DEFAULT_LABEL_SIZE_ID = '58x40'` из
`frontend/src/utils/labelSize.ts`. Паллетоместа О1/О2/ПС1/ПС2 — обычные ячейки;
паллеты ставятся в них стандартным механизмом.

## 3. Проверки

| Проверка | Требования | Вердикт |
|---|---|---|
| C1. Локальный стенд (etalon `7e0aa9fe`): прогон без записи, с записью, повторный с записью | R1, R2, R5 | подтверждено: создано 871 (5 были заведены раньше вручную), итого 876/876; повтор — 0 создано, штрихкоды не изменились |
| C2. Карта склада «Ячейки» на стенде | R1 | подтверждено в браузере: 876 строк с названиями из файла; скан `LOC-…` последней ячейки → «Ячейка ПС2-А2-09» |
| C3. Бой: прогон без записи | R1, R4 | подтверждено: склад «Основной», было 3 ячейки, к созданию 876, конфликтов 0 |
| C4. Бой: запись 26.09.2026 12:45:33–12:45:41 UTC | R1, R2, R3 | подтверждено SQL: активных 879 = 876 новых + 3 старых; все 876 в формате `LOC-[0-9A-F]{12}`; штрихкоды уникальны, совпадений с другими арендаторами 0 |
| C5. Бой: старые ячейки | R4 | подтверждено SQL: `A 1.1` — 3 шт, `A 1.2` — паллета П-000002, штрихкоды прежние |
| C6. Бой: распознавание скана | R7 | подтверждено: `resolve_warehouse_scan` и `resolve_any_scan` находят 876/876 по штрихкоду ([resolve_check.py](WMS-539/resolve_check.py)) |
| C7. PDF этикеток из боевых штрихкодов | R6 | подтверждено: 876 страниц 58×40 мм; все 876 штрихкодов при 203 dpi распознаны macOS Vision и совпали с боевыми; тексты совпали |
| C8. Живой скан напечатанной этикетки сканером ArtMaks | R7 | не проверено — нет доступа к складу |

## Заключение

Загрузка выполнена и проверена на бою (C1–C7). Не проверен живой скан бумажной этикетки
на складе (C8). Скан в русской раскладке на трёх экранах не работает — это WMS-540, не эта задача.

Скрипты: [import_cells.py](WMS-539/import_cells.py) (идемпотентный импорт, `--apply` для записи),
[make_labels_pdf.py](WMS-539/make_labels_pdf.py) (PDF этикеток), список названий
[artmaks_cells.json](WMS-539/artmaks_cells.json).
