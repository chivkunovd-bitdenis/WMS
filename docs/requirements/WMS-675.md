## Заключение

Блокер живого чтения снят реальными доказательствами. На11:31UTC Ozon подтверждает26 единиц; на11:36UTC WMS не провёл ни одной, поэтому адресная missingdelta26, а не31. После полного разрешённого восстановления ожидаются резерв16→1, 26 движений/проведённых ledger, 26 фактов и по26 единиц активных начислений `fbs_order`/`packing`: прежние11 фактов/22 начисления сохраняются, добавляются15 фактов/30 начислений. У22 существующих начислений amount не определён; денежные тарифы/суммы этим аудитом не исправлены и не объявлены готовыми.

Исправление подстатусов662 принято по результатам, переданным ведущим. Опубликованный [операционный план](../reviews/wms675-evidence-20261006/RECOVERY_PLAN.md) версии `ced5a713e56d3bb4fe2c310d3813306f08446ce2` использует штатный662 только на exact scope после одного общего проверенного деплоя и команды ведущего; отдельные копии кода/runtime overrides/подавление публикаций запрещены. При применении свежо перечитываются external proof и current ledger/резервы/billing, вычисляется оставшаяся missingdelta и сохраняются существующие факты/начисления без повторов. Нормальное следствие — обычная публикация остатков по активным bindings этого seller/затронутых товаров; операторские лимиты не меняются, точные публикуемые цифры без bindings/caps не установлены. Нюанс after_commit на savepoint не позволяет обещать ровно1 publish только после outer commit.

**Функциональная проверка восстановления принята:** на общем candidate acd0523e9986e89149959319c74fd355c659d22e плюс опубликованный контракт675 реальный662 провёл26 и повторно дал расход/начисления0. Сохранённый [proof](../reviews/wms675-incident-regression-20261006.md) фиксирует отдельную PostgreSQL testDB и точный тестовый SHA. Существующие product code/ожидания662 не менялись.

**WMS-675 не закрыта операционно:** общий CI/выпуск ведёт ведущий; фактическое production-восстановление, свежий external/current-ledger refresh при применении и независимый production readback не выполнены. Нужны один общий проверенный deploy и команда ведущего на штатный exact-scope путь; перед применением missing пересчитывается заново, начисления не повторяются. Функциональный PASS не является утверждением о production-проведении.
