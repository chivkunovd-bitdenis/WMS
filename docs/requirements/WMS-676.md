# WMS-676 · Уточнение допустимой замены ревью Opus

## Исходный запрос и уточнения

Прямое поручение владельца 06.10.2026 в текущем чате: если до Opus нельзя
достучаться, разрешено использовать Astra в качестве ревьюера. Записать разрешение
в чате и правилах проекта, чтобы недоступность Opus не остановила ночной выпуск.
Прежние поручения сохраняются: новые рабочие этапы Sol 6.1, независимое ревью
Astra high, без навыков, готовая проверенная часть выпускается к 06:00 по Тбилиси.

Этот документ фиксирует только дополнение правил WMS-676. Результат миграции
Telegram-службы, устранение её технических дефектов и продуктовые ветки здесь
не принимаются: их отдельные документы и свидетельства нужно сохранить при
объединении с веткой `codex/wms676-sol61-pipeline`.

## Требования

- R1. При недоступном обязательном Opus ревью проводит отдельная независимая
  сессия Astra с явно заданным effort `high`; повторное разрешение не требуется.
- R2. Разрешение действует во всех путях запуска: CLI, облако, CI,
  Telegram-контроллер и вложенные агенты. Ошибка Opus и результат Astra точного
  SHA сохраняются. Ни отсутствие ревью, ни самопроверка исполнителя не заменяют его.
- R3. AGENTS.md и CLAUDE.md содержат одинаковое правило. Тесты, аналитическая
  приёмка, полный CI и фактическая проверка production SHA не отменяются.
- R4. Мониторинг каждые 20 минут использует это разрешение, а не старое требование
  ждать только Opus. Подтверждённая ошибка запуска сейчас: cloud CLI `--remote`
  вернул `401 OAuth access token has expired`; это не пройденное ревью.

## Заключение

Разрешение владельца перенесено в оба файла правил. Это исправление процесса,
поэтому его продуктовая цепочка не запускается рекурсивно. Проверка идентичности
правил и итоговый diff выполнены перед сохранением. Никакие ключи, auth-сессии,
production-данные или бизнес-процессы этой правкой не менялись. Ветка требует
публикации и включения проверенной правки в эталон; выпуск продуктов не объявляется.
