# WMS-601 — ошибка 500 каталога на сортировке большого селлера

## Исходный запрос и подтверждённая причина

30.09.2026 владелец сообщил о постоянной 500 на экране сортировки и запретил дальнейшие выкладки: «пока ничего не кати ... это из-за этого?».

Production-логи показали: GET /products/linked-wb-catalog?seller_id=... возвращает500, в цепочке get_linked_wb_catalog → _ff_catalog_out_rows → marking_code_service.count_available_for_products_batch PostgreSQL отклоняет запрос с более чем65535 параметрами. Запросы /operations/fbs-supplies/{id}/pick-options при этом возвращают200. Последний выпуск WMS598 менял только API/колонку инвентаризации, этот код не менялся; новая группировка WMS600 ещё не реализована и не выкладывалась.

## Требования

| ID | Требование |
|---|---|
| R1 | Исправить подсчёт доступных кодов ЧЗ для большого набора товаров так, чтобы ни один запрос не превышал лимит PostgreSQL и каталог не отвечал500 по этой причине. |
| R2 | Сохранить правильные количества, нулевые значения, seller/tenant scope и применяемые правила доступности кодов. Не скрывать ошибку усечением каталога или тихими нулями. |
| R3 | Минимальная самостоятельная правка с воспроизведением границы параметров и целевой проверкой; не смешивать её с перестройкой экрана600. |
| R4 | Никаких production-записей, push, merge или deploy до отдельной команды владельца. |

## Проверки

| Проверка | Требования | Вердикт |
|---|---|---|
| Большой набор товаров: ограниченное число параметров каждого запроса и правильное объединение результатов | R1,R2 | Подтверждено целевым тестом: 32 769 синтетических ID проходят порциями; каждый запрос с раскрытыми PostgreSQL-параметрами ниже лимита 65 535, итог содержит все ID без усечения. |
| Селлеры, пустой набор, отсутствие кодов, разные источники наличия | R2 | Подтверждено целевым тестом с реальными строками в изолированной тестовой БД: общий пул, прямые коды, нули, чужой селлер и чужая организация дают ожидаемые значения на нескольких порциях. |
| Независимое ревью минимального исправления | R1-R4 | Технический PASS для точного кода и тестов `95512b1d48edc22064da6086450854ad0b5a6bf6`: [отчёт Sol-review](../reviews/WMS-601-query-limit-review.md). Структура того коммита получила REJECT, потому что документ WMS-601 существовал только в общем родителе с WMS-600. Этот отдельный коммит переносит неизменный код и тесты вместе с полным документом и единственной записью WMS-601 в бэклоге; отдельная проверка структуры дала PASS для code SHA `4cad1dd669b3ab9548c456c20234c60636e20f0c` и HEAD `6e6820ec154b86091fa2c6717a55623c8da1a4ca`. Stable patch-id кода и тестов совпадает с исходным исправлением. |

## Заключение

Причина production 500 подтверждена серверным traceback. Локальная правка ограничивает число параметров каждого запроса и сохраняет исходные правила подсчёта; целевые тесты прошли, техническое независимое ревью исходного кода дало PASS. Самостоятельный коммит `4cad1dd669b3ab9548c456c20234c60636e20f0c` прошёл отдельную проверку структуры; исходный структурный REJECT снят. В production исправление ещё не применялось, поэтому ошибка 500 там не считается устранённой; push, merge и deploy запрещены владельцем.
