# WMS-542 · Инвентаризация: каждый скан сразу записывается на сервер «плюс один»

## 1. Исходный запрос и уточнения

Ведущий владельцу 26.09.2026: «Надёжно — доработкой: каждый скан сразу уходит на сервер как
«плюс один», как уже сделано в приёмке.» … «кладовщики должны нажимать «Сохранить» после каждой
ячейки, иначе при перезагрузке или закрытии вкладки несохранённые штуки пропадут».

Владелец: «вот это надо сразу сделать качественно». «отдай дешёвому разрабту быстро а сам мониторь».

Требования составлены ведущим по прямому указанию владельца без отдельного аналитика.

## 2. Существующий процесс

Экран «Инвентаризация» (`frontend/src/screens/ff/inventory/FfInventoryPage.tsx`,
`FfInventoryCountScreen.tsx`, `InventoryScan.ts`, `foundQueue.ts`, `inventoryCountApi.ts`).
Кладовщик сканирует ячейку/тару, затем товар. Если строки товара в этом месте нет —
`POST /inventory-counts/{id}/found` (сервер находит товар по штрихкоду, +1, идемпотентно по `scan_id`).
Если строка уже есть — экран увеличивает число у себя; на сервер оно уходит абсолютным значением
тронутых строк (`PUT /lines`) только при «Сохранить», следующей находке, создании/удалении тары,
перемещении строки или проведении. Проверено на стенде: 3 скана → на сервере 1 до «Сохранить».

## 3. Требования

| № | Требование |
|---|---|
| R1 | Каждый скан товара в документе инвентаризации — в ячейке россыпью, в коробе/палете/грузоместе, для строки, которая числилась по учёту, для уже найденной строки и для новой находки — сразу записывается на сервере как +1 к строке этого товара в этом месте. Экран после ответа показывает значение сервера. |
| R2 | Повтор того же скана (тот же `scan_id`, повтор запроса после обрыва связи) не добавляет вторую штуку. Новый пик того же товара — новая штука. |
| R3 | Два оператора, одновременно сканирующие один и тот же товар в одном месте одного документа, получают сумму своих сканов — ни один скан не теряется и не затирается. |
| R4 | После сканов без нажатия «Сохранить» перезагрузка или повторное открытие документа показывает все отсканированные штуки. |
| R5 | Ручной ввод числа в строке и «Сохранить» работают как раньше. Если у оператора есть несохранённая ручная правка строки и он сканирует этот товар в этом месте, итог = его ручное число + 1 (правка сохраняется до +1, как экран уже делает перед находкой). |
| R6 | Проведение, пустые места, создание/удаление тары, перемещение строки, комментарий работают как раньше. Непосчитанные строки проведение не трогает. |
| R7 | Надёжность скана не ухудшается: русская раскладка, регистр, очередь сканов с повтором при обрыве связи, отложенные сканы при уходе в другой документ. |
| R8 | Интерфейс не меняется: без новых экранов, кнопок, окон и подсказок. |
