# WMS-528 · Лист подбора FBS: ячейки и тара, откуда брать товар

Запись задачи: [канонический бэклог, WMS-528](../KANONICHESKIY_BACKLOG.md#wms-528).

## 1. Исходный запрос (25.09.2026)

> была тема с тем чтобы в листе подбора отображалась тара откуда можно взять товар
> не тоько ячейка но и тара
> короче надо делать так: если ячеек нет кроме сортинга то отображаем только тару
> если есть ячейки то ячейки с тарой на ней. Отображаем по убыванию - ячейки и тару где
> больше всего товара сейчас, и которые покроют текузитй подбор, более не нужно, иначе их
> слишком много может быть
> доведи до прода быстро без использования кучи скиллов

Владелец явно попросил быстрый путь: отдельные агенты аналитика, разработчика,
перекрёстного ревью и приёмки не запускались. Реализацию и проверку сделал ведущий агент.

## 2. Исходная точка

- Печатный лист подбора FBS строится в рабочем экране поставки
  (`FfFbsSupplyWorkspace` → `buildFbsPickingListPrintHtml`). Колонка «Ячейка»
  показывала только коды ячеек из `order.inventory.locations`, без тары, все подряд,
  и целиком скрывалась при выключенном адресном хранении.
- Сервер уже отдаёт `GET /operations/fbs-supplies/{id}/pick-options` — общий расчёт
  источников подбора (WMS-058): по товару ячейки, внутри них тара (путь палета › короб)
  или «Россыпью», со свободным количеством за вычетом всех активных подборов.
  Зона сортировки приходит с кодом «Без ячеек». Новый серверный код не нужен.

## 3. Требования

- **R1.** Товар в зоне сортировки: в листе называется только тара (для товара
  россыпью в сортировке — «Россыпью»).
- **R2.** Товар в адресной ячейке: «ячейка · тара», для россыпи — только ячейка.
- **R3.** Места сортируются по убыванию свободного количества и выводятся, пока их сумма
  не покроет оставшееся к подбору (заказано минус подобрано). Остальные не выводятся.
  Если подбирать нечего — места не выводятся.
- **R4.** Колонка выводится и у клиента без адресного хранения (раньше скрывалась).
- **R5.** Сбой запроса мест не блокирует печать: лист печатается, пустые места — «—»,
  оператор видит предупреждение. Ложного «нет остатка» при сбое нет.
- **R6.** Дизайн листа и остальные колонки не меняются.

## 4. Проверки

Локальный стенд: ветка `feat/wms528-picklist-containers`, uvicorn + SQLite + vite.
Поставка WB из 6 заказов: футболка (3 шт.) лежит A-01 россыпью 2, A-02 в коробе
BOX-A2 10, A-03 в коробе BOX-A3 5, сортировка в коробе BOX-S0 1; худи (3 шт.) лежит
только в сортировке: BOX-S1 2, BOX-S2 2, BOX-S3 1. Кнопка «Печать листа подбора»
нажималась в браузере; окно печати встроенного браузера блокируется, поэтому
`window.open` подменялся заглушкой, сохраняющей HTML листа.

| C2 | R2, R3 | Футболка: лист показал одну строку «A-02 · Короб BOX-A2: 10»; A-01, A-03, BOX-S0 не выведены | выполнено |

реальная бумажная печать.

## 5. Заключение

Требования R1–R6 выполнены на локальном стенде. Перекрёстное ревью и приёмка аналитиком
не проводились по прямому указанию владельца делать быстро; это отмечено в статусе задачи.
