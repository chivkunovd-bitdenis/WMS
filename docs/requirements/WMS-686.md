## Существующий процесс

Основа etalon4b298efc95be7b4b6b7fe5665be9f3671f1fe747: FfSuppliesShipmentsPage, /app/ff/mp-shipments, полноэкранный документ, Товары/Подбор/Упаковка, дата, склад, итоги, Короба. Подбор: FfUnloadPickPage/UnloadPickScreen, поле скана, место, таблица и количества по источникам. Упаковка: FfPackagingTaskPanel. Демо импортирует настоящие компоненты/тему и действует только над вымышленным локальным состоянием.

## Требования

- R1. Сохранить настоящее полноэкранное окно, вкладки, компоненты, колонки, иконки, тему и прочие элементы вне целевых изменений. Отдельный URL baseline использует исходные компоненты. Основание текущий запрос.
- R2. Подбор: скан ячейки/короба выбирает источник; количество относится к выбранному товару. Действия «Забрать весь короб» и «Забрать всё из ячейки» переносят известный состав. Смешанные товары не объединяются в одно число. Основание573/788.
- R3. Неизменённый короб переносится целиком со своими товарами/КИЗ без обязательного вскрытия/перескана. Основания548/763,559/774,564/779.
- R4. Частичный подбор допускает разные отгрузки/направления из одного короба. Скан фиксирует конкретный КИЗ выбранного товара; оставшееся содержимое и история приёмки сохраняются. Количество без идентификации не выдаётся за подтверждённый конкретный КИЗ. Основания563/778,573/788,574/789.
- R5. Не требовать дополнительной упаковки неизменённого короба. Упаковка доступна для добровольной проверки, маркировки и изменения состава; повторная проверка единицы не удваивает количество. Основания564/779,569/784.
- R6. Упаковка: прежний или новый короб (с текущим уникальным кодом); ШК товара → КИЗ → выбранный короб. «Закрыть короб» сохраняет состав и выбирает следующий. Основания548/763,550/765.
- R7. КИЗ сохраняет известную связь с приёмкой и получает связь с отгрузкой. Неизвестную приёмку не выдумывать. Возможен учёт нанесённого кода без прежнего скана приёмки. Повторная проверка отличается от использования кода другой единицей. Основания556/771,561/776,564/779.
- R8. Подбор, упаковка, сканы и закрытие короба не списывают товарный остаток; меняют расположение/состав. Списание только при проведении отгрузки. Основание AGENTS.md.
- R9. Только вымышленные данные. Fetch всегда локальный; неизвестный маршрут возвращает явную ошибку без сетевого fallback. Нет Telegram/WB/Ozon/ЧЗ вызовов, клиентской авторизации, реальной печати и production операций.
- R10. Прогресс сохраняется после обновления в localStorage; сброс демо восстанавливает исходное состояние.

## Весь процесс из беседы и вопросы

1. Source541/756: селлер создаёт направление, выбирает склад и дату выезда; отдельно предложены дата слота WB, загрузка Excel и прикрепление пропуска после готовности. «Общие поставки» сформулировано неоднозначно, запрет не вводим. WB передача также WMS679, API записи не обещаем.
2. Sources546/761,548/763: подготовка на приёмке, состав/КИЗ/код короба, хранение до готовности. Здесь демонстрируем принятую тару; приёмку не меняем.
3. Source573/788: целый короб, частичный товар, вся ячейка. При разделении маркированного товара сканируют конкретные уходящие КИЗ.
4. Sources550/765,564/779,569/784: дополнительная упаковка по необходимости, новый/старый короб, закрытие → следующий.
5. Source561/776: селлеру нужна выгрузка связей КИЗ/приёмка/отгрузка. Новый отдельный отчёт без определения места не вводим; связи демонстрируем в контексте короба.
6. Sources575/790,576/791: услуги и понятное ТЗ сотрудникам на этапах, калькулятор как пример. Поля/цены/автоначисления не согласованы. Здесь используем существующее packaging_instructions.

Решение ведущего по текущему прямому scope владельца: срочный макет показывает подбор/упаковку. Слот/пропуск и общая форма услуг не добавляются; вся беседа сохранена выше для последующего определения отдельного объёма. Существенных вопросов, блокирующих этот макет, нет.
