## Существующий процесс и цель

База реализации: актуальный origin/etalon `9f92acee102edc6def244d1d583a3105742bd3b6`. Внутренние отчёты `/reports/inventory` уже существуют; WMS-531 добавила XLSX. Новые методы дополняют существующий отчёт детальными движениями для клиента, не меняют его текущие маршруты или UI.

КИЗ хранится в `fbs_order_markings`: `order_id`, `order_product_id`, `kind`, `value`, ссылка `marking_code_id`. Журнал `fbs_shipment_reversal_ledger` связывает движение и FBS-заказ; для Ozon точные идентификаторы движений могут храниться в `ozon_positions_json`. SKU — существующий `Product.sku_code`. Эти факты подтверждены чтением моделей/сервиса; наличие полного набора исторических данных каждого клиента не проверялось.

## Решения и границы

Предлагаемые новые маршруты внутри текущего API: `GET /reports/client-movements` и `GET /reports/client-movements/export.xlsx`. Это прикладные пути; базовый URL развёртывания указан отдельно в документации. Фильтр `barcode` трактует произнесённое «шика» как ШК товара. API использует существующий вход и Bearer; новые сервисные ключи не создаются. Доступ в ЛК конкретного клиента остаётся отдельной операционной задачей: имя/учётная запись клиента не сообщены, доступ не выдан этой реализацией.

Прежняя запись WMS-533 включала остатки и движения. Текущий выпуск реализует уточнённые владельцем методы движений; существующий отчёт остатков сохраняется, новый внешний контракт остатков здесь не заявляется.
