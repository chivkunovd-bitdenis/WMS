## Существующий процесс и цель

База реализации: актуальный origin/etalon `9f92acee102edc6def244d1d583a3105742bd3b6`. Внутренние отчёты `/reports/inventory` уже существуют; WMS-531 добавила XLSX. Новые методы дополняют существующий отчёт детальными движениями для клиента, не меняют его текущие маршруты или UI.

КИЗ хранится в `fbs_order_markings`: `order_id`, `order_product_id`, `kind`, `value`, ссылка `marking_code_id`. Журнал `fbs_shipment_reversal_ledger` связывает движение и FBS-заказ; для Ozon точные идентификаторы движений могут храниться в `ozon_positions_json`. SKU — существующий `Product.sku_code`. Эти факты подтверждены чтением моделей/сервиса; наличие полного набора исторических данных каждого клиента не проверялось.

## Решения и границы

Предлагаемые новые маршруты внутри текущего API: `GET /reports/client-movements` и `GET /reports/client-movements/export.xlsx`. Это прикладные пути; базовый URL развёртывания указан отдельно в документации. Фильтр `shk` означает ШК товара и связан с `size` из того же товара. API использует существующий вход и Bearer; новые сервисные ключи не создаются. Доступ в ЛК конкретного клиента остаётся отдельной операционной задачей: имя/учётная запись клиента не сообщены, доступ не выдан этой реализацией.

Прежняя запись WMS-533 включала остатки и движения. Текущий выпуск реализует уточнённые владельцем методы движений; существующий отчёт остатков сохраняется, новый внешний контракт остатков здесь не заявляется.

Уточнение владельца 29.09.2026 после просмотра отчёта: клиент видит только оприходование и списание товара. Перекладывания, передача между продавцами и подбор товара для FBO недопустимы. В FBO допустима только завершённая отгрузка: заявка `shipped` или `done` с `shipped_at`, период и порядок определяются временем `shipped_at`. Старые несвязанные движения не восстанавливаются. Excel должен быть в форме для селлера: листы WB/Ozon/Общие, русские колонки «Дата и время (UTC)», «Движение», «Причина», «Документ / заказ», «Код товара», «Товар», «Размер», «Штрихкод», «Приход, шт.», «Расход, шт.», «Склад», «КИЗ». «Движение» — только «Оприходование» либо «Списание». В Excel не должно быть UUID, технических кодов, цветных статусов и пояснительных блоков; белые строки с чёрным текстом, серая шапка.

Это уточнение заменяет прежнюю проверку C11, которая допускала показывать подбор FBO. Уточнение владельца от 30.09.2026 ещё сильнее ограничивает перечень: только приёмка, возврат, отгрузки FBS/FBO и инвентаризация. JSON сохраняет машинные имена полей и операций, но набор событий совпадает с Excel. Для обоих методов исключены `stock_transfer_in/out`, `warehouse_map_move`, `container_reattach`, `transfer`, `fbs_order_pick/undo`, `ownership_transfer_*` и любой другой тип.
