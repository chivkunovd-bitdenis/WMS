# WMS-612 · Компактные предупреждения перед передачей FBS-поставки

## Исходный запрос

> возьми сразу исправление
> тут пиздец какой то
> Должна должна быть одна строка на каждую ошибку. То есть первое: не создан короба, и можно как бы раскрыть, посмотреть в каких заказах. Но, блять, не так, а нахуй построчно как-то, блять, адекватно, нормально в этой модалке. То же самое с ЧЗ. Вот этого пиздеца не должно быть, должен быть аккуратный экран.

Владелец приложил фотографию окна «Передать поставку в WB?», где номера сотен
заказов выведены одним длинным абзацем.

### Уточнение владельца 01.10.2026

> Во-первых, выкати на стейдж, во-вторых, надо вообще все. Спасибо. Все, всего доброго. Нужно все, короче... вот эту ошибку про короба, что у товара нет коробов, вообще нахуй убрать. В принципе не нужно.

## Существующий процесс и цель

Перед передачей поставки оператор видит серверные запреты и предупреждения.
Одинаковые причины уже объединяются, но номера всех затронутых заказов дописываются
через запятую в тот же абзац. Из-за этого окно становится длинным и нечитаемым.

Цель — полностью убрать коробочные предупреждения из передачи. Для остальных
проблем оставить одну компактную строку на тип и показывать конкретные заказы
только после раскрытия, по одному заказу на строку.

## Требования

- **R1.** В окне подтверждения одинаковые предупреждения и запреты показываются
  одной строкой на тип проблемы, без перечня заказов в основном тексте.
- **R2.** Строка с затронутыми заказами показывает их количество и раскрывается
  по нажатию.
- **R3.** В раскрытой части каждый заказ WB показывается отдельной строкой.
- **R4.** Отсутствие физических коробов и отсутствие распределения заказов по
  коробам не создают проверок передачи и не показываются в модалке даже при
  получении устаревшего серверного ответа с такими кодами.
- **R5.** Предупреждения об отсутствующем Честном знаке объединяются в одну строку
  «Не нанесён Честный знак» с общим списком заказов.
- **R6.** Уровень проверки сохраняется: блокеры остаются в красном блоке,
  предупреждения — в жёлтом; возможность передачи не меняется.
- **R7.** Большой список заказов прокручивается внутри раскрытой части и не растягивает
  окно на всю высоту экрана.

## Заключение

Коробочные предупреждения удалены из серверной предпроверки и дополнительно
фильтруются клиентом для совместимости со старым ответом. Остальные предупреждения
остались компактными и раскрываемыми. Локальные проверки, визуальная проверка и
выкладка на Railway staging пройдены. API и web фактически обслуживают продуктовый
SHA `24ddd2005bd48bd1198b2c720fd72f261812db43`.
