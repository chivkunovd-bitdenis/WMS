# WMS-553 · Освободить короба текущей приёмки ArtMaks

## Запрос

Владелец поручил SQL-запросом убрать товары из коробов в нераспределённую сортировку,
сохранив сами короба, чтобы оператор сканировал ячейку, пустой короб и затем товары.
Без навыков, агентов и изменения приложения.

## Требования

- Только приёмка `f140d4ca-cf60-402e-90cd-7fa9d8815f9d` (#000007):
  60 коробов, 321 SKU, 323 строки состава, 4139 единиц. Другие приёмки не меняются.
- Сохранить коробовые UUID/barcode и общее количество каждого товара.
- Удалить привязку состава к коробам, перевести реальные остатки в россыпь
  в существующей `__SORTING__`, сохранить движение в журнале парой минус/плюс.
- Одна транзакция с блокировками и проверками до/после. Исходный снимок сохранить.

## Проверки

| Проверка | Вердикт |
|---|---|
| Production preflight | PASS: 60 коробов, 4139 единиц, posted_qty=0, distribution=0, все короба в сортировке |
| Пустой короб и свободный товар поддержаны текущим кодом | PASS: без box_lines контейнер можно размещать; loose_remaining считается из actual_qty минус posted_qty и состава |
| SQL до/после, UUID, товарные итоги | PASS: транзакция committed, UUID/barcode 60 коробов совпали, количество и packed/unpacked каждого из 321 SKU сохранены |
| Рабочий сервис сортировки после применения | PASS: 60 коробов, содержимое 0, свободно 321 SKU / 4139 единиц; posted_qty=0 |

## Заключение

Выполнено на production 27.09.2026 из commit `1bef8e66d4e770592863fcb03b70b5e18cb35d4f`.
323 привязки состава к коробам сняты; 4139 единиц переведены в россыпь существующей
сортировки. Созданы парные записи движения `container_reattach`, нет изменения
общего остатка ни одного SKU. Приложение и другие приёмки не менялись, деплой не нужен.
Снимки до/после сохранены локально в `var/evidence/wms553-before.json` и
`var/evidence/wms553-after.json`, данные клиента не отправлялись в публичный remote.
Рабочий `get_sorting_objects` подтвердил 60 пустых коробов и 4139 свободных единиц.
Физический скан товара оператором не выполнялся в рамках SQL-операции.
