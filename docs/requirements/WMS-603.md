# WMS-603 — распознавание короба сканером в подборе FBS

## Исходный запрос и факты

30.09.2026 владелец: «щас сделаи за сканом», затем уточнил: «короб не сканируется — а ячейки сканируются». На приложенном экране активна ячейка Ж-1-4, режим «товар, который снимаете», ошибка «Товар не найден по штрихкоду в этой поставке». Верхняя ошибка 500 каталога отдельно исправляется WMS-601.

Текущий production SHA 5d5d42deaf9f4dc8cbdfd230d9cd3a0136be0f8c содержит выпущенную в другой сессии WMS-602: нормализацию сканов ячеек. В 12:23:57 UTC скан текущей поставки ответил 200, в 12:24:17 — 409. В контейнерном resolver остаётся точное сравнение internal_barcode после trim; при отсутствии совпадения pick_scan переходит к поиску товара. Точное INB-M5KSFV1J1XP9WW ранее выбирало короб в серверной проверке, но это не доказывает распознавание физической этикетки. Raw-код неудачного скана не сохранён в журнале; запросили его у владельца. Причина конкретного несовпадения пока не доказана.

Запрет владельца «пока ничего не кати» сохраняется: локальная реализация, тесты, независимое ревью и commit разрешены, push/merge/deploy и production-записи не выполняются. Не переносить сюда разрешение на отдельный выпуск WMS-602 из другой сессии.

## Требования

| ID | Требование |
|---|---|
| R1 | В подборе FBS скан существующего короба после ячейки выбирает именно этот короб; следующие товарные сканы используют выбранное место. |
| R2 | Поддержать подтверждённый пробел распознавания: регистр, существующие варианты раскладки сканера и AIM-префикс известного кода, сохраняя приоритет точного совпадения. Не выдумывать соответствие внешнего кода неизвестному коробу. |
| R3 | Сохранить границы клиента и склада, неоднозначность не разрешать случайным выбором; выбор ячейки/тары не меняет остатки. Не менять чужие процессы приёмки/упаковки. |
| R4 | Отдельно подтвердить исходный случай по точной строке сканера, если владелец её предоставит. Не объявлять физическую приёмку по одному тесту нормализованного кода. |

## Проверки

| Проверка | Требования | Вердикт |
|---|---|---|
| Точный код, другой регистр, AIM, раскладка → один существующий короб | R1,R2 | Подтверждено локальным API-тестом для inbound-короба и складской тары; физический скан не проверялся. |
| Чужой tenant/склад и неоднозначные варианты; отсутствие движения при выборе | R3 | Подтверждено локальным тестом: чужой контур не находится, неоднозначность даёт 409, остатки и движения не меняются; `_` и `%` сравниваются буквально. |
| Ячейка → короб → товар, сохранение конкретного источника | R1,R3 | Подтверждено локальным API-тестом: снятие записано с выбранным ID короба. |
| Точный физический скан владельца и независимое ревью | R4 | Строка физического скана ещё не получена; независимое ревью кода прошло без замечаний P1/P2 — [отчёт](../reviews/WMS-603-review.md). |

## Заключение

Локально исправлен подтверждённый пробел: подбор FBS сначала ищет буквальный код короба, затем варианты регистра, AIM-префикса, управляющего обрамления и раскладки в границах клиента и склада. Целевые тесты пройдены; `ruff check .` и `mypy .` прошли. Причина именно физического скана не доказана без строки, которую передал сканер. Независимое ревью прошло, физическая приёмка ожидается. Выпуск остановлен владельцем; код сохраняется только в локальной ветке.
