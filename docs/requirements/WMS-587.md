## Исходный запрос и уточнения

## Существующий процесс и цель

В существующей приёмке состав документа набирают через «Добавить товары». Требуется альтернативный способ заполнить тот же состав из XLSX, сохранив выбранного селлера, количества, размерные варианты и текущие правила редактирования документа. Новый процесс приёмки/учёта товара не создаётся.

Исходный кандидат экрана — `frontend/src/screens/v2/SellerInboundDraftScreen.tsx`; исполнитель проверяет его фактическое использование в текущей базе `origin/etalon 9f92acee102edc6def244d1d583a3105742bd3b6` и существующие API добавления строк. Точное подключение и browser evidence фиксируются после проверки.

## Решения и границы

Плановые количества для строк из файла устанавливаются в переданные значения: это делает повтор загрузки безопасным, не превращая его во второй приход. Отсутствующие в файле строки не удаляются. Файл с ошибками не импортируется частично: пользователь исправляет перечисленные строки и повторяет загрузку. Эта семантика — решение ведущего внутри запроса, не слова владельца.

Без выдачи новых учётных данных, merge или deploy. Не создаётся новая сущность товара, дополнительный импортный журнал или отдельный экран.
