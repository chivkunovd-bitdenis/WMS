# WMS-593 · Основной штрихкод товара во всех печатях

## Исходный запрос и уточнения

30.09.2026: В карточке товара при нескольких ШК можно выбрать основной. Вся товарная печать во всех заказах и документах использует его; при единственном ШК он основной автоматически.

Владелец поручил срочную параллельную реализацию Sol/Terra без навыков и отдельной аналитической цепочки, затем изолированное ревью. Деплой и внешние операции этим пакетом не выполняются.

## Требования

**R1.** Один сохранённый выбор основного из известных штрихкодов товара, доступный в карточке; один код используется автоматически.

**R2.** Каталог, приёмки, отгрузки, инвентаризация, FBS WB/Ozon, массовая лента и мобильные товарные этикетки получают один и тот же основной код.

**R3.** Импорт не отменяет выбор оператора, прежние коды сохраняются для сканирования. QR маркетплейса и уникальный КИЗ не заменяются товарным ШК.

**R4.** Сохраняются права и границы селлеров/организаций; повторное открытие показывает сохранённый основной.

## Проверки

| Проверка | Вердикт |
|---|---|
| C1: проверить R1 на собранной реализации | Подтверждено локально: в карточке товара 445100 выбран Ozon OZN445100, каталог показал выбранный ШК, повторное открытие сохранило выбор; при одном известном коде API вычисляет его автоматически. |
| C2: проверить R2 на собранной реализации | Код каталога, FBS worklist и ленты, сортировки, складской карты, приёмки и инвентаризационного листа использует общий выбор; целевые тесты и сценарии FBS проверены локально. После интеграции WMS-598 три целевых теста подтвердили новый основной ШК в строках и дереве уже созданной инвентаризации, а также в повторно открытой печатной ведомости. Целевой тест сканирования существующей строки по `line_id` подтвердил выбранный Ozon ШК и отказ для кода соседнего товара другого селлера. Реальный принтер и весь производственный набор документов не проверялись. |
| C3: проверить R3 на собранной реализации | Проверено чтением кода и целевым тестом: WB/Ozon импорт не пишет в `primary_print_barcode`; после смены импортированного Ozon ШК с A на B выбранный A остаётся кодом печати и доступен в карточке и сканере вместе с B. QR заказа и КИЗ формируются отдельными путями. |
| C4: проверить R4 на собранной реализации | Подтверждено локально на PostgreSQL: выбранный ШК остался в БД и карточке после повторного открытия. PATCH ограничен администратором ФФ и поиском товара в текущем tenant; неизвестный товарный ШК отклоняется. |

## Заключение

Реализация локально проверена на тестовой базе и в браузере. Независимое ревью Sol и повторное ревью исправлений пройдены; итоговый проверенный SHA пакета — `b3284895fc6a2522659b36276c6db1896db72d15`. Сохранность Ozon-алиасов и сканирование выбранной строки инвентаризации по основному ШК подтверждены отдельно. Нативный ТСД сохранён в отдельном репозитории коммитом `8f9f4b35a9eab3d52d9422ae15b1f58e1d7859c0`: текущий основной ШК используется в товарных этикетках, отдельно проверено соответствие КИЗ конкретной позиции многопозиционного заказа Ozon. Независимое мобильное ревью пройдено, хеши проверенных файлов сверены с коммитом. Физическая печать и производственная приёмка не заявляются. По команде владельца от 30.09.2026 публикация новых изменений и деплой остановлены.
