# WMS-406 — запись услуги только по подтверждённой передаче WB

09.09.2026. Изменения приложения сохранены отдельно от расследования исторических 878. Ничего из этой проверки не запускалось на production; склад, frontend и навигация не менялись.

`fbs_order_billing_service.confirmed_order_handover_dates(session, tenant_id, orders)` возвращает пакет дат без фильтра статусов: сохранённый scoped supply.delivered_at либо confirmed `supply_deliver` с точным order ID из checkpoint resolutions или связанной FbsShipmentReversalLedger. Это поддерживает отвязанные заказы; `supply_from_orders` не является передачей. Снимок resolutions содержит лишь списываемые товары, поэтому не исключает несопоставленные заказы, сохранившие связь с успешно переданной поставкой. Отвязанные заказы без доказательства не получают выдуманную дату. Подтверждённая дата операции приоритетнее текущей связи, повторные подтверждения выбирают первую дату.

Для WB writer не принимает sorted/done, packed_at, created_at_wb или произвольный occurred_at вместо передачи. Поздняя синхронизация может восстановить услугу только для уже подтверждённой передачи. Ozon сохраняет существующий контракт, включая confirmed handover. Идемпотентность, ставки и вложенная транзакция начисления остаются прежними. Writer использует согласованное ledger API `respect_billing_start=False` из зависимого commit `6d0b068d` (локальный cherry-pick `7032d941`): отсутствие цены не выдумывает сумму и не блокирует передачу.

Существующий backfill фактов проверяет WB всех статусов, включая поздние cancelled/defect, и устанавливает точную дату без допуска в сутки. Начисленные/включённые в счёт даты по-прежнему защищены. Денежный backfill не начисляет исторический неподтверждённый WB fact; отбирает подтверждённую дату передачи, даже когда прежняя дата факта вне выбранного периода. Дополнительно исправлен обнаруженный целевым запуском разбор CLI tenant UUID. Денежная отмена после подтверждённой передачи WB сохраняет FBS/packing; складской возврат не менялся.

Проверено 27 целевых сценариев из test_fbs_handover_billing.py, test_backfill_fbs_order_facts.py и test_fbs_order_charge_savepoint.py последовательными ограниченными прогонами: сначала 25 прошли, два новых обнаружили ошибку UUID; после исправления оба прошли. После добавления monetary cancellation guard повторно прошли все 7 handover-сценариев. Покрыты публичная передача, ошибка WB, timeout/reconcile, ошибка локального списания, ошибка billing, повтор, WB/Ozon количества, detached snapshot/ledger, исключение failed/create operation, сохранность учтённых дат и исторический денежный период. Ruff прошёл по изменённым файлам; mypy — по четырём изменённым source-файлам. Использован собственный SQLite в /private/tmp с отдельным data-dir; новых зависимостей и полного suite не было.

Основной checkpoint — `d2758db62b51f0ce1e22321d3d142611cf520e31`; последующий commit содержит UUID/cancellation correction и этот отчёт. Общая интеграция report/invoice, CI, восстановление исторических фактов и deployment принадлежат root; здесь они не объявляются выполненными.
