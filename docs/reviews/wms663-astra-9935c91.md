## F4-R / P1: неполный readback выдаётся за принятие всех показанных документов

Сценарий на отдельной SQLite с FakeMarketplaceTransport:

1. Принять сохранённую ГТД A `001/ABC-09` у экземпляра 81.
2. Кабинет возвращает `CABINET-NEW`, `ship_not_available`, `gtd_invalid`.
   Настоящий GET теперь верно показывает rejected и конкретную ошибку.
3. Следующий STATUS возвращает `ship_available`, но без экземпляра 81;
   остальные экземпляры присутствуют. Ни SET, ни нового выбора оператора нет.
4. GET оставляет A в snapshot с CABINET-NEW и raw gtd_invalid, присваивает
   A.state=unknown, но возвращает общий state=accepted и обе видимые коллекции
   ошибок пустыми. DOM показывает «Принято» рядом с CABINET-NEW; неизвестность
   отсутствующего A вообще не отображается.

Фактический вывод сервиса:

```text
before {"state":"rejected","errors":["gtd_invalid"],"A":"CABINET-NEW"}
partial {"state":"accepted","errors":[],"A":"CABINET-NEW",
         "A_state":"unknown","A_errors":[],"A_raw_errors":["gtd_invalid"],"sets":1}
```

Причина находится в `backend/app/services/ozon_exemplar_documents_service.py`:
строки 250–251 принимают любой непустой список при ship_available;
строки 277–284 вычисляют общий state/errors только по вернувшейся части remote,
не проверяя полный набор показанных экземпляров. Ниже, строки 294–304,
отсутствующему A правильно присваивают unknown, но это не отражается в общем
состоянии. Обновление snapshot намеренно сохраняет отсутствующие в ответе
экземпляры. В `frontend/src/screens/v2/OzonExemplarDocuments.tsx:94` выводится
только общий `data.state`; `exemplar.state` не отображается. Поэтому внутренний
unknown не защищает оператора от ложной надписи.

Это нарушение существующих R6/R7, прямо предусматривающих неполный products
и запрет ложного успеха, а не новое продуктовое требование. Старый отказ нельзя
выдавать за доказанный текущий отказ без свежего ответа, но его отсутствие в
неполном ответе также не доказывает принятие. Как минимум общий результат должен
остаться неизвестным, пока отсутствующий документ не подтверждён. Исправление
не должно возобновлять исторический writer, накладывать старые choices либо
запрещать следующее допустимое действие по одному факту неполного чтения.

DOM с точным JSON, полученным этим сервисным сценарием:

```text
{"accepted":true,"errorVisible":false,"unknownVisible":false}
FAIL: expected 'ГТД / РНПТПринятоТовар с ГТД ...' not to contain 'Принято'
1 failed, 2.42s, exit 1
```

Сначала отдельно проверено, что в DOM действительно есть input со значением
CABINET-NEW. Ошибка ожидания относится к реальному тексту компонента. Это
целевая jsdom-проверка, не браузерная проверка геометрии и не живой Ozon-инцидент.

## Как воспроизвести новую пробу без изменения продукта и тестов

Из backend запустить следующим Python через stdin, со снятыми
WMS_TEST_DATABASE_URL/WMS_TEST_DATA_DIR, как в команде выше. Необязательное
сохранение полного view в scratch JSON позволяет передать именно этот ответ
в DOM, без ручного моделирования ответа сервиса:

```python
import sys, asyncio, json
from pathlib import Path
sys.path.insert(0, 'tests')
import conftest
from test_wms663_accepted_current_status import _accepted_then_current_status
from test_wms663_astra_regressions import STATUS, SET, _exemplar
from app.services import ozon_exemplar_documents_service as docs

async def main():
    assert conftest.engine.dialect.name == 'sqlite'
    await conftest._reset_database()
    async with conftest.SessionLocal() as session:
        order, _, transport, fresh, before, kwargs = await _accepted_then_current_status(
            session, 'rejected'
        )
        fresh['status'] = 'ship_available'
        fresh['products'][0]['exemplars'] = fresh['products'][0]['exemplars'][1:]
        transport.endpoint_responses[STATUS] = fresh
        view = await docs.get_exemplar_documents(session, **kwargs)
        print(json.dumps({
            'state': view['state'], 'errors': view['errors'],
            'A': _exemplar(view)['gtd'], 'A_state': _exemplar(view)['state'],
            'A_errors': _exemplar(view)['errors'],
            'A_raw_errors': _exemplar(view).get('gtd_error_codes'),
            'sets': sum(path == SET for path, _ in transport.endpoint_calls),
        }))
        # For DOM only: write to the separate scratch directory selected by reviewer.
        # Path(SCRATCH / 'partial-view.json').write_text(json.dumps(view))
    await conftest.engine.dispose()

asyncio.run(main())
```

Для DOM использован отдельный временный каталог с symlink node_modules к
установленным зависимостям frontend; product/tests checkout не менялись.
Конфигурация scratch: `export default { esbuild: { jsx: "automatic" },
test: { environment: "jsdom" } }`. Компонент импортирован по абсолютному пути
из проверяемого checkout. Первая попытка запуска по /var/folders дала ошибку
разрешения пути до выполнения тестов; повтор по каноническому /private/var/folders
запустил обе пробы. Исходный семисценарный тест взят из
`wms663-f4-developer-dom-probe.txt` без изменения ожиданий. Дополнительный тест:
