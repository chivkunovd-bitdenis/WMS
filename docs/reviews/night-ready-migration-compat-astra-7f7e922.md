## Проверка графа и отсутствия повторных изменений БД

Локально проверены объявления всех миграций через Python AST и загружен полный граф через Alembic 1.19.0 (`ScriptDirectory`). Получены 199 уникальных ревизий, все ссылки `down_revision` и `depends_on` разрешаются, обход от головы до основания проходит целиком, циклов и потерянных ветвей нет. Единственная конечная ревизия — `20261003_0001`.

Alembic `_upgrade_revs('head', '20261003_0001')` возвращает пустой список. Через штатный `EnvironmentContext` в offline-режиме с PostgreSQL-диалектом, `starting_rev='20261003_0001'` и `destination_rev='head'` независимо получен ровно следующий SQL:

```sql
BEGIN;

COMMIT;
```

Проверка использовала миграционные файлы точного SHA, без подключения к БД и без загрузки настроек приложения. Она воспроизводит выбор ревизий и генерацию SQL Alembic, но не заявляется как online-запуск entrypoint. Первый запуск локальной проверки остановился из-за отсутствия `backend` в Python import path; после добавления этого пути проверка завершилась успешно, код репозитория не менялся.

Таким образом, на указанной существующей staging-БД восстанавливается возможность прочитать уже применённую историю. Ни `CREATE/ALTER/DROP`, ни исторический `UPDATE ff_staff_permissions`, ни изменение таблицы версии не выполняются. Четыре миграции с реальным изменением схемы сохраняют исходные тела; пять merge-ревизий сохраняют исходные пустые тела и родительские связи. Нет новых фиктивных ревизий, подмены исторических миграций пустышками или смены revision ID. `stamp`, downgrade и ручная правка `alembic_version` не предложены и не выполнялись. Наличие исходных функций `downgrade()` в исторических файлах не означает их вызов.

Применимый риск из библиотеки сбоев — потеря исправлений при сборке общего дерева (B11), а также ложное восстановление старого поведения вместе с историей (B15). Здесь он закрыт точным сравнением всего дерева вне миграций и доказательством пустого плана их выполнения. Новые продуктовые сущности, ограничения операторов и изменения соседних процессов этим diff не вводятся.
