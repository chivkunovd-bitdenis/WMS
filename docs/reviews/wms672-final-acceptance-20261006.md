## Решение по исходным проверкам

Полные критерии, классы и актуальный вердикт каждой C1–C12 находятся в [требованиях v3](../requirements/WMS-672.md). Исходные критерии не удалены и не заменены краткими формулировками этого отчёта.

- C1/C2 приняты: приёмка и возврат 200/300, один документ/передача, реальный PDF с полным числом/порядком страниц 58×40 и raster CODE128 образцов. C3 принят по прежнему неизменному рендереру.
- C4/C5 приняты по второму новому run; C6 — двойное подтверждение по первому и восстановление технического действия по реальной функции ревьюера. Отдельного серверного replay сырого HTTP POST нет. Смена all-N ожидания — разрешённая семантическая коррекция; первый FAIL остаётся FAIL.
- C7 частично подтверждён: браузерный reload сохраняет попытку/HTML, Node-проверка unknown запрещает вторую ленту. Не выполнен полный исходный переход после выяснения результата к отдельному подтверждению новой перепечатки.
- C8 принят по совокупности: браузер доказывает сохранение источника после afterprint/reload и отсутствие второй ленты, реальная функция в Node VM — завершение 300 отметок с прежними ID/HTML при принятой/непринятой потерянной отметке и старых timestamps. Синтетические HTTP/storage/print прямо ограничивают этот результат; браузерного завершения всех 300 после reload нет.
- C9 принят в исходной области: два сохранённых API-теста, отклонение чужого клиента/документа/box_id, снимки бизнес-данных без изменений и неизменный сервис. Новая проверка live API/БД/браузера прав не требуется исходным C9.
- C10 частично подтверждён: пустая/одиночная пачка, окно создания грузомест/открытие без печати и соседние 86 тестов. Отдельное выполнение контрактов интеграции WMS-659 не выделено доказательством.
- C11 не закрыт: требуется ручная проверка настоящих компонентов обоих процессов, прежнего места действия/диалога, длинных названий, полного предпросмотра, понятной ошибки и соседних действий без физической отправки.
- C12 не проверен: операторские серии 200/300, число и порядок до последней, пустые стикеры, сканы и настройки принтера — только после выпуска и отдельного поручения. PDF и afterprint не доказывают бумагу.

## Минимальный остаток без новых условий

Для C9 в исходном сценарии ничего не осталось; его отсутствие в последнем remote run не стирает более ранние два PASS неизменного backend. Для C11 нужен ограниченный ручной сценарий обоих экранов в разрешённом тестовом браузере; Mac Chrome в текущем поручении запрещён и не открывался. Для C12 необходима только исходная отдельно разрешённая послевыпускная физическая проверка — она не превращается в условие печатать сейчас.

Полный браузерный прогон восстановления всех 300 не был специально задан исходными C7/C8. C7 уже имеет настоящую перезагрузку, C8 допускает DOM-контур; сочетание этой браузерной проверки с исполнением реальной функции закрывает доказательство завершения C8. Поэтому повтор неизменного C7/C8/PDF не назначен новым обязательным условием. Пробел постоянных assertions полного восстановления сохранён: текущее браузерное PASS не доказывает все 300, а Node probe не переименован в браузерный тест. Постоянную охрану и её перенос после выпуска нельзя объявить выполненными этим отчётом.

При этом исходные незавершённые части C7 и C10 остаются: явная новая перепечатка после выяснения unknown и проверка контрактов интеграции WMS-659. Нужна адресная проверка этих частей, не повтор успешных больших серий. Найденных технических дефектов ревью нет; недостаточность доказательства не объявляется продуктовым дефектом. Полный CI итогового SHA и выпуск также не подтверждены. Исторический неполный тестовый контракт до реализации и недоказанный RED не исправлены задним числом.

Изменены только требования WMS-672, её запись бэклога и этот отчёт. Продукт, принятые WMS-673/WMS-657 (`2e49343af`) и чужие файлы сохранены. Новая БД, npm, загрузки больших артефактов, браузер, секреты/сессии, внешняя отгрузка/печать/вывод из оборота и деплой не выполнялись. Git-публикация этого заключения означает сохранность документа, а не выпуск продукта.
