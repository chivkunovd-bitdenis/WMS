## Контракт

Использованы существующие `_accept_a`, `_exemplar`, `_scan`, `_seed_order`,
`_remote_snapshot` и `_transport`. Историческое действие принимает ГТД
`001/ABC-09`. Затем кабинет меняет значения экземпляра 81 на `CABINET-NEW`
и `CABINET-NEW-RNPT`, сохраняя остальные поля. Настоящий
`get_exemplar_documents` получает один из трёх свежих результатов:

- `ship_not_available` с `gtd_error_codes=["gtd_invalid"]`: код отказа
  присутствует одновременно в `view.errors` и `exemplar.errors`, которые
  использует реальный экран; новые значения не имеют состояния `accepted`.
- `validation_in_process`: состояние текущего представления и экземпляра
  — `checking`, то есть проверка новых сведений, а не принятие прежнего действия.
- `ship_available` с неизвестным `gtd_check_status="future_status"`:
  новые сведения не выдаются за `accepted` ни в представлении, ни у экземпляра.

GET обязан читать STATUS без SET и create-or-get. Свежие номера, признаки
отсутствия, масса и маркировки должны совпадать со свежим снимком. Версия
исторического действия не увеличивается, его сохранённый choices не заменяется
кабинетными значениями, in_flight не включается. Новых полей или способа
хранения отдельного текущего состояния контракт не требует; использованы
существующие выходные state/errors и существующие средства проверки операций.

Для каждого из трёх результатов отдельные контроли выполняют второй GET,
а затем настоящий save документа B либо submit_marking для экземпляра 82.
Повторное чтение не создаёт ожидающего писателя. Разрешённое новое действие
доступно, увеличивает версию ровно на один и делает ровно второй SET с учётом
исторического. В этом SET сохраняются свежие поля A и присутствует новое
значение B либо новый КИЗ. Предыдущая принятность не означает принятие нового
действия: результат его отдельной проверки здесь не подменяется.

Ещё шесть контролей после каждого свежего результата проверяют устаревшую
expected_version для documents и marking: 409 с кодом
`ozon_exemplar_documents_conflict`, без изменения данных и вызова провайдера.

Здоровый accepted GET и прежние unknown/active writer/late GET контроли
переиспользованы запуском существующего неизменённого
