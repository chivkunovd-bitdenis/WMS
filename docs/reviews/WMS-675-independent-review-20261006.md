## Подтверждённые замечания

### F1 · высокий приоритет: P6 запрещает обязательный отчёт и общий кандидат

В `backend/tests/test_wms675_recovery_evidence_contract.py:187–207` проверяется весь `git diff 5b897e1553f8201fb67a404b26ecae14e46179bb...HEAD`. Разрешены только файл контракта, требования и дерево frozen evidence. Файл этого обязательного ревью не разрешён. Проверка в памяти с добавлением только его пути к реальному выводу Git дала конкретную ошибку:

```text
WMS-675 preparation changed non-evidence files: ['docs/reviews/WMS-675-independent-review-20261006.md']
```

После сохранения этого отчёта следующий запуск P6 отвергнет корректный результат ревью. По той же причине интеграция принятой зависимости 662 или любых других задач общего выпуска будет воспринята как запрещённый diff675, хотя требования отдают общую интеграцию root. Зелёный результат на 744010e30 не переносится на SHA с отчётом и общий кандидат.

Вернуть отдельному тестировщику: проверка должна сохранять строгие границы изменений самой дорожки, но оценивать её определённый диапазон коммитов/кандидат и разрешённые документы, а не все изменения произвольного будущего HEAD. Не снимать проверку постороннего продукта и не ослаблять хэши evidence. Ревьюер контракт не исправляет.

### F2 · высокий приоритет: контракт зависит от истории Git, которой backend CI не получает

`_source_bytes()` выполняет `git show d61805978b3e7878d1056c99b4e6e0823edf49a5:<path>`, а P6 также требует `git ls-tree` того же источника и merge-base с `CONTRACT_BASE`. В backend job `.github/workflows/ci.yml:77` используется `actions/checkout@v4` без настройки глубины истории и без отдельного получения этих ревизий перед pytest. Стандартный короткий checkout этого action не предоставляет произвольный исходный commit из другой ветки и старую базу. Наличие объектов в общем локальном Git-хранилище worktree скрывает зависимость.

Это вывод из конфигурации и вызовов Git, не заявление о выполненном удалённом CI. В таком checkout контракт завершится ошибкой Git ещё до проверки raw evidence; полный fetch в других jobs не распространяется на backend job. Вернуть тестировщику/координатору: обеспечить воспроизводимость проверки на CI-кандидате с достоверно закреплённым источником, не заменять отсутствие источника пропуском/успехом. Изменение общего CI требует владельца этого участка; ревьюер его не меняет.

### F3 · средний приоритет: P4 не проверяет свежесть новой передачи

P4 (`:135–146`) читает только два frozen файла — `recovery_plan_exact.json` и RECOVERY_PLAN.md. Он проверяет исторические `NOT_PERFORMED`, `mutation_authorized=false`, `totals.current662_missing_delta=11` и наличие четырёх буквальных фраз плана. Ни новый отчёт подготовки, ни даты manifests, ни текущая неизвестная missing delta не читаются. Поэтому при неизменных frozen файлах подмена свежести в новом разрешённом документе не влияет на результат P4. Это расходится с указанной в требованиях автоматической частью P4, которая должна проверять структуру/происхождение данных, а не фразы реализации.

Сама текущая постановка и handoff честны: старые26 не названы актуальной командой, current delta неизвестна. Дефект относится к силе контракта, а не к установленной подмене данных в кандидате. Вернуть тестировщику: проверять отдельные данные новой передачи и происхождение/время снимков, сохраняя raw JSON; предусмотреть отрицательный случай, когда historical26/11 объявлены текущей дельтой без свежих источников. Содержательную проверку последовательности по-прежнему выполняет аналитик в P8.
