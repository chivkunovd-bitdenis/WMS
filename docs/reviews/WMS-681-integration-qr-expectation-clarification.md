# WMS-681: уточнение ожидаемого QR при объединении веток

Это ограниченное решение аналитика по уже утверждённым требованиям, принятое 07.10.2026 по поручению ведущего. Требования не изменены, новая реализация или новые тесты этим документом не приняты.

Проверены `docs/requirements/WMS-681.md` (исходные слова, R1 и продолжение R4–R7/C5–C11), общий файл `frontend/src/screens/v2/FfFbsSupplyWorkspace.assembly.dom.test.tsx` из временного объединения `95b4728eb58793e3a58cb89b057e53ba8b9228a5`, а также тот же файл из продуктовой цепочки WMS-681 `5eb18bc0ca54c2005ef551c2877c5dd3943ec01e`. Современная тестовая поверхность из общей базы сохраняется; целый старый файл из 681 переносить нельзя.

## Что заменено последующим утверждённым поведением

Старый случай «WMS-681: короб без грузоместа WB не печатает внутренний QR вместо этикетки WB» на временно сохранённой общей базе требует `retry-qr` length 0 после явного нажатия «QR» и безусловный текст «Грузоместо WB для короба не создано». Такие ожидания описывают первоначальное исправление, остановившее ложную печать. Продолжение R4/C5 явно требует восстановления прежней группы через существующий серверный путь после этого же действия. Поэтому отсутствие recovery-запроса при явном «QR» и безусловный прежний текст законно заменены последующим поведением. Никакого разрешения незапрошенного автоматического восстановления это не создаёт.

После явного «QR» непривязанного WB-короба должен вызываться существующий `retry-qr`. Для успешной синтетической fixture сервер возвращает настоящую ready-этикетку WB в новом снимке: её получение и окно предварительного просмотра ожидаются. Для fixture отказа сервер возвращает ошибку, настоящего ready-asset нет: окно не открывается, причина видна. Точный старый текст про отсутствие грузоместа не обязателен при иной фактической причине, например таймауте WB. При частичном серверном сохранении следует читать свежий снимок и сохранять доступные настоящие этикетки. Это следует из R4–R6, а не из удобства теста.

## Что сохраняется

Запрет печатать локальный FBS-код вместо этикетки WB (R1) остаётся обязательным. Нельзя просто убрать отрицательный случай: он должен по-прежнему ловить ложное окно/локальный QR при отказе или отсутствии готовой настоящей этикетки. Позитивный случай восстановления проверяет другой исход того же явного действия. Идентификаторы физических коробов, содержимое и исходный ключ прежние; неизвестный внешний результат не повторяется вслепую; одна группа не создаётся дважды (R4/R5). Массовая печать получает свежие QR, сохраняет готовую часть, показывает недоступную часть, а при нуле готовых не открывает окно (R6).

Запреты recovery-запроса без явного печатного действия сохраняются в прежних случаях: обычный скан, создание короба с выключенной автоматической печатью и переключение упаковки/коробов сами не запрашивают QR. Проверки отсутствия лишнего старта, современной общей полосы сканирования, ожидания КИЗ и сохранения выбранного короба при задержанном скане не отменены. Ветка 681 основана на старой тестовой поверхности: её изменения общего harness, возврат кнопки «Начать работу», старого поля КИЗ и прежних сценариев упаковки не имеют основания в WMS-681. Следует переносить только необходимые QR-fixture/QR-cases в сохранённый современный harness, сохраняя остальные прежние ожидания. Ozon, tenant/seller/supply, остаток, резерв, тариф, КИЗ и передача поставки не меняются (R7).

Тестировщик и разработчик самостоятельно сохраняют контракт, RED, исправление и независимое ревью требуемого изменения тестовой интеграции. Этот документ не объявляет их выполненными и не принимает ещё не проверенный объединённый код.
