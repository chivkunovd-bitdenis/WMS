## Собственные проверки

Проверены точный Git diff между контрактом и коррекцией, полный исходный текст
теста и принадлежащей задаче миграции. `git diff-tree` подтверждает, что коммит
коррекции меняет ровно один файл теста. Исходный контракт замораживает три файла
после исключения документа требований: этот тест, `test_wms654_cells.py` и
`CatalogSection.wms654.test.tsx`. Коррекция является строгим подмножеством 1/3;
два остальных файла побайтно неизменны в HEAD. Git ancestry подтверждает порядок
контракт → коррекция → проверяемый HEAD. Файл перед коррекцией совпадает с
исходным контрактом, нынешний файл — с коррекцией.

Однократная проверка стандартным Python (`ast`, `subprocess`, XML parser)
завершилась exit 0 и установила:

- Все **12 узлов `assert`**, включая сообщения, полностью совпадают в AST —
  структуре Python-кода без номеров строк. Не изменены равенство старых строк,
  nullable tier, `None` у старых записей, координаты перечитанной новой ячейки
  и разрешение старого штрихкода.
- После исключения присваиваний `baseline_files` и `new_revisions` всё тело
  асинхронного теста совпадает по AST. В текущем файле нет `try`, `pass`,
  `skip`, `skipif` или `xfail`; исключения не превращаются в успех.
- Исполнение исходного неизменённого утверждения о наличии `tier` с пустым
  словарём колонок даёт ожидаемый `AssertionError: Upgrade left old storage
  schema without persisted tier`. Это структурное подтверждение отказа,
  не новый запуск на PostgreSQL.
- Разность списков файлов Git между старым baseline и общей базой
  `f71b99c0f19bdbf48e8e0b95b62aefe8709307fc` содержит ровно девять чужих
  миграционных файлов. При добавлении собственного файла точное условие нового
  selector совпадает только с ним и ни с одним из девяти.

По исходному коду новый helper перебирает ревизии настоящего
`ScriptDirectory.from_config(config)` и выбирает единственное точное имя
`20261007_2302_wms654_location_tier.py`. Миграция имеет revision
`20261007_2302`, down_revision `20261001_2301`; её upgrade только добавляет
nullable Integer `tier` в `storage_locations`. Файл миграции одинаков в
коррекции и проверяемом HEAD. Выбор основан на принадлежности задаче, а не
на результате выполнения миграции.

Если нужного файла нет в корректно загружаемом каталоге, helper возвращает
пустой список. Тест всё равно удаляет `tier` из схемы, созданной текущими
моделями, и выполняет прежнее утверждение о его восстановлении; оно падает.
Если каталог повреждён и Alembic не может построить граф, исключение также не
подавляется. Пустой выбор не даёт ложного PASS.

Старое условие брало все файлы, которых не было в `4b298efc`, поэтому на общей
базе захватывало девять посторонних исторических миграций. Тест создаёт текущую
схему через модели и восстанавливает только отсутствие `tier`: повторное
применение посторонних upgrade в этом сценарии выходит за его подготовленное
исходное состояние. Ограничение собственной миграцией соответствует C8/R5/R7;
исходный тест и раньше не являлся прогоном всей истории Alembic с пустой БД.
