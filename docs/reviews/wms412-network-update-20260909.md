# WMS-412 — обновление Android через сеть, 09.09.2026

Статус: **ОПУБЛИКОВАНО · СЕТЕВОЕ ОБНОВЛЕНИЕ 7→8 ПРОЙДЕНО В ПРИЛОЖЕНИИ**.

09.09 в 18:58 МСК Android установил 0.1.7-network-update через системный
com.google.android.packageinstaller после скачивания кнопкой приложения.
Вход тем же PIN и прежняя незавершённая поставка сохранились.

На главном экране добавлено «Обновление приложения». Экран показывает установленную
версию и проверяет опубликованный update.json. Только новая совместимая версия
предлагает скачивание. APK скачивается отдельным HTTP-клиентом без авторизации WMS
в закрытый кэш приложения. Неполный файл удаляется; перед установкой повторно
проверяются размер, SHA256, package, версия, minSdk и совпадение сертификатов подписи.
FileProvider открывает установщику только подпапку updates. В Android 8+ при необходимости
открывается системное разрешение для этого приложения; затем сотрудник повторно
нажимает установку. Финальное подтверждение выполняет Android. Автоматического
запуска установки во время складской работы нет, новые таблицы не добавлены.

Источник обновлений: [публичный выпуск tsd-preview](https://github.com/chivkunovd-bitdenis/WMS/releases/tag/tsd-preview).
APK 8 и update.json опубликованы после отдельного прямого разрешения владельца
«да, делай». Предыдущий отказ auto-review разрешён; ожидающего запроса больше нет.
GitHub подтвердил state=uploaded и SHA256 файла, идентичный локальному APK.
Публичный update.json заново скачан и полностью совпал с сохранённым описанием.
Полная история mobile и ключи подписи не опубликованы. Это debug-сборка
с существующей подписью Android Debug, не новый production-signing.

## Реальная проверка обновления в Android

В APK 7 нажаты «Проверить обновление» и «Скачать обновление». Приложение нашло 8,
загрузило 43 МБ с публичного GitHub и показало «Обновление скачано и проверено».
Нажата установка, открыт штатный экран разрешения Android, включено разрешение
только для WMS ТСД. После возврата файл сохранился; повторное нажатие открыло
системный диалог «Do you want to update this app?». Нажато Update.
Для перехода 7→8 adb install не использовался.

После установки Android сообщил versionCode 8 /0.1.7-network-update,
installerPackageName=com.google.android.packageinstaller, lastUpdateTime 18:58:35.
SHA256 установленного base.apk совпал с опубликованным файлом 91b6e431…88c90c9.
Приложение открыто обычной иконкой, сохранённый сотрудник вошёл прежним PIN
без пароля. На экране обновлений повторная проверка показала «Установлена
последняя версия». FBS получил список с сохранённого сервера, открыта прежняя
WMS401-Android-0909-1346: 2 заказа, подобрано 2, упаковано 2, передача не выполнялась.
В версии 8 также проверен выход на главный экран Android и возврат: открытая
поставка сохранилась, пустого экрана при этом не было (resumed8.png).
Системные сведения, публичные метаданные и снимки нажатых экранов — в artifacts рядом.

Ограничения: проверено в существующем emulator-5554 на Android 15. Физический
ATOL / Android 7 этим прогоном не проверен. Перед сетевым сценарием старая версия 7
однократно показала пустой экран после длительной паузы; crash-log AndroidRuntime
был пуст, перезапуск приложения восстановил обычный вход. Причина не установлена,
эта отдельная аномалия не объявляется исправленной обновлением. Общая физическая
приёмка мобильного WMS-401 остаётся открытой.

## Как выпускать следующие версии

1. Увеличить versionCode и versionName в Android-проекте. Сохранить код commit.
2. Собрать APK с тем же applicationId и прежней подписью. Для новой подписи эта
   цепочка обновления не подходит; управление ключами в эту задачу не входит.
3. Сохранить APK с уникальным именем, проверить apksigner/aapt, вычислить размер
   и SHA256. Сформировать update.json того же формата, что сохранён рядом.
4. После разрешённой публикации загрузить новый APK в тот же выпуск tsd-preview,
   затем заменить update.json. Старые APK не заменять другим содержимым.
5. На устройстве открыть обновление, скачать, подтвердить установку Android;
   проверить новую версию, сохранённый вход и свою незавершённую поставку.

Официальный контракт: https://developer.android.com/reference/androidx/core/content/FileProvider
и https://developer.android.com/reference/android/content/pm/PackageManager#canRequestPackageInstalls().
