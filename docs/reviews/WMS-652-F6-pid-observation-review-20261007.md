# WMS-652 / F6: независимое ревью фиксации PID

**PASS для узкой коррекции F6 fixture в `e2495dfa50767f156e6f54d91889c6067d6d5625`, после тестового контракта `fb05f4dc22a1fb6b62ab0d52be2729ae4b449f3c`.** Это продолжение независимого ревью gpt-6.1-sol/high. PASS `27a33df9abe2e2dd22c67631609a02b98c69664f` для b6/P989 сохраняется; его проверки не повторялись. Текущий SOURCE/main и отдельная дельта 672 здесь не рассматриваются и не одобряются.

Прочитаны реальные Git blobs обоих тестов, root diagnosis и backend-checks-419.log. CI run 37550233864 действительно содержит 3 PASS / 1 FAIL: observed_status-normal остановился на одинаковых последних PID 90/90 после подтверждения contention. Поздние бизнес-проверки этого случая тогда не исполнялись. Возможное переиспользование соединения обосновано listener/transaction кодом; конкретный checkout в старом логе не зафиксирован, поэтому его нельзя выдавать за непосредственно наблюдённый факт.

Коррекция сохраняет копию двух PID, переданных конкретному PostgreSQL запросу, **до await**. Она записывается в observed_pids только при истинном pg_blocking_pids результате, до release; live map и полная live PID trace остаются диагностикой. Проверка двух независимых PostgreSQL backend IDs сохранена и относится к моменту реально подтверждённого ожидания. Это не замена connection assertion одним флагом contended и не произвольный первый/setdefault PID.

Собственный AST/replay исполнил неизменённую функцию нового frozen regression против реальных методов fixture обоих SHA: до коррекции RED AttributeError observed_pids, после PASS. Regression не тавтология: observer проверяет текст запроса и точные bind values, а после подтверждения тест изменяет live map так, чтобы старая завершающая проверка ошибочно видела один PID. Дополнительные собственные сценарии доказали сохранение правильной пары при изменении live map непосредственно во время await и перед release; неподтверждённый block и искусственный same-PID ответ по-прежнему отвергаются конечной connection assertion. Это адресный replay методов, не исполнение настоящей PostgreSQL гонки.

History подтверждает test-before-correction: e249 имеет непосредственным родителем fb05. Обе исходные параметризации normal/observed × local/observed_status сохранены побайтно в AST. Все последующие SQL-error/deadlock, lock hierarchy, stock/reserve, cancellation/handoff, billing и повторные idempotency проверки сохранены; бизнес-хвост после `assert not schedule.errors` побайтно идентичен. Нет product, policy, workflow или бизнес-ожиданий в этой коррекции. Четыре исходных F6 ID не переименованы и не удалены; новая regression — отдельное добавление.

В пределах ограниченного ожидания появился отдельный evidence commit `d88c0773419f984ab12ba8f78f88ac88eee02e83`. Проверены фактические raw XML четырёх PG-кейсов и regression, SHA-256 всех четырёх XML/log артефактов совпали с immutable evidence. XML содержит **все четыре исходных случая PASS, без failure/error/skipped**, отдельная regression — 1 PASS. PostgreSQL startup/shutdown log подтверждает отдельный PG17 на 55467. Исполнение выполнил исходный тестировщик; reviewer независимо разобрал raw receipts, собственного PG прогона не дублировал. Поэтому новый адресный результат подтверждён в этой границе, но не заменяет CI интеграционного SHA. Первоначальный connection refused и старый CI FAIL сохраняются исторически, не переписываются в PASS.
