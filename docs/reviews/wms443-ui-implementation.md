# WMS-443 · реализация web и ТСД

## Изменения

Web использует основной вход `POST /auth/login-by-name` с ФИО и паролем. На той же форме есть компактный переходный путь через совместимый `POST /auth/login` для старой учётной записи. Шапки, карточки сотрудников, тарифы, упаковка и журналы ЧЗ выводят `display_name` или новые поля автора `*_name`; контактные email селлеров не менялись.

В существующих настройках ФФ и селлера добавлены редактирование собственного профиля через `PATCH /auth/me`, создание сотрудника с ФИО, необязательной должностью и паролем, а также правка ФИО/должности в строке соответствующего сотрудника. Роль и права остаются самостоятельными существующими полями.

ТСД использует те же новый и переходный входы. После токена он обязательно читает профиль; при ошибке профиль не создаёт сессию. Новый PIN-ключ включает нормализованный адрес сервера, `organization_slug` и `user_id`; на Home и в выборе сотрудника показаны ФИО и должность. Изменения Android сохранены отдельным commit `76babe2559d0e4603c690cbaebe9f36f291c9594`; переносимый исходный diff находится в `docs/reviews/artifacts/wms443/mobile.patch`.

## Проверки исполнителя

- `frontend`: `npx tsc --noEmit -p tsconfig.app.json` — успешно.
- `frontend`: `npm run build` — успешно.
- `git diff --check` для web и Android — успешно.
- Исходный web-экран Settings на локальном 5197 просмотрен до изменений: шапка и сотрудники действительно показывали email. Попытка открыть свой Vite на 5205 в subagent browser не поддержана средой, поэтому браузерная проверка изменённого экрана остаётся для независимого ревью/приёмки.
- Gradle и emulator-5580 не запускались: они выделены другой WMS-задаче. Android-тесты обновлены по новому контракту, но запуск ожидает выделения слота.

Это не заключение независимого ревью и не приёмка аналитика.
