## Единственный предметный внешний шаг

На общей проверенной версии оператор использует существующий Ozon-заказ,
которому действительно требуется ГТД или РНПТ. Зафиксировать версию общей сборки,
seller/posting и целевой product/exemplar без ключей и персональных данных.

1. Открыть заказ в «Упаковка и маркировка» → «ГТД / РНПТ». Убедиться, что
   показаны реальные экземпляры и нужный документ; подготовка create-or-get
   является отдельным действием оператора, если экземпляры ещё не созданы.
2. Ввести настоящий номер или выбрать фактически допустимое «номера нет» только
   у нужного экземпляра; сохранить. Сохранить внешний ответ set/status и экран:
   HTTP 200 set показывает проверку, итоговое принятие должно подтверждаться Ozon.
3. Обновить проверку, закрыть/повторно открыть заказ. Тот же выбор и фактический
   результат сохранены, повторного слепого set нет; соседние сведения не потеряны.
4. После принятия оператор продолжает свою штатную сборку. Зафиксировать внешний
   результат и сохранение документов. Этот сценарий не поручает агенту внешнюю
   сдачу, физическую отгрузку, списание или вывод КИЗ.
5. Если имеется настоящий отказ Ozon по документу, сохранить его причину,
   исправить реальные сведения, снова сохранить/проверить/reopen. Намеренно
   ложные номера не придумывать. Без такого случая подпроверка отказ→исправление
   остаётся непроверенной и весь C19 не становится PASS.
