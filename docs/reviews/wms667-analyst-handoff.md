# WMS-667: передача от аналитика тестировщику

06.10.2026. Подтверждённая версия `169df20e4ada819c9aa2`, сообщение автора #230.
Полный контракт и проверки C1–C10: [требования](../requirements/WMS-667.md).
Постановка выполнена самостоятельно по прямому поручению владельца, без навыков
и дочерних агентов. Рабочая ветка `codex/wms667-stock-filter`; свежий etalon
`0f1460b023700a99f17b504d6af3934a02bc68cc` уже включён без конфликтов.

Сначала отдельный тестировщик пишет C1–C9, сохраняет доказательство RED
(проверка падает именно из-за отсутствующего поведения, а не ошибки окружения)
и коммит `WMS-667: контракт тестов`. Ссылки на реальные тесты и результаты
нужно заполнить в требованиях; сейчас они не объявлены существующими.
Для чистых регрессий C7 допустим исходный PASS, но он не заменяет RED C1/C3/C8.

Использовать реальный API `/products/ff-catalog-page` и тестовую БД, сверяя
значения с `/operations/inventory-balances/summary`. Подходящие существующие
примеры — `backend/tests/test_wms538_ff_catalog_batch.py`,
`backend/tests/test_wms418_catalog_publication_filter.py`; UI монтировать
реальным компонентом по образцу
`frontend/src/screens/v2/FfProductsCatalogScreen.sellerUrlFilter.dom.test.tsx`.
Не ограничиваться проверкой текста исходника или подменённой функцией фильтра.
Разработчик не меняет ожидания контракта тестов.

Фильтрация должна произойти на сервере до счёта/пагинации, по той же семантике
`on_hand`, что используется для отображаемого `quantity`. Тест C3 специально
отличает это от фильтрации уже загруженной страницы. C2 и C5 отделяют общий
остаток от доступного количества и настроек FBS. Новых сущностей учёта не нужно.

Браузерный осмотр существующей вкладки стенда не выполнен: она занята другой
сессией автоматизации. Это оставляет C10 для последующей ручной приёмки;
дизайн прочитан только в текущем коде. Production, авторизация, секреты и
записи Telegram не затрагивались.

Состояние бота прочитано напрямую через SQLite в режиме `mode=ro`, без
инициализации Store и без записей. Две найденные записи agent_job, содержащие
WMS-667, имеют `status=done`; у ticket 18 этап `failed`, hotfix отсутствует.
В проверенном снимке активного дублирующего задания не обнаружено. Нового
задания боту не создавали. Перед реальным запуском тестировщика контроллер
должен перечитать актуальное состояние, поскольку снимок может измениться.

Эта передача не является приёмкой продукта или разрешением на выпуск.
