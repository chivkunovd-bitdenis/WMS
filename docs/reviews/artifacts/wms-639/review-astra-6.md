**Набор инструментов: оценка конкретных возможностей.** В разделе 11 приведены и список, сообщённый моделью, и `Object.keys(tools)` из живого вызова. Отключения в `CODEX_DISABLED_FEATURES`, `CODEX_EXTRA_CONFIG` и `build_codex()` соответствуют итоговым настройкам отчёта; они применяются и к новой сессии, и к resume. У аналитика выбран read-only, сторонняя пользовательская конфигурация и правила не подгружаются. Самостоятельный повтор платного вызова в этом круге не выполнялся.

- `functions.exec` в описанной среде исполняет JavaScript без `fs`, `require`, `process`, `Deno`, `fetch` и импортов. В перечисленных вложенных инструментах нет командной оболочки, веб-поиска или просмотра произвольного файла. Вызов разрешённого MCP из JavaScript сохраняет проверки читателя; произвольный JavaScript сам по себе не даёт системных возможностей.
- `collaboration.*` управляет сессиями агентов. По живой проверке раздела 11 дочерний агент получил тот же ограниченный набор. Конкретного перехода к агенту с командной оболочкой, другим читателем или сетью в предоставленных данных нет.
- `request_user_input` не даёт файлового или командного доступа; в неинтерактивном запуске не предоставляет дополнительного канала действий.
- `apply_patch` отклоняется read-only песочницей, включая попытку вне каталога. Конкретного сценария раскрытия содержимого файла через этот инструмент в указанной конфигурации не обнаружено.
- Общие `list_mcp_resources`, `list_mcp_resource_templates` и `read_mcp_resource` не являются произвольным файловым читателем: собственный сервер объявляет только пять инструментов, а методы ресурсов в его обработчике не реализованы. Подключение стороннего сервера этими методами не предоставлено.
