## Новое замечание

### F2 — существенное (P2): прерванная загрузка iframe оставляет печать заблокированной

**Место:** `frontend/src/screens/ff/inventory/printInventorySheet.ts:181`
и `:215–216`; последствие — ожидающий `await` в
`frontend/src/screens/ff/inventory/FfInventoryPage.tsx:288` и недостижимый
для этой попытки сброс флага на `:291–293`.

**Что и почему.** Единственный вход в завершение нового Promise — `iframe.onload`.
Если подготовка iframe оборвана до этого события, Promise не разрешается
и не отклоняется. Нет ни ограниченного ожидания загрузки, ни завершения при её
прерывании. В частности, проверка `contentWindow === null` тоже выполняется только
внутри `onload`: она не спасает случай, когда загрузка вообще не завершилась.
Таймер на 100 мс ставится лишь после `onload` и страховкой загрузки не является.
В результате кнопка остаётся отключённой, а повторный запрос недоступен до
пересоздания страницы. До этой правки незавершившийся iframe не удерживал флаг
страницы навсегда — это новое последствие добавленного ожидания.

**Как воспроизведено.** В отдельном тесте с настоящим `FfInventoryPage`:

1. Открыть документ, нажать «Печать листа», вернуть успешный ответ `/print-sheet`.
2. Удержать `onload` созданного iframe, моделируя прерванную загрузку; не вызывать
   его вручную. Дополнительно отправлен `error`, который тоже не завершает попытку.
3. Продвинуть виртуальное время на 60 000 мс. Проверить, что отложенных таймеров
   нет, кнопка всё ещё `disabled === true`.
4. Нажать кнопку: число запросов остаётся равным 1, повтор невозможен.

Все эти утверждения воспроизведены. Бесконечность ожидания следует не из одной
минуты теста, а из отсутствия другого пути завершения в коде: при окончательно
прерванной загрузке больше нечему разрешить Promise.

**Граница доказательства.** Это управляемая имитация незавершившейся загрузки
в jsdom, а не зарегистрированный инцидент в production и не проверка клавиши
остановки загрузки в конкретном браузере. Не утверждается, что браузер обязан
выдавать `error` для `srcdoc`: отсутствие восстановления уже видно без этого
события. Частота и конкретный браузерный способ прерывания здесь не установлены.

**Что исправить.** Обеспечить завершение неудачной подготовки до `onload`
с освобождением флага и возможностью повторить печать. При прекращении ожидания
отменить обработчик/таймер и убрать iframe, чтобы его поздняя загрузка не открыла
старое окно поверх новой попытки. Добавить компонентную проверку: загрузка
не завершается → отказ подготовки → кнопка снова доступна → новый запрос работает;
поздний `onload` старой попытки не печатает. Снимать флаг просто по времени,
оставляя прежний iframe способным напечатать, нельзя: это вернёт дубликаты F1.

Других подтверждённых замечаний к указанному diff нет.

## Проверенные исходы и пределы проверки

Дополнительный временный набор импортировал настоящий компонент из worktree,
использовал его реальные дочерние компоненты и функцию печати. HTTP и методы
окна подменялись для воспроизведения исходов. В репозиторий этот набор не добавлялся.

| Исход | Наблюдение |
| --- | --- |
| Успешная подготовка, второй клик до загрузки | Один запрос и один `print()`; штатный компонентный тест проходит. |
| Намеренный повтор после возврата `print()` | Новый запрос уходит; кнопка разблокирована. |
| HTTP 500 | Iframe не создаётся; кнопка разблокируется, следующий клик отправляет новый запрос. |
| `contentWindow === null` при `onload` | Iframe удаляется, Promise завершается; компонент снова допускает запрос. |
| `frameWindow.print()` бросает исключение | `catch` удаляет iframe, `finally` завершает Promise; повтор доступен. |
| Закрытие/отмена, представленная событием `afterprint` и возвратом `print()` | Iframe удаляется; повтор доступен. У события нет различия между печатью и отменой. |
| Загрузка не доходит до `onload` | Кнопка остаётся заблокированной; F2. |

Ошибка `focus()` отдельно не воспроизводилась: по коду она перехватывается
и не мешает поставить таймер печати. Исключение при самом чтении `contentWindow`
или регистрации `afterprint` не покрыто имеющимися тестами; эти действия находятся
вне `try` асинхронного обработчика. Реальный сценарий такого исключения для
создаваемого здесь same-origin `srcdoc` не установлен, отдельным дефектом это
не объявляется.

Разрешение Promise связано с возвратом `print()`, а `afterprint` только удаляет
iframe. Поэтому проверка подтверждает требование F1 «не раньше фактической попытки»,
но не универсальное ожидание закрытия нативного диалога: HTML Standard допускает,
что браузер не ждёт решения пользователя перед возвратом из `print()`.
Источник: [HTML Standard, Printing](https://html.spec.whatwg.org/multipage/timers-and-user-prompts.html#printing).
Реальное закрытие/отмена системного диалога, блокировка взаимодействия с основной
страницей и физическая печать в этом ревью не проверялись. Изолированный браузер
через доступный интерфейс `iab` запустить не удалось: `Browser is not available: iab`.
