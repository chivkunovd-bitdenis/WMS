# WMS-402 · сетевая печать с ТСД — патч для мобильного репозитория

`tsd-network-print.patch` переводит печать этикеток на ТСД с локального
системного диалога печати на очередь печати WMS. Тем же путём идут все виды
этикеток: QR заказа и короба, товарный штрихкод и код ЧЗ — разметка листа
не меняется, меняется только адресат.

Патч правит пять файлов мобильного приложения:

- `core/api/fbs/FbsApi.kt` — вызов `POST operations/fbs-print-jobs/document`;
- `core/api/fbs/FbsModels.kt` — тела запроса и ответа задания печати;
- `features/fbs/FbsPrinting.kt` — та же разметка выводится в PDF вместо
  системного диалога печати;
- `features/fbs/FbsViewModel.kt` — номер задания на одно нажатие кнопки и
  отправка листа в очередь;
- `features/fbs/FbsScreens.kt` — единственная точка вызова печати и строка
  статуса задания.

## Исходный коммит

Патч собран и проверен на применимость против мобильного репозитория в
состоянии `af9693126d19d16918abd5cc7b7fbe99dfebc142` (ветка
`codex/wms397-mobile`, `WMS-401 WMS-412 restore login back navigation and FBS
chronological order`). На другом коммите сначала проверьте применимость.

## Как применить

Из корня мобильного репозитория:

```bash
git rev-parse HEAD   # ожидается af9693126d19d16918abd5cc7b7fbe99dfebc142
git apply --check -p1 <путь>/tsd-network-print.patch
git apply -p1 <путь>/tsd-network-print.patch
```

`--check` ничего не пишет на диск: он только сообщает, ложится ли патч.

## Что дальше

После применения нужна **одна сборка Android** — её выполняет владелец.
Сборка здесь не запускалась, поэтому компиляция патча не подтверждена.

При сборке отдельно посмотрите на `FbsPrinting.kt`: наследники
`PrintDocumentAdapter.LayoutResultCallback` и `WriteResultCallback` создаются
из кода приложения. В `android.jar` эти конструкторы доступны, но проверить
это без сборки было нельзя — если компилятор ругнётся именно на них, дальше
смотреть надо там.
