## Покрытые writers

Новые события используют существующие `document_created` и `data_changed` в существующем `DocumentEvent`. Ни новых типов документов/событий, ни таблиц, счётчиков, статусов или параллельных журналов нет.

| Приёмка, короба | `create_open_box`, `create_boxes_for_request`, `open_box_by_barcode`, `close_box_intake`, существующий `_close_open_boxes`, `mark_box_label_printed`, `delete_empty_box` |

| Повреждение | Единственное существующее присваивание `is_damaged` в API обрамлено before/after. Второго writer или повторного commit не добавлено. Оба направления true/false фиксируются, равное значение пропускается |
| MP, документ | `create_request`, `delete_draft_request`; удаление пустых коробов существующим `delete_empty_boxes_for_ship` |

При удалении документа before содержит явные идентификаторы дочерних коробов/грузомест; after=null. При отдельном удалении тары сохраняются её идентификатор и предыдущее состояние. История не привязана внешним ключом к удалённому документу/коробу. Имеющиеся события изменения количества и строк не заменены и не дублируются. Автоматические события статуса, даты и количества остаются единственными для этих изменений. `inbound_cargo_place_service.py` прочитан, но не изменён: его quantity writer уже пишет tare-событие, а создание/печать находятся в inbound_intake_service. Отдельного существующего writer удаления или закрытия грузоместа в разрешённых файлах нет; новый endpoint или жизненный цикл ради журнала не создавался.

Payload — только явная проекция: идентификаторы, номер короба/грузоместа, перечисленные статусы/признаки, реквизит `waybill_number`, количество плановых коробов, место хранения, время отметки печати. `waybill_number` — отдельно разрешённый постановкой идентификатор накладной; произвольные заметки, free_text, сериализация модели/запроса, токены, содержимое файлов и коды маркировки не добавлены. Отметка повторной печати меняет существующее время и потому даёт новый факт; повторное присваивание того же флага или реквизитов не даёт события. Отметка печати не названа доказательством физического выхода этикетки из принтера.

Каждый новый факт проходит через неизменённый `record_document_mutation`: автор берётся из контекста после аутентификации, а не из body/параметра user_id; сохраняются ID и снимок имени с tenant-проверкой. Явный system-контекст остаётся system. Снимок не меняется при переименовании пользователя. Новых блокировок строк, NOWAIT, навигационных/аудитных разрешений или дополнительных commit нет. Ошибка записи истории изолируется существующими savepoints (точками отката); гарантии полной истории при отказе хранилища не добавлены.
