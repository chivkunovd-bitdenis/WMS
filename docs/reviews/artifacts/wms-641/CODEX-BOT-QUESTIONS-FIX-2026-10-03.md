# WMS-641 · Бот засыпает клиента вопросами: установить правку и переразобрать обращение

Задание для Codex на маке владельца, 03.10.2026. Сначала прочитай
[HANDOFF-2026-10-03.md](HANDOFF-2026-10-03.md): там пути, службы и грабли.

## Что случилось

Клиент в чате подробно описал проблему. Аналитик бота не стал разбираться сам: не посмотрел код, не
сопоставил слова клиента с тем, что в WMS уже есть (уникальные коды коробов, возвраты и т. п.), и
устроил клиенту полный опрос, причём уже второй раз.

Слова владельца: клиент должен делать минимум. Бот сначала сам смотрит код и данные, сопоставляет и
анализирует. Спрашивает только если без ответа реально нельзя принять решение, и тогда 1–2 точечных
вопроса.

## Что уже сделано (в облаке, ветка `feat/wms641-support-agent`)

Коммит **d0977e05** поверх 3094f1df / ce616547, запушен:

- `support_agent/prompts.py`: у аналитика обязательный порядок. Перечитать всё, что написал клиент;
  найти в коде, как устроен процесс; сопоставить с тем, что в системе уже есть; при доступе к базе
  проверить там; выбрать самое вероятное толкование. Вопрос только если решение невозможно, не больше
  1–2, и никогда не переспрашивать то, что клиент уже написал или о чём уже спрашивали.
- `support_agent/pipeline.py` + `config.py`: `limits.max_client_asks` (по умолчанию **1**, было
  захардкожено 2), не больше 2 вопросов в одном обращении к клиенту. Отдельный вопрос «мешает ли это
  работе прямо сейчас» выключен: `limits.ask_client_urgency = false`.
- Тесты в `tests/test_pipeline_chat.py`. В облаке ruff и mypy чистые, новые тесты зелёные. **48
  тестов требуют macOS-песочницу (`sandbox-exec`) и в облаке не запускались**: до правки падали те же
  48, но на маке их надо прогнать.

Служба на маке **ещё на старом коде** (3094f1df), правка не установлена.

## Что сделать

Работай в `~/Projects/WMS/.worktrees/wms639-support-agent` (ветка `feat/wms641-support-agent`).
Состояние агента (`~/.wms-support-agent/state.db`, `config.json`) не удалять и не пересоздавать.

1. **Подтянуть ветку.**
   ```
   cd ~/Projects/WMS/.worktrees/wms639-support-agent
   git pull origin feat/wms641-support-agent
   git log -1 --format=%H   # должен быть d0977e05… или новее
   ```
2. **Прогнать тесты агента на маке.**
   ```
   cd tools/support_agent
   .venv/bin/python -m pytest tests -q
   ```
   Ожидаемо: всё зелёное, кроме одного известного падения проверки uppercase SHA в workflow выкладки
   (см. хэндофф). Любое другое падение — сначала чинить, не ставить.
3. **Установить в службу** тем же способом, что в хэндоффе:
   ```
   SHA=$(git rev-parse HEAD); T=$(mktemp -d)
   git archive "$SHA" tools/support_agent | tar -x -C "$T"
   bash "$T/tools/support_agent/launchd/install.sh"
   launchctl print gui/$(id -u)/pro.sellerfocus.wms-support-agent | grep state   # running
   ```
   Сверить, что файлы в `~/.wms-support-agent/app` совпадают с этим коммитом (как сверял в прошлый раз).
4. **Конфиг.** Новые ключи не обязательны: если в `config.json` в `limits` их нет, действуют умолчания
   (`max_client_asks: 1`, `ask_client_urgency: false`). Если там явно стоят другие значения, привести к
   этим.
5. **Найти обращение.** В `state.db` найти последнее клиентское обращение, где бот задавал клиенту
   вопросы (`tickets`, `messages`; сообщения бота клиенту — `outbox` с `purpose = 'client'`).
   Прочитать всю переписку клиента по нему. Владельцу коротко: номер обращения, чат/селлер, что клиент
   написал своими словами, что бот у него спросил.
6. **Переразобрать по новым правилам.** Синтетических команд от имени владельца не создавать. Дать
   владельцу готовый текст, который он отправит в личку **@wms_korob_bot**, например:
   > По обращению №N: клиенту больше вопросов не задавай. Разберись сам по коду и базе, что у нас уже
   > есть (коды коробов, возвраты и т. п.), выбери самое вероятное толкование и пришли мне сводку.

   После его сообщения проверить по логу (`~/Library/Logs/wms-support-agent.log`) и `outbox`, что
   аналитик отработал, владельцу пришла сводка, а **клиенту не ушёл новый вопрос**.
7. **Влить в etalon** — только по отдельному «да» владельца (PR #352, как в хэндоффе).
8. Дописать в `HANDOFF-2026-10-03.md` раздел «Продолжение: вопросы клиенту» с тем, что сделано и
   проверено, коммит и пуш в эту же ветку.

## Готово, когда

- Служба `running` на коммите с d0977e05, тесты на маке прогнаны, результат записан.
- По последнему обращению владелец получил сводку без нового опроса клиента.
- Если бот всё равно задал клиенту вопрос, это **не готово**: разобрать по `llm_calls` и логу, почему
  (промпт или лимит), и чинить.
