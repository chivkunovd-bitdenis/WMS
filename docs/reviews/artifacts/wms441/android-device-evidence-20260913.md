# WMS-441: проверка на emulator-5580, 13.09.2026

Проверка выполнена только на изолированных локальных API и синтетических
документах. Рабочие документы и внешний стенд не использовались.

## Восстановление после потери ответа

Документ `#000012` (`9bc3e3f7-dee2-4486-853b-b7c445519412`) был размещён
через собственный proxy-harness. Первая отправка россыпи с
`operation_id=2f84e494-2be0-43de-abec-fc606b683611` дошла до сервера, после
чего proxy закрыл gate, сохранил UUID и отдал клиенту обрыв ответа. Пока gate
был закрыт, GET этого документа возвращал 503, а повторный POST с тем же UUID
был остановлен proxy до upstream. Приложение было принудительно остановлено и
запущено заново; экран показал явное состояние «Размещение не подтверждено» и
кнопку «Повторить».

После открытия gate кнопка отправила тот же UUID. Прокси записал доставленный
ответ 200. До и после повтора в API была ровно одна пара движений этой операции:
`stock_transfer_out -1` и `stock_transfer_in +1`; документ оставался с фактом
2, проведено 1, остаток 1. Последняя отдельная единица затем была размещена
обычным действием, и документ ушёл из очереди. Это подтверждает повтор одного
намерения после restart без второй проводки.

## Грузоместо в смешанном документе

После mobile-коммита `170890c4e93da62298bf5c4a5d4a0db43d7c9372` установлен
собранный debug APK. Для отдельного документа `#000013`
(`09a0d2ad-530b-4a8e-b679-168414d89f18`) создана локальная смесь: факт 6,
короб 2, грузоместо 3, россыпь 1.

Экран размещения показал три обычные секции: «Короба» (2), «Грузоместа» (3) и
«Без короба» (1). У карточки грузоместа были показаны его номер и собственный
внутренний штрихкод. Оператор выбрал «Грузоместо №1», отсканировал существующую
ячейку `W441-MIX-A`, увидел шит «Разместить грузоместо №1?» с количеством 3 и
подтвердил действие. После ответа грузоместо пропало из очереди, а счётчик стал
`3 из 6`; то есть оно не было превращено в россыпь.

В том же документе через приложение размещены оставшаяся россыпь 1 и закрытый
короб 2. Документ исчез из очереди сортировки. Контрольное чтение API:
`status=done`, `actual=6`, `posted=6`, `sorting_remaining_qty=0`; остатки
короба и грузоместа равны нулю. Серверный маршрут для cargo остался
`POST /warehouses/{warehouseId}/sorting-objects/place` с телом
`kind=cargo_place`, идентификатором самого грузоместа и ячейкой, поэтому
размещение остаётся одной существующей атомарной операцией склада.
