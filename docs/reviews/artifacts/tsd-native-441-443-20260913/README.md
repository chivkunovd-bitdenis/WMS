## Конкретный оставшийся пробел C5 для Terra

Ожидаемый операторский результат по WMS-443 R8/C5: в существующем контексте истории этой приёмки можно увидеть, что1шт разместил A, а2шт — B. После смены сотрудника A остаётся автором первого действия. История API подтверждает это, но не заменяет экран.

Воспроизведение без новой операции: войти собственным synthetic профилем, открыть `http://127.0.0.1:5204/app/ff/sorting?open_inbound=cb6fca0b-0ff0-41d6-b64b-9ff659e99402&inbound_workspace=sorting`. Карточка показывает A1/B2 как ячейки и done, но не авторские строки. Перейти в «Ячейки» (`/app/ff/warehouse-map`) того же склада: остатки A1/B2 видны, «Журнал перемещений» показывает «Перемещений пока не было».

`GET /operations/inbound-intake-requests/cb6fca0b-0ff0-41d6-b64b-9ff659e99402/movements` возвращает обе пары с правильными actor_user_id. `GET /warehouses/6bfd8c96-3e29-411c-8017-1d5cdf4c95ae/map` возвращает `journal: []`. Карта читает свой существующий WarehouseMapEvent, поэтому её пустота не является доказательством отсутствия складских движений. Это конкретный продуктовый пробел отображения для составного C5; новый журнал/экран не предлагается. Terra нужно определить поддерживаемый существующий путь истории inbound и показать авторов в этом контексте; повторять размещение документа не нужно. Финальный web-показ не принят; код в этом проходе не исправлялся.
