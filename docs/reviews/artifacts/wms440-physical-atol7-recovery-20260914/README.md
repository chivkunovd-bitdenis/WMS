# WMS-440: восстановление physical ATOL7 update

Скриншот владельца зафиксировал, что физический ТСД уже читает manifest версии 15, но штатная проверка обновления прекращает установку с текстом «Подпись обновления не совпадает с установленным приложением». Это исключило устаревший manifest как причину и оставило проверку подписанта до запуска нового APK.

Для воспроизводимого исправления сохранён перенос двух mobile-коммитов в `mobile-code16-atol7-recovery.patch`: `36f3552` добавляет code 16 и автоматическую проверку двойной подписи, а `38d85f9` делает release-подпись явным параметром среды. В исходниках нет пути к хранилищу ключа, паролей или иных учётных данных. Release получает конфигурацию только при одновременной передаче `WMS_TSD_SIGNING_STORE_FILE`, `WMS_TSD_SIGNING_STORE_PASSWORD` и `WMS_TSD_SIGNING_KEY_PASSWORD`; debug остаётся стандартной debug-сборкой.

Публичный org-asset code 16 проверен анонимным полным скачиванием: [WMS-TSD-0.1.15-atol7-code16.apk](https://github.com/oyster-labs-cy/wms-tsd-updates/releases/download/tsd-preview/WMS-TSD-0.1.15-atol7-code16.apk). Его SHA-256 — `0670c318eea594b2b82358d454a5e22f82820e95da68d697f91750c247ac2981`, размер — `37390781` bytes, пакет — `ru.wms.tsd`, versionCode — `16`, versionName — `0.1.15-android7-dualsign-verified`, minSdk — `24`. `apksigner` с диапазоном API 18–35 подтвердил v1 и v2; SHA-256 сертификата подписанта — `e873450b1acd50e2f686b048c8649d157907c34fd19cf43a7d81af3c864b55fd`.

После этой проверки владелец повторил штатный путь на физическом ТСД: code16 с сертификатом `e873…b55fd` снова дал «Подпись обновления не совпадает с установленным приложением» до системного установщика. Поэтому этот asset сохранён как историческая попытка, а не как доказанное исправление.

Следующий versioned asset [WMS-TSD-0.1.16-release-key-code17.apk](https://github.com/oyster-labs-cy/wms-tsd-updates/releases/download/tsd-preview/WMS-TSD-0.1.16-release-key-code17.apk) использует существующий project release certificate `426aa37de6069fb33087f59b18f8718c04dbe750386a2adca12baf82158cb16e`. Анонимная проверка подтвердила package `ru.wms.tsd`, code17/name `0.1.16-release-key-recovery`, minSdk24, размер `37396338` bytes, SHA-256 `6d5c7cc7775accd68141bad26b5604742919114f76d407dfffe19a6eae5d1eca` и v1+v2. Его физический trial остаётся ожидаемым.

На момент этого readback оба публичных manifest снова отдают code15, а не code16 или code17: [org manifest](https://github.com/oyster-labs-cy/wms-tsd-updates/releases/download/tsd-preview/update.json) и [personal manifest](https://github.com/chivkunovd-bitdenis/WMS/releases/download/tsd-preview/update.json). Это наблюдаемое состояние канала, а не основание утверждать результат code17.

`mobile-code18-atol7-updater-fix.patch` сохраняет узкое исправление updater для следующего кандидата18. На API24–27 оно пропускает к обязательному Android installer только APK, у которого уже совпали SHA/размер, package, version и minSdk, но один из двух signer-наборов PackageManager отсутствует; два доступных разных набора по-прежнему дают отказ. На API28+ отсутствие или различие signer остаётся отказом. Локальный непубликованный APK18 подписан прежним public/debug certificate `e343…aeb6`, имеет code18/name `0.1.17-atol7-updater-fix`, SHA-256 `7306a8c1efd0f521301818be7213a8421cd4b8c9ad54b4d5f9327d783321eddf`, размер `45576204` bytes и v1+v2. На этой машине сейчас нет подключённого API35 устройства, поэтому разрешённая sanity-установка PUBLIC11→18 без очистки данных остаётся невыполненной, а manifest для18 не менялся.
