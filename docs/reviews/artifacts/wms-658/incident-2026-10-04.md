# WMS-658: расследование импорта от 04.10.2026

Дата фиксации: 05.10.2026.

## Результат

Доступная часть расследования выполнена: проверены исходное сообщение владельца,
связанный с ним предыдущий read-only job, квитанции запросов данных, ограничения
штатного `read_data`, материалы WMS-658 в Git и сохранённые журналы проверок.

Установить первое место расхождения для конкретного импорта от 04.10.2026 по этим
материалам нельзя. Исходное сообщение установлено точно: `messages.id=71`,
`msg_id=101`, личный чат `689889703`. В сообщении нет `import_id`, `tenant_id`,
`seller_id`, названия селлера или приложенного файла, поэтому конкретную операцию
нельзя однозначно определить и безопасно прочитать в границах клиента.

Корневая причина инцидента не установлена и не приписывается фильтру ЧЗ, формату
КИЗа, сохранению файла или этапу печати без доказательств. В частности, отсутствие
исходного файла среди доступных материалов не доказывает, что файл был утрачен в
production.

Автоматическая проверка C22 подтверждает только поведение read-only инструмента
аудита на искусственно созданном импорте. Она не является расследованием
инцидента 04.10.2026.

## Проверенные доступные материалы

- запись исходного сообщения в штатном `state.db`: `messages.id=71`,
  `msg_id=101`, личный чат `689889703`;
- предыдущий read-only job `7b12c58a57b8be4b`, запущенный именно по source event
  `71`, и его сохранённый результат;
- квитанции `agent_data_query` для source event `71`;
- ограничение штатного `read_data` для личного owner-чата без выбранного
  привязанного клиентского чата (`choose_bound_client_chat`);
- исходный запрос и требования в `docs/requirements/WMS-658.md`;
- реализация read-only сопоставления в
  `backend/app/services/marking_import_audit_service.py`;
- контракт C22 в
  `backend/tests/test_wms658_marking_import_contract.py`;
- журналы проверок SHA `7b5b289ad80cc40b113dec7fe4d2327ed5ad8aec` в
  `.agent-runs/night-checks/`;
- файлы и текстовые ссылки в текущем Git-checkout по датам `04.10.2026`,
  `2026-10-04` и идентификаторам импорта WMS-658.

Job `7b12c58a57b8be4b` завершился, но production `raw_json` и конкретный импорт в
нём не проверялись; сохранённый результат не содержит идентификатора операции.
Для source event `71` нет ни одной квитанции вида `agent_data_query:71:*`, то есть
production-запрос по этой операции фактически не отправлялся.

Штатный `read_data` намеренно не разрешает такой запрос из личного owner-чата без
выбранного привязанного клиентского чата. По содержимому сообщения `71` выбрать
tenant или селлера без догадки невозможно. Это подтверждённый пробел
идентификации и авторизованной области чтения, а не доказательство отсутствия или
утраты данных в production.

## Конкретные пробелы доказательств

1. В исходном сообщении нет `import_id`, `tenant_id`, `seller_id`, названия
   селлера или файла, по которым можно было бы определить конкретную операцию.
2. Авторизованная область чтения не выбрана: сообщение пришло из личного чата,
   привязанный клиентский чат не установлен, а выбирать tenant/селлера догадкой
   нельзя.
3. Production-запрос по source event `71` не отправлялся, поэтому нет read-only
   выгрузки `MarkingCodeImport` и связанных `MarkingCode` с полными `cis_code`,
   `product_id`, `pool_id` и признаками происхождения этикеток.
4. Нет строки `MarkingCodeImportFile` и байтов объекта по её `storage_key`.
   Без чтения строки нельзя утверждать, что исходный PDF не сохранялся: сейчас
   доказано только отсутствие артефакта в переданных материалах.
5. Нет сохранённых `label_artifact_pdf` реальных кодов этого импорта.
6. Нет идентификатора задания печати и конечного PDF/PNG, отправленного на печать.
   Поэтому фактическое содержимое печатного задания и бумажной этикетки не
   подтверждено.

## Граница безопасного продолжения

Безопасно продолжить сопоставление реальных артефактов можно только после появления
точного `import_id` и авторизованной области tenant/селлера. Тогда
`audit_marking_import(...)` можно выполнить в read-only сессии и сопоставить
исходные DataMatrix, `cis_code`, `label_artifact_pdf`, продукт, пул и конечный
файл, если он сохранился. Выбирать организацию или селлера догадкой, повторять
внешнюю загрузку либо восстанавливать отсутствующие значения нельзя.

В ходе доступной проверки внешняя загрузка не повторялась, production-данные не
изменялись. До появления точной идентификации первое расхождение и корневая
причина инцидента остаются неустановленными.
