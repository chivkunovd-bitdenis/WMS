с 9 940 новыми WB. Окно 1440×900 (эмуляция встроенного браузера), замеры getBoundingClientRect.

## НАРУШЕНО
1. **WMS-719, размер рвётся по слогам.** Колонка «Размер» 89 px, у ячейки word-break/overflow-wrap normal, но
   «Универсальный» выводится как «Универ / сальны / й» (видно на скриншоте). C6: «Размеры читаются» — нарушено.
2. **WMS-720 R1, фото раздувает строку и таблицу.** Фото квадратом занимает ширину, равную высоте строки, и этим
   сужает текстовый блок названия до ~220 px (ячейка «Товар» 619–658 px). Название переносится узкой полосой → строка
   выше → фото шире. Итог: Ozon 4 позиции — строка 397 px, фото 396 px; WB с названием ~300 символов — строки 199 и
   358 px. R1: «размер определяется высотой строки, нужной тексту… и сам не вызывает роста строки» — здесь высоту
   строки задаёт сужение текста самим фото. Следствие: при окне 1440 таблица шире области (scrollWidth 1626 при
   clientWidth 1130 для Ozon; 1491 для трёх WB), колонки «Селлер», «Маршрут сдачи», «Отгрузить до» уходят за правый
   край (эталон FBS из AGENTS.md §3 виден только горизонтальной прокруткой). Для сравнения, вид WB без длинных строк —
   scrollWidth 1278 при 1130 (отдельно не сравнивалось с etalon).
3. Наблюдение (не засчитано дефектом, повторить после исправления): сразу после поиска, пока картинки грузились,
   рамка фото была 218×198 (не квадрат), после загрузки — 198×198, то есть загрузка картинки меняла ширину.
