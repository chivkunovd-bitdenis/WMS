# WMS-667: доказательство контракта тестов до реализации

Тестировщик: gpt-6.1-sol, самостоятельно, без skills и дочерних агентов.
Проверяемый продукт: `af81ac250`, поверх etalon
`0f1460b023700a99f17b504d6af3934a02bc68cc`. Продуктовый код не менялся.
Новые тесты C1–C9 закрепляют `has_stock=true`; выключенное значение —
`false` либо отсутствие параметра. Элемент «С остатком» находится в текущем
блоке фильтров и доступен через `ff-catalog-has-stock-filter`.

Все backend-запросы идут через настоящий ASGI API и настоящие таблицы БД.
Сводка `/operations/inventory-balances/summary` служит наблюдаемым эталоном
`quantity`; фильтр, источник остатков и обработчики API не подменены.
Исходящие HTTP-запросы через AsyncHTTPTransport запрещены тестовой фикстурой.
Запросы интерфейса подменены только на границе HTTP: смонтирован настоящий
FfProductsCatalogScreen, выполняются его эффекты и настоящие события DOM.

## Полученные результаты

- [SQLite](sqlite-red.txt): **12 failed, 5 passed**, ошибок окружения нет.
- [Изолированный PostgreSQL](postgres-red.txt): **12 failed, 5 passed**,
  ошибок окружения нет. Те же целевые падения, что на SQLite.
- [DOM](dom-red.txt): **2 failed, 4 passed**, ошибок окружения нет.

C1 сравнивает со сводкой значения 3, 0, отсутствие строки и -2; ноль и
отрицательное число получены суммой разных строк, включая положительные.
Падает последующий запрос `has_stock=true`, который возвращает все четыре
товара. C2 успевает подтвердить остаток 5, резерв 5/7 и доступно 0/-2,
после чего падает на включении нулевого товара в ответ нового отбора.
C3 подтверждает обычную страницу A,B и total=5, а новый отбор снова отдаёт
A,B вместо C,D. Это падение отличает серверный отбор до пагинации от
попытки отфильтровать только загруженную страницу.

C4 проверяет отдельные и совместные фильтры, включая активную связь Ozon;
шесть сочетаний падают на оставшихся нулевых товарах. Точное совпадение
Ozon SKU, где нулевой товар не соответствует поиску, служит PASS-контролем.
C5 перед падением подтверждает неизменность всех колонок товаров, остатков,
резервов-направлений, расположений и связей площадок после GET. C6 сверяет
общий остаток 9 до и после перераспределения между расположениями, включая
тару на втором складе с is_operational=false; новый отбор ошибочно сохраняет
нулевой товар. C7 проходит: положительный товар другого tenant исключён из
items/total, сотруднику без нужных прав возвращается 403.

Остальные backend PASS — новый контроль обычного каталога/сводки/передачи
остатков/неизменности данных и две существующие проверки WMS-418.
C8 выполняет выбор селлера, площадки, категории, поиска и передачи остатков,
переходит на позднюю страницу и только затем падает на отсутствии «С остатком».
C9 падает на том же отсутствующем элементе. Контракты продолжают проверку
после его появления: offset=0, сохранение фильтров, ответ API в таблице и
счётчике, пустой результат, выключение без повторного монтажа экрана.
DOM PASS — новый контроль обычной таблицы и три существующих теста URL-фильтра.

## Повторение

Из `backend`, с существующим Python-окружением проекта:

```sh
WMS_TEST_DATABASE_URL='sqlite+aiosqlite:///:memory:' python -m pytest -n 0 \
  tests/test_wms667_catalog_has_stock_contract.py \
  tests/test_wms418_catalog_publication_filter.py --tb=short -q
```

PostgreSQL запускался отдельным локальным процессом на 127.0.0.1:56767,
база `wms_test667_contract`, без пароля и внешних сервисов. Кластер занимал
около 53 МБ. Для схемы проекта использован max_locks_per_transaction=1024;
shared_buffers=16MB, max_connections=10. Для повторения на отдельно созданной
изолированной тестовой базе с локальным пользователем:

```sh
WMS_TEST_DATABASE_URL='postgresql+asyncpg://LOCAL_USER@127.0.0.1:56767/wms_test667_contract' \
  python -m pytest -n 0 \
  -o asyncio_default_fixture_loop_scope=session \
  -o asyncio_default_test_loop_scope=session \
  tests/test_wms667_catalog_has_stock_contract.py \
  tests/test_wms418_catalog_publication_filter.py --tb=short -q
```

Единый цикл событий нужен для повторного использования asyncpg-соединений
существующими фикстурами. Первоначальные ошибки разных циклов событий и
лимита блокировок локального кластера устранены параметрами запуска; они
не считаются RED. Изменений общих фикстур и продукта ради запуска нет.
