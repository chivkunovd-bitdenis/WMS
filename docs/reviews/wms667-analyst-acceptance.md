## Основания приёмки

До реализации на SQLite и PostgreSQL сохранены одинаковые **12 failed,
5 passed**; DOM — **2 failed, 4 passed**. Падения проверяют отсутствующий
отбор, пагинацию и отсутствующий элемент интерфейса; C7 исходно проходит как
регрессия существующих прав. Это доказательства тестировщика, не новый
прогон аналитика.

Разработчик сообщает 17 PASS контрактов/соседних WMS-418 на SQLite и PostgreSQL,
14 PASS WMS-530/WMS-538 на PostgreSQL, 6 PASS DOM, ruff/mypy/tsc/build PASS.
Его README честно сохраняет первоначальный StaleDataError соседнего теста
на SQLite `:memory:` и успешные проверки того же неизменённого теста на
файловой SQLite и PostgreSQL. Эти результаты не подменены новым запуском.

Независимый отчёт Astra подтверждает **39 PASS PostgreSQL**: 17 контрактных
и WMS-418, 14 WMS-530/WMS-538, 7 сервиса остатков и 1 существующего guard
публикации. Дополнительно — **2 PASS API/SQL**, **6 PASS DOM** и **2 PASS
поздних ответов**. Матрица API проверяет страницы, total/scope_total/категории
и сочетания фильтров; SQL-проба сопоставляет выделенный общий расчёт с прежним
выражением. Поздние ответы каталога/сводки не заменяют новую выборку.
Все прогоны относятся к изолированным данным; это не проверка живого учёта.

Сравнение Git показало: после продуктового SHA до начала приёмки добавлен
только отчёт Astra. Backend-тесты, DOM-контракт и guards с коммита контракта
не изменены. Повторять неизменённые прогоны без новых оснований не требуется;
результаты Astra и разработчика приняты как переданные доказательства и
не объявлены личными запусками заменяющего аналитика.

## Точная ручная граница C10

**C10: НЕ ПРОВЕРЕНО.** На предыдущих этапах авторизованный каталог не был
доступен для осмотра; текущая приёмка дополнительно связана прямой остановкой
браузерной работы владельцем из-за памяти. Браузер, Chrome и Playwright не
запускались. Это невыполненная проверка, а не обнаруженный дефект или
разрешение считать визуальную часть пройденной.

Сохраняются все первоначальные ручные действия: на безопасном стенде открыть
каталог и сопоставить его с текущим дизайном, проверить читаемость прежних
фильтров и «С остатком», длинное имя селлера, узкий экран без наложений,
затем сопоставить положительный полностью зарезервированный товар с колонкой
«Остаток». Для последнего действия подходит существующий безопасный тестовый
пример; изменение живого остатка или резерва для приёмки не требуется.
Автоматические C2/C8 подтверждают положительный общий остаток при полном
резерве и логику компонента, но не выполняют этот ручной осмотр.
Новых проверок, сущностей или условий выпуска аналитик не добавляет.
