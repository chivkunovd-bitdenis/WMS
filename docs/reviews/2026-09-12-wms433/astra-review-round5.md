## 2. Новые подтверждённые дефекты

**№35. Одиночный код и код в пунктах списка проходят фильтр.**

Причина в [assistant_safety.py:228](backend/app/services/assistant_safety.py:228): одна распознанная строка требует четырёх пробелов отступа; маркер списка мешает распознаванию начала строки. То же поведение у исполнителя.

Все пять новых негативных входов:

| Вход; `\n` означает перенос строки | Обе `sanitize_answer` | Сохранение через `submit_executor_result` |
|---|---|---|
| `import os` | Пропускают | Без замены |
| `print("hello")` | Пропускают | Без замены |
| `answer = 42` | Пропускают | Без замены |
| `- import os\n- import sys` | Пропускают | Без замены |
| `Вот код: import os; print(os.getcwd())` | Пропускают | Без замены |

Проверена последовательность **фильтр исполнителя с реальными идентификаторами → настоящий сервис бэка → перечитывание SQLite в памяти**. Это оставшаяся разновидность №33: запрещённый фрагмент кода доходит до сохранённого ответа. **R17, C13.**

**№36. После размонтирования продолжается обработка POST и запускаются новые GET.**

Места: [перезапуск загрузки и очистка компонента](frontend/src/components/assistant/AssistantPanel.tsx:280), [обработка завершения POST](frontend/src/components/assistant/AssistantPanel.tsx:386).

Воспроизведены три последовательности:

- **POST задержан → размонтирование → успех POST.** Обработчик снова добавляет A в уже очищенный набор локальных идентификаторов и вызывает два обновления состояния.
- **POST задержан → размонтирование → ошибка POST.** Вызываются четыре обновления состояния и начинается новый GET. После его завершения вызываются ещё три обновления.
- **GET №1 задержан → закрыть → открыть → размонтировать → завершить отменённый GET №1.** Сохранённый `reloadRequested` запускает GET №2 после размонтирования. Новый запрос не отменён; его завершение вызывает три обновления состояния.

Обычный одиночный GET при размонтировании отменяется корректно. Дефект возникает в продолжениях запросов: они не проверяют, существует ли ещё компонент. **Появление чужой переписки не подтверждено**; подтверждены новые запросы после выхода и вызовы обновления состояния уничтоженного компонента.

## 3. Замечания без блокировки

- **Пустой список идентификаторов ослабляет фильтр исполнителя.** `Таблица users…` и упоминание `submit_executor_result` проходят; код из двух импортов и синтетический `ghp_` блокируются. `process_one` явно пишет предупреждение и продолжает обработку. Бэкенд с непустым списком эти внутренние имена блокирует.
- Список бэка фактически собирается из `__tablename__` в файлах моделей, а не непосредственно из `Base.metadata`. Сверка текущей версии показала: **все 105 имён таблиц из metadata включены**, пропусков нет.
- При медленном GET очередной тик опроса также устанавливает `reloadRequested`. После получения готового ответа начинается один лишний GET. Сам ответ применяется, интервальный опрос прекращается; регрессии №31 нет.
