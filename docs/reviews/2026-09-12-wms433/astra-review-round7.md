## 2. Новые подтверждённые дефекты

**№37. Точечная вычистка оставляет содержимое жёсткого класса R17.**

Вызвана настоящая `redact_unsafe_fragments` со списком идентификаторов из `backend/app`. Подтверждено:

- Вход прошлого корпуса `Вот пример:\n\n    def post_supply():\n        return True` остаётся **целиком**. Код с отступом относится к жёсткому классу.
- `SELECT\n id,\n email\nFROM users` превращается в `[скрыто]\n id,\n email\nFROM users`. Через `process_one → format_backlog_card → list_chat_backlog_candidates` остаток SQL попадает и в карточку, и в кандидаты.
- У синтетического PEM удаляется `-----BEGIN PRIVATE KEY-----`, но сохраняются короткая строка тела `QUJDREVGR0hJSktMTU5PUA==` и закрывающий маркер.
- `Ошибка (/srv/private/thing.conf) — повторить.` остаётся без изменений.
- При пустом списке идентификаторов `/srv/assistant_messages.py/assistant_messages` превращается в `/[скрыто]/assistant_messages`: часть пути и имя таблицы сохраняются.

Причина: шаблон, достаточный для обнаружения опасного текста и замены всего ответа, не обязательно охватывает весь удаляемый фрагмент. Дополнительно SQL-шаблон удаляет обычное слово `Update` во фразе `После Update повторите вход.`

Источник: [вычистка сводки](tools/assistant-agent/wms_assistant_agent.py:408).

**№38. Сводка из одного инлайн-фрагмента не заменяется полезным ответом.**

В `process_one` передан `backlog_summary = "`post_supply()`"` и безопасный `answer_text`. Карточка и кандидат получили `` `[скрыто]` `` вместо ответа. После удаления `[скрыто]` остаются обратные кавычки, которые проверка ошибочно считает содержанием. Для полностью ограждённого блока кода замена на `answer_text` прошла.

Источник: [проверка остатка сводки](tools/assistant-agent/wms_assistant_agent.py:1558).

**№39. Телефон со скобками попадает в список кандидатов другого пользователя.**

Через полный путь формирования карточки передана сводка с `ivan@example.com +7 (999) 123-45-67`. В кандидате почта заменена на `[email скрыт]`, телефон остался целиком. Отдельно подтверждено: `+79991234567` скрывается, варианты `+7 (999) 123-45-67` и `8 (999) 123-45-67` — нет. Это существующий пробел фильтра контактов, проявляющийся на сохраняемой теперь сводке.

Источник: [фильтр контактов](tools/assistant-agent/wms_assistant_agent.py:753).

**№40. Ожидание при выключенном исполнителе засчитывается как неудачные попытки.**

Воспроизведение: сообщение создано 40 минут назад, прежних обработок нет; первый вызов модели немедленно завершается `AssistantAgentError`. `process_one` создаёт баг и отправляет «обращение передано владельцу». В карточке записано **«≥3 попыток — модель не успела ни разу»**, хотя был один вызов.

Уточнение: **до первой попытки отказа нет**. Старое сообщение с успешным ответом модели обрабатывается нормально. Дефект проявляется после первой ошибки, включая ошибку запуска: ожидание из R22 неправомерно исчерпывает бюджет повторов.

Источник: [решение по возрасту сообщения](tools/assistant-agent/wms_assistant_agent.py:1507).

**№41. Захват на 12 минут не покрывает допустимую продолжительность цикла.**

В настоящих функциях подготовки checkout подменены результаты и длительности Git-команд: два успешных `fetch` по **119 секунд**, остальные команды мгновенные; модель — **599 секунд**. Получается **837 секунд ещё до записи карточки и отправки результата**, при захвате на **720 секунд**. Каждый отдельный вызов укладывается в свой таймаут.

Таймауты Git есть: clone/fetch — 120 секунд, checkout — 60/30, служебные команды — 15/30, push — 60. Однако общего бюджета или продления захвата нет. Поиск номера дополнительно выполняет до трёх команд по 30 секунд **на каждую ветку**. Поэтому повторный захват ещё работающего запроса остаётся возможен.

Источники: [подготовка checkout](tools/assistant-agent/wms_assistant_agent.py:568), [серверный захват](backend/app/services/assistant_service.py:194).

**№42. Уборка считает работающий checkout осиротевшим только по возрасту.**

Подмена каталога с возрастом 1801 секунда приводит к вызову `rmtree`; признака завершения владельца каталога функция не проверяет. Каталог возрастом 30 секунд сохраняется.

Достижимость длинного цикла проверена отдельно: обход 15 веток, по 29 секунд на каждую Git-команду, занял в модели времени **1334 секунды**; вместе с подготовкой и моделью — **2171 секунда до commit**. Все отдельные таймауты соблюдены. Второй экземпляр при старте выбирает такой ещё используемый checkout для удаления.

Поиск идёт непосредственно в `tempfile.gettempdir()` по `wms-assistant-checkout-*`, без разделения по экземпляру или репозиторию.

Источник: [уборка каталогов](tools/assistant-agent/wms_assistant_agent.py:540).

## 3. Замечания без блокировки

**Молчаливый нормальный выход `--once` не воспроизведён.** Ожидаемая и неожиданная ошибки выводятся в stderr. Но обе дают код завершения **0**, а stdout ошибочно сообщает «очередь пуста». Это мешает отличать сбой от отсутствия работы.

Буферизация stdout воспроизведена в памяти: до сброса буфера вывод отсутствует. Она объясняет пустой файл во время работы, но не доказывает причину описанного завершившегося запуска. Для диагностики нужны оба потока вывода. Источник: [main](tools/assistant-agent/wms_assistant_agent.py:1661).
