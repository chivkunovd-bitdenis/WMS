1. **P1 — запуск скрипта через stdin позволяет Docker забрать оставшуюся часть скрипта.**  
   В [deploy.yml, строка 40](/Users/deniscivkunov/Projects/WMS/.worktrees/wms415-coord/.github/workflows/deploy.yml:40) новый скрипт подаётся в `bash -s` через стандартный ввод. В [prod-update.sh, строки 88–89](/Users/deniscivkunov/Projects/WMS/.worktrees/wms415-coord/scripts/deploy/prod-update.sh:88) `docker compose exec -T` наследует этот же ввод. Флаг `-T` отключает терминал, но интерактивный ввод Compose остаётся включённым по умолчанию — это подтверждено [документацией Docker](https://docs.docker.com/reference/cli/docker/compose/exec/).

   При чтении Docker из stdin он может забрать команды, следующие за блоком `pg_dump`: проверку архива, миграции и запуск остановленных сервисов. Shell при этом способен завершиться с кодом `0`. Локальный пример Bash с читающей stdin подставной командой воспроизвёл именно пропуск оставшейся части скрипта; реальный Docker я не запускал.

   **Исправление:** сначала получить текст скрипта с проверкой результата `git show`, затем выполнять его отдельно от stdin, например через `bash -c "$deploy_script" </dev/null`. Для `pg_dump` дополнительно явно отключить stdin. Перенаправление архива в `pg_restore` сохранить. Текущий тест запускает файл через `bash path` ([строки 52–55](/Users/deniscivkunov/Projects/WMS/.worktrees/wms415-coord/backend/tests/test_prod_deploy_backup.py:52)), поэтому новый способ запуска из workflow не проверяет.

2. **P2 — ошибка загрузки актуального скрипта не проваливает шаг деплоя.**  
   Та же [строка 40 workflow](/Users/deniscivkunov/Projects/WMS/.worktrees/wms415-coord/.github/workflows/deploy.yml:40): код завершения `git show` внутри `< <(...)` не становится кодом завершения `bash -s`. Если чтение файла из `origin/etalon` завершится ошибкой без вывода, Bash выполнит пустой ввод успешно. Следующая проверка HTTP может получить `200` от прежней версии приложения.

   Это отдельно воспроизведено локально: производитель ввода завершился с кодом `17`, а внешний shell продолжил работу с итоговым `0`. **Исправление:** отдельное проверяемое присваивание `deploy_script="$(git show ...)"` под `set -e`, затем запуск. Добавить отрицательный тест на ошибку получения скрипта.

3. **P2 — ошибка поиска старого seller-контейнера маскируется под успешную очистку.**  
   В [prod-update.sh, строки 120–123](/Users/deniscivkunov/Projects/WMS/.worktrees/wms415-coord/scripts/deploy/prod-update.sh:120) `docker ps` также выполняется внутри `< <(...)`. При ошибке перечисления контейнеров цикл получает пустой ввод; скрипт может дойти до `Done`, оставив старый listener работающим. Последующий `compose ps` не проверяет закрытие старого порта.

   Потеря ошибки в такой конструкции подтверждена отдельным локальным примером Bash. **Исправление:** сначала получить список контейнеров отдельной командой с проверяемым результатом, затем останавливать найденные контейнеры. Успешный пустой список допустим; ошибка Docker должна завершать деплой ошибкой. В тестах сейчас предусмотрены только успешный backup и ошибки dump/archive ([строка 14](/Users/deniscivkunov/Projects/WMS/.worktrees/wms415-coord/backend/tests/test_prod_deploy_backup.py:14)).
