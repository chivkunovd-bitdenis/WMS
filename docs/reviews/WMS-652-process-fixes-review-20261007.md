## Проверка прежних двух P1

saved_process_policy теперь сначала читает Git entry `HEAD:guards/PROCESS_CONTRACTS.json`. Отсутствующий рабочий файл при сохранённой policy и dangling symlink (ссылка на отсутствующий файл) дают ValueError до построения/выполнения moves. Независимые пробы сохраняют original, документ, MANIFEST, policy state и git status без дополнительных изменений. Полная ветка legacy move допускается только при действительном отсутствии сохранённой policy; наличие несохранённого файла или ссылки не объявляется отсутствием защиты. Прежние unprotected move/import rewrite, пустая active forever-ссылка и повтор зарегистрированной задачи сохраняют свои ожидания.

В workflow производитель ci-shards.xml теперь включает test_promote_guards.py вместе с четырьмя прежними файлами. Policy требует все 13 promoter cases и прежние 24 infrastructure cases: реальный сохранённый JUnit содержит **37 PASS и 54 успешные subtests**, а существующий парсер принимает именно эти 37 имён. Проверены 37 testcase rows и aggregate tests=91 при failures/errors/skipped=0; [точные raw statistics](../evidence/WMS-652/process-fixes-review-20261007/ci-shards-report-stats.json) сохранены. Raw report загружается в guard-executed-contracts текущих SHA/run/attempt; process-proof скачивает тот же артефакт, имеет обязательную зависимость guards и проверяет suite с exact=true. Общий stdout unittest discover больше не подменяет этот JUnit.

## Новые строгие контракты

Для двух конкретных WMS-654 test.each templates поддержка ограничена исходным `frontend/src/sections/CatalogSection.wms654.test.tsx`, Vitest и фиксированным report `frontend-all.json`. Матрица содержит четыре комбинации sides/tiers для independent coordinates и по четыре для двух названных map openings — всего **12 буквальных expanded IDs**, без wildcard или принятия одного совпадения за всю матрицу. Перед проверкой имён остаются обязательными сохранённая policy, source SHA-256 и равенство source HEAD bytes.

Независимо удалён по одному каждый из всех 12 matrix IDs: каждый вариант отвергнут до mutation. При полном наборе оба template references обрабатываются вместе, original/document/policy/MANIFEST сохраняются и повторный вызов также не создаёт diff. Frozen negatives дополнительно отвергают неверный source owner, подменённое значение комбинации, чужой report и неверный source hash. Все 12 ожидаемых имён также найдены passed в настоящем сохранённом frontend JSON WMS-654, а все 20 новых frontend IDs сопоставлены с этим report и policy. Поддержка не ослабляет остальные suites или шаблоны.

Для WMS-687 companion-совместимость допускается только при коррекции точного старого DOM path. Дополнительные пути ограничены двумя буквальными новыми test paths permission/regression и документом требований той же задачи. Существующий или уже frozen test нельзя выдать за новый; symlink/executable/gitlink не является regular test blob. В документе разрешена только смена столбца «Тест», при сохранении требований, ожидаемого поведения, остальных клеток, строк и текста. Если ancillary_files объявлен, его множество должно точно совпасть с фактическим companion diff. Предоставленный review report проверяется по точному commit, ancestry и неизменному blob.

Проверки через настоящий contract_change_errors на отдельных Git fixtures подтвердили разрешённый состав и отказ для лишнего test file даже той же задачи, product file, test/документа другой задачи, изменения собственного R1, существующего permission test, удаления original/companion, symlink/executable companion, неверного ancillary_files и изменённого привязанного review report. Все проверки работают без mutation. Прежний формат metadata review сохранён; реальные независимые review/приёмка остаются обязанностью контроллера, а не выводятся из synthetic PASS-поля fixture. Отдельная приёмка реального последующего импорта WMS-687 этим заключением не проведена.
