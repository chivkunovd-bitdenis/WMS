06.10.2026. Реализация опирается на frozen RED-коммит
`d13dfa1f97ba38221aeca22b3f3682ef9525d6f3`. Все шесть его проверок сохранены
без изменений. Требования и остальные старые тесты не менялись.

## Поведение и границы

В существующем kv используется `owner_client_reply_pause:{chat_id}`.
Операторская команда `pause-client-replies` проверяет реальный Telegram-источник:
автора по owner_user_id конфигурации, точный чат и принадлежность указанных
обращений. Модель не устанавливает паузу и не определяет запрет по догадке.
Оператор отвечает за смысл выбранного сообщения; CLI проверяет его происхождение.
Повтор старого источника не заменяет более новую паузу.

AgentTools запрещает enqueue обоих process reply и обычного queue_reply
в этот чат. Dispatcher до claim проверяет каждую строку очереди: файлы,
старые финальные ответы, notices и строки без ticket_id также не отправляются.
Подавленные строки сохраняют существующий статус pending и историю;
анализ, tickets, jobs, sessions и конфигурация не изменяются. Остальные чаты
и приватный канал владельца продолжают отправку.

Отдельная команда `approve-client-reply` атомарно создаёт только одну новую
строку и сохраняет её конкретное разрешение в той же записи kv. Пауза остаётся
true; прежние queued final не разрешаются. Источник должен быть новым сообщением
настоящего владельца в целевом чате либо его приватном канале. Он должен точно
содержать явное разрешение, адресата, номер обращения, текущую версию и полный текст:

```text
Разрешаю отправить в чат CHAT_ID ответ по обращению TICKET_ID, версия VERSION:
ТОЧНЫЙ ТЕКСТ ОТВЕТА
```

Это детерминированный операторский формат проверки одного разрешения, а не
LLM-распознавание согласия. Перед dispatch повторно сверяются автор, источник,
его revision и текст, текущая версия обращения, адресат, текст и ключ строки.
Повтор команды не создаёт второй ответ. Изменение версии, источника или тела,
а также новая пауза запрещают отправку. Неизвестный исход Telegram не разрешает
слепой повтор: используются прежние outbox-правила repeat_ok=false.

## Операторские команды после независимого ревью и безопасной установки

Команды ниже в этой сессии на рабочей базе **не выполнялись**. Ведущему переданы
проверенные source 333/msg 470, owner 689889703, chat -4899527415 и обращения
22/WMS-677, 24/WMS-678. Путь конфигурации выбирает ведущий по установленной службе.

```sh
python -m support_agent pause-client-replies --config CONFIG \
  --chat-id -4899527415 --source-message-id 333 --ticket-id 22 --ticket-id 24

python -m support_agent approve-client-reply --config CONFIG \
  --chat-id CHAT_ID --source-message-id NEW_OWNER_SOURCE_ID \
  --ticket-id TICKET_ID --version CURRENT_VERSION --text-file EXACT_REPLY_FILE
```

Ни одна команда не вызывает Telegram или модель. Разрешение создаёт намерение
отправки; фактическую доставку выполняет существующий dispatcher отдельно.
Новая таблица, статус заданий, глобальная пауза и detector не добавлены.
