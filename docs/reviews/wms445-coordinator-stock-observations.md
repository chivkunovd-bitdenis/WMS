# WMS-445: проверка связанного складского результата

Ведущий выполнил дополнительное чтение локальной синтетической БД после эмуляторного checkpoint исполнителя. Это не независимое ревью и не приёмка БА.

Для WB `7354349e-645a-40ea-9b7c-45ff8676e790` найдена одна запись `fbs_shipment` с расходом1. Для Ozon `4095c41a-8333-41f6-8279-bbc5034b826b` найдены две записи `fbs_shipment`, расход2 и1, всего3. Подтверждения находятся в [JSON](artifacts/wms445/coordinator-stock-evidence.json).

Связи прочитаны через `fbs_shipment_reversal_ledger.shipment_movement_id` и `ozon_positions_json[].movement_id`, затем по фактическим ID в `inventory_movements`. Нулевые связи движений в pick/pack сами по себе не доказывают отсутствие списания отгрузки: её записи существуют в том же журнале. Поэтому прежнее наблюдение исполнителя «inventory_movements=0» нельзя обобщать на весь документ.

Передать эти факты независимому ревьюеру WMS-445 и аналитику WMS-444 для общей сверки. Чтение не изменяло документы, остатки, поставки или начисления. Проверка нативной потери ответа после commit остаётся открытой; она авторизована исходной задачей, требуется подготовить локальный scoped response-drop proxy, а не получать дополнительное разрешение.
