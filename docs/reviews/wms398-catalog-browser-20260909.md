# WMS-398 / WMS-275: два открытия учебного каталога staging

09.09.2026, около 05:04–05:05 МСК, настоящий Chrome открыл
`https://web-production-9e7c1.up.railway.app/app/ff/products` и один раз
перезагрузил страницу в том же контексте. На каталоге QA tenant
`9c31f3f4-ce62-4c1f-891a-295b278f1e69` задержка 15–20 секунд не воспроизвелась:
таблица появилась через **2228,3 мс**, повтор — **1929,8 мс**.
Каталог содержит **257 товаров**, загруженная страница — **100 строк**;
видимый счётчик «Найдено: 257 из 257» подтверждён в браузере.
Сто строк находятся в таблице, а не одновременно в пределах высоты окна.

Перед открытием `/api/health` вернул 200 `status=ok`. Маршрут `/health/runtime`
на web/backend отсутствует и вернул 404; приписывать ему доказательство SHA нельзя.
Root отдельно подтвердил deploy `50c9c88e0e56097e857fa26e0bda419d69125f9f`.

`b4bcf60f-de31-436c-8795-b16c603ac982`, web
`68045976-3d52-4564-962a-9aff21d0381e`, SUCCESS, 428 runtime Python-файлов,
расхождений/лишних 0. Этот proof включён в evidence с указанием происхождения.
Оба браузерных открытия загрузили `/assets/ff-D5xOaoJh.js`.

Использован установленный Google Chrome headless, 1440×1000, имеющийся Playwright.

**Playwright routing отключает HTTP-cache:** повтор использует тот же браузер,
но не является замером обычной перезагрузки с прогретым HTTP-кешем.
Данные, фильтры, складские документы и интеграционные настройки не изменялись.
Новых товаров, нагрузки, зависимостей и тестовых баз не создавали.

## Запросы, размеры и время

В каждом открытии зафиксировано **19 API-ответов, все HTTP 200** до завершения
начальной сетевой активности. Для трёх товарных запросов ниже — по одному
вызову на открытие, а не повторные попытки. `/sellers` вызван дважды.

| Запрос | Строк | JSON после распаковки, байт | gzip тело, байт: первое / повтор | TTFB, мс: первое / повтор | Полный ответ, мс: первое / повтор |
| --- | ---: | ---: | --- | --- | --- |
| `/products` | 257 | 193417 | 18570 / 18568 | 283,7 / 266,7 | 293,5 / 283,9 |
| `/products/ff-catalog` | 257 | 238469 | 20775 / 20780 | 324,5 / 313,8 | 341,4 / 327,4 |
| `/products/ff-catalog-page?limit=100&offset=0` | 100 | 87465 | 9454 / 9454 | 323,6 / 325,2 | 346,5 / 350,5 |

Всего три товарных ответа содержат **519351 байт распакованного JSON** на открытие.
Размеры gzip получены из браузерного Resource Timing, распакованного тела —
из настоящего response.body. Сами каталожные данные не сохранены в evidence:
только размеры, число строк и временные характеристики.

TTFB — интервал от отправки HTTP-запроса до первого байта ответа, включает сеть
и backend. Полный ответ измерен browser request timing до responseEnd.
**Отдельное серверное время неизвестно:** ни `Server-Timing`, ни `X-Process-Time`
в ответах нет; в прочитанном backend не найден соответствующий middleware.
Нельзя называть TTFB временем SQL или чистым временем сервера.

Время появления строк отсчитывается от начала browser navigation. Добавленный
только в измерительный контекст MutationObserver фиксирует первую непустую
отрисованную таблицу; существующий browser locator затем подтверждает строку.
Это не время завершения загрузки всех изображений и не аппаратный замер ТСД.

## Что подтверждено кодом и наблюдением

В `frontend/src/App.tsx:475` `refreshProducts` запускает `/products` и
`/products/ff-catalog` через Promise.all. В обоих замерах запросы стартовали
практически одновременно. При этом сам экран независимо загружает страницу
через `FfProductsCatalogScreen.tsx:349`, затем ждёт `/inventory-balances/summary`
и лишь после этого вызывает `setCatalog` на строке 375. Последовательный запрос
остатков занял 280,6 / 280,4 мс в этих двух открытиях.

По Resource Timing запрос страницы начался на 1453,3 / 1159,7 мс от navigation,
его тело получено на 1799,6 / 1510,0 мс; строки появились на 2228,3 / 1929,8 мс.
Следовательно, весь интервал до таблицы нельзя приписать запросу каталога.
Два полных списка — подтверждённые дополнительные чтения, но **не доказанная
причина прежней многосекундной задержки** на этом объёме. Чтения сторонних
разделов при старте также видны в evidence; их влияние отдельным экспериментом
не изолировалось. Причину времён production-каталога на 11210 товаров по этим
257 учебным товарам устанавливать нельзя.

Производственный код не менялся: на этом объёме нет основания исправлять
предполагаемое узкое место. Для завершения общей WMS-398 нужны измерения
репрезентативного каталога/экранов в отдельно разрешённом контуре; для WMS-275
по-прежнему не доказаны пиковая нагрузка и физический ТСД.
