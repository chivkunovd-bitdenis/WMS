### F1 · P1 · R9: демо вызывает настоящую браузерную печать

Место: `docs/mockups/WMS-686/mockApi.ts:291`, `docs/mockups/WMS-686/demoTransform.ts:30`. Изоляция заменяет fetch и добавляет панель упаковки, но оставляет действующий обработчик печати исходного компонента: `frontend/src/screens/ff/FfPackagingPage.tsx:410`, кнопка на строке 912 → `frontend/src/utils/printShipmentPackagingSheet.ts:236` → `iframe.contentWindow.print()`.

Воспроизведение: открыть демо → Упаковка → «Печать накладной». В отдельном headless Chrome клик создал iframe с документом «Лист отгрузки — 000086». Перед выполнением отложенного вызова функция print этого iframe была заменена счётчиком; после ожидания счётчик получил один вызов `iframe.print`, iframe удалён. Таким образом, штатный путь действительно достигает функции печати, а не локального отказа mockApi. Физическая печать не выполнялась. Аналогичный прямой путь печати кода короба существует в `FfSuppliesShipmentsPage.tsx:1066`; отдельно кликом он не проверялся.
