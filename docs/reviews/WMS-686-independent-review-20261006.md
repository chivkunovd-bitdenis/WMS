## Findings

### F1 · P1 · R9: демо вызывает настоящую браузерную печать

Место: `docs/mockups/WMS-686/mockApi.ts:291`, `docs/mockups/WMS-686/demoTransform.ts:30`. Изоляция заменяет fetch и добавляет панель упаковки, но оставляет действующий обработчик печати исходного компонента: `frontend/src/screens/ff/FfPackagingPage.tsx:410`, кнопка на строке 912 → `frontend/src/utils/printShipmentPackagingSheet.ts:236` → `iframe.contentWindow.print()`.

Воспроизведение: открыть демо → Упаковка → «Печать накладной». В отдельном headless Chrome клик создал iframe с документом «Лист отгрузки — 000086». Перед выполнением отложенного вызова функция print этого iframe была заменена счётчиком; после ожидания счётчик получил один вызов `iframe.print`, iframe удалён. Таким образом, штатный путь действительно достигает функции печати, а не локального отказа mockApi. Физическая печать не выполнялась. Аналогичный прямой путь печати кода короба существует в `FfSuppliesShipmentsPage.tsx:1066`; отдельно кликом он не проверялся.

Это нарушение явной границы «нет реальной печати», а не предложение убрать исходные кнопки или изменить дизайн. Одной подмены fetch для этой границы недостаточно.

### F2 · P2 · R7: нанесённый КИЗ без прежнего скана приёмки нельзя провести через UI

Место: `docs/mockups/WMS-686/Controls.tsx:202`–211, `docs/mockups/WMS-686/model.ts:45`–50.

Воспроизведение: после частичного подбора закрыть первый короб, получить открытый WHB-DEMO-002 → скан DEMO-P1 → DEMO-NEW-KIZ → WHB-DEMO-002. Второй скан возвращает «Код не относится к выбранному товару/коробу…», скан короба лишь выбирает его; состав и количество не меняются. Интерфейс принимает только КИЗ, уже содержащиеся в исходных единицах; все исходные единицы имеют известную приёмку. Достижимого случая с нанесённым кодом без скана приёмки нет.

Контракт C7 проверяет `addUnit` с `intakeId: null` непосредственно в reducer, но такой вызов не достижим из React-панели. Поэтому успешный тест модели не доказывает согласованное R7 в кликабельном макете. Случай с известной приёмкой работает.

### F3 · P2 · R9: часть неизвестных маршрутов получает успешный ответ

Место: `docs/mockups/WMS-686/mockApi.ts:170`, `docs/mockups/WMS-686/mockApi.ts:278`.

Воспроизведение независимым вызовом `createMockFetch()`:

- GET `/api/operations/packaging-tasks/not-a-demo-task` → HTTP 200, задание `demo-pack`;
- GET `/api/unknown/available` → HTTP 200, список демонстрационных товаров.

Сопоставление через `includes` принимает неизвестные адреса вместо явного отказа. Реальной сети нет, но требование об отказе неизвестного маршрута нарушено: ошибочный адрес маскируется успешными данными. C9 проверяет только адрес, не совпадающий ни с одной такой широкой веткой.
