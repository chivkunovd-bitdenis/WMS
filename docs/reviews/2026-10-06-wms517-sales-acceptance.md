## Проверенное поведение кода

Прочитаны текущие AGENTS.md, актуальная постановка и исходные слова владельца,
`wb_sales_report`, repository, create/retry и финальная стадия orchestration,
новые контракты и developer/tester handoff. Предыдущее аналитическое решение
`6b85381722dafb690c3a2c4b90cce762b4b3643b` и независимое review
`wms517-astra-096475c.md` подтверждают законную замену устаревшего ценового
источника в трёх legacy tests; проверка истории ошибок, claims и retry сохранена.

R18–R20: допускается точная S-продажа своего переданного FBS WB заказа по
`wb_rid == srid`. Сам `wb_status=sold` и старый снимок цены не разрешают вывод.
R, неизвестный тип и конфликт исключают строку; одна sale не размножается по
нескольким локальным заказам. Чтение продолжается до пустого массива с точным
курcором, включая седьмой знак дробной секунды. Завершённый краткий cache
используется только чтением; create/retry/final builder требуют fresh report.
HTTP/transport/stalled cursor не превращают частичный отчёт в полный.

R19: после 429 ожидающий caller сравнивает поколение общего cooldown и заново
атомарно резервирует слот Redis. Разработчик сообщил отдельную проверку native
Lua с тремя ожидающими reservations и интервалами 61 секунду; это его smoke,
не независимый многопользовательский HTTP-прогон аналитика. Независимый frozen
waiting-caller тест проверяет конкретный прежний дефект A429/B61.

R20/R22/R24: финальная sales-проверка идёт после True API preflight до bytes.
После ожидания проверяются принадлежащая процессу lease, локальная привязка
и срок auth. Mixed return сохраняет оба выбранных item и исходное S-основание
вернувшегося, добавляет фактическое R-основание/ошибку, не включает его в документ;
исправная строка продолжает подпись-заглушку и terminal recovery. Цена берётся
из finishedPrice точной продажи, перенос Decimal exponent не округляет дробную
копейку. Числовая JSON-лексема с невозможным exponent сохраняется как evidence
и ошибка одного item, без HTTP500 и потери исправного соседа. Уже начатый
UNKNOWN/submitted recovery работает по прежним bytes/hash, не вызывает fresh
sales или повторный create POST.

R21: изменена одна публичная подпись состава отчёта: проданные FBS WB товары,
период по дате передачи. Колонки/компоненты/диалог сертификата не изменены.
Рендер текущего SHA в браузере аналитиком не проверен. Историческая UX-приёмка
и 18 frontend state/API tests разработчика не являются новым браузерным proof.
