# WMS-396: независимая сверка двух ревью

Модель: Astra xhigh. Проверенный срез: `4ff1151354df9b4254dedccb01c027f8bf1ffe6f`.
Проверка только чтением исходников через `git show`: без тестов, браузерных
действий и запросов к живым сервисам. Незакоммиченные исправления в вердикт
не включены. Основания: отдельные отчёты Opus и Astra в этой папке.

Приняты шесть исправлений:

1. Во время приёмки можно отменить собственную ошибочную привязку кода.
   Проверка количества иначе не позволяет заменить ошибку. Использованные
   FBS-коды защищены. Для прежнего печатного кода удаляется только связь приёмки.
2. Работающий проверяющий процесс перед завершением подбирает новые коды,
   добавленные после повторного открытия документа. Финализация согласуется
   с существующей блокировкой приёмки. Новые статусы и блокировки оператора
   не требуются. Исчезнувшее после HTTP событие пропускается, не оставляя job running.
3. Подходящий напечатанный код того же товара/селлера без упаковочной и FBS-связи
   допускается к проверке на приёмке. Его source/status/pool/history сохраняются.
   Исключение FBS для внешнего приёмочного кода не расширяется на печатный пул.
4. Повторное автоматическое завершение/проведение проверяет только ещё не
   проверенные коды. Явная повторная проверка обновляет ответы. TTL не нужен.
5. Зелёный ответ требует одновременно INTRODUCED, checkResult=true и verified=true.
   Пропущенное verified означает неподтверждённый ответ. Реальный ошибочный
   ответ внешнего сервиса не воспроизведён, поэтому тяжесть P1 не доказана.
6. Итог failed фоновой задачи сохраняется до дополнительного чтения документа:
   вторичная ошибка восстановления не должна откатить запись результата.

Отклонены как дефекты данной задачи:

- Предполагаемый запрет обычному сотруднику: App.tsx передаёт в параметр
  isFulfillmentAdmin фактическое право canReceptionOps; сервер требует reception.
- Ошибка для другой строки того же товара: unique(request_id, product_id)
  запрещает такие строки; для другого товара раньше срабатывает product-check.
- Требование добавить панель сортировки: таблица приёмки намеренно отсутствует
  в workspace=sorting ещё до изменения. Завершение сохраняет текущий workspace,
  а коды доступны в существующем документе приёмки. Расширение экрана не требуется.

Отсутствие индекса по номеру документа подтверждено, но значимая задержка не
измерена. Это не доказанный блокер и не основание добавлять индекс вслепую.
Складские остатки, резервы, навигация и разрешение упаковки не должны меняться.
Это вердикт по коду, а не подтверждение живого складского сценария.
