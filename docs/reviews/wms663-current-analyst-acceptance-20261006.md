### C10: что реально доказал PostgreSQL

Текущий `test_wms663_two_sessions_commit_one_posting_version_once` открывает две настоящие `SessionLocal`, одновременно сохраняет разные ГТД одного экземпляра с expected_version=0 и требует ровно один успех, один `ozon_exemplar_documents_conflict`, один SET. На SQLite он явно SKIP. Исторический `wms663-developer/postgres-race.txt` содержит 1 PASS/3.65s; `wms663-developer/evidence.md` устанавливает временную isolated базу `127.0.0.1:56663/wms_test663` и её последующее удаление. Полная историческая PG-матрица имела также MissingGreenlet, исправленный отдельно 76f2162. Позднейшие 112/993 прогоны оставляли PG SKIP. Нового current PG результата не найдено, подключения к общей базе и создание контура в этом проходе не выполнялись.

Это тест двух document writers, не смешанная гонка marking/document. Для текущего доказательства достаточно этого теста на отдельном локальном PG и одного адресного mixed race с FakeTransport, сверкой итоговых marks/docs, версии и числа SET. Общие PG517/операторские базы для этого не использовать.

Текущая девятистрочная read-матрица в `test_wms663_customs_documents_contract.py` прочитана: validation_in_process→checking; полный matching ship_available→accepted; пустой ship_available→unknown; старый номер+mystery check→unknown; ship_not_available+gtd_invalid→rejected; update_available→editable; update_not_available без errors→unknown; null status/products→unknown; future_status→unknown.
