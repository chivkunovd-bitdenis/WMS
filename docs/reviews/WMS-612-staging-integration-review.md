# WMS-612 — независимое ревью интеграционного кандидата staging

01.10.2026 проверен итоговый код `9e2cfa42e74e21cf07cbb59041dc244b2f5eddf7`,
затем происхождение merge-кандидата
`afd9037106c2842b0f4912ba8daf9a0b648caed3`. Ревью провёл GPT-6 Sol high
как доступный fallback: предписанная AGENTS.md модель Opus в этой среде была
недоступна. Это заключение **не является ревью Opus**.

При первом просмотре кандидата `c7c4ea04dd1e03a78d002a6e3c9e7cbbffb67487`
найдены два P2 в окне передачи WB-поставки. Проверки состава с номером заказа в
тексте не объединялись в одну строку по типу; отменённые заказы сразу выводились
длинным списком без ограничения высоты. Исправление `b12c9a5e8979da41ced1e5e7b27bd362e80a3e58`
сгруппировало проверки по коду и поместило отменённые заказы в раскрываемый список
с ограничением высоты 220 px. Повторное ревью нашло ещё один P2: под общим кодом
`marking_not_allowed` скрывались разные причины по конкретным заказам, а для
`negative_stock` терялись величины нехватки. В `9e2cfa42e74e21cf07cbb59041dc244b2f5eddf7`
индивидуальные причины, количества и расхождения состава сохранены в строках
заказов внутри раскрытия; дубли одинаковых деталей удаляются. В основном тексте
остаётся одна компактная строка по типу без перечня номеров. Финальное адресное
ревью изменений WMS-612: **PASS, новых P1/P2 не обнаружено**.

Проверки по сохранённому коду:

- На первоначальном интеграционном кандидате прошли 47 адресных backend-тестов,
  Ruff и mypy. После исправлений WMS-612 прошли 49 адресных frontend-тестов,
  `npx tsc --noEmit -p tsconfig.app.json` и `npm run build`. DOM-тест проверил
  раскрытие разных причин и количеств у конкретных заказов; отдельный DOM-тест
  проверил 200 отменённых заказов, данные товара и короба и прокрутку внутри
  ограниченного списка. Повторный полный backend-прогон после чисто frontend-правок
  не проводился.
- Alembic показал единственную конечную миграцию `20261001_0612` с родителями
  `20260929_0590` и `20260930_0567`. Исходные `etalon@b93968f0` и
  `staging@24ddd200` входят в историю кандидата; production WMS-611 также
  сохранилась в истории.
- Merge `afd9037106c2842b0f4912ba8daf9a0b648caed3` имеет родителей
  `9e2cfa42e74e21cf07cbb59041dc244b2f5eddf7` и уже опубликованный
  `staging@424efa0074f2fddb6b03fa43bb3e2842bb53e4d1`. Все восемь
  изменённых файлов WMS-517 побайтово совпали с этим staging SHA. Проверенные
  файлы WMS-612 и merge-миграция побайтово совпали с `9e2cfa42`; конечная
  миграция Alembic осталась одна. Эта сверка сохраняет опубликованный состав
  staging и не принимает новых незамороженных изменений WMS-517.

Границы заключения: ревью и локальные проверки не доказывают опубликованную
версию API/web, работу worker, переход PostgreSQL на стенде, доставку mobile APK,
работу физического принтера или операторскую приёмку. Проверки C8–C18 в
`docs/requirements/WMS-612.md` должен заполнить аналитик по фактическим
результатам выпуска. Деплой этим ревью не выполнялся.
