# WMS-398: предел проверки production-каталога

9 сентября 2026 года агент ozon_terminal_guard проверил существующие источники
доступа, чтобы измерить большой каталог через настоящий браузер. Новые пароли,
токены и учётные записи не создавались, восстановление пароля не запускалось.
Код и данные не менялись.

В основном `.secrets` найден только staging-token.txt, в рабочих деревьях
отдельных `.secrets` нет. Токен стейджа в production не отправлялся.
DEPLOY_SERVER_RU.md описывает SSH и развёртывание, но не FF-учётную запись;
другой актуальный путь входа в просмотренных README, CLAUDE, корневых документах
и скриптах не найден. Значения server.env и JWT-секреты не читались.

Инвентаризация интерфейса недоступна при заблокированном Mac; список браузеров
пуст, запущенного Chrome с доступным портом CDP нет. Новые запросы без сессии
к `/api/auth/me` и `/api/products/ff-catalog-page?limit=1&offset=0` вернули401
`not_authenticated`. Это не проверка прежних токенов и не утверждение об их
истечении.

Дополнительно найдены localStorage-каталоги Chrome Default, Profile2 и Profile4.
Доступного читателя LevelDB в PATH, Python, backend-venv, Node runtime и
frontend-зависимостях нет. Поэтому точная запись origin
`https://wms.sellerfocus.pro` → `wms_token_ff` → значение не прочитана.
Профили не копировались и не изменялись, все JWT регулярными выражениями не
собирались, зависимости не устанавливались. Наличие действующей сохранённой
сессии остаётся неизвестным, а не доказанно отсутствующим.

Защищённый production-каталог не открыт, замеров на его большом объёме нет.
Учебные2.23/1.93с на257товарах из соседнего staging-отчёта не переносятся на
production. Это ограничение измерительного среза не изменяет результаты
стейдж-приёмки подготовленного основного релиза.
