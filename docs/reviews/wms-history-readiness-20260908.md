## WMS-047: исторический план изменился, прежний запуск неприменим

Воспроизведён отбор `reconcile_fbs_unlinked_shipments.py`, но без `FOR UPDATE`:
существующий ledger без `shipment_movement_id`, без `reversed_at`, заказ не
`cancelled`/`defect`, поставка имеет `delivered_at`, текущий товар принадлежит
конкретному селлеру. Все найденные записи относятся к WB и поставкам `source=wms`.

| Селлер и арендатор | Строк / единиц | Групп точных источников | Остаток в этих источниках |
| --- | ---: | ---: | ---: |
| ИП Фадин, Империя ФФ | 36 / 36 | 12 | 314 |
| ИП Машнин, Империя ФФ | 7 / 7 | 4 | 102 |
| ИП Рябов, FFAdam | 5 / 5 | 2 | 153 |

Всего **48 единиц**, а не прежние 49. Ledger датированы 21–26 августа. У Фадина
сейчас 36 вместо 37. Причину изменения относительно прежней выборки установить
по агрегированному старому числу нельзя: старого списка ID для прямого сравнения
в этой проверке нет. Число 37 нельзя использовать как текущий expected-count.
Контрольные отпечатки отсортированных ID кандидатов сохранены в JSON.

Несовпадений tenant, владельца товара/заказа и product_id между ledger и заказом
не найдено. У выбранных источников нет контейнеров. По товарам кандидатов не найдено
`ownership_transfer_out`. Это проверка записанных связей, а не физический пересчёт.

**Конкретные ограничения перед применением:**

1. В базе два селлера с точным именем «ИП Фадин»: нужный в «Империи ФФ»
   (`d1f26146-e99a-41af-9471-9c80ec990db3`) и другой у «ИП Львова В.В.».
   CLI ищет имя глобально и требует ровно одну строку, поэтому существующая команда
   по имени завершится отказом. Для этого селлера сначала необходим точный выбор
   tenant/seller в инструменте; переименовывать селлеров ради запуска нельзя.
   Код CLI в рамках read-only задачи не менялся.
2. У Машнина три единицы относятся к product
   `ae172339-cfc2-43e2-b4d7-e1a84c0d09f3`, location
   `2f22105f-c78a-4ac4-969d-9f76ae336a1d`: текущий остаток **−5**, после предлагаемого
   списания будет **−8**. Остальные группы имеют достаточно физического количества
   для выбранного списания; это не расчёт свободного остатка с резервами.
   Согласие на обычное «досписать 7» не следует подменять молчаливым согласием
   увеличить конкретный минус.
3. В том же диапазоне дат и только у этих трёх селлеров отдельно остаются
   **2 defect** Фадина с переданной поставкой и **32 cancelled без supply_id**
   (Фадин 31, Рябов 1). Они исключены. Прежнее число 52 относилось к старой
   проверке; эта ограниченная выборка не выдана за пересчёт всей базы.

Сам CLI не вызывался даже без `--apply`: его текущий dry-run берёт `FOR UPDATE`.
Опасный `reconcile_fbs_shipped_stock.py` также не вызывался. Для последующего
применения нужны новый точный сухой отчёт непосредственно перед операцией,
проверка его ID/числа и отдельное разрешение владельца на конкретный объём и минус.
Стадия готовности: данные уточнены; прежний запуск без изменения границ непригоден.

## WMS-048: чужую связь восстановить нельзя

Заказ **5515735341**, ID `15272ef2-b423-4f40-95b1-a3fd99e3c821`, статус `done`,
поставка **WB-GI-266096235**, `source=wms`, передана **17.08.2026 16:50:06 UTC**.
В поставке шесть заказов, у пяти есть связанное движение, у целевого ledger отсутствует.
Текущая карточка товара `eadd0460-4850-4a39-a7f4-7758e14c9f42` принадлежит Loviana.

Прямая связь `fbs_order_picks` подтверждает подбор именно этого заказа 17 августа
в 15:20:17 UTC; `undone_at=NULL`, движение `947b0124…` имеет тип `fbs_order_pick`
и дельту +1. Оно не является списанием при передаче. Перемещение 18 августа —
пара −1/+1 с одной `transfer_group_id`, его суммарная дельта равна нулю.

У этого товара за всю сохранённую историю найдены только два `fbs_shipment`:
−1 от 19 августа (`db634e5b…`) и +1 от 23 августа (`4e180e0e…`). Оба напрямую
связаны через ledger с **другим заказом 5521827979**. Присвоение этих движений
целевому заказу испортит уже существующую связь и не является исправлением.

26 августа пара с `transfer_group_id=176081d9-e993-58e6-ae42-fd29c500201d`

или списать с него штуку автоматически.

Стадия готовности: пропущенная запись подтверждена, среди сохранённых
`fbs_shipment` свободного движения для восстановления ссылки не найдено. Выбор коррекции
остатка и её владельца требует отдельного решения с учётом передачи собственности;
никакое списание или изменение связей здесь не подготовлено как безопасный apply.
Причина исходного пропуска 17 августа по этим данным не доказана.

## WMS-013: деньги пока не определены, старые числа фактов устарели

Для «Империи ФФ» сейчас `billing_enabled_from=NULL`. Для услуг `fbs_order` и
`packing` **0 тарифов V2 вообще**, **0 старых тарифов**. Следовательно, нет ни
утверждённой даты начала, ни ставок на исторический период. Сумма добора не считалась
и не может быть обоснована выбором сегодняшнего тарифа.

Ограниченная историческая выборка: только WB, три исходных селлера Loviana,
ИП Фадин и ИП Чжоу, заказы созданы в WB **до 05.09.2026 00:00 UTC**.
Это граница исследования старых заказов, а не выбранная дата биллинга.
Текущий статус и дата работы могли измениться позднее; диапазоны сохранены в JSON.

| Селлер | sorted/done + in_delivery с подтверждением передачи | Уже имеют факт | Не хватает фактов | Начислений fbs_order |
| --- | ---: | ---: | ---: | ---: |
| Loviana | 583 | 581 | 2 | 0 |
| ИП Фадин | 2712 | 2712 | 0 | 0 |
| ИП Чжоу | 362 | 362 | 0 | 0 |

Прежние соотношения «5479 против 993» и подобные нельзя использовать как нынешний
объём создания фактов. Для двух отсутствующих фактов Loviana статус `in_delivery`
подтверждён датой передачи. У шести существующих фактов Loviana расхождение с
сохранённой передачей больше суток; у этих шести нет начислений или прямой ссылки
на факт из счёта V2. Это кандидаты на отдельную сверку дат, а не выполненная правка.
У **2494** подтверждённых заказов Фадина и **2** Loviana нет даты передачи,
упаковки или подбора: текущий скрипт использует время создания заказа в WB.
Это запасной источник даты, а не доказанное время складской работы.

Отменённые и бракованные заказы рассмотрены отдельно:

| Селлер | cancelled / defect | Со связанным списанием cancelled / defect | История перехода sorted/done |
| --- | ---: | ---: | ---: |
| Loviana | 581 / 50 | 549 / 50 | 0 / 0 |
| ИП Фадин | 2874 / 189 | 106 / 4 | 1 / 0 |
| ИП Чжоу | 671 / 82 | 635 / 82 | 0 / 0 |

Ноль записанных переходов не означает, что заказ не достигал сортировки:
история статусов у большинства старых записей отсутствует. Связанное складское
списание доказывает записанное списание, но само по себе не подтверждает сортировку WB.
Есть один конкретный подтверждённый историей случай: заказ Фадина **5608277472**
(`8ced568d-9510-45ae-911a-13ebfaddc4d3`) перешёл **sorted → cancelled**
03.09.2026 08:16:50 UTC; факта `fbs_order` у него нет. Текущий генератор выбирает
только `in_delivery/sorted/done` и этот cancelled не возьмёт. Массово расширять
его на все отменённые заказы нельзя: для остальных такого доказательства не получено.

Прочитаны актуальные `backend/scripts/backfill_fbs_order_facts.py` и
`backfill_billing_charges.py`. В текущей ветке генератор уже защищает даты фактов,
если есть начисление либо ссылка из счёта, и не меняет даты ledger. Старая фраза
канона о безусловном redating ledger не описывает этот код. Состав production-образа
для запуска этих standalone scripts не подтверждён: по относительному пути
`scripts/backfill_fbs_order_facts.py` внутри API-контейнера файл не найден.
Код из рабочей ветки нельзя объявлять уже доступным для исполнения в production.

Денежный скрипт рассчитан на выбранный период и начисляет также сопутствующую
упаковку. Его dry-run вызывает функцию создания начислений и затем откатывает
транзакцию; поэтому в этой строго читающей проверке он также не запускался.

До денежного плана владельцу необходимо определить: с какой даты начинать
выставление денег за прошлую работу; какие исторические ставки `fbs_order` и
`packing` действуют у нужных селлеров и с каких дат; как трактовать записи без
подтверждённой даты работы и отдельно доказанный cancelled после sorted.
После этих решений потребуется конкретный сухой денежный расчёт за согласованный
период. Складские операции ради появления финансового факта не переигрываются.
