## Проверенный механизм и безопасное следующее действие

В установленном `support_agent/agent_tools.py::_tool_queue_process_reply`
проверяются задача, тип сообщения, текст и версия описания; проверки запрета
ответов владельцем в этом методе нет. Он может создать `necessary_question`
или `description_confirmation` для клиентского чата.
`support_agent/telegram.py::flush_outbox` отправляет все `pending` после
`claim_outbox`; проверки запрета для клиентского чата в этом пути также нет.

Ограниченный поиск установленного кода и исходников не выявил существующей
команды или API для отдельного mute/owner-pending, сохраняющего анализ задач.
`quiet_sec` в pipeline — задержка обработки после активности, а не запрет отправки.
`cancel_job` отменяет само запланированное или работающее задание; для продолжения
анализа при запрете клиентских сообщений он не подходит.

При текущей пустой очереди удалять или отменять нечего. Если появится запрещённое
промежуточное сообщение, минимальное воздействие — отменить только точные ещё
не отправленные строки outbox данного чата, сохранив tickets и agent_job.
`sending` и `unknown` требуют выяснения фактической отправки, их нельзя слепо
возвращать в очередь. Автоматический запрет новых клиентских сообщений требует
отдельного исправления проверенного пути; в этом аудите оно не реализовано.

Файлы установленного runtime прочитаны непосредственно; полного соответствия
runtime одному Git SHA эта проверка не устанавливает. Отчёт не является
приёмкой бизнес-задач, подтверждением deployment или внешнего действия.
