# WMS-378 / WMS-379: два исправления ссылочного входа после общего ревью

Основание: независимый Astra review полного выпуска a1b64752. Root открыл
обе цепочки и подтвердил дефекты; реальные пароли, ключи или приглашения
пользователей для проверки не использовались.

## Конкурентное применение ссылки

set_password_by_link читал User без блокировки. Пока другой запрос менял
пароль, ожидающий запрос проверял прежний fingerprint и после ожидания своей
записи успешно затирал уже изменённый пароль. Исправление — существующий
session.get с FOR UPDATE и populate_existing до проверки fingerprint.
Смена пароля и прежний commit остаются на месте; новых сущностей нет.

Новая регрессия на отдельной локальной PostgreSQL БД держит реальную блокировку
первой смены пароля, запускает вторую и ждёт pg_stat_activity Lock, затем
фиксирует первую. На исходном коде тест упал: DID NOT RAISE AuthError.
После исправления второй запрос получает link_used, первый пароль остаётся.
Весь профильный test_auth_email_links.py: 8 passed. Ruff и mypy двух изменённых
файлов прошли. БД создана только для этого прогона и удалена после результата.
Полный CI не запускался отдельно на каждый найденный дефект: будет один на
объединённые исправления общего ревью.

## Форма ссылки при уже существующей сессии

На настоящем staging a1b64752 root открыл в отдельной странице искусственные
адреса /seller/set-password?token=qa-invalid-link-display-only и
/set-password?token=qa-invalid-link-display-only с существующей FF-сессией.
Оба показали «Нет доступа» вместо формы; пароль не отправлялся. Это
неиспользуемая строка для проверки маршрута, не действующий токен.

App и SellerApp теперь дают существующему пути /set-password приоритет перед
проверкой сохранённой сессии. В SellerApp этот путь также не перехватывается
экраном наличия FF-сессии. Сама PublicAuthScreen, её дизайн и запросы не менялись.
После успешного заполнения прежний useAuth очищает адрес переходом на корень
соответствующего портала. TypeScript и сборка прошли. Повтор на staging после
развёртывания объединённых исправлений ещё требуется; отправка писем и реальная
смена клиентских паролей не заявляются как проверенные.
