## D1 · P2: показанный размер 48 не находится фильтром 48

Место: `backend/app/services/seller_fulfillment_catalog_service.py:475–485`,
в частности строка 481; аналогичная нормализация категории — строки 546–556,
в частности 552. Нарушены R2/R4/R6; для группировки категории также R5.

SQL `trim(value)` без набора символов удаляет обычный пробел U+0020.
Существующие `_size_label()`, `_size_label_from_entry()` и
`subject_name_from_card()` используют Python `strip()`, который удаляет также
табуляцию и неразрывный пробел. Проверка строкового типа JSON исправлена,
но после неё SQL оставляет эти символы внутри значения для фильтра и порядка.

В собственной SQLite и PostgreSQL 17.10 проверена импортированная карточка:

```json
{"sizes": [{"techSize": 148, "wbSize": "\t48\t"}]}
```

Фактический результат реального сервиса на обоих движках:

```text
size=None  -> page [('wb:669954', ['48'])], total=1, keys=['wb:669954']
size='48'  -> page [], total=0, keys=[]
size='148' -> page [], total=0, keys=[]
```

На PostgreSQL тот же отказ фильтра 48 воспроизведён с `wbSize="\u00a048\u00a0"`.
Дополнительно проверен WMS-товар с пустым `wb_size`/`wb_barcode`, собственным
`ProductBarcode(source="wb", barcode="own")` и двумя вариантами карточки:

```json
{"sizes": [
  {"techSize": "148", "skus": ["other"]},
  {"techSize": 148, "wbSize": "\t48\t", "skus": ["own"]}
]}
```

Без фильтра возвращается одна строка товара с `wb_size="48"`. С фильтром 48
`page=[]`, `keys=[]`, `total=0`; с 148 также пусто. Собственный вариант найден
при обогащении, но исключён SQL-фильтром. Это не смешение с чужим вариантом и
не изменение остатка. Примеры созданы локально; наличие таких данных в production
не утверждается.

Второе проявление той же причины: три SQLite-карточки одного артикула/размера с
`subjectName` соответственно `"\tФутболки\t"`, `"Пуховики"`, `"Футболки"`
дают показанный порядок **Футболки → Пуховики → Футболки**. Полная выдача и три
страницы по одной строке совпадают, total=3: строки сохранены, но равная видимая
категория разбита на две группы. На собственном PostgreSQL с en_US.UTF-8 этот
пример дал непрерывную группу благодаря порядку сравнения строк; нарушение
группировки PostgreSQL этим примером не заявляется.

Нужно привести нормализацию SQL к семантике существующих функций отображения
в обоих движках, сохранив выбор строкового techSize/wbSize и собственного
варианта. Не менять отображаемые значения или существующие ожидания тестов.
Обычный `trim` размера уже присутствовал в базе сравнения: это оставшаяся
граница исправляемого F2, а не новый дефект проверки типа JSON. Нормализация
категории добавлена именно в рассматриваемом изменении. Повтор всей истории
и новые продуктовые требования для исправления не нужны.
