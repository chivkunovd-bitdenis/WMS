# WMS-395: существующий крестик отвязки для WB КИЗ из пула

Ветка `codex/wms395-pool-inline` создана в существующем worktree от
`origin/staging`, SHA `27400e5ff45d4e93eb6afc174f60710f3930abb4`.
Root передал реальный браузерный случай: оператор сканировал WB КИЗ из пула,
binding имел `source=pool`, но крестик не появился. В прочитанном коде оба
места показа отмены вызывали `hasOperatorKiz`, который пропускал исключительно
`source=operator`; это и есть исправленная причина.

Предикат переименован в `hasRemovableKiz(order, marketplace)` и принимает
существующее различие WB/Ozon. Для WB допускаются источники `operator` и
`pool`, включая `rejected`, но по-прежнему исключается `missing`. Сам inline
крестик, его размер, место, disabled-условия, обработчик, диалог подтверждения
и DELETE не менялись. Пункт существующего меню использует тот же предикат.
Для Ozon сохранены прежние `operator`-only, исключение rejected/missing и
отсутствие inline-крестика. Backend, навигация, складские операции и сущности
не менялись.

Проверки `npx tsc --noEmit -p tsconfig.app.json` и `npm run build` прошли на
существующем symlink `frontend/node_modules`, без установки зависимостей.
Vite сообщил только предупреждение о крупных чанках. Unit-тесты на два условия
не добавлялись. Собственный сгенерированный `frontend/dist` удалён после проверки
для освобождения диска.

Этот файл описывает реализацию по коду. Новая версия в живом браузере пока
не проверена: ожидается отдельный deploy нового SHA. КИЗ заказа A500043 и
данные staging в ходе этой правки не изменялись.
