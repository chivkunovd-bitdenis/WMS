# WMS-396: ручное удаление ошибочного КИЗ, 08.09.2026

Проверка выполнена в обычном Chrome через native accessibility: отдельная
вкладка `http://127.0.0.1:15396`, API `127.0.0.1:18396`. Существующие
`tmp/qa396/runtime.py`, `manifest.json` и `browser.sqlite` не пересоздавались.
Прочитана защита runtime `socket.connect` / `connect_ex`, запрещающая внешние
подключения; ЧЗ отвечает синтетической функцией. Живые данные не использовались.
Checkout при проверке: `af537a950238e8f8930487de4d3ae78421dc3ff6`; это номер
checkout, а не утверждение о перезапуске процесса API из этого коммита.

В приёмке №000002 (`f4cd36fe-76b8-49fe-bd00-b0f7e44be9db`) раскрыт список
«Коды ЧЗ: sku-qa396». На экране были количество 4 и два синтетических КИЗ
с serial `GOODBOX123456` и `GOODCARGO1234`. Нажата кнопка «Убрать код из приёмки»
в строке `GOODBOX123456`. Строка исчезла, второй КИЗ остался. Количество
сохранилось: 4, объём — 4.00 л, коробов и грузомест — по одному.

Read-only снимки SQLite до и после лежат в `tmp/qa396/delete-before.json`
и `delete-after.json`. Сравнение полных строк показало изменения только
`marking_codes` и `marking_code_events`: обе таблицы уменьшились с 6 до 5 строк.
Документ, товарные строки, короба, грузоместа, распределение, остатки,
резервы и движения остались без изменений. Сохранились прежние два движения
с суммой 5 единиц. Удаление КИЗ не создало складского движения.

## Граница проверки проведённой приёмки

Кликом открыт №000001: прочитаны статус «В сортировке», количество 5 и
сообщение «Приёмка завершена. Остаток принят на склад ФФ». Попытка раскрыть
«Коды ЧЗ: sku-qa396» вернула `cannotClickOffscreenElement`; последующие
изображение, прокрутка и чтение accessibility — `failedToCreateImageDestination`.
Отсутствие кнопки удаления в раскрытом списке проведённого документа поэтому
этим браузерным проходом **не подтверждено**.

Затем запись отчёта и создание Git index.lock также вернули
`No space left on device`. `df` показал 100% использования раздела Data.
Это конкретный сбой среды, а не подтверждение дефекта приложения или блокировки Mac.

Код и канонический бэклог не менялись; pytest и ревью не запускались.
Это локальная проверка на синтетике, не подтверждение staging-деплоя.
Исходные runtime/manifest/SQLite сохранены; изменение тестовых данных —
только удалённый по заданию КИЗ и его привязка.

## Дополнительная ручная проверка root

После освобождения генерируемых кешей root открыл ту же локальную синтетику
через IAB tab36, нажал Приёмка → №000001 → оба раскрытия Коды ЧЗ.
Оба списка успешно раскрылись: три кода первого товара и один второго.
В обоих списках отсутствуют кнопки удаления. Статус «В сортировке», количество
5 и сообщение о завершённой приёмке видимы одновременно. Скриншот подтверждает
красную строку проблемного товара, зелёный годный код, красные проблемный/
недоступный и значки !. Это закрывает предыдущую локальную браузерную границу
про отсутствие удаления в проведённой приёмке. Живой staging и настоящий
положительный ответ ЧЗ этим действием не проверялись.
