# WMS-443: наблюдения координатора в локальном вебе

Дата: 13.09.2026. Проверяемый UI: `7134b8ec4bd916dc0f4ae3e7ce0a13d52357b7b8`, worktree `wms443-tsd-ui`, Vite 5205, тестовый API 18082. Это вспомогательная проверка координатора, а не независимое ревью или приёмка аналитика.

Через браузер Codex выполнены следующие реальные действия:

1. Открыта новая форма: основное поле «ФИО» и пароль, на той же форме есть «Вход по прежнему логину».
2. Переходный вход существующим синтетическим администратором выполнен. Шапка показывает «ФИО не указано · администратор»; существующие настройки доступны, в них есть поля собственного профиля и создания сотрудника.
3. Через локальный API создана отдельная тестовая учётная запись `e9d8fdab-9242-47e0-9c5f-2191eb2b4b5c`, ФИО «Ирина Тестовая WMS443», должность «Приёмщик». Ответ создания подтверждает обе строки и display_name. Общий профиль администратора не изменялся.
4. После выхода из администратора реальная форма входа принимает ФИО и пароль новой тестовой учётки. Шапка меняется на «Ирина Тестовая WMS443 · сотрудник». Права новой записи не расширялись; закрытый для неё раздел настроек показывает «Нет доступа», что здесь не считается дефектом.

## Подтверждённое замечание R5

Должность «Приёмщик» сохранена сервером, но в шапке вошедшего пользователя отсутствует: видны только ФИО и системная роль «сотрудник». Это подтверждено деревом доступности и снимком браузера. R5 прямо требует должность в профиле/шапке. Исполнителю нужно добавить её в существующую шапку в рамках текущего оформления, не подменяя должность ролью и не добавляя новый экран. Проверить также шапку портала селлера и длинные значения по R11.

## Оставшиеся проверки

Создание и редактирование сотрудника именно через UI, сохранение собственного профиля старого администратора, тёзки, ошибки чтения профиля, Android/PIN и сквозное авторство ещё не подтверждены этой проверкой. Собранный код и приведённые наблюдения не являются положительной приёмкой WMS-443.
