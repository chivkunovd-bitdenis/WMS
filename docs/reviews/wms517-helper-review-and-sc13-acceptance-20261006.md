## Независимое ревью helper

`scripts/ops/wms517-read-sold.py` SHA256
`39b89c06514485b5e62c20dd8de57fbc48bf60904195cd229bf2a28d481810d6` фиксирует
exact tenant/seller AVpack. До remote execution проверяет два SHA256 принятого
reader/repository. Исходники интерпретируются отдельным процессом существующего
API-контейнера: сервис/файлы приложения не заменяются, ключи и настройки остаются
в приложении. Seller/tenant loader читает существующее подключение без его
изменения; eligible query сохраняет границы переданного WB FBS, привязки, отмен,
брака и возвратов. Свежий состав перечитывается после ожидания WB; claims
сверяются отдельно по точным tenant/seller.

Remote-путь содержит SELECT и GET supplier/sales. Reader завершает read-транзакцию
через session.commit до HTTP; helper не добавляет ORM mutations, create/prepare,
submit, подпись, отгрузку или исправление остатков. Redis получает штатные rate
slots и completed-report cache: служебная запись обозначена, а не названа
отсутствием любых writes. Пагинация идёт до [], неполный/ошибочный отчёт не
становится complete; ошибок reader сохраняются только коды. Произвольные stderr,
headers, body, credentials, полный CIS и подписи наружу не публикуются.

Выход helper сохраняет complete/error flags; один exit0 сам по себе не является
доказательством полного чтения. В конкретном JSON complete=true, errors отсутствуют,
обе страницы200 и coverage_missing=[]. Подтверждённых дефектов новой helper-дельты
не найдено. Runbook использует существующий экран, без фиксирования84 в программе,
повторной отправки ссылки, terminal/DevTools или подписи за оператора.
