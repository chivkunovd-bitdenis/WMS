# WMS-680 / WMS-673: уточнение контракта печатных колонок

07.10.2026. Ограниченное аналитическое уточнение по поручению ведущего; тесты и продукт этим документом не меняются. Прочитаны оба `frontend/src/screens/v2/fbsPickingColor.wms673.{dom,pdf}.test.*`, `wms673PrintRenderer.ts`, текущий `fbsUx.ts`, действующие R8–R10/C680-15…19 в требованиях WMS-680 и финальная приёмка отдельных колонок (продукт b6e5aef170, независимый PASS db5dd38c). Просмотрен исходный скрин владельца `docs/evidence/WMS-680/acceptance-20261007/owner-print-preview-baseline.png`; прежнее размещение внутри товара на нём — основание уточнения, а не принятый новый макет.

Исходные слова владельца в требованиях: «На всё должен быть отдельный столбец: цвет, размер, артикул. Везде отдельный свой столбец, но не делай их огромными, они должны быть реально по размеру… колонки для цифр… пустые… или точно под числовые значения, где количество… узкими, за счёт этого остальные столбцы шире». Это заменяет прежние структурные ограничения WMS-673, которые несовместимы с отдельным артикулом и компактной шириной; остальные защиты остаются.

## Законно заменённые ожидания

В FBS печатной таблице теперь 12 столбцов вместо 11: №, Фото, Товар, Артикул, Цвет, Размер, Ячейка / тара, Заказы соответствующей площадки, Стикер, Взять, Подобрано, Маркировка. Проверки C5 числа ячеек, C6 числа заголовков/пустого colspan, C7 и C7/C11 числа колонок/строк должны ожидать эту структуру. Пустая таблица по-прежнему обязана иметь colspan, равный реальному числу заголовков; её защита не удаляется.

Старое `headers.slice(3,6) == [Размер, Цвет, Ячейка / тара]` заменяется новой структурой. Индекс Цвета по-прежнему 4, но Размер теперь 5, Артикул 3, Ячейка 6, Заказ 7, Стикер 8, Взять 9, Подобрано 10 (индексы с нуля). Сопоставления DOM/PDF и массивы `cellsWithoutColor` должны учитывать это; изменение индекса не разрешает терять само проверяемое значение. Старый артикул продавца больше не обязан быть частью склеенной строки «Товар … ART … WB … ШК»: он находится в отдельной ячейке. Все прежние артикулы, WB/SKU/ШК и принадлежность позиции сохраняются в своих ячейках/реквизитах. Различные идентификаторы не заменяются одним новым полем и не объединяются между товарами.

Фиксированная ширина Размера 78px и числовых колонок 62px заменена соразмерной содержимому компактной шириной по R9. Числа и заголовки остаются читаемыми, длинные характеристики переносятся в собственных ячейках. Нельзя заменить требование геометрии одним ожиданием наличия CSS или удалить проверки вместимости. Остальные прежние параметры не объявлены отменёнными: текущая форма сохраняет размер A4 landscape, поля 10mm, шрифт размера 20px, области №28px/Фото54px/Стикер116px; проверки этих параметров остаются. Владелец не задавал новых точных миллиметров, числа страниц или шрифта.

## Обязательная сохранность всех прежних TC-ID

Все существующие C1–C7/C9–C11, их single/group и параметрические случаи сохраняются; ни удаление, ни новая пропускающая пометка skip, ни ослабление защиты не разрешены этим решением. Прежние ограничения запуска реальных PDF по наличию внешних артефактов не выдаются за выполненную геометрию; артефакт обязан соответствовать точному HTML.

Сохраняются точные цвета/размеры своей позиции WB и Ozon, barcode/posting identity, объединение повторного ID и разделение разных seller/product ID, заполненный цвет при пустом дубле/обратном порядке, прочерк для отсутствующего/null/empty/whitespace. Сохраняется экранирование `&`, разметки и скриптов как текста без созданных элементов (C5). Сохраняются ячейки/тара, свежие pick-options, количества, фактическое подобрано, маркировка, порядок строк и старые экранные заголовки; новая печатная колонка не добавляется заодно в экранную таблицу.

Сохраняются реальные React-кнопки одиночной/групповой печати и текущий API-путь с тем же auth, только GET и неизменными fixture-данными (C6/C10). Отказ options не теряет цвета и строки, старый fallback сохраняется, причина видна и явный повтор работает. Заблокированное окно не вызывает лишний fetch; закрытое во время запроса окно не получает запись; явный повтор остаётся (C9). Доступность печати на прежних вкладках не меняется (C11). Новых складских/marketplace мутаций нет.

В реальной PDF-геометрии сохраняются полные строки/варианты/идентификаторы, повтор заголовков, A4 landscape, отсутствие выхода за страницу и колонку, наложений и смещения цвета/размера/ячейки/заказа/стикера/чисел в чужую строку. Старые PDF-поиски переставляются по новым индексам и разделённому артикулу; проверка полноты и принадлежности строки сохраняется. Длинный размер/цвет должен переноситься и оставаться читаемым; точное число строк переноса не превращается в новый запрет на иной корректный компактный макет.

## Отдельная техническая зависимость PDF-помощника

`wms673PrintRenderer.ts::pdfTable` сейчас жёстко отказывает при `geometry.columnBounds.length !== 11`. Поэтому адаптация только двух test-файлов не делает реальные PDF-проверки совместимыми с 12 столбцами. Это передано ведущему для отдельного узкого разрешения тестировщику; принимающий аналитик помощник не меняет. Требуется сохранить проверки SHA-256/точного HTML, границ столбцов/страниц и принадлежности строки. При отсутствии совместимого помощника реальные PDF-проверки остаются технически незавершёнными, а не зелёными.

Это уточнение объясняет основание нового контракта. Изменение тестов, RED на неверной структуре, независимое ревью и окончательный CI выполняются отдельно; их PASS этим документом не заявлен.
