# WMS-401 — Android API timestamp parsing

The saved APK screenshot `outputs/wms401-android-20260909/39-both-packed.png` shows raw timestamps such as `2026-09-09T10:43:24+00:00`. The app catches the date parser exception and returns the original string. The same parser also feeds oldest-order selection and the six-hour deadline highlight.

The cause was reproduced with the exact cached `desugar_jdk_libs:2.1.4` Java time classes used by the Android build (minSdk 24; core library desugaring enabled). Its `DateTimeFormatterBuilder$InstantPrinterParser.parse` bytecode appends a literal `Z`; `Instant.parse` rejects `+00:00` and `+03:00` at index 19, and the fraction-plus-offset case at index 26. Host JDK 17 accepts these inputs, which explains why the previous ordinary JVM regression was green. `OffsetDateTime.parse(value).toInstant()` accepts all four exercised forms on both implementations: `Z`, zero offset, nonzero offset and six fractional digits with offset.

Mobile commit `e2d43b5cc7817bf5be164b53ef9e2ef723c4f718`, based on `d15f09d4c09c74438ebd6b31632db0c346525a6f`, replaces only the three parsing calls and corresponding imports. `displayTime` became internal so the existing test class can check its actual output. The display pattern, local timezone, picked-order exclusion, WB-id tiebreak, invalid-value fallbacks and exclusive six-hour comparison stay the same. No navigation or visual design was changed.

The targeted `FbsViewModelTest` suite passed 12/12 tests on host JDK 17, then 12/12 using the exact Android library Java time classes patched into the host JVM. The latter is a check of the Android date implementation, not a device or AVD test. New cases directly check formatting in GMT+03:00, UTC and offset forms, microseconds, ordering where the older order has the larger WB id, exclusion of an already picked order, and times immediately before versus exactly at the six-hour boundary. A separate compatibility probe records the old parser failures and the replacement parser successes. Its script and both test XML files are retained with this report.
