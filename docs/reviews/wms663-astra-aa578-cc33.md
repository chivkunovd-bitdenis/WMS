## C7: чужой экземпляр больше не загрязняет ожидаемый состав

Отдельный контракт `d66c59a8a13b7053c88680745f10ea07d4d015e2` сохранён до правки.
В нём STATUS заменяет целевой exemplar 81 на 99981; ложного принятия нет,
но затем правильный полный ответ 81/82 раньше оставлял view unknown, потому что
snapshot уже требовал дополнительно 99981. Исходный ввод и единственный SET
сохранены в ожиданиях; ожидание восстановления не заменено вечным unknown.

В resume_exemplar_document_check два setdefault заменены на get с пропуском
неизвестного product_id и обновлением только известного exemplar_id. Это
не фильтрация доказательства перед классификацией: classify_document_status
получает полный raw и сохраняет его как last_status до обновления snapshot.
Поэтому чужая подмена не подтверждает отсутствующий целевой экземпляр, а
последующий правильный STATUS может закрыть именно прежний запрос.

Существующие экземпляры, отсутствующие в частичном ответе, остаются в snapshot.
F4-R по-прежнему требует, чтобы весь ожидаемый состав присутствовал в свежем
last_status; старые данные не превращаются в свежее принятие. Пропущенные
поля известных экземпляров сохраняются через update, включая сведения,
которые STATUS не возвращает. Выбор оператора, состояние writer, checkpoint,
версии, tenant/posting checks и пути SET не менялись. Следующая явная запись
по-прежнему получает свежий полный snapshot существующим путём.
