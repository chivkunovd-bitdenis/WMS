## F3 / P2: целая числовая цена сверх лимита Python отклоняет здорового соседа

Место: `backend/app/services/wb_sales_report.py:347–349`.
Исправление сохраняет лексемы дробных/экспоненциальных чисел через `parse_float=str`,
но целые JSON-числа всё ещё преобразуются стандартным `int`. Значение
`finishedPrice`, состоящее из 5000 цифр `9` без кавычек, — синтаксически корректное
JSON-число. На используемом Python его преобразование превышает предел количества
цифр и вызывает ValueError. Обработчик превращает это в
`wb_sales_incomplete_json` для всей страницы до проверки конкретного item.

Независимое воспроизведение использовало существующий публичный API-контракт F2,
заменив только значение числового контрпримера в памяти процесса: экспоненту
`1e9999999999999999999` на целое из 5000 девяток. Ни файл теста, ни ожидания,
ни параметры single/healthy-neighbor и exception-trace/http-status не менялись.
**4 failed, 6 warnings, 2.49s: во всех четырёх случаях HTTP 409 вместо 200.**
Оба mixed-варианта останавливаются до штатного частичного результата: здоровый
сосед с ценой 12.34 не получает ожидаемую подготовку. Это уже не HTTP 500 и не
повтор прежнего Decimal InvalidOperation; это оставшаяся потеря независимости
строк на той же границе разбора цены. Реальное получение такого числа от WB
не утверждается: это синтетическая проверка повреждённой стоимости по R22.

Для исправления нужен независимый контракт до кода для целой числовой лексемы,
с сохранением исходного значения, ошибкой только плохого КИЗ и продолжением
здорового. Следует безопасно обрабатывать также целые числовые лексемы до
предметной проверки цены, учитывая типы остальных полей отчёта. Отказ всей
страницы как будто её JSON синтаксически испорчен не выполняет R22.

## Что прошло повторную проверку

**F1 / R19 закрыт в проверенном сценарии.** Общий срок и новая generation
(метка изменения ограничения) записываются одной Lua-операцией Redis. Уже
ожидающий caller сверяет метку после сна; при изменении снова атомарно резервирует
отдельное время. Чтение метки до резервирования допускает лишнее безопасное
перерезервирование при гонке, но не отменяет общий срок. Повторный defer не
уменьшает срок, и этот путь не повторяет HTTP-запрос, получивший 429.

Дополнительно выполнен независимый probe через настоящий `read_sales_report`
и httpx.MockTransport с виртуальными часами. A входит в HTTP на 0; B/C/D уже
спят до 61/122/183; A получает 429/Retry-After:120. Затем часы последовательно
переводятся к следующему пробуждению. Проверены четыре комбинации: общий fake
Redis / локальный режим, один defer / повторный такой же defer.
**Все четыре PASS: A=0, B=244, C=305, D=366 секунд.** Ровно четыре HTTP-обращения,
у A явная ошибка, у B/C/D завершённый пустой отчёт; разрывы ровно 61 секунда,
скрытого повтора A нет. Продуктовые функции не подменялись; подменялись часы,
Redis I/O, credentials fixture и HTTP-транспорт. Существующие тесты на диске
не дописывались. Это полная трёх-waiter HTTP-симуляция с fake Redis, не доказательство
трёх HTTP-callers на настоящем Redis.

По коду production без общего broker по-прежнему отказывает до HTTP; локальный
fallback доступен лишь вне production. Серия heartbeat сохраняется при каждом
ожидании; нового DB lock или изменения lease ownership в дельте нет.
Нативный Lua smoke разработчика с тремя перенесёнными резервированиями и
интервалами 61s прочитан в handoff; здесь заново не запускался и не выдаётся
за собственный прогон. Предыдущие проверки leases/core остаются evidence
предыдущего ревью, без выдуманного полного повторного прогона.

**Прежний F2 закрыт для исходной экспоненциальной цены.** Сырой числовой exponent
не создаёт Decimal при чтении страницы; исходная лексема остаётся в evidence,
ошибка создаётся только по плохому item, здоровый получает ровно 1234 копейки.
Публичные проверки с распространением исключений и с обычным HTTP-ответом
проходят. Точная стоимость продолжает проверяться без float и округления
дробной копейки. Прежний mixed return/healthy путь также прошёл целевую серию.

**R21, текстовая дельта:** единственная изменённая подпись честно говорит о
проданных FBS-заказах WB и сохраняет период по дате передачи. Разметка и
управление не меняются. Браузерная/операторская приёмка здесь не выполнялась.
