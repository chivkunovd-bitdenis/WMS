# Батч 04. Карта процесса сортировки и размещения по ячейкам

## Граница батча

Проверяется только работа сотрудника фулфилмента после завершённой приёмки: очередь «Сортировка» → доказательство exact документа и склада → выбор или скан адресной ячейки → частичная раскладка → сохранение/применение → восстановление после ошибки, reload, Back/Cancel и повторного действия → полное размещение → исчезновение документа из очереди и появление доступного остатка в ячейках. Приёмка B03 не повторяется, остатки/движения вне контрольного read-back относятся к B05, упаковка и отгрузка не начинаются.

Входной fixture: request `41823675-2b08-4714-97b6-8782486c4dda`, №`000007`, seller `B01 UX Seller 960724`, статус `sorting`, A=`3`, B=`2`, всего `5`, коробов `0`, stock только в зоне Sorting `3/2`, available=`0`. Любая мутация запрещена, пока эти признаки и целевой synthetic склад/ячейки не доказаны визуально.

## Физический процесс и роли

| Момент | Кто и где физически | Что у сотрудника в руках/голове | Что должна дать система | Выход шага |
|---|---|---|---|---|
| Получение задания | Сортировщик у стола/тележки с пятью принятыми единицами | Номер поставки/селлер, два SKU, количество 3/2 | Однозначная строка с номером, seller, складом и остатком | Открыт exact документ, чужой товар не затронут |
| Подготовка адреса | Сортировщик стоит перед складом/рядом ячеек | Код или штрихкод целевой ячейки | Точный склад, доступные ячейки, возможность сканировать адрес без мыши | Выбрана ячейка того же склада |
| Идентификация товара | В одной руке товар, в другой сканер | ШК товара или видимый SKU | Контекст текущего товара и +1/количество без повторного поиска строки | Товар связан с адресом и количеством |
| Частичная раскладка | Тележка физически идёт к одной или нескольким ячейкам | Сколько уже положено и сколько осталось | Прогресс по SKU и общий остаток после каждой проводки | Разложенная часть доступна, остаток остаётся в Sorting |
| Исправление | Ошибка ячейки/количества, повторный scan/click, reload | Нужно быстро понять, что реально проведено | Конкретная ошибка, отсутствие двойной проводки, server read-back и простой recovery | Нет потери/дублирования stock |
| Завершение | Последняя физическая единица положена в ячейку | Должно быть A=3/B=2, остаток Sorting=0 | Явный итог, один CTA, понятное последствие и следующий шаг | Документ закрыт, stock в ячейках, available=5 |
| Контроль | Старший смены сверяет систему с полкой | Exact SKU и целевые ячейки | Быстрый read-back на 1280/1920 без ручного сложения | Сохранность 3+2=5 доказана |

## Твёрдые продуктовые правила

1. Exact документ доказывается номером `000007`, seller, двумя SKU A/B, accepted `3/2`, remaining `5`; порядок строки не считается доказательством.
2. До первой проводки доказываются exact warehouse и synthetic ячейки. Чужие tenant, seller, склад и production-похожие ячейки не используются.
3. UI обязан удерживать контекст «какой товар → какая ячейка → сколько» без скрытого правила и без постоянных переключений scanner/keyboard/mouse.
4. Штрихкод ячейки и товара должен быть естественным основным путём склада. Если экран поддерживает только dropdown/manual, это фиксируется как отсутствующий operational path, а не выдаётся за PASS сканирования.
5. Unknown/invalid/wrong-warehouse/sorting-buffer destination не должны создавать черновик или движение. Если соответствующий ввод недоступен в UI, ставится `N/A` или `FAIL_UX` с точной причиной, без прямой подмены UI API-вызовом.
6. Количество — только целое `>0`, не больше доступного остатка товара/источника. Blank, zero, negative, decimal и overage должны объясняться до mutation.
7. «Сохранить» и «Применить раскладку» должны отличаться по смыслу. Сотрудник обязан понимать, переместился ли stock физически/учётно или сохранился лишь черновик.
8. Частичное применение допустимо только если UI явно показывает A/B posted/remaining, общий remaining и продолжение работы после reload.
9. Repeat/double-click не должен повторно проводить stock. После любой проводки проверяется reload/read-back.
10. Back/Close/Cancel/reload не должны оставлять неясное смешение сохранённого и несохранённого. Recovery не требует догадок или ручной сверки нескольких экранов.
11. Полное завершение означает Sorting=`0`, cells=`3/2`, available=`3/2`, total=`3/2`; сумма товара до и после остаётся `5`.
12. Нельзя начинать B05, упаковку, FBS, MP-отгрузку, WB sync или любые действия с ключами/секретами.

## Инвентарь UI и действий

- `/app/ff/sorting`: populated queue, точная строка, статус, seller, line count, remaining total, даты, keyboard reachability, reload.
- Sorting document: process title, human number, plan boxes, plan date, status, primary CTA, print/close, exact product identity, accepted/distributed/remaining summary.
- Product putaway card: source, destination cell selector/scan affordance, quantity, add/remove row, split across cells, validation states.
- Draft controls: `Сохранить`, `Применить раскладку`, различие результата, reload и повторное открытие.
- Error/recovery: blank/zero/negative/decimal/overage qty; missing cell; unknown/wrong/sorting-zone cell where UI affords it; repeated apply; double-click; Close/Back/reload with dirty draft.
- `/app/catalog` («Ячейки»): exact warehouse selection, synthetic cell code/barcode proof, no cross-warehouse destination leakage; print reachability only if safe and relevant.
- `/app/ff/products`: exact A/B stock read-back for Sorting/cells/available; 1280 and honest 1920 when full row does not fit.

## AS-IS event-count protocol

Для каждого фактического happy path считаются отдельно:

- mouse clicks/taps;
- keyboard input/Enter;
- scanner events, если UI действительно их принимает;
- смены точки внимания между физическим товаром, экраном, scanner, keyboard и mouse;
- решения, которые сотрудник вынужден принять без явного правила на экране.

Минимальный идеальный flow формулируется в пределах текущих экранов и сущностей: открыть exact документ → сканировать адрес → сканировать/подтвердить товар/количество → увидеть немедленный прогресс → повторить → завершить. Новый workflow engine, отдельный wizard, новый design system и тотальный редизайн не предлагаются.

## Stop boundary

Если exact request уже не `sorting`, remaining не `5`, stock не `3/2` только в Sorting либо synthetic warehouse/cells нельзя доказать, мутации прекращаются и batch получает `BLOCKED_FIXTURE`. Любой визуально не открытый screen/action получает `NOT_RUN`; отсутствие scan control не компенсируется скрытым API-вызовом.
