# Ночной выпуск 06.10.2026 — разрешение и обязательные ворота

## Источник решения

Прямая формулировка владельца в текущем чате:

> «Ну окей, давай дожмем все эти задачи, в чем проблема? за ночь дожмем всё это.»

06.10.2026 ведущий дополнительно передал действующее решение владельца: к 06:00
по Asia/Tbilisi выпустить готовую часть текущего пакета, не ожидая незавершённые
задачи. Предыдущее ограничение на merge и production deploy этим решением снято.
Эта вторая формулировка сохранена как переданный координатором handoff, а не как
самостоятельно восстановленная дословная цитата владельца.

## Обязательные границы выпуска

1. В кандидат входят только задачи с принятой реализацией и полным зелёным CI
   точного итогового SHA. Макеты и незавершённые задачи исключаются.
2. Перед merge кандидат проходит staging-сценарии и независимое строгое ревью
   Astra high. Дополнительно владелец потребовал Cloud Opus review по CI; локальный
   Claude CLI не считается выполнением этого требования.
3. Особо проверить, что кандидат не ломает остатки FBS, непрерывную печать и
   основные складские сценарии. Код, CI, staging, deploy и production-проверка —
   отдельные доказательства.
4. WMS-670 (PR #372; ошибочно опубликована как WMS-666) критична для пакета.
   Номер исправляется новым коммитом без переписывания истории, затем нужен новый
   полный CI точного SHA.
5. Production deploy выполняется только после merge готового кандидата в
   `etalon`. Незавершённые задачи не задерживают готовую часть и не попадают в неё.

## Текущий технический путь production

Действующий путь задают `.github/workflows/deploy.yml` и
`scripts/deploy/prod-update.sh`: ручной workflow `Deploy Production` подключается
к VPS, сервер получает `origin/etalon`, проверяет принадлежность deploy SHA этому
стволу, последовательно собирает сервисы, запускает миграции отдельным сервисом,
поднимает API, Celery worker/beat и web, после чего workflow проверяет HTTP 200 на
`/`, `/seller/` и `/api/health`.

Файл `docs/DEPLOY_SERVER_RU.md` содержит устаревшие детали о миграциях через
Celery worker и обязательном WB re-sync. Текущий скрипт является источником истины:
WB re-sync из обычной выкладки удалён и допускается только как отдельная ручная
операция под наблюдением.

## Нерешённая инфраструктурная граница

На момент записи в активных GitHub Actions репозитория нет workflow для Cloud
Opus review: доступны CI, Deploy Production и workflow сборки/проб. Локальная
настройка support-agent `review=opus` относится к CLI-контуру и не удовлетворяет
запрету владельца на локальный Claude CLI. До появления или точного указания
действующего Cloud Opus workflow этот обязательный ворот нельзя считать пройденным.
