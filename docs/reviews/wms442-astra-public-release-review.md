## F9 · P2 · Добавление tags отключило прежние branch-push сборки

В `.github/workflows/print-agent-package.yml:4–9` добавлен только `push.tags: ['wms-print-v*']`; `branches` отсутствует. Ранее любое изменение `tools/print-agent/**` в обычной ветке автоматически запускало Windows/macOS тесты и сборки. После изменения такой branch push больше не запускает этот workflow. `paths` этого не исправляет. [GitHub документирует](https://docs.github.com/en/actions/reference/workflows-and-actions/workflow-syntax#onpushbranchestagsbranches-ignoretags-ignore), что указание только tags исключает события неопределённого типа refs; для tag push paths вообще не вычисляется.

Это регресс существующего CI-пути, не просьба о новом обязательном наборе тестов. Зелёный tag run34777407261 доказывает tag-путь и не восстанавливает branch-путь. Исправление: сохранить прежнюю область branch triggers, добавив отдельно нужные теги; публикация по-прежнему должна быть только для release-тега. Проверка: относящийся к print-agent branch push запускает две сборки без publish, tag запускает сборки и publish, посторонний branch diff сохраняет прежний paths-фильтр.

## F10 · P2 · Повторная публикация удаляет доступные пакеты до безопасного завершения

Строки81–82 при существующем release без сверки выполняют `gh release upload ... --clobber`. [Контракт GitHub CLI](https://cli.github.com/manual/gh_release_upload): старые assets удаляются до загрузки, при ошибке загрузки они теряются. Поэтому обычный повтор workflow способен лишить существующий пользовательский URL пакета/контрольных сумм или оставить частично заменённый набор. Ветви сохранения/восстановления прежних файлов нет. Это нарушает устойчивость предоставленного пути загрузки при повторе; не требуется строить новую систему релизов.

Точный publish-shell из текущего YAML выполнен локально с подменённым gh, моделирующим документированный delete-before-upload. На existing_success вызван clobber; на existing_upload_failure shell завершился1 после удаления первого уже опубликованного файла, остальные остались прежними. [Результат пробы](artifacts/wms442-public-release-review/publish-probe-results.json). Это модель границы CLI с реальным shell workflow, не причинение сбоя настоящему GitHub. Сам факт delete-before-upload подтверждён официальным контрактом; существующий публичный release не повреждался.

Исправление: повтор должен сверять и сохранять уже опубликованный согласованный набор; не удалять рабочие файлы ради повторной отправки того же выпуска. Для отличающегося набора нужен явный отказ/новый выпуск вместо тихой замены; восстановление отсутствующих файлов должно учитывать совпадение source/checksums. Способ реализации выбирает исполнитель, без новых пользовательских экранов. Проверить существующий полный выпуск, неполный выпуск, несовпадение и ошибку upload; после отказа прежние файлы доступны и согласованы. Не трогать текущие реальные assets ради отрицательного теста.
