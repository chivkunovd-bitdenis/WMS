# WMS-375 / A29 — отказ после создания пустого короба

06.09.2026. Проверяемый код: `2bca33913df601db655ff7bb94914cc18fb4ce22`.
`inventory_count_service.py` и `warehouse_map_service.py` не изменялись;
diff этих файлов относительно указанного коммита пуст до и после опыта.
Production, внешние API и реальные данные не использовались.

**Подтверждён ограниченный эффект:** после ошибки остаётся пустой физический
короб без связи с документом; повтор создания заводит второй короб. Первый
доступен обычному скану и может быть использован в том же документе. Потери
товара, движения остатков или начисления этим опытом не установлены.

## Один локальный опыт

Использовались существующие API и сервисы через ASGI-клиент, тестовые
регистрация/склад/товар и отдельная SQLite-база
`scratchpad/wms375_a29_probe.sqlite`, заданная через `WMS_TEST_DATABASE_URL`.
Создан черновик инвентаризации с физическим остатком 3 штуки. Рабочий браузер
и PostgreSQL-конкурентность в этот опыт не входили.

Точка отказа установлена обёрткой **после возврата настоящей**
`warehouse_map_service.create_sorting_object`: её `commit` уже выполнен,
а `InventoryCountCreatedContainer` вызывающий сервис ещё не добавил.

```python
async def fail_after_box_commit(*args, **kwargs):
    result = await actual_create_sorting_object(*args, **kwargs)
    captured.append(result["id"])
    raise RuntimeError("A29 injected after container commit, before document link")
```

Это моделирует отказ между двумя записями; сами `commit` не подменялись.
Результат хранения проверялся отдельной сессией базы после исключения.

| Шаг | Прочитанный результат |
|---|---|
| Ошибка при `POST /operations/inventory-counts/{id}/containers`, `kind=box` | 1 короб, 0 связей с документом; физический остаток 3, движений 0. |
| Повторное чтение документа | Короб отсутствует в основном дереве, присутствует в `scannable_containers`. |
| Повтор исходного POST после снятия отказа | HTTP 200; теперь 2 разных короба и 1 связь. Первый ID не переиспользован; второй короб виден в дереве. |
| Обычный `POST /operations/inventory-counts/{id}/found` с кодом тестового товара и ID первого короба | HTTP 200; первый короб появился в дереве документа. Это строка находки в черновике, физический остаток остаётся 3, движений 0. |

Точный итог единственного прогона: **1 passed, 5 warnings in 1.10s**.
Предупреждения — существующие DeprecationWarning библиотеки Swig.

```json
{
  "after_failure": {"boxes": 1, "document_links": 0, "tree_visible": false, "scannable": true},
  "after_retry": {"boxes": 2, "document_links": 1, "original_reused": false},
  "after_found_scan": {"original_tree_visible": true, "physical_stock": 3, "movements": 0}
}
```

Одноразовый тест выполнялся как `backend/tests/test_wms375_a29_probe.py`;
после опыта перемещён в игнорируемый `scratchpad/test_wms375_a29_probe.py`,
чтобы не менять замороженный набор релиза. Исходник опыта сохранён рядом как `a29_probe.py`; он не входит в
автоматический набор тестов. Постоянное доказательство — этот протокол и исходник. Временный тест использовал фикстуры `test_inventory_counts` и штатный
изолированный жизненный цикл тестовой базы; общий набор не запускался.

## Граница вывода

Создание короба и связь с документом действительно не атомарны, повтор не
восстанавливает связь первого короба автоматически. При этом первый короб
не исчезает и не блокирует продолжение: он остаётся сканируемой пустой тарой,
а найденный в нём товар можно зарегистрировать обычным действием документа.
Пустые короба сами по себе не являются ошибкой принятой модели хранения.
Этот опыт не доказывает production-инцидент, потерю товара или финансовый
ущерб и не проверяет одновременное проведение документа другим оператором.
Исправления application-кода в рамках A29 не вносились.


## Исправление после опыта

Создание тары из документа теперь передаёт commit=False в существующую
операцию; палета использует уже имевшийся параметр commit, короб/грузоместо
остаются после flush. Тара и InventoryCountCreatedContainer сохраняются
одним финальным commit документа. Остальные вызовы по умолчанию сохраняют
прежнее поведение. Новых таблиц, статусов или условий для оператора нет.

Один адресный прогон:5passed за3.11с. Для box/cargo_place/pallet искусственный
отказ до связи оставляет0тары/0связей; обычный повтор —1тара/1связь. Проверены
также прежняя видимость нового короба и запрет менять проведённый документ.
Ruff прошёл, root mypy двух сервисов прошёл. Исходник регрессии находится
в backend/tests/test_inventory_counts.py. Ожидает отдельного CI и выкладки.
