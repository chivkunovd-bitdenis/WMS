model_reasoning_effort=high. Не исправлять код, не запускать тесты/деплой,

Владелец заказал два независимых перекрёстных Opus-ревью всего боевого выпуска,
затем твой отдельный арбитраж и заключительную сводку оркестратора. Ты получаешь
оба отчёта одновременно после завершения обоих; ни одному ревьюеру не передавали
находки другого до его финального ответа.

## Дополнительные требования к полноте и точности арбитража

В дополнении первого обзора остались отказы читать финансовые/инвентаризационные
экраны под аргументом «UI не влияет на деньги/остатки». Такой аргумент неверен:
экран определяет payload, доступные действия и отображаемый результат. Проверь
по обоим документам карту покрытия. Если второй тоже оставил эти изменённые
пути без чтения, закрой пробел сам по diff и точкам вызова: FfBillingInvoiceCreate,
FfBillingScreen, FfBillingSellerDetails, FfBillingTariffMatrixPanel, FfStoragePage,
FfInventoryCountScreen/InventoryCountDialog/InventoryTree/foundQueue,
FfPackagingPage, FbsSupplyHistoryDialog, SellerSettingsScreen, печатные utils,
fbs_print_asset_service/storage, billing_tariff_matrix_service,
operation_fact_service, сервисы catalogue/provider. generatedOpenAPI/документы
можно классифицировать отдельно, но работающие формы не исключать из review.

Перепроверь текст первичных отчётов буквально: есть заголовки P2/P3, под которыми
сам автор пишет «не находка»/«безопасно»/«активатор отсутствует». Это не доказанные
дефекты production. В R1-A3/A4 не перепутать row lock, transaction advisory и
session advisory lock на отдельном соединении: commit не освобождает все виды
блокировок одинаково. R1-A6 утверждает «следующий опрос дошлёт хвост» — докажи,
есть ли cursor/checkpoint либо повтор снова остановится на той же плохой строке.
В R1.A2 утверждается «ozon_live выключен в проде», что противоречит свежему
наблюдению в BRIEF/ORCHESTRATOR_EVIDENCE: false по умолчанию не значит false в
работающем процессе. Не переноси это утверждение в итоговый вердикт.

Рекомендации добавить таблицу/поле/массив должны быть обоснованы существующими
полями и разрешением владельца, а не просто понравившимся вариантом. Сейчас
только ревью, ни одной такой правки не выполнять.
