# WMS-517 — контракт тестов F3 до исправления продукта

Независимый TESTWRITER, 06.10.2026. Основание: F3/R22 из
`docs/reviews/wms517-astra-997be6e.md`. Проверенный HEAD до тестового коммита:
`b05b4838488513a286cc3c1d853db82fabc88550`; продуктовый SHA:
`997be6ebbf2e8cd9429505b2d6090b6b3372f3c4`. После него до данного запуска
добавлен только отчёт ревью. Продуктовые файлы не изменялись.

Новый файл `backend/tests/test_wms517_raw_integer_price.py` сохраняет публичную
HTTP-проверку существующего `test_wms517_raw_numeric_price.py`, но передаёт
`finishedPrice` как целое JSON-число из 5000 девяток **без кавычек**.
Число строится в памяти одной строкой; огромного файла-фикстуры нет.
Меняются только байты fake HTTP-ответа WB; производственный парсер, подготовка
операции и публичный API работают без подмены. Реальные credentials не нужны.

Контракт содержит ровно четыре случая: single / healthy-neighbor, каждый с
`raise_app_exceptions=True` и `False`. Ожидается HTTP 200 и
`invalid_sale_price` только у плохой позиции. В БД плохая позиция должна быть
`failed`, без цены и документа, с исходной 5000-значной лексемой в evidence;
здоровая должна остаться `pending` с ценой ровно 1234 копейки. Выбранные позиции
не теряются. Документов и внешних вызовов отправки не создаётся.

## RED до исправления

Из каталога backend:

```sh
env -u WMS_TEST_DATABASE_URL -u WMS_TEST_DATA_DIR PYTHONDONTWRITEBYTECODE=1 \
  /Users/deniscivkunov/Projects/WMS/backend/.venv/bin/python -m pytest -q \
  tests/test_wms517_raw_integer_price.py --tb=short -p no:cacheprovider
```

Результат: **4 failed, 6 warnings in 3.32s**, exit 1. Все четыре падения —
на проверке публичного HTTP-статуса: **409 вместо 200**, строка 80 нового теста.
Оба mixed-сценария не достигают проверки цены здоровой позиции, поскольку
продукт отклоняет всю страницу. Это ожидаемое RED-доказательство дефекта,
а не успешная приёмка. Ruff нового файла: **All checks passed**.

Контрольный повтор неизменённого `tests/test_wms517_raw_numeric_price.py`
той же командой: **4 passed, 6 warnings in 2.32s**. Существующий
экспоненциальный контракт исправлен; новое падение относится к целым числам.

Использован собственный SQLite из тестового harness с уникальным именем;
`WMS_TEST_DATABASE_URL` и `WMS_TEST_DATA_DIR` удалены только из окружения дочернего
процесса. Общий PostgreSQL 56517, production, Telegram и кабинеты секретов
не затрагивались. Skills и дочерние агенты не использовались.

Отрицательное огромное число не добавлено: для воспроизведённого F3 достаточно
одной ограниченной лексемы из 5000 цифр и четырёх обязательных комбинаций.
Отдельная проверка знака здесь не доказывала бы новую причину сбоя.

## Передача разработчику

Сначала сохранить и опубликовать этот тестовый контракт отдельным коммитом,
затем исправлять продукт. Ожидания и существующие тесты не менять. После
исправления повторить новый файл и существующий raw_numeric_price-контракт,
проверить совместимость прочих числовых полей отчёта. Перекрёстное ревью,
приёмка аналитика, полный CI и деплой данным тестовым этапом не закрываются.
Владение этого этапа ограничено новым тестом и этим новым документом передачи.
