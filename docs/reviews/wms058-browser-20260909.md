# WMS-058: фактическая браузерная проверка staging

09.09.2026, 04:31 МСК, настоящий Google Chrome открыл staging
`https://web-production-9e7c1.up.railway.app`. Скан выбранного складского короба
и товара успешно наполнил МП-короб из точного источника. Второй сценарий
разместил уже подобранную единицу без повторного складского движения.
Учебный документ отменён штатной операцией, Chrome закрыт в finally.

Запуск выполнен только после сообщения root `DEPLOYMENT READY` для полного SHA
`27400e5ff45d4e93eb6afc174f60710f3930abb4`. Root сообщил SUCCESS backend
`227cd159` и web `0f9dfc90`, сравнение 428 Python-файлов без различий и HTTP 200.
Это подтверждение выпуска от root; сам сценарий не читает Railway или файловую
систему контейнера. В браузере использовались настоящие ответы staging `/api`,
без подмены ответов. Локальный код приложения в этом запуске не работал.

## Наблюдавшиеся действия и остатки

В браузере открыт `/ff/mp-shipments?open_mp={id}`, вкладка «Упаковка», раздел
«Короба», кнопка «Наполнить». Штрихкоды введены в существующее поле
`ff-mp-box-add-scan-input` с Enter. После каждого ответа проверялось видимое
значение столбца «В коробах», затем перечитывались API документа, точных
источников, балансов по ячейке/сортировке и движений этого товара.

| Шаг | Выбранный WHB | Соседнее грузоместо | Сортировка | Подобрано / в коробах | Новые движения относительно начала |
| --- | ---: | ---: | ---: | --- | --- |
| До сканов | 37 | 20 | 3 | 0 / 0 | Нет |
| Browser: скан `FBSVID-BOX-03` | 37 | 20 | 3 | 0 / 0 | Нет |
| Browser: первый скан товара | 36 | 20 | 3 | 1 / 1 | Одна строка −1 из ячейки |
| API: предварительно подобрать вторую единицу из того же WHB | 35 | 20 | 3 | 2 / 1 | Всего две строки −1 из ячейки |
| Browser: скан уже подобранного товара | 35 | 20 | 3 | 2 / 2 | Те же две строки, новой нет |

Скан источника вернул `kind=container`, `container_kind=box`, точные ID короба
и ячейки. Видимость чипа с кодом источника проверена браузерным locator.
Первый скан товара изменил только quantity выбранного контейнера 37 → 36.
Все остальные источники `/pick-options` остались прежними.

Для подготовки второго сценария публичный `/{id}/pick/scan` получил barcode
товара, location и явные `container_kind=box/container_id`. Это самостоятельный
подбор второй единицы, он закономерно сделал 36 → 35. Затем диалог наполнения
открыт заново без выбора ячейки, и повторный браузерный скан товара дал видимые
«План 2 / В коробах 2 / Доступно 0». Полные ответы балансов по двум местам
совпали до и после этого скана, как и полный набор ID складских движений товара.
На сохранённом снимке видны количество 2 и уведомление «Добавлено 1 шт».

HTTP 200 получен для всех трёх браузерных сканов. Измерение начинается перед
fill + Enter и заканчивается после видимого результата и двух кадров браузера;
оно включает доставку ввода автоматизацией. HTTP — от создания запроса до
получения полного ответа, то есть сеть вместе с сервером.

| Браузерный скан | До видимого результата, мс | HTTP, мс |
| --- | ---: | ---: |
| Выбор WHB | 375,1 | 292,6 |
| Товар из WHB | 615,6 | 528,8 |
| Уже подобранный товар в короб | 510,8 | 411,5 |

Это отдельные наблюдения малого документа, не нагрузочный тест. Событий
`pageerror` и заблокированных запросов — 0. Сетевой ограничитель разрешал
запись только на перечисленные операции собственного нового MP ID.

## Штатная отмена и граница доказательства

После закрытия Chrome выполнен POST `/{id}/cancel`, затем GET документа
подтвердил `cancelled`. Новая строка движения
`1288a4ac-6aa5-4f94-85d4-1266e5dc42cb` вернула +2 в сортировку. Итоговый GET
балансов показал: `FBS-VIDEO-01` 57 → 55, сортировка 3 → 5, сумма этих двух мест
60 → 60; reserved по обоим местам 0. Отмена не возвращает товар в прежний WHB:
это существующая семантика TASK-019. Ручных перемещений обратно не было.
Точный WHB был перечитан как 35 непосредственно перед отменой; после отмены
читается агрегат ячейки, а не новый container-specific endpoint.

Приёмочный INB в этом живом запуске не проверен: отдельного собственного
сохранённого фикстура в прочитанных отчётах не найдено, чужая приёмка не взята.
Локальные публичные API-тесты INB из отчёта реализации не подменяют эту границу.
Отказ исчерпанного источника, смешанное quantity > 1, целая привязка ready box,
физический ТСД и печать в данном браузерном запуске также не проверялись.
FBS-поставка root и параллельные документы других агентов не изменялись.
