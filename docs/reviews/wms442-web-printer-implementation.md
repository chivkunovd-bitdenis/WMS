# WMS-442 — веб-подключение принтера на карте склада

## Реализация

В контексте уже выбранного склада на карте появился существующего стиля
вторичный action «Принтер». Он открывает один `AppDialog`, а не новый экран.
Диалог всегда читает `GET destination`: показывает фактическую очередь,
платформу, `connection_id` и состояние связи с программой. Пока этот GET не
ответил или вернул ошибку, интерфейс не выдаёт «принтер не назначен» за факт.

Форма кода доступна только администратору. Сначала `pair/preview` показывает
очередь и платформу; изменение кода или смена склада очищает preview. Лишь
после явного «Подключить» вызывается `pair`, затем повторяется GET. При потере
ответа после POST диалог не отправляет второй POST: сверяет `connection_id`
первого preview с фактическим назначением. Если сервер уже показывает другое
подключение, оно остаётся на месте и выводится как актуальное.

У сотрудника приёмки нет поля кода и действий подключения, но есть тот же
прочитанный серверный статус. `online` описан как связь программы, без обещания
выхода бумаги. Опубликованной ссылки на пакет сейчас нет, поэтому интерфейс
прямо говорит об этой границе и не выдаёт фиктивную ссылку.

## Осмотр и проверки

Перед изменением я осмотрел работающий локальный экран «Ячейки → Карта склада»
в отдельном headless Chrome-контексте: светлый фон, панель фильтров, выбранный
склад, строку ячейки с прежней кнопкой печати и группу действий
«Создать ячейку». Снимок `/tmp/wms442-warehouse-map-baseline.png` сравнивался
с результатом. Нативный CUA в момент проверки был заблокирован экраном
блокировки macOS, поэтому это не CUA-проход. После изменения осмотрен
`/tmp/wms442-printer-connected.png` и узкий диалог с длинной очередью
`/tmp/wms442-printer-online-long.png`: действие осталось в той же группе,
строка ячейки и её печать сохранены, названия переносятся без наложения кнопок.

На изолированных fixtures WMS-442 и разрешённом локальном API выполнены:

- C14: пустое назначение, preview синтетического кода с очередью и `darwin`,
  явное назначение и повторное открытие с совпадающими `connection_id` и
  очередью. Ссылку на опубликованный пакет проверить невозможно: такого
  артефакта в контуре нет.
- C15: смена кода убирает preview, закрытие диалога сохраняет прежнее
  назначение, а замена меняет только выбранный склад; после перезагрузки второй
  fixture остался без назначения.
- C16: локальный route пропустил один `pair` на сервер и оборвал ответ.
  Диалог сделал один POST и подтвердил точный `connection_id` повторным GET.
- C17: неверный код дал понятную ошибку; сотрудник с правами приёмки/ячеек
  увидел статус, но не форму кода; искусственный GET 403 показал ошибку прав,
  не ложное «нет принтера».
- C18: перед heartbeat показано состояние без `last_seen_at`; после heartbeat
  показано «Программа на связи. Это не подтверждает выход бумаги». Длинная
  очередь не пересекается с кнопками. Введённый код не оказался в URL или
  `localStorage`.

Старый `last_seen_at`, сетевой отказ preview/pair и физическая бумага этим
checkpoint не проверялись. Они остаются предметом приёмки/физического C13, а
не поводом подменять результат интерфейсным успехом.

## Техническая проверка

После изменения выполнены `npx tsc --noEmit -p tsconfig.app.json` и
`npm run build` из `frontend`; фактический browser walkthrough описан выше.
Это реализация и локальная проверка, не независимое ревью, приёмка или деплой.
