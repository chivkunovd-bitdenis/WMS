# WMS-442 — передача реализации интерфейса ТСД

## Что реализовано

В `mobile.patch` сохранён только исходный код и тесты мобильного контура из
`af969312..217f313`. Патч включает уже принятые в этой ветке изменения WMS-441
и новую WMS-442-печать; он не содержит APK, Gradle-кэша, токенов или файлов
этикеток. Проверка `git apply --check --reverse` для него прошла на мобильном
commit `217f31380f5f7b8af37329a99f7fad5365b80247`.

Экран сортировки теперь получает назначение склада через
`GET /operations/print/warehouses/{warehouse_id}/destination`. Два компактных
действия в самом документе открывают выбор товара или уже доступной ячейки,
затем один и тот же нижний лист подтверждения. В нём показаны объект, его
проверенный штрихкод, WB/Ozon, число копий и назначенная очередь. Отсутствие
штрихкода или назначения объясняется в листе и не меняет цель сканирования,
размещение или завершение документа.

До POST приложение синхронно сохраняет `job_id` и точное тело в защищённом
хранилище с ключом сервера, сотрудника и документа. После перезапуска оно
сначала читает это же задание. Только получив 404, повторяет исходный POST;
новое подтверждённое действие создаёт новый UUID. Состояния очереди выводятся
из сервера буквально: ожидание передачи, приём очередью с квитанцией, отказ
до передачи либо неизвестный результат. При `running` приложение не создаёт
новую печать автоматически.

## Проверки и границы доказательств

Статическая проверка `git diff --check` прошла. В
`SortingViewModelTest` добавлены сценарии сохранения полного тела до POST,
сохранения цели сортировки и восстановления после потерянного ответа через
404 тем же UUID. Gradle, unit-тесты и эмулятор не запускались: Android-ресурс
в момент передачи был занят WMS-445 по прямому ограничению ведущего.

До реализации я прочитал существующую структуру рабочего `SortingScreen.kt`,
общие `ScanScaffold`, `ConfirmSheet`, `QtyInput` и карточки ТСД, а также
зафиксированный аналитиком осмотр веб-эталона ячеек. Самого работающего
экрана ТСД я не видел: эмулятор был недоступен. Поэтому визуальное соответствие
и сценарий C12 пока не подтверждены. На первом свободном эмуляторе нужно
пройти: товар WB и Ozon, ячейку без предварительного скана, отмену/ошибку с
сохранённой целью, loss после POST-commit с перезапуском, и последующее
размещение из WMS-441. Физическая C13 требует отдельного реального ПК и
принтера и этой реализацией не доказана.

## Как продолжить

После освобождения ресурса из `mobile/android` запустить только
`./gradlew testDebugUnitTest` и собрать debug APK с существующими параметрами
WMS-445. Затем на разрешённом эмуляторе выполнить C1–C5, C8 и C12 против
loopback API с отдельными fixtures WMS-442. Не применять мобильный commit к
remote: это отдельный nested Git-контур. Внешний Git-коммит содержит патч и
этот handoff, чтобы работа была восстанавливаемой.
