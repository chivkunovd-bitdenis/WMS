# WMS-665 · Вывод проданных КИЗ AVpack с компьютера Виталия

Четыре кода для пробного запуска найдены. Итоговая цель на 05.10.2026 — не эти
четыре строки, а все 80 КИЗ селлера со статусом WB `sold`. По прямому поручению
владельца WMS получил
реквизиты из штатного WB seller-info и создал отсутствовавший профиль селлера:
«ИП Горячкина Татьяна Ивановна», ИНН `132608771877`. Запись и системное событие
изменения перечитаны из production. Подпись и отправка документа в ЧЗ пока не
выполнялись. Execute помощника только выделяет точные строки и открывает штатное
окно ЭЦП; сертификат и окончательную кнопку выбирает Виталий. Для полного набора
используется отдельный локальный фильтр вкладки: production код не меняется.

## Что нужно на компьютере

Существующий WMS-517 адаптер ожидает CryptoPro CSP не ниже 5.0.13003,
CryptoPro Browser Plug-in не ниже 2.0.15003 и его браузерное расширение.
Это ограничения текущего кода, а не утверждение, что оборудование Виталия проверено.
Нужны драйвер физического токена, установленный личный сертификат с доступным
закрытым ключом и доверенная цепочка сертификатов. Если всё это уже работает для
входа в ЧЗ, переустанавливать без диагностики не требуется. Конкретная ОС и версии
Виталия ещё не известны. Никакой отдельный ключ API ЧЗ помощнику не нужен.

Для dry-run CryptoPro не требуется: помощник не обращается к сертификатам.
Следующие шаги относятся к штатной подписи и выполняются самим Виталием/его
администратором, а не помощником:

1. Узнать ОС и модель токена. Для Windows открыть [официальную страницу плагина CryptoPro](https://cryptopro.ru/products/cades/plugin), скачать подходящий установщик и выполнить его мастер. Производитель предлагает объединённый комплект CSP, плагина и расширения; при уже установленном CSP подобрать совместимый вариант по официальной инструкции. Для macOS использовать отдельную [инструкцию macOS](https://docs.cryptopro.ru/cades/plugin/plugin-installation-macos), не Windows-файл.
2. Перезапустить браузер и включить расширение CryptoPro по [инструкции Windows](https://docs.cryptopro.ru/cades/plugin/plugin-installation-windows) либо macOS. Для этого runbook далее используется Chrome; совместимость другой ОС/браузера с WMS пока не проверялась.
3. Если токен не определяется, установить драйвер именно его производителя. Существующий сертификат должен быть связан с контейнером на токене в личном хранилище текущего пользователя. В Windows это проверяют в CryptoPro CSP, вкладка «Сервис», просмотром сертификатов в контейнере; установку существующего личного сертификата описывает [официальное руководство CSP](https://www.cryptopro.ru/sites/default/files/public/faq/csp/zhtyai.00101-01_92_01._instrukciya_po_ispolzovaniyu._windows.pdf). Новый ключ или сертификат для этой подготовки не выпускается, закрытый ключ не экспортируется.
4. На странице плагина открыть ссылку «диагностическую страницу» и проверить обнаружение плагина/CSP и сертификата. Тестовую подпись выполнять только по отдельному решению владельца ЭЦП; успех диагностики ещё не подтверждает полномочия в ЧЗ или приём документа.

Виталий входит в свой seller-кабинет WMS и выбирает «ИП Горячкина Т.И.», затем
«Честный знак → Вывод из оборота». Период «Передано WB» — 18.09.2026–19.09.2026,
поиск пустой, фильтр товара пустой, «Только не выведенные» включено.
По умолчанию последние семь дней скроют эти сентябрьские заказы. Если строк много,
выбрать 250 строк на странице. Перед помощником снять ранее выбранные галочки.

## macOS: запуск одной командой без DevTools

Виталию передаётся один файл `avpack-sold-kiz.command` из `scripts/ops/`.
Сохранить его в «Загрузки», оставить открытой ровно одну авторизованную вкладку
Chrome `https://sellerfocus.pro/seller/honest-sign/withdrawals` и выполнить в
Терминале одну команду:

```sh
/bin/zsh "$HOME/Downloads/avpack-sold-kiz.command"
```

Файл содержит проверенный помощник всех 80 строк: ничего не скачивает при запуске,
не требует Node/Python и не просит вставлять JavaScript. Если файл получен с правом
исполнения, его можно открыть двойным щелчком; команда выше не зависит от сохранения
этого права при пересылке. Запуск не снимает системные защиты и не меняет настройки.

При первом запуске возможны два штатных разрешения:

- В Chrome: **View → Developer → Allow JavaScript from Apple Events**
  («Вид → Разработчик → Разрешить JavaScript из событий Apple»; название зависит
  от языка). Это [официальное требование Chromium](https://www.chromium.org/developers/applescript/).
- В macOS разрешить Терминалу управлять Chrome в системном запросе. Если ранее
  отказали: **Системные настройки → Конфиденциальность и безопасность → Автоматизация
  → Terminal → Google Chrome**. Порядок описан в [инструкции Apple](https://support.apple.com/en-nz/guide/mac-help/mchl108e1718/mac).

Если разрешения нет, файл остановится и покажет короткую инструкцию. Включить его
нужно один раз вручную, затем повторить ту же команду; скрипт сам разрешения не
выдаёт. Включение разрешения Chrome позволяет локальным приложениям выполнять JS
в открытых страницах, поэтому после работы его можно снова выключить.

Успешный запуск заканчивается штатным окном выбора ЭЦП для 80 строк. Launcher
выбирает найденную вкладку и выводит её окно Chrome поверх Терминала.
Виталий сам выбирает сертификат и нажимает
«Подписать и отправить». Launcher не подписывает и
не отправляет документ. При ошибке или таймауте автоматического повтора нет:
проверить экран, а перед новой подготовкой перезагрузить вкладку. При потерянном
ответе уже начатой отправки действуют правила восстановления существующей операции
ниже — повторную операцию не создавать.

Реальная автоматизация Chrome и разрешения на компьютере Виталия пока не проверены.
Ни установка launcher, ни сообщение об открытом окне не подтверждают принятие ЧЗ.

## Ручной технический запуск помощника (не требуется Виталию на macOS)

Файл `scripts/ops/avpack-kiz-helper.js` предназначен для DevTools Snippet на
открытой странице WMS. Сохранить его как локальный snippet и выполнить определение;
само определение не запускает действия. Не вставлять в snippet пароли, PIN или ключи.

В Chrome открыть меню ⋮ → «Дополнительные инструменты» → «Инструменты разработчика».
В панели выбрать **Sources → Snippets** (раздел может быть спрятан за `»`), нажать
**New snippet**, назвать его `WMS-665`, вставить полный текст полученного файла
и сохранить Ctrl+S (на macOS Cmd+S). Затем нажать кнопку запуска внизу редактора
либо Ctrl+Enter (Cmd+Enter на macOS). Это только определит `AvpackKizHelper`.
Во вкладке **Console** выполнить одну из коротких команд ниже; в результате
раскрыть `verifiedTargets` и `status`. После перезагрузки страницы определение
snippet нужно запустить повторно. Порядок подтверждён [документацией Chrome](https://developer.chrome.com/docs/devtools/javascript/snippets).

```js
await AvpackKizHelper.createHelper().run({ mode: 'dry-run' })
```

По умолчанию проверяется только первый заказ 5803306927 — для первого пробного
вывода одного КИЗ. Dry-run сверяет аккаунт и текущие строки через GET, ничего не
подписывает, не отправляет и не выделяет. Для проверки всех четырёх:

```js
await AvpackKizHelper.createHelper().run({
  mode: 'dry-run',
  orderIds: ['5803306927', '5800165076', '5807803330', '5809136493']
})
```

Для выделения всех четырёх КИЗ и открытия окна выбора сертификата:

```js
await AvpackKizHelper.createHelper().run({
  mode: 'execute',
  orderIds: ['5803306927', '5800165076', '5807803330', '5809136493']
})
```

Execute заново сверяет tenant, seller, права, полный CIS, row id, заказ, статус и
отсутствие активной операции. Затем он проверяет, что на экране ничего не выбрано,
ставит галочки только на указанных строках и открывает существующий диалог
«Выберите сертификат». Помощник не делает POST, не выбирает сертификат, не
подписывает и не нажимает «Подписать и отправить».

### Полный запуск для всех 80 WB sold КИЗ

Для сегодняшней полной операции вместо четырёхстрочного помощника использовать
`scripts/ops/avpack-sold-kiz-filter.js`. Установить его отдельным DevTools Snippet
тем же способом. Сам запуск snippet только определяет `AvpackSoldKizFilter`.

Сначала выполнить безопасную проверку:

```js
await AvpackSoldKizFilter.createHelper().run({ mode: 'dry-run' })
```

Ожидаемый результат: `status: "ready"`, `targetCount: 80`, `noSend: true`.
Если число другое или показана ошибка, execute не запускать. Затем:

```js
await AvpackSoldKizFilter.createHelper().run({ mode: 'execute' })
```

Скрипт повторно проверяет точный AVpack tenant/seller и все 80 `row_id` в текущем
реестре. После этого он временно подменяет **только GET списка** в данной вкладке,
обновляет штатный экран, выбирает все 80 и открывает обычный диалог сертификата.
POST и URL операций проходят без изменений в существующий WMS-517. Полные КИЗы
в файле не хранятся. После перезагрузки вкладки локальный фильтр исчезает.

До открытия диалога основной экран должен показать «Выбрано КИЗ: 80». В самом
диалоге Виталий проверяет владельца/ИНН/срок сертификата и только затем нажимает штатную кнопку.
Сам помощник не создаёт операцию, не подписывает и не отправляет документ.

## Сертификат и результат

Штатный интерфейс показывает сертификаты личного хранилища текущего пользователя,
срок которых ещё действует и для которых доступен закрытый ключ. Виталий выбирает
сертификат нужного участника ЧЗ, проверяет владельца, ИНН, срок и отпечаток.
Адаптер затем находит ровно этот сертификат по SHA-1 отпечатку, проверяет его срок,
цепочку и наличие ключа; ключ остаётся на компьютере/токене. PIN вводится только
в родном окне CryptoPro. Если ЭЦП представителя, его полномочия в ЧЗ должны уже
быть оформлены; помощник не настраивает их и не утверждает их наличие.

После ручного нажатия Виталием «Подписать и отправить» штатный процесс работает так:

1. WMS создаёт одну идемпотентную операцию по выбранным row id и берёт ИНН
   `132608771877` из профиля селлера.
2. Backend получает в True API challenge авторизации. CryptoPro на компьютере
   Виталия подписывает challenge attached CAdES-BES; закрытый ключ не покидает токен.
3. Backend передаёт подпись авторизации в True API, получает сессионный токен,
   проверяет КИ, статус, товарную группу, стоимость и строит точные документы.
4. Браузер проверяет SHA-256 полученных байтов, после чего CryptoPro подписывает
   каждый документ detached CAdES-BES тем же сертификатом.
5. В backend уходят только подписи и отпечаток сертификата. Backend отправляет
   документ типа `LK_RECEIPT` с причиной `DISTANCE` в ЧЗ и сохраняет внешний
   идентификатор для последующей сверки статуса.

Если сервер отключил production-отправку или доступ селлера, помощник не обходит
запрет. При неизвестном результате повторно новый документ не создаётся.

05.10.2026 отдельно прочитаны три несекретные настройки работающего backend:
`withdrawal_environment=production`, `withdrawal_production_submit_enabled=True`,
`withdrawal_allowed(Горячкина)=True`. На момент проверки эти выключатели не
блокировали процесс; настройки не менялись.

Перед пробной отправкой Виталий сверяет четыре выбранные строки; перед полной —
счётчик 80 и правильный сертификат. Нажатие «Подписать и отправить» запускает существующий
WMS-517 процесс; помощник этого действия не выполняет.

При потере ответа или статусе «Передаётся»/«Ожидает ЧЗ» не создавать новый документ.
Продолжать проверку той же операции через штатный экран. Успех — статус вывода,
подтверждённый ЧЗ; открытый диалог, подпись или HTTP-ответ сами по себе не доказывают
окончательное принятие документа.
