# WMS-665 · Пробный вывод КИЗ AVpack с компьютера Виталия

Четыре кода найдены, но вывод сейчас блокирует отсутствие ИНН селлера в профиле
реквизитов WMS. В этой работе ни подпись, ни отправка документа в ЧЗ не выполнялись.
Текущая версия помощника только проверяет строки и показывает блокер;
execute останавливается до открытия окна ЭЦП.

## Что нужно на компьютере

Существующий WMS-517 адаптер ожидает CryptoPro CSP не ниже 5.0.13003,
CryptoPro Browser Plug-in не ниже 2.0.15003 и его браузерное расширение.
Это ограничения текущего кода, а не утверждение, что оборудование Виталия проверено.
Нужны драйвер физического токена, установленный личный сертификат с доступным
закрытым ключом и доверенная цепочка сертификатов. Если всё это уже работает для
входа в ЧЗ, переустанавливать без диагностики не требуется. Конкретная ОС и версии
Виталия ещё не известны. Никакой отдельный ключ API ЧЗ помощнику не нужен.

Для текущего dry-run CryptoPro не требуется: помощник не обращается к сертификатам.
Следующие шаги относятся к будущей штатной подписи после исправления ИНН и выполняются
самим Виталием/его администратором, а не этим скриптом:

1. Узнать ОС и модель токена. Для Windows открыть [официальную страницу плагина CryptoPro](https://cryptopro.ru/products/cades/plugin), скачать подходящий установщик и выполнить его мастер. Производитель предлагает объединённый комплект CSP, плагина и расширения; при уже установленном CSP подобрать совместимый вариант по официальной инструкции. Для macOS использовать отдельную [инструкцию macOS](https://docs.cryptopro.ru/cades/plugin/plugin-installation-macos), не Windows-файл.
2. Перезапустить браузер и включить расширение CryptoPro по [инструкции Windows](https://docs.cryptopro.ru/cades/plugin/plugin-installation-windows) либо macOS. Для этого runbook далее используется Chrome; совместимость другой ОС/браузера с WMS пока не проверялась.
3. Если токен не определяется, установить драйвер именно его производителя. Существующий сертификат должен быть связан с контейнером на токене в личном хранилище текущего пользователя. В Windows это проверяют в CryptoPro CSP, вкладка «Сервис», просмотром сертификатов в контейнере; установку существующего личного сертификата описывает [официальное руководство CSP](https://www.cryptopro.ru/sites/default/files/public/faq/csp/zhtyai.00101-01_92_01._instrukciya_po_ispolzovaniyu._windows.pdf). Новый ключ или сертификат для этой подготовки не выпускается, закрытый ключ не экспортируется.
4. На странице плагина открыть ссылку «диагностическую страницу» и проверить обнаружение плагина/CSP и сертификата. Тестовую подпись выполнять только по отдельному решению владельца ЭЦП; успех диагностики ещё не подтверждает полномочия в ЧЗ или приём документа. После исправления ИНН проверить отсутствие сообщения о неготовности CryptoPro в штатном WMS-диалоге.

Виталий входит в свой seller-кабинет WMS и выбирает «ИП Горячкина Т.И.», затем
«Честный знак → Вывод из оборота». Период «Передано WB» — 18.09.2026–19.09.2026,
поиск пустой, фильтр товара пустой, «Только не выведенные» включено.
По умолчанию последние семь дней скроют эти сентябрьские заказы. Если строк много,
выбрать 250 строк на странице. Перед помощником снять ранее выбранные галочки.

## Запуск помощника

Файл `scripts/ops/avpack-kiz-helper.js` предназначен для DevTools Snippet на
открытой странице WMS. Сохранить его как локальный snippet и выполнить определение;
само определение не запускает действия. Не вставлять в snippet пароли, PIN или ключи.

В Chrome открыть меню ⋮ → «Дополнительные инструменты» → «Инструменты разработчика».
В панели выбрать **Sources → Snippets** (раздел может быть спрятан за `»`), нажать
**New snippet**, назвать его `WMS-665`, вставить полный текст полученного файла
и сохранить Ctrl+S (на macOS Cmd+S). Затем нажать кнопку запуска внизу редактора
либо Ctrl+Enter (Cmd+Enter на macOS). Это только определит `AvpackKizHelper`.
Во вкладке **Console** выполнить одну из коротких команд ниже; в результате
раскрыть `verifiedTargets` и `blocker`. После перезагрузки страницы определение
snippet нужно запустить повторно. Порядок подтверждён [документацией Chrome](https://developer.chrome.com/docs/devtools/javascript/snippets).

```js
await AvpackKizHelper.createHelper().run({ mode: 'dry-run' })
```

По умолчанию проверяется только первый заказ 5803306927 — для первого пробного
вывода одного КИЗ. Dry-run сверяет аккаунт и текущие строки через GET, ничего не
подписывает, не отправляет и не выделяет. Для проверки всех четырёх:

```js
await AvpackKizHelper.createHelper().run({
  mode: 'dry-run',
  orderIds: ['5803306927', '5800165076', '5807803330', '5809136493']
})
```

Проверка запрета исполнения:

```js
await AvpackKizHelper.createHelper().run({ mode: 'execute' })
```

Execute снова проверяет строки и завершает работу с
`seller_billing_inn_missing_or_invalid`, не выделяя код и не открывая диалог.
Dry-run возвращает этот же блокер вместе с результатом проверки строк.
Блокер установлен по production read-only проверке 05.10; текущий seller API
не позволяет читать профиль реквизитов, поэтому помощник не выдаёт его за
свежую проверку. Флага обхода и ручного ввода ИНН нет. Даже после внешнего
исправления профиля эта версия остановится: нужна отдельная повторная проверка
и новая версия помощника. Для проверки другого кода передать его номер в `orderIds`.

## Что требуется исправить перед подписью

SELECT по точным tenant/seller вернул ноль строк `billing_profiles`. Проверена
политика read-only роли: она видит все строки этой таблицы, это не маскировка
результата правами. Функция `participant_inn()` в работающем backend требует
10- или 12-значный ИНН именно из этого профиля.

Минимальный путь: получить правильный ИНН участника «ИП Горячкина Т.И.» из
подтверждённых реквизитов селлера и после отдельного согласия сохранить его
штатным экраном реквизитов фулфилмента. Другой вариант — отдельно изменить
источник ИНН в продукте, если канонические реквизиты уже хранятся в другом месте;
это задача реализации, не настройка этого скрипта. Нельзя подставлять ИНН Виталия
по его имени или сертификату: представитель и владелец КИ могут различаться.
В этой работе реквизиты не искались в кабинетах ключей, не создавались и не менялись.

## Сертификат и результат

Штатный интерфейс показывает сертификаты личного хранилища текущего пользователя,
срок которых ещё действует и для которых доступен закрытый ключ. Виталий выбирает
сертификат нужного участника ЧЗ, проверяет владельца, ИНН, срок и отпечаток.
Адаптер затем находит ровно этот сертификат по SHA-1 отпечатку, проверяет его срок,
цепочку и наличие ключа; ключ остаётся на компьютере/токене. PIN вводится только
в родном окне CryptoPro. Если ЭЦП представителя, его полномочия в ЧЗ должны уже
быть оформлены; помощник не настраивает их и не утверждает их наличие.

Штатный процесс сначала подписывает запрос авторизации (attached CAdES-BES), затем
точные байты документа (detached CAdES-BES), передаёт документ типа LK_RECEIPT
с причиной DISTANCE через backend. Backend проверяет владельца КИ, статус,
товарную группу, стоимость и применимые реквизиты места деятельности.
Если сервер отключил production-отправку или доступ селлера, помощник не обходит запрет.

05.10.2026 отдельно прочитаны три несекретные настройки работающего backend:
`withdrawal_environment=production`, `withdrawal_production_submit_enabled=True`,
`withdrawal_allowed(Горячкина)=True`. На момент проверки эти выключатели не
блокировали процесс; настройки не менялись.

Перед реальной отправкой нужны подтверждение конкретного кода/списка владельцем,
сверка текущего состояния кода в ЧЗ и выбор правильного сертификата самим Виталием.
Текущее поручение разрешает подготовку, но не фактический вывод агентом.

При потере ответа или статусе «Передаётся»/«Ожидает ЧЗ» не создавать новый документ.
Продолжать проверку той же операции через штатный экран. Успех — статус вывода,
подтверждённый ЧЗ; открытый диалог, подпись или HTTP-ответ сами по себе не доказывают
окончательное принятие документа.
