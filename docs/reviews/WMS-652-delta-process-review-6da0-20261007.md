# WMS-652: независимое ревью дельты ef154 → 6da0

**Вердикт: FAIL** для `6da0eb63b143d71d789c25a20ee04e3c49cbf14b`. Проверка границ WMS-684/586 молча пропускает запрещённые изменения, если другая задача стоит первой в заголовке коммита. Это воспроизведено на настоящих изолированных Git-историях, а не установлено поиском строк. Исправлений ревьюер не вносил.

Ревью выполнено в той же независимой сессии Sol 6.1 high. Предыдущий PASS для `ef154664e365644f4ba002c6e8affc5607fae725`, опубликованный в `eefd980e43d4e01639f7cb0fba4c08299844cb65`, сохраняется в его прежних границах. Проверялась только новая накопленная дельта. Код читался из неизменяемых Git-объектов, адресные проверки запускались в собственном detached worktree точного кандидата. Рабочие файлы интегратора не использованы как проверенный код. Актуальные AGENTS сверены с origin/etalon; полные библиотеки owner-cases/failure-cases прочитаны в этой же исходной сессии и сохранены в контексте.

## Блокирующее замечание R1 — P1

В `backend/tests/test_wms684_586_scope_contract.py` переменная `TASK_SUBJECT` принимает только заголовки, начинающиеся с WMS-684 или WMS-586 и заканчивающие последовательность идентификаторов двоеточием. `_wms684_586_task_history`, строки 70–74 кандидата, отбрасывает остальные коммиты. После этого `assert_wms684_586_scope` считает отсутствие обнаруженных путей успешной проверкой. По тому же отфильтрованному списку выполняется сравнение защищённых обработчиков и накладной.

В трёх одинаковых репозиториях после контрактного коммита добавлен один и тот же запрещённый файл `backend/app/models/forbidden.py`. Менялся только заголовок следующего коммита:

| Заголовок | Реальный diff | Обнаруженные пути | Результат защиты |
| --- | --- | --- | --- |
| `WMS-684 WMS-586: forbidden model` | новый файл модели | файл модели | правильно отклонён |
| `WMS-652 WMS-684 WMS-586: forbidden model` | тот же файл | пусто | **молча принят** |
| `WMS-684 WMS-586 forbidden model` | тот же файл | пусто | **молча принят** |

Вторая форма явно относит изменение к обеим задачам. Несколько WMS-идентификаторов допускаются процессом; порядок идентификаторов не меняет принадлежность изменения. Требование двоеточия также отсутствует в общем контракте. Поэтому исправление ошибочного сравнения всей интеграционной ветки не обеспечивает обещанное ограничение собственных изменений задач. Оно может скрыть настоящее добавление модели или изменение защищённого обработчика. Запрещённое продуктовое изменение в самом снимке кандидата этим воспроизведением не утверждается: подтверждён обход охраны.

Для устранения R1 требуется доказать отклонение такого же собственного запрещённого изменения при разных порядках идентификаторов задач и допустимых формах заголовка, сохранив успешный сценарий с чужим коммитом в смешанной ветке. Сужать область защиты или менять требования для прохождения теста нельзя. Исправление должен внести исполнитель; ревьюер его не реализовывал.

Воспроизведение: `python3 docs/evidence/WMS-652/delta-review-6da0-20261007/reproduce_scope.py`. Скрипт извлекает именно проверяемый Git blob. Его нулевой код выхода означает успешное воспроизведение **FAIL**, а не прохождение кандидата. Результаты сохранены в [scope-canaries.json](../evidence/WMS-652/delta-review-6da0-20261007/scope-canaries.json). Четыре существующих теста того же файла прошли и не обнаружили эти два дополнительных сценария. Непубликовавшееся описание интегратора сохранено с исходным SHA-256 в evidence; его положительный пример использует только первую форму заголовка.
