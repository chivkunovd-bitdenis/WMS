Продолжен b3020e8f в wms270-login-and-ports. WIP доверял первому X-Forwarded-For без проверки прокси, считал только завершённые неуспехи (параллельный burst проходил до регистрации), и бесконечно накапливал ключи.

Исправленный ограничитель берёт только ASGI request.client, атомарно занимает попытку перед DB/password work, хранит ограниченное число клиентов и попыток и удаляет истёкшие записи. Успех освобождает только свою попытку, не обнуляет чужие неуспехи и незавершённые проверки. Дублирующий словарь IP/email исключён: при одинаковом лимите общий IP уже строже пары. Настройки остаются существующими WMS_LOGIN_MAX_ATTEMPTS/WMS_LOGIN_WINDOW_SECONDS. Для доверенных proxy необходима проверка серверного ASGI-контура; сырые пользовательские заголовки приложением не разбираются.

Scoped проверки: 32 passed, 1 skipped в семи auth-файлах; после добавления фактического concurrent HTTP сценария — 8 passed в test_wms270_login_rate_limit.py. В HTTP burst из20 запросов только5 дошли до ожидающей проверки пароля, остальные15 получили429. Проверены поддельный XFF, смена email, ограничение памяти/expiry, успешный вход. ruff/mypy PASS (437 файлов). Изоляция состояния limiter между тестами добавлена в conftest, чтобы один сценарий не ограничивал следующий. Полный pytest не запускался.

WMS377 пока не принят: сохранённые loopback binds из WIP не означают закрытие реальных портов. Требуются чтение актуальной reverse-proxy схемы, проверка доверенного client IP, независимое review, CI/deploy и внешняя проверка HTTPS/API/прямых8088/15174. Внешние настройки и секреты не менялись.

## WMS-417: проверка прокси и повторных попыток, 10.09 09:40 МСК

Поэтому host-specific overlay теперь публикует 8088 только на частном bridge,
а не на 0.0.0.0 и не на недоступном внешнему Caddy host-loopback. Перед применением
нужно повторно проверить gateway/subnet. Сеть пока не менялась. Старый seller15174
нужно отдельно убрать после проверки действующего /seller, compose сам по себе
существующий legacy-контейнер не закрывает. У production API/DB/Redis PortBindings
пусты; утверждение об их открытых внешних портах опровергнуто live inspect.

через adapt stdin, конфигурация не применялась. Настоящий HTTP путь после deploy
остаётся отдельной проверкой. Local compose binds DB/Redis/API/web на loopback.
