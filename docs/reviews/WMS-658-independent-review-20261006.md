## F1 · P2 · Аудит может пропустить потерю исходного макета

Места: `backend/app/services/marking_import_audit_service.py:128`, `:211`
и `:67`. Затронуты R6/R11, C22.

Исходный PDF сравнивается с сохранённым кодом только по декодированным
payload (полным значениям DataMatrix). Исходный макет вообще не сравнивается
с `label_artifact_pdf`. Поэтому этикетка, заново созданная до сохранения в
базу, становится эталоном для сравнения с конечным PDF. Это особенно существенно
для рассматриваемого инцидента: найденная цепочка Геруса содержит позднее
создание новых макетов при неизменном полном коде.

Собственный сценарий на SQLite в памяти: исходный PDF `_label_pdf` содержит
артикул `SUPPLIER-ORIGINAL`, размер и DataMatrix; в `label_artifact_pdf`
сохранён другой макет `build_datamatrix_pdf` с тем же полным кодом; конечный
PDF равен этому новому макету. Все PDF реально декодировались, исходный файл
имел корректные размер и SHA-256. Подменена только функция чтения исходного
файла, возвращающая синтетические байты вместо внешнего хранилища.
Результат:

```text
SOURCE_TO_SAVED_LAYOUT_CHANGED True
AUDIT_SOURCE_LAYOUT_SUBSTITUTION {'first_divergence': None, 'evidence_gaps': []}
```

Есть и второй воспроизведённый пропуск в сравнении конечного PDF. Сигнатура
изображения содержит только его положение, без содержимого. Два исходных
макета с разными видимыми артикулами растеризованы в PNG и помещены каждый
в свою PDF-страницу одинакового размера. Исходный и сохранённый PDF одинаковы,
конечный содержит другой артикул; DataMatrix одинаков. Результат:

```text
RASTER_CONTENT_BYTES_DIFFER True
RASTER_LAYOUT_SIGNATURE_EQUAL True
AUDIT_FINAL_IMAGE_SUBSTITUTION {'first_divergence': None, 'evidence_gaps': []}
```

Нужна доказательная проверка всей цепочки исходная этикетка → сохранённый
артефакт → конечная этикетка с учётом допустимого пропорционального масштаба
и выделения этикетки из многостраничного/многоместного PDF. Для изображений
недостаточно сравнения координат. Если конкретный переход нельзя подтвердить,
аудит должен явно вернуть пробел доказательств. Текущий C22 ловит новый макет
только после сохранённого артефакта и с отличающейся структурой PDF, поэтому
его зелёный результат не опровергает эти два сценария.

## F2 · P2 · Backfill не сверяет nmID доказательства с товаром

Место: `backend/app/services/wb_honest_sign_service.py:186`, `:216`;
apply повторно использует этот план в `:295`. Backfill — разовая операция
включения признака у существующих товаров. Затронуты R9/R10, C19/C20.

Соединение таблиц проверяет `Product.wb_nm_id` и колонку
`SellerWildberriesImportedCard.nm_id`, но затем проверяется только наличие
`nmID` внутри `raw_json`. Его равенство идентификатору товара не проверяется.
В отчёт и fingerprint (контрольный отпечаток плана) попадает nmID товара,
поэтому неверный raw nmID скрыт даже в результате dry-run.

Собственный сценарий на SQLite в памяти: у товара и строки imported-card
`nm_id=658001`, а в raw-карточке `nmID=999999`, `subjectID=101`,
`needKiz=true`. Синтетический справочник содержит subject 101. Dry-run
включил товар в `apply`, показал `nmID=658001`, оставил `skipped=[]`.
Apply этого плана завершился успешно:

```text
BACKFILL_MISMATCHED_NMID_APPLY True 1
```

То есть флаг стал true и изменён один товар на основании raw-карточки с
другой идентичностью. Это сценарий несогласованных исходных данных, а не
утверждение, что такая строка найдена в production или создаётся штатным
импортом карточек. R10 требует проверять соответствующий nmID до записи.
Нужно исключать такое доказательство из apply, показывать оба идентификатора
и причину расхождения; изменение raw nmID после dry-run тоже должно
обнаруживаться до первой записи. Текущие C19/C20 не содержат этот случай.

## Что проверено по трём путям и границам

По чтению кода `/import`, `/import/auto`, `/import/assign` вызывают общий
`_try_insert_imported_code`. Новый код и включение флага товара находятся
в одной транзакции. В ручном пути больше нет промежуточного commit через
`_apply_pool_products`; при неуспешной вставке флаг не включается, пустые
пулы удаляются. Исходный `cis_code` сохраняется отдельно от нормализованной
идентичности; SQL fallback сохраняет проверку tenant и окончательное
Python-сравнение. Новых дефектов здесь статически не обнаружено.

Автоматический каталог ограничен точным `tenant_id + seller_id`, фильтра
ЧЗ нет. Оба ручных пути допускают выбранного селлера и существующие общие
строки `seller_id=null`, проверяя tenant и запрещая другой seller.
API селлера использует его effective seller, а не переданный чужой seller.
Поиск по артикулу/размеру/GTIN сохранён; неоднозначность не выбирает товар
догадкой. Ручной каталог фронта снимает только фильтр ЧЗ.

У нового `/imports/{import_id}/result.pdf` проверяются tenant и доступ
к seller для основного и каждого дополнительного импорта. Собственные
прямые вызовы настоящей функции маршрута на БД в памяти дали:

```text
foreign-tenant          404 import_not_found
other-seller            403 forbidden
additional-other-seller 403 forbidden
```

Это проверка функции API и реальных запросов к БД, не HTTP-проверка
аутентификации. Утечки через новый маршрут в этих случаях не обнаружено.

Сервис печати выбирает только коды разрешённых import_batch_id, проверяет
число принятых строк, сохраняет порядок явно переданных code_ids и копии.
CSV/TXT кодируется из полного сохранённого значения. Для PDF обязательный
артефакт не заменяется генерацией; декодирование артефакта сверяется с полным
`cis_code`. Миграции и консервативная проверка происхождения старых смешанных
импортов прочитаны. Назначение остатка PDF повторно разбирает исходные байты
из запроса и сохраняет вырезанный артефакт даже при отказе хранения исходника.
Эти выводы основаны на коде и существующем контракте, зелёный набор повторно
не запускался. Они не доказывают сохранность конкретного исторического макета.

WB включает флаг по `needKiz=true` или официальной связи subject→родитель
«Одежда», не по `kizMarked`/названию товара. Обновление монотонно, сбой
справочника диагностируется без отказа всего импорта. Границы backfill
по tenant/seller есть; корректность raw-доказательства ограничена F2.
