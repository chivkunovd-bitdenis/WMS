### F4 · P2 · Неоднозначность внутри одного PDF исчезает при извлечении

Места: `backend/app/services/marking_import_audit_service.py:149`, `:186`;
вызываемый extractor — `backend/app/services/marking_label_artifact_service.py:871`.
Затронуты доказательство исходного макета R11/C22 и прямое уточнение владельца:
неоднозначные source crops должны оставлять явный пробел доказательств.

Аудит собирает кандидаты исходных макетов по полному `label.cis` и проверяет,
что их сигнатура единственна. Однако штатный extractor удаляет повторы
полного cis в пределах файла **до возвращения областей этикеток**. Для двух
страниц с тем же КИЗом и разными видимыми артикулами аудит получает только
первый макет. Проверка единственности проходит, второй вариант не виден.

Собственное воспроизведение на SQLite в памяти использовало две настоящие
этикетки: одинаковый полный КИЗ, одинаковые рамки 220×220 на листах 600×800,
разные видимые артикулы `SOURCE-ORIGINAL` / `SOURCE-DIFFERENT`. Сохранённый
артефакт и конечный PDF равны первому вырезанному макету. Каждый source
ImportFile имел правильные размер и SHA-256 синтетического файла.
Подменено только чтение внешнего хранилища; decoder, extractor, сигнатуры,
данные БД и audit настоящие. Те же две страницы проверены двумя способами:
как два ImportFile и как один PDF после штатного merge.

```text
AMBIGUOUS_TWO_FILES
  source_codes=2, first_divergence=None,
  evidence_gaps=['source_to_artifact_layout']
TWO_PAGE_SOURCE_DECODED_VS_EXTRACTED 2 1
AMBIGUOUS_TWO_PAGES_ONE_FILE
  source_codes=2, first_divergence=None, evidence_gaps=[]
```

Упаковка одинакового исходного содержимого в один файл меняет вывод аудита
с «неоднозначно» на отсутствие пробелов. Нужно сохранить все исходные
области для проверки доказательств до удаления повторов: разные макеты
одного полного payload должны давать `source_to_artifact_layout` независимо
от числа файлов. Правило удаления повторов при сохранении импортных кодов
может сохраняться; полнота исходного доказательства проверяется отдельно.

Положительные контроли этой диагностики прошли: один однозначный рамочный
источник и два одинаковых источника вернули
`first_divergence=None, evidence_gaps=[]`. Разные макеты между файлами
честно дали пробел. Таким образом, F4 относится именно к потере второго
кандидата внутри одного PDF, а не к любому повтору кода.

### F3 · P2 · Штатно вырезанная этикетка ошибочно считается подменённой

Место: `backend/app/services/marking_import_audit_service.py:220`, `:241`.
Это побочный дефект исправления F1 в непосредственном соседнем пути
R6/R11/C22, не новый бизнес-сценарий.

Условие `source_to_artifact_layout_complete` считает сравнение доказательным,
когда число исходных страниц, декодированных КИЗов и сохранённых страниц
совпадает. Но одна страница с одним КИЗом может содержать этикетку в рамке
и внешние поля. Штатный PDF-парсер сохраняет вырезанную этикетку. Аудит
сравнивает координаты относительно **всей исходной страницы** с координатами
относительно **вырезанной этикетки** и объявляет отличие подменой.

Собственный сценарий: `_label_pdf` 220×220 помещён без изменения масштаба
в рамку `(30,30,250,250)` на странице 600×800. Настоящий
`auto_import_marking_codes` разобрал PDF, сохранил полный КИЗ и артефакт
220×220; настоящий `build_import_result_pdf` подготовил его к печати.

## F1 · P2 · Аудит может пропустить потерю исходного макета

Места: `backend/app/services/marking_import_audit_service.py:128`, `:211`
и `:67`. Затронуты R6/R11, C22.

Исходный PDF сравнивается с сохранённым кодом только по декодированным
payload (полным значениям DataMatrix). Исходный макет вообще не сравнивается
с `label_artifact_pdf`. Поэтому этикетка, заново созданная до сохранения в
базу, становится эталоном для сравнения с конечным PDF. Это особенно существенно
для рассматриваемого инцидента: найденная цепочка Геруса содержит позднее
создание новых макетов при неизменном полном коде.

Собственный сценарий на SQLite в памяти: исходный PDF `_label_pdf` содержит
артикул `SUPPLIER-ORIGINAL`, размер и DataMatrix; в `label_artifact_pdf`
сохранён другой макет `build_datamatrix_pdf` с тем же полным кодом; конечный
PDF равен этому новому макету. Все PDF реально декодировались, исходный файл
имел корректные размер и SHA-256. Подменена только функция чтения исходного
файла, возвращающая синтетические байты вместо внешнего хранилища.
Результат:

```text
SOURCE_TO_SAVED_LAYOUT_CHANGED True
AUDIT_SOURCE_LAYOUT_SUBSTITUTION {'first_divergence': None, 'evidence_gaps': []}
```

Есть и второй воспроизведённый пропуск в сравнении конечного PDF. Сигнатура
изображения содержит только его положение, без содержимого. Два исходных
макета с разными видимыми артикулами растеризованы в PNG и помещены каждый
в свою PDF-страницу одинакового размера. Исходный и сохранённый PDF одинаковы,
конечный содержит другой артикул; DataMatrix одинаков. Результат:

```text
RASTER_CONTENT_BYTES_DIFFER True
RASTER_LAYOUT_SIGNATURE_EQUAL True
AUDIT_FINAL_IMAGE_SUBSTITUTION {'first_divergence': None, 'evidence_gaps': []}
```

Нужна доказательная проверка всей цепочки исходная этикетка → сохранённый
артефакт → конечная этикетка с учётом допустимого пропорционального масштаба
и выделения этикетки из многостраничного/многоместного PDF. Для изображений
недостаточно сравнения координат. Если конкретный переход нельзя подтвердить,
аудит должен явно вернуть пробел доказательств. Текущий C22 ловит новый макет
только после сохранённого артефакта и с отличающейся структурой PDF, поэтому
его зелёный результат не опровергает эти два сценария.

## F2 · P2 · Backfill не сверяет nmID доказательства с товаром

Место: `backend/app/services/wb_honest_sign_service.py:186`, `:216`;


То есть флаг стал true и изменён один товар на основании raw-карточки с
