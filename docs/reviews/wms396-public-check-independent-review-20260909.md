The background job is claimed under a row lock only from pending state. Each external request starts after its database session has closed. Before writing its result, the worker reacquires the receiving-request lock and checks that its job is still running, then locks the event and checks its tenant and pending status. An expired worker therefore cannot overwrite the replacement job's pending snapshot. Deleted events are skipped; newly scanned pending events are drained by the existing outer loop. The exception cleanup also checks for a newer active job before changing pending snapshots. Existing receiving capacity, deletion, lifecycle and inventory operations are outside the implementation diff.

Request pacing uses the existing process-local MarketplaceBackoff with a two-second interval. In one asynchronous event loop, there is no await between observing an expired interval and reserving the next interval.
