# WMS-673 / WMS-657 — разрешённая смена семантического контракта печатного листа

06.10.2026. Замещающий аналитик Sol 6.1: публикация результата после прерывания
`urgent673_657_semantic_analyst` из-за ENOSPC (нехватки места на диске).
Область этого этапа — только данный отчёт. Требования, продукт, тесты и охрана
не изменяются; навыки, агенты, браузер, новые прогоны, live и деплой исключены
прямым текущим поручением владельца. Параллельная работа WMS-672 и отдельного
разработчика числового fallback WMS-673 не входит в заключение.

## Источник разрешения и исходные границы

Полностью прочитан актуальный `origin/etalon:AGENTS.md` из
`954862b718f9f2f1faefb2f00ad2fef72a6e1929`, требования
[WMS-673](../requirements/WMS-673.md), прежние требования WMS-657 из этого
etalon и замороженный тест
`23c65f86d:frontend/src/screens/v2/fbsPickingListPrint.wms657.test.ts`.

Последнее уточнение владельца WMS-657: «проблема только одна: когда там написано
было у Виталика универсальный, потом он ломает всю таблицу. То есть надо чтобы
там просто перенос нормально как-то работал». Поэтому WMS-657 сама по себе
не разрешала добавлять цвет: её R2 и C1–C3 сохраняли десять колонок и соседство
«Размер → Ячейка / тара». Это был действительный узкий контракт, а не ошибка
тестировщика.

Отдельная WMS-673 разрешает новый столбец. Её R1 прямо задаёт расположение
«после „Размер“ и перед „Ячейка / тара“»; R4 сохраняет размер 78 px / 20 px,
а R5 требует согласованного числа ячеек и прежнего печатного процесса.
Текущее прямое поручение владельца этому замещающему аналитику отдельно
подтверждает: «allowed semantic business contract supersession 11column+
ColorafterSize» и «separate TESTWRITER after published report».
Именно WMS-673 R1/R4/R5 и это поручение разрешают описанную ниже замену
старых структурных ожиданий. Technical PASS ревью не является источником
бизнес-разрешения.

## Заключение о совместимости

Для интегрированного листа WMS-673 разрешено заменить часть старого контракта
WMS-657 о неизменном составе из десяти колонок на одиннадцать колонок с цветом
после размера. Это смена ожидаемого бизнес-поведения (семантического контракта),
а не исправление только тестовых данных или загрузчика PDF. Нельзя объявить
старые FAIL успешными, просто поменяв fixture или сославшись на PDF PASS.

Новый порядок для прежнего WB-контрольного входа:
`№ → Фото → Товар и идентификаторы → Размер → Цвет → Ячейка / тара → Заказы WB → Стикер → Взять → Подобрано → Маркировка`.
Относительный порядок всех прежних колонок сохраняется. В иных площадках
сохраняется существующая семантика идентификаторов WB/Ozon по WMS-673 R5.
Размер остаётся в прежней позиции; ячейка/тара и следующие поля получают
ровно одну новую позицию из-за вставки цвета. Цвет занимает компактное место
из гибкого пространства таблицы по R4; это не разрешает расширять размер,
менять фиксированные ширины фото, номера, стикера или количеств.

Индекс размера 3, его поиск по полному тексту и проверки повреждённых копий
PDF остаются действующими. Границы колонок берутся из фактического рендера:
их нельзя подменять синтетическими координатами. Сохранить существующие
допуски геометрии, проверки страниц, заголовка размера, текстового состава,
отсутствия пересечений и принадлежности значения строке. Добавление цвета
может изменить высоту строки, но не разрешает терять строки, смешивать их
или отключать проверку пагинации. Пустая строка нового листа согласуется
с 11 колонками по WMS-673 R5. Короткий/пустой размер и длинные соседние поля
не удаляются из контрольных входов ради успешного результата.

## Статус и следующий этап

Прочитан опубликованный отчёт
[независимого ревью](wms673-astra-bc272386.md), коммит `ff559d760`:
technical PASS относится к продукту `bc2723866b4a0671c510124c39426058f201d2da`,
PASS reader — к `03538bbed00fef241f920847c6cc53d67fa2dc8c`; в отчёте сохранён
PASS всех трёх фактических PDF-проверок. Здесь эти прогоны не повторялись.
Их результат не закрывает прежние несовместимые ожидания WMS-657, приёмку
или полный CI. WMS-580 и числовой Ozon fallback ведёт другой разработчик;
разрешения менять их ожидания данный отчёт не даёт.

После публикации этого отчёта отдельный TESTWRITER сохраняет явно обозначенную
миграцию контракта отдельным коммитом, со ссылкой на источник разрешения и
описанием перечисленных замен. Он сохраняет постоянную защиту WMS-657 и
доказывает, что проверки продолжают ловить потерю/обрезание размера, неверную
колонку, смешение строк и выход за границы. Сам аналитик контрактные файлы
не меняет и тестировщика этим этапом не запускает. Старые результаты приёмки
WMS-657 не переносятся автоматически на новый интегрированный лист.
Приёмка WMS-673, актуальные результаты тестов и полный CI точного итогового
SHA остаются отдельными обязательными этапами; выпуск этим отчётом не одобрен.
