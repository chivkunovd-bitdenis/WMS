## Что подтверждает только исторический первичный снимок

[historic-official-excerpt.json](historic-official-excerpt.json) содержит дословные JSON-поддеревья двух методов и всех связанных схем с разрешением ссылок `$ref`. Он явно помечен fresh=false. Дата сохранения по репозиторному описанию — 25.08.2026; она не означает получение документа сегодня. SHA-256 полного исходного `OZON_FBS_OPENAPI.json`: `b31282086acccf22f7a292c4060882e7f825b8d241a58215b2e6363e4a441eb2`. SHA-256 выдержки: `0e89b8a1af5a721b999234dc6fae1dda275a4e58efd0d584eb091a499b11f39a` (16811 bytes).

Исторический `/v6/fbs/posting/product/exemplar/set` принимает `posting_number`, полный `products` с `product_id` и `exemplars`; экземпляр содержит `exemplar_id`, `gtd`, `is_gtd_absent`, `rnpt`, `is_rnpt_absent`, `marks`, `weight`. `multi_box_qty` находится на уровне запроса. Номера — string, отдельные признаки отсутствия — boolean. Описание метода требует передавать весь набор товаров и экземпляров, включая ранее переданные. HTTP 200 означает создание асинхронной задачи, а результат нужно читать через `/v5/fbs/posting/product/exemplar/status`.

Исторический ответ `/status` возвращает `posting_number`, `products` с `product_id` и `exemplars`. Для каждого экземпляра отдельно возвращаются номер ГТД, его absent-флаг, `gtd_check_status` и `gtd_error_codes`; аналогично для РНПТ. `gtd_check_status` описан как статус проверки ГТД, `rnpt_check_status` — как статус проверки РНПТ. Оба имеют `type: string`, **без enum, example, default или перечня значений в description**. Это доказывает отсутствие опубликованного перечисления в данном снимке. Нельзя из этого установить намерение автора оставить значения открытыми навсегда, фактический набор значений сегодня или трактовку `passed` для документов. Перечень маркировок `marks.check_status` принадлежит другой схеме и не переносится на документы.

Общий `status` в старом описании различает `ship_available` (сборка доступна), `ship_not_available` (недоступна), `validation_in_process` (проверка), `update_available` (редактирование доступно), `update_not_available` (редактирование недоступно). Доступность сборки и редактирования различны. Полная композиция для проверки совпадения включает тот же posting, все product_id/exemplar_id и выбранные номера/absent-флаги; потерю соседей нельзя заменить совпадением только целевого поля. Последнее — применение требований R5–R7 к ответу, а не дополнительная цитата Ozon.
