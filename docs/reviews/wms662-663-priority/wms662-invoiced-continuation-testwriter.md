# WMS-662: независимый контракт продолжения после выставленного счёта

Проверяется риск, обнаруженный разработчиком после F3 fix
`6e37dd8292e9f02f773d1cfa04e0a3f052a7a584`: увеличение прежнего начисления
не делает дополнительную единицу доступной для следующего счёта.
Прочитаны исходные approve/continuation fixtures, F3 review и публичные
invoice services. Продуктовый код и прежние frozen contracts не изменены.

Новый контракт: `backend/tests/test_wms662_invoiced_continuation.py`.
Он запускает настоящие deliver, observed sync, preview/create/get invoice
services; подменена только внешняя граница Ozon, реальная HTTP-сеть запрещена
существующим frozen fixture. Собственная случайная SQLite и каталог данных
явно заданы переменными WMS_TEST_DATABASE_URL / WMS_TEST_DATA_DIR.
Пользователь и ставки — исключительно синтетические тестовые записи;
авторизация, production, Telegram и кабинеты секретов не использованы.

Сценарий: approve фиксирует A/1, параллельная запись повышает заказ до A/2.
Полностью выполнены прежние проверки расхода/резерва/факта/начислений A/1
и повтора ключа без внешних запросов. Через create_invoice_v2 выставляется
настоящий первый счёт: сборка 1000 + упаковка 800 = 1800 копеек, источники
сохраняют именно эту сумму. Только затем read-only sync подтверждает A/2:
расход 2, завершение поставки, суммарные начисления 3600. Первый счёт и его
источники неизменны; повтор его ключа возвращает тот же счёт.

Публичный preview следующего счёта должен увидеть дополнительную единицу
стоимостью 1800. Дальнейший контракт требует настоящего второго счёта,
повтора ключа без дубля, сохранности обоих снимков после ещё одного sync
и отсутствия третьего платного счёта. Общая выставленная сумма — 3600.
Количество, ID и внутреннее представление фактов/начислений не задаются:
тест фиксирует бизнес-результат «выполненные единицы оплачиваются ровно один раз».

RED на исходном продукте: **2 failed, 6 warnings in 1.77s** — оба варианта
(обычное продолжение / ещё два read-only sync) достигают целевой ошибки:
`A/2 is completed; immutable first invoice covers A/1 only, but next invoice
cannot bill the incremental unit: selected_source_already_invoiced`.
Сервис отклоняет выбор на проверке занятых ledger IDs в
`billing_invoice_v2_service._preview_selected_operations`.
Проверки после целевого RED являются контрактом будущего исправления,
их успешное выполнение пока не заявлено. Ruff нового файла прошёл.
Перед фиксацией HEAD был `8bcae18889f79c0c380edfe8b7c1f4b3392159eb`;
`git diff 6e37dd8292e9f02f773d1cfa04e0a3f052a7a584 -- backend/app` пуст:
RED получен на указанном продукте, несмотря на параллельные документальные коммиты.

Команда из backend:
`/Users/deniscivkunov/Projects/WMS/backend/.venv/bin/python -m pytest -q
-p no:cacheprovider tests/test_wms662_invoiced_continuation.py --tb=short`.
Перед запуском обязательно задавать собственные изолированные SQLite/data paths.

Передача разработчику: сохранить новый и прежние контракты, обеспечить доступность
невыставленного дополнительного объёма без изменения уже выданного счёта,
без повторного начисления/выставления ранее оплачиваемой единицы.
Конкретное хранение delta не предписывается. Эта передача подтверждает дефект
и тест до реализации, а не исправление, приёмку или CI.
