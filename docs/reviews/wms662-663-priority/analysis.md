## Подтверждённая диагностика свежей кодовой базы

`ozon_fbs_sync_service._apply_status` снимает резерв по локальному done/cancelled, но не создаёт складского движения проведения. `sync_ozon_order_statuses` исключает локально terminal done/cancelled из опроса. Поэтому ранее завершённый заказ без движения не восстанавливается одним обычным опросом, а резерв может освободиться раньше расхода. Отмена имеет существующий путь сторно и возврата подбора; новый положительный ответ не должен оживлять сохранённую отмену.

`ozon_fbs_process_service._full_exemplar_products` собирает payload из маркировок и отдаёт только exemplar_id/marks. Поля gtd/rnpt, absent-флаги и remote weight не сохраняются этим writer. Простая галка без единого полного payload может быть стёрта следующей записью КИЗ. UI `FfFbsSupplyWorkspace.tsx` не содержит is_gtd_absent/is_rnpt_absent. Существующие модели API поддерживают их; новые таблицы/экраны не требуются.

Официальная WB документация повторно найдена 06.10: https://dev.wildberries.ru/en/docs/openapi/orders-fbs?locale=ru. Она отличает complete (передано в доставку) от confirm (сборка); parent done закрывается также при приёме первой единицы и не доказывает весь состав. Поисковый индекс помечен возрастом5 месяцев; это не live Seller API proof. Сохранённая официальная Ozon спецификация остаётся источником схемы /set и /status; текущая публичная официальная страница не получена, private enum документных проверок не придумывается.
