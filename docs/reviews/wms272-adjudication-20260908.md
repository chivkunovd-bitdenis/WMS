# WMS-272: независимая сверка замечаний Opus и исправлений

Модель Astra xhigh. Исходный проверенный диапазон: 693ac992..8baa351f.
Финальные исправления: 08f2ac39 и 12c230bd. Только чтение исходников и тестов;
ревьюер не запускал тесты повторно, не менял код и не обращался к живым сервисам.

Подтверждены две причины дефектов исходного кандидата:

1. Ранняя фиксация операции без номера WB оставляла заказы занятыми после
   потерянного ответа или остановки процесса. Повтор отказывался продолжать,
   новый ключ упирался в ту же сохранённую операцию. Это новый бессрочный тупик.
2. Восстановление пустого либо частично добавленного состава подтверждало
   операцию раньше завершения добавления всех выбранных заказов.

Предложенный Opus seller lock вокруг repair вторую гонку не закрывал: создание
освобождает транзакционную блокировку до HTTP. Проверка только непустого состава
также недостаточна: добавление выполняется пакетами. Предложенная правка fbsUx
относилась к передаче, а не настоящему диалогу создания и не устраняла тупик.

Принято минимальное исправление 08f2ac39: до получения реального номера WB
локальная незавершённая операция не сохраняется. Перед HTTP read-транзакция
завершается; после ответа существующая короткая блокировка защищает повторную
проверку и сохранение операции сразу с WB ID. Конкурентный проигравший использует
первую сохранённую поставку; свой лишний пустой черновик заказами не заполняет.
Ошибка его HTTP не меняет победителя. Возможный пустой remote-черновик — явный
компромисс прежнего потока, не новая потеря заказов. После сохранения WB ID
работает существующее продолжение. Repair требует полный исходный набор.

Дополнительная сверка обнаружила частичного победителя: confirmed-ветка resume
могла привязать исходно запрошенный, но отклонённый WB заказ. Исправление
12c230bd принято отдельно: недостающая привязка ограничена сохранёнными
accepted_wb_order_ids, ответ сохраняет partial_rejection. Новый paused-HTTP тест
проверяет равенство ответов двух запросов, new/без supply для отклонённого заказа
и отсутствие add-orders в лишнюю поставку. В финальной дельте новых дефектов
не выявлено. Целевые PostgreSQL, ruff/mypy выполнены исполнителем и описаны
в wms272-finish-20260908.md.

Новые API, интерфейс, сущности, статусы, TTL и удержание соединения во время HTTP
не добавлены. Складские движения, резервы, упаковка и навигация не расширяются.
Базовая двойная блокировка фонового repair отмечена как прежнее поведение,
а не основание добавлять её исправление в этот ограниченный diff.

В заключительном Opus повторе найден неверный сохранённый факт: helper по
умолчанию ставил wb_timeout до первого add HTTP даже после успешного create.
Astra приняла ровно очистку operation.error_code до commit; отображение этого
поля оператору не доказано. Исправление ad116f0d и проверка success с утверждением
error_code=None во время paused add прошли на отдельной PostgreSQL-базе (1 passed,
ruff успешен). База удалена. Пустой order_ids снова отвергнут как недостижимый
штатный путь. Последний Opus CLI max получил обе малые дельты целиком и одобрил
их, результат — wms272-opus-last-delta-20260908.md.
