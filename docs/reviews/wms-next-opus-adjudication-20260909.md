# WMS-058: обязательное исправление после финального Opus

09.09.2026, 06:36 МСК. Astra xhigh независимо прочитала результат Opus
session4a26b04b-0320-44f7-9938-c38793d43bcb и проверила наблюдения по frozen
8cc97a07e6a8fa89e9506f7b79ef2474eb8a735b. Безусловное разрешение выпуска
**не подтверждено**: третье замечание шире текста диалога, найден P1.

В FfMarketplaceUnloadBoxAddDialog.tsx товарP из контейнераA может ожидать
ответа plan_limit_exceeded, когда оператор уже поставил скан контейнераB
в scanQueueRef. Обработка422 сохраняет только barcodeP и открывает диалог,
но уже сформированная очередь продолжает работу. ОтветB обновляет sourceRef.
Подтверждение ставит новый runScan(P,true), который читает текущий sourceRef:
в запрос уходит P,1,B,allow_over_plan=true. Если вB есть товар, сервер
корректно исполняет этот неправильный для намерения оператора источник.

Проверены сохранение pending на519–521, очередь542–545, подтверждение565–571,
чтение источника408 и серверный collect с выбранным контейнером. Выключение
scanner hook не останавливает уже поставленные задания. Координатор отдельно
прочитал эти участки текущего кандидата. На момент вердикта это достижимая
цепочка по исходникам, браузерное воспроизведение ещё поручено отдельному агенту.

Минимально требуется сохранять конкретное тело отказавшего запроса и при
подтверждении менять только allow_over_plan; последующий отказ очереди не
должен подменять ожидающее решение. Нельзя заморозить источник раньше
выполнения предшествующего source-скана или оставить очередь зависшей после
отмены/закрытия. Новые серверные сущности и изменения дизайна не требуются.
При одиночном подтверждении количество остаётся1 — весь короб не переносится.

Остальные замечания Opus обязательных изменений не требуют: EVENT_VOIDED
является существующим названием события, а повторное назначение дополнительно
проверяет состояние и причину; UUID location_code не виден при выбранной таре.
В описании охвата Opus ошибочно указал6 тестовых файлов: в diff9 прикладных
и9 тестовых. Это ошибка отчёта, не самостоятельный дефект приложения и не
доказательство непрочитанности трёх файлов. Исходный ответ сохранён без правки.

PR207 остаётся черновиком. Production40b722a4 не обновлялся. Исправление делает
отдельная Astra high, реальный браузер проверяет другой агент; затем требуются
целевые frontend-проверки, независимая оценка исправления, обновлённый CI/staging
и завершающее ревью изменённого участка тем же Opus max.
