# 02 — UX-спека мобильного приложения ТСД

Аудитория документа: исполнители тикетов (в т.ч. дешёвые модели). Всё, что здесь
написано, — обязательные требования, не пожелания. Отступления — только через
владельца проекта.

## 0. Главный принцип

Это НЕ ужатый веб. Сотрудник стоит у стеллажа, в одной руке ТСД/телефон, в другой
товар, возможно в перчатках, освещение плохое, времени мало. Каждый экран отвечает
на один вопрос: **«что мне отсканировать/сделать прямо сейчас?»**

Десять правил (нарушение любого = тикет не принят):
1. Один экран — одно действие. Никаких табов с параллельными задачами.
2. Экран всегда готов принять скан. Скан — главный ввод, тап — вспомогательный.
3. Результат скана виден без чтения: зелёная вспышка + звук + вибрация = успех;
   красная вспышка + другой звук + длинная вибрация = ошибка. Текст ошибки — крупно,
   человеческим языком («Этого товара нет в заявке»), автоскрытие через 3–4 сек
   или по следующему скану.
4. Прогресс всегда на виду: «Отобрано 12 из 40», прогресс-бар.
5. Тач-таргеты ≥ 56dp, основная кнопка действия — во всю ширину внизу экрана
   (зона большого пальца), высота 64dp.
6. Шрифты: ключевая цифра/артикул — 24–32sp; никаких текстов < 16sp.
7. Количество вводится только цифровой клавиатурой (`KeyboardType.Number`)
   или степпером +/−, никогда полноразмерной клавиатурой.
8. Ручной ввод ШК с клавиатуры рядовому сотруднику запрещён (правило бизнеса).
   Фоллбек «ввести вручную» показывается только роли админа ФФ.
9. Опасные действия (закрыть короб с расхождением, завершить приёмку при недостаче)
   — конфирм-диалог с явным описанием последствий, кнопки разнесены.
10. Потеря сети — не тупик: баннер «Нет связи», операция ретраится кнопкой,
    введённое не пропадает.

## 1. Дизайн-токены

- Тема: светлая (склады бывают тёмные, но экраны ТСД на солнце/под лампами
  читаются лучше в светлой; тёмную не делаем в v1).
- Цвета: `Primary #1565C0` (действия), `Success #2E7D32`, `Error #C62828`,
  `Warning #F57F17` (расхождения), `Surface #FFFFFF`, `Background #F5F5F5`,
  текст `#1A1A1A` / secondary `#5F6368`. Контраст всегда ≥ 4.5:1.
- Скругления 12dp, отступы кратны 8dp, карточки с elevation 1.
- Статусы документов — цветные чипы, те же формулировки, что в вебе
  (Запланирована / Принята по коробам / Принята / Подтверждена / Отгружено...).

## 2. Библиотека паттернов (композаблы в `ui/patterns/`)

Каждый экран собирается ТОЛЬКО из этих паттернов. Новый паттерн = отдельный тикет.

### P1. ScanScaffold
Каркас любого «рабочего» экрана: верхняя полоса (название задачи + прогресс
X из Y + кнопка выхода), центральная зона контента, невидимое поле фокуса для
wedge-ввода, нижняя основная кнопка. Подключён к `ScannerManager`: событие скана
приходит колбэком независимо от источника (broadcast / wedge / камера).
На смартфоне в правом нижнем углу FAB «камера» — открывает P7.

### P2. TaskListScreen
Список заданий (заявки на приёмку/отгрузку). Карточка: номер + селлер, дата,
статус-чип, счётчик штук (план/факт), пиктограмма расхождений. Сортировка по дате.
Pull-to-refresh. Пустое состояние с человеческой фразой. Поиск не нужен в v1 —
списки короткие; фильтр по статусу — чипы сверху.

### P3. ScanPrompt
Центральный элемент «отсканируй X»: крупная иконка (короб/товар/ячейка),
подпись «Отсканируйте штрихкод короба», последний скан снизу мелко.
Состояния: idle / success-вспышка / error-вспышка (+ текст ошибки).

### P4. LineProgressList
Список строк документа с прогрессом: фото товара (маленькое), артикул (крупно),
название (1 строка, ellipsis), «12 / 40» + мини-прогрессбар. Завершённые строки
уезжают вниз и сереют. Активная (по последнему скану) — подсвечена и проскроллена
в видимую область.

### P5. QtyInput
Ввод количества: гигантские «−», число (32sp), «+», под ними цифровая клавиатура
по кнопке. Валидация min/max с объяснением («Осталось разместить 7»).

### P6. ConfirmSheet
Нижний шит подтверждения действия с последствиями: заголовок, 1–3 строки фактов
(«Коробов: 5 из 6 · Расхождение по 2 товарам»), красная/зелёная основная кнопка,
отмена. Используется для: закрыть короб, завершить приёмку, отгрузить.

### P7. CameraScanSheet
Полноэкранный сканер ML Kit (только смартфоны): видоискатель с рамкой, фонарик,
после успешного распознавания — авто-закрытие и то же событие скана, что и у ТСД.

### P8. ErrorBanner / OfflineBanner
Единый показ ошибок API (парсинг detail как в вебе) и баннер «Нет связи. Повторить».

## 3. Инвентарь экранов

### A. Служебные

**A1. Логин** — email+пароль (один раз на устройство), затем экран «кто работает»:
крупные плитки сотрудников с сохранённой сессией + PIN (4 цифры, локальный).
Смена сотрудника — с главного экрана в одно касание.

**A2. Главный экран (Home)** — три гигантские плитки-кнопки на весь экран:
«Приёмка» (с бейджем: сколько заявок ждёт), «Сортировка», «Отгрузка».
Внизу: имя сотрудника, склад, индикатор связи, выход.

### B. Приёмка

**B1. Список поставок** (P2) — заявки в статусах «Запланирована» и «Принята по
коробам». Тап → B2.

**B2. Приёмка по коробам** — факт количества коробов (P5), кнопка «Создать короба»
→ список коробов с их ШК и статусом печати этикетки. Кнопка «Дальше — приёмка товара».
Состояние заявки после этого шага = «Принята первично».

**B3. Приёмка товара** (P1+P3+P4) — главный рабочий экран, «золотой экран» проекта.
Логика сканов:
- скан ШК короба → короб открывается, шапка показывает «Короб №3», ScanPrompt
  переключается на «Сканируйте товар»;
- скан ШК товара при открытом коробе → +1 в строку короба (P4 обновляется, зелёная
  вспышка);
- скан товара, которого нет в заявке → красная вспышка «Товар не из этой заявки»;
- скан другого короба → текущий закрывается вопросом (P6), открывается новый;
- кнопка «Закрыть короб» → P6 с итогами по коробу;
- режим «Без короба» (loose) — отдельная кнопка-переключатель в шапке.
Выход с экрана не теряет прогресс (всё уже на сервере после каждого скана).

**B4. Завершение приёмки** — сводка план/факт по строкам, расхождения подсвечены
Warning, P6 «Завершить приёмку» → complete-receiving + verify.

### C. Сортировка (размещение)

**C1. Список к размещению** (P2) — заявки, принятые, но с remaining_qty > 0.
Тап → C2.

**C2. Размещение** (P1+P3+P5) — цикл:
1. ScanPrompt «Сканируйте короб или товар» → показывает, что внутри и сколько
   осталось разместить;
2. ScanPrompt «Сканируйте ячейку» (у ячеек есть ШК; кнопка «Без ячейки» — как
   явный выбор);
3. P5 с предзаполненным «всё оставшееся» → подтверждение;
4. зелёная вспышка, возврат к шагу 1, прогресс в шапке уменьшается.
Ошибки: ячейка чужого склада, товар уже размещён — красная вспышка с текстом.

### D. Отгрузка

**D1. Список отгрузок** (P2) — заявки «Подтверждена ФФ» и далее. Тап → D2.

**D2. Отбор (pick)** (P1+P3+P4) — зеркало B3: скан товара → +1 к отобранному
(`pick/scan`), строки-цели из заявки, скан лишнего → ошибка без изменения количества.
Подсказка по строке: из какой ячейки брать (если распределено).

**D3. Упаковка в короба** (P1+P3+P4) — «создать короб» → скан товаров в короб
(`boxes/{id}/scan`) → «закрыть короб» (P6). Список коробов с наполнением.
Если у заявки есть packaging-task с маркировкой ЧЗ: после скана товара экран
требует скан кода маркировки (verify_marking_pair) — двойной ScanPrompt
«товар → код ЧЗ», несовпадение пары = красная ошибка.

**D4. Завершение отгрузки** — сводка по коробам и строкам, P6 «Отгрузить»
→ submit + ship. После успеха — большой зелёный экран «Отгружено» на 2 сек.

## 4. Состояния, обязательные для каждого экрана

loading (скелетоны, не спиннер на весь экран) / empty (текст человеком) /
error сети (P8 + retry) / success. Для рабочих экранов дополнительно:
optimistic UI запрещён — количество меняется только после ответа сервера
(на складе правда важнее скорости; латентность в локальной сети мала).

## 5. Что намеренно НЕ делаем в v1

Тёмная тема, оффлайн, push-уведомления, инвентаризация, перемещения, печать
с устройства, планшетная раскладка, локализация (только русский), анимации
сложнее вспышек и прогресс-баров.
