# Макет ТСД · пакет ArtMaks 08.10 (WMS-736…741, связанные WMS-711 и WMS-713)

Кликабельный макет новых процессов мобильного ТСД (терминала сбора данных) по переписке с ArtMaks 08.10.2026. Слева — экран устройства, справа — пульт: кнопки «сканера», готовые сценарии и журнал того, что в этот момент сделала бы система. Данные вымышленные, сервер не вызывается, приложение ТСД не меняется.

## Как открыть

```sh
sh /Users/deniscivkunov/Projects/WMS/.worktrees/tsd-artmaks-analysis/docs/mockups/WMS-736/open.sh
```

Затем http://127.0.0.1:16736/ в обычном браузере. Скрипт ничего не устанавливает: он ставит ссылку node_modules на /Users/deniscivkunov/Projects/WMS/frontend/node_modules и запускает Vite. Сброс — кнопка «Начать»/«Заново» у сценария или обновление страницы.

Проверка сборки: из этой папки ./node_modules/.bin/tsc -p tsconfig.json и ./node_modules/.bin/vite build (папка dist в Git не попадает).

## Устройство

Экран 360 × 640 dp в портрете — эталон маленького экрана, принятый в WMS-711 (вопрос Q4). Из них 24 dp занимает строка состояния и 48 dp — системная навигация, приложению остаётся 568 dp: это самый тесный случай, на ТСД с большим экраном будет просторнее. Точная модель UROVO у ArtMaks не установлена. 1 dp макета = 1 CSS-пиксель; масштаб «по окну» только увеличивает картинку.

Цвета, шапка, полоса места, диалоги и нижние листы повторяют приложение (сборка 0.2.0, код 19, репозиторий WMS-TSD, коммит 41f0f33: ui/theme/Theme.kt, ui/patterns, features/fbs, features/inbound). Изменённые пакетом экраны набраны не меньше 16 sp с кнопками не ниже 48 dp; экраны, которые пакет не меняет, нарисованы как есть.

## Где ТСД сейчас отстаёт от веба (проверено по коду сборки 19 и origin/etalon)

1. **Подбор FBS** — плоский список товаров вместо маршрута по ячейкам; полностью подобранные товары уезжают вниз; плашки мест показывают «доступно» без учёта уже подобранного (так же путалась веб-таблица 08.10). Закрывает WMS-711.
2. **Создание поставок** — причина отказа группы без номера заказа; группы проверяются по одной с блокировкой окна; повтор после частичного создания ничего не делает, но звучит как успех. WMS-713, WMS-741.
3. **Упаковка** — нет ни слова о недоборе (WMS-737); короб нельзя очистить или удалить (в вебе — меню «Очистить»/«Удалить», WMS-738); передачи нет в упаковке, «Назад» водит через законченный подбор (WMS-739).
4. **Приёмка** — нет фильтров и поиска; в списке нет черновиков селлеров, сортировки и оприходованных; черновик селлера открывается и тут же закрывается (WMS-736).
5. «Короба внутри короба» в прочитанном коде подбора и упаковки FBS и приёмки нет: короба там плоские. В FBO-подборе ТСД (ветка wms686-fbo-pick, WMS-686) есть «перенос короба целиком» — этот пакет его не разбирал.

## Переделка 09.10 по замечаниям координатора и что противоречит прежним решениям

Все 15 пунктов внесены в макет и в требования (WMS-736 R10, WMS-737 R8–R9, WMS-738 R9, WMS-739 R1–R2 и R7–R10, WMS-740 R1–R7, WMS-741 R1–R3). Три пункта расходятся с действующими решениями или правилами — они сделаны, но вынесены владельцу:

- **Экран поставки (п. 7)** — владелец в WMS-584 R8 отклонил «кнопки наверху» («он же был нормальный»). В макете по умолчанию новый вид (действия внизу, состав свёрнут); прежний включается на пульте: «Экран поставки → как утверждено (WMS-584 R8)». Вопрос В1 в WMS-739.
- **Конец подбора (п. 6)** — владелец в WMS-584 сам задал две кнопки «К упаковке» и «Завершить подбор». «Завершить подбор» я не убирал, а сделал второстепенной; «К упаковке» — главная. Вопрос В2 в WMS-739.
- **Ошибка держится до следующего действия (п. 4)** — меняет правило UX ТСД 3 («автоскрытие через 3–4 с или по следующему скану», mobile/docs/02_UX_SPEC.md). Записано в WMS-740 R2.

Пункты 2–5 и 13 про экран подбора относятся к WMS-711 (в работе в другой ветке); я записал их требованиями в WMS-740 с пометкой «перенести в реализацию WMS-711». Пункт 1 — к окну WMS-713; записан в WMS-741 R1–R3.

Не приведены к 16 sp и 48 dp существующие экраны, которые пакет не меняет: список новых заказов FBS и карточки «В работе» (11–15 sp, как в сборке 19), подвал главного экрана («Кладовщик» 13 sp, «Сменить» 40 dp) и вид экрана поставки «как утверждено (R8)».

## Что проверено в макете

Первый проход 09.10: все семь сценариев. Исправлено тогда: лист фильтров не перекрывал нижнюю кнопку, «Сбросить» уезжал за край, маршрут не возвращался к ранней ячейке, служебный код __SORTING__, обрезанная вторая строка блока места, ошибка React.

Второй проход после переделки (09.10, тот же встроенный браузер, касания по экрану и кнопки сканера на пульте): все семь сценариев заново. Автоматически по каждому экрану пакета замерено: текстов меньше 16 px и кнопок ниже 48 px нет (кроме перечисленных выше неизменяемых экранов); на подборе маршрут — 397 из 568 dp (70%); в окне создания поставок содержимое помещается без прокрутки; обрезаются многоточием только длинные названия товаров (размер вынесен в начало строки или к штрихкоду). Найдено и исправлено во втором проходе: размер товара пропадал под многоточием; кнопка «Создать без WB …» обрезалась в окне; над маршрутом оставалась полуобрезанная строка (добавлен запас внизу списка, после полного подбора список возвращается к началу).

Снимки «до» и «после» лежат локально в docs/mockups/WMS-736/evidence/before и evidence/after этой рабочей копии; по правилу .gitignore картинки в docs в Git не хранятся.

Не проверено: физический ТСД, реальный сканер и клавиатура Android, печать, Ozon (переключатель есть, заказов нет), полный путь ЧЗ (показаны только QR → код ЧЗ).
