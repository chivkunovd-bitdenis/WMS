# WMS-666 · интерактивный макет общих действий упаковки

Это локальный React-макет для сравнения интерфейсов, а не реализация в рабочем продукте. Он использует настоящие `FfFbsSupplyWorkspace`, `FfFbsSupplyAssembly`, `FbsPackingScanBar`, их строки, штатные диалоги и `muiTheme`. Код `frontend/src`, backend и CI не изменяется: Vite преобразует исходные компоненты только в памяти при обслуживании этого макета.

## Запуск

Базовый продуктовый коммит для этого макета — `212f19d548496fef7baf75c83204b771e304281b` (07.10.2026). Получите **полный checkout** WMS на этой базе в отдельной ветке/рабочем дереве и поместите туда каталог макета. Пример из существующего репозитория, без абсолютных авторских путей:

```sh
git worktree add --detach .worktrees/wms666-demo-source 212f19d548496fef7baf75c83204b771e304281b
```

Если репозиторий использует sparse-checkout, отключите его в новом рабочем дереве (`git sparse-checkout disable`), чтобы в нём существовал `frontend/src`. Каталог `docs/mockups/WMS-666` должен содержать эти файлы макета. Используйте уже установленные зависимости именно этого frontend; установка новых зависимостей не нужна для текущего рабочего дерева.

Из корня полного checkout WMS с уже установленными frontend-зависимостями:

```sh
ln -s frontend reference-frontend
ln -s frontend/node_modules node_modules
node node_modules/vite/bin/vite.js --config docs/mockups/WMS-666/vite.config.ts
```

Если ссылки уже существуют, используйте их. Для этого макета не нужны Docker, `npm ci` или production-сборка. В текущем изолированном checkout `reference-frontend` ссылается на соседний frontend; исходники этой ссылки доступны только для чтения. На другом компьютере ссылка выше использует собственный `frontend` и не требует абсолютных путей. Vite обслуживает только localhost и использует существующий каталог зависимостей для кеша.

Откройте [предложение для отдельной поставки](http://127.0.0.1:16667/), [предложение для общей сборки](http://127.0.0.1:16667/?mode=group&variant=proposal), [исходную общую сборку](http://127.0.0.1:16667/?mode=group&variant=baseline), [исходную отдельную поставку](http://127.0.0.1:16667/?mode=single&variant=baseline) или [общую сборку Ozon](http://127.0.0.1:16667/?mode=group&marketplace=ozon).

Служебная панель находится внутри открытого Dialog через portal, поэтому её переключатели доступны клавиатуре и программе чтения экрана. Панель и журнал демонстрации не относятся к предлагаемому продуктовому интерфейсу. Положение главного окна сдвинуто вниз только для служебной панели; исходные ширины строк и колонок сохранены.

## Что можно сравнить

У предложения одна полоса ручных действий над существующими строками: общий выбор, печать выбранного либо всего, проверка WB и контекстные действия над именованной поставкой. Полоса сохраняет числа «напечатано» и «упаковано», исходный признак «Сдаём без Честного знака» отдельной поставки и исходные условия доступности действий (занятость, редактируемость, наличие сохранённых/удаляемых КИЗ, уже выполненный пропуск); выбранное количество показывается дополнительно. Сканер и его флажки доступны одновременно с ручной печатью, без переключателя режимов.

В общей сборке выбор распространяется на обе поставки. Ручная печать делит выбранные заказы по их исходным поставкам и открывает штатные окна печати последовательно; чужие заказы не передаются callback другой поставки. Следующее окно открывается после успешной демонстрационной печати. «Закрыть»/«Отмена» останавливает оставшуюся очередь; продолжение требует нового нажатия печати.

«Проверить в WB · все 2 поставки» относится ко всем кодам этих поставок, независимо от выбора строк. В меню можно выбрать одну именованную поставку и проверить только её. «Всё упаковано» и «Сдать без Честного знака» относятся ко всей выбранной поставке, а очистка/перенос — только к отмеченным заказам этой одной исходной поставки. У двух демонстрационных поставок разные согласованные селлеры; перенос между ними не допускается исходным правилом принадлежности селлеру. Штатный диалог переноса и список выбранных заказов доступны, но успешный перенос/создание третьей поставки здесь не моделируется.

Построчные QR, ЧЗ/ШК, ТЗ, точная перепечатка КИЗ, отметки и остальные колонки остаются исходными. QR открывает настоящий `FbsPrintPreviewDialog` с изображением DEMO; это не валидная этикетка WB. Массовая WB-печать передаёт QR + ЧЗ + ШК, построчная ЧЗ/ШК — без QR. У Ozon QR в сканере выключен, построчный слот QR остаётся исходным пустым слотом.

## Демонстрационные данные и действия

`fixtureBase.mjs` — копия исходной фикстуры `frontend/tests-e2e/wms652-critical/fixtures.mjs` из базового Git-коммита. Из неё собраны две вымышленные поставки и шесть заказов, часть с принятыми КИЗ и печатными отметками, часть без кода; включено длинное название. У первой поставки и каждого её заказа селлер Альфа, у второй и её заказов — селлер Бета. Селлер отображён также в контексте меню и служебном журнале. Это исходные данные для проверки композиции, а не реальные складские документы.

Данные и изменения живут в памяти страницы; перезагрузка или «Сбросить» возвращает фикстуру. Служебный журнал показывает точные номера заказов, поставку, состав этикеток и область действия. Для скана доступны `DEMO-1-2`, `DEMO-2-2`, затем демонстрационный КИЗ `010460000000000121DEMO`. QR/ЧЗ-флажки влияют на ожидаемый демонстрационный результат. В модели отдельно различаются штрихкод товара и явный выбор заказа стикером/полем строки. ЧЗ из WB-пула доступен только товарному WB-скану, никогда явному выбору или Ozon. Выключенные WB-флажки не дают товарному WB-скану выбрать или упаковать заказ. Поиск Ozon от этих флажков не зависит; автоматическая точная копия входного КИЗ применяется только к WB. Явный выбор без уже сохранённого КИЗ ожидает входной код оператора. «Назад» отключён: отмена складской операции не моделируется, что прямо указано в служебной панели; успех отмены не имитируется.

Скан-контроллер и HTTP-ответы заменены локальными stub-функциями. Это демонстрация доступности управления и его области действия, **не проверка настоящего алгоритма сканирования**, проверки WB, распределения КИЗ, списания, восстановления после сбоя или работы физического сканера. Окна печати настоящие, но доставка печати заменена журналом, без построения реального задания принтеру. Сохранение печатных отметок — демонстрационная запись в памяти.

`mockApi` не отправляет реальные API-запросы. Неизвестные и внешние fetch-запросы отклоняются; `window.open` и `window.print` блокируются, а действия штатных окон печати перехватываются преобразованием Vite. Принтер, WB и Ozon не вызываются. Нереализованные соседние действия показывают локальную ошибку; из макета нельзя проводить реальные документы.
