# WMS-686 · ArtMaks FBO

Кликабельный React-макет настоящего полноэкранного документа отгрузки WMS. Вне целевых подбора/упаковки импортируются неизменённые production-компоненты и тема. Демонстрационные товары/КИЗ/документы вымышлены. API полностью заменён локальными ответами, неизвестные пути явно отказывают; рабочие системы не вызываются.

Из корня checkout:

```sh
npm --prefix frontend ci
ln -s frontend/node_modules node_modules
frontend/node_modules/.bin/vite --config docs/mockups/WMS-686/vite.config.ts
```

Если корневой node_modules уже существует, symlink не нужен. Макет: http://127.0.0.1:16866/ . Исходный экран: http://127.0.0.1:16866/?baseline=1 . Сброс вымышленных данных: http://127.0.0.1:16866/?reset=1 . Обычный адрес сохраняет прогресс между обновлениями, reset специально возвращает исходное при каждом открытии.

Проверяемый сценарий: Подбор → скан ячейки `А-1-1` → скан короба `INB-DEMO-001`. Можно забрать весь короб, всю ячейку либо выбрать DEMO-TS-48, количество2 и КИЗ `DEMO-KIZ-2 DEMO-KIZ-5`. Упаковка → `DEMO-P1` → `DEMO-KIZ-2` подтверждает прежнюю единицу без удвоения. Закрыть короб выбирает следующий с новым кодом. Чтобы добавить исходную единицу: `DEMO-P1` → `DEMO-KIZ-1` → код выбранного открытого короба (например `WHB-DEMO-002`). Связи показываются в раскрытии КИЗ выбранного короба. Для другого товара `DEMO-P2`, коды7–10. Второй исходный короб `INB-DEMO-002` содержит p1 КИЗ11–12.

Сохранность UI: Vite-плагин вставляет только целевые компоненты и локальные обработчики обновления в память сборки. Файлы frontend/src не правятся. Каждый заменяемый фрагмент должен встретиться ровно один раз; при изменении эталона сборка явно останавливается. Слот/пропуск, новая форма услуг, тарифы и отчёты не добавлены.

Проверки:

```sh
node --test docs/mockups/WMS-686/model.test.ts
frontend/node_modules/.bin/tsc --noEmit -p docs/mockups/WMS-686/tsconfig.json
frontend/node_modules/.bin/vite build --config docs/mockups/WMS-686/vite.config.ts
```

Vite складывает bundle в игнорируемый dist. Для автономного статического размещения собрать bundle и использовать обычный static server. Backend, авторизация и секреты не нужны.

На свежем/сброшенном демо последняя физическая единица во втором коробе не имеет ранее учтённого КИЗ. Чтобы показать нанесённый код без истории приёмки: после partial2 и закрытия первого короба сканировать DEMO-P1 → DEMO-NEW-KIZ → WHB-DEMO-002. История показывает «Приёмка не указана»; код привязывается к существующей единице, общий остаток не увеличивается. Исходный createDemoState для контрактных тестов сохранён; только этот UI fixture показывает реальный случай неполной маркировочной истории. Печатные кнопки сохраняют прежнее оформление, но native print заменён демо событием; нового окна предпросмотра нет.
