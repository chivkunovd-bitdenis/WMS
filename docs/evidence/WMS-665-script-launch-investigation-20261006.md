# WMS-665 / ticket 25: почему avpack-sold-kiz.command остановился

Расследование по source 381/revision 1, Telegram 529 владельца
689889703: «Разберись с проблемой. У него сам скрипт не работает».
Проверка 06.10.2026. Это отчёт о существующем помощнике WMS-665,
который использует экран WMS-517. Новая задача и карточка не создавались.
Разрешения на вывод, подпись, ЧЗ, production или внешний ответ нет.

## Установленная причина и её границы

Виталий уже прислал текст Terminal: **source 382 / Telegram 738**,
после фото source 380 / Telegram 736. На Mac выполнена исходная команда
скачивания и запуска. Ошибка дословно:

```text
execution error: Error: MacLauncherError: Откройте ровно одну вкладку https://sellerfocus.pro/seller/honest-sign/withdrawals и закройте её дубликаты. (-2700)
```

Это ошибка **поиска вкладки Chrome**, не скачивания, shell, выбора КИЗ или
подписи. Встроенная оболочка принимает исключительно старый домен
`sellerfocus.pro`. Правильный `wms.sellerfocus.pro`, доставленный ранее
в out 446 / Telegram 725, ею отвергается. Оболочка выбрасывает эту ошибку
при `matches.length !== 1`, до первого `evaluate` и внедрения помощника
на страницу. Список реальных вкладок не передан: нельзя утверждать,
что были именно дубликаты либо что Виталий уже открыл исправленный адрес.
Непосредственно доказан отказ поиска; несовместимость старого файла
с действующим адресом доказана чтением и локальным воспроизведением.

Запуск дошёл до JavaScript for Automation (системный JavaScript macOS)
и чтения списка вкладок Chrome. Значит, в этом запуске загрузка файла,
последовательность `chmod 700`, `/bin/zsh` и запуск `/usr/bin/osascript`
не были местом остановки. Доступ к выполнению JavaScript **на странице**
ещё не проверялся: настройка Chrome Allow JavaScript from Apple Events
может понадобиться на следующем этапе, но не объясняет текущую ошибку.
CryptoPro, сертификаты и PIN в этом запуске не использовались.

Исправление одной ссылки в сообщении не обновляет файл. Команда фиксирует
SHA `70c505acf6f7ce8202b94fcb16cc05545324eb3f`, поэтому повторное скачивание
по ней всегда получает прежний файл, даже после публикации исправления.
Не следует возвращать пользователя к адресу с HTTP 404.

## Совместимость с действующим экраном

Проверена опубликованная статическая сборка, полученная из HTML правильного
маршрута. Авторизованная сессия Виталия и реальный DOM не открывались.
В `/assets/SellerKizWithdrawalScreen-DREne0Wj.js` (38344 байта,
SHA-256 `db1c806aadea0bc4a66da655bf1a74a550d8a7687f5a1316df8e6b46f5ba5cf2`)
сохранены ожидаемые помощником признаки:
`seller-kiz-withdrawal-page`, «Обновить», «Найдено:», «Выбрано КИЗ:»,
`Выбрать все доступные КИЗ по фильтрам`, «Вывести из оборота» с количеством,
«Выберите сертификат», кнопка закрытия и путь реестра
`/operations/marking-codes/self/withdrawals`.
Опубликованный `/assets/api-S4YWLRK7.js` содержит `wms_token_seller`.

Чтение текущего локального `SellerKizWithdrawalScreen.tsx` и
`sellerKizWithdrawalApi.ts` согласуется с этими маркерами: обновление
получает реестр через fetch; выбор всех собирает страницы по 250 строк;
кнопка открывает штатный диалог и запрашивает сертификаты. Создание операции
и подписи относятся к последующему подтверждению. Сам помощник GET-проверкой
проверяет авторизованного пользователя/tenant/seller/право вывода, затем
наличие точных row_id без текущей операции и только потом готовит выбор.

В исправлении согласованы все слои: URL оболочки, regex поиска вкладки,
проверка origin внедрения, origin фильтра, внешний поиск/фокус вкладки
и генератор `.command`. Встроенные Base64-исходники также обновлены;
редактирование только видимого URL в `.command` было бы недостаточным.
Файл самодостаточен: Node/npm/Python для запуска на Mac не нужны,
локальный путь нужен только для скачанного файла. Он не обновляется сам.
Оболочка опрашивает результат до 120 раз с интервалом 0.25 секунды;

кода; новые ограничения расследованием не вводились.

## Конкретное решение и проект ответа

Техническая замена уже опубликована: использовать файл по проверенному
SHA `c42f4d318c094253ce82ba6947c80a342cda57e0`, а не исходному SHA
из сообщения 667. Нового исправления кода для этого отказа не требуется.
Для подготовки файла можно только скачать и проверить его синтаксис
следующей командой; **она не запускает сценарий и не открывает подпись**:

```sh
curl -fsSL 'https://raw.githubusercontent.com/chivkunovd-bitdenis/WMS/c42f4d318c094253ce82ba6947c80a342cda57e0/scripts/ops/avpack-sold-kiz.command' -o "$HOME/Downloads/avpack-sold-kiz.command" && chmod 700 "$HOME/Downloads/avpack-sold-kiz.command" && shasum -a 256 "$HOME/Downloads/avpack-sold-kiz.command" && /bin/zsh -n "$HOME/Downloads/avpack-sold-kiz.command"
```

Она приведена как предложение владельцу и на компьютере оператора не
выполнялась. Проверить хеш нужно по указанному выше значению. Запуск файла
без `-n` пока не предлагать: в исправленной версии остались **те же 80
замороженных row_id**, не свежий полный набор продаж. Состав unchanged доказан
diff; его актуальность здесь не проверена. Требование out 446 / Telegram 725
дождаться свежего набора сохраняется. Замена URL решает воспроизведённую
ошибку поиска, но не является проверкой права/полноты реального вывода.
