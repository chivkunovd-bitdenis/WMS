1. Model tests используют целые копейки, не `Decimal` для integer columns.
2. Ставка и историческая переоценка проверяются на PostgreSQL INTEGER overflow до записи; ошибка не оставляет частично изменённый тариф, tenant activation или ledger.
3. Backend/E2E ссылаются на зарегистрированные S-31 testcase IDs, включая S-31-TC-017/018.

## Repeat-review repair

- Номер счёта уникален внутри tenant (`tenant_id + number`), а не глобально; два tenant могут независимо получить первый номер своей последовательности.
- `rate × quantity`, integer money и `NUMERIC(precision, scale)` проверяются до `session.add`, savepoint и flush; переполнение не может частично зафиксировать складской факт.
- Invoice API явно возвращает decimal values строками; S-31 нормализует реальные строки перед выводом количества и форматирует строковые копейки без стократной ошибки.
- Глобальная геометрия `AuthedAppLayout` не меняется; ограничение ширины принадлежит только S-31.
- Celery остаётся на прежних UTC semantics. Billing запускается в 23:30 UTC, то есть в 02:30 Москвы, не сдвигая WB-задачи.
- Финальные browser assertions требуют правый заголовок таблицы целиком и ровно три смысловых разделителя в строке детализации счёта — без `· ·`.

## Финальная owner correction

- Переполнение расчёта биллинга перехватывается на границе приёмки и отгрузки: складской документ остаётся завершённым, начисление не записывается, а в финансах сохраняется видимая проблема `billing_calculation_overflow`.
- Пока такая проблема не устранена, счёт за период не формируется даже при наличии других корректных начислений: неполный неизменяемый счёт выпустить нельзя.
- Таблица начислений сведена с десяти до шести колонок без потери данных: дата находится под номером документа, количество/единица/ставка собраны в «Расчёте», исполнитель и проблема занимают одну компактную колонку.
- Детализация источника счёта собирается только из непустых частей в одну строку; двойные разделители невозможны.
- Выбор месяца использует русскую локаль и показывает оператору `Август 2026`, сохраняя прежний API-формат `YYYY-MM`.
