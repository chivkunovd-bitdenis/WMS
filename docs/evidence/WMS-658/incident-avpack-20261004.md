## Что удалось установить

Найдена конкретная цепочка AVPack → **ИП Герус Д.В.**: PDF 0/10 → просьба
владельца вручную привязать → восстановление десяти кодов через TXT → жалоба
на неправильный макет → генерация новых PDF-этикеток агентом. Исторический
журнал подтверждает действия и результат записи; новое чтение production
подтверждает точные документы, коды, связь с товаром и нынешние PDF.

Это наиболее сильный найденный кандидат для исходной жалобы WMS-658. Но
прямой ссылки между bot message 71/Telegram №101 и этим чатом нет. Уточнение
владельца «предположительно Шерин» не заменено фактом о Герусе: отдельно
проверена операция Шерина 135/135. Её имеющиеся данные говорят об автоматическом
успешном импорте, а не о найденном ручном восстановлении из картинок.

**Усечение КИЗа у найденных десяти кодов Геруса не обнаружено.** Все десять
85-символьных `cis_code` с двумя GS (разделитель байт 0x1D) совпадают с
`unmatched[].marking_code` первоначального отказа. Каждый текущий PDF
декодируется в тот же полный payload. При этом нынешний PDF — созданный позже
макет, не доказанное восстановление исходного оформления. Равный DataMatrix
не доказывает равную этикетку; вырезанный PDF также сам по себе не означает
обрезанные данные кода.

## Конкретные сценарии для тестировщика и разработчика

R1–R12 и C1–C23 не переопределяются. Ниже уточнения внутри существующих проверок;
новые номера проверок и новая продуктовая сущность не создаются. RED означает
ожидаемую проверку, которую тестировщик должен сначала доказать падающим запуском,
а не уже выполненный аналитиком тест.

1. **C22/R11, разово: отсутствующий конечный файл.** Подготовить известный источник,
   сохранённый полный код и совпадающий артефакт; вызвать существующий аудит с
   `final_print_pdf=None`. Ожидание: явно незавершённое сравнение конечного файла,
   пробел `final_print_pdf`; отсутствие расхождения не выдаётся за полную сверку.
   По коду `marking_import_audit_service.py` SHA `2531904d...` эта ветка сейчас
   не добавляет `final_print_pdf` в evidence_gaps. Это конкретное основание нового
   RED. Существующий C22 проверяет source-gap, но не этот пробел.
2. **C22/R11 и C11/C15/R6, разово/навсегда соответственно: другой макет с тем же
   КИЗом.** Взять тестовый исходный PDF с читаемыми артикулом и размером; заменить
   сохранённую страницу заново созданной этикеткой с тем же полным DataMatrix,
   но иным текстом/счётчиком. Ожидание: источник и факт подмены макета различимы,
   результат расследования не утверждает «этикетка сохранена» только по равным
   payload. Текущий аудит на `2531904d...` сравнивает только декодированные строки
   и не проверяет происхождение/вид страницы. Тестировщик должен определить
   проверяемый признак/эталон с сохранением пропорционального масштабирования
   и допустимого crop; простое побайтовое равенство всего PDF не подходит.
3. **C11/C14/C22, постоянные печатные и разовое расследование:** PDF с валидными
   КИЗами → товар первоначально не найден → сохранение источника отказало →
   последующее ручное назначение. Подготовка воспроизводит найденные 0/10,
   has_label_artifact=true и тот же набор полных значений. Ожидание по R5/R6:
   данные не усечены; точная PDF-этикетка не заменяется реконструкцией из текста,
   её отсутствие остаётся видимым. Проверить штатный `/import/assign` с исходным
   файлом и без доступного артефакта в тестовой среде. Не добавлять запрет
   оператору из-за отсутствия исходного PDF в архиве, если точный пригодный
   загруженный label artifact уже доступен. Исторический обход через TXT не
   объявляется новой штатной продуктовой функцией восстановления.

Новые тесты аналитик не пишет; разработчик не меняет замороженные ожидания.
Техническую причину «исходный PDF не сохранён + обход через TXT + созданный макет»
не смешивать с исправлением SQL-нормализации. Нельзя вводить blanket-запрет
коротких КИЗов, менять остатки/FBS или настраивать секреты ради этой постановки.

## Что остаётся для приёмки

Нужны доказательные оригинал PDF либо доступная архивная копия с установленным
происхождением, фактический конечный печатный файл и подтверждение связи жалобы
№101 с найденным случаем или другим точным импортом. Недостающий PDF не получать
повторным выпуском/внешней загрузкой. Нынешние сгенерированные PDF нельзя объявлять
оригиналом. Для Шерина три PASS-образца не закрывают весь импорт 135 кодов.

Предъявить аналитику новый SHA после отдельного переноса продукта, неизменённые
контракты, результаты новых RED→PASS сценариев и независимое ревью точного SHA.
Затем выполнить C4/C23 в браузере, отдельно бумагу у оператора, и R10/C19 по
доказанным текущим данным/справочнику в согласованной области чтения. Полный CI
проверяется координатором после заполненной приёмки. Пока подтверждены не все
обязательные проверки, статус WMS-658 — **не принята**.
