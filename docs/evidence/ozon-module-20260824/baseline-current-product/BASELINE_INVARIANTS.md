# Baseline текущего продукта перед Ozon rework

**Дата наблюдения:** 24 августа 2026 года

**Git SHA приложения:** `af0779e1c425eede8d811da666822ff6ed178331`

**Режим:** локальный живой Codex In-app Browser, desktop и narrow; параметр `ozonPrototype` отсутствовал во всех URL.

**Роли:** локальный FF-администратор и локальный тестовый селлер.
**Внешние маркетплейсы:** не вызывались. Для открытия непустых состояний через штатный UI созданы локальные черновики FBO и возврата; для FBS workspace добавлены минимальные строки только в локальную browser SQLite.

Этот документ фиксирует не желаемый Ozon UI, а реально наблюдённый продукт, который нельзя семантически заменить параллельным интерфейсом.

## 1. Очередь FBS

Скриншоты: `01-fbs-queue.png`, `02-fbs-queue-desktop.png`.

Наблюдаемые инварианты:

- один маршрут `/app/ff/fbs`, одна шапка **«Заказы FBS»**;
- верхние действия: **«Обновить»**, **«Забрать заказы из WB»**;
- верхние вкладки: **«Заказы»**, **«Остатки WB»**;
- статусные вкладки: **«Новые»**, **«В работе»**, **«В доставке»**, **«Просрочены»**, **«Завершённые»**, **«Отменённые»**;
- фильтры новых заказов: селлер, **«Склад селлера / WB»**, поиск; отдельной Ozon-панели или route нет;
- таблица новых заказов содержит checkbox и пять смысловых колонок: товар, заказ/сканирование, селлер, склад, дата WB/сборки;
- вкладка **«В работе»** показывает одну строку на поставку и семь колонок: номер/название, селлер, склад, заказы/единицы, короба, статус, дата отгрузки;
- выбор строки поставки открывает существующий FBS workspace поверх той же очереди.

Минимальная Ozon-дельта обязана жить в этой же панели фильтров, этих же статусных группах и этих же таблицах. WB-текст допустим только в WB-контексте; в Ozon-контексте он условно заменяется маркетплейс-нейтральным или Ozon-текстом. Второе действие открытия workspace запрещено.

## 2. FBS workspace

Скриншоты: `12-fbs-workspace-composition-desktop.png`, `13-fbs-workspace-packing-desktop.png`, `14-fbs-workspace-picking-readonly-desktop.png`, `15-fbs-workspace-picking-narrow.png`.

Наблюдаемые инварианты:

- это один modal workspace внутри `/app/ff/fbs`, а не отдельная страница;
- шапка содержит название поставки, селлера, WB-номер, WMS-склад, маршрут, дату отгрузки, общий прогресс и deadline;
- четыре неизменные стадии: **«Состав» → «Подбор» → «Упаковка и маркировка» → «Короба»**;
- в составе две реальные строки заказов; колонки: фото, заказ WB, товар/идентификаторы, количество, маркировка, подбор;
- единственный основной переход из состава — **«Начать работу с поставкой»**;
- при отсутствии адресного остатка текущий backend честно автопропускает подбор и показывает причину; вкладка подбора затем доступна назад только для просмотра;
- read-only подбор сохраняет сканерные поля, ручной подбор и кнопку перехода к упаковке, но блокирует изменение уже завершённого шага;
- упаковка показывает общий счётчик `напечатано/упаковано`, общий print action, bulk packed action, скан стикера заказа и по одной строке на заказ;
- WB-специфичный baseline-копирайт: **«Сдать в Wildberries»**, **«Заказ WB»**, WB-номер и WB deadline. Он не является универсальным текстом.

Ozon обязан использовать тот же modal, header, progress, stage tabs и stage bodies. Ozon-специфичные label/package/hand-over состояния добавляются условными полями и действиями внутри соответствующей текущей стадии. В Ozon-контексте запрещены WB-тексты и developer jargon. Состояние `picked = 0`, `packed > 0` недопустимо: обязательный инвариант процесса — `0 ≤ packed ≤ picked ≤ total`, кроме явно документированного текущего автопропуска подбора, где UI обязан показывать причину и согласованное подготовленное количество.

## 3. Отгрузки / FBO document

Скриншоты: `03-mp-shipments-list-desktop.png`, `04-fbo-document-empty-desktop.png`, `05-fbo-product-picker-empty-desktop.png`, `16-fbo-document-narrow.png`.

Наблюдаемые инварианты:

- один маршрут `/app/ff/mp-shipments`, заголовок **«Отгрузки на МП»**;
- текущий create block содержит селлера и одно действие **«Создать отгрузку на МП»**;
- список содержит семь колонок: номер, плановая дата, создано, статус, селлер, дополнительная информация, строк;
- документ открывается существующим полноэкранным modal **«Отгрузка на маркетплейс»**;
- header: FF-склад, статус, дата отгрузки, **«Склад WB (маркетплейс)»**;
- четыре метрики: план, подобрано, осталось подобрать, упаковано из подобранного;
- три стадии: **«Товары»**, **«Подбор»**, **«Упаковка»**;
- вкладка товаров использует существующие scan/add-product actions и текущий product picker;
- таблица товара содержит текущие WB-поля **«Артикул WB»** и категории WB в picker;
- footer документа содержит единственное утверждение и закрытие; отдельного Ozon-документа нет.

Ozon выбирается в текущем create block. В том же документе условно меняются warehouse/delivery/timeslot/package/label поля. Метрики обязаны вычисляться из одной модели и удовлетворять `0 ≤ packed ≤ picked ≤ plan`, `remaining = plan - picked`. WB-поля должны сохраняться без изменений для WB и исчезать либо обобщаться для Ozon.

## 4. Приёмка и возврат

Скриншоты: `06-reception-list-desktop.png`, `07-return-product-picker-empty-desktop.png`, `08-return-card-empty-desktop.png`, `17-return-card-narrow.png`.

Наблюдаемые инварианты:

- один маршрут `/app/ff/reception`; верхние действия **«Создать приёмку»** и **«Создать возврат»**;
- одна очередь документов с фильтрами селлера, статуса и поиска;
- возврат открывается в существующей карточке документа;
- header карточки: тип, номер, селлер, принято, короба, литраж, вес, статус;
- действия черновика: **«Добавить товар»**, **«Начать приёмку»**, **«Сохранить»**, **«Закрыть»**;
- таблица возврата: товар, габариты, план, принято; ниже существующий блок коробов и грузомест;
- product picker использует тот же каталог селлера и текущие поля WB.

Ozon return обязан входить в эту же очередь и карточку. Возврат в остаток запрещён до явно завершённого осмотра каждой единицы; defect/quarantine/restock являются состояниями существующей строки, а не прямыми взаимоисключающими shortcut-кнопками. Ни одно fixture-действие возврата не имеет права выполнять backend/provider/stock request.

## 5. Каталог

Скриншоты: `09-catalog-desktop.png`, `10-catalog-create-dialog-desktop.png`, `18-catalog-narrow.png`.

Наблюдаемые инварианты:

- один маршрут `/app/ff/products`, вкладки **«Товары»** и **«Короба и грузоместа»**;
- текущие действия **«Загрузить Excel»** и **«Создать товар»**;
- фильтры: поиск, селлер, категория;
- таблица содержит 12 колонок, включая SKU, ШК, остаток, ТЗ, ЧЗ и резервы;
- create dialog содержит WMS-идентичность товара, артикул продавца, размер, один barcode, габариты и ТЗ упаковки;
- отдельного каталога маркетплейса нет.

Ozon offer/product linkage добавляется в существующую строку, row action или текущий dialog. Нельзя создавать Ozon tab, отдельную таблицу или менять WMS SKU как первичную идентичность.

## 6. Настройки селлера

Скриншоты: `11-seller-settings-desktop.png`, `19-seller-settings-narrow.png`.

Наблюдаемые инварианты:

- один маршрут `/seller/settings`;
- сначала сотрудники и права;
- затем существующая карточка **Wildberries** с состоянием ключа и двумя действиями: заменить ключ, синхронизировать товары;
- далее существующая карточка Честного Знака;
- отдельного integration workspace, marketplace-settings route или таба нет.

Ozon получает соседнюю карточку в этом же вертикальном потоке. Client-Id/API key вводятся в существующем dialog pattern; статус подключения и последней успешной синхронизации показан операторскими словами. Кнопки публикации FBS-остатков в S0/S1 запрещены.

## 7. Геометрический baseline

Полные числовые значения находятся в `BASELINE_GEOMETRY.json`.

- desktop наблюдался при фактическом viewport `1600 × 1111`;
- narrow наблюдался при фактическом viewport `433 × 938`;
- FBS workspace narrow: modal `369 × 874`, `scrollWidth = clientWidth = 369`;
- FBO document narrow: modal `433 × 938`, `scrollWidth = clientWidth = 433`; underlying list уже имеет `body.scrollWidth = 960`;
- return card narrow: modal `433 × 938`, без горизонтального переполнения;
- catalog narrow уже имеет широкую таблицу `1284 px` внутри узкого main; это baseline-дефект, который Ozon-дельта не может ухудшать;
- seller settings narrow уже имеет `body.scrollWidth = 1084`; Ozon-карточка не может увеличивать эту ширину или создавать новый горизонтальный overflow.

## 8. Обязательные проверки следующего результата

1. Ни одного WB-текста в Ozon-контексте.
2. Ни одного операторского `fixture`, `projection`, `provider API`, `readback`, `pending`, `uncertain`, `exemplar`, `QUARANTINE`, `mapped` и аналогичного developer jargon.
3. `0 ≤ packed ≤ picked ≤ total/plan`, с явной и согласованной моделью автопропуска подбора.
4. Restock недоступен до обязательного осмотра.
5. Ноль network requests на каждом fixture route, включая initial mount и открытие modal/card.
6. Ни одной пары одинаковых или синонимичных действий в одной зоне.
7. Side-by-side screenshot каждой изменённой зоны относительно перечисленного baseline.
8. Геометрия изменённой зоны не хуже числового baseline; существующий narrow overflow не расширяется.
9. WB path без Ozon-контекста сохраняет тексты, действия, состояния и геометрию baseline.
