# Подбор показывает тару — проверено на стенде руками

Экран: документ отгрузки → вкладка «Подбор», стенд
`https://web-production-9e7c1.up.railway.app`, роль администратор ФФ.
Сборка `9b0ea766`. Проверял 29.08.2026.

## Что было

Экран подбора умел тару с самого макета: у него есть модель мест с видами
`палета / короб / грузоместо / россыпь`, цепочка вложенности и подписи. Но
кормили его выдуманными объектами: в `FfUnloadPickPage.tsx` в список `objects`
передавался **пустой массив**, а место строилось одной строкой на ячейку.
Оператор видел «в ячейке СТЕЛЛАЖ 1.1» и не знал, из какого короба снимать.

## Что сделано

Влиты две готовые ветки: `codex/review-p1-fixes-20260829` (три бэковых P1 из
внешнего ревью) и `codex/pick-containers-20260829` (поле `sources` в обоих
`pick-options`). Конфликт при слиянии был в одном импорте
`fbs_picking_service.py` — нужны оба, оставил оба.

Страница подбора теперь читает `sources`: строит цепочку тары снаружи внутрь и
делает отдельную строку места на каждый физический источник.

Ручка `pick/set` принимает только `storage_location_id`, поэтому строк на ячейке
может быть несколько, а сохраняется сумма по ячейке: при вводе в одну строку
подставляем её число и складываем с остальными строками той же ячейки. Доля
источника режется по порядку, чтобы сумма не превысила доступное — сервер
агрегаты по таре не делит. Сканер тоже понимает тару: держатель строки может
быть коробом.

Экран один и тот же на отгрузку и на ФБС, поэтому подключены оба.

## Данные, на которых видно

На стенде во всех документах товар лежал россыпью, тару показывать было не на
чем. Через ручку карты склада положил короб `WHB-5C71E9B9338A` в ячейку
`СТЕЛЛАЖ 1.1` склада «Тестовый» и переложил в него 20 штук `FBS-TEST-S1-P1`.
Ответ `pick-options` после этого:

```json
"sources": [
  {"quantity": 20, "is_loose": false, "source_label": "Короб WHB-5C71E9B9338A",
   "container_path": [{"kind": "box", "code": "WHB-5C71E9B9338A", "label": "Короб WHB-5C71E9B9338A"}]},
  {"quantity": 28, "is_loose": true, "source_label": "Россыпью", "container_path": []}
]
```

## Что видно и что нажато руками

Открыл отгрузку `№000019`, вкладка «Подбор», раскрыл строку `FBS-TEST-S1-P1` —
в колонке «Где лежит» стоит **«В 2 местах»**, внутри:

```
СТЕЛЛАЖ 1.1 · внутри 54 шт
  FBS test product 1 · FBS-TEST-S1-P1 · S      лежит 34   [поле]
  Короб WHB-5C71E9B9338A · внутри 20 шт
    FBS test product 1 · FBS-TEST-S1-P1 · S    лежит 20   [поле]
```

Ввёл число в поле **строки короба** — ушёл `POST .../pick/set` и вернул **200**,
шапка товара пересчиталась. Перезагрузил экран: сохранённое число осталось на
строке короба.

По дороге поймал, что при вводе числа больше доступного сервер отвечает `409` и
экран честно перечитывает документ, не оставляя оператора с цифрой, которой в
системе нет.

## Чего этот шаг не делает

Запись по-прежнему ложится **на ячейку целиком**: ручка `pick/set` знает только
`storage_location_id`. Значит система видит «сняли 7 из СТЕЛЛАЖ 1.1», но не
«сняли 7 из короба WHB-5C71E9B9338A». Чтобы факт писался по конкретной таре,
нужна отдельная бэковая правка ручки — это не сделано и за это я не ручаюсь.
