## Недостающая адресная проверка настоящего HTTP

`frontend/src/utils/printDirectQr.ts` в предъявленном HEAD и origin/etalon
отправляет body без protocolVersion в `POST /print`. Он читает `result.error`;
вызова `/jobs/<key>/retry` там нет. Нативный `printJob` возвращает существующий
failed_before_submit без schedule, а legacy handler ждёт только saved/submitting
и возвращает общий error. Эти две source-границы требуют проверки R12.

Выполнен `http-recovery-probe.py`; результат — `http-recovery-result.json`.
Проба берёт точный Git source de9 и компилирует всю программу. Изменены только
пути ОС lpstat/lp и appSupport (временное изолированное хранилище); unused CUPS
observer привязан к внешней фикстуре. Настоящие HTTP/Printer/defaultPrinter,
проверка размеров, digest и персистентность не подменялись. Системная очередь,
склад и операторские данные не затронуты; temp executable удалён после пробы.

Подготовлен один valid PNG58×40/ключ same-scan. Сначала lpstat fixture отказывает
при -d и -p. После первого legacy POST fixture восстанавливается. Повторяется
тот же POST два раза, затем передаётся другой ключ с тем же PNG.

Наблюдения:

1. Первый /print возвращает409/failed_before_submit. В reason записано
   «Недоступна служба печати macOS… Этикетка не отправлена… повторите скан»,
   но error — общее «Задание сохранено, приём очередью не подтверждён».
2. После восстановления оба /print с same-scan снова409/failed_before_submit.
   Исходные timestamps/observations сохраняются; никаких новых lpstat/lp
   для same-scan нет. Операторский повтор не инициирует безопасный retry.
3. Новый other-scan сразу200/accepted с receipt Label_Printer-41;
   actual lp содержит media=Custom.58x40mm, copies=1. Значит внешняя фикстура
   восстановлена, отказ same-scan вызван именно программным сохранённым состоянием.
4. Legacy mirror содержит только other-scan с квитанцией; same-scan не стал
   unknown и не отправлялся. Защита от дубля здесь работает, но R12 восстановления
   исходного скана не выполнено. health200 также не означает готовый принтер.

## Требуемая коррекция и границы

По R12 действующий повтор legacy /print с тем же ключом после доказанного
failed_before_submit должен возобновить безопасную попытку, сохраняя отказ
автоматического повтора submitting/unknown/accepted и уникальность отправки.
Конкретная причина отказа должна попасть в error, который читает текущий экран.
Для этого не требуется новая продуктовая стадия или расширение frontend.
Технический способ выбирает разработчик; исходное R12 не смягчается.
После коррекции нужна предметная перепроверка HTTP восстановления, причины
ошибки и защиты unknown/одновременного повтора, затем новая приёмка exact SHA.

Нет новой дистрибутивной сборки, Direct package CI, immutable URL/checksum,
установки, штатных разрешений на клиентском Mac, live CUPS/бумаги или Telegram.
Ранние ed053 emulator/QR результаты не объявлены проверкой candidate de9.
main/production/652 не изменены. Product source сохраняется de9.

fixtures и затем заполнить ссылки тестов отдельным контрактом до installer-кода.
