# WMS-607: startup owner — контракт до коррекции

Отдельный тестировщик `01a11389`, Sol 6.1/high. Точная база: `a04a7b35f1e866c1283bdc46fff2d41eaf68b4d6`. Ожидание следует из R-U4/R-U5 и U-C4; продукт, требования и прежние контракты не менялись.

Фактический новый прогон: **1 целевой FAIL, 2 PASS, 0 ERROR, 0 SKIP**. При чужом executable настоящий `owned_pid` получает неподходящий путь от `ps` и возвращает status2. `health_ok` отказывает; настоящий `start_owned` затем продолжает опрос/ожидание и сообщает общий отказ readiness. Новый тест требует nonzero с причиной чужого владельца, без последующего startup sleep/poll, принятия foreign health200 или сигнала чужому процессу. Это содержательное падение утверждения на текущем скрипте, не ошибка подготовки.

Обычный собственный здоровый процесс проходит настоящую проверку ownership, HTTP JSON и readiness. Отсутствие владельца во время прогрева допускает ожидание до собственного ready. Числовое окно/число опросов не задаётся. Временные COPY-мутации actual source — отказ от подтверждённого health и отказ от прогрева — вызывают по одному целевому assertion FAIL без ERROR/SKIP. Копии удалены.

Исполняется неизменённый полный блок shell-функций `port_pid` → `start_owned`, вместе с настоящим JSON helper. Внешние `lsof/ps/curl/nohup/sleep` контролируются; `kill` блокирует и фиксирует любые сигналы наблюдаемому владельцу. Real temporary files/work/state, native macOS plutil и реальные shell decisions не заменены моделью. Readiness-команда — внешний безопасный stub. Nohup представляет только собственный безвредный shell, ожидающий временный FIFO: встроенный `kill -0 "$child"` и ветка `wait` в продукте не переписаны. FIFO освобождается после результата, без TERM или изменения controller signal/wait scope. Ни порта, ни native приложения, ни CUPS/provider действия нет. Журнал содержит синтетические сохранённые receipt/unknown bytes и остаётся неизменным.

Сохранённые package receipts `71640d0c1160049f085bc6b524581ff25a804b1c` прочитаны из Git: run37579919987/attempt1, source точно a04, ARM33 PASS; Intel9 PASS/1 ERROR (`TimeoutExpired(15s)`, UC4), payload отсутствует. Их manifest и точные XML bytes проверены. Новый контролируемый случай **не доказывает историческую причину Intel CPU/timing** и не делает failed run успешным. Повторного Intel/ARM/package прогона не было.

Старые10 + rollback4 + existing19 сохранены побайтно; 15s в старом контракте неизменны. Их тесты, компиляция, CI и browser не запускались.
