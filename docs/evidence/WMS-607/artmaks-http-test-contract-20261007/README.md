# WMS-607: HTTP-контракт до исправления ArtMaks

Контракт фиксирует два непринятых случая P-A5/P-A6 на продукте
`de9f31a464fc09df26c6a77b488c904ea3ec19e2`, база требований и приёмки
`77443e92dba2872993ee358cfb7c4c88279b47c8`. Продукт не исправлялся.

Настоящий полный Swift-код компилируется и запускается обычным серверным
входом, без `--self-test-http`. Подменены только пути внешних `lp`/`lpstat`
и каталог журнала. Неиспользуемый CUPS-символ нужен для линковки и аварийно
завершит процесс при вызове: успешного наблюдения очереди он не имитирует.
Запросы идут только в собственный localhost-процесс; принтер не вызывается.
Настоящие HTTP parser/handler, PNG-проверка, размер, ключ, журнал, worker
и таймер системной команды остаются в компилируемом коде.

На macOS 26.3 фактический прогон пяти новых случаев дал **2 FAIL / 3 PASS /
0 SKIP / 0 ERROR**, exit 1, 3.587 секунды (включая компиляцию). В
`precode-red.log` сохранены точные ошибки, а в `precode/*.json` — ответы HTTP,
вызовы внешних фикстур, настоящие сохранённые задания и происхождение исходника.

Первое падение: после доказанного `failed_before_submit` и восстановления
`lpstat` два повторных legacy POST с исходным ключом всё ещё дают 409. Новый
контрольный ключ получает 200/квитанцию, поэтому восстановление службы
подтверждено до целевого утверждения. После исправления ожидаются 200 для
обоих повторов и ровно одна отправка исходного задания; размер 58×40 мм и
одна копия проверяются по фактическим аргументам `lp`.

Второе падение: конкретный `reason` о недоступной службе macOS и отсутствии
отправки не входит в `error`, который читает существующий frontend. Контракт
разрешает добавить контекст к сообщению, но требует сохранить саму причину.

Три успешных случая защищают неизвестный внешний исход, текущую передачу и
полученную квитанцию от повторного `lp` или перезаписи намерения. Для состояния
`submitting` удерживается только внешний `lp`; реальный повтор protocol-v2
наблюдается до освобождения команды, затем legacy POST получает её квитанцию.
Для `unknown` внешняя команда реально возвращает ошибку без квитанции: это
не доказательство отсутствия бумаги. Восстановление внешней команды не
разрешает автоматически повторять такой ключ. CUPS-наблюдение и перезапуск
не проверяются новым набором: исходные замороженные 6/5/3 остаются неизменными.

Команда разработки, из корня checkout на macOS:

```sh
python3 tools/print-agent/test_macos_artmaks_http_contract.py -v
```

Для сохранения сырых ответов можно задать `WMS607_HTTP_EVIDENCE_DIR` отдельным
каталогом. `WMS607_SWIFT_SOURCE` выбирает исходник для проверки временной копии,
не меняя тест или продуктовый файл.

Контроль чувствительности:

```sh
python3 docs/evidence/WMS-607/artmaks-http-test-contract-20261007/mutation-control.py
```

Он временно оставляет защиту существующего ключа только для
`failed_before_submit`. Все три случая сохранения должны упасть, без ошибок
инфраструктуры; сам контроль возвращает 0 только при этом результате.
`mutation-red.log`, `mutation-result.json` и `mutant/*.json` сохраняют
фактические нарушения. Тесты и tracked Swift не переписываются.

В требованиях добавлены только ссылки «Тест» у P-A5/P-A6; отрицательные
вердикты аналитика остаются. Это фиксация тестов до кода, не повторная приёмка,
не выпуск ArtMaks и не часть основного WMS-652 релиза.
