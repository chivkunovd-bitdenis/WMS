# WMS-607: контракт автообновления Mac до кода

Отдельный тестировщик `gpt-6.1-sol/high` зафиксировал автоматические U-C1–U-C8 на принятой программной базе `756b45a4d46b9e9a33657549e2c2addb6bae89c1`. Эта сессия ранее рецензировала HTTP-исправление, но не писала продуктовый код. Будущую реализацию обновления должен проверить другой независимый ревьюер. Поручение владельца и требования R-U1–R-U8 сохранены; нового согласования не требуется.

На этой базе нет Direct-входа автообновления. Фактический прогон: **10 проверок, 2 PASS, 8 FAIL на явном `NOT IMPLEMENTED`, 0 ERROR, 0 SKIP**. Восемь отказов означают отсутствующую интеграцию, а не воспроизведённые ошибки работающего установщика. Ни импорты, ни компиляция не являются причиной этих отказов. После добавления входа те же тесты вызывают настоящий bash CLI и проверяют наблюдаемые файлы, архивы, журнал и команды; тестовая реализация обновления не написана.

Две проверки сохранности уже выполняют существующий продукт: полный `build_console.main` с внешними компилятором/архиватором и настоящие Swift `Printer` из публичной `.4` и текущей версии с внешним submit. Они проверяют Direct-метаданные и повтор сохранённых receipt/unknown без новой отправки. Обе проверки отдельно падают утверждением на временной копии с целевой порчей: `runtime=paired` либо обход сохранённого ключа. По одному FAIL, ноль ERROR/SKIP; копии удалены, исходники не изменены. Первоначальная исправленная ошибка подготовки драйвера хранится отдельно как `harness-development-error.log` и не входит в доказательство RED.

Технический вход контракта: `tools/print-agent/update_macos_direct.sh --app-dir … --state-dir … --backup-dir … --manifest …`. Все каталоги временные. JSON задаёт pinned source и отдельные ARM/Intel URL/SHA256; URL `fixture.invalid` и крошечные ZIP являются внешними фикстурами, не выпущенными пакетами. Если разработчик выберет другое имя реального bash-входа, допустим `WMS607_UPDATER_ENTRY`; адаптер, реализующий обновление вместо продукта, недопустим. Метаданные и флаги — тестовое подключение к настоящей операции, не новые пользовательские правила.

Аппаратные ответы, скачивание, native-архитектура, процессы, health и разрешения контролируются на внешней границе. Только абсолютные пути перечисленных OS-команд заменяются в временной копии входа; алгоритм установки, проверки, архивирования и rollback не заменяется. ZIP, прежние bytes/права/ссылки, их восстановление и Swift-журналы настоящие. Исполняемый файл внутри ZIP — внешняя фикстура запуска, не настоящий Swift-пакет. Нативные `Printer` компилируются отдельно из неизменённых классов; CUPS submit/queue подменены, наблюдатель запрещён. Host Library, default printer, чужие процессы и физическая печать не затрагивались.

Контракт охраняет выбор ARM/Intel/Rosetta; отказ до изменения при неверном пакете; полный уникальный архив; собственность процесса; rollback без отката текущих receipt/unknown; повтор, конкуренцию и прерывание; реальный replay совместимых журналов; штатный отказ разрешения и безопасное продолжение. Полноценную конкурентную работу реального принтера или разрешения ОС эти внешние фикстуры не доказывают. U-C9/U-C10 остаются ручными с пустыми Test/Вердикт. В требованиях заполнены только восемь ячеек Test; классы, ожидаемое поведение и вердикты не менялись. Все прежние файлы `tools/print-agent`, включая frozen6/resolver5/native3/HTTP5, сохранены побайтно.

Команда для реализации (из постоянного checkout на macOS с уже имеющимся Swift):

```sh
WMS607_UPDATER_EVIDENCE_DIR=/path/to/review-owned/raw \
python3 -B docs/evidence/WMS-607/updater-test-contract-20261007/run-contract.py \
  --report /path/to/review-owned/macos-direct-updater.xml
```

Десять точных XML-ID, исходная замкнутая группа файлов, команды и SHA256 записаны в `contract.json`; фактические исходные логи/XML и JSON операций приложены. `source-probe.py` воспроизводит проверку сохранности и исходных квитанций на этом frozen checkout без запуска тестов. `manifest.json` закрепляет байты доказательств.

Следующий этап — отдельный разработчик с неизменяемыми ожиданиями этого контракта, затем другой ревьюер и исходный аналитик. Перед GREEN нужно выполнить весь новый контракт на настоящем updater, без SKIP/ERROR и без тестовой подмены его алгоритма. Пакеты/доставка/установка клиенту, CI, реальные разрешения и физическая этикетка здесь не выполнялись; приёмка автообновления не заявляется.
