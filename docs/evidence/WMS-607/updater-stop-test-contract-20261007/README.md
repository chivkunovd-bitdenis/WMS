# WMS-607: дополнительный контракт остановки при rollback

Отдельный тестировщик Sol 6.1/high фиксирует P1 из независимого ревью `30ffc6bce9fffcdc1b4e0b95b9c8782bfb41896c` **до исправления разработчиком**. База — `6232cf29765f1b25466e96919ee7840bf5874c62`. Это уточнение автоматической защиты существующих R-U4/R-U5/R-U6 и U-C4/U-C5/U-C6, не новые требования и не приёмка.

Новый отдельный файл вызывает неизменённый блок настоящих shell-функций от `port_pid` до конца `rollback`, включая принадлежность процесса, остановку, inventory и очистку transaction. Функция hash также взята из исходника. Временный драйвер задаёт только пути/исходное состояние и вызывает `rollback || result=$?`, как реальная обработка отказа. `ps/lsof/kill/sleep` — управляемые внешние ответы. Файлы, права, ссылки, renames, удаления и сравнение дерева выполняются настоящими командами macOS. Никакого сервера, порта, запуска приложения или принтера нет.

Реальные временные файлы журнала содержат синтетические accepted receipt/unknown и сохранённый payload. Они проверяются на побайтную сохранность, а не выдаются за выполненную печать или новый replay Swift. После TERM fixture хранит независимый alive-файл: успешный TERM может оставить его, ошибка TERM тоже; успешная остановка удаляет его. Ни один настоящий PID не используется.

Фактические четыре случая: **2 целевых FAIL, 2 PASS, 0 ERROR, 0 SKIP**. При TERM-success/survivor и TERM-error код действительно возвращает неуспех, но под живым собственным процессом ставит предыдущие app bytes, расходует `work/previous`, удаляет recovery intent и переводит transaction в 0; в конце ошибочно сообщает foreign. Тесты требуют оставить target, прежнюю копию, архив, intent/transaction и текущий журнал до безопасной остановки, сообщив именно owned-stop failure. Падения — утверждения о наблюдаемом результате, не ошибки подготовки.

Положительные случаи закрепляют текущие границы: успешная owned-остановка восстанавливает предыдущую application, завершает transaction и сохраняет журнал; подтверждённый foreign owner не получает сигнал, application-only recovery завершается, restart не заявляется и результат остаётся nonzero. Для обоих проверок временная порча копии исходного shell-кода вызывает по одному содержательному FAIL без ERROR/SKIP: пропуск очистки intent и обход двух проверок принадлежности. Копии удалены; исходный updater не менялся.

Запуск только нового контракта:

```sh
WMS607_STOP_RAW=/path/to/owned/raw \
python3 -B tools/print-agent/test_macos_direct_updater_stop_contract.py \
  --report /path/to/owned/updater-stop.xml
```

На macOS используется настоящий `/usr/bin/stat`; на другой ОС SKIP не является приёмкой. `contract.json` содержит точные четыре XML-ID, SHA256 и команду; исходный результат и контрольные мутации приложены. `source-probe.py` проверяет байты/квитанции без повторного запуска. Старый контракт `a40bf5b9a2f833a16cb9ff8c941c46c02a0b9d72`, все его 28 файлов теста/доказательств и требования неизменны. Старые десять тестов, сборки и CI не запускались.

Разработчик получает неизменяемые ожидания и возвращается с коррекцией в свою сессию. После исправления нужны адресный GREEN и отдельное независимое ревью. Здесь нет реализации, аналитической приёмки, установки клиенту, выпуска пакетов или физической печати. Точный коммит замороженного теста передаётся в `result.md` отдельной записью после фиксации.
