# WMS-672: render-consumption proposal before implementation

The completed trace in commit185447983635437533cfe49e8418c3e451c76233 demonstrates admission saturation for valid native images. This proposal changes preparation lifecycle, keeping original PNGs and the printed document unchanged. It is not yet implemented or proven by a Linux counterfactual.

For the awaitable inbound handoff only, temporarily give the existing print iframe a small nonzero viewport which can participate in raster preparation. It remains aria-hidden and pointer-inert; it adds no operator control or preview. Lay out only the active parallel cohort of the original image elements as small nonoverlapping thumbnails. Their temporary image-rendering must be auto, rather than the original pixelated. Continue to require the actual image.decode() calls and the existing drain of every started peer on failure. After cohort success, allow the existing rendering boundary before starting the next cohort.

Before beforeTransfer/print, restore every original inline style and the original iframe geometry. Persist and hand off the exact original full HTML, original PNG sources, label order, physical page dimensions and original pixelated print appearance. All300 native decodes must succeed before the single transfer. Genuine native failure continues to abort and preserve its first reason after draining peers; no retry, loaded-image fallback or partial transfer is introduced. Non-handoff scan printing remains unchanged.

Exact Chrome141 source provides the causal route, not a web API guarantee of paint completion. TileManager calls ConvertImagesToTasks and then DecodedImageTracker.OnImagesUsedInDraw for raster/prepaint images; the tracker erases the successful explicit-decode lock by stable image ID. CacheKey.FromDrawImage uses a smaller scaled/mip target for an ordinary filtered thumbnail, whereas nearest-neighbor/pixelated forces the original dimensions even for a tiny displayed image. A hidden CPU canvas, opacity0, zero-size or fully culled offscreen frame is not assumed to exercise that route. Preparation geometry must avoid those conditions while remaining visually unobtrusive.

Separate testwriter contract must freeze the lifecycle invariant before product code: active-cohort raster eligibility and ordinary filtering; no next-cohort start before a rendering boundary; original style/source restoration before the single transfer; all-native-ready, strict error/drain and stalled-parent-frame behavior remain guarded. Do not freeze an arbitrary engine budget, private retention delay or exact viewport/group size. The already frozen7+2 and11/C5 remain unchanged.

The one actual Linux141 comparison must preserve C5 and additionally inspect native original-key Unref/Remove relative to cohort raster work. A PASS alone cannot prove the suggested unlock route, and failed eligibility would be reported without numeric tuning or error masking.
