# WMS-672 · Дополнительный контракт завершения активных декодирований

Отдельный замещающий тестировщик Sol 6.1 возобновлён ведущим 07.10.2026. Это стадия **тесты до нового кода**, не собственное ревью или продуктовая приёмка. База опубликованного общего кандидата — `565559aaff73e5a2f0fb436cac1032a4856a8379`; продукт двух файлов равен предыдущей коррекции `9e757a02c`. Новый механизм завершения peers (уже начавшихся параллельных декодирований) ещё отсутствует.

## Граница требования и доказательства

Исходные R3/R4/C5 требуют корректного выхода из подготовки после известной ошибки, отсутствия частичной передачи и ложных отметок, а затем явного повторения исправленной подготовки. Действующая `inboundLabelPrinting.current` удерживает одну попытку; она не должна освобождаться, пока её начатая работа ещё продолжается. Новая проверка закрепляет техническое завершение этой попытки: сначала заканчиваются уже начатые декодирования, затем очищается iframe и снимается busy. Следующие группы после известного отказа не требуются и не запускаются. Размер группы, число одновременно начатых работ, срок в секундах и конкретный способ реализации не задаются.

Наблюдение Linux C5 о незавершённых внешних wrapper promises не доказывает активность native decoder внутри Chromium. Более того, независимый источник `6edd7ccc` содержит успешный повтор после отказа150 при15 таких незавершённых обещаниях; при299 были11. Счётчики не объявляются причиной engine-сбоя. Новый контролируемый тест отдельно доказывает преждевременную очистку при **действительно удерживаемом** Promise декодирования. Устранение этого дефекта ещё не означает исправление общего Linux C5: неизменный сценарий Chromium141 должен подтвердить результат после реализации.

## Тест и реальные исходники

[Новый файл](../../../../frontend/tests-e2e/wms672-peer-drain.test.mjs) исполняет фактический `printBarcodeLabel.ts` и всю функцию `printInboundInternalLabels`, извлечённую AST TypeScript по имени без переписывания её тела. Используется parent jsdom и настоящий дочерний DOMException; image.decode заменён контролируемой внешней границей, storage/HTTP/print синтетические. Здесь нет настоящего PNG decoder, React/MUI-рендера, принтера или production.

1. Первый native EncodingError возникает на втором decode; остальные начатые peers удерживаются. Peer с первым входным индексом после снятия hold тоже отклоняется с другой причиной. До hold-release iframe должен жить, операция оставаться незавершённой, busy и текущая попытка — активными. После завершения всех начатых peers ожидается **именно первый** объект ошибки и его исходная причина, без следующих групп, source-save, print и mark POST.
2. Второй случай синхронно бросает DOMException на втором decode при уже удерживаемом первом peer. Он требует той же последовательности; начатые успешные peers действительно заканчиваются до cleanup. Это проверяет, что синхронный throw не бросает уже начавшуюся работу.

Повторная попытка защищена реальным guard функции: тест наблюдает, что `inboundLabelPrinting.current` остаётся true до завершения peers и становится false после cleanup. Дополнительное UI-подтверждение во время hold не вызывается; фактический успешный исправленный повтор300 сохраняет прежний браузерный C5.

```sh
node --test --test-reporter=tap frontend/tests-e2e/wms672-peer-drain.test.mjs
```

[Pre-code TAP](precode-red.tap) (только конечные пробелы нормализованы для Git; точный исходный поток — [gzip](precode-red.tap.gz), SHA256 в contract.json) фиксирует **2 FAIL, 0 PASS, 0 skip/cancel** по ожидаемому assertion `failed tape source must live until held active decode peers settle`, а не по setup/import. В async-случае при очистке15 peers pending, после release14 успешно готовы и один вторично отказал; в sync-случае при очистке1 pending, после release он готов. В обоих наблюдениях до release iframe уже отключён, операция завершена, busy/guard сняты. Это управляемая оснастка, не счётчик native Chromium.

Прежние семь выполнены: [7 PASS,0 FAIL,0 skip](existing-seven.tap). Прежние семь `05a7d08a65e135256fa69e8bf84519e95bcdef96` и11/C5 остаются побайтно неизменными. [Метаданные](contract.json) содержат точные новые2 имена, ожидаемый отдельный CI-артефакт `release-print/672-peer-drain.tap`, зависимости исполнения и сохранённые SHA256 старых файлов. CI wiring/registry/ссылки требований остаются у интегратора/аналитика. Существующие `672-native-errors.tap` и `672.json` не заменяются новым отчётом.

## Передача

Разработчик получает опубликованный контракт до нового механизма, повторяет RED на базе+контракте, реализует только продукт, затем проверяет тот же неизменный контракт. Независимая сессия проводит ревью и отдельный аналитик — приёмку; тестировщик не принимает собственную дельту. Сохранённый RED не является пройденным CI или разрешением объявить общий релиз готовым. Linux C5 после реализации, весь итоговый CI и выпуск сохраняют самостоятельные доказательства.
