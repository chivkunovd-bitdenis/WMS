# WMS-672: независимое техническое ревью узкой native decode дельты

**Техническое ревью исходников PASS, замечаний нет.** Проверен product fix
`9e757a02cefa0cd1f7a95d272944e0b7c2b0660a`, включённый без изменения продуктовых
байтов в общий источник `296107aafcf44d1ac5afa623d32c644fa5396233`.
Эффективность изменения в Linux, продуктовая приёмка и переход доверенного
product reference пока ожидаются и этим промежуточным вердиктом не объявляются.

Дельта состоит ровно из двух файлов: пять добавленных и две удалённые строки.
В catch функции `printInboundInternalLabels` доступное непустое строковое
сообщение теперь читается независимо от конструктора Error родительского окна.
Это позволяет сохранить сообщение DOMException из iframe; пустое, нестроковое
или отсутствующее сообщение оставляет прежний generic fallback. `finally`,
снятие reentrancy/busy, уборка iframe и порядок source/transfer/marks не менялись.
Сообщение показывается существующим способом через `setError`, нового HTML
рендеринга или нового пользовательского действия нет.

В `printBarcodeLabels` группа decode уменьшена с 32 до 16 только для awaitable
handoff пути приёмки. Внутри группы остаётся Promise.all; каждая группа обязана
успешно завершиться, прежде чем выполнение дойдёт до print. Прежние parent-frame
yielding и timer fallback сохранены. Нет игнорирования decode errors, скрытых
повторов печати или частичной передачи; non-handoff scan-to-print путь не менялся.
Меньшая группа увеличивает число прежних пауз между группами. Проверяемый
источник сам по себе не доказывает достаточность такого изменения для Chromium.

До реализации отдельная роль зафиксировала контракт
`05a7d08a65e135256fa69e8bf84519e95bcdef96`; новый тестовый файл побайтно сохранён.
Новые семь случаев исполняют настоящую screen operation и настоящий utility
с управляемыми платформенными границами jsdom. Они проверяют перенос сообщения
iframe DOMException, прежний fallback, отсутствие успешных действий при отказе,
перекрытие подготовки и готовность всех 300 изображений до source save/передачи.
Они не являются фактическим нативным PNG-декодированием Chromium.

Подключение к CI в `f528152ca04ccf2d86207b95ee3de0b96141948f` также просмотрено:
команда выполняет семь случаев без подавления ошибок; отдельный raw TAP сохраняется
в release-print, последующий runner его не удаляет, process-proof скачивает его
в `print/672-native-errors.tap` и требует ровно семь имён. Все прежние определения
suite сохранены. На этом pre-fix источнике сверены actual hashes 227 файлов,
19 suites и 1168 case IDs; это проверка содержимого registry, а не включение pin.

Сохранённый developer TAP до кода имеет три целевых message failures и четыре PASS;
после кода — **7 PASS, 0 fail/cancel/skip/todo**. Прочитаны raw TAP и локальные
typecheck/build receipts с exit 0. Независимая сессия эти уже выполненные проверки
повторно не запускала. Source receipt подтверждён чтением actual Git blobs:
восемь прежних/new test/config/harness файлов сохраняют зафиксированные хеши;
старый C5, его assertions/timeouts/retries, scope helper и frozen 51 scope tests,
CI wiring не менялись от просмотренного pre-fix общего источника.

Независимо исполнен настоящий `product_scope.py` как read-only сравнение:
от прежнего `d61805978b3e7878d1056c99b4e6e0823edf49a5` он сообщает ровно два
проверенных product paths и exit 1; от fix `9e757a02...` сообщает пустой diff
и exit 0. Последний запуск проверяет равенство продукта фиксированному источнику,
но **не одобряет** новый доверенный reference. Его выбор должен последовать после
