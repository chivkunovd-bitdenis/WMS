# PRODUCT_BROWSER_APPROVED

- Проверено в живом Codex In-app Browser: `http://127.0.0.1:15194/ui-kit.html`.
- Перед проверкой страница была перезагружена при viewport `1600 × 1000`.

## Ручной сценарий «Поля формы»

Визуально проверены `MoscowDateInput`, `MoscowDateRangeInput` и управляемый
`PreferenceSwitch`. Поля остаются нормального размера, подписи и контуры не
сдавлены; на панели нет микроскопических элементов.

Кнопки примеров периода были нажаты по очереди:

1. «Обычный период» выставляет `2026-08-01` — `2026-08-07`; оба поля имеют
   `aria-invalid="false"`, ошибки нет.
2. «Обратный порядок» выставляет `2026-08-12` — `2026-08-11`; оба поля имеют
   `aria-invalid="true"`, а связанный через `aria-describedby` текст ошибки:
   «Дата окончания не может быть раньше даты начала».
3. «Слишком длинный» выставляет `2026-01-01` — `2027-01-02`; оба поля имеют
   `aria-invalid="true"`, а связанный текст ошибки: «Период превышает
   допустимую длину».
4. «После допустимой даты» выставляет `2026-12-31` — `2027-01-01`; оба поля
   имеют `aria-invalid="true"`, оба видимых сообщения и соответствующие
   `aria-describedby` сообщают: «Дата вне допустимого диапазона».

`PreferenceSwitch` («Показывать дополнительные сведения») переключён из
`false` в `true` и обратно в `false`; значение управляемого поля меняется и
возвращается корректно.

## Геометрия

Горизонтального переполнения нет.
