# WMS-477 — Chrome reproduction of Astra findings 1, 2 and 4

21.09.2026, проверяемый продуктовый код:
`69b3f2ccc119e7a9ec67eeb629d4e96e69a6b414`.
Изолированная ветка `codex/wms477-astra-ui-repro`; release branch не менялась.

Использован настоящий установленный Google Chrome, headless, 1440 × 1000.
Оснастка импортирует настоящий `FfFbsSupplyWorkspace` и `ErrorBoundary` WMS-484;
продуктовые файлы не подменяются. Только ответы `window.fetch` создаются из
синтетических данных и удерживаются до явно заданного события. Часы Playwright
ускоряют ожидание, исполняя неизменённые продуктовые `setInterval`/`setTimeout`.
Ни production, ни backend, ни WB не вызывались. Это наблюдение React-компонента
в браузере, не только исполнение извлечённых функций в памяти.

## Запуск

Нужны Python с Playwright, установленный Chrome и frontend/node_modules проекта.
Из корня этого checkout:

```bash
python3 docs/evidence/WMS-477/astra-ui-repro/reproduce.py
```

Скрипт копирует оснастку в игнорируемый `frontend/tmp/wms477-astra-repro`, поднимает
свой Vite на `127.0.0.1:5577` с `--strictPort` и завершает только свой процесс.
Другой свободный порт: `WMS_QA_PORT=5578 python3 .../reproduce.py`.
Результат и скриншоты — `local/result.json` и `local/*.png` рядом со скриптом.
`baseline-result.json` сохраняет точные события и DOM-текст успешного
воспроизведения на исходном SHA. Все четыре `bug_reproduced=true`, pageerror — 0.
Скрипт намеренно проверяет наличие исходных дефектов; после исправления его
старые bug-assertions должны перестать выполняться.

## Дополнительная C23: WMS-484, клиентская ошибка и физическое изменение DOM

Запуск на том же продуктовом SHA:

```bash
python3 docs/evidence/WMS-477/astra-ui-repro/boundary.py
```

21.09.2026 выполнены три сценария в Google Chrome 153.0.0.0. Скрипт завершился
с кодом 0. `boundary-result.json` содержит фактическое состояние DOM до/после,
а также перехваченные сообщения `/client-errors`. `boundary-fallback.png`
осмотрен: видны панель изолированной оснастки, текст ошибки и кнопка «Обновить»;
страница не превращается в пустой экран или стандартную ошибку React Router.
Локальные повторные прогоны пишут в игнорируемый `local-boundary/`.

| Сценарий | Наблюдение и вердикт |
|---|---|
| Одно клиентское исключение внутри настоящего ErrorBoundary | Синтетический сосед FBS выбрасывает исключение в layout effect. Ошибка отправляется в mock client-errors с component=FfFbsSupplyWorkspace; после автоматической повторной отрисовки FBS доступен. Пройдено. |
| Три повторных исключения при попытках восстановления | После предусмотренных повторов появляется настоящий fallback с текстом «Не удалось показать этот раздел. Обновите страницу.» и кнопкой. Нажатие настоящей кнопки перезагружает страницу, FBS снова доступен. Пройдено. |
| Физическое удаление DOM-узла FBS | В Chrome удалён настоящий React-owned узел размера A1 через element.remove(). Следующий mock workspace убирает столбец размера. React пытается удалить уже отсутствующий узел и выбрасывает реальный NotFoundError/removeChild; методы DOM не подменялись. ErrorBoundary перехватывает ошибку, client-errors получает stack, FBS автоматически восстанавливается. Пройдено. |
| Опрос до ошибки и после возвращения к работе во всех трёх сценариях | Выбрана A1, скан стикера активирует её, оставлен фрагмент следующего скана 010460PARTIAL. После 15000 ms приходит новый accepted. Ввод, выделение checkbox, активная строка и фокус сохранены, вердикт обновлён. Пройдено. |

**Граница сохранения состояния:** само восстановление после исключения пересоздаёт
дочерний компонент. В двух сценариях автоматического восстановления наблюдались
пустой ввод, отсутствие выбранного checkbox и активной строки. Доказательство
сохранности относится к обычному 15-секундному опросу после повторного ввода и
выбора оператором, а не к переносу несохранённого ввода через падение или reload.
JSON сохраняет эти сбросы явно; проверка их не скрывает.

Искусственная ошибка вводится только в оснастке; физическое удаление выполняется
только в изолированном браузере с синтетическими данными. Полная оболочка портала,
историческая причина production-инцидента, расширения браузера и живой WB здесь
не проверялись. Проверены настоящий FBS-компонент, ErrorBoundary и клиентский
репортёр из SHA 69b3f2. Production не вызывался. Release branch не менялась.
