## Починено в бэке

Первая правка связала создаваемые палеты, короба и грузоместа с конкретной
приёмкой. Добавляющая миграция `20260830_0242` создаёт nullable-ссылки, старый
глобальный сценарий создания без документа сохранён.

Вторая правка добавила постоянную ячейку входящим коробам и грузоместам.
Миграция `20260830_0243` только добавляет nullable-поля; её `downgrade` намеренно
не удаляет данные, потому что задание запрещает разрушительные миграции.

Третья правка включила в карту остатки незавершённой приёмки и номер исходного
документа. Уже оприходованная часть по-прежнему приходит из складских остатков,
а незавершённая — только как разница `quantity - posted_qty`, поэтому одна и та
же часть товара не считается дважды.

Четвёртая правка исправила прогресс подбора: `picked` теперь считается по
физическому источнику, опустевший источник остаётся в ответе с доступным
количеством 0, а проверка доступности сравнивает физический остаток только с
новой дельтой, не с накопительным итогом.

Пятая правка расширила существующие scan-эндпоинты MP и FBS. Скан тары теперь
возвращает `kind=container`, её тип, идентификатор, номер и корневую ячейку;
следующий скан товара может передать эту пару и списывает товар из указанной
тары. Новый роут не добавлялся.

## Осталось фронту

### A-03: передавать документ при создании тары

В `FfSortingObjectsPage.tsx:146-154` функция `createObject` должна при
`embedded && inboundRequestId` добавлять в JSON поле `inbound_request_id`.
Backend уже принимает его. После успешного ответа остаётся прежний `load`, но
он вернёт объект именно в выбранном документе.

### Б-04: искать тару по документу

В `WarehouseMapTypes.ts:21-31` нужно добавить nullable-поле
`source_document_number`, а в `WarehouseMapRows.ts:94-107` включить его в
`haystack` контейнера. Backend уже возвращает поле для входящей и созданной в
документе тары. Поиск по точному штрихкоду менять вслепую не надо: текущая
`findByBarcode` на строках 323-361 уже сравнивает его, и сначала следует
воспроизвести именно оставшийся barcode-сбой на актуальном bundle.

### Д-05: определить и реализовать момент срабатывания сканера

Сейчас `FfCatalogInboundPackages.tsx:443-475` запускает lookup только на Enter.
Если требование — искать по мере ввода, нужен локальный фильтр списка для
частичной строки. Для сканера без Enter нужен явный вызов `lookup` на blur или
по настроенному терминатору сканера. Нельзя запускать серверный exact lookup на
каждый неполный символ: это создаст гонки и ложные «не найдено».

### Е-06 и Ж-01: не отправлять каждую цифру как завершённое количество

Связка `handlePlaceQtyChange` → `applyDelta` → `onSetPicked` на строках
`UnloadPickScreen.tsx:174-205` должна держать локальный текстовый черновик и
фиксировать итог на Enter, blur или коротким debounce (задержкой после конца
ввода). Нельзя делать поле disabled после первой цифры; при запросе нужно
сериализовать сохранения конкретной строки и откатывать только её при ошибке.
Backend теперь возвращает сохранённое `source.picked`, поэтому после reload
значение можно восстановить без догадки.

### Ж-02 и Ж-03: закончить сканер места/тары/товара

В `ScannerLine.tsx:97-113` blur должен вызывать тот же безопасный submit, что и
Enter, если непустое значение ещё не отправлялось. В
`FfUnloadPickPage.tsx:103-112` тип результата нужно расширить вариантом
`container` и полями `container_kind`, `container_id`, `container_code`.
Обработчик на строках 407-481 должен при таком ответе выбрать `objRef`, а при
следующем скане товара отправить вместе с `storage_location_id` выбранные
`container_kind/container_id`. `UnloadPickScreen.tsx:230-275` также должен
обработать `container` отдельно, а не проваливаться в ветку товара.
