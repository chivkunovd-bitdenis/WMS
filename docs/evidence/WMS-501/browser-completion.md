# WMS-501: продолжение — реальный браузер, 2026-09-21

Аналитик провёл шесть ограниченных сценариев в настоящем Chrome через CUA. Открыт только выделенный frontend `127.0.0.1:5541`, proxy на backend `127.0.0.1:18451`; PostgreSQL `127.0.0.1:55451/wms501_browser2`. Пользователь, селлер, товары, документы и учётные данные синтетические. Исходный код продукта соответствует baseline `3e125074`; изменения аудита не подменяли компоненты или HTTP-обработчики продукта.

Запуск воспроизводим через [browser-runtime.sh](browser-runtime.sh), fixture через [browser-seed.py](browser-seed.py). Seed намеренно удаляет/создаёт схему **только** exact-DSN disposable БД после assert. Не запускать его на другом окружении. [browser-fault-app.py](browser-fault-app.py) оборачивает настоящий ASGI приложения: управляемо задерживает запрос или заменяет один ответ; контроль хранится в `.audit-runtime/browser-fault.json`. [browser-fixtures.json](browser-fixtures.json) содержит идентификаторы. [browser-http.jsonl](browser-http.jsonl) содержит метаданные фактических HTTP-запросов, без токенов/тел запросов. [browser-state.py](browser-state.py) читает серверные значения после UI-действий.

## Существенное уточнение охвата сортировки

На текущем `/app/ff/sorting` открыт `SortingObjectsScreen` через `FfSortingObjectsPage`, **не** прежний `FfInboundSortingPanel`. Старый handler `distribution-scan` с `scanBusy` нельзя выдавать за browser finding активного маршрута. Текущий экран сканирует ячейки/тару, а россыпь размещается плюсом/перетаскиванием; товарный barcode осмысленно отвечает «ни ячейка, ни объект этой приёмки». Это также описано в `frontend/src/content/knowledge/02-razmeshchenie.md`. Старый S5 остаётся code finding для соответствующих legacy/FBS handlers, с отдельной проверкой достижимости каждого.

В B5 два запроса действительно перекрывались: request004374db start1790005514.71937/end1790005529.777174; request46d47d0a start1790005520.025211/end1790005520.06587. Полные значения сохранены в HTTP-журнале. После reload страницы/перечитывания active cell сбрасывается, но оба объекта подтверждены сервером и UI. Положительный сценарий не исключает гонки с другим размещением тех же остатков.

## Границы доказательств и исключённые попытки

Это наблюдаемая работа локального браузера на synthetic данных, не production browser acceptance, не физический ТСД и не камера. Профиль скорости сети и пользовательские устройства не измерены; UI p50/p95/p99 не получены. Две вкладки разделяют один localStorage, поэтому не подменяют два независимых физических устройства. Общий frontend preload/polling остаётся рассмотренным в [frontend-performance.md](frontend-performance.md).

При первоначальной попытке global `typeText` без input запроса не возникло; эта попытка не засчитывалась как скан. Для B1/B2/B3/B4/B6 использованы настоящие отдельные keydown+Enter. В сортировке первоначальный typeText на перерисовываемом поле дал неполный код, без POST; поэтому B5 явно использует fill полного видимого textbox+Enter, а не утверждает измерение аппаратной последовательности. Chrome не поддержал content.export; скриншоты и AX состояния реально просмотрены в CUA, но локальные PNG не сохранены. Этот файл — изложение наблюдений, не автоматически экспортированный UI transcript.

Во время подготовки был временный ENOSPC: запись журнала audit wrapper дала500 при открытии документа. После восстановления места /health200 и сценарии повторены. Эта500 не относится к дефектам продукта. В dev console также видны предупреждения React о DOM props `fullWidth`, `indicator`, `selectionFollowsFocus`, `textColor`; влияние на задержку не измерялось.

Проверка закончена без правок продукта. Все мутации ограничены именованной disposable БД; процессы: backend PID62656, frontend PID62344 (для последующей адресной остановки ведущим). Повторный runtime без новых причин не требуется.
