## P2: подготовленная к коммиту запрещённая правка может исчезнуть из проверки

В `wms666TaskChangedPaths` сбор незакоммиченных путей использует
`git diff --name-only -z HEAD --` и untracked-файлы. Эта команда сравнивает HEAD
с рабочими файлами и не проверяет отдельно индекс — содержимое, подготовленное
командой `git add` к следующему коммиту. Если после `git add` вернуть рабочий файл
к содержимому HEAD, запрещённая staged-правка остаётся в индексе, но collector
возвращает для неё пустой список. Зелёная проверка поэтому может предшествовать
коммиту запрещённой backend-правки без повторного `git add`.

Воспроизведено в отдельном временном Git-репозитории фактическими exported
collector/validator из проверяемого файла. TypeScript транспилирован штатной
библиотекой проекта; только Vitest `expect(...).toBe(...)` заменён эквивалентным
Node assert для вызова вне test runner. Тела проверяемых функций не менялись.

1. Baseline чужой задачи содержит `backend/app/services/inventory_service.py`;
   следующий коммит WMS-666 добавляет только разрешённый UI-контракт.
2. Изменить inventory и выполнить `git add`: validator возвращает этот путь.
3. Вернуть рабочий inventory к baseline, оставив индекс как есть:
   `git diff --cached --name-only` по-прежнему возвращает inventory,
   но collector + validator возвращают `[]`.

Нужное узкое исправление: включить отдельные пути
`git diff --cached --name-only -z` в объединение с рабочими/untracked путями
и добавить отрицательную проверку staged + counteredit. Продукт и остальные
границы для этого менять не требуется. Текущие fixtures проверяют staged без
последующего counteredit и потому эту дыру не обнаруживают.
