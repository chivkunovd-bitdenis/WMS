# WMS-666: печать production-кандидата 322bb46

Адресная проверка исходника `322bb46d96178fc25f007aaf2807c9ce7dfe9bc0` выполнена 9 октября 2026 локально. Итог — PASS по указанным программным границам. API — синтетическая фикстура, данные production и внешние маркетплейсы не затрагивались. Новая БД приложения не создавалась; `ledger/direct-jobs.sqlite3` — собственный журнал реального обработчика печати, а не WMS-БД.

`native-joins.json` подтверждает обычный вход `supply_id=wb-a` и групповой `supply_ids=wb-a,wb-b`: два последовательных заказа в каждом. Для каждого заказа отправлен QR, затем две одинаковые копии полного КИЗ; все 12 заданий приняты неизменёнными `Handler` и `Printer` из `tools/print-agent/wms_print_direct.py` кандидата. Контрольные хэши PNG браузерного ввода, SQLite-журнала и эмулируемого приёмника совпали. Независимое чтение пикселей подтвердило QR конкретного заказа и полный КИЗ каждой копии. Настройка размера — 60×80 мм. Идентичность исходника и обработчика записана в `source-identity.json`; fingerprint самого handler-файла — `ee7d1fb1ef1d603231e428e445c03e9dde95fd745f454b58c8aeea02faff35b2`.

`result.json`, `ordinary-manual.json`, `group-manual.json` и `manual-decoded.json` подтверждают ручную печать через настоящие экран, диалог и построитель HTML-ленты. Обычный вход печатает только выбранный первый заказ, исключая второй; группа последовательно печатает выбранный заказ каждой собственной поставки. Три ленты содержат QR и две точные копии полного КИЗ соответствующего заказа. `group-cancel.json` подтверждает отмену первой формы группы до подтверждения: новые запросы ленты и новые задания отсутствуют, кнопка очереди снова доступна.

Ручная лента в текущем продукте направляется через `printTapeSections` в браузерный `window.print()`. В proof перехвачена эта внешняя граница, а не контроллеры продукта. Ручной маршрут не обращается к Direct Handler. Нативное подтверждение относится к последовательным сканам. Физический принтер, драйвер, бумага, production-деплой и реальный API здесь не проверялись.

В процессе адаптации прежнего runner обнаружены ошибки фикстуры (prefix scan_id, отсутствующие markingIds/click) и среды: общий Vite-кэш вернул HTTP 504 динамическому модулю bwip-js. Они исправлены только в файлах доказательства, затем повторены затронутые маршруты; native PASS повторно после его принятия не выполнялся. Исторические ошибочные проходы оставлены с префиксами `harness-*` и `native-passed-manual-capture-error-*`; актуальные итоги находятся в `summary.json`, `native-joins.json`, `manual-decoded.json` и `result.json`.

Локальные процессы принадлежали этой проверке: Handler PID 89478 (17843), финальный Vite PID 91729 (16676); браузер runner использовал CDP 16677.
