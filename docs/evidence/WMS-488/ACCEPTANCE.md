## Production read-only и перенос прав

[Исходный аудит](AUDIT.md) сохраняет границу проверки: 50 текущих пользователей, 356 GET-вызовов реальных обработчиков с подменой только зависимости текущего пользователя, без чтения/выпуска токенов и без записей в БД. Там подтверждена scan-утечка, а массовое отображение чужих товаров в свежем обычном каталоге не воспроизведено. Это не опровергает сообщение владельца.

Проверены связи товаров, селлеров, пользователей, движений, остатков и карточек маркетплейсов: ошибочных владельцев/арендаторов не найдено. На старой production-версии опубликованный frontend с точными readonly-ответами показывал каталоги шести магазинов 38/7/19/21/1/15, но сохранял прежнюю сессию после события соседней вкладки.

Точный код новой миграции был выполнен в изолированном production-процессе с БД READ ONLY и перехватом UPDATE: один кандидат на явный флаг, ноль выполненных записей. У всех 50 пользователей доступные магазины до/после совпадают; новые делегации не создаются и существующие не включаются. Единственный мигрируемый пользователь ранее уже обладал правом включать пять существующих отключённых делегаций по старому email-правилу. Отключённая делегация сама по себе нового права не создаёт. Второй существующий менеджер с явным флагом и пятью активными делегациями остаётся без изменений.

Вопрос о том, является ли второй менеджер намеренно уполномоченным сотрудником AVpack, остаётся продуктовым. Его доступ не объявлен ошибкой и не отозван без установления назначения. Runtime больше не выдаёт новое менеджерское право по email; право хранится явно в БД.
