## Изоляция внешних систем

Autouse-фикстура `legacy_sales_http` в этом модуле подменяет `wb_sales_report.Redis.from_url` локальным `RedisBoundary`: `eval` возвращает `0`, `get` — `None`, а `set` и `aclose` ничего не делают. Поэтому тестовый URL не открывает Redis-соединение. Он только позволяет `read_sales_report` пройти ветку, которая при production-конфигурации без общего лимитера иначе закрывается отказом.

`httpx.AsyncClient.send` перехватывает запросы к `wildberries.ru` и возвращает синтетические строки продаж из `_SYNTHETIC_SALES`. Другие HTTP-клиенты фикстура допускает только с `MockTransport` или `ASGITransport`; сам тест использует in-process `ASGITransport` к приложению. По этому пути нет сетевого обращения к WB. Вызовов Celery-задач (`delay`, `apply_async` или отправки в worker) этот тест не выполняет. Строка `celery_broker_url` не становится реальным брокером: `Redis.from_url` уже заменён локальным stub.

Таким образом, можно подтвердить локальную изоляцию Redis/WB и отсутствие вызова Celery worker/broker в этом сценарии. Это не означает, что сам тест был запущен в рамках данного ревью: продуктовые тесты здесь не выполнялись.

## Что доказательство не охватывает

Локальный `RedisBoundary` намеренно упрощён: `eval=0` не проверяет межпроцессную координацию, конкуренцию, реальные lease/cache сроки, поведение при недоступности Redis или корректность распределённого rate limit. Для этих гарантий нужны отдельные специализированные тесты; данный сценарий подтверждает только то, что старый API-gate тест может подготовить операцию через зафиксированный локальный контур.

Синтетические продажи не подтверждают полноту живого WB отчёта, реальные продажи и состав КИЗ Виталика, доступность его токена, подписание ЭЦП, отправку в ЧЗ, работу production-очереди, CI или deployed SHA. Никаких выводов об этих фактах это ревью не делает.

Для закрытия именно исторической fixture-коррекции остаются отдельные процессные доказательства, перечисленные в FX5171–FX5174 `docs/requirements/WMS-517.md`: зафиксировать новую точную пару в допустимом immutable-history реестре, показать test-first RED-отрицательные случаи для запрещённых изменений и отсутствия поздней подмены, зарегистрировать этот отчёт как review evidence, выполнить необходимый точный прогон и полный CI кандидата. До этого корректен только технический вердикт PASS при формальном статусе OPEN.
