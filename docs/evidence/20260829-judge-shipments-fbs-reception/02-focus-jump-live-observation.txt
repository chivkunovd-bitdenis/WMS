Пункт 2. Проверка "сканер не должен красть курсор".
Живая сессия в браузере (mcp Claude_Browser), документ Отгрузка №000020, вкладка "Подбор",
место "A 1.1" (aria-label поля "Снять", type=number).

Шаг 1. computer.left_click по ref поля "Снять" (место A 1.1).
Проверка через javascript_tool:
  document.activeElement -> {"tag":"INPUT","placeholder":"","value":"0","name":"Снять"}
  Вывод: фокус реально в поле количества, значение 0.

Шаг 2. computer.triple_click по тому же полю (выделить содержимое), затем computer.type("12").
Проверка через javascript_tool сразу после ввода:
  document.activeElement -> {"tag":"INPUT","value":"","ariaLabel":"Сканер: место или товар"}
  Вывод: фокус ПЕРЕСКОЧИЛ из поля количества в поле сканера ("Пикните место или товар").

Шаг 3. Скриншот интерфейса сразу после шага 2 показывает:
  - поле "Снять" для места A 1.1 содержит "12" (значение применилось);
  - "Снято" по товару выросло с 1 до 13 (1 из ячейки 232 1.1 + 12 из A 1.1);
  - "Осталось" уменьшилось со 109 до 97;
  - строка "97 штук осталось снять из 110 по плану отгрузки".
  Это состояние сохранено на сервере и повторно сфотографировано как
  04-podbor-current-state.png (открыто заново в отдельном заходе, те же цифры: Снято 13, Осталось 97).

Итог: набор цифр в поле количества уводит фокус в поле сканера — воспроизводит жалобу
"ставлю кол-во товара в подборе отгрузки и там сразу перескакивает курсор в сканирование".
