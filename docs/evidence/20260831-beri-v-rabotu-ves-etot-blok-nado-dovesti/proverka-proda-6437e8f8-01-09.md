## Не подтвердилось / требует правки

### 1. Минус создаётся при живом остатке в соседней ячейке

`manual_pick` побеждает все прочие источники безусловно
(`fbs_shipment_source_service.py:_load_manual_sources` + приоритет в
`resolve_fbs_shipment_sources`), это закреплено тестом
`test_manual_pick_wins_and_keeps_exact_container_for_reversal`. Поэтому при
недостаче на назначенном месте система уходит в минус, **не пытаясь взять
свободную штуку из другой ячейки того же склада**. В прогоне выше B-01 всё
время держала свободную единицу.

Последствие не бухгалтерское, а торговое: минус суммируется с плюсом при расчёте
доступного, публикуемый остаток становится нулём, товар перестаёт продаваться.
Инструмента «показать ячейки с отрицательным остатком» в системе нет.

### 2. Подбор молча разрешает подобрать одну штуку в два заказа

Для WB подбор больше не уменьшает остаток. Проверка доступности для обычной
ячейки — `available_quantity_at_location` (`inventory_service.py:310`) — вычитает
только резервы обычных отгрузок. Вычитание уже сделанных подборов есть ровно
в одной ветке: когда подбирают прямо из зоны сортировки
(`_active_pick_count_for_sorting_source`, `fbs_picking_service.py:1117`).
Для ячейки хранения такой защиты нет.

Раньше её роль выполнял сам перенос в сортировку: он уменьшал остаток, и второй
подбор упирался в нехватку. Перенос для WB убрали (`fbs_picking_service.py:1141`,
условие `supply.marketplace != "wb"`) — защита ушла вместе с ним.

Оператор узнаёт о недостаче только на экране передачи, когда заказы уже
упакованы и разложены по коробам.

## Что предлагается поправить

1. **Порядок источников при недостаче.** Если на назначенном подбором месте не
   хватает — добирать из другой ячейки того же склада, где остаток есть.
   В минус уходить только когда по складу действительно ноль.
2. **Вычитать сделанные подборы для любой ячейки**, а не только для зоны
   сортировки. Тогда «доступно 0» видно на подборе, а не на передаче.
3. **Отчёт по отрицательным остаткам.** Иначе минусы копятся незамеченными и
   тихо занижают публикацию в кабинет продавца.
