# Короба в каталоге — интеграционная проверка перед stage

Дата: 23.08.2026

Проверена финальная реализация поверх `origin/etalon` после атомарной волны FBS.

## Граница изменения

- прежняя вкладка «Товары» остаётся вкладкой по умолчанию и не меняет таблицу, фильтры и действия;
- «Короба и грузоместа» вынесены в отдельную верхнюю вкладку;
- скан внутреннего ШК раскрывает и подсвечивает найденный короб;
- состав короба показывает колонки «Фото», «Название», «Артикул продавца», `SKU`, «ШК»,
  «Размер», «Селлер», «В коробе» и «Документ прихода»;
- документ прихода передаётся общим контрактом `kind / id / number / date`; текущий источник — приёмка;
- новых складских записей при просмотре и сканировании не создаётся.

## Проверки на объединённом коде

- `ruff` по изменённым backend-файлам — успешно;
- `mypy` по изменённым backend-модулям — успешно;
- `backend/tests/test_inbound_package_catalog.py` — `4 passed`;
- production frontend build (`tsc -b` + Vite) — успешно;
- frontend unit — `143 passed`;
- Chromium `frontend/tests-e2e/catalog-box-lookup.spec.ts` — `2 passed`;
- сканирование, раскрытие, подсветка, столбцы и документ прихода доказаны живым браузерным сценарием;
- строка короба использует свежие реквизиты из ответа lookup API, а не устаревший кэш каталога;
- lookup вместе с отображением результата уложился в установленный тестом предел `1.5 s`.
