# UI-kit prerequisite волны 4 — закрытие возврата `UIKIT_REWORK_REQUIRED`

**Статус:** `UIKIT_ACCEPTED`

Возврат ревьюера был по делу: `AppDialog.test.tsx` сверял внутреннюю константу,
а не поведение, а тесты `MoneyInput`/`CheckboxInput` опирались на SSR-разметку и
приватный валидатор. Ниже — почему это случилось и чем закрыто.

## Почему поведенческие юнит-тесты были невозможны

`frontend/vitest.config.ts` задаёт `environment: 'node'`, а в зависимостях нет
ни `jsdom`, ни `happy-dom`, ни `@testing-library/react`. DOM в юнит-слое
отсутствует, поэтому «кликнуть чекбокс», «поймать Escape» или «проверить
ловушку фокуса» там нельзя физически. Требование ревьюера было верным по сути,
но недостижимым в том слое, куда его адресовали, — отсюда и повторные круги.

Поведение перенесено в настоящий браузер по странице-витрине `ui-kit.html`,
которую Playwright поднимает вместе с реальным backend. Ни один ответ не
подменяется: это живые компоненты, живой DOM, живые клики и клавиши.

## Найденный при этом настоящий дефект

Первый же прогон показал, что `AppDialog` печатает в консоль ошибку React:

```text
React does not recognize the `disableEscapeKeyDown` prop on a DOM element.
```

В MUI 9 `Dialog` больше не пробрасывает `disableAutoFocus`,
`disableEnforceFocus`, `disableRestoreFocus` и `disableEscapeKeyDown` в `Modal` —
они утекают на DOM-узел, и React их отбрасывает. То есть константа
`DIALOG_ACCESSIBILITY`, которую и проверял зелёный юнит-тест, **не настраивала
ничего**. Тест сверял мёртвое значение само с собой и поэтому был зелёным.

Все четыре флага стояли в `false`, что совпадает с поведением MUI по умолчанию,
поэтому удаление константы не меняет поведение — оно убирает ошибку в консоли и
ложное ощущение настройки. Тест-шов `__appDialogTest` и файл
`AppDialog.test.tsx` удалены вместе с ней: без константы им нечего проверять.

`FormFields.test.tsx` сохранён. Он рендерит в статическую разметку и проверяет
связку label/`aria-describedby` и валидаторы — для node-окружения это законный и
полезный слой, он дополняет браузерные проверки, а не подменяет их.

## Доказанное в браузере

`frontend/tests-e2e/ui-kit-form-primitives.spec.ts` — 7 passed.

| TC | Что доказано |
|----|--------------|
| TC-NEW-101 | `CheckboxInput` действительно переключается кликом по видимой подписи в обе стороны |
| TC-NEW-102 | недоступный `CheckboxInput` не переключается, причина связана через `aria-describedby` и читается программой чтения |
| TC-NEW-103 | `MoneyInput` сохраняет ровно `12.20` и `0.29` — строка не проходит через число и не теряет хвостовой ноль |
| TC-NEW-104 | `12.205` и `-5.00` помечаются `aria-invalid="true"` с точным текстом причины; `5.00` снова валидна |
| TC-NEW-105 | `AppDialog` связывает заголовок через `aria-labelledby`, начальный фокус внутри модалки, десять Tab подряд не выпускают фокус наружу |
| TC-NEW-106 | Escape закрывает окно и возвращает фокус кнопке-триггеру |
| TC-NEW-107 | сторож: React не сообщает о нераспознанных пропсах — регресс мёртвых «настроек» больше не пройдёт молча |

Замечание по `TC-NEW-105`: MUI отдаёт начальный фокус контейнеру
`.MuiDialog-container`, который лежит рядом с `[role="dialog"]`, а не внутри
него. Проверка containment ведётся по корню модалки; первая редакция теста
падала именно из-за слишком узкого ассерта, а не из-за компонента.
