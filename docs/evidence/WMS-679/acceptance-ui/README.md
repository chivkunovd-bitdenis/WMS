# WMS-679: ограниченное визуальное доказательство 07.10.2026

Это дополнение для исходного принимающего аналитика, а не самостоятельная полная приёмка. Проверены реальные `FfSuppliesShipmentsPage` и текущая `muiTheme` через Chrome/CUA; тестовая сцена подставляет только искусственные GET-ответы. Ни WB, ни production не вызывались. Все мутации отклоняются QA-сценой. Продукт WMS-679 `cb9afe1f84ac649297b0afa71d18349246d9a622`, независимое PASS `7889949531bfa08f83719ec837ac76f2feb78109`. На момент финальной сверки HEAD `739bcadf1be4fe92e24af3d30b42f892f858e598`; diff компонента относительно product пуст. Требования и ожидания тестов не менялись.

## Наблюдаемое поведение

1. В существующей отгрузке №000679 вкладка «Упаковка» → «Короба» показывает короб INB-DEMO-679, состав 3 шт. и действие «Скачать XLSX для WB». Рядом сохраняется «Загрузить по накладной». Это synthetic seller/document/box, не реальные данные.
2. Первый GET экспорта возвращает искусственный 503. Текст «Демо: временная ошибка экспорта, повторите запрос» виден прямо возле действия; текущий документ и состав не исчезают, повтор доступен.
3. Повторный GET получает 5929 байт обезличенного настоящего шаблона из Git. Заголовок `x-wms-warning-code: wb-shelf-life-date-required` выводит в том же документе: «Перед загрузкой в WB укажите фактическую дату партии для товаров со сроком годности: WMS не хранит дату окончания партии». Ошибка исчезает. В trace два GET, ни одной мутации. Это подтверждает реакцию компонента на данный заголовок; формирование живого XLSX бэкендом доказывают отдельные backend-тесты, эта сцена не заменяет их.
4. В идентичной искусственной Ozon-отгрузке CUA DOM показывает 0 элементов `ff-mp-wb-fbw-export`, прежний импорт остаётся видимым.
5. Нажатие прежнего импорта открывает именно «Загрузить по накладной» с описанием колонок Штрих-код, Кол-во, Адрес; это отдельный импорт, не экспорт. Файл не загружался.
6. При 390×844 новая кнопка остаётся читаемой внутри «Короба», не перекрывает соседние действия. В существующей таблице упаковки выше наблюдаются тесные/пересекающиеся заголовки; эта таблица не менялась WMS-679 и не исправлялась в этом ограниченном проходе. Полную адаптивность всего старого экрана этот результат не заявляет.

## Честные пределы

- `waitForEvent('download', timeoutMs:10000)` перед повтором не дал подтверждения сохранённого файла. Видны успешный ответ и предупреждение после Blob/anchor-кода компонента, но наличие файла в Downloads не доказано. Разрешения браузера не менялись.
- Открыта существующая форма размера внутреннего ШК короба (58×40). Нажатие «Печать» вызвало штатный iframe.print и заблокировало управление этой вкладкой при заблокированном macOS. Вкладка закрыта штатным CUA. Образ внутренней этикетки, системный preview и бумага в этом проходе НЕ подтверждены. Имя «Внутренний ШК WMS» остаётся отдельной кодовой/контрактной проверкой, не выданной здесь за визуальную.
- Сценарий позднего ответа A после открытия B здесь не воспроизводился: для него остаются ранее предъявленные технические проверки; не заявляется дополнительное визуальное доказательство.
- Приём WB Partners, допустимость INB/WHB для реального WB, загрузка файла, WB QR и физическая сдача не проверялись. C15/C16 не закрываются.
