## Шаблон тикета (для дешёвых моделей)

Каждый тикет перед выдачей исполнителю разворачивается по шаблону:

```
### T-XX: <название>
Контекст: 2–3 предложения — что это за экран/модуль и зачем.
Читать перед работой: mobile/docs/02_UX_SPEC.md §<...>, 01_AUDIT.md §<...>,
  эталон: <путь к золотому экрану/паттерну>.
Файлы: какие создать/менять (точные пути).
API: эндпоинты + имена сгенерированных методов клиента.
Использовать паттерны: P1/P2/... (не изобретать свои компоненты).
Состояния: loading / empty / error / success — все обязательны.
Acceptance criteria: чеклист из 5–10 проверяемых пунктов.
Проверка: команда сборки + как симулировать скан (adb broadcast) + что увидеть.
```

## Правила для исполнителей

1. Перед началом: прочитать PROGRESS.md, 02_UX_SPEC.md (целиком), свой тикет.
2. Не трогать чужие файлы, не «улучшать попутно», не менять паттерны.
3. Любой вопрос/неоднозначность — записать в PROGRESS.md в секцию «Вопросы»,
   выбрать консервативный вариант, пометить TODO в коде.
4. После тикета: собрать проект, прогнать линт и тесты, обновить статус здесь,
   дописать журнал в PROGRESS.md (что сделано, какие файлы, что проверено).
