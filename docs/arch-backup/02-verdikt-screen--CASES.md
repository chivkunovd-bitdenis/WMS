| S-03-TC-036 | Закрыть вкладку пока запрос «Передать в доставку» в полёте — нет зависшего состояния |

**Принцип отбора.** Нормальные кейсы (TC-001–023) написаны автором фичи в идеальных
условиях. Ломающие бьют по реальным операторским паттернам: двойной клик в спешке,
два окна одновременно, сеть упала в середине операции, WB прислал что-то нестандартное,
данные поменялись пока оператор смотрел. Каждый кейс описывает **правильное** поведение
системы — не «падает», а конкретный экран/сообщение/состояние.

## Смежные кейсы

Источник: `MAP.md` строки «задевает соседние карточки» для карточки 02, раздел
«Смежные экраны, чьи кейсы придётся перекликать» (S-14 и S-15 прямо названы как
требующие полного прогона при изменении данных меты).

### S-14 · FbsPackagingPage

> MAP.md: «`FfPackagingPage (S-14)` и `PackagingPendingMarkingWorklist (S-15)` —
> 01 меняет данные меты, 04 сносит костыль в упаковке. Кейс упаковки прогоняется целиком.»

Карточка 02 меняет трактовку ответа WB (`map_wb_decision_to_meta_status`,
`compute_delivery_allowed`) и вид статуса в строке заказа. На S-14 оператор сканирует
код и первым видит обратную связь от WB. Если правки 02 нарушат показ вердикта или
логику «код уже привязан», упаковщик будет работать с ложным состоянием.

| Номер | Что проверяет |
|---|---|
| S-14-TC-001 | Скан ЧЗ не даёт немедленный зелёный — «WB подтвердил» только после ответа WB |
| S-14-TC-002 | Двойной скан одного кода — отбивается сообщением, дубля нет |
| S-14-TC-003 | WB вернул ошибку при проверке — оператор видит перевод reason, не технический код |
| S-14-TC-004 | Код принадлежит другому заказу — система отклоняет без технических деталей |

### S-15 · PackagingPendingMarkingWorklist

> MAP.md: та же строка — кейс прогоняется целиком при изменении данных меты.
> Дополнительно: MAP.md карточка 01 вводит событие `wb_orphaned` (возврат кода в пул),
> что напрямую меняет содержимое ворклиста.

| Номер | Что проверяет |
|---|---|
| S-15-TC-001 | Подтверждённый WB заказ уходит из ворклиста автоматически, без перезагрузки |
| S-15-TC-002 | Все заказы подтверждены — пустое состояние экрана без краша |
| S-15-TC-003 | Событие `wb_orphaned` (01) — заказ возвращается в ворклист ровно одной строкой |
