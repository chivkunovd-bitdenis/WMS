## Ломающие кейсы

Заведены в `tests/cases/S-03.md` (раздел «Ломающие кейсы · 06-picking-list-order»).

| TC-ID | Сценарий | Почему ломает |
|---|---|---|
| S-03-TC-011 | «Печать стикеров» при активном фильтре «Не собраны» | Фронт берёт `order_ids` из `visible` вместо полного `items` → лента короче листа, номера рвутся |
| S-03-TC-012 | Двойной быстрый клик «Печать стикеров» | `setBusy(true)` батчится асинхронно; до следующего рендера кнопка enabled → два запроса в полёте |
| S-03-TC-013 | Закрыть модалку во время загрузки листа | `load()` завершается на размонтированном компоненте → unhandled rejection или предупреждение React |
| S-03-TC-014 | Бэк вернул 500 на загрузку листа | Обработчик ошибки не показывает Alert или выводит технический текст с HTTP-кодом |
| S-03-TC-015 | Один стикер WB не получен — нумерация не съезжает | Фильтрация `sticker_file === null` по индексу сдвигает «№ K»: стикер №4 получает плашку «№ 3» |
| S-03-TC-016 | Заказ удалён из поставки после открытия листа | Фронт шлёт устаревший `order_ids`; бэк возвращает 500 или выдаёт чужой стикер |
| S-03-TC-017 | Поставка N=1 заказ | Реализация рисует диапазон «1–1» вместо одиночного «1» |
| S-03-TC-018 | Все N заказов — один товар | Схлопывание ломается или порядок внутри группы идёт не по `wb_order_id` |
| S-03-TC-019 | Артикул содержит `<`, `>`, `&` | `printImages` собирает HTML строкой; спецсимволы становятся тегами / XSS в окне печати |
| S-03-TC-020 | Две вкладки с одной поставкой | «№» пересчитываются на фронте по `visible`; галочка «Собрал» в одной вкладке меняет индексацию в другой |
| S-03-TC-021 | «Печать стикеров» из воркспейса ≠ из модалки листа | Воркспейс шлёт `workspace.orders` без сортировки (`relationship` без `order_by=`); лента другая |
| S-03-TC-022 | Поставка в статусе «не сборка» | Бэк возвращает 403/400; фронт крашится или показывает сырой код ошибки |
