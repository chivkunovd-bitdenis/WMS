# S-17 — Приёмка на FF

Маршрут: `/app/ff/reception`. Портал: фулфилмент.

## Что видно на живом экране

- Заголовок «Приёмка на FF».
- Значимый элемент «Создать возврат».
- Основное действие «Создать приёмку».
- Пустое состояние «Нет приёмок в очереди».

## Кейсы

- **TC-S17-P01.** Открываю /app/ff/reception → жду заголовок «Приёмка на FF» и рабочий каркас портала.
- **TC-S17-P02.** Открываю экран → нахожу «Создать возврат» → элемент видим и доступен оператору.
- **TC-S17-N01.** Подменяю основной список на пустой → открываю экран → жду человекочитаемое состояние «Нет приёмок в очереди», без пустой белой страницы.
- **TC-S17-N02.** Открываю маршрут без авторизации → жду форму входа нужного портала; данные экрана не показываются.
- **TC-S17-R01.** Открываю экран → дважды быстро жму «Создать приёмку» без ожидания ответа → мутация уходит не больше одного раза и дубль сущности не появляется.
- **TC-S17-R02.** Задерживаю ответ основного API → сразу ухожу на /app/ff/dashboard → оболочка остаётся рабочей, поздний ответ не возвращает меня назад и не создаёт дубль.
- **TC-S17-F01.** Подменяю основной API на 500 → открываю экран → вижу словами ошибку или предложение повторить; шапка и меню не исчезают.
- **TC-S17-F02.** Задерживаю основной API на 1,5 секунды и обрываю запрос → экран не белеет, показывает стабильный каркас и понятное состояние сбоя.
