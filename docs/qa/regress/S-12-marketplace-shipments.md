# S-12 — Отгрузки на МП

Маршрут: `/app/ff/mp-shipments`. Портал: фулфилмент.

## Что видно на живом экране

- Заголовок «Отгрузки на МП».
- Значимый элемент «Плановая дата».
- Основное действие «Создать отгрузку на МП».
- Пустое состояние «Нет документов».

## Кейсы

- **TC-S12-P01.** Открываю /app/ff/mp-shipments → жду заголовок «Отгрузки на МП» и рабочий каркас портала.
- **TC-S12-P02.** Открываю экран → нахожу «Плановая дата» → элемент видим и доступен оператору.
- **TC-S12-N01.** Подменяю основной список на пустой → открываю экран → жду человекочитаемое состояние «Нет документов», без пустой белой страницы.
- **TC-S12-N02.** Открываю маршрут без авторизации → жду форму входа нужного портала; данные экрана не показываются.
- **TC-S12-R01.** Открываю экран → дважды быстро жму «Создать отгрузку на МП» без ожидания ответа → мутация уходит не больше одного раза и дубль сущности не появляется.
- **TC-S12-R02.** Задерживаю ответ основного API → сразу ухожу на /app/ff/dashboard → оболочка остаётся рабочей, поздний ответ не возвращает меня назад и не создаёт дубль.
- **TC-S12-F01.** Подменяю основной API на 500 → открываю экран → вижу словами ошибку или предложение повторить; шапка и меню не исчезают.
- **TC-S12-F02.** Задерживаю основной API на 1,5 секунды и обрываю запрос → экран не белеет, показывает стабильный каркас и понятное состояние сбоя.
