# WMS-399 — статус дизайна

**09.09.2026:** Клод Опус завершил авторскую сессию дизайна. Прототип
`prototypes/wms399-chat/` содержит все запрошенные экраны, требования и
хендофф написаны. Реального браузерного прохода автор не выполнял —
следующий шаг за Codex: собрать (`vite build`), пройти `tsc -b --noEmit`
и проверить в браузере, вернув Клоду Опусу конкретные замечания без
переверстки.

Сессия дизайна `8f165d2e-0399-4c15-a9be-cb182241cde4`, модель
`claude-opus-4-7`. Первый заход не завершился без итога; второй заход
упёрся в лимит пятичасового окна (`out of extra usage`) и был досрочно
остановлен. Третий заход 09.09.2026 после явного возобновления координатора
довёл прототип до полного состава и выполнил авторские поправки совместимости с
установленными версиями зависимостей (MUI 9, TypeScript 6).

## Что теперь есть

- `docs/design/wms399-chat/REQUIREMENTS_RU.md` — продуктовые требования
  (интент, роли, IA, сценарии, состояния, вложения, уведомления, поиск,
  контракт интеграции, открытые вопросы). Формулировки скорректированы:
  примеры проблем описаны как проектные сценарии, а не подтверждённые
  инциденты; роли/каналы/статусы — проектные view-модели с явной
  оговоркой, что бэкенд опирается на существующие права ФФ и селлера.
- `docs/design/wms399-chat/DESIGN_HANDOFF_RU.md` — техническое описание:
  запуск, роутинг, токены, матрица достижимых состояний, контракты
  действий и данных, инварианты видимости, известные ограничения
  прототипа, что Codex не должен переделывать без владельца.
- `prototypes/wms399-chat/` — runnable Vite + React 19 + MUI 9 + TS 6
  прототип, зависимости берутся из симлинка `node_modules` основного
  фронта. Работает hash-роутинг, тема повторяет базу WMS.

## Экраны и состояния

Все обязательные состояния из требований достижимы через UI и/или
демо-меню (иконка молотка в топ-баре): инбокс, канал (лента, разделители,
system-события, внутренние заметки), композер (вложения с прогрессом,
неудачей и повтором, ограничения, offline), треды, реакции, followup,
пикер документа, карточка документа и её устаревшее/удалённое состояние,
предпросмотр документа в drawer, лайтбокс, ящик участников с правилом
приглашений, кросс-канальный поиск, центр уведомлений, настройки
уведомлений (push permission, digest, per-conversation mute), мобильная
и десктопная ширина.

## Ограничения, о которых нужно помнить

Полный список — в `DESIGN_HANDOFF_RU.md` §8. Коротко: нет реалтайма,
виртуализации ленты, серверной пагинации, реальных push и email,
антивируса вложений, аудита правок, персистентности драфтов между
перезагрузками. Автор дизайна не проверял макет вручную в браузере —
это следующая задача Codex.

## Что следующим шагом делает Codex

1. Собрать прототип (`node_modules/.bin/vite build` из
   `prototypes/wms399-chat/`) и пройти `tsc -b --noEmit`.
2. Открыть `http://127.0.0.1:5199/` и пройти по демо-меню все
   переключатели (роль, ширина, оффлайн, upload fail, permission
   denied, doc outdated). Убедиться, что переходы по маршрутам, отправка
   сообщений, треды, вложения, пикер документа, предпросмотр документа,
   лайтбокс, поиск, уведомления и настройки работают.
3. Вернуть Клоду Опусу замечания по дизайну (если они есть),
   не переделывая макет самому. Все поправки к исходникам, включая технические, вносит тот же Opus;
   Codex только организует проверки и сохраняет результат.
4. Обновить эту сводку, канонический бэклог WMS-399 и подтверждённый
   commit SHA.
