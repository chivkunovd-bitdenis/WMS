# Пилотный запуск TSD приложения — гайд для тестировщика

## Что это

ТСД приложение — это мобильное приложение для складского WMS, предназначено для работников фулфилмента. 

**Три основных флоу:**
- **Приёмка** — приём товаров от поставщиков в коробах
- **Сортировка** — размещение товаров по ячейкам хранения
- **Отгрузка** — сборка и упаковка товаров (включая печать Честного Знака), отправка заказов

**Аппаратное обеспечение:**
- Работает на профессиональных ТСД: Urovo, Zebra, Chainway и других
- Работает на обычных Android-смартфонах (сканер = камера устройства)

**Требование к сети:**
- Постоянное подключение к Wi-Fi
- Оффлайн-режима нет — без сети приложение не работает

## Установка APK

### Где найти файл
- Путь к APK: `mobile/android/app/build/outputs/apk/release/app-release.apk`
- Размер: примерно 36 МБ

### Подготовка устройства
1. На Android-устройстве перейти в **Настройки → Безопасность** (или **Приложения**)
2. Найти опцию **«Установка из неизвестных источников»** и разрешить её (или разрешить для вашего приложения для управления файлами)

### Способы установки

**Вариант 1: через компьютер (ADB)**
```bash
adb install app-release.apk
```
Компьютер и устройство должны быть в одной сети, на устройстве включена отладка по USB (**Параметры → О телефоне → Номер сборки** ×7 раз → **Параметры разработчика → Отладка по USB**).

**Вариант 2: вручную**
- Скопировать APK на устройство (USB-кабель, облачное хранилище, мессенджер)
- Открыть файловый менеджер, найти файл и открыть его
- Установка начнётся автоматически

### Важно: замена версий
- Release и Debug версии подписаны **разными ключами**
- Если на устройстве уже стоит **Debug-версия**, то перед установкой Release нужно сначала **удалить** старую версию:
  ```bash
  adb uninstall ru.wms.tsd
  ```

## Первый вход

### Настройка сервера
1. Запустить приложение
2. На экране входа найти кнопку **«Настройки сервера»** (обычно внизу экрана или в меню)
3. Ввести адрес вашего сервера WMS: `http://IP-адрес-сервера:порт`
   - Пример: `http://192.168.1.100:18080`
   - Устройство и сервер должны быть в **одной локальной сети**

### Вход в систему
1. На экране входа ввести:
   - **Email** (учётная запись фулфилмент-администратора или кладовщика)
   - **Пароль**
2. После успешного входа приложение попросит **установить 4-значный PIN**
   - Этот PIN используется для быстрого входа в дальнейшем (вместо email+пароль)

### Тестовый стенд (если используется)
Если вы тестируете против тестового сервера, используйте:
- **Email:** `admin@test.example.com`
- **Пароль:** `TsdTest123!`
- **PIN:** `1234`

## Что проверить на реальном ТСД (аппаратном сканере)

**Это критичный этап — данные здесь определяют совместимость с реальным оборудованием.**

### Чеклист проверок

#### Сканер и его режим работы
- [ ] **Определить способ вывода ШК на вашем ТСД:**
  - Приложение поддерживает два режима:
    - **Broadcast-интент** (Urovo, Zebra, Chainway, Honeywell, Newland, Motorola) — сканы поступают как система-интент
    - **Режим клавиатуры (Wedge)** — ТСД имитирует клавиатуру, ШК вводятся как текст
  - Если сканы не приходят → **записать модель ТСД и способ вывода**, отправить разработчику
- [ ] **Проверить сканирование:**
  - На экране приёмки/сортировки/сборки появится поле для ввода ШК
  - Отсканировать ШК — код должен появиться в поле и обработаться

#### Качество сканирования
- [ ] Сканировать ШК **с разных расстояний** (близко, далеко, на краю рабочей зоны)
- [ ] Сканировать **под углом** (не только прямо)
- [ ] Сканировать **в перчатках** (если сотрудники работают в перчатках)
- [ ] Сканировать **серию кодов подряд** (быстро, один за другим) — коды не должны теряться

#### Поведение в экстремальных условиях
- [ ] **Блокировка экрана посреди работы:**
  - Заблокировать экран
  - Разблокировать
  - Приложение должно остаться в рабочем состоянии (не краш, не потеря данных)
  
- [ ] **Кратковременная потеря Wi-Fi:**
  - Отключить Wi-Fi во время работы
  - На экране должна появиться **понятная ошибка сети** (не молчаливый краш, не зависание)
  - После включения Wi-Fi приложение должно восстановиться

## Что проверить на смартфоне (камера-сканер)

Если используется обычный смартфон, то сканер — это встроенная камера.

### Базовая настройка камеры
- [ ] На экранах приёмки, сортировки или сборки найти **иконку QR-кода** в шапке экрана
- [ ] Нажать на неё — откроется приложение камеры
- [ ] При первом запуске приложение попросит **разрешение на доступ к камере** — разрешить

### Сканирование кодов
- [ ] Навести камеру на ШК (обычный 1D-ШК: EAN/UPC/Code128)
  - Когда код распознан, рамка на миг **зеленеет** — код принят и ушёл в работу на экране под камерой
  - Камера **остаётся открытой** для серийного сканирования (можно сканировать следующий код подряд, пауза ~2 сек между повторами одного кода). Закрыть — кнопкой **«Закрыть»**
  
- [ ] Попробовать отсканировать:
  - Обычные ШК (EAN/UPC/Code128)
  - QR-коды
  - DataMatrix (коды Честного Знака)

### Обработка ошибок при сканировании
- [ ] **Отсканировать неверный ШК** (не из текущей задачи)
  - Должен появиться **красный баннер с ошибкой** ПРЯМО в окне камеры (не закрывая камеру, не уходя на другой экран)
  - Текст ошибки должен быть понятным (например, «Товар не найден в приёмке»)
  - Сотрудник может сразу отсканировать правильный код

## Три флоу — сценарий приёмки → сортировки → отгрузки

### Приёмка (Receiving)

1. Открыть экран **Приёмка** из главного меню
2. Выбрать **поставку из очереди** (список доступных приёмок)
3. На экране приёмки:
   - [ ] Отсканировать коробку (или выбрать **«Без короба»** если товар без упаковки)
   - [ ] Сканировать каждый товар, добавляя его в коробку
   - [ ] Когда все товары в коробке, **закрыть короб** (кнопка на экране)
4. Система сравнит **план (документ) vs факт (что отсканировали)**
   - Расхождения подсвечиваются красным
   - Разобраться с расхождениями (переСканировать, скорректировать)
5. **Завершить пересчёт** — приёмка закрыта

### Сортировка (Putaway)

1. Открыть экран **Сортировка** из главного меню
2. Выбрать **заявку к размещению** (задача на перемещение товара)
3. На экране сортировки:
   - [ ] Отсканировать коробку или выбрать товар из списка
   - [ ] Отсканировать **ячейку хранения** (место на полке, куда должен пойти товар)
   - [ ] Система покажет информацию: товар, количество, ячейка
   - [ ] **Подтвердить размещение** (кнопка)
4. Повторять для всех товаров в заявке
5. **Завершить заявку** — размещение закончено

### Отгрузка (Dispatch)

1. Открыть экран **Отгрузка** из главного меню
2. Выбрать **отгрузку** (заказы, готовые к сборке и отправке)
3. На экране отгрузки:
   - [ ] **Создать новый короб** (кнопка в интерфейсе)
   - [ ] Сканировать товары, добавляя их в короб (либо сканировать ячейку, откуда берётся товар)
   - [ ] Когда все товары в коробе, **закрыть короб**
4. **Упаковка:**
   - Если товар имеет **Честный Знак (ЧЗ)**, то печать кодов идёт на рабочем месте упаковки **в веб-интерфейсе WMS**
   - На ТСД просто **подтверждаем счёт упакованного** (система учитывает, что товар уже в коробе и готов)
   - [ ] **Завершить упаковку** — все товары зафиксированы
5. **Защита:** без завершённой упаковки кнопка **«Отгрузить»** будет заблокирована
   - [ ] Убедиться, что отгрузить можно только после завершения упаковки
6. **Завершить отгрузку** — товары выгружены из системы

## Что присылать разработчику по итогам

После пилотного тестирования соберите и отправьте следующие данные:

### Обязательно
- [ ] **Модель ТСД** (если тестировали на аппаратном ТСД)
- [ ] **Способ вывода ШК на вашем ТСД** (broadcast-интент, режим клавиатуры, или что-то другое)
- [ ] **Работает ли сканирование?** (да/нет, если нет — какой ШК сканируется, а какой нет?)

### Проблемы и ошибки
- [ ] **Скриншоты или видео** любых крашей, ошибок, зависаний
- [ ] **Шаги для воспроизведения** (что делали, когда произошла ошибка)
- [ ] **Текст ошибок** из консоли или экрана, если есть

### Удобство использования (UX)
- [ ] Где текст слишком **мелкий** или неудобно читается
- [ ] Где **кнопки неудобно расположены** (слишком далеко, слишком близко)
- [ ] **Лишние шаги** в каком-то флоу (слишком много кликов/сканов)
- [ ] Где **непонятна логика** интерфейса

### Производительность
- [ ] На каких шагах **теряются сканы** (если происходит)
- [ ] Где приложение **зависает** или **очень медленно** реагирует

## Известные особенности

### На эмуляторе
На Android-эмуляторе под нагрузкой может периодически появляться ошибка **«System UI isn't responding»** — это артефакт эмулятора, к приложению отношения **не имеет**.

На реальном устройстве этого быть не должно.

### Оптимальные условия для тестирования
- Реальное устройство (ТСД или смартфон)
- Стабильное Wi-Fi соединение с тестовым сервером
- Реальные или тестовые данные в системе (поставки, заказы, ячейки)
